七、差距诊断

差距 1：30.1% 会话"仅检索未执行"（1,798 个会话）
这些会话调用了 search_apis 但从未执行 run_code。可能原因：
  • 检索结果已满足——用户只需查看 API 文档，复制到自己的脚本中使用（非负面）
  • 检索结果不匹配——API 库中缺少用户需要的功能（需补充 API 覆盖）
  • 用户放弃——检索后发现任务过于复杂，转向其他方式
建议：对这 1,798 个会话做抽样深读，区分"已满足"和"未满足"的比例，定位 API 库覆盖盲区。
差距 2：37.7% 代码执行失败率（12,345 次 run_code 失败）
失败主因 87% 为 EDA 工具运行时错误（error_log 非空）。典型失败场景：
  • 未打开 cellview/design 就执行布局操作（pyAether/SKILL 最常见）
  • 对象不存在（如引用未加载的 lib/cell/view）
  • 权限不足或文件路径错误
  • EDA 工具环境未正确初始化
建议：①在 API 文档中增加"前置条件"说明（如"需先调用 open_cellview"）；②在 run_code 沙盒中增加环境预检查；③对高频失败场景生成示例代码模板。
差距 3：pyAether/SKILL 成功率（59%/56%）显著低于 Tcl（78%）
Tcl（WaveView）API 集合简单、场景单一（波形分析），而 pyAether/SKILL 面向 Aether/Virtuoso 全流程，API 库庞大、场景复杂。建议：针对 pyAether/SKILL 的高频错误场景，提供"场景向导"——用户描述目标后，智能体自动补全前置步骤。
差距 4：7.9% 会话为"高错误零成功"（471 个会话，2,604 次失败）
这些会话执行了 3+ 次 run_code 全部失败，0 次成功。这类会话是体验最差的用户，平均每个会话失败 5.5 次。建议：对这 471 个会话逐一分析失败根因，识别共性问题和 API 库缺陷，作为优先改进项。
差距 5：9 月成功率骤降（71.5% → 37.3%）
9 月用户数从 9 人暴增到 70 人（+678%），新用户大量涌入导致成功率骤降。11 月回升至 71.2%，说明用户度过了学习曲线。建议：建立新用户 onboarding 引导（示例会话、常见错误 FAQ、推荐使用流程），缩短学习曲线。

八、核心结论

  1. 已形成生产级使用规模：323 人、696 台、65,481 次调用，月增速 ~56%
  2. 代码执行成功率 62.3%：约 2/3 的代码执行成功，Tcl（78%）> pyAether（59%）> SKILL（56%）
  3. 用户满意度正面：正面:负面 = 3:1（75.1% 正面），明确放弃率仅 2.8%
  4. API 检索覆盖优秀：98.1% 检索有效率，但 30.1% 会话仅检索未执行（链路断裂点）
  5. 主要差距：EDA 工具环境前置条件缺失（87% 错误主因）、pyAether/SKILL 场景复杂度、新用户学习曲线
  6. 改进方向：API 文档增加前置条件、环境预检查、场景向导、新用户 onboarding、高频错误案例库
