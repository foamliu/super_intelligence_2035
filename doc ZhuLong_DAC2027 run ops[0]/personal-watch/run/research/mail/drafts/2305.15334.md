I am Yang Liu, a researcher working on LLM agents; my work is at https://foamliu.github.io/.

Your AST sub-tree check is the part we keep re-implementing. Because only keys such as `repo_or_dir` and `model` are matched, and optional arguments like `pretrained=True` are skipped, a call with a wrong required type can still land in the same subtree — so the line between your "error" and "hallucination" categories depends on which arguments you register per API.

Three questions:

1. How sensitive are the reported error and hallucination numbers to that registration list? Did you test an alternative where all non-default arguments must match?
2. Retrieval-aware training appends the retrieved documentation as a JSON block. At a corpus far larger than APIBench, does BM25 ranking quality or document truncation bind first — and did you ablate top-k with the Oracle retriever held fixed?
3. Gorilla is a fine-tuned LLaMA-7B. If the same recipe moved to roughly 2B parameters with Chinese-language API documentation, would you still train the retriever-aware objective, or start with retrieval-only prompting?

Thank you for APIBench and the released model.
