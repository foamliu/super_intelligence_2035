关于 RTLLM 设计质量目标与 PPA 度量的三个问题

## 正文

谢老师：

您好。我是刘杨，做 LLM agent 方向的研究，主页 https://foamliu.github.io/。

我们正把「生成 RTL → 过仿真 → 看 PPA」接成设计流程里的自动评测，RTLLM 的 syntax / functionality / design quality 三层目标与 30 个设计是我们的起点。三个问题：

1. 表 IV 中 accu 的人工参考是 239 µm² / 19K µW，GPT-3.5+self-planning 是 231 µm² / 18K µW，比参考还小。这可能是真的更优，也可能是 testbench 未覆盖边界。你们如何区分？是否要求固定的边界向量集合？
2. timing 列的 −0.42 ns 看起来是 slack。换到自有 PDK 复现时是否必须全部重跑综合？跨工艺库比较是否有推荐的归一化方式（例如以参考设计为 1.0 的相对值）？
3. multi 8bit 上 GPT-3.5 面积 640 µm²、参考 52 µm²，失败更像位宽推理还是规划长度？若扩展到「多模块 + 接口约束」的题目，三层判据里哪层最先失效？

感谢您的时间，答复会直接决定第三层判据怎么写进流程。

祝好，
Yang Liu
