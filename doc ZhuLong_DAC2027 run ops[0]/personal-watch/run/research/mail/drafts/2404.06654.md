RULER 把 needle-in-a-haystack 扩成 13 个任务、并用 Llama2-7B 在 4K 的 85.6 作为「有效长度」的固定阈值，这个做法我们直接借用了。我是刘杨，做 LLM agent 与长上下文评测，主页 https://foamliu.github.io/。

我们在 2B 级模型上做 32K 扩窗验收时遇到一个口径问题：有些候选在 4K 本身就只有 87–90，按 85.6 的绝对线仍算「有效」，但它相对同尺寸基线的退化其实很大。想请教两点：

① 这个固定阈值是否应改为按同尺寸基线归一 —— 二选一：保持 85.6 即可 / 应按模型族基线归一，并给一句理由；
② 13 个任务里实际最先掉点的是 retrieval，还是 CWE / FWE 这类 aggregation？这决定我们把 32K 到 128K 的预算优先投给检索还是聚合。
