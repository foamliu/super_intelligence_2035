### **9\.2 失败根因分析（3 强模型 pro/glm/kimi 共性 21 题）**

|类别|数量|根因|
|---|---|---|
|沙箱不支持 dbCreate\* \(图形创建\)|9|dbCreateRect/Inst/Path/Label/schCreateInst 全返回 nil, eda\_sandbox\_lite 缺完整 Layout/Schematic Editor 运行时|
|沙箱内存限制|4|Memory report peak 379MB, foreach\+dbCreate 触发 OOM|
|模型逻辑错 \(ASSERT\_FAIL\)|4|空串处理/window ID nil/返回值/坐标变换|
|语法/API错|4|undefined func\(assemble引号\)/setq参数/car类型/layer号|

> **核心发现**: 21 个共性失败中沙箱环境问题占 62% \(13/21\), 模型能力问题占 38% \(8/21\)。eda\_sandbox\_lite 不支持 dbCreate\* 图形创建 API \(dbCreateRect/dbCreateInst/schCreateInst 全 nil\), 约 20\+ 题需要这些 API → 无论模型多强都过不了 → pass@1 上限约 68%。纯逻辑题 \+ 查询类题基本都过。
> 
> 

### **9\.3 关键发现**

- **glm\-5\.2 最优（68\.0%）**，doubao 最弱（37\.3%）——SKILL Lisp 代码生成能力模型间差异大。

- **沙箱不支持 dbCreate 是最大系统性根因**——eda\_sandbox\_lite 缺完整 Layout/Schematic Editor, dbCreateRect/Inst/Label/schCreateInst 全 nil, \~20 题受影响。

- **SKILL 4 端口 SKILL 模式 cwd 隔离**——用户在服务端拷 4 份 skill\_work 起独立沙箱，消除并发污染风险。

- **format\_skill\_cli\_output 的 skill\_code 当文件 bug**——cline 偶尔把 skill\_code 当文件写而非目录，导致 NotADirectoryError，已修。

- **TECHLIB 定位**——系统库 /proj/train/AI\_Virtuoso/libs/TECHLIB（完整, 含标准 cell），cwd/TECHLIB 是 ddGetObj 识别所需的本地映射（不完整），clean\_skill\_workdir 保留 cwd/TECHLIB \+ 还原 cds\.lib/\.cdsinit。
