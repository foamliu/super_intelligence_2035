# **Introduction**

大语言模型\(LLM\)在通用代码生成上已展现出强大能力。然而,将 LLM 应用于 EDA 脚本编写——工程师借此操作内存中的设计数据库、创建版图实例、绘制原理图、查询网表——仍然充满挑战。原因有三:**其一,EDA API 长尾且工具特定**,大量接口在公开训练语料中罕见出现;**其二,正确性无法静态验证**,它依赖真实 EDA 环境中的可观测副作用\(如版图被修改、原理图被更新\);**其三,无执行反馈则静态生成无法诊断错误或迭代修正**。现有 LLM\+EDA 工作主要聚焦于 HDL/RTL 生成,而基于真实工具 API 的脚本编写——尤其在文档不全、沙箱执行的场景下——仍鲜有研究。

本文呈现 **ZhuLong**,一个面向 pyAether 的、执行反馈驱动的 LLM 编码智能体。其名取自"睁眼即破暗"的神话意象,寓意照亮不透明的 EDA API、自动化工具特定的脚本工作流。ZhuLong 构建于 Cline\-CLI 之上，以 MCP\(Model Context Protocol\)工具服务器形式向 agent 暴露一组工具，构成"检索—查阅—执行—反馈—修正"的闭环: `search_apis`\(向量召回\)、`search_apis_by_keyword`\(关键词检索\+缩写展开\)、`get_api_details`\(完整文档查阅\)、`run_code`\(沙箱执行\)。其中 MCP 框架、沙箱服务、API 召回基础与部分工具接口由团队前期建立;召回层与详情层职责分离——召回只嵌入一句话摘要,详情才返回完整签名,避免两层重复。本文在既有基座之上推进，新增关键词补路检索、Memory Bank 查询工具与沙箱探针，核心增量在自进化经验系统与其可靠性，详见下文。

**研究问题:agent 能否从裸状态自进化,逼近人类工程师手工调试出的经验?** ZhuLong 的上述工具底座本身已能让一个训练有素的 agent 达到相当水平——但这一水平大量依赖人类工程师手工固化的领域知识\(精心编写的工作流 prompt、规则与技能\)。我们观察到:人类工程师把 pyAether 的领域知识手工沉淀为少量手写规则与技能后,agent 即可取得很高的通过率;这相当于人类手工完成了"经验进化"。本文的真正问题是:**移除这些手写经验,让 agent 从裸初始状态\(无规则、无技能\)出发,仅凭执行反馈与跨任务经验沉淀,能否自动进化出与人类手写经验相当的知识体系?** 这是一个比"在弱基线上靠经验拉分"更难、也更贴近工业落地的问题——前者问"经验能加多少分",后者问"自进化能否替代人类工程师的领域知识固化"。

本文在既有基座之上推进。**既有基座\(团队前期建立,非本文贡献\)**:MCP 服务器框架、远程沙箱执行服务、基础 API 召回与向量库、评估流水线框架。该基座本身已让训练有素的 agent 达到相当水平——但正如前述,这水平大量依赖人类手工固化的领域知识\(规则/技能\),相当于人类手工完成了"经验进化"。

**本文贡献围绕"自进化经验系统的建立与可靠性"展开**,分两层:

**A\. 自进化经验系统\(本文建立\)**——在既有工具底座之上:

1. **Memory Bank 自进化系统**。构建三层记忆金字塔\(L0 原始 trace / L1 模式聚合 / L2 技能归档\)与读写分离架构——写侧\(是否把 trace 蒸馏进 L1/Rules/Skills\)与读侧\(下游 agent 是否能看到\)解耦,读侧由"L1 是否有内容"动态决定,避免写侧噪声直接污染读侧。配套失败根因二级分类\(error\_code\+failure\_root\)与沉淀链\(8 个 step\)。

2. **写侧知识质量治理**。经验沉淀前做 ground\-truth 校验\(纠正 trace 中的假阳性成功\)、三态分级\(已验证/决策/易误导\)、反例计数门控。机制依据:不精准的经验知识比无知识更糟\(历史实验中,含 agent 推断的 L1 曾致净负,治本后转净正\),即"治理而非积累"是自进化可信赖的关键。

3. **0 误判领域 validator**。超越 MCP JSON Schema 语法校验的静态防御,在业务语义级\(SWIG 类型语义/API 存在性/kwargs 拼写\)拦截确定性 API 误用,以 0 误判\(绝不拦截本可通过的任务\)为硬约束——precision 优先,recall 受逻辑错天花板约束\(逻辑错不可静态拦截\)。

4. **检索增强与向量库重建**。新增关键词补路检索\(token overlap\+BM25\+缩写映射,补向量检索对缩写类 API 的召回失败\);重建向量库\(嵌入 name\+一句摘要,对齐召回语义\),召回层与详情层职责分离。

5. **anti\-leakage 稀疏黑盒蒸馏\(非 RL\)**。agent 全程看不到测试答案,系统仅从稀疏 pass/fail \+ 沙箱 trace 蒸馏进化,区别于依赖密集奖励或自生成测试的路线。

**B\. 经验可靠性\(本文进一步修正\)**——在 A 的系统上发现并修正"经验知识反向伤害 agent"的失真:

6. **经验知识的适用边界治理\(Scope Boundary\)**。看似合理的 L1 条目因缺适用边界,在条件不符的任务上误导。将 L1 从"事实陈述"升级为"条件知识"——沉淀时强制记录可观测前提\(Precondition\)与语义约束\(Constraint\),只陈述 trace 事实、禁止推断替代方案;注入时对带边界条目标注、对绝对否定话术软化。这与 SkillOpt"看似合理的诊断也会伤害模型"的观察一致,但本文用事前边界约束\(而非事后 held\-out gate\)解决。

7. **检索\-注入对象的对齐修正**。指出经验检索的根本错配:若嵌入文本含"解法"\(API 序列\)、而注入 query 是"问题"\(任务描述\),则语义相近但解法相反的经验会被误召回。修正为嵌入"问题"\(任务摘要\)、注入返回"解法",使同题自然高相似度召回自身解法、异题不误匹配——在不泄露答案\(只给 API 名/方向,非完整序列\)前提下实现精准召回。

8. **反思输入与错误来源的可靠性**。修正三个导致经验沉淀失真的缺陷:\(a\) 反思须基于最终提交代码而非过时中间版本,否则产出的"bug"对提交代码为假阳性;\(b\) 区分"自测已修复的历史错误"与"评估期真实错误",避免基于前者产出误导性经验并跨题传染;\(c\) AST 检测 except 块中的环境归因话术,切断"自测失败却被合理化为环境问题"的滑坡。

9. **评估可信化与可归因**。多端口沙箱隔离\(各端口独立工作目录\)从根消除并发污染,使通过率变化可归因到方法而非环境噪声;采用固定题集多轮迭代\(自进化设定\)与三元组指标\(新做对/退化/净增\),以净增持续为正为健康判据——能检测多数自进化工作\(Reflexion/Trace2Skill\)从结构上回避的同题退化。

为公平对比,validator 与手写规则/技能同属"经验层":裸基线关闭以测真·纯原生下限,自进化阶段允许 agent 自行沉淀 validator 规则以公平追赶人类。

主实验以"裸基线 → 自进化各轮 → 逼近人类手写经验"的进化曲线为实证\(数据见实验章\)。

# **Related Work**

## **LLM for EDA: From RTL Generation to Procedural Scripting**

EDA \+ LLM 呈两极:\(a\) HDL/RTL 生成;\(b\) 高层过程式脚本自动化。本工作属 \(b\)。

**\(a\) RTL/Verilog 生成。** ChipNeMo、RTLCoder、AutoChip、CodeV\-R1 用 LLM 生成电路描述,LLM 充当代码生成器;CodeV\-R1 尝试 RLVR,但受限于自动化验证环境稀缺,改用 rule\-based testbench generator \+ distill\-then\-RL。这条线的验证信号依赖人为构造的 testbench,与本工作的"黑盒 verifier \+ anti\-leakage"约束不同。

**\(b\) 高层过程式脚本自动化\(本工作位置\)。** 该方向近年快速涌现:ChatEDA【Wu et al\. 2024, IEEE TCAD】首次确立"LLM 自主生成 EDA 工具操控脚本"范式;OpenROAD Agent【Wu et al\. 2025, ICLAD】在此基础上增加执行反馈自纠错\(NL→Python 脚本→OpenROAD 执行→根据报错动态修正→迭代直至成功\),是**与本工作场景最同构的已有工作**;AutoEDA【Lu et al\. 2025】用 MCP 微服务化 agent 驱动全流程 Tcl 编排;EDA\-Copilot【Xiao et al\. 2025, TODAES】偏问答辅助而非自主执行;ChaTCL【Rui et al\. 2025, ISEDA】多 agent \+ RAG 面向 Tcl 但缺执行纠错闭环。iScript【Xu et al\. 2026, arXiv:2603\.04476】用 CPT\+SFT 模型微调 \+ iScript\-Bench\(116 题\)面向 Innovus PD Tcl;FluxEDA【Chen et al\. 2026, arXiv:2603\.25243】提供基于 gateway 的状态化执行基础设施。Agentic EDA 综述【Zang et al\. 2026, arXiv:2512\.23189】将 Agentic EDA 定位为 L3 自治度。

**与最同构 OpenROAD Agent 的对比\(核心\):**

|维度|OpenROAD Agent|本工作|
|---|---|---|
|目标平台|OpenROAD\(开源物理设计\)|Aether/pyAether\(商业平台\)|
|目标语言|Python \(OpenROAD API\)|Python \(pyAether API,大规模\)|
|训练方法|三阶段SFT\+RL\(Qwen2\.5\-Coder\-32B\)|不微调模型,MCP工具服务器\+经验蒸馏|
|反馈机制|OpenROAD subprocess error message|远程沙箱 print\_log/error\_log \+ 黑盒测试|
|评估|EDA Corpus 测试集 accuracy|隐藏测试 pass/fail\(黑盒 verifier\)|
|经验沉淀|无跨任务记忆/无自进化|L0/L1/L2 跨任务沉淀 \+ 读写分离|
|validator|无|0\-FP 静态 validator|
|并发隔离|未明确|多端口沙箱隔离|

**核心 delta = 自进化记忆治理 \+ API 正确性保障 \+ anti\-leakage 约束下的蒸馏进化 \+ 黑盒测试评估**,OpenROAD Agent 均不具备。

**与 iScript 的对比\(次近邻\):** iScript 用模型微调\(CPT\+SFT\)提升单次生成质量,无迭代执行反馈/无自进化/无记忆;验证是 LLM\-based 对比 golden reference,非真实执行;其 function 正确率显著低于语法正确率\(语法对但逻辑错是主要瓶颈,与本工作失败模式同构\)。

**与 FluxEDA 的关系:** FluxEDA 聚焦**执行基础设施层**\(gateway \+ 持久 session \+ 状态保持/rollback \+ 领域 Skills\);本工作聚焦**决策\+进化层**。FluxEDA 解决"如何可靠地与 EDA 工具交互",我们解决"如何可靠地生成正确的交互脚本并持续改进"。二者互补,且都采用 MCP 作为标准化工具接口。

**与 AutoEDA 的关系:** AutoEDA 同样用 MCP 微服务架构,但面向全流程 Tcl 编排\(非单平台精细 API\),经验沉淀仅 parallel learning\(粗粒度\),无分级校验/读写分离。

## **Self\-Evolving \& Memory\-Augmented Agents**

Voyager【Wang et al\. 2023】、ExpeL【Zhao et al\. 2024, AAAI】、MemGPT【Packer et al\. 2024】、CoALA【Sumers et al\. 2023】 等以技能库 / 经验归纳 / 分层记忆 / 认知架构实现跨任务经验复用。CodeAct【Wang et al\. 2024, ICML】提出"Python 代码即 action"统一 agent action space,比 JSON tool\-calling 提升约 20%;本工作本质上是 CodeAct 在 EDA 领域的实例化\(action space 限定为 pyAether Python API 调用\)。本工作采用三层 Memory Bank\(L0 原始 trace / L1 模式聚合 / L2 技能归档\),与该家族同向,但额外引入**写侧知识质量治理**\(见 §2\.3\)。

**ExpeL【Zhao et al\. 2024, AAAI】是与本工作 L1 机制同构的对照系\(机制同构,任务类型不同\)。** ExpeL 处理交互式决策任务\(HotpotQA/ALFWorld/FEVER,textual observation \+ 确定性环境,ReAct 式环境交互——非代码生成\),与本工作代码生成任务类型不同,同构的是**机制**\(跨任务经验→抽象 insight→注入下游\)。其 train 阶段反馈为 success/fail 二元信号且无标答\(与本工作 pass/fail\+error\_log 同构\),用 Reflexion 收集经验后以两种模式学习:抽抽象 insight 注入下游 prompt\(类似我们的 L1\)\+ 存成功轨迹作 few\-shot 检索。ExpeL 明确鼓励"重复/相似任务直接模仿成功轨迹"\(§4\.2\),即 with\-retention 式——既复用抽象 insight 也复用完整成功解;本工作因固定题集反复跑\(复用具体解=查表,污染自进化叙事\)而选 without\-retention,只复用抽象 L1 不复用具体解——**设定差异\(固定题集 vs train/test 分开\)驱动的设计差异**\(详见 §2\.4\.1\)。ExpeL 的 insight 治理仅 ADD/EDIT/UPVOTE/DOWNVOTE \+ importance count\(归零删除\)的 LLM 投票计数,无 ground\-truth 校验,且明确承认"successful trajectories can be suboptimal and mislead"。其 Table 3 实证"加 reflections 反而变差"\(reflections hallucinate 误导 insight 提取\),是**未治理经验知识反向伤害**的证据,与本工作"治理前 L1 含 agent 推断致净负、过度抽象 L1 致同题退化"同构——印证"治理"而非"积累"是自进化可信赖的关键。ExpeL 的 Fig 6 还实证 success/failure 对比对 \> 单纯多成功轨迹\(经验多样性\>数量\),支撑本工作用 disconfirm\(反例计数\)而非纯 source\_count\(成功计数\)的 L1 排序设计。本工作相对 ExpeL 的差异:写侧 GT 校验 \+ 三态分级 \+ disconfirm≥2 门控\(ExpeL 仅投票计数\)。

**MemOrb【Huang et al\. 2025, arXiv:2509\.18713, Fudan】** 在 e\-commerce 客服的多轮对话场景下,把多轮交互蒸馏成 compact strategy reflections 存入共享 memory bank 并检索复用\(frozen agent,无微调\),与本工作"把执行 trace 蒸馏成 L1 跨任务检索"机制同向。MemOrb 的反思输入是**完整 trajectory \+ 显式 reward 分项**\(§A\.1\),并采用三阶段检索:\`q'=LLM\_rewrite\(q⊕C\)\`\(C 为运行时上下文\)→ 同编码器嵌入 → MIPS top\-k——其中**LLM 查询重写是 MemOrb 的核心机制**。本工作的反思输入目前是预提取摘要\(searches/apis/errors\)而非完整 trajectory,且 LLM 查询重写默认关闭\(仅 rule\-based 重写在跑\),这是检索侧尚未补齐的差距\(详见 §6\)。MemOrb 的 Orb=6\-tuple\(observation/emotion/outcome/context…\)以 SHA\-256 内容去重、emotion 参与嵌入;本工作用更轻量的 \(identifier, description\) bullet,以可读性与可治理性换结构化程度。注意 MemOrb 的设定是 pass@k\(同一客服任务多轮累积不重置\),反思用于同一任务下一轮\(intra\-task\);本工作固定题集自进化,反思用于跨任务\(inter\-task\),设定不同。

**设定同构工作:Trace2Skill【Du \& Pinckney, NVIDIA, arXiv:2605\.21810】**——同样"黑盒 verifier 二元判定 \+ agent 看不到答案 \+ skill 当进化对象"\(设定同构,区别于 ExpeL 的机制同构\)。但三处本质不同:

|维度|Trace2Skill|本工作|
|---|---|---|
|防泄露机制|物理隔离\(agent 拿不到 verifier\)|prompt 纪律 \+ 事后 strip\(agent 技术上能自测,靠纪律不用\)|
|进化时机|online\(单题 640 rollout 快速收敛\)|offline\(一题 1 shot,靠多轮沉淀累积\)|
|技能载体|task\-wise\(单题独立 skill,RTL 异质迁移不可靠\)|cross\-task\(L1 跨题聚合,经验证可迁移\)|

载体方向的差异源于任务异质性:CVDP RTL 语义各异迁移不可靠 → task\-wise;pyAether API 调用模式有共性\(SWIG 构造/命令族/创建类反向验证\)→ cross\-task 可迁移。Trace2Skill 的 task\-wise 结论也为我们 held\-out 评估的"逻辑错类退化"担忧提供论文级佐证。另有同名工作 Trace2Skill【Ni et al\. 2026, arXiv:2603\.25158, Alibaba Qwen】\(非 NVIDIA 版\)将多条 trace 并行蒸馏成单一 skill 目录\(error/success analyst 分离 \+ 层次化合并\),蒸馏链路与本工作同构;其 Stage 2"失败必须因果可解释,丢弃 log\-only guesses"的约束,与本工作将失败类条目改为只走矛盾分析\(非 error\_log 猜测\)的治理同向。但 Ni 版是 disjoint evolving/test split \+ 单一 skill 文档,本工作固定题集自进化 \+ 多条 L1 可检索——其"单一 skill 优于 episodic 检索"结论在通用任务成立,但本工作 EDA 任务异质性强、API 规模大,单一文档臃肿,故采用多条可检索 L1。Ni 版亦是 SkillOpt 的 baseline\(无 held\-out gate,见上\)。

**SkillOpt【Yang et al\. 2026, arXiv:2605\.23904】将 skill 优化推向完整训练范式。**它把 skill 文档当作 frozen agent 的外部状态,由独立 optimizer model 从 rollout 证据提出 add/delete/replace 编辑,核心是 **train/val/test 三分 \+ held\-out gate**:只有严格提升 validation 分的 edit 才被接受,否则记入 rejected\-edit buffer 作负反馈;epoch\-wise slow/meta update 跨 epoch 追踪 improvements/regressions/persistent failures/stable successes。SkillOpt 在 6 个通用 benchmark\(SearchQA 问答 / SpreadsheetBench 电子表格 / OfficeQA\+DocVQA 文档 / LiveMathematicianBench 数学 / ALFWorld 具身决策,**非代码生成,与 EDA 不重叠**\)、7 个 target model、3 种 execution harness\(direct chat/Codex/Claude Code\)上,52 个 \(model,benchmark,harness\) cell 全胜或并列,把 Ni et al\. 版 Trace2Skill【arXiv:2603\.25158,trajectory\-level skill distillation,无 held\-out gate】作 baseline 之一且全胜\(GPT\-5\.5 direct chat 平均 \+5\.4pp\)——注意此处 baseline 是 Ni 版\(多 trace 蒸馏\)而非 NVIDIA 版\(verifier\-guided\),两版机制不同,SkillOpt 与 NVIDIA 版 Trace2Skill 无直接对比。数据集用各 benchmark 自带 deterministic split\(默认 2:1:7 train:selection:test,部分 4:1:5;selection 仅门控,test 仅终报\),rollout batch≈40、每 epoch 20 sampled tasks。其 §3\.5 原话"plausible textual diagnoses can still hurt the actual target model"恰印证本工作的一个观察——看似合理的经验知识实际可能伤害 agent,held\-out gate 是其解法。**SkillOpt 与本工作呈互补关系而非竞争,且是三层互补**:任务层\(SkillOpt 通用任务 vs 本工作 EDA 代码生成,不重叠\)\+ 设定层\(SkillOpt train/val/test 三分 skill 优化 vs 本工作固定题集自进化\)\+ 机制层\(SkillOpt 独立 optimizer 编辑单一 skill 文档 vs 本工作蒸馏 L1 条目\+治理\)。SkillOpt 用 train/selection/test 协议优化 skill 跨任务泛化\(靠独立 val split 做 gate,多次采样无 LLM 噪声问题\);本工作针对固定题集上的持续进化并显式检测退化\(无独立 val,靠 without\-retention \+ 噪声分离 \+ Scope Boundary 事前约束\)。两者解决的问题不同——它"skill 怎么优化且不退化",本工作"固定题集上怎么自进化且不退化"。后者使本工作能观测到"知识注入导致旧题退化"的现象——这在 disjoint\-split 设计下结构上不可见\(train/val/test 题不重叠,不存在"同题上轮通过这轮失败"\)。本工作 P2\-6 held\-out 评估器以 SkillOpt 的 held\-out gate 为成熟参照\(见 §6\)。

**SkillOS【Ouyang et al\. 2026, arXiv:2605\.06614, UIUC \+ Google】**\(注意:与 SkillOpt 是两篇不同论文,arXiv 号仅差一位易混\)把"何时 insert/update/delete 技能"这一**curation 策略本身当作可学习的对象**:用一个 trainable 的 skill curator\(冻结 executor\)从下游任务反馈中用 RL 学出 curation 策略,而非像 SkillOpt 那样用独立 optimizer model 编辑单一 skill 文档。SkillOS 用 **grouping**\(相关任务组内早期技能由后续任务成功率评估,把延迟反馈变可用\)与**复合奖励**\(r\_task \+ r\_fc \+ r\_cnt 内容质量连续分 \+ r\_comp 仓库级简洁度\)为 curation 提供学习信号,并用 **4 维 judge**\(Fig\.12:ABSTRACTION / REUSABILITY / ACTIONABILITY / FAITHFULNESS\)产出连续奖励喂 RL;其训练中涌现 insert→update 相位转移\(delete 始终少\),技能内容从"泛泛 tips"演化到"failure\-handling \+ conditional branches"。**本工作的技能质量门直接借鉴 SkillOS 的这 4 维**\(对齐 Fig\.12,非早期的 CORRECTNESS/COMPLETENESS 等\),在蒸馏时用它识别过拟合 skill\(带具体 task 名如 design\_42 的 skill,ABSTRACTION=0\.10 被精准识别,旧维度抓不到\)。差异:SkillOS 的 4 维是喂 RL 的**连续 formative reward**,本工作是**二元 summative gate**\(threshold 0\.4\)——formative vs summative 是设计差异非对齐偏差。SkillOS 用 RL 学 curation\(更新机制可学习、可涌现\),本工作 curation 仍预设规则\(GT 校验/分级/disconfirm\),无可学习机制——这是本工作相对 SkillOS 的差距\(见 §6 未来方向\)。

**EvoAgentBench【Gao et al\. 2026, arXiv:2607\.05202, 安徽大学 \+ EverMind/盛大 \+ 东南大学】是与本工作最直接对照的自进化评测基准**——专门评测 agent 自进化 via Ability Transfer\(能力迁移\),且把"有用的经验"明确定义为**可复用的过程**\(搜索/调试/验证的程序性知识\),与本工作 L1 沉淀"API 用法/参数构造"过程性经验同构。它从 4 域\(BrowseComp\-Plus / LiveCodeBench / SWE\-Bench Verified / GDPVal\)执行 trace 抽取 Ability\(带 trigger/procedure/evidence/boundary\),规范化成 Ability units 建 **Ability Graph**\(节点=任务,边=共享 Ability\),划分 528 train / 267 test。

**★关键借鉴:ability\-supported yet instance\-disjoint 划分原则\(§3\.2\.5\)。** EvoAgentBench 直击自进化评测的核心张力——**测试题既不能和训练题重复\(instance\-disjoint,防泄露\),又必须能从训练经验受益\(ability\-supported,否则测不到迁移\)**。普通 held\-out split 只满足前者但牺牲后者\(测试题可能与训练经验无关,测不出迁移\)。其做法:用 Louvain 社区检测把 Ability Graph 分成"过程重叠的局部社区",再**约束采样**——每个 test 任务必须和同社区的至少一个 train 任务共享至少一个 edge\-eligible Ability;并用 soft headroom signal 避免被"所有 backbone 都解决或都失败"的天花板/地板题主导。结果:zero unsupported test tasks。**这一原则为本工作的 held\-out 评估\(见 §2\.4\.1 / P2\-6\)提供了正名 precedent**:disjoint 不等于测得到迁移,自进化评测需要 ability\-supported 的 split,而非随机 disjoint。

**★Anchor Skill:oracle 参照的论文级对应物。** EvoAgentBench 设 Anchor Skill 诊断参照——用**与评估 backbone disjoint** 的 construction backbone 构建、skill 内容只用 train\-side evidence。Anchor 在 4 域 6 个 cell 全部正增益,但**没有自动方法在所有 setting 维持正增益**——印证"经验参照有效,自动方法追赶是难题"。本工作的**人类 V5\.4 baseline\(1 手写 rule \+ 4 手写 skill \+ validator\)即对应 Anchor**:人类专家手工构建的经验参照,用以衡量自进化能否逼近。EvoAgentBench 证明 Anchor 正增益但自动方法跟不上,与本工作"人类经验 \+3\.3pp\(d=1\.56 大效应\)但自进化追赶难"同构。差异:EvoAgentBench 是多域 benchmark\(4 域 795 题\),Ability Graph 需足够 task 建社区;本工作单域 EDA\(158 题\),且目前用 without\-retention 同题迭代\(测进化\+检测退化\)而非 transfer split——但其 ability\-supported disjoint split 是本工作未来 held\-out 路线\(见 §6\)的直接参照。

记忆治理方面,《Governing Evolving Memory》【Lam et al\. 2026】提出 System 2 验证步骤治记忆演化风险;本工作的 ground\-truth 校验 \+ 三态分级 \+ disconfirm 门控是这一思想面向 EDA 脚本工作流的具体工程实践,且历史实验中观察到治理前后 L1 对 agent 影响由净负转正\(数据见实验章\)。

## **Verifier\-Driven Learning \& Execution Feedback**

RLVR 线\(ReVeal【Jin et al\. 2025, arXiv:2506\.11442, MSRA】、CodeV\-R1\)通过**生成测试用例**或**构造 testbench**获得密集奖励信号。ReVeal 让 agent 在每轮交替生成代码与测试用例\(`<generation-answer>` / `<verification-answer>`\),调用 Python 解释器执行,用测试通过率作密集 per\-turn 奖励,RL 训练使生成与验证能力 co\-evolve。

**本工作与 RLVR 线是对比而非借鉴:** ReVeal 依赖 agent 自生成测试用例造密集奖励,而**生成能匹配隐藏 ground\-truth 的测试本身就是泄露风险**——与我们的 anti\-leakage 约束直接冲突。ReVeal 的验证阶段通过 `<tool-feedback>` 获取"expected output, actual output, pass/fail judgment"细粒度反馈;在我们的场景下,这类反馈等价于暴露隐藏测试的预期输出,破坏 anti\-leakage。在"不能生成测试\(防泄露\)\+ 不能 RL\(信号过稀疏\)"的工业约束下,本工作选择**蒸馏\(非 RL\)**:把单次成功经验抽象为跨任务可复用知识\(L1 模式 / L2 技能\),用长期跨任务积累替代单任务快速收敛。这是对 RLVR 线的**补充而非替代**,更贴近反馈稀疏、不能泄露答案的真实工业场景。

VeriHarness【Ray \& Goyal 2026, arXiv:2607\.14167】实证:结构化反馈\(失败位置 \+ 观察值 \+ 合法替代\)比原始诊断提升终端成功率 42\-44pp\(TextWorld 50 games\);**消融:只给位置\+观察值不够,增益主要来自"合法替代"\(admissible alternatives\)**;prose vs JSON keyed 格式效果相近,说明是信息内容而非格式有效。本工作目前处理非结构化 `print_log`/`error_log`,将其结构化为 VeriHarness 式反馈\(失败位置\+观察值\+合法替代\)是未来方向\(T1\)。

## **Agent Evaluation Methodology**

SWE\-bench【Jimenez et al\. 2024】、AgentBench 等提供代码/智能体评估基准。iScript 在 EDA 领域建立了 iScript\-Bench\(116 题,pass@k 评估\),但功能验证依赖 LLM\-based 对比 golden reference,不是真实执行——可扩展但不等同于真实功能验证。FluxEDA 在真实商业 EDA 环境上\(case study\)验证,但未建系统性 benchmark。Agentic EDA 综述【Zang et al\. 2026】指出"Sim\-to\-Silicon benchmark \+ formal grounding"是可信度缺口的核心。

Agentic Harness Engineering \(AHE\)【Lin et al\. 2026, arXiv:2604\.25850, Fudan】提出以三大可观测性支柱\(component/experience/decision observability\)驱动 harness 自动进化,10 次迭代在 Terminal\-Bench 2 上 pass@1 从 69\.7%→77\.0%,且冻结 harness 跨模型家族迁移 \+5\.1\~10\.1pp。AHE 的核心洞见:工具、中间件、长期记忆承载改进,系统 prompt 单独反而回归——**结构性工程知识可迁移,策略性文本不可迁移**。AHE 体现的 harness\-as\-optimization\-target 原则\(优化目标递进 instruction→structured context→workflow→harness code→optimizer code,评估器须在进化循环之外,可编辑面须显式设计且手写部分不可覆盖\)与本工作设计一致:本工作的 L0/L1/L2 文件化记忆\(文件系统即通用接口\)、`origin: auto_distilled` 边界标记\(可编辑面机器可读\)、写侧读上轮 benchmark 的 `execution_results.jsonl`\(评估器在循环外\)均与该原则对齐。Externalization in LLM Agents【Zhou et al\. 2026, arXiv:2604\.08224, SJTU\+OPPO】从认知制品\(cognitive artifacts\)视角系统综述四大外部化\(memory/skills/protocols/harness\),指出"agent 进步越来越取决于外部认知基础设施而非仅更强模型"。

本工作在评估方法论上的贡献是三重的:\(1\) 建立内部基准\(规模与切分见实验章\),pass/fail 由**真实沙箱执行\+隐藏测试**判定\(黑盒 verifier\),分母统一全集,区别于 iScript 的 LLM\-based 功能评估;\(2\) 多端口沙箱隔离\(各端口独立 workdir\)消除沙箱并发竞争导致的 pass 率抖动,使 pass 率变化可归因到方法而非环境噪声——这是对 AHE reproducibility 轴的工程实践,也与 AHE 的发现一致\(工具\+中间件比 prompt 更可迁移\);\(3\) 可复现性工程不限于 EDA,是可迁移的评估方法论贡献。

### **自进化的评估协议:without\-retention 全量重生**

**自进化 vs 迁移学习。** 自进化是在固定题集上反复迭代、追求逐轮 pass rate 上升,正确比较是 Round N vs Round 1;迁移学习是在 A 上学、B 上测。本工作是自进化,不做 train/test split——那会把研究问题从"进化能力"偷换成"泛化能力"。

**防泄露论证。** 一个潜在质疑是"同题迭代是否构成测试集污染"。本工作不成立此污染,因 black\-box verifier 是防泄露的终极机制:agent 全程只见 pass/fail \+ error\_log,从不见测试脚本/预期输出/参考解。同题迭代不叫泄露,叫学习\(类比工程师在同一项目上越做越熟\)。Reflexion【Shinn et al\. 2023】是同题迭代的先例且未被质疑泄露;本工作比它更进一步,做了跨任务知识聚合 \+ 写侧治理。

**without\-retention 协议。** 本工作每轮对全部任务从零生成代码\(只注入 L1/L2 抽象知识,**不复用上轮做对的具体代码**——`_enrich_verified_code` 收集上轮解但 prompt 不消费它\)。这是 without\-retention 设定。选此而非 with\-retention\(已通过题直接复用上轮解\)的理由:\(1\) 能检测退化\(Regressed\)是比 Reflexion\(通过即退出\)/ Trace2Skill\(报 best\-so\-far,起点全错只能 gained\)更严格的硬优势;\(2\) pass rate 提升完全归因于知识积累,无"代码缓存/吃老本"嫌疑;\(3\) 同题回退正是 without\-retention 才能暴露、with\-retention 会掩盖的退化信号。

**三元组指标 \+ 噪声分离。** 每轮报:Newly Solved\(上轮失败本轮通过\)/ Regressed\(上轮通过本轮失败\)/ Net Gain = Newly Solved − Regressed。健康自进化的判据是 **Net Gain 持续 \> 0**\(非 Regressed→0——without\-retention 下 Regressed 结构性 \> 0,因 LLM 采样噪声 temperature\>0 致同 prompt 不同代码\)。我们用同题多次重生成的 pass 率方差量化采样噪声,从 Regressed 中剥离"真知识退化"与"采样抖动"。**回退不可消灭是领域共识**\(Trace2Skill LCB / MUSE source\_count / SkillOpt rejected\-edit buffer / SkillOS curation 各自兜底,均不保证零回退\);判据是净增——gained 须 \> lost,否则越进化越差。

**与其他自进化工作的区分。** 自进化在学界无统一定义,本工作明确区别于:Reflexion\(自我修正,通过即退出,不重跑,无法测退化\)/ Voyager\(能力积累,开放世界任务不重复,旧 skill 默认永远可用\)/ ExpeL\(经验迁移,train/test 分开,旧题不再评估\)。本工作是少数真正面对"同题再次出现 \+ 已通过题重做"设定的工作,且以 without\-retention \+ 三元组指标严格量化进化与退化。

# **Contributions**

本工作并非简单打包现有技术\(MCP 工具服务器、RAG 检索、ReAct 决策循环、自进化/记忆/蒸馏概念\),价值在于组件间**独特的集成方式与针对场景的深度改造**。四项贡献按"实证强度"排序:

1. **写侧知识质量治理。** L0→L1 蒸馏前做 ground\-truth 校验\(纠正 trace 中的假阳性成功\)、三态分级\(已验证/决策/易误导\)、disconfirm≥2 门控。机制依据:未经治理的经验知识会反向伤害\(ExpeL Table 3"加 reflections 反而变差"、SkillOpt"看似合理的诊断也会伤害模型"均印证\);本工作历史实验中,治理前 L1 含 agent 推断致净负、治理后转净正\(数据见实验章\),即"治理而非积累"是自进化可信赖的关键——这是《Governing Evolving Memory》System 2 思想面向 EDA 脚本生成的落地。**读写分离**\(沉淀与消费解耦,读侧由"L1 是否有内容"动态决定\)是让该治理生效的架构,而非贡献本身。

2. **Anti\-leakage 下的稀疏黑盒蒸馏\(非 RL\)。** Agent 全程看不到测试答案,系统仅从稀疏 pass/fail \+ 沙箱 trace 进化。区别于多数自进化工作\(给 agent 丰富奖励或不在意泄露\)与 RLVR 线\(靠生成测试/造 testbench 拿密集奖励\),本工作在"anti\-leakage \+ 稀疏信号 \+ 蒸馏\(非 RL\)"三约束组合下证明持续进化可行。与 iScript\(无迭代反馈、无自进化\)和 ReVeal\(agent 自生成测试,与 anti\-leakage 冲突\)均形成互补对比。

3. **0\-FP 领域 validator\(诚实表述\)。** 超越 MCP JSON Schema 语法校验的领域静态防御,拦截确定性 API 误用\(SWIG 类型传原生值 / kwargs 拼写错 / 编造 API\)。**precision\-optimized: 以 0 误判\(绝不拦截本可通过的任务\)为硬约束,recall 受逻辑错天花板约束**\(多数失败为 AssertionError 等逻辑错,不可静态拦截;详见实验章\)。这是领域知识深度嵌入的静态防线。区别于 FluxEDA 的 gateway\-level 治理\(请求级类型安全\)和 MCP 的 Schema 验证\(语法级\),本 validator 在**业务语义级**拦截\(SWIG 类型语义 / API 存在性 / kwargs 真实拼写\)。

4. **可复现性 \+ without\-retention 严格评估。** 多端口沙箱隔离消除并发抖动使 pass 率可归因\(映射 AHE reproducibility 轴\);without\-retention 全量重生 \+ 三元组指标\(Newly Solved/Regressed/Net Gain\)能检测多数自进化工作\(Reflexion/Trace2Skill/Voyager\)从结构上回避的退化,并以 Net Gain 持续 \> 0 为健康判据。这是比 best\-so\-far\(Trace2Skill\)与"通过即退出"\(Reflexion\)更严格的评估口径。

# **Discussion: Limitations \& Future Work**

\(对照 memory `implementation-gaps-from-papers` roadmap \+ Qwen 报告新点 \+ VeriHarness 实证\)

- **从非结构化日志高效提取知识\(T1\)**:VeriHarness 实证"合法替代"是修复增益的主要来源——只给位置\+观察值不够。当前 validator 命中只报"TypeError: emyPointF expected"缺少"合法替代"\(应补充 `ae.emyPointF(x,y)`\);validator 命中回流 L1 形成 Trace2Skill 式 coadaptation 闭环\(当前断点:validator 命中只进 response,不进 trace\_parser→L0→L1\)。

- **检索侧对齐 MemOrb\(真·新点\)**:本工作反思输入是预提取摘要,LLM 查询重写默认关闭。MemOrb【Huang et al\. 2025】用完整 trajectory \+ LLM 查询重写\(`q'=LLM_rewrite(q⊕C)`\)做检索,是其核心增益来源之一。补齐完整 trajectory 反思输入 \+ 启用 LLM 查询重写是检索侧待补的两个差距。

- **可学习的 curation\(真·新点,SkillOS 启示\)**:本工作 curation\(GT 校验/分级/disconfirm\)仍是预设规则。SkillOS【Ouyang et al\. 2026】把 curation 策略当可学对象、用 RL 从下游反馈学出 insert/update/delete,并涌现出相位转移。让 curation 可学习\(而非全规则\)是下一阶段方向,但需先有可靠 held\-out 评估器\(见下\)。

- **蒸馏触发机制自动化\(真·新点\)**:基于置信度的蒸馏触发,平衡学习效率与知识质量\(当前写侧触发仍启发式\)。

- **Bounded edit budget\(真·新点,SkillOpt 启示\)**:L1 蒸馏目前无"每轮最多新增几条"的显式上限,某轮突蒸馏出大量条目会灌入噪声。借鉴 SkillOpt 的文本学习率\(每步最多 L 条 edit,cosine 衰减\),给 L1 新增/修改加 budget\(如每轮≤5 条新增、≤3 条修改\),防噪声灌入。

- **自进化闭环安全 / memory poisoning\(P2\-6\)**:held\-out 评估器防逻辑错类知识跨题注入退化\(Trace2Skill task\-wise 结论佐证此风险\)。**成熟参照 = SkillOpt【Yang et al\. 2026】的 held\-out gate**\(train/val/test 三分,只接受严格提升 val 的 edit,rejected edit 作负反馈\);但其依赖独立 val split,本工作固定题集设定需人为切分 D\_in/D\_out。本工作原计划的 SelectQ pass\-dominant 代理排序\(T2\)可被 held\-out gate 取代——真实行为指标比质量分代理更硬。Scope Boundary\(事前加适用边界\)与 SkillOpt held\-out gate\(事后拒绝伤害性 edit\)同源不同向,可结合。

- **validator recall 上限**:逻辑错不可静态拦截,validator 是 precision 优先的防线,非完整解;逻辑错需 held\-out 行为评估 \+ 反思增强。

- **跨领域迁移\(远期\)**:读写分离框架能否迁移至其他 EDA 平台\(Synopsys/Vivado\)。FluxEDA 的统一执行接口\+MCP 标准化降低了迁移门槛。

## **术语速查\(表中出现的专有概念\)**

- **anti\-leakage\(防泄露\)**:agent 全程看不到测试答案\(测试脚本/预期输出/参考解\),只从 pass/fail \+ error\_log 学习。本工作的硬约束。

- **disconfirm\(反例计数\)**:本工作对 L1 知识条目的可信度度量——统计"这条知识在其他任务上被证伪\(导致失败\)的次数",次数高则降级或不注入。区别于 source\_count\(统计被验证成功的次数\)。

- **GT 校验\(ground\-truth 校验\)**:蒸馏 L1 前,用 benchmark 的隐藏测试结果纠正执行 trace 里的"假阳性成功"\(trace 报成功但实际未通过\),防止错误经验沉淀。

- **三态分级**:L1 条目按可信度分"已验证/决策类/易误导类",注入时区别对待\(已验证优先,易误导类需额外门控\)。

- **held\-out gate\(留出门控\)**:SkillOpt 的机制——把题集分 train/val/test 三份,新知识\(val 上\)必须严格提升验证分才接受注入,否则丢弃。需独立 val split 支撑。

- **frozen target\(冻结目标模型\)**:不更新模型权重,只优化外部知识\(skill 文档/L1 条目\)。SkillOpt/Ni版/ExpeL/本工作都用此路线,区别于 ReVeal 的 RL 训练。

- **best\-so\-far\(历史最优\)**:报多次尝试里"至少成功过一次"的结果,而非稳定通过率。Trace2Skill\(NVIDIA版\)640 次 rollout 里 1 次通过即算"解决"。

- **task\-wise**:每道题独立进化一套 skill,不跨题复用。因 RTL 任务异质性强、跨题迁移不可靠。

- **读写分离**:知识沉淀\(写侧,trace→L1\)与知识消费\(读侧,是否注入下游\)解耦,读侧由"L1 是否有内容"动态决定,避免写侧噪声直接污染读侧。

- **Scope Boundary\(适用边界\)**:给 L1 条目标注"在什么前提/约束下适用",防止过度泛化\(如"emyPointF 需构造"注入到不需要它的题导致误导\)。

- **0\-FP validator**:0 误判的静态代码检查器——绝不拦截本可通过的任务\(precision 优先\),recall 受限于逻辑错不可静态拦截。

## **关键对照结论\(读表要点\)**

1. **本工作是唯一"固定题集自进化 \+ 能检测同题回退"的。** 表 A2 中除本工作外,所有工作的题集设定\(题不重叠/task\-wise/单题内\)都从结构上回避了"同题重做"——因此都测不到同题回退\(即"上轮通过、本轮重生成反而失败"\)。本工作历史实验中观测到此类退化信号,这是 without\-retention 评估协议的严格性所在\(见 §2\.4\.1\)。

2. **本工作知识治理最重,且唯一有 GT 校验。** 各工作治理手段:Trace2Skill\(NVIDIA\)用 SelectQ\+LCB\(仅在选 skill 阶段\);Ni 版靠"失败因果可解释";SkillOpt 靠 held\-out gate;SkillOS 靠可学习 curation \+ 4 维 judge 连续 reward;ExpeL 只有 LLM 投票计数;MUSE 靠 evaluate\+refine;MemOrb 靠 SHA\-256 内容去重。本工作是 GT 校验 \+ 三态分级 \+ disconfirm≥2 三层。ExpeL 的 Table 3"加 reflections 反而变差"和 SkillOpt 的"看似合理的诊断也会伤害模型"都印证了治理\(而非单纯积累\)是自进化可信赖的关键。

3. **防泄露程度:本工作 ≈ Trace2Skill\(NVIDIA\) \> 其他。** 多数工作靠 disjoint split 物理回避\(题不重叠自然看不到测试\),或 train/test 分开。只有 NVIDIA 版和本工作同样面对"agent 技术上能自测、靠纪律不用"的张力。ReVeal 走相反路线\(agent 自生成测试造密集奖励\),与本工作的防泄露约束直接冲突,故为对比而非借鉴。

4. **知识载体光谱:ExpeL\(无结构自然语言\)→ MemOrb\(6\-tuple,内容去重\)→ 本工作\(半结构 id\+desc\)→ Ni版/SkillOpt\(单一文档\)→ Voyager\(可执行代码\)。** 本工作在中间偏 ExpeL 端。Ni 版"单一 skill 优于 episodic 检索"的结论在通用任务成立,但本工作 EDA API 规模大、任务异质性强,单一文档会臃肿检索不到——这反向支撑本工作采用多条可检索 L1 的设计。SkillOS 的 4 维质量 judge\(ABSTRACTION/REUSABILITY/ACTIONABILITY/FAITHFULNESS\)与本工作蒸馏质量门共享同一组维度,但 SkillOS 用作 RL 连续 reward\(formative\),本工作用作二元 gate\(summative\)。

5. **质量门维度的来源:本工作的 4 维技能质量门直接借鉴 SkillOS Fig\.12**\(对齐 ABSTRACTION/REUSABILITY/ACTIONABILITY/FAITHFULNESS\),实测能精准识别过拟合 skill\(带具体 task 名的 skill,ABSTRACTION=0\.10\);早期的 CORRECTNESS/COMPLETENESS 等维度抓不到此类过拟合。这是 SkillOS 对本工作的直接借鉴点,与 SkillOpt 的 held\-out gate\(机制借鉴,见 §2\.2\)是两篇不同工作的不同借鉴,勿混。

6. **报 best\-so\-far 的只有 Trace2Skill\(NVIDIA\)\(1/80 算解决\)。** 其他工作报稳定通过率。这是 NVIDIA 版评估的弱点——640 次 rollout 里蒙对 1 次即算"解决",严重高估。本工作 1\-shot 稳定通过率比它严格两档。
