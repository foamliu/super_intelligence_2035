## 1. 后训练不是「越训越强」——先量「覆盖度」，别只盯 pass@1

- **来自**：**Sharpening Tax in Post-Training**（arXiv:2610.01509，TOP-18，`action=试跑`）。
- **结论**：**预训练 LLM + 轻量 inference harness 即可是能干 agent**；后训练把任务推向「总解 / 永不解」两端，**提升采样效率却牺牲解空间覆盖**；给足 test-time 预算时，**预训练版的 pass@K 常胜过 post-trained 版**。论文给出诊断指标 **Sharpening Tax** 与采样法 **PTGS**。
- **能改什么**：① **BaiZe 后训练**：在 SFT/RL 之外**加一条 pass@K（覆盖度）诊断**，避免「单题变强、覆盖变窄」而不自知；② **ZhuLong**：把「预训练模型 + 轻 harness」设为**强基线**，先证明后训练带来的增益**超过其 Sharpening Tax 成本**再投产。
- **预期收益**：**保住 test-time 扩展能力**，少烧后训练算力，避免「评测涨、实战覆盖反而降」。
- **成本**：**低～中**（先**读原文**复现 Sharpening Tax 指标；再在现有评测里挂一个 pass@K 视图，约 1–2 人日）。

## 2. 把「写测试」与「改代码」拆成两个角色，并**冻结测试**（防假自信）

- **来自**：**ExecCritic**（arXiv:2609.09133，TOP-2，`action=试跑`，有代码 `github.com/msr-orchard/execcritic`）。
- **结论**：patch 与 test 由**同一轨迹**生成会**同错而同信（false confidence）**；把测试交给独立的 **Test agent**、用 **fail-closed harness 冻结测试**后，只让 **Repair agent** 据执行反馈改源码——**测试质量决定反馈是否有用**（实验：差的测试把 resolved 从 61.2% 拉到 57.3%，好的测试升到 65.3%）。
- **能改什么**：**ZhuLong** 的 **generate–execute–refine 闭环**与**判分护栏**：把「测试构造」独立成角色 + 冻结测试 + fail-closed 校验，再进入修复。
- **预期收益**：**提高执行反馈可信度**，减少「自测自过」的假 resolved。
- **成本**：**中**（改 harness 脚手架 + 角色化训练/提示；先**试跑**其代码跑通闭环）。

## 3. 仓库级 SWE 有「类别跷跷板」——用**类别专家 + 同源自蒸馏**稳住

- **来自**：**One to More, More to One**（arXiv:2609.23377，TOP-5，`action=试跑`，放出 `Logics-SWE-Qwen3.6-27B`）。
- **结论**：池化 RL 下**部分类别涨、部分类别退**（聚合指标掩盖）；用**类别感知专家训练 + 同源自我蒸馏 + 标签路由多教师 on-policy 蒸馏（MOPD）**把专家收敛成一个可部署学生，**无需外部模型提供轨迹**。
- **能改什么**：**ZhuLong** 的 **SWE 类 agent 训练**（按类别分池、避免退步）；**BaiZe** 的**数据配比 / 可执行任务构造**（`Executable task construction` + `SWE Labeler` 多轴标注）。
- **预期收益**：**避免「一类涨、一类退」**，把训练池**证据化组织**。
- **成本**：**中～高**（复现成本高；先**读原文**，评估我们现有任务分池能否复用其 RRE 循环）。

## 4. 长上下文成本的真瓶颈在**存储/带宽**——KV 要「跨层复用 + 低比特 + 分层」

- **来自**：**DeepSeek-V4.1-Flash**（arXiv:2609.19969，TOP-1，`action=读原文`）。
- **结论**：论文把长上下文瓶颈明确指向 **HBM / SSD 容量与带宽**；用**跨层 KV 复用（CSA2）+ FP4 KV 缓存 + SWA Bounded Replay**，把全局 KV 压到 **890 bytes/token（≈ V4-Flash 的 1/4）**、持久 KV 压到 **≈1/8**；且 **prefill 8B / decode 16B 非对称激活**（每 token）。
- **能改什么**：**BaiZe** 的**长上下文高效推理**——KV 预算、**低比特(FP4) KV**、**HBM/SSD 分层缓存**；对**存储研究院**视角，这套「热 KV 常驻 HBM、冷 KV 落 SSD」的工程范式最值得复刻。
- **预期收益**：**显著降低长上下文显存/带宽成本**，提升 agentic（input-heavy）负载的性价比。
- **成本**：**中**（先**读原文**评估可迁移性；KV 量化 + 分层落地的工程验证需排期）。

## 5. Mamba 的「回忆(recall)」有**规模律**——可用于混合架构选型

- **来自**：**On the Recall Scaling Laws in Mamba**（arXiv:2609.07681，TOP-15，`action=读原文`，有代码）。
- **结论**：从**理论 + 机制**（hashing 视角）刻画 **Mamba 的 recall 规模律**，解释 SSM 在「精确回忆」上的能力边界与随规模的走向。
- **能改什么**：**BaiZe** 的 **Mamba-2 × attention 混合架构**选型——**哪些能力（精确回忆/检索）该交给 attention、哪些（长程聚合）可交给 SSM**，以及规模律外推时的预期。
- **预期收益**：**用证据支撑混合比例决策**，减少「拍脑袋定架构」的风险。
- **成本**：**低～中**（**读原文** + 对照我们的架构配置做一次小规模复核）。
