本轮 batch 在运行过程中触发 [run_batch][FUSE] Token 额度耗尽, 触发熔断! 停止剩余 worker（出现 2 次）。 mini 模型 API 的 Token 额度无法支撑 16 worker 并发跑 500 case，熔断后大量 worker 被停止， 导致 471/500（94.2%）的 case 为 "no submit.zip produced（cline 未产出任何文件）"—— 这些是基础设施噪声（worker 被熔断终止 / cline 被 rate-limit 拦截），不是模型能力失败。

仅 ~28/500（5.6%）的 case 为真实能力评测（cline 确实运行并产出了 submit.zip，但内容错误，check.py 判 FAIL）。 这 28 个真实能力 case 中 0 PASS，提示 mini 远弱于 pro，但样本量太小且 batch 整体被 infra 污染， 0.0% 不可作为 mini 的干净能力结论（AGENTS.md §1.2「infra ≠ 能力」）。

6. FUSE 熔断机制说明

run_batch.sh 内置 Token 额度熔断（FUSE）机制：

  • 检测（run_batch.sh:319-320）：每个 worker 完成后，检查 cline stderr / 日志是否含 Token额度已用完|Token quota|rate.?limit|额度|quota.*exhaust。
  • 触发（run_batch.sh:323-328）：命中则打印 [FUSE] Token 额度耗尽, 触发熔断!，写 FUSE_TOKEN_EXHAUSTED 标志文件到 PROGRESS_DIR。
  • 传播（run_batch.sh:297-298）：后续 worker 进入 run_task 前检查标志文件，存在则跳过新 case 直接退出。
  • 效果：已派发的 case 继续跑完，未派发的 case 被跳过（记录为 no-submit.zip FAIL）。

本轮 FUSE 触发 2 次，说明 mini API 的 Token 额度在 16 worker 并发下很快耗尽。mini 是轻量模型，API 配额可能远低于 pro。
