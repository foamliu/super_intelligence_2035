1. 总体评价与核心结论

论文理论框架（grounding gap / L4 / 贝叶斯形式化）完整且先于实测陈述，符合"预测而非事后解释"的科学规范，是全文最强部分。系统设计、benchmark 构造、错误分析均有扎实基础。但全文最严重的问题是：headline 数字 84.8% 是 1-shot 探路值，而受控 5-run 实测锚点 full_v3 = 82.1±3.0%，二者相差 2.7pp 且未在正文说明。这导致摘要、引言、结论与 4 张表（main-ablation / ablation-harness / phi-bound / llm-comparison）的锚点行、以及所有 Δ 与错误分析（"134/158"）全部建立在过时的探路值上，形成系统性"过度声称"。在 5-run 实测已落地的当下，这属于必须在投稿前修正的 🔴 硬伤。

此外，论文存在两个相邻表格共用字母 (N) 但语义不同（易混淆）、缺少配对显著性检验、缺少结果可视化图、未声明 backbone 量化版本（fp4）等问题，分述如下。

3. 评测口径（Pass@1 分母 / 5-run / 配对检验 / timeout / gen-fail）

🟢 可回填 #2Pass@1 分母 = 158 全量，gen-fail 计为失败 —— 与实测口径一致，但论文未显式说明 gen-fail 处理
5_bench.tex:41-42（Pass@1 公式）｜ 6_exp.tex:267-274（Error Analysis 提"3 generation-stage failures"）
公式 Pass@1 = #passed / Total × 100%，Total=158，隐含 gen-fail=未通过。实测各臂 gen-fail 数（如 phi_k1 r1: 103/158 通过、35 gen-fail）即按此口径计入分母。一致 ✅。
但论文仅在 Error Analysis 提"3 generation-stage failures"（针对 84.8% 那次 run），未在评测协议段声明"生成失败计为未通过、计入 158 分母"。对于 k=1 臂（gen-fail 达 30-35/158，占失败主体），这一口径必须前置说明，否则读者会误以为 65% 全是"执行错误"。
建议：在 §5.3 或 §6.1.2 加一句"生成阶段失败（超时/未产出代码）计为未通过，计入 Pass@1 分母；S2 低预算臂的 gen-fail 是 Φ 预算约束的直接体现，非基础设施故障"。
🟠 建议 #3未声明任何配对显著性检验（McNemar / paired bootstrap）
6_exp.tex:32（"mean ± standard deviation over those runs"）｜ 7_discussion.tex:12（仅定性提"benchmark size limits statistical power"）
5-run × 158 题，每臂共有 5×158=790 个任务级配对结果，完全具备做 McNemar 或 paired bootstrap 的条件。当前仅报 mean±std，对于小 gap（如 full 82.1 vs wo_retrieval 81.0 = 1.1pp，或 GLM 83.3 vs DeepSeek 82.1 = -1.2pp）无法判断是否显著。
特别是 (B) binary ±16.1 vs (N) none ±2.2（tab:ablation-harness）的"N>B"反转结论，仅凭 mean 比较、无检验，说服力弱。
建议：至少对主表（main-ablation、phi-bound、llm-comparison）的关键相邻行做 paired bootstrap（任务级配对，B≥1000）或 McNemar，报告 p 值或 95% CI；或在 Limitations 明确"未做配对检验，小效应量结论需谨慎解读"。
🟠 建议 #45-run mean±std 的"run"定义与重排方式未充分说明
6_exp.tex:32（"five independent runs with reshuffled task orderings and fresh agent contexts"）
已提到"重排任务顺序 + 全新 context"，✅ 较好。但未说明：(1) 5 次运行的 LLM 推理是否独立（temperature/采样是否固定？同一 backbone 同一 key 是否会因服务端缓存导致 run 间不独立？）；(2) std 用的是样本标准差（n−1）还是总体（n）—— README §4.1 指定 n−1，论文应与 README 一致并注明。
建议：补一句"std 采用样本标准差（n−1=4）"；若 LLM 服务端有缓存，声明"5 次运行独立采样、不复用缓存"或如实说明。
🟠 建议 #5"timeout ≤10"作为 run 有效性判据未在论文声明，infra 故障 run 的剔除/重跑规则缺失

🔴 硬伤 #5gen-fail 随 k↓ 递增 —— 论文完全未报告此现象
6_exp.tex:174-221（§S2 全节）｜ tab:phi-bound（无 gen-fail 列）
实测（MEMORY_ZHULONG.md）：phi_k3 r5=25 gen-fail ｜ phi_k1 r1=35 gen-fail、r2=30 gen-fail。gen-fail 随 Φ 预算 k↓ 显著递增（k=10→k=3→k=1：从个位数到 25 到 30-35）。这是 Φ 预算约束的直接行为表现：预算耗尽后 agent 无法继续执行→生成阶段失败。
论文 §S2 与 tab:phi-bound 只报 Pass@1 和 Converged(%)，完全没有 gen-fail 维度，错过了一个强证据：gen-fail 的递增正是"预算约束作用于工具边界、agent 仍自主决策"机制的可观测佐证，直接支撑 §8 语义约束第 1 条。
建议：在 tab:phi-bound 增加"Mean gen-fail"列（或并入"Mean read-backs"旁），并在 §S2 正文用 1-2 句描述"k↓ → gen-fail↑ → Pass@1↓ 的链条"。这是低成本高回报的补充（数据已在 daily-memories）。
