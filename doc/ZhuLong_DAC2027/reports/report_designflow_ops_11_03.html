二、今日修复（被测换 cline + 防泄题 hook）

🚨 起因：pi 有 bash/read/write 工具，benchmark agent 在 .pi_debug/<case>/ 里放了 _reference_check.py（= check.py 判分器全文），pi 直接 import _reference_check 跑了它——判分标准（答案）直接放在考生面前。pi trace（~/.pi/agent/sessions/）确认了这一泄漏。这是通过率偏高的主因。

修复 1：被测 pi → cline CLI + PreToolUse hook（用户直令）

项pi（旧）cline（新）
shell 工具有 bash/read/write/edit（任意访问）有 read/write/bash 但被 PreToolUse hook 拦截
防泄题 hook无PreToolUse（EDA-Flow-Bench 现成）
workdir 隔离check.py 放进 cwd（泄漏）只放 prompt+assets+task_brief，不放 check.py/reference/jsonl
判分在 pi cwd 内跑cline 退出后独立进程在 /tmp/judge/ 跑
headless 调用pi --print --no-approvecline -c <workdir> --auto-approve true --json

修复 2：PreToolUse hook scope 并发覆盖 → flock + append

问题：hook_scope.txt 是单文件，shard A 写 designflow/cline_eval，shard D 写 .cache/cline_eval，后写覆盖先写 → scope 只剩一个路径 → 另一 shard workdir 落 scope 外 → hook 放行 → 隔离失效。
修复：部署 hook 时用 flock 加锁 + grep -qxF || append（去重追加），多 shard scope 共存。
验证：10 次并发写入（5×A + 5×D），最终 scope 恰好 2 行，无重复无丢失 ✅

修复 3：cline 卡 run_commands 循环 → MCP 工具名修正（二连错）

第一错：CLI_PROMPT 引导 cline 用 mcp__pyAether_MCP_server__run_commands，但 pyAether server（10.251.36.15:8090）只暴露 search_apis/get_api_details/run_code —— 没有 run_commands。cline reasoning 明说 "There is no mcp__pyAether_MCP_server__run_commands in my tool list"，卡死。
第二错：改用 eda_flow server（127.0.0.1:18891，有 run_commands），但写成了 mcp__eda_flow__open_session，而 cline 实际工具名是 eda_flow__open_session（无 mcp__ 前缀）。PreToolUse hook 的 MCP_PREFIXES 不认 eda_flow__ → 落兜底分支 → override 成 /dev/null → eda_flow 工具全废。
修复：MCP_PREFIXES 加 eda_flow__；CLI_PROMPT 和 hook 引导消息全改用 cline 真实工具名（无 mcp__ 前缀）。
验证：PTSignoff-001 冒烟 PASS（277s），Verification-001 产出全部 5 个交付文件 ✅

修复 4：timeout 1500s → 2400s（40min）

依据：19 条 cline eval 数据，PASS 最慢 3732s（FormalityLaunchDiag-001），1500s 会误杀。2400s 覆盖多数 PASS，1h+ 卡死（EmXlsModel-001 8991s）不迁就。
