④ 口径校验

4.1 thinking flag 是否真生效（逐题 thinking 块计数）

从 cline session 逐 assistant 消息统计 type==thinking 块数与字符量。若跨档计数差异显著 → flag 生效；若字符量相近而 Pass@1 仍差异 → flag 影响 reasoning 结构/质量而非体量。

已知现象（需在报告中说明）：A-none（不传 flag）仍有非零 reasoning 字符量。两种解释：(a) GLM-5.2 模型自发产生 thinking 块（flag 仅调节档位而非开关）；(b) 抽取法计入非 thinking 内容。判定依据：若 A-none 的 块计数 显著低于 low/medium → flag 仍生效（仅体量相近）；若计数也相近 → flag 对该模型 reasoning 体量无显著控制。Pass@1 跨档差异（none<low≈medium）已证明 flag 对 行为结果 有效。

4.2 思维链语言是否真切换

轴 B 各语言变体须抽 3~5 条 trace 核对 thinking 块 正文语言是否真切换为指令语言（en/zh/es/fr/ru）。核验方法：对每个 B- 代表轮，从 trace 目录 trace_ablation_think_lang/B_<lang>_r<N>/<gen_batch>/cli_data/worker_*/data/sessions/<sid>/<sid>.messages.json 读 assistant 消息的 thinking 块正文，肉眼/启发式判定主导语言。本生成器未自动判定语言（避免误判），完成数据后请人工抽查并在此节补录片段。未生效的变体须标注「该变体未生效」而非当有效数据。

4.3 none 档实现口径

cline --help 枚举 = none|low|medium|high|xhigh（5 档）。A-none 传 --thinking none（CLI 接受）。若后续发现 none 不被接受则改「不传 flag」，并在报告标注口径差异。

⑥ 与既有基线对照（Δpp + 配对 McNemar）

⑦ 结论（边际收益 · 是否值得改生产配置）

初步趋势（基于已跑轮次）：
  • 开 thinking（none→low）: Δ+4.6pp（79.5%→84.2%）
  • low→medium: Δ+1.3pp（84.2%→85.4%）
边际收益：thinking none→low 显著提升（+4.7~5.9pp），low→medium 边际趋平（≈+0.6pp），说明对 GLM-5.2 + PyAether 158 任务，开 low 档即获大部分增益，medium 以上边际收益递减。成本：reasoning token 跨 none/low/medium 体量相近（待 high/xhigh 确认是否陡增）。语言：轴 B 待跑完判定；若各语言 Pass@1 在噪声内（std~1-2pp）则思维链语言对 GLM-5.2 EDA 任务影响有限。
生产配置建议：若成本敏感，low 档为性价比最优点；若追求上限且 quota 充裕，medium。high/xhigh 待数据。轴 B 若无显著差异，生产可保留默认（英文）不加语言指令，避免 prompt 膨胀。
