cline 压缩机制选型报告：basic vs agentic

ZhuLong（DAC2027）· 40 题长轨迹子集 × ABBA 6 轮 · 基座 deepseek-v4-pro-cloud · cline 3.0.51 · 2026-11-13

🔍 给忙碌 Agent 工程师的一句话结论

选 --compaction basic，不选 agentic。

在相同基座、相同协议、相同 40 题长轨迹子集下，basic 比 agentic：Pass@1 高 10pp（69.2% vs 59.2%）、收敛率高 9pp（80.8% vs 71.7%）、每通过题快 29%（3.7min vs 5.2min）、生成失败少 39%（6.7 vs 11.0）。agentic 唯一优势是每题 token 低 15%——但这是因为它把 169 条消息压缩成 10 条（94% 压缩率），丢失了 agent 后续需要的代码片段和 API 返回值，导致重新探索、循环、超时。basic 保留原文片段（49% 压缩率），agent 能直接引用，收敛更快。

四、根因抽样分析：为什么 basic 更好？

核心根因：agentic 的 LLM summary 压缩率过高（94%，169→10 条消息），把原始消息浓缩成 Goal/State/Done 摘要，丢失了 agent 后续需要的具体代码片段、API 返回值、错误日志。agent 压缩后无法引用之前的探索成果，被迫重新调用 API、重新写代码，导致消息数膨胀（67-93 msgs vs basic 44-51 msgs）、循环、超时。basic 的 rule-fold 保留原文片段（49% 压缩率，69→35 条），agent 能直接引用之前的代码和 API 返回值，收敛更快。

五、为什么 agentic 看起来省 token 但实际不省

agentic 的 token 陷阱：agentic 每题 token 更低（1.92M vs basic 2.22M，省 15%），但这不是因为 agentic 更高效，而是因为它压缩率更高（94% vs 49%）导致 context 更短。然而：
  1. per pass token 基本持平（3.21M vs 3.24M）—— agentic 省的 token 被更多失败题（gen_fail 11 vs 6.7）抵消
  2. per pass 墙钟高 29%（5.2min vs 3.7min）—— agentic 每通过一题花更多时间（重新探索）
  3. 6 轮总墙钟多 1 小时（6.20h vs 5.17h）—— agentic 的超时题拖慢整体
  4. LLM summary 本身有额外推理成本（agentic 每次压缩调用一次 LLM 生成摘要，basic 是纯规则折叠零 LLM 成本）—— 这部分 token 未计入 task token，但实际消耗了 API quota
结论：agentic 的 token 优势是表面的，综合成本（墙钟 + API quota + 失败重试）反而更高。

6.1 一句话行动项

立即行动：把 cline 的默认 compactionStrategy 从 agentic 改成 basic（<data-dir>/settings/global-settings.json）。零代码改动，零风险，预期 Pass@1 +10pp。

6.2 什么时候考虑 agentic

agentic 的适用场景（窄）：仅当你的 agent 任务是闲聊型（不需要引用之前的代码/数据，只需要语义上下文），且 context 极度紧张（必须压缩 90%+）时，agentic 的 LLM summary 才有优势。对于代码生成 / 工具调用型 agent（需要引用 API 返回值、代码片段、错误日志），basic 的原文保留是刚需。
