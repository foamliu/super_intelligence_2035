七、差距诊断

差距 1：28.4% 会话"仅检索未执行"（2,738 个会话）
这些会话调用了 search_apis 但从未执行 run_code。可能原因：
  • 检索结果已满足——用户只需查看 API 文档，复制到自己的脚本中使用（非负面）
  • 检索结果不匹配——API 库中缺少用户需要的功能（需补充 API 覆盖）
  • 用户放弃——检索后发现任务过于复杂，转向其他方式
建议：对这 2,738 个会话做抽样深读，区分"已满足"和"未满足"的比例，定位 API 库覆盖盲区。
差距 2：14.1% 代码执行失败率（9,545 次 run_code 失败）
失败集中在 10 月（1,314 次，成功率 79.4%），主因 pyAether daemon 池因 lib.defs 无效路径卡死。典型失败场景：
  • pyAether daemon 卡死在 Qt 事件循环（11-25 修复前）
  • 未打开 cellview/design 就执行布局操作
  • 对象不存在（引用未加载的 lib/cell/view）
  • EDA 工具环境未正确初始化
建议：①在 API 文档中增加"前置条件"说明；②在 run_code 沙盒中增加环境预检查；③对高频失败场景生成示例代码模板。
差距 3：264 个全量失败会话（4.2%）
这些会话执行了 3+ 次 run_code 全部失败，0 次成功。这类会话是体验最差的用户。根因：pyAether daemon 未就绪（11-25 前）、lib.defs 无效路径、许可证不足。11-25 修复后新增全量失败会话趋近 0。建议：建立 daemon 健康监控告警，避免再次出现长时间 daemon 故障。
差距 4：SKILL/Tcl 用户收敛
SKILL 用户从 175 人（11-16）降至 96 人，Tcl 从 41 人降至 39 人。调用次数 SKILL -5.3%、Tcl -33.5%。可能原因：pyAether 逐步覆盖原 SKILL/Tcl 场景，部分用户迁移至 pyAether。建议：评估 SKILL/Tcl 的不可替代场景，针对性保留和增强。

八、核心结论

  1. 已形成生产级使用规模：305 人、695 台、67,659 次调用，11 月日均 1,761 次（8.5 倍于 10 月）
  2. 代码执行成功率 85.9%：较 11-16 报告（62.3%）大幅提升，主因 pyAether daemon 池修复 + lib.defs 清理
  3. 用户满意度正面：正面:负面 = 5.1:1（83.7% 正面），明确放弃率 12.1%
  4. pyAether 主导：63.6% 调用来自 pyAether，275 人使用，是 EDA 脚本能力核心语言
  5. API 检索成为标准前置：44,914 次 search_apis 调用，55.2% 检索会话完成闭环执行
  6. 任务复杂度高：68% 会话超 30 次工具调用，反映 EDA 任务多步骤迭代特征
  7. 主要差距：28.4% 仅检索未执行（API 覆盖盲区待查）、10 月 daemon 故障拉低成功率、SKILL/Tcl 用户收敛
  8. 改进方向：API 文档增加前置条件、环境预检查、daemon 健康监控、高频错误案例库、仅检索会话深读
