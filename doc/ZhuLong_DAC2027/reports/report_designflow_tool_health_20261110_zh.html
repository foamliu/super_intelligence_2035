⑥ 方法与被排除项

方法与被排除项

数据源：triage_summary.json（696 cases）+ cline_session.jsonl（每个 case 的 agent 会话）。

解析覆盖：有可解析 session = 630；软链断裂/无 session = 66（多为 ABSENT/ERROR，cline 未产出会话，不计入矩阵分母）；session 存在但无 run_commands 调用 = 0。

四态定义：有正常输出(ok) / 报错退出(error) / 调了但无产物(no_output) / 从未调用(never)。「从未调用」= runs_with_session - runs_invoked，绝不算工具失败。

调用判定（两套口径）：true_call = invoke(段首执行) + probe(which/type 探测)；raw_mention = 词边界正则命中（含 printf/echo/heredoc/JSON 字符串里的提及，仅作旁注，避免把写配置文件里的工具名误当工具调用）。健康矩阵以 true_call 为主。

no_output 的注意：命令以 > /dev/null 2>&1 重定向时，stdout/stderr 为空但工具可能已正常执行；本类按字面记为 no_output，报告里不把它判为失败。

失败签名归一化：取 stderr 首行（无则 stdout 头 400 字符），去掉路径/时间戳/行号/十六进制后按 13 条规则聚类，命中即归类，未命中归 other。签名只对【真正执行/探测 EDA 工具的命令】聚合（invoke/probe），剔除 grep/ls/test 等普通命令的 non-zero exit 噪声。
