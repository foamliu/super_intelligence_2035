本月 EDA-Flow-Bench **初步构建完成**：搭好评测框架、改进沙盒（支持 Linux 命令 + session 概念 + 并发）、通过真实 Trace 挖掘了一批 Case（Lite + Full）、针对烛龙与若干 LLM 评测集可跑出符合预期的结果。但评测集仍处于初步阶段，**断言难度不足、部分 Case 资产受权限限制无法访问、脚本类 Case 尚未从静态评估转向 EDA 服务器实跑**三大问题待解；人工核验进行中，受业务理解所限断言质量存在风险。

## 本月主要进展

**进展 1：评测框架搭建完成。** 跑通"题目 → agent 执行 → `check.py` 判分 → 报告"全链路；改进沙盒以支持 **Linux 命令执行 + session 概念 + 并发**，为多 Case 并行评测提供基础。500 任务主评测集已成形（4 shard 并行造题，覆盖 13 个 EDA domain），Full 集 2,186 个 case。

**进展 2：真实 Trace 挖掘 Case。** 基于烛龙在长鑫 PDC / TYA 团队上线后的真实会话 Trace，挖掘并构建了一批 Case（Lite + Full）。针对烛龙自身与若干 LLM 评测集（doubao-pro / lite / mini + deepseek-v4-pro）跑评测，**可跑出符合预期的结果**（deepseek-v4-pro 单 run 21.78% / doubao-pro 3-run 10.18±1.18% / doubao-lite 4.68±0.77% / doubao-mini 2.39±0.19%；doubao-pro 对齐用户基准 10.5%，验证评测流程正确）。

**进展 3：人工核验启动。** Case 的人工核验正在进行，逐题审查任务形态、资产完备性、断言覆盖度。

## 当前问题

> 评测集仍处于初步构建阶段，以下三大问题需在后续迭代中解决：

**问题 1：断言数量虽充足，但难度不足。** 当前每 Case 的 `check.py` 断言条数达标（≥8 条，多在 15-16 条），但多数断言停留在"交付物存在 / 脚本能跑 / 格式正确"等表层检查，**对 agent 是否真正理解电路语义、是否正确处理边界条件的深度断言不足**。导致部分 Case 即使 agent 行为有缺陷也能蒙混过关，判分区分度不够。

**问题 2：受权限限制，部分 Case 资产无法访问。** 真实 Trace 中的部分 Case 涉及内部工艺数据 / 受限设计资产，agent 沙盒无法访问原始资产目录。当前采取"导出可离线复跑样本"的折中方案，但**部分 Case 的资产完备性受损**，影响评测真实性。

**问题 3：脚本类 Case 应从静态评估转向 EDA 服务器实跑。** 当前脚本类 Case 在开发服务器做静态评估（跑 `check.py` 看输出 JSON 字段对不对），但真实工程中脚本要在 **EDA 服务器上实跑**（调真实 pyAether / SKILL / Tcl 工具链）。静态评估能验证"脚本写对了"，但**验证不了"脚本在真实 EDA 环境里能跑通"**——后者才是评测本意。

## 风险与阻塞

**风险 1：人工核验速度较慢。** 500 任务逐题人工核验工作量大，当前核验进度跟不上造题速度，Case 入库后积压等待核验。

**风险 2：业务理解有限，断言质量存在风险。** 用户与几位实习生对电路设计各领域经验有限，**恐怕无法写出高质量的断言**——尤其是 analog / waveform / characterization 等深 domain 的语义级断言。这是问题 1 的根因，也是后续评测集质量的主要风险。

**风险 3：deepseek 3-run 未收口**（r2 跑中 / r3 待起，预计 11-24 上午全完）→ 阻塞 McNemar 配对检验 + 论文 §6 强模型对比段。

**风险 4：ICML 论文 §6 18 处 `\TBD` 待回填**（令纪律：3-run 出来先报数，等用户裁定才回填）。
