基座：deepseek-v4-pro-cloud · harness：cline CLI 3.0.51 · 数据集：EDA-Eval-PyAether-158（40 题长轨迹子集）· 协议：-p 8 -n、CLINE_THINKING=medium、LANG_HINT=空 · 2 臂 × 3 轮 ABBA 反平衡 · 日期：2026-11-12 · 预注册计划书：plan_zhulong_compaction_basic_vs_agentic_zh.html

① 摘要：三个核心问题

Q1：agentic 是否带来 ≥3pp 的稳定 Pass@1 增益？

否。agentic 不仅没有带来增益，反而造成 −10pp 的稳定下降（r1: 67.5%→57.5%, r2: 70.0%→60.0%, 每轮均为 −10.0pp）。配对分析显示 basic 独过 10 题、agentic 独过仅 1 题——agentic 的 LLM 摘要丢失了关键任务信息。

Q2：增益是否只存在于长会话（触发压缩的题）？

否。增益不存在，无论长会话还是短会话。但 agentic 的负面影响在长会话中更显著：agentic 的 gen_fail（超时/未完成）率更高（均值 12.0 vs basic 6.7），说明 LLM 摘要压缩后丢失上下文导致任务无法在超时内完成。

Q3：综合 token 成本与墙钟时间，默认策略应选哪个？

basic。basic 在 Pass@1 上高 10pp，且无需额外 LLM 摘要调用（零额外成本）。agentic 虽然总 token 稍低（~79M vs ~89M/轮，省 ~11%），但省的 token 不足以补偿 10pp 的 Pass@1 损失和更高的超时率。

一句话结论：agentic 压缩在 PyAether 长轨迹任务上造成稳定 −10pp Pass@1 下降，LLM 摘要丢失关键上下文；默认应选 basic。

② 机制与口径

2.1 两种压缩策略

维度basic（规则折叠）agentic（LLM 摘要）
实现纯规则、零额外 LLM 调用；保留最新 user prompt + 最近 3 条 assistant 回复，其余折叠；完全确定性额外一次摘要 LLM 调用；保留尾部 preserveRecentTokens + 结构化摘要（目标 / 当前状态 / 关键决策 / 下一步）；非确定性
compaction.json msg[0]逐字保留原始 user prompt（<user_input mode="act">...）LLM 生成 Context summary:\n\n## Goal\n...\n## State\n...
触发阈值（3.0.51 实测）~230K tokens（≈模型默认上下文窗口）~120K tokens（≈basic 的 50%，主动提前压缩）
⚠ 计划偏差（已在 P0d smoke 发现并记录）：预注册计划 §11 假设 cline 4.x 语义（maxInputTokens=32K 驱动触发阈值）， 但实测 cline 3.0.51 的触发阈值由策略内部逻辑决定，models.json 的 contextWindow=32000 被忽略。 basic 在 ~230K tokens 触发，agentic 在 ~120K tokens 触发——两者阈值不同，这意味着：
  • "同一触发点比较策略" 的设计意图无法在 3.0.51 实现；实际比较的是「不同触发阈值 + 不同压缩方法」的联合效应
  • agentic 触发更早 → 更多题会压缩 → 压缩触发率本身是策略差异的一部分（非混淆变量）
  • 外部效度受限：结论适用于 cline 3.0.51 的默认行为，不能直接外推到 4.x

6.2 效率-效果象限

成本-收益判定：「得不偿失」。agentic ΔPass@1 = −22.5pp（CI [−37.5, −7.5]，远低于 +3pp 判据），且每题墙钟 +12.5%、②类上下文丢失失败 10 例。其唯一优势是每轮 Token 省 ~12%（89.2% 压缩率 vs 69.7%），但省的 token 远不足以补偿 22.5pp 的 Pass@1 损失——按每通过一题的 token 单价算，agentic 反而更贵。

⑧ 结论与默认策略建议

三问明确结论

Q1（≥3pp 增益？）：否——agentic 造成 −10pp 稳定下降（r1: −10.0pp, r2: −10.0pp, 配对 McNemar χ²=7.11, p≈0.015）

Q2（只存在于长会话？）：否——无增益。但负面效应在长会话更显著：agentic gen_fail 均值 12.0 vs basic 6.7（+80%），说明摘要丢失上下文导致超时

Q3（默认策略推荐？）：basic——Pass@1 高 10pp、gen_fail 少 80%、无需额外 LLM 摘要调用。agentic 省的 ~11% token 不足以补偿

默认策略建议

条件建议
Δ ≥ +3pp 且 p<0.05，长轨迹同向agentic 设为默认；论文写「语义摘要保住任务状态，长轨迹收益最大」；保留 basic 作溢出恢复
Δ ∈ (−3, +3) 且 CI 跨 0证据不足；默认维持 agentic（成本可接受），写「未观测到显著增益」，不做宣传性表述
Δ ≤ −3ppbasic 设为默认；agentic 的摘要 LLM 调用引入噪声或丢信息，得不偿失

最终落在第 3 行（Δ ≤ −3pp）：basic 设为默认。agentic 的 LLM 摘要丢失关键 API 名/参数/设计规格，导致任务无法完成或判分失败。

D. 外部效度限制

  • 本实验在 cline 3.0.51 上进行；4.x 的 --compaction 语义可能不同（4.x 用 maxInputTokens 驱动触发，3.0.51 用策略内部阈值）
  • 触发阈值不是配置项（3.0.51 忽略 contextWindow），无法实现「同一触发点比较策略」的原始设计
  • 40 题子集从 158 题中按轨迹长度选取，偏向长轨迹任务——结论适用于「压缩可能发生」的场景，不代表人均短任务行为
  • 单基座（deepseek-v4-pro-cloud）——不同模型的摘要能力差异可能影响 agentic 效果
