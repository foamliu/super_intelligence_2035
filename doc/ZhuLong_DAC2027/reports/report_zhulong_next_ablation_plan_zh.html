4. 必做项详述（纯 CPU，立即可做）

A1 · 配对显著性检验（McNemar + paired bootstrap）必做

动机：论文所有消融比较仅报 mean ± std，无任何显著性检验。两个最关键的 claim 依赖小差距——(i) 执行闭环决定性：full(82.1) vs rag(71.8)，Δ=−10.3pp，看似远超 std，但无 p 值；(ii) 自探索增益：full(82.1) vs wo_selfexp(77.3)，Δ=−4.8pp，两者 std 完全重叠（3.0 与 2.9），审稿人必问"这是否统计显著"。检索移除 full vs wo_retrieval Δ=−1.1pp 更是远小于 std，必须显式说明"不显著"而非暗示有效。这是论文最致命的开放缺口。
做法 + 成本：从 5-run 的 retained traces 提取每任务×每轮的 pass/fail 矩阵（158 任务 × 5 轮 = 790 配对观测/臂）。对每对臂做：(a) McNemar 检验（基于 pooled pass/fall 列联表的配对二项检验，给出 χ² 与 p 值）；(b) paired bootstrap（对 158 任务重采样 10000 次，给出 Δ 的 95% 置信区间）。两者互补：McNemar 给单点 p 值，bootstrap 给 Δ 的区间。纯 Python（statsmodels / 手写 bootstrap），0 GPU，墙钟 ~4–6h 开发 + 跑全。
优先级：必做。这是审稿人首要质疑，且成本极低（纯 CPU，traces 已在位）。不做则论文多个 Δ 无法声称"显著"。
编排：纯 CPU，与 readback_binary r2–r5 及 B.glm-5.3-flash / B.deepseek-v4-flash 完全并行，不占沙盒不占 GPU。建议 10-16 启动，10-17 完成。产出可直接回填正文 Δ 句与表格脚注。
回填落点：tab:main-ablation / tab:phi-bound / tab:llm-comparison 各 Δ 列加 p 值脚注；正文 §6 "execution is decisive"、§4 "self-exploration gain" 句加显著性标注（显著 / 不显著 / 边缘）。关键诚实点：wo_retrieval Δ=−1.1pp 大概率不显著 → 应如实写"retrieval removal is not statistically significant on PyAether-only slice"，反而强化"execution > retrieval"的核心叙事。

A2 · Error Analysis 深挖（代表性 run 失败分类）必做

动机：论文 §error-analysis 用 full_v3 r3=81.6%(129/158) 代表性 run 提及 L4 violation（隐藏类型契约、内部 selection state），但分类是定性的、未给数量分布。审稿人会问"29 个失败到底分几类、各占多少、是否印证 grounding-gap 的 L1–L4 框架"。这是把理论框架（§4）与实证缝合的关键证据。
做法 + 成本：取 full_v3 r3 的 29 个失败任务的 traces（batch 2026_1012_071034，traces 在位），逐任务读 error_log / run_code 返回，按 L1（语法/API 名错）/ L2（参数/签名错）/ L3（语义/逻辑错）/ L4（设计状态相关：hidden type contract、internal selection、layout-dependent）四类人工归类，给数量表 + 2–3 条代表性 trace 原文片段。纯 CPU，0 GPU，墙钟 ~6–8h（含人工判读）。
优先级：必做。直接支撑 §4 grounding-gap 框架的实证性，是把"理论叙事"变成"有数据支撑的论证"的最低成本路径。
编排：纯 CPU，与主线评测完全并行。建议 10-17 启动（A1 完成后），10-18 完成。可与 C1（gen-fail 机制）合并做，共用 trace 解析脚本。
回填落点：§error-analysis 加失败分类表（L1–L4 × 数量 × 占比）+ 2–3 条 trace 证据；§4 grounding-gap 的 L4 原则从"定性提及"升为"29 个失败中 X 个属 L4"。

A3 · phi-bound 的 Converged / read-backs / gen-fail trace 解析必做

动机：tab:phi-bound 中 unbounded 与 lagged 两行的 Converged(%) 与 Mean read-backs 仍是 [TBD]（6_exp.tex:236）。k10/k3/k1 已有 gen-fail，但 Converged 与 read-backs 也未系统填。表格半空降低可信度，且 §8.4 要求"必须同步报告 Converged(%)"。
做法 + 成本：从 4 个 phi 臂的 5-run traces（k10/k3/k1/lagged 全部在位）+ full_v3 锚点 5 批，解析每 trace 的 finish_reason==completed（=Converged）与 run_code 调用次数（=read-backs），按臂汇总。脚本可复用 echo 数据收集（运维令二十四）已写的解析逻辑。纯 CPU，0 GPU，墙钟 ~3–4h。
优先级：必做。traces 全在位，成本极低，直接清掉 4 个 [TBD]，且 Converged 列是 §8.4 明文要求的。
编排：纯 CPU，与主线并行。建议 10-16 与 A1 同日启动（解析脚本类似），10-16 晚完成。

5. 建议项详述（含 GPU，主线收口后做）

B1 · readback_none (N′) fresh 5-run 重测建议

动机：N′ 档当前采信 legacy 73.3±2.2（5-run，Pass@1 可信），但其 echo 数据（run_code 次数 / 墙钟 / gen-fail）在早期 /home 磁盘危机已删，不可恢复，导致 tab:ablation-harness 与 tab:readback-cost 的 N′ read-backs 列恒为 [TBD]‡（脚注已注明 unrecoverable）。论文 §S1 的"保真度↓→收敛成本↑"单调论证缺了 N′ 这一档的 cost 证据，三档只有两档有 cost，论证链不完整。fresh 重测可同时（a）确认 Pass@1、（b）恢复 N′ 的 echo cost 数据补全单调证据。
做法 + 成本：切 set_s1_fidelity.py readback_none + stop.sh && start.sh → 跑 5 轮（每轮 ~1.5h，none 档回读最少 → 收敛最快）= ~7.5h GPU + 沙盒。判据同 readback_binary（判据十三：仅 timeout≤10 且无 infra 故障，Pass@1 任何值有效）。echo 数据收集复用运维令二十四脚本。
优先级：建议（非必做）。Pass@1 已有可信 legacy 值，但 cost 证据缺失使单调论证留缺口；GPU 早收口（10-18 后空闲）使成本可承受。若时间紧可降为 1-run 探路只补 cost。
编排：在 B.deepseek-v4-flash fresh 收口之后启动（~10-19），不与主线冲突。占 ~1 个 GPU 天。完成后 S1 三档（full/binary/none）echo 数据齐全，tab:readback-cost 三行全填。
回填落点：tab:ablation-harness (N′) read-backs 列 + tab:readback-cost N′ 行；§S1 单调论证补全"none 档 run_code 次数/墙钟"。

B2 · 锚点 full 在完整 EDA-Scripting-Bench（449 任务）re-run 1 轮建议

动机：论文反复声明"all figures are provisional, obtained on the PyAether-only slice, will be regenerated on the full EDA-Scripting-Bench"（6_exp.tex:32等多处）。截至投稿，没有任何一个数字来自完整 449 任务集（PyAether 158 + SKILL 158 + Tcl 133）。审稿人最可能质疑"你的 headline claim（执行闭环决定性、+10.3pp）是否只是 PyAether 切片的偶然"。哪怕只把锚点 full在全 bench 跑 1 轮，验证 82% 量级在 449 任务上仍成立，就能把"provisional"降级为"validated on full bench, single run"，极大增强论文可信度。
做法 + 成本：保留 full 配置，仅把评测集从 PyAether-only 切到完整 EDA-Scripting-Bench（449），跑 1 轮（不是 5 轮，控成本）。SKILL/Tcl 档需确认沙盒 run_code 的 lang=skill/tcl + host=virtuoso/waveview/innovus 端口就绪。墙钟 ~4h（449 任务比 158 多 ~2.8×）。0 额外 GPU 模型成本（用同一 backbone）。
优先级：建议。这是把论文从"切片 provisional"推向"全 bench validated"的性价比最高一步，且只需 1 轮。若 1 轮锚点在全 bench 量级吻合（~80%），论文可信度跃升；若显著偏离，也提前暴露风险。
编排：在 B1（readback_none）之后或并行启动（~10-20），占 ~1 个 GPU 天。不与任何主线冲突。⚠️ 前置：确认 SKILL/Tcl 沙盒端口健康（virtuoso/waveview/innovus），否则只跑 PyAether+SKILL 两档。
回填落点：新增一段"Full-bench validation"或在 §6 开头加一句"the anchor was re-measured on the full 449-task EDA-Scripting-Bench (1 run, X%), confirming the PyAether-slice findings generalize"；把正文多处 "provisional, PyAether-only" 的措辞软化。

7. 与 S1 / B 主线的编排原则

  1. 评测优先纪律不变：所有"必做"项（A1/A2/A3）纯 CPU，与主线 readback_binary r2–r5 + B.glm-5.3-flash + B.deepseek-v4-flash 完全并行，绝不抢占沙盒端口或 GPU。
  2. 主线 GPU 收口后才动"建议"项的 GPU：B1/B2 的 GPU 占用排在 B.deepseek-v4-flash fresh 之后（~10-19 起），保证不延后任何主线臂。
  3. 切配置纪律：B1（readback_none）切配置必须 set_s1_fidelity.py readback_none + stop.sh && start.sh 串行 &&，核对 .env（OMEGA=high/READBACK=none/phi=0/0/核心4工具ON）；切回锚点时反向复位。B2 不切 set_ablation（保持 full），仅切评测集参数。
  4. 判据十三常驻：所有消融臂 Pass@1 任何值有效，仅 timeout≤10 且无 infra 故障为作废理由；不因低分重跑。
  5. 数字同步纪律：回填论文 Δ 列与正文同一数字必须同步改（README §6.1），A1 出 p 值后若某 Δ 改判"不显著"，正文相应句必须同步软化。
  6. 每轮唤醒 commit+push：每完成一个建议项即 git add doc/ZhuLong_DAC2027/{run,ZhuLong_DAC2027} + commit（前缀 zhulong plan: / zhulong S1-echo: / zhulong paper-fix:）+ push，不依赖 loop 兜底。
