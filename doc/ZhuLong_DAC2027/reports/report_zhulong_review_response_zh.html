1.1 意见 #1 — 理论 overclaim（Critical）

意见摘录："Section 4 defines a grounding gap using Bayesian inference and then posits D_grounding ≤ g(ε) … the draft explicitly calls this a prediction, not a theorem … The theoretical contribution is an intuitive hypothesis expressed in Bayesian notation rather than a demonstrated result."

判定：已落实（正文）/ 待改（摘要措辞）

证据位置： 4_grounding.tex:56、7_discussion.tex:4、0_abstract.tex:14-16

正文对照（已落实）：

（评审所见旧版，推测）Lemma：D_grounding ≤ g(ε)，由标准 POMDP 模型近似结果可得 …

（现行 4_grounding.tex:56）Claim (observation-fidelity bound). … We posit that D_grounding ≤ g(ε), with g(ε)→0 as ε→0 and g independent of the complexity of the prior K: the grounding gap is bounded by observation fidelity, not model scale. We state this as a prediction the experiments can test rather than a theorem derived here; the next paragraph tests it from both sides.

评审推荐的两条出路（"formal proposition + proof" 或 "call it a framework / conceptual hypothesis"）——本文已选第二条：以 Claim 命名、显式声明"prediction … rather than a theorem"，且 §7 Discussion L4 改写为"a paradigm that may generalize"，措辞已收敛为框架性而非定理式。

摘要待改（§1.1 待改项）：

（0_abstract.tex:14-16 现行）… with a theoretical grounding showing EDA correctness is a situated property whose "grounding gap" a Bayesian argument bounds by observation fidelity, not model scale.

（拟改）… with a grounding-gap framework that recasts EDA correctness as a situated property and proposes—as a testable claim rather than a proven bound—that the gap is set by observation fidelity, not model scale; the experiments test this claim from both the observation and prior axes.

理由：评审明确允许"the title and abstract can remain ambitious, but the wording must accurately reflect the evidence"。把"theoretical grounding showing … bounds"改为"framework … proposes as a testable claim"与正文 §4.2 Claim 的措辞一致。

1.2 意见 #2 — 57.4pp 归因错误（Critical）

意见摘录："The abstract and introduction say the observation ladder improves Pass@1 by 57.4pp with the LLM fixed. However, Table 3 reports … full-observation vs no-read-back is 13.5pp, not 57.4. The 57.4-point figure is the difference between the full system and the pure-LLM baseline, which changes more than observation alone. … Correct the abstract, contribution bullets, Section 4.2, and Section 6.2.1."

判定：部分落实（§4.2、§6.2 已分；摘要未分）

证据位置： 4_grounding.tex:59、6_exp.tex:50、0_abstract.tex:18-21

正文对照（已分）：

（4_grounding.tex:59）The read-back ladder (N' → B → F, Table~\ref{tab:omega}) manipulates ε from large to small with retrieval and effector fixed, and the monotone accuracy gain (13.5pp, N' to F) reflects g(ε)'s monotonicity under a single-variable slice; the system-level ε axis—pure LLM with no observation to the full system—spans 57.4pp.

（6_exp.tex:50）Relative to the full system, removing execution costs 13.2pp pooled, removing retrieval 11.8pp, and removing self-exploration 3.1pp; against the pure-LLM floor the full system gains 57.4pp.

三组数字已分别在 §4.2 与 §6.2 显式分开：13.5pp = 受控回读轴（N'→F，单变量切片）；3.3pp = B−N'（二值反馈档，评审 §57 推荐补充的数字，现行正文未单列，见下）；57.4pp = 系统级 ε 轴（Pure-LLM 18.3 → Full 75.7）。

摘要待改（§1.2 待改项）：

（0_abstract.tex:18-21 现行）ZhuLong reaches 75.7% pooled Pass@1 vs. 18.3% (pure LLM) and 62.5% (retrieval-only); with the LLM fixed, the observation-fidelity axis (no observation → full observation) spans 57.4pp, versus 22.0pp for the backbone axis.

（拟改）ZhuLong reaches 75.7% pooled Pass@1 vs. 18.3% (pure LLM) and 62.5% (retrieval-only); the controlled read-back ladder (no read-back → binary → full observation, LLM fixed) spans 13.5pp, the binary-feedback rung adds 3.3pp over no read-back, and the system-level observation axis (pure LLM → full system) spans 57.4pp—versus 22.0pp for the backbone axis.

理由：评审明确要求"Separate the controlled read-back comparison from the overall system-versus-baseline comparison"。改后摘要同时给 13.5pp（受控）、3.3pp（B 档）、57.4pp（系统级），三组数字与其来源一一对应。

注（3.3pp 推测标记）： 评审 §57 给出 B = 65.5、N' = 62.2 → B−N' = 3.3pp。本文 zhulong_results.md 与 Table 3 显示 B=65.5、N'=62.2，3.3pp 为算术核对结果（非新实验）。摘要拟改文本中加入此数以完整回应评审 §57 的"binary-feedback effect as 3.3 points over no read-back"。

1.3 意见 #3 — benchmark 不可独立验证（Critical）

意见摘录："EDA-Scripting-Bench contains 449 tasks derived from non-redistributable vendor documentation. The draft explains the task schema and assertion-based scoring, but readers cannot readily inspect the full task set, reproduce all commercial runtime behaviors, or verify that the assertions adequately capture the intended design changes."

判定：待改（§5 无 release 声明）

证据位置： 5_bench.tex 全 44 行——已写 schema、4 切片组成、协议；未写 release / licensing / 可复现子集 / 评估 harness 可得性。

拟补段落（加在 5_bench.tex 末尾，新 §5.5 Release and reproducibility）：

\subsection{Release and reproducibility}
The full 449-task set derives from non-redistributable vendor documentation and cannot be released wholesale. We release what licensing permits: (i) the task schema, natural-language prompts, function signatures, and assertion specifications for all 449 tasks; (ii) the evaluation harness, PreToolUse hook, and configuration files for all five ablation configurations; (iii) anonymized execution traces for the 291-task audited subset (SKILL + two Tcl hosts); and (iv) a fully reproducible public subset of 30 PyAether tasks whose APIs are documented in the public Empyrean Aether Python reference and require no vendor-internal context. Independent researchers can reproduce (iv) end-to-end with the released harness; (i)–(iii) let them inspect every assertion and re-score the released traces. Assertions were designed by EDA experts to be self-contained and executable in a clean sandbox, and each assertion was independently reviewed by a second expert; a task passes only when code executes without errors and all assertions hold, so a plausible-but-incorrect implementation that does not produce the asserted design change fails. What cannot be independently reproduced is execution against the live commercial runtimes, which requires authorized vendor access—this is a licensing limit, not an algorithmic one.

证据锚： "30 PyAether 公开子集"为推测性承诺——本文 zhulong_results.md 未单列此子集，需用户确认是否真有 30 个仅依赖公开文档的 PyAether 任务可释放。若不可，应改为"我们正与厂商协商释放一个 PyAether 公开子集"。待用户拍板可释放任务数。

1.4 意见 #4 — 对照面太窄（Major）

意见摘录："The main experiments compare ZhuLong against a pure LLM and several component ablations, including retrieval-only RAG. This establishes that the complete harness is better than those configurations under the selected protocol, but it does not clearly establish superiority over the most relevant existing EDA agents or alternative execution-grounded coding systems."

判定：已防御（结构性限制）+ 部分落实（语义对齐）

证据位置： 6_exp.tex:41、2_background.tex:10

现行防御（6_exp.tex:41）：

… no third-party agent can execute these runtimes without the MCP bridge, so baselines are tool-registration ablations of the same fixed harness—which makes single-variable attribution possible.

这是结构性限制而非疏漏：四个商业运行时（Empyrean Aether / Cadence Virtuoso / Synopsys WaveView / Cadence Innovus）均需授权访问，ChatEDA / MCP4EDA / AutoEDA 等公开 EDA agent 仅支持开源工具链（Yosys / OpenLane / OpenRoad，见 2_background.tex:10），物理上无法在本文 benchmark 上运行。评审推荐的"retrieve–execute–repair loop"与"general-purpose coding agent with equivalent tool access"——本文 w/o Self-Expl. 配置（检索+沙盒、无离线自探索）即 retrieve–execute–repair；RAG 配置即 retrieval-only。ZhuLong Full = retrieve + execute + repair + offline self-exploration，与 w/o Self-Expl. 的差（+3.1pp pooled）正是"加了离线自探索的 retrieve–execute–repair"相对于"裸 retrieve–execute–repair"的增量。

拟补一句（加在 6_exp.tex:41 末尾）：

The w/o-Self-Exploration and RAG configurations operationalize the retrieve–execute–repair and retrieval-only baselines the reviewer requests; their gap to ZhuLong (Full) isolates the offline-self-exploration increment under the same tool access and execution budget, which is the controlled comparison the protocol permits.

评审 §79 推荐的"stronger iterative baseline with the same execution-call budget"对应本文 S2 的 budget-k 扫描（6_exp.tex:68，k=1/3/10 + lagged channel）——已展开。不再单加新基线。

1.5 意见 #5 — 组件贡献不均匀（Major）

意见摘录："The full system does not win every slice. On SKILL, ZhuLong scores 60.3%, below the 61.5% reported without offline self-exploration. On PyAether, removing retrieval barely hurts … The paper itself notes that toolchain-specific effects vary substantially."

判定：已落实（叙述）+ 待改（Wilson CI）

证据位置： 6_exp.tex:56、6_exp.tex:62、6_exp.tex:105、7_discussion.tex:7

现行正文（已写）：

  • 6_exp.tex:56：PyAether 上回读通道可替代检索（86.7% trace 用 dir()/inspect/__doc__ 沙盒内省），故 w/o Retrieval 在 PyAether 反升（81.0 vs 81.4）——已解释为"检索只是 Ω 的一种实现而非通道本身"。
  • 6_exp.tex:62：自探索是"cost-negative rung"，移除检索使 agent 退化为盲探沙盒（2.3× 时间）。
  • 6_exp.tex:105：SKILL 上 Full 落后 w/o-Self-Expl. −1.2pp，明确披露；各切片组件幅度差异（execution +26.4pp on SKILL vs +2.6pp on Tcl；retrieval redundant on PyAether but +21.3/+14.1pp on SKILL/Tcl）已逐项列出。
  • 7_discussion.tex:7：self-exploration +3.1pp 已明确定性为"complementary, not headline"。

评审推荐"reframe as generally effective architecture with toolchain-dependent component value, rather than implying every component is individually necessary in every setting"——本文 §6.3 L105 已用"the structure (observation and execution jointly closing the loop) is shared"措辞做了 reframe，但摘要仍称"retrieval, documentation inspection, and sandbox execution … into a closed loop"未明示组件并非处处必需。建议在摘要不动（空间紧），在 §6.3 末加一句强化 reframe。

拟补一句（加在 6_exp.tex:105 末尾）：

The contribution is thus a generally effective architecture whose component magnitudes are toolchain-dependent; on PyAether the read-back channel substitutes for retrieval, and on SKILL the offline-self-exploration increment is locally negative, but the joint observation+execution loop is shared and reproduces on every slice.

Wilson CI（待改项）： 评审 §128 明确要求"confidence intervals and paired comparisons"。本文现行 5 配置 × 5 run 仅报 mean±s.d.，未给 CI。拟在 6_exp.tex:50 主结果句后加一句：

Wilson 95% intervals on the pooled Pass@1 are Full [72.7, 78.5], RAG [58.6, 66.2], w/o-Self-Expl. [69.4, 75.4], w/o-Retrieval [72.0, 78.0], Pure-LLM [15.0, 21.8]; the controlled N'→F read-back gap 13.5pp has a paired bootstrap 95% interval [8.2, 18.4]pp.

注（待重新跑统计）： 上述 Wilson / bootstrap 数值为占位推测，需用 zhulong_results.md 的 5-run 原始数据重算后填入。本轮未跑统计脚本，标 待改。
