0. 一句话目标

S2 只动 Φ（信念更新） 一个轴，固定观测 Ω 与先验 K：一条锚点（unbounded ≡ full）＋ 三条 k 预算＋ 一条 lagged 滞后。 本轮为 1-shot 探路，跳过锚点，只跑 4 个新臂（k10 → k3 → k1 → lagged），各 1 轮，用于验证预算 hook 计数正确、lagged 滞后量精确为 1、并产出 tab:phi-bound 的 provisional 首值。

2. 探测路径实验组成（4 臂 + 1 跳过锚点）

臂改什么README 表状态
Φ unbounded无预算上限（≡ full 基线）tab:phi-bound unbounded跳过 ✅ 84.8%（=full）
Φ k=10hook 限 run_code ≤ 10 次tab:phi-bound k=10本轮
Φ k=3hook 限 run_code ≤ 3 次tab:phi-bound k=3本轮
Φ k=1hook 限 run_code ≤ 1 次tab:phi-bound k=1本轮
Φ laggedhandler 返回上一拍状态（L=1）tab:phi-bound lagged本轮

执行顺序：k=10 → k=3 → k=1 → lagged，各 1 轮。 理由：先 k=10（预算宽松，验证 hook 计数正确、不误杀）再逐档收紧到 k=1，最后跑机制独立的 lagged。

3. 语义约束（最易做错，逐字遵守）

  • ① 预算约束的是「agent 能执行/观测多少次」，绝不是「agent 何时必须提交」。
  • ② 实现 = 工具边界拒绝调用（agent 收到 error 继续自主运行）；严禁中断 trace / 改写任务 / 逼 agent 提前提交——一旦改变终止行为，测到的就是「人为干预」而非 Φ。
  • ③ 必须同时报告 Converged (%)（=finish_reason == completed 的 trace 占比），且紧挨 Pass@1；否则紧预算造成的提前停止会被误读为「收敛」。
  • ④ lagged = 滞后 1 次执行：第 n 次 run_code 返回第 n−1 次状态，第 1 次返回「尚无先前状态」占位；用单槽缓冲（非队列），元数据记 reported_call_index 以便审计滞后量恰好 = 1。
  • ⑤ 预算 hook 错误信息必须带唯一前缀 [PHI-BUDGET-EXHAUSTED]——Cline 多 hook 引擎对 cancel 做 OR 合并、对原因做换行拼接，无前缀就无法区分是反作弊 hook 还是预算 hook 拒的。
  • ⑥ 若 L=1 测不出效应再上 L=2，并在正文如实报告「L=1 无效应」；本轮探路先用 L=1。

4. 代码前置依赖 / 阻塞项

阻塞项：以下 4 项是「切配置后生效」的前提。经核对当前 harness（eda_fastmcp），尚未实现——仅 scripts/set_ablation.py 与 scripts/cline_hooks/PreToolUse（反作弊）存在；set_s2_phi.py、预算 hook、lagged 缓冲均缺。跑之前必须补齐。
#依赖要求
1scripts/cline_hooks/PreToolUse在现有反作弊 hook 之外追加 Φ 预算计数（两者共存，不得破坏反作弊）：同 trace 内对 run_code 计数（按 session/trace id 归零），超 k 返回 {"cancel": true, "errorMessage": "[PHI-BUDGET-EXHAUSTED] k=<N>"}；拒绝落到 trace 元数据 denied_by_hook / deny_reason。
2tools/run_code.py支持 EDA_PHI_LAGGED=1：单槽缓冲返回上一拍状态（第 1 次回「尚无先前状态」占位），记 reported_call_index；缺省 0（关闭）。
3scripts/set_s2_phi.py <ARM>ARM ∈ {phi_unbounded, phi_k10, phi_k3, phi_k1, phi_lagged}：写 .env（EDA_PHI_BUDGET=<N> / EDA_PHI_LAGGED=0|1）并启用/停用预算 hook；缺省 unbounded。
4trace 元数据采集 finish_reason、run_code_calls、denied_by_hook、deny_reason、reported_call_index（README §4）。否则 Converged (%) 与滞后量无法核对。

5. 开跑前 canary（每批一次；不通过 → 立即停，本批作废）

  • 故意触发一次应被拒绝的调用（run_commands 或读写工作区外路径），确认真被拒；若未拒 → 停止退出。
  • k=10 开跑前：故意让 run_code 超预算一次，核对 deny_reason 含 [PHI-BUDGET-EXHAUSTED] 且不与反作弊拒绝混淆。

6. 打分与 S2 专属核对（缺一不可）

  • Converged (%)：finish_reason == completed 占比（紧挨 Pass@1 记录）。
  • k 臂（k10/k3/k1）：统计 deny_reason 含 [PHI-BUDGET-EXHAUSTED] 的 trace 数 > 0（证明预算 hook 确实拒过），记 run_code_calls 均值（Mean read-backs）。
  • lagged 臂：核对 reported_call_index 与真实调用序号差 == 1（滞后量恰好为 1），否则该臂作废。

7. 预计耗时（估算，待首臂实测后校准）

单臂一轮30–90 分钟158 任务 / 8 并发 / 单 trace / 无重试；full 约 24 工具调用·trace⁻¹，run_code 沙盒执行为主延迟项；k=1 最快、k=10 接近无界。

8. 红线

  • 反作弊 PreToolUse hook 全程启用、各臂完全一致——它是冻结变量，不是消融对象。
  • cimi_search / cimi_fetch / vqa 永远关闭，不要碰。
  • 各 hook 的 errorMessage 必须用唯一前缀区分，否则归因错标。
  • 不填臆造值：未测保持 [TBD] 或显式 provisional；± 只加在 Pass@1 上。
