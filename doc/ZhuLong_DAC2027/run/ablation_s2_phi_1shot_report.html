3. 关键发现

  • Pass@1 随预算单调上升：60.8 → 69.0 → 75.3 → 84.8。相邻增量 +8.2 / +6.3 / +9.5pp，暂未观测到「饱和」——k=10 仍显著低于无界（−9.5pp），需 5 轮重测确认，或需更高 k 档。
  • lagged（L=1 观测滞后）几乎无损伤：修复 trace_key per-task 隔离后 r2 出分 84.2%（Converged 98.1%），仅比 unbounded（84.8%）低 0.6pp——「落后一拍」对迭代式代码调试几乎无害，与「执行预算 k」的 24pp 量级形成鲜明对比。滞后量审计：0 index-mismatch（跨任务串槽已修）、133/158 trace 的 reported_call_index 精确满足差==1；其余 25 trace 的缺报均为 MCP 超时/入参校验/幻觉工具名（非滞后机制缺陷）。
  • Converged 单调上升：71.5 → 79.1 → 91.1（unbounded 待补齐）。预算越紧，agent 在预算耗尽后持续 no-op 超额重试、最终自行终止的比例越高（cancelled 14→33→45），这正是「紧预算 ≠ 提前收敛」的实证。
  • 语义约束守住：终止权始终在 agent 手里（overrideInput「改写不中断」），cancelled 均为 agent 自身终止、而非 hook 中断；deny_reason 带唯一前缀 [PHI-BUDGET-EXHAUSTED]，与反作弊拒绝可区分。
