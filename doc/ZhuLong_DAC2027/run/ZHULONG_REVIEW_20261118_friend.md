## 文档 A · 两份文档的综合评价

先说总体判断：这两份材料是一套相当成熟、纪律性很强的研究方案——从「卖 bench」转向「检验可证伪的认知命题」这个重定位是对的，v1.4/v1.6 的三层假设结构和机制级负对照设计在方法论上明显强于一般的 agent 记忆论文。但存在几个结构性风险，其中至少一个可能在 ICML 审稿中直接致命。下面分层说。

### 一、做得好的地方（真实优势，不是客套）

1. **重定位诊断准确。** 计划书 §2.1 指出的三条硬伤——trace 不可开源、bench 社区价值被削弱、10.0% 单点数字会过期——都是真问题。把主线从「评测集本体」换成「记忆+RSI 在长链编排上的可证伪收益与边界」，让命题在数字过期后仍是长效贡献，这个逻辑成立。

2. **杀手级对照 N1 的设计是全文最关键的增量。** 「等 token 预算的无关填充」直接堵住审稿人最常用的反驳（"你只是给了更多上下文"）。DATE27 没做这个对照，新论文补上，是实质性方法论进步。N2（错误/无关记忆）与 M8（负效价偏倚）两个负对照方向也对。

3. **机制级假设 H2a/H2b/H2c 的「合取消解 + 部分机制有效」处理是诚实的。** 三条机制全部证伪才否定 H2，1–2 条存活写「部分机制有效」——这避免了「一荣俱荣一损俱损」的过度声称，是预注册纪律的正确用法。

4. **诚实路线写得到位。** 「若 H1 证伪 → 写成 RSI 在长链 flow 的边界条件」这句如果真兑现，本身是可发表的认知贡献。DATE27 的 +2.5pp 在 40 题上只是信号（6_conclusion 自己承认 modest challenge test set），flow 层是否复现本就是经验问题。

5. **开源边界 v1.4 收缩是理性决策。** 用户判断「Lite 500 题 + mock-EDA 开源费力不讨好」是对的：mock 沙盒复现不了 physical_verify 2.9% 的 DRC/LVS 真实 grounding depth，开源后差异化优势自降。改为「协议白皮书 + NDA 评审包」更轻也更可信。

### 二、结构性风险（按严重程度排序）

#### R1（最高危）：H1c「记忆是 RSI 的前提」的证伪条件设计有逻辑漏洞

H1c 的判据是 S1 ≤ M0（无记忆时自改进无收益）。但 S1 臂的定义是「每 session 内 in-context 自改进，session 结束即丢弃」。问题在于：单次 run 内部的 in-context learning 本身就构成一种「短期记忆」，S1 在 session 内生成的技能会被同 session 复用——这恰恰是 DATE27 单脚本层 +2.5pp 的机制来源之一。所以 S1 ≈ M0 很可能不成立，不是因为「记忆不是前提」，而是因为 session 内记忆已经足够。

**建议**：H1c 的陈述应精确化为「跨 session 长期记忆是 **跨 session RSI** 的前提」，并在 S1 臂明确禁止任何 session 间持久化（包括 harness 层的文件残留）。否则 H1c 可能被一个定义模糊的 S1 臂「伪证伪」，浪费 480 run。

#### R2（高危）：最小矩阵 120 题 × 1 trace 的统计功效不足以支撑任何 3pp 结论

计划书 §5.3 自己诚实写了「120 题下 McNemar 双侧 α=0.05 功效 ≈ 0.62」。但 0.62 的功效意味着 **40% 的真效应会被漏检**——如果 H1a 真实效应是 3pp，你有近一半概率得到 p>0.05 然后写成「记忆无增益」。更麻烦的是 H2b 的判据是 3pp 且带「记忆库 ≤0.6×」的联合条件，M7 vs M2 在 120 题下几乎不可能同时满足两个条件还达到显著。

**建议**：要么把最小矩阵抬到 200 题/臂（成本可控，8 workers 下 M3+N1+... 约 30h），要么在论文里把 120 题结果明确定位为「pilot signal，不作结论」并在 abstract 里就不报具体 pp 数字。**最危险的做法是 120 题跑出 2.1pp 就写成「H1a 部分支持」**——这会毁掉预注册纪律的可信度。

#### R3（中高危）：M4 迁移臂与 N2 的区分在实现上可能坍缩

M4（训练域写→目标域只读）和 N2（注入错误/无关记忆）都依赖「记忆内容审计」来判断是「抽象认知」还是「题面答案缓存」。但审计标准是人工逐条判「抽象 vs 答案片段」，这在 120 题 × 数百条记忆上不可扩展，且 inter-annotator agreement 未设计（原文提到 Cohen's κ 但只在 failure taxonomy 那里 deferred）。

**建议**：M4 的泄露率审计需要一个机器可判的代理指标，比如「记忆条目中是否包含目标域任务的 prompt 子串 / 文件名 / 断言字面量」，用 n-gram 重叠率自动判泄露，人工只审 borderline。否则 M4 的「泄露率=0」判据在审稿人眼里是未经验证的声称。

#### R4（中危）：情绪机制的三条映射有「生物隐喻过载」风险

审稿人（尤其 ICML 的 ML 背景 AC）很可能问：「你的三个机制和已有的 retrieval-augmented / importance-sampling / context-compression 方法在计算上有何本质不同？」

- 惊奇度门控 ≈ priority sampling by prediction error（Generative Agents 的 importance score 已做）
- 武器聚焦压缩 ≈ error-stack-only logging + root-cause extraction（工程上常见）
- 状态感知检索 ≈ query rewriting with conversation state（RAG 里已有）

论文目前靠「首次在真实 EDA flow 上预注册检验」来差异化，但这是 **setting 差异不是方法差异**。**建议**：在 §4.5.1 的公式旁边加一段「与最近邻方法的计算差异」：比如 surprise 用的是 KL(posterior∥prior) 而非 embedding 距离，penalty 项是 sunk-cost 而非固定权重——把这些差异写成可消融的子变量（α/β 扫描已在 M5 里，但没说明扫描的是「机制贡献」还是「超参」）。

#### R5（中危）：696-run 快照的 M0 锚点与 120 题最小矩阵的子集不一致

计划书说「最小矩阵取 top-120 by chain length」，但 M0 锚点 10.0% 是 696-run 全集的 62/620。120 题子集的 M0 Pass@1 很可能显著偏离 10.0%（长链任务更难，top-120 by chain length 的 M0 可能只有 4–6%）。如果直接用 10.0% 作 M0 锚点去对比 M3 的 120 题结果，**基线口径就错了**。

**建议**：在最小矩阵里必须重跑 M0 在 120 题子集上的 Pass@1，或者明确写「M0 锚点 = 同子集实测值，非 696-run 的 10.0%」。§5.4 表格里「M0 引用快照」那一行需要改。

### 三、细节问题（不影响录用但应修）

1. 摘要里 "7.6× drop" 与 "7.1× domain gap" 的并置容易误读——前者是 script→flow 的跨任务难度，后者是 flow 内部域间差异，建议在 abstract 里加半句区分。
2. H2b 的判据「M7 ≥ M2 + 2pp 且记忆 ≤0.6×」是联合判据，但证伪条件写的是「M7 < M2−2pp **或** 记忆 ≥0.8×」——**中间地带（记忆 0.6–0.8×，Pass@1 持平）没有归属**。建议明确记为「弱支持」并单独定义。
3. 表 5 的 UNK 列合计 **119** 与正文 **49** 不一致（正文说 FAIL-with-submit UNKNOWN 49 跑，表 5 的 UNK 是 119，含 ERROR-status 的 aborted）。应加脚注说明两个口径。
4. 参考文献里 **DATE27 是 PLACEHOLDER**，ICML 截稿前必须落实；否则 Related Work 的「继承 DATE27 方法骨架」这一核心叙事缺引用支撑。

### 四、一句话结论

方案的方法论骨架（预注册 + 三层假设 + 机制级负对照 + N1 杀手对照 + 诚实负结果路线）已经达到 ICML 可投水平，重定位判断正确。**但 H1c 的定义漏洞、120 题的功效不足、M0 锚点子集不一致这三处必须在跑实验前修掉**——它们不是写作问题，是会直接导致「跑完 480 run 才发现假设设计有歧义」的资源浪费。情绪三机制需要在 Related Work 里补一段「与最近邻方法的计算差异」，否则 setting 差异撑不起 contribution 列表的第 5 条。

**如果只能改一件事**：先修 H1c 和 M0 锚点口径，这两个是实验设计的地基，改晚了所有臂的数字都要重跑。

## 文档 B · sub-hypotheses 和 ablation 是否太多了

### 结论先行

**sub-hypotheses 不多**（3+7 的结构是合理的），但 **ablation 确实偏多**（13 臂对一个 ICML 单篇投稿过重）。真正的风险不是「数量」本身，而是 **臂数与假设的对应关系存在冗余和失衡**——有 3 个臂在最小矩阵里根本跑不出可解释的结论。

### 一、Sub-hypotheses：7 条不多，结构是对的

3 核心 + 7 子（H1a/b/c · H2a/b/c · H3）这个「总–机制–边界」三层结构在方法论上是标准且内聚的：

- **H1 的三个子假设**各管一个必要侧面（功能级增益 / 链长单调性 / 记忆-RSI 依赖），析取消解「任一证伪即否定总命题」逻辑自洽。
- **H2 的三条机制**一一对应三个可计算公式（Eq.1/2/3），合取消解「全证伪才否定」，允许「部分机制有效」——这是预注册纪律的正确用法。
- **H3 独立标注**「附论、与 H1/H2 独立证伪」，避免了读者误以为它是前提。

7 条子假设对应 3 个核心命题，平均 2.3 条/核心，没有为了凑数而拆分的痕迹。ICML 审稿人对「预注册 + 每条带证伪条件 + 统计检验明确」的组合通常是正面的，数量本身不构成负担。

**唯一要动的是 H1c 的措辞**（上一轮已提）：S1 ≤ M0 作为「记忆是 RSI 前提」的判据有定义漏洞——session 内 in-context learning 本身就是短期记忆，S1 很可能不 ≈ M0。建议把陈述精确化为「跨 session 长期记忆是跨 session RSI 的前提」，并在 S1 臂明确禁止任何 session 间文件残留。这是**表述精度问题，不是数量问题**。

### 二、Ablation：13 臂偏多，且有 3 个臂在最小矩阵里「跑不出结论」

13 臂（M0/M1/M2/M3/S1/M3+S1/N1/N2/M4/M5/M6/M7/M8）的问题不在总数，而在**臂与假设的映射有冗余、成本与功效不匹配**。逐个看：

#### 2.1 冗余臂：M1 和 M2 对 H1 的边际贡献很低

**M1（静态 SOP 记忆）**：判据是 M1 ≥ M0 + 2pp。它回答的是「人工 SOP 有没有用」，但 H1a 的主判据是 M3 ≥ M0 + 3pp，M1 既不是 H1a 的主对照（主对照是 M0 vs M3），也不是任何机制假设的载体。它唯一的叙事价值是「自动记忆是否优于人工 SOP」（M2 vs M1），但这一条没有写成任何子假设。
→ 建议：要么把「M2 vs M1」升格为 H1a 的一个子判据（那 M1 就有归属），要么把 M1 降为附录/消融补充，不进主臂表。

**M2（自动记忆无门控）**：对 H1a 是 M2 ≥ M0 + 2pp 的弱对照，对 M3 是 M3 ≥ M2 + 1pp 的门控收益检验。但 **1pp 在 120 题下完全无功效**（§5.3 自己说 3pp 功效才 0.62，1pp 基本是噪声）。M2 真正的用途是作为 M5/M7 的对照组（惊奇门控 vs 均匀采样、压缩 vs 全量），这在 H2a/H2b 里已经有明确定位。
→ 建议：M2 只作为 H2a/H2b 的对照臂存在，**删掉它作为 H1a 弱对照的判据**（M2 ≥ M0+2pp 和 M3 ≥ M2+1pp 两条判据撤掉），否则会出现「M2 跑出 +1.8pp 算不算支持 H1a」的歧义。

#### 2.2 功效不足臂：120 题最小矩阵下，M5/M6/M7 的机制判据几乎不可能显著

| 臂 | 判据 | 120 题下可行性 |
|---|---|---|
| M5 vs M2 | ≥3pp，等 token | 3pp @ n=120 功效 0.62，勉强；但要「记忆库 token 差 ≤10%」的联合条件进一步压低功效 |
| M6 vs M3 | 失败子集 ≥3pp，失败子集 ≥40 题 | **n=40 子集上检测 3pp，功效 <0.3，基本不可能显著** |
| M7 vs M2 | ≥2pp 且记忆 ≤0.6× | 2pp @ n=120 功效 ~0.4，联合条件更严 |

**M6 在最小矩阵里实际上跑不出结论**——失败子集只有 40 题，3pp 差异的功效不到 0.3。这意味着即使机制真的有效，你大概率得到 p>0.05，然后按预注册写成「H2c 证伪」——**这是假阴性，比假阳性更伤**，因为它会把一个真机制误判为无效并写进论文。

→ 建议：最小矩阵要么把 M6 的失败子集抬到 **≥80 题**（即总题量 ≥240，按失败率 1/3 反推），要么明确把 M6 定位为「理想矩阵才检验的机制臂」，最小矩阵只跑 M5/M7。**不能既跑 40 题子集又用 3pp 阈值。**

#### 2.3 边界臂：M8 是可选臂，别进主表

M8（负效价偏倚）原文已标「可选」。它的判据 M8 ≤ M6 是单向的（只证「过度防御有害」），即使成立也只支持「状态感知收益不来自偏负」这个弱结论。
→ 建议：M8 放附录，不进 13 臂主表。主表放 12 臂，M8 作为 robustness check 单独报。

#### 2.4 真正不能删的臂

- **M0（基线）、M3（H1a 主判据）、N1（杀手对照，全文最关键）、M3+S1 + S1（H1b/H1c 的 2×2 析因，四个格缺一不可）** —— 这 6 个臂是骨架，删任何一个假设都塌。
- **M4（迁移污染检验）** —— 它是「记忆是抽象认知还是答案缓存」的唯一直接检验，且直接回应审稿人最可能的攻击（跨题污染）。保留。
- **M5/M6/M7** —— H2 的三条机制，各对应一条子假设，删了 H2 就空了。

### 三、建议的收敛方案

**方案 A（推荐，改动最小）：13 → 10 臂主表 + 3 臂附录**

- 主表 10 臂：**M0 · M3 · S1 · M3+S1 · N1 · N2 · M4 · M5 · M6 · M7**
- 删 M1、M2 的主表身份（M2 仅作 M5/M7 的对照，在 H2a/H2b 结果表里出现，不进总臂表；M1 移附录）
- M8 移附录
- 撤掉 M2 作为 H1a 弱对照的两条判据（M2≥M0+2pp、M3≥M2+1pp）
- 对应假设映射变成干净的一对多：
  - H1a → M0 vs M3，N1 排除
  - H1b/H1c → {M0, M3, S1, M3+S1} 2×2
  - H2a → M5 vs M2（M2 作为对照出现）
  - H2b → M7 vs M2
  - H2c → M6 vs M3
  - H1+H2 可迁移性 → M4
  - 负对照 → N1、N2、M8（附录）

**方案 B（更激进）：把 7 条子假设并成 5 条**

- H1b 和 H1c 合并为「RSI 的增益依赖跨 session 记忆且随链长增长」（一个 2×2 析因 + 分层，本来就是同一组臂）
- H2a/H2b/H2c 保持三条（机制不能并，并了就失去机制级可证伪性）
- H3 保持独立
- 这样 3 核心 + 5 子，臂表不变。**但不太推荐**——7 条子假设的结构本身清晰，合并反而让证伪条件变复杂。

### 四、一句话结论

Sub-hypotheses 7 条不多，结构内聚，只需修 H1c 的「跨 session」措辞。Ablation 13 臂偏多，真正的病不是总数而是：**(1) M1/M2 对 H1 的边际贡献低且判据功效不足；(2) M6 在 120 题最小矩阵下失败子集仅 40 题、3pp 判据基本跑不出显著，是假阴性风险最高的臂；(3) M8 是可选臂不该进主表。** 建议 13 → 10 臂主表 + 3 臂附录，并撤掉 M2 作为 H1a 弱对照的两条判据。

**如果只改一处**：把 M6 的最小矩阵题量抬到 ≥240（失败子集 ≥80）或者明确 M6 只在理想矩阵检验——这是当前设计里最可能「跑完才发现结论不可用」的臂。
