A3–A6 各自「只改哪一个变量」及对「多 agent vs 单 agent」可归因性的影响：

新臂相对哪个旧臂改了什么（唯一变量）是否会污染「多 agent vs 单 agent」可归因性
A3 相对 A0：同时引入「小预算」+「多 agent 交接」。为保可归因性，必须配 A0′＝同小预算下无 spawn 的单 agent。真正对比是 A3 vs A0′（同预算），不是 A3 vs A0（A0 是无预算限制的旧基线） 会污染（若不测 A0′）：A3 vs A0 同时变了「预算」和「agent 数」两个变量。✅ 解法＝强制配 A0′ 预算基线，把唯一变量收敛回「agent 数」。这是用户令 §3 明确要求的「必须先测 A0′ 预算基线」
A4 相对 A0：引入「分段接力 + 主 agent 只编排不写码」。两变量耦合：agent 数（多）+ 主 agent 角色（编排 vs 全做） 部分污染：A4 同时改了「agent 数」和「主 agent 是否亲自写码」。要拆开归因需额外加 A4′（主 agent 编排 + 单段子 agent 写码）。但若只问「多 agent 接力 ≤/≥ 单 agent」这一总问题，A4 vs A0 仍可答。判据用 A4 ITT ≥ A0 ITT
A5 相对 A2：唯一改「采纳协议」（A2 无脑采纳 → A5 强制 triage），spawn 时机/对象/工具不变 不污染「多 agent vs 单 agent」：A5 是 A2 的「修复版」，判据应是 A5 vs A0（多 agent 修复后是否反超单 agent），不是 A5 vs A2。A5 vs A2 只能回答「triage 是否修复无脑采纳」，属子问题
A6 相对 A2：唯一改「spawn 触发条件」（A2 一律 spawn → A6 仅高风险 spawn），verifier 协议不变 不污染：A6 = A0（低风险路径）+ A2（高风险路径），是 A0 与 A2 的条件混合。判据 A6 vs A0 回答「条件 spawn 是否 ≥ 一律不 spawn」。可归因性清晰

一句话归因口径：A3 必须配 A0′（否则双变量不可归因）；A4 若只问总问题可对比 A0，拆归因需加 A4′；A5/A6 单变量清晰，直接对比 A0。

§3 A3 专项（用户思路·重点）

① H_ctx 形式化

设 ctx_req(t)＝任务 t 所需最小上下文（完整读完题 + 查全 API + 推理链不丢细节），W＝底模上下文窗口（deepseek-v4-pro ≈ 128K）。

H_ctx：在 ctx_req(t) > W 的子集 S_overflow 上，Δ = ITT(multi) − ITT(single) 显著为正；在 ctx_req(t) ≤ W 的子集 S_fit 上，Δ ≤ 0。即 Δ 与 (ctx_req / W) 正相关，存在交叉点 ctx_req* ≈ W。

证据：配套报告 §3 :357-364（H_ctx 形式化原文）

④ 结论：「自然超窗路径是死路 ⇒ 唯一可行 = 强制小预算」

逐条推理：

  1. 40 题 max 112,318 < 128K（§5）· 158 题 max 100,115 < 128K（§6）· 两数据集均无任务自然超窗；
  2. 即便禁用 compaction 让上下文自然长，真实需求也只是略超 100K，超窗任务太少（统计检验力不足）+ 禁用会冒窗口溢出→null-content/报错风险；
  3. 且观测峰值 ~100K 本身被 compaction 截断（57 events/28 tasks 实证）→「看不到超窗」部分是压缩产物；
  4. ⇒ H_ctx 的「自然超窗」路径在本数据集上不可行（配套报告 §6 :468, :478-481）。

唯一可行路径 = A3 强制小预算：把主+子 agent 预算人为压到 32K/48K → 所有任务被迫「超预算」 → 多 agent 交接 vs 单 agent 压缩在同子集上可比。预算是旋钮，可让多数任务超预算→大子集→强检验力（配套报告 §6 :479 路径(b) 标「推荐」）。
