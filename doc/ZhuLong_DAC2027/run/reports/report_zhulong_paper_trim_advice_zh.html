⑤-A 摘要草稿（6 页版，~16 行）

\begin{abstract}
EDA scripting with tool-specific, often undocumented APIs is a long-tail bottleneck that
existing LLM tooling fails to address. We present \textbf{ZhuLong}, an execution-grounded
LLM coding agent for PyAether, SKILL, and Tcl that unifies API retrieval, documentation
inspection, and sandbox execution into a closed generate--execute--refine loop. We give a
\textbf{theoretical grounding}: EDA correctness is a \emph{situated} (L4) property no offline
knowledge can guarantee, and a Bayesian argument bounds the resulting ``grounding gap'' by
\emph{observation fidelity}, not model scale. On \textbf{EDA-Scripting-Bench} (449 real tasks,
four commercial runtimes), the full system reaches \textbf{75.7\%} pooled Pass@1, versus
\textbf{18.3\%} (pure LLM) and \textbf{62.5\%} (retrieval only); with the LLM fixed, the
observation ladder moves Pass@1 by 57.4~pp, while the backbone axis spans only 22.0~pp.
ZhuLong is already deployed in production EDA scripting flows at a leading memory design
house, serving hundreds of design engineers.
\end{abstract}

⑤-B 引言草稿（6 页版，~30 行）

\section{Introduction}\label{sec:introduction}
LLMs excel at general code generation, but EDA scripting---manipulating live design
databases, routing schematics, querying netlists---remains hard: APIs are long-tailed and
tool-specific; correctness depends on side effects in a stateful database, not return
values; and without execution feedback, static generation cannot diagnose or refine errors
\cite{chen2024dawning,blocklove2024eda}. Prior LLM-for-EDA work targets the digital flow
(RTL/Verilog, RTL-to-GDSII Tcl); the custom/analog surface---PyAether, SKILL,
waveform Tcl---where correctness must be read back from the live layout, schematic, or
waveform, is underexplored. These pain points are not hypothetical: the system reported here
is already deployed in production EDA flows serving hundreds of engineers at a leading
memory design house.

We present \textbf{ZhuLong}, an execution-grounded LLM coding agent for PyAether, SKILL, and
Tcl, built on Cline-CLI \cite{cline2024cline} and four unified MCP tools
\cite{lee2025autoeda}---semantic and keyword API search, documentation lookup, and sandbox
execution---that form a closed generate--execute--refine loop over four commercial runtimes
via a single \texttt{lang}--\texttt{host} pair. An offline \textbf{API self-exploration}
mechanism enriches the documentation prior as a bounded complement. Beyond the engineering,
we give a \textbf{theoretical grounding} (Section~\ref{sec:grounding-theory}): EDA correctness
is a situated (L4) property, and a Bayesian analysis bounds the grounding gap by observation
fidelity, not model scale---a prediction the experiments could refute rather than a
post-hoc explanation.

\noindent\textbf{Contributions.}
\begin{itemize}
  \item \textbf{RQ1 (ceiling).} We formalize the grounding gap and measure it from both
  sides: the observation ladder moves Pass@1 by 57.4~pp (LLM fixed), while the backbone axis
  spans 22.0~pp (harness fixed)---observation, not scale, sets the ceiling.
  \item \textbf{RQ2 (necessary components).} Ablation isolates retrieval, execution, and
  belief update as jointly necessary and not interchangeable; offline self-exploration is a
  bounded complement, not a substitute (Section~\ref{sec:experiments}).
  \item \textbf{RQ3 (toolchain generality).} \textbf{EDA-Scripting-Bench} (449 tasks, 4
  runtimes, one schema) re-measures the same structure slice by slice; we release the
  harness, schema, and protocol (Section~\ref{sec:benchmark}).
\end{itemize}
