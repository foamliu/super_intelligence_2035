1冻结底座（所有配置共用，不得变动）

  • 任务三要素：自然语言 prompt + 函数签名 + 断言测试代码；通过判据 = 生成的代码在 PyAether sandbox 中无错误执行且全部断言通过。
  • 运行口径：一律 -p 8 -n（8 并发 + 禁用 Memory Bank 注入）；Pass@1、单次无 retry。
  • 主 backbone：deepseek-v4-pro-fp4。只有 S3（tab:llm-comparison）才换 backbone。
  • 检索默认：name+description 索引的向量检索。只有 S1 才显式改该索引的保真度。
  • 反作弊 PreToolUse hook：全程启用、所有臂完全一致——它是冻结设置，不是消融变量（历史教训：未隔离时 pure LLM 曾 >98%，属内部数据，不得进论文）。
  • 扩展工具 cimi_search / cimi_fetch / vqa：永远关闭，不要碰。

3探路试验安排（1-shot：每臂 1 轮，先验证后铺开）

为什么先探路？ 完整一轮 = 158 个任务 × 5 轮，成本高。探路用 1 轮快速回答三件事：(a) harness 能起、切轴代码语义正确（否则切配置会静默失效）；(b) 反作弊 hook 真被装载（canary）；(c) 拿到能指导后续投入的粗略 Pass@1。

3.3 探路前的 canary（每批强制，README §8）

故意触发一次本应被拒绝的调用（如 run_commands 或读写工作区外路径），确认它真的被拒。若未被拒 → hook 未加载，立即停止，该批数据作废。目的是提前暴露「未隔离 / 归因混乱」这类致命问题，而不是跑完才发现数据全废。

数据口径速查（README §4.1）

量写法说明
跨 5 次运行的准确率78.5 ± 1.8✅ 只有 Pass@1 写 mean ± std
由均值算出的差值 Δ+43.0 pp（不加 ±）加 ± 会被误读成「差值的标准差」
跨 trace 汇总的比例/计数Converged (%)、Mean read-backs、Avg/Trace 单值跨运行 std 会严重低估其变异
确定性/结构性量tab:selfdoc-cost 等单值与运行无关，mean ± std 无意义
  • Converged (%) := finish_reason == completed 的 trace 占比，必须紧挨 Pass@1 报告（否则紧预算造成的低 Pass@1 会被误读为「收敛」）。
  • 数字必须能回溯到 (config_id, run_id) 原始记录；Δ 与主表数字必须同批算出，不得跨批次拼。
  • 当 Δ 与散布同量级（如 +3.2 pp），正文须注明统计功效不足（论文 §7 已定位为「互补增益而非头条结论」）。
