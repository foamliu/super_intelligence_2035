四、中优先级问题

中 #7 Tcl 回读轴"中间档倒挂"的解释不完整

§6.1：Tcl 上 N′(无回读)=86.6 > B(二值)=82.1 < F(全观测)=87.2，B 既低于 N′ 又低于 F。论文解释："Tcl scripts are short and near-single-shot, largely solved from documentation, so a binary signal supplies no actionable information"。

这只说明 B≈N′（二值无用），但没解释 B < N′（二值比无回读更差 4.5pp）。若二值"无用"，B 应等于 N′，不应更低。合理解释是：binary "fail" 信号诱导 agent 在预算内重试错误修复，消耗 message budget 后被迫提交更差解；而 N′（无任何回读）让 agent 直接提交首次最佳猜测。

建议

§6.1 Tcl 倒挂段补半句："a binary 'fail' signal can mislead the agent into spending its budget on ill-informed retries, whereas no feedback leaves the first (often documentation-grounded) guess intact"。这把"倒挂"从瑕疵转为对 Principle 3 的精细化（反馈质量而非反馈有无才关键），反而强化框架。

中 #8 "Pure LLM"基线的执行语义未讲清

§6 tab:main-ablation "Baseline 1: Pure LLM = 18.3%"。但 Pure LLM 关闭了 run_code，agent 无法执行代码——那 18.3% 的 pass 是怎么来的？读者会困惑："no sandbox"是否等于"代码根本不跑"。

实际机制（论文未明说）：agent 仍可写代码到文件（Cline-CLI 的 file-write 未禁），eval harness 在 trace 结束后单独执行该文件评分。所以 18.3% = "无任何执行反馈下一次性写对的代码"。

建议

§6.1 setup 段或 Pure LLM 行表注补一句："For the Pure LLM arm, run_code is unregistered so the agent writes code without execution feedback; the harness scores the final file against assertions after the trace." 1 句话消除困惑。

中 #9 表注 "Baseline 2: RAG (retrieval only)" 与正文 "RAG = retrieval + self-exploration" 命名冲突

tab:main-ablation 表注写 "RAG (retrieval only)"，但 §6.1 正文写 "RAG (retrieval + self-exploration, no sandbox; coincides with w/o-Sandbox)"。"retrieval only" 与 "retrieval + self-exploration" 自相矛盾。

建议

表注改为 "Baseline 2: RAG (retrieval + self-exploration, no sandbox)"，与正文一致。

中 #10 Innovus 各臂 std 普遍偏高，提示运行时不稳

Innovus（57 任务）在多个臂上 std 异常：C1.full 85.3±15.4（5 轮 63.2/75.4/93.0/93.0/93.0 呈双峰）、B.glm-5.2 68.4±16.2、C1.wo_retrieval 61.8±34.6（含 r3=1.8% 异常）。Innovus licence breaker 历史上多次 OPEN（8663/8666/8667/8670），用 8650 组兜底，这种 infra 抖动会渗入 std。

建议

§7 limitations 加半句"the Innovus slice (57 tasks, smallest n) shows elevated variance across arms, partly attributable to runtime licence availability; pooled results are robust but Innovus-level point estimates should be read as indicative"。

中 #11 backbone 轴 22.0pp 跨度含不可部署弱模型，"观测>规模"修辞被弱化

§6.3 S3："the backbone remains decisive—22.0pp spread"。22.0pp = DeepSeek-V4-Pro 75.7 − Doubao 53.7。但 Doubao-Seed-2.0-Pro（53.7）是明显不达标的弱模型，真实部署不会用它。若只比可部署梯队（DeepSeek-V4-Pro 75.7 / GLM-5.3-Flash 74.8 / GLM-5.2 70.9），跨度仅 4.8pp，而非 22.0pp。

建议

§6.3 补一句限定："the 22.0pp span includes markedly weaker backbones (e.g., Doubao 53.7%) that would not be deployed in practice; among deployable backbones the spread narrows to 4.8pp, further underscoring that observation, not backbone choice, sets the ceiling for production use"。把潜在攻击转为论点加强。

中 #12（v2 新增） Benchmark task 采样策略与代表性未交代

§5 只说 "EDA experts curated each assertion to be self-contained"，但没交代：

  • 449 task 是从 vendor 文档里怎么采样出来的？随机？分层？按 API 受欢迎度？
  • 几个专家 curate？是否双盲？inter-annotator agreement？
  • 任务是否覆盖各运行时的代表性 API 分布，还是偏向某类（如 layout 多、schematic 少）？

低 #15 "harness-budget" 超时与 message-budget 耗尽未量化

§6.4："Generation-stage failures are a harness-budget, not a grounding, phenomenon—mostly timeouts ... or message-budget exhaustion"。多少 timeout、多少 budget 耗尽？无数字。若 §6.1 的 Φ 预算表（阻断 #1）回正文，可顺带给 PyAether 的 Converged 99.1% @ k=∞ → 76.3% @ k=1 作为量化锚点。

低 #16（v2 新增） §4.2 "transition is deterministic" 论证可澄清 policy stochasticity

§4.2："the same action in the same state yields the same result, with no action stochasticity—so $\mathcal{T}$ is exact"。这描述的是环境转移 $\mathcal{T}$（确实 deterministic），但读者可能困惑：agent 的 LLM 调用是 stochastic 的（temperature>0），那"no action stochasticity"是否成立？

实际"action stochasticity"指环境对同一 action 的响应是否随机，与 policy 是否 stochastic 无关——论证成立。但可加半句澄清："stochasticity in the policy $\Pi$ is orthogonal to $\mathcal{T}$; the bound concerns the environment's response to a given action, not the action's distribution"。低优先，澄清即妥。

低 #17（v2 新增） 5-run 仅 mean±std，无 Wilson CI / paired test

所有表报 mean±s.d. over 5 runs，但无置信区间、无 paired significance test。+3.1pp（self-exploration）这种小效应在 n=5 下统计功效不足——§7 limitations 已提"benchmark size limits power to certify small effects"，但未点明"无 CI/test"。

评审 I 已判定低优先 defer supplementary。建议维持现状，limitations 已覆盖。若空间允许可加半句"we report mean±s.d. rather than confidence intervals; with n=5, small effects (e.g., +3.1pp) should be read as indicative, not certified"。

低 #18 §4.2 Claim 措辞 "we posit" 偏弱

"We posit that D_grounding ≤ g(ε)"。论文已声明这是"prediction the experiments can test rather than a theorem"，措辞诚实。但"posit"在审稿人眼里≈"猜"。可保留（诚实优于过度声称），或改为"we conjecture (and test below)"。

  • "EDA Scripting" 偏泛——论文实际聚焦 custom/analog scripting（PyAether/SKILL/Tcl on commercial runtimes），与已有数字流程 EDA agent（ChatEDA/MCP4EDA/AutoEDA on Yosys/OpenLane）区分。标题未体现这一定位。
  • 未体现 benchmark（EDA-Scripting-Bench，449 tasks）与理论框架（grounding gap）两个贡献——只突出了 system。
  • 未传递核心发现"observation fidelity > model scale"——这是 RQ1 的头条结论。

候选标题（按推荐度排序）

推荐 ★1 ZhuLong: Execution-Grounded LLM Agents for EDA Scripting

改动极小（"An" → 删，"Agent" → "Agents" 复数化与 RQ3 多运行时呼应）。保留现标题的所有优点，去掉冗余冠词。风险最低、收益清晰——适合"想稳"的场景。

推荐 ★2 ZhuLong: Closing the Grounding Gap in EDA Scripting with Execution-Grounded LLM Agents

把核心理论贡献"grounding gap"提到标题。与 §4 标题 "Theoretical Grounding: The Grounding Gap" 直接呼应，给评审一个理论锚点。
略长（14 词），但 DAC 历史上 14-16 词标题常见。
适合"想突出理论 + 区别纯系统论文"的场景。

候选 ★3 ZhuLong: An Execution-Grounded LLM Agent and Benchmark for EDA Scripting

加 "and Benchmark" 突出双贡献（system + EDA-Scripting-Bench）。DAC 评审常看重 benchmark 贡献，标题点明可加分。
"An ... Agent and Benchmark" 略堆砌，节奏不如 ★1 紧凑。

候选 ★4 ZhuLong: Observation Fidelity, Not Model Scale, Bounds LLM Agents for EDA Scripting

把核心发现（RQ1: observation > scale）放标题，最具冲击力。
把结论放标题有争议——若评审质疑 57.4pp 归因（review A 已遇过），标题会被反噬。且"Observation Fidelity"是论文内术语，标题首次出现无解释，陌生读者可能跳过。
不推荐，除非想赌一把"标题即结论"的传播力。

候选 ★5 ZhuLong: Execution-Grounded LLM Agents for Custom and Analog EDA Scripting

把"Custom and Analog"明确化，与数字流程 EDA agent（ChatEDA/MCP4EDA/AutoEDA）标题级区隔。related work 段已强调这一定位，标题呼应可强化。
"Custom and Analog" 缩窄了范围，但论文 Tcl slice 含 Innovus（floorplanning/place/route，偏数字后端），严格说不是"analog"——术语边界模糊可能被挑刺。
若选此标题，需把 §5 Innovus 描述改为"custom+back-end scripting"而非纯 analog。

候选 ★6 ZhuLong: An LLM Agent that Orchestrates EDA Design Flows via Execution-Grounded Scripting

突出 abstract/intro 的"connective tissue / flow orchestration"定位——这是论文的动机叙事钩子。
标题把"orchestrate flows"与"scripting"并列，但论文实测是 per-task Pass@1，没有端到端 flow 跑通的量化指标。标题说"orchestrates flows"但实验只测单任务，可能被评审抓"claims vs evidence mismatch"。
不推荐——除非补一个 end-to-end flow case study。

综合建议

首选 ★1（稳）：改动最小，保留现标题所有优点，去掉冗余冠词。若想零风险就选这个。

次选 ★2（突出理论）：把 "grounding gap" 提到标题，给评审一个理论锚点，区别于纯系统论文。DAC 评审里有 ML 理论背景的会买单。这是我个人最推荐的——论文的理论贡献（§4 贝叶斯框架 + 可证伪预测）是区别于其他 EDA agent 论文的核心差异点，标题应体现。

不推荐 ★4 / ★6：前者结论性标题有反噬风险，后者 claims-evidence mismatch。

★3 / ★5是中间选项：★3 突出 benchmark 双贡献，★5 突出 custom/analog 定位——但都有副作用（堆砌 / 范围边界模糊）。
