\subsection{Experimental Setup}
\label{sec:exp-setup}

\textbf{Research questions.} The framework of Section~\ref{sec:grounding-theory} makes three testable claims, one per RQ: \textbf{RQ1 (ceiling)}---is accuracy bounded by observation fidelity $\Omega$ or by the prior $\mathcal{K}$? (S1 varies $\Omega$ with the LLM fixed; S3 varies $\mathcal{K}$ with the harness fixed.) \textbf{RQ2 (necessary components)}---does bridging the gap require observation, execution, and continuous belief update, and can one substitute for another? (S2 varies the effector and the belief-update budget.) \textbf{RQ3 (toolchain generality)}---does the same structure reproduce on a different toolchain? (S4 re-runs S1--S2 on the SKILL and Tcl slices.)
% 研究问题（框架三条可检验主张，一 RQ 一条）：RQ1 上限——准确率受 Ω 保真度还是先验 K 约束？（S1 固定 LLM 变 Ω；S3 固定框架变 K）。RQ2 必要组件——是否同时需观测/执行/持续信念更新，能否互换？（S2 变执行器与信念更新预算）。RQ3 工具链通用性——同结构能否在不同工具链复现？（S4 在 SKILL/Tcl 切片重跑 S1–S2）。

\textbf{Benchmark and protocol.} We evaluate on \textbf{EDA-Scripting-Bench} (449 tasks, Section~\ref{sec:benchmark}) using \textbf{Pass@1}. Each task runs in a single trace (the agent may iterate \emph{within} it via $\Phi$ but is never restarted) with a 2500-second timeout; a file-based \texttt{PreToolUse} hook enforces a tool whitelist, blocks shell and code-search tools, and confines file access to a fresh working directory, so no assertions or reference solution is reachable---identical in every configuration, hence part of the fixed protocol. Each configuration is run five times (reshuffled order, fresh contexts), reported as mean $\pm$ s.d.; $\Delta$ is from table means. Task cases derive from non-redistributable vendor documentation (unlikely in public pretraining), and no third-party agent can execute these runtimes without the MCP bridge, so baselines are tool-registration ablations of the same fixed harness, making single-variable attribution possible.
% 评测集与协议。EDA-Scripting-Bench 449 任务，Pass@1。单 trace（可经 Φ 内迭代不跨 trace 重启），2500s 超时；PreToolUse hook 强制白名单、屏蔽 shell/代码搜索、文件限新工作目录——断言与参考解不可达（所有配置一致）。每配置 5 次（重排/全新上下文）均值±标准差；Δ 由表均值算。任务源自不可再分发厂商文档；无 MCP 桥第三方无法执行，故基线为同框架工具注册消融——使单变量归因成为可能。

\textbf{Configurations.} We isolate components by tool registration (a disabled tool is unregistered and invisible; the agent policy is held fixed), giving five configurations (Table~\ref{tab:main-ablation}): \emph{Pure LLM} (no retrieval, sandbox, or self-exploration), \emph{RAG} (retrieval + self-exploration, no sandbox; $=$ w/o-Sandbox), \emph{w/o Self-Expl.} (retrieval + sandbox), \emph{w/o Retrieval} (sandbox + self-exploration), and \emph{ZhuLong (Full)} (all three on). S1 probes the observation axes at their extremes; S2 bounds $\Phi$. All main experiments use DeepSeek-V4-Pro as the backbone; S3 evaluates five additional backbones under the identical harness.
% 配置（表 tab:configurations 并入文字）：通过工具注册隔离组件（禁用工具注销不可见，策略固定）。五配置：Pure LLM、RAG（与 w/o-Sandbox 合一）、w/o Self-Expl.、w/o Retrieval、ZhuLong Full。S1 探观测轴极端；S2 给 Φ 加界。主实验用 DeepSeek-V4-Pro；S3 另评 5 backbone。

\subsection{Results and Ablations}
\label{sec:exp-results}

Table~\ref{tab:main-ablation} gives the five configurations pooled and per slice. Relative to the full system, removing execution costs $13.2$~pp pooled, removing retrieval $11.8$~pp, and removing self-exploration $3.1$~pp; against the pure-LLM floor the full system gains $57.4$~pp. Wilson 95\% intervals on the pooled Pass@1 ($n{=}2245$): Full $[73.86,77.41]$, w/o-Self-Expl.\ $[70.72,74.41]$, w/o-Retrieval $[62.00,65.97]$, RAG $[60.47,64.47]$, N$'$ $[60.16,64.17]$, B $[63.49,67.42]$, Pure-LLM $[16.76,19.96]$; the controlled $N'\to F$ read-back gap of $13.50$~pp has 95\% interval $[10.82,16.18]$~pp (SE$=1.37$~pp). A paired bootstrap is deferred: batch directories store only counts, so per-task arrays would require a one-shot regrade over both arms' batches. Where each component's contribution comes from is toolchain-specific (Section~\ref{sec:cross-language}).
% 主结果（表~\ref{tab:main-ablation}，5 配置合并+分切片）。相对完整系统：移除执行 -13.2pp、移除检索 -11.8pp、移除自探索 -3.1pp；相对纯 LLM 下限 +57.4pp。Wilson 95% CI（pooled n=2245）已加；N′→F 13.5pp gap 独立比例正态近似 CI [10.82,16.18]pp（保守·比 paired 紧）；paired bootstrap 待 per-task regrade（batch 目录仅存计数）。各组件贡献来源因工具链而异（§6.3 S4）。

\subsubsection{S1: Observation fidelity (RQ1)}
\label{sec:omega-fidelity}

Principle 2 predicts that with the model fixed, accuracy is bounded by the fidelity of $\Omega$. \textbf{Documentation axis.} Holding the agent loop, effector, and LLM fixed, removing retrieval costs 11.8~pp pooled, but highly toolchain-specific: on PyAether the read-back channel substitutes for retrieval (86.7\% of traces introspect via the sandbox using \texttt{dir()}/\texttt{inspect}/\texttt{\_\_doc\_\_}, reconstructing the API knowledge retrieval would return), whereas on SKILL and Tcl the API surfaces cannot be recovered from execution alone, so removing retrieval removes the knowledge. Retrieval is thus one \emph{implementation} of $\Omega$, not the channel itself.
% S1 观测保真度（RQ1）。原则 2 预测固定模型时准确率受 Ω 保真度约束。文档轴：固定循环/执行器/LLM，移除检索合并 -11.8pp，但高度工具链特定——PyAether 上回读通道可替代检索（86.7% trace 沙盒内省重建 API 知识）；SKILL/Tcl API 面无法仅凭执行恢复。故检索只是 Ω 的一种实现而非通道本身。

\textbf{Read-back axis.} The second axis is how much of the live state execution returns. We compare three closed-loop variants differing only here (Table~\ref{tab:omega}, lower block): (N$'$) \emph{no read-back}---\texttt{run\_code} executes but returns nothing; (B) \emph{binary feedback}---pass/fail only; (F) \emph{full observation}---stdout, traces, per-assertion outcomes, and queried state (the default). The predicted monotone ordering N$'$ $<$ B $<$ F holds pooled and on the two largest slices; on Tcl it inverts at the middle rung, because Tcl scripts are short and near-single-shot, largely solved from documentation, so a binary signal supplies no actionable information. This is the $\epsilon$-axis the claim of Section~\ref{sec:bayesian} predicts tracks accuracy; the N$'$-to-F gap operationalizes the grounding gap as an accuracy difference.
% 回读轴：执行返回多少实时状态。三闭环变体仅此处不同：(N′) 无回读、(B) 二值、(F) 全观测（默认）。预测单调 N′<B<F 在合并与两最大切片成立；Tcl 中间档倒挂（短脚本近单发，二值信号无可操作信息）。这是 §4.2 引理预测的 ε 轴：N′→F 差距即落地鸿沟的准确率化。

\textbf{Self-exploration rung.} The top rung adds constraints discovered offline (Section~\ref{sec:selfdoc}); per the framework this enriches only the L1--L3 facts $\Omega$ can return, so it should move the result less than the channel's own fidelity. Removing it (retrieval and effector kept) drops Pass@1 from 81.4\% to 77.3\% on PyAether (75.7\% to 72.6\% pooled), a bounded prior-side complement rather than a substitute. Self-exploration is the one cost-negative rung (cutting net-active solve time by 27.0\%, see Table~\ref{tab:cost}), whereas removing retrieval makes the agent fall back on blind sandbox probing (2.3$\times$ the full system's time).
% 自探索档：加离线发现的约束（§3.4）。按框架只丰富 Ω 可返回的 L1–L3 事实，效应应小于通道自身保真度。移除（保留检索+执行器）PyAether 81.4→77.3（合并 75.7→72.6），有界先验侧补充非替代。自探索唯一成本为负档（求解时间 -27.0%）；移除检索退化为盲探沙盒（2.3 倍完整系统时间）。

\subsubsection{S2: The closed loop (RQ2)}
\label{sec:closed-loop}

Principle 3 requires that actions reach the design through a causal interface and that $\Phi$ run continuously. \textbf{Effector.} Removing the sandbox drops pooled Pass@1 from 75.7\% to 62.5\% ($-13.2$~pp): without an effector, $b_t$ receives no live-state evidence and the agent is a prior-only predictor. \textbf{Belief update.} We bound how often the agent \emph{may} execute (the number of \texttt{run\_code} calls per trace, denied at the tool boundary once spent) rather than forcing early submission, and vary the evidence along two axes: the budget $k$, and a \emph{lagged} channel that returns the \emph{previous} execution's state, leaving the agent one action behind the design. On PyAether, accuracy rises monotonically with the budget (63.8\% at $k{=}1$, 69.1\% at $k{=}3$, 77.7\% at $k{=}10$, unsaturated); the lagged channel lands between $k{=}3$ and $k{=}10$ (73.0\%)---stale evidence is worth markedly less than fresh---and tighter budgets leave traces unfinished (Converged drops from $99.1$ to $76.3$ at $k{=}1$).

\subsubsection{S4: The toolchain axis (RQ3)}
\label{sec:cross-language}

The four slices share one schema, assertion criterion, and harness, so S1--S2 re-runs slice by slice with nothing changed but the toolchain. Table~\ref{tab:main-ablation} carries the comparison: the pure-LLM floor and the advantage of closed-loop configurations reproduce on every slice (the one exception being SKILL, where the full system trails its w/o-Self-Exploration variant by $1.2$~pp), and the read-back ordering N$'$ $<$ B $<$ F holds on the two largest slices and pooled (the Tcl inversion is disclosed in Section~\ref{sec:omega-fidelity}). Component magnitudes are toolchain-specific---execution buys $+26.4$~pp on SKILL but only $+2.6$ on Tcl, and retrieval is redundant on PyAether yet worth $21.3$ and $14.1$~pp on SKILL and Tcl---but the structure (observation and execution jointly closing the loop) reproduces on every slice.
% S4 工具链轴（RQ3）。四切片共享 schema/断言/框架，S1–S2 逐切片重跑除工具链外不变。表~\ref{tab:main-ablation}：纯 LLM 下限与闭环优势每切片复现（唯一例外 SKILL 完整系统比 w/o-Self-Exploration 低 1.2pp）；回读排序 N′<B<F 在两最大切片与合并成立（Tcl 倒挂见 §6.2 S1）。组件量级工具链特定——执行 SKILL +26.4pp、Tcl 仅 +2.6pp；检索 PyAether 冗余、SKILL/Tcl 价值 21.3/14.1pp——但结构（观测+执行共同闭环）每切片复现。

\subsection{Error Analysis}
\label{sec:error-analysis}

On PyAether, ZhuLong reaches 81.4\% Pass@1 (129/158). Generation-stage failures are a harness-budget, not a grounding, phenomenon---mostly timeouts on multi-step tasks or message-budget exhaustion cycling through \texttt{search\_apis}. Manual inspection of execution-stage failures yields two root causes: 12 \textbf{API-misuse} cases (correct API family, but an undocumented C++-binding contract---hidden types, internal state, or context preconditions---is violated), and 9 \textbf{API-composition errors} (valid calls composed incorrectly, or a mandated call replaced by a plausible approximation, e.g., a substring match for equality). Both share one signature: the violated constraint is invisible in documentation and only weakly exposed by execution---the L4 invisibility Section~\ref{sec:grounding-theory} predicts situated correctness hinges on.
% 错误分析（16:1x 微调正文压缩 ~4 行以让结论回 p6；事实保真：81.4%/129/158、12 API 误用、9 组合错误、L4 不可见性）。PyAether 81.4%（129/158）。生成阶段失败=框架预算现象非落地现象（多步任务超时 / 消息预算耗尽于 search_apis 循环）。执行阶段失败两类：12 例 API 误用（选对 API 族但违反 C++ 绑定强制而文档未揭示的契约——隐藏类型/内部状态/上下文前置条件）；9 例 API 组合与工作流错误（各自有效调用错误组合，或强制调用被似是而非近似替换如子串匹配代相等性）。两类共享同一签名：被违反约束文档不可见、执行仅弱暴露——即 §4 预测情境正确性所系的 L4 契约不可见性。
