\subsection{Experimental Setup}
\label{sec:exp-setup}

\textbf{Research questions.} The framework of Section~\ref{sec:grounding-theory} makes three testable claims, one per RQ: \textbf{RQ1 (binding constraint)}---which axis, observation fidelity $\Omega$ or the prior $\mathcal{K}$, is binding, and over what range? (S1 varies $\Omega$, S3 varies $\mathcal{K}$.) \textbf{RQ2 (necessary components)}---do observation, execution, and belief update each matter, and can one substitute for another? (S2 varies the effector and update budget.) \textbf{RQ3 (toolchain generality)}---does the structure reproduce on another toolchain? (S4 re-runs S1--S2 on SKILL and Tcl.)
% 研究问题（框架三条可检验主张，一 RQ 一条）：RQ1 binding 约束——观测保真度 Ω 与先验 K 哪条轴是 binding、在什么区间？（S1 固定 LLM 变 Ω；S3 固定框架变 K）。RQ2 必要组件——是否同时需观测/执行/持续信念更新，能否互换？（S2 变执行器与信念更新预算）。RQ3 工具链通用性——同结构能否在不同工具链复现？（S4 在 SKILL/Tcl 切片重跑 S1–S2）。

\textbf{Benchmark and protocol.} We evaluate on \textbf{EDA-Scripting-Bench} (449 tasks, Section~\ref{sec:benchmark}) using \textbf{Pass@1}: one trace per task (the agent may iterate within it via $\Phi$ but is never restarted), a 2500-second timeout, and a \texttt{PreToolUse} hook that enforces a tool whitelist, blocks shell/code-search tools, and confines file access to a fresh directory---identical in every configuration. Each configuration runs five times (reshuffled order, fresh contexts), reported as mean $\pm$ s.d. Task cases derive from non-redistributable vendor documentation (unlikely in public pretraining), and no third-party agent can run these runtimes without the MCP bridge, so baselines are tool-registration ablations of the same harness---enabling single-variable attribution.
% 评测集与协议。EDA-Scripting-Bench 449 任务，Pass@1。单 trace（可经 Φ 内迭代不跨 trace 重启），2500s 超时；PreToolUse hook 强制白名单、屏蔽 shell/代码搜索、文件限新工作目录——所有配置一致。每配置 5 次（重排/全新上下文）均值±标准差。任务源自不可再分发厂商文档；无 MCP 桥第三方无法执行，故基线为同框架工具注册消融——使单变量归因成为可能。

\textbf{Configurations.} We isolate components by tool registration (a disabled tool is unregistered and invisible; the agent policy is held fixed), giving five configurations (Table~\ref{tab:main-ablation}): \emph{Pure LLM} (no retrieval, sandbox, or self-exploration), \emph{RAG} (retrieval + self-exploration, no sandbox; $=$ w/o-Sandbox), \emph{w/o Self-Expl.} (retrieval + sandbox), \emph{w/o Retrieval} (sandbox + self-exploration), and \emph{ZhuLong (Full)} (all three on). S1 probes the observation axes at their extremes; S2 bounds $\Phi$. All main experiments use DeepSeek-V4-Pro as the backbone; S3 evaluates five additional backbones under the identical harness.
% 配置：通过工具注册隔离组件（禁用工具注销不可见，策略固定）。五配置：Pure LLM、RAG（与 w/o-Sandbox 合一）、w/o Self-Expl.、w/o Retrieval、ZhuLong Full。S1 探观测轴极端；S2 给 Φ 加界。主实验用 DeepSeek-V4-Pro；S3 另评 5 backbone。

\subsection{Results and Ablations}
\label{sec:exp-results}

Table~\ref{tab:main-ablation} gives the five configurations pooled and per slice; against the pure-LLM floor the full system gains $57.2$~pp. Wilson 95\% intervals on the pooled Pass@1 ($n{=}2245$; Table~\ref{tab:main-ablation}) place Full at $[75.11,78.60]$ and Pure-LLM at $[18.11,21.40]$, and give the two RQ2 component gaps, which exclude~0---retrieval $+10.7$~pp $[8.1,13.3]$ and execution $+8.3$~pp $[5.7,10.9]$---while self-exploration $+2.4$~pp $[-0.1,4.9]$, the binary-over-none read-back rung $+1.2$~pp $[-1.5,3.9]$, and the SKILL self-exploration difference $-1.2$~pp $[-3.6,6.0]$ straddle~0, consistent with their complementary framing.\footnote{All difference intervals treat the two arms as independent and pool task-runs as i.i.d.; a paired, task-clustered analysis would only tighten them.}
% 主结果（表~\ref{tab:main-ablation}，5 配置合并+分切片）。相对纯 LLM 下限 +57.2pp。合并 Pass@1 的 Wilson 95% CI（n=2245；表~\ref{tab:main-ablation}）将 Full 置为 [75.11,78.60]、Pure-LLM 置为 [18.11,21.40]，并给出两个 RQ2 组件鸿沟，且均排除 0——检索 +10.7pp [8.1,13.3]、执行 +8.3pp [5.7,10.9]——而自探索 +2.4pp [-0.1,4.9]、回读轴二值对无回读档 +1.2pp [-1.5,3.9] 与 SKILL 自探索差 -1.2pp [-3.6,6.0] 跨 0，与其互补定位一致。脚注：所有差异区间视两臂独立、将 task-runs 作 i.i.d.；配对、任务聚类分析只会更紧。各组件贡献来源因工具链而异（§6.3 S4）。

\subsubsection{S1: Observation fidelity (RQ1)}
\label{sec:omega-fidelity}

Principle 2 predicts that with the model fixed, accuracy is bounded by the fidelity of $\Omega$ \emph{on the failures that require observing the live design}. \textbf{Documentation axis.} Holding the agent loop, effector, and LLM fixed, removing retrieval costs 10.7~pp pooled, but highly toolchain-specific: on PyAether the read-back channel partially substitutes for retrieval (sandbox introspection via \texttt{dir()}/\texttt{inspect}/\texttt{\_\_doc\_\_} rises from 49.0\% to 86.7\% of traces once retrieval is removed). Tcl substitutes likewise through its own enumeration channels---\texttt{info commands} and \texttt{get\_db} probing---recovering the API surface but not its deep semantics, so removing retrieval there costs only $7.7$~pp. SKILL's sandbox has no such channel (\texttt{apropos}/\texttt{describe} fail), leaving only \texttt{boundp}/\texttt{isCallable} existence checks, so the API surface cannot be rediscovered and retrieval there is irreplaceable ($15.1$~pp). Retrieval is thus one \emph{implementation} of $\Omega$, not the channel.
% S1 观测保真度（RQ1）。原则 2 预测固定模型时准确率在"需要观测实时设计"的失败上受 Ω 保真度约束。文档轴：固定循环/执行器/LLM，移除检索合并 -10.7pp，但高度工具链特定。PyAether 上回读通道部分替代检索：移除检索后经 dir()/inspect/__doc__ 的沙盒内省 trace 占比从 49.0% 升至 86.7%。Tcl 同样通过自己的枚举通道替代——info commands 与 get_db 属性探测——能重建 API 面但重建不了深层语义，故移除检索仅损失 7.7pp。SKILL 沙盒无此枚举通道（apropos/describe 不可用），只剩 boundp/isCallable 做存在性检查，API 面无法系统性重建，故检索在该宿主不可替代（15.1pp）。故检索只是 Ω 的一种实现，而非通道本身。

\textbf{Read-back axis.} The second axis is how much of the live state execution returns. We compare three closed-loop variants differing only here (Table~\ref{tab:omega}, lower block): (N$'$) \emph{no read-back}---\texttt{run\_code} executes but returns nothing; (B) \emph{binary feedback}---pass/fail only; (F) \emph{full observation}---stdout, traces, per-assertion outcomes, and queried state (the default). The predicted monotone ordering N$'$ $<$ B $<$ F holds pooled and on the two largest slices, though on PyAether the middle rung is narrow ($+1.2$~pp, within one combined s.d.): a bare pass/fail verdict adds little actionable information, and the F rung carries almost the whole ladder ($+5.9$~pp of the $7.1$~pp N$'$-to-F gap). On Tcl it inverts at the middle rung---short, near-single-shot scripts solved from documentation leave a binary signal nothing to act on. Cost sharpens the reading (Table~\ref{tab:cost}): binary feedback is \emph{more} expensive than full observation on every operating metric---without actionable error information the agent probes blindly---while no read-back collapses cost together with accuracy. What the channel returns, not how often the agent acts, drives both---the N$'$-to-F gap operationalizes the grounding gap; within these three rungs, the return lies in investing read-back fidelity rather than merely enabling execution.
% 回读轴：执行返回多少实时状态。三闭环变体仅此处不同：(N′) 无回读、(B) 二值、(F) 全观测（默认）。预测单调 N′<B<F 在合并与两最大切片成立，但 PyAether 中间档很窄（+1.2pp，小于一个合并标准差）：裸 pass/fail 几乎不提供可操作信息，阶梯增量几乎全由 F 档贡献（7.1pp 的 N′→F 差距中 F 档占 +5.9pp）。Tcl 中间档倒挂（短脚本近单发，二值信号无可操作信息）。成本进一步佐证（表~\ref{tab:cost}）：二值反馈在每个运行指标上均比全观测更贵——无可操作错误信息时代理只能盲目试探；无回读则成本与准确率一同塌缩。决定两者的不是代理行动多频繁，而是通道返回什么。这是 §4.2 引理在 L4 失败上预测准确率跟随的 ε 轴：N′→F 差距即落地鸿沟的准确率化。

\textbf{Self-exploration rung.} The top rung adds constraints discovered offline (Section~\ref{sec:selfdoc}); per the framework this enriches only L1--L3 facts, so it should move the result less than the channel's fidelity. Removing it (retrieval and effector kept) drops Pass@1 from 82.5\% to 77.0\% on PyAether (76.9\% to 74.5\% pooled; Table~\ref{tab:main-ablation}), a bounded prior-side complement rather than a substitute. Self-exploration is cost-negative at runtime (cutting net-active solve time by 28.1\%, see Table~\ref{tab:cost}).
% 自探索档：加离线发现的约束（§3.4）。按框架只丰富 Ω 可返回的 L1–L3 事实，效应应小于通道自身保真度。移除（保留检索+执行器）PyAether 82.5→77.0、合并 76.9→74.5（表~\ref{tab:main-ablation}），有界先验侧补充非替代。自探索在运行期成本为负（求解时间 -28.1%）。

\subsubsection{S2: The closed loop (RQ2)}
\label{sec:closed-loop}

Principle 3 requires actions to reach the design through a causal interface and $\Phi$ to run continuously. \textbf{Effector.} Removing the sandbox drops pooled Pass@1 from 76.9\% to 68.6\% ($-8.3$~pp): without an effector the agent becomes a prior-only predictor. \textbf{Belief update.} We bound how often the agent \emph{may} execute (a per-trace \texttt{run\_code} budget, denied at the tool boundary) rather than forcing early submission, and vary the evidence along two axes: the budget $k$, and a \emph{lagged} channel that returns the \emph{previous} execution's state, leaving the agent one step behind. On PyAether, accuracy rises monotonically with the budget (63.8\% at $k{=}1$, 69.1\% at $k{=}3$, 77.7\% at $k{=}10$, unsaturated); the lagged channel lands between $k{=}3$ and $k{=}10$ (73.0\%)---stale evidence is worth markedly less than fresh---and tighter budgets leave traces unfinished.
% S2 闭环（RQ2）。原则 3 要求动作经因果接口作用于设计且 Φ 持续运行。执行器：移除沙盒合并 Pass@1 从 76.9% 降至 68.6%（−8.3pp）——无执行器则 b_t 收不到实时状态证据，智能体沦为仅先验预测器。信念更新：限制每 trace 可执行的 run_code 调用数（耗尽即在工具边界拒绝）而非强制提前提交，并沿两轴变化证据——预算 k，以及滞后通道（返回上一次执行状态，使 agent 落后设计一步）。PyAether 上准确率随预算单调上升（k=1 时 63.8%、k=3 时 69.1%、k=10 时 77.7%，未饱和）；滞后通道落于 k=3 与 k=10 之间（73.0%）——陈旧证据明显不如新鲜——更紧预算使 trace 未完成。

\subsubsection{S4: The toolchain axis (RQ3)}
\label{sec:cross-language}

The four slices share one schema, assertion criterion, and harness, so S1--S2 re-runs per slice with nothing changed but the toolchain. Table~\ref{tab:main-ablation} carries the comparison: the pure-LLM floor and the closed-loop advantage reproduce on every slice (except SKILL, where Full trails w/o-Self-Exploration by $1.2$~pp), and the read-back ordering N$'$ $<$ B $<$ F holds on the two largest slices and pooled (narrowly at the middle rung on PyAether; Tcl inverts, see Section~\ref{sec:omega-fidelity}). Component magnitudes are toolchain-specific, tracking each host's introspective surface---execution buys $+8.1$~pp on SKILL but only $+5.3$~pp on Tcl, and retrieval buys $+15.1$~pp on SKILL, $+9.1$~pp on PyAether, $+7.7$~pp on Tcl---but the structure (observation + execution closing the loop) reproduces on every slice.

\subsection{Error Analysis}
\label{sec:error-analysis}

ZhuLong passes 82.5\% on PyAether, 60.3\% on SKILL, 88.6\% on WaveView, and 91.6\% on Innovus (Table~\ref{tab:main-ablation}). We split each slice's misses into a \emph{generation-stage} failure (no executable candidate returned) and an \emph{evaluation-stage} failure (a candidate returned but no pass). The generation/evaluation split is 29/109 on PyAether, 31/281 on SKILL, 1/43 on WaveView, and 1/23 on Innovus.
% 错误分析。ZhuLong 在 PyAether 过 82.5%、SKILL 60.3%、WaveView 88.6%、Innovus 91.6%（表~\ref{tab:main-ablation}）。失败分两阶段：生成阶段失败（轮次在产出任何可执行候选前结束）与评测阶段失败（产出候选但未通过）。生成/评测切分：PyAether 29/109、SKILL 31/281、WaveView 1/43、Innovus 1/23。下面剖析评测阶段失败。

The failures reduce to two missing ingredients, neither a matter of raw model capability: domain knowledge the prior would need to produce a candidate (L3), and a contract in the live design that $\Omega$ cannot see (L4). Generation-stage failures are predominantly L3; the four evaluation-stage patterns below are predominantly L4---constraints documented nowhere yet decisive, visible only through $\Omega$.
% 失败归结为两个缺失要素，均非模型原始能力问题：产出候选所需的领域知识（L3），与实时设计中 Ω 看不见的契约（L4）。生成阶段失败以 L3 为主；下方四类评测阶段模式以 L4 为主——文档从未记录却决定成败、仅能通过 Ω 观测的契约。
