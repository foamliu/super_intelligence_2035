\section{Experiments}
\label{sec:experiments}

\subsection{Experimental Setup}
\label{sec:exp-setup}

\subsubsection{Research Questions}

The framework of Section~\ref{sec:grounding-theory} makes three testable claims, one per research question:
\begin{itemize}
\item \textbf{RQ1 (Ceiling: observation or prior?).} Is accuracy bounded by $\Omega$'s fidelity or by $\mathcal{K}$'s strength? S1 varies $\Omega$ (LLM fixed); S3 varies $\mathcal{K}$ (harness fixed).
\item \textbf{RQ2 (Which components are necessary, and interchangeable?).} Does bridging the gap require observation, a causal effector, and continuous $\Phi$? S2 varies the effector and the belief-update budget.
\item \textbf{RQ3 (Domain class or toolchain?).} Does the same structure reproduce on a structurally different toolchain? S1--S2 are re-run on the SKILL and Tcl slices of \textbf{EDA-Scripting-Bench}.
\end{itemize}
RQ1 and RQ2 test the structural claims; RQ3 tests whether they follow from the domain's structure rather than from one toolchain.

\subsubsection{Benchmark and Evaluation Protocol}

We evaluate ZhuLong on \textbf{EDA-Eval-PyAether} (158 tasks) using \textbf{Pass@1} as the primary metric. Each task runs in a single trace with per-execution timeout 2500\,s; the agent may iterate within a trace via $\Phi$ but is never restarted. A file-based \texttt{PreToolUse} hook enforces a tool whitelist, blocks shell/code-search, and confines file access to a fresh empty workspace (identical across all arms). Each configuration is evaluated over five independent runs with reshuffled task order; accuracy is mean$\pm$std. Generation-stage failures (no executable code) are reported separately from execution-stage failures. Runs with infrastructure faults are discarded and re-run; the full-system anchor must reach $\geq$75\% Pass@1 as a health floor. All figures are on the PyAether slice; cross-language results in Section~\ref{sec:cross-language}.

\subsubsection{S2: The closed loop (RQ2)}
\label{sec:closed-loop}

Principle 3 requires actions to reach the design through a causal interface, and $\Phi$ to run continuously.

\textbf{Effector.} Removing the sandbox drops Pass@1 from 81.4\% to 72.2\% ($-9.2$~pp; McNemar $p{<}10^{-8}$, 95\% CI $[-13.1, -5.4]$~pp); adding it to the RAG baseline raises it by the same amount. Without an effector, $b_t$ receives no evidence about the live state and the agent is reduced to a prior-only predictor. Execution returns concrete error messages that guide corrections, transforming one-shot generation into iterative search~\cite{kumar2026agentforge, jiang2024seed}.

\textbf{Belief update.} ZhuLong is autonomous, so we do not shorten the loop or force early submission. Instead we bound how often the loop \emph{may execute}---the number of \texttt{run\_code} calls per trace---which determines how much state evidence $b_t$ receives. Once the budget is spent, the call is denied at the tool boundary; the agent keeps running under its own control until it submits. Table~\ref{tab:phi-bound} also includes a \emph{lagged} channel: a single-slot ($L{=}1$) buffer whose read-back returns the state from the \emph{previous} execution, leaving the agent permanently one action behind the design. Principle~3 predicts accuracy rises with the execution budget but saturates once updates outpace the design's dynamics.

\subsection{Error Analysis}
\label{sec:error-analysis}
% 错误分析

To characterize failure modes, we inspected a representative trace from the full-system 5-run set---the run whose Pass@1 (81.6\%, 129/158) is closest to the 5-run mean (81.4$\pm$1.5\%). The 29 failures comprise 17 generation-stage failures (no executable code produced) and 12 execution-stage failures, classified by the L1--L4 hierarchy of Section~\ref{sec:grounding-theory}.

The dominant execution-stage failure mode is \textbf{L4} (8/12, 67\%): situated truthfulness violations that no offline knowledge can prevent---the code is syntactically correct (L1), uses documented APIs with plausible arguments (L2--L3), yet fails because it violates an \emph{undocumented} binding contract, depends on an internal selection state, or assumes a runtime context that does not hold. For example, Task 010 (\texttt{add\_instance\_to\_schematic}) executes and passes the agent's own assertions, yet the official harness rejects it: \texttt{target\_cv must be an opened cellview object}---an L4 property of the live design state, not of the API signature. Tasks 063, 074, 146, 155 follow analogous patterns (hidden type names, attributes absent in the test path, GUI-dependent return values). The remaining execution-stage failures are \textbf{L3} (4/12, 33\%): valid APIs composed with incorrect logic (Task 052 substitutes a custom validator for the mandated call; Task 058 uses substring matching instead of equality). \textbf{L1/L2 = 0\%}.

The 17 generation-stage failures are timeout (4), wrong save path (10, saving to \texttt{ws/} instead of \texttt{ws/pyAether\_code/}---a procedural error amenable to harness-level mitigation), and no code produced (3).

The L1--L4 classification makes the grounding-gap framework concrete: 67\% of execution-stage failures are L4, invisible until the agent acts on the live design and reads back the result. This is why the execution loop is decisive: the sandbox is the only channel through which the agent can observe hidden type contracts, internal selection states, and runtime-context dependencies. These findings motivate type-aware API documentation and case-level knowledge distillation.
