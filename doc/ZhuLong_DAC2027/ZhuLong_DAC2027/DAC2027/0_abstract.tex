\begin{abstract}
    EDA scripting with tool-specific, often undocumented APIs remains a long-tail 
    bottleneck that existing LLM-based tooling fails to address. We present 
    \textbf{ZhuLong}, an execution-grounded LLM coding agent for PyAether, SKILL, and Tcl 
    that combines API retrieval, documentation inspection, and sandbox execution via 
    unified MCP tools into a closed generate--execute--refine loop. We further provide 
    a \textbf{theoretical grounding} for why runtime observation is necessary: EDA correctness 
    is a \emph{situated} property that cannot be guaranteed from static knowledge, 
    and we formalize this ``grounding gap'' with a Bayesian argument showing it is 
    bounded by observation fidelity---not model scale. We test this claim from both sides: with the LLM fixed, the observation ladder moves Pass@1 by 57.4~pp from the pure-LLM floor to the full system, while the backbone axis spans only 22.0~pp with the harness fixed. ZhuLong's harness supplies precisely that observation: it reads the environment's documented API facts, and reads back what executing code does to the live design.

    We evaluate ZhuLong on \textbf{EDA-Scripting-Bench}, 449 real-world tasks with assertion-based execution, spanning PyAether, SKILL, and Tcl on four commercial runtimes, where the complete system achieves \textbf{75.7\%} pooled Pass@1 over 
    five runs, substantially outperforming a pure LLM baseline (\textbf{18.3\%}) and 
    a retrieval-only baseline (\textbf{62.5\%}). Ablation studies show the execution 
    loop is decisive: removing either execution ($-13.2$~pp) or retrieval ($-11.8$~pp) 
    reduces accuracy. A complementary offline 
    \textbf{API self-exploration} mechanism contributes a further $+3.1$~pp accuracy 
    while cutting online per-task solve time by 27\% (excluding one-time offline exploration).
