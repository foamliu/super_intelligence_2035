\section{System Design}
\label{sec:system}

\subsection{Overall Architecture}
\label{sec:overall-architecture}

ZhuLong is built on Cline-CLI \cite{cline2024cline}, an open-source framework for autonomous coding agents, extended with EDA-specific retrieval, documentation, and execution capabilities. We call the resulting runtime an \textbf{ICL-type autonomous agent}: an agent that decides its own next action, keeps no explicit posterior, and maintains its belief state implicitly by in-context learning, as formalized in Section~\ref{sec:grounding-theory}. The policy is kept commodity and unmodified, so any gain is attributable to the interface; the runtime's permission and hook mechanisms also supply the enforcement points on which the fixed evaluation protocol relies (Section~\ref{sec:exp-setup}). As shown in Figure~\ref{fig:architecture}, the system comprises three components: the LLM-based agent runtime, the API knowledge base, and the EDA execution environment, linked through four MCP tools, with an offline \textbf{API self-exploration} step pre-augmenting the knowledge base.
% ZhuLong 基于 Cline-CLI，扩展 EDA 特定检索/文档/执行能力。称其运行时为 ICL 型自主智能体：自主决定下一步、无显式后验、以上下文学习隐式维护信念（§4 形式化）。策略保持商品化未改，使增益可归因于接口；运行时权限与 hook 机制提供固定评测协议的执行点（§6）。三组件：LLM 智能体运行时、API 知识库、EDA 执行环境，经四个 MCP 工具连接，离线自探索预增强知识库。

\subsection{Four MCP Tools}
\label{sec:mcp-tools}

The four tools jointly realize the observation channel $\Omega$ and the effector of Section~\ref{sec:grounding-theory}, each accepting a unified \texttt{lang}--\texttt{host} pair that selects the target runtime so identical agent logic covers all four runtimes: \texttt{search\_apis} retrieves relevant APIs by semantic similarity (BGE-M3 embeddings \cite{bge2024} with FAISS \cite{douze2024faiss}, top-$K$ above a threshold, merged with BM25 keyword matches); \texttt{search\_apis\_by\_keyword} retrieves by explicit keyword matching (CamelCase overlap plus BM25), complementing semantic search when a name fragment is known; \texttt{get\_api\_details} fetches full documentation (parameters, return values, examples), augmented by offline self-exploration when available; and \texttt{run\_code} executes generated code in an isolated headless EDA sandbox and reads back a structured result (status, error log, stdout, return value) for iterative refinement, dispatching on the \texttt{lang}--\texttt{host} pair to resident or one-shot workers per runtime.
% 四个工具共同实现 §4 的观测通道 Ω 与执行器，各接受统一 lang-host 对选定运行时：search_apis 语义检索（BGE-M3+FAISS，top-K 阈值，并入 BM25）；search_apis_by_keyword 关键词检索（CamelCase+BM25，已知名称片段时补充）；get_api_details 取完整文档（参数/返回值/示例，可被自探索增强）；run_code 在隔离无头沙盒执行并回读结构化结果（状态/错误日志/stdout/返回值），按 lang-host 分发到各运行时的常驻或一次性 worker。

\subsection{Agent Workflow}
\label{sec:agent-workflow}

The agent iteratively refines its output through execution feedback \cite{cline2024cline}: reasoning over the instruction, retrieving and inspecting candidate APIs, generating and executing code, then re-planning based on the observed result. The agent is not constrained to a fixed sequence---it may skip retrieval when it already knows the API or conduct multiple rounds when initial results lack confidence---and terminates when it judges further attempts unlikely to succeed.
% 智能体通过执行反馈迭代优化：推理→检索查阅 API→生成执行代码→据观察重规划。不受固定序列约束，已知 API 可跳过检索，置信不足可多轮；判定继续无望时终止。

\subsection{Offline API Self-Exploration (Complementary)}
\label{sec:selfdoc}

EDA API documentation is often incomplete, omitting parameter constraints, return structures, and error conditions. As Section~\ref{sec:grounding-theory} makes precise, retrieval-based augmentation enriches only the L1--L3 facts $\Omega$ can return, so it is complementary to---and bounded by---the observation of L4 that requires acting on the live design; we position self-exploration as an efficiency and robustness mechanism, not the primary accuracy driver. ZhuLong \textbf{proactively discovers} API behaviors through offline counterfactual experimentation in the sandbox: for each target API, the exploration agent reads available documentation, identifies gaps, generates targeted test scripts, executes them via \texttt{run\_code}, and iteratively refines a behavioral model capturing parameter constraints, return structures, error conditions, and side effects. A per-API confidence score accumulates information gain; exploration stops when the score exceeds threshold $\tau$, when two consecutive rounds add no new constraint, or when a per-API execution budget $M$ is exhausted; generated scripts are expert-gated to filter destructive operations. This offline process runs once per API, and the enriched documentation is served at runtime via \texttt{get\_api\_details} with no runtime overhead---removing it makes the agent both slower and more token-hungry (see supplementary material).
% 自探索（互补）。EDA 文档常不全。如 §4 所述，检索增强只丰富 Ω 可返回的 L1–L3 事实，故相对"作用于实时设计观测 L4"是互补有界的；自探索定位为效率/鲁棒性机制而非精度主驱动。ZhuLong 通过沙盒离线反事实实验主动发现 API 行为：读文档→识别缺口→生成测试脚本→run_code 执行→迭代细化行为模型。每 API 置信度分数累积信息增益，超阈值 τ / 连续两轮无新增 / 预算 M 耗尽时停止；脚本经专家把关过滤破坏性操作。每 API 一次性离线，运行时经 get_api_details 提供无额外开销——移除后更慢更费 token（详见 supplementary material）。附录 tab:cost 已删（10-24 删附录方案 B）。
