\section{Introduction}
\label{sec:introduction}

Large language models (LLMs) have demonstrated strong capabilities in general-purpose code generation \cite{vaswani2017attention, openai2023gpt4, yang2025qwen3}. However, applying LLMs to EDA scripting---where engineers manipulate in-memory design databases, create layout instances, route schematics, and query netlists---remains challenging: EDA APIs are long-tailed and tool-specific (many rarely appear in public training corpora); correctness cannot be verified statically (it depends on observable side effects in a real EDA environment); and without execution feedback, static generation cannot diagnose errors or iteratively refine \cite{chen2024dawning, blocklove2024eda}. Existing LLM-based EDA work has mainly focused on HDL generation \cite{thakur2023verigen, liu2023rtlcoder}, while scripting with real tool APIs---especially with incomplete documentation and sandbox execution---remains underexplored.

This paper presents \textbf{ZhuLong}, an execution-grounded LLM coding agent for PyAether, SKILL, and Tcl. Built on Cline-CLI \cite{cline2024cline}, ZhuLong extends three MCP tools \cite{lee2025autoeda}---\texttt{search\_apis}, \texttt{get\_api\_details}, and \texttt{run\_code}---that form a closed loop: retrieve candidate APIs, inspect their documentation, execute code in the EDA environment, and iteratively refine based on observed errors. All tools accept a unified \texttt{lang} parameter, so the same agent logic covers all three languages. We further provide a \textbf{theoretical foundation} (Section~\ref{sec:grounding-theory}): EDA scripting correctness is a \emph{situated} property that cannot be guaranteed from static knowledge, and the resulting ``grounding gap'' is bounded by observation fidelity---not model scale.

The main contributions are:

\begin{itemize}
    \item \textbf{An account of \emph{which} factor sets the ceiling, with measurements that distinguish them (RQ1).}
    We formalize the \emph{grounding gap}: EDA correctness is a situated (L4) property that no offline knowledge can guarantee, bounded by \emph{observation fidelity} not model capacity (Section~\ref{sec:grounding-theory}). We answer RQ1 from both sides---laddering $\Omega$ with the LLM fixed, and changing $\mathcal{K}$ with the harness fixed---stated \emph{before} the measurements as predictions the experiments could refute.

    \item \textbf{A harness whose necessary components we isolate (RQ2).}
    ZhuLong couples three MCP tools---\texttt{search\_apis}, \texttt{get\_api\_details}, \texttt{run\_code}---so that retrieval (observation), sandbox execution (effector), and the generate--execute--refine loop (belief update) form one closed loop, driven by a single \texttt{lang} parameter covering PyAether, SKILL, and Tcl (Section~\ref{sec:system}). ZhuLong attains \textbf{81.4\%} Pass@1 on the 158-task PyAether slice, versus \textbf{10.5\%} (pure LLM) and \textbf{72.2\%} (RAG). Ablation shows the components are jointly necessary and not interchangeable: adding execution to RAG yields \textbf{+9.2~pp}, removing it ($-9.2$~pp) or retrieval ($-0.4$~pp) reduces accuracy, and bounding $\Phi$ degrades it monotonically.

    \item \textbf{A cross-language benchmark on which the same structure can be re-measured per toolchain (RQ3).}
    \textbf{EDA-Scripting-Bench} places PyAether, SKILL and Tcl under one task schema, one assertion criterion and one harness (Section~\ref{sec:benchmark}). The completed PyAether slice (\textbf{EDA-Eval-PyAether}, 158 expert-reviewed tasks) is the first standardized PyAether benchmark. We release the harness, task schema and evaluation protocol; task cases derive from vendor documentation and customer designs and cannot be redistributed.
\end{itemize}
