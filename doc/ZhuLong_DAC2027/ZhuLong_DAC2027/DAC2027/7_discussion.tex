\section{Discussion}
\label{sec:discussion}


The theoretical characterization of Section~\ref{sec:grounding-theory} elevates the error analysis of Section~\ref{sec:error-analysis} from empirical observations to a structural principle: in domains with long-tailed, under-docu\-mented APIs, the grounding gap is bounded by observation fidelity, so execution channels—not larger priors—are the binding constraint. This paradigm may generalize to other domain-specific scripting tasks with similar characteristics.
% 第~\ref{sec:grounding-theory}节的理论刻画把第~\ref{sec:error-analysis}节的错误分析从经验观察提升为结构原则：在长尾、文档不完善API的领域，落地鸿沟受观测保真度约束，执行通道——而非更大的先验——才是约束所在。这一范式可能推广到其他具有相似特征的领域特定脚本任务。

Several limitations also warrant acknowledgment. First, performance varies significantly across base LLMs (53.7\%--75.7\% pooled), indicating that the underlying model remains a decisive factor. Second, offline self-exploration incurs upfront cost (one-time per API), amortized over subsequent queries. Third, the interactive bridge is single-threaded, limiting concurrent deployment. Fourth, although the headline results are pooled over all 449 tasks, the per-slice dispersions can be large for the ablated configurations (e.g., Tcl w/o Retrieval $\pm 13.8$), so slice-level comparisons should be read with care. Fifth, although each configuration was evaluated over five independent runs, the benchmark size limits statistical power to certify small effects, so the self-exploration gain (+3.1 pp) is reported as a complementary benefit rather than a headline result. Sixth, Pass@1 is assertion-based: a pass certifies that the generated code produces the effects the task's assertions check in the live runtime, not full functional equivalence; the assertions were expert-curated (Section~\ref{sec:benchmark}) but remain a proxy for correctness.
