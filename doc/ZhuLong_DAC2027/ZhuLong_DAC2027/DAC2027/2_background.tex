\section{Background and Motivation}
\label{sec:background}

We target three widely-used EDA scripting interfaces across four commercial runtimes: PyAether for Empyrean Aether \cite{empyrean_pyaether}, SKILL for Cadence Virtuoso \cite{cadence2024virtuoso}, and Tcl for Synopsys Custom WaveView and Cadence Innovus. Despite their prevalence, scripting for these environments poses challenges beyond what generic LLM code generators can address.
% 我们关注四种商业运行时上的三个广泛使用的 EDA 脚本接口：PyAether（Empyrean Aether）、SKILL（Cadence Virtuoso）、Tcl（Synopsys Custom WaveView 与 Cadence Innovus）。

\textbf{EDA scripting is fundamentally different.} Prior LLM code generation succeeds where correctness is verified by unit tests \cite{chen2021evaluating, austin2021program}. EDA scripting presents three distinct challenges: (i) APIs are long-tailed, tool-specific, and poorly documented; (ii) correctness depends on side effects in a live, stateful database, not return values; and (iii) the community lacks a standardized benchmark. The first two are technical; the third is infrastructural.
% EDA 脚本根本不同。此前 LLM 代码生成在单元测试可验证的领域成功；EDA 脚本面临三挑战：(i) API 长尾工具特定文档不全；(ii) 正确性取决于实时有状态数据库的副作用而非返回值；(iii) 缺标准化评测集。

\textbf{Prior custom/analog scripting work stops short of execution.} LayoutCopilot \cite{liu2025layoutcopilot} targets analog \emph{layout} (not scripting) via multi-agent collaboration; ChaTCL \cite{rui2025chatcl} and RAG-EDA \cite{pu2024rag} retrieve from static knowledge bases to generate Tcl scripts but do not execute them, so runtime errors remain undetected and the gap between ``looks plausible'' and ``actually works'' stays unbridged. Execution feedback is not itself new---in the digital flow, ChatEDA \cite{he2024chateda}, MCP4EDA \cite{wang2025mcp4eda}, and AutoEDA \cite{lee2025autoeda} close the loop against synthesis and P\&R state on open-source toolchains (Yosys, OpenLane, OpenRoad)---but none grounds against the live layout, schematic, or waveform database of custom/analog tools, the surface this paper targets. A recent survey \cite{liu2026agentic} organizes EDA agents by handoff validity; ZhuLong targets the custom/analog scripting handoff, previously ungrounded. Concurrent benchmarks focus on digital Tcl \cite{xu2026iscript} or physical-design agents \cite{li2026pdagent}; our benchmark is the first for custom/analog scripting across three languages and four commercial runtimes.
% 已有定制/模拟脚本工作止步于执行。LayoutCopilot 做模拟版图（非脚本）多 agent 协作；ChaTCL/RAG-EDA 用静态知识库生成 Tcl 但不执行，运行时错误无法发现。执行反馈在数字流程已有（ChatEDA/MCP4EDA/AutoEDA，开源工具链 Yosys/OpenLane/OpenRoad），但都未触及定制/模拟工具的实时版图/原理图/波形数据库——本文目标面。近期 survey \cite{liu2026agentic} 以 handoff 有效性组织 EDA agent；ZhuLong 针对此前未接地的定制/模拟脚本 handoff。同期 benchmark 聚焦数字 Tcl \cite{xu2026iscript} 或物理设计 agent \cite{li2026pdagent}；本 benchmark 是首个面向定制/模拟脚本、跨三语言四商业运行时的。

\textbf{Our approach.} ZhuLong closes the loop from generation to execution to refinement, supplies a \textbf{theoretical grounding} (Section~\ref{sec:grounding-theory}) explaining \emph{why} execution is necessary, and provides the missing infrastructure: \textbf{EDA-Scripting-Bench} (Section~\ref{sec:benchmark}).
% 我们的方法。ZhuLong 闭环"生成→执行→修正"，给出执行必要性的理论论证（§4），并提供缺失的基础设施 EDA-Scripting-Bench（§5）。
