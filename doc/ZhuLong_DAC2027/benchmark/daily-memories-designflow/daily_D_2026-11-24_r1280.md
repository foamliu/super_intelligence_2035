## 2. 修复手段（核心：canonical wrapper）

对 58 条「selftest 错置 root」case，**不重写各 selftest 的路径逻辑**（38 种路径模式，重写风险高），而是在 `reference/<id>/negative/negative_selftest.py` 落一个 **canonical wrapper**：

```python
HERE = os.path.dirname(os.path.abspath(__file__))      # negative/
CASE_ROOT = os.path.dirname(HERE)                      # reference/<id>/
ROOT_SELFTEST = os.path.join(CASE_ROOT, "negative_selftest.py")
if CASE_ROOT not in sys.path: sys.path.insert(0, CASE_ROOT)  # import check
os.chdir(CASE_ROOT)                                            # 相对 'negative'/'check.py' 路径
sys.argv = [ROOT_SELFTEST] + sys.argv[1:]
runpy.run_path(ROOT_SELFTEST, run_name="__main__")  # __file__=root → HERE=case root
```

**保证**：root selftest 的 `HERE/CHECK/NEG_DIR/ASSETS` 路径推导零改动，断言条数与严格度一条不降；wrapper 只是把 canonical 入口指向 root 逻辑。每条实测 `python3 negative/negative_selftest.py` rc=0 且 ≥3 distinct FAIL labels。

**副作用排查**：wrapper 文件本身位于 `negative/`，少数「遍历 negative/ 文件作 neg」的自测会把它当作一个 neg 提交——该提交跑 check() 必 FAIL（wrapper 在 check 沙箱里找不到 root selftest → exit 2），不破坏「all negs FAIL + ≥3 distinct」判定。57 条 wrapper case 实测全 PASS，无回归。
