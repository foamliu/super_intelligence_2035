### 本轮发现与修复

#### 审计脚本 `scripts/audit_check_returns.py` 两个 bug

**Bug #1（嵌套 helper 假阳）**：`audit_check_source` 用 `ast.walk(check_fn)` 收集 return，但 `ast.walk` 会递归进入 check() 内定义的嵌套 FunctionDef/Lambda 体——这些 helper 的 return 不影响 judge（judge 只看 check() 自身返回值）。修法：改用自己写的 `_walk_own`，遍历 check_fn 子树但跳过嵌套 FunctionDef/AsyncFunctionDef/Lambda 子树。效果：D-shard reference OK 380→459（+79 假阳修正）。

**Bug #2（判据语义错误）**：原判据 `all_compliant = all(r[1] for r in returns)` 要求 check() 的**所有** return 都 compliant。但失败路径的 non-compliant return（变量/list/tuple/str/None）在新契约下正确产生 FAIL——这是预期行为，不是违规。只有当 check() **没有任何 success-capable return**（即连一条能产生 PASS 的 return 路径都没有）时，才是真 VIOLATION（因为正确交付件也会被判 FAIL）。修法：新判据 = 存在 success-capable return（shape ∈ {True, dict-pass-ok, bool_call, boolop, not, ternary-双分支 compliant}）→ OK；否则 → VIOLATION。效果：OK 459→480（dict-fix 后）→ 最终 631。
