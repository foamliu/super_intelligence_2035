# Task
Implement `proc pnr_signoff_parse_sta_report {report} { ... }` in Tcl per this spec:

You are parsing a Synopsys PrimeTime static-timing signoff report (a single Tcl string `report` with newline-separated sections). The report has four kinds of blocks:
1. A "Reading SPEF file" block with lines:
     `#   Number of nets annotated: <int>`
     `#   Number of nets total:     <int>`
2. One or more per-path report_timing blocks, each ending in a path-slack line:
     `  slack (VIOLATED)   <num>`   or   `  slack (MET)   <num>`
   (lowercase `slack`, a `(VIOLATED|MET)` tag, NO colon, NO trailing `ns` -- just a signed decimal).
3. A "# Timing Summary" block with:
     `  WNS (ns): <num>`
     `  TNS (ns): <num>`
     `  Number of violating endpoints: <int>`
     `  Number of total endpoints:     <int>`
4. A "# Critical Path Summary" block with:
     `  Critical Path Levels: <int>`
     `  Data Arrival Time:    <num> ns`
     `  Data Required Time:   <num> ns`
     `  Slack (VIOLATED|MET):     <num> ns`
   (note this one HAS a colon and a trailing `ns` -- it is NOT a path-slack line; do not confuse it with type 2.)

Rules (these encode real-world traps a junior engineer gets wrong):
1. Slack sign convention: slack = required - arrival. A VIOLATED path has arrival > required, so its slack is NEGATIVE. Do NOT compute arrival - required (that flips the sign). `slack_convention_ok` = 1 iff `critical_slack_ns == critical_required_ns - critical_arrival_ns` (within 0.001), else 0.
2. TNS = sum of the NEGATIVE path slacks ONLY. MET (positive) paths must NOT be added. Round TNS to 2 decimals. If there are no negative slacks, TNS = 0.0.
3. WNS = the WORST (most negative) slack over all type-2 path-slack lines. It may be POSITIVE if every path is MET (passing design). Do NOT take the max, do NOT force a negative, do NOT just take the first.
4. SPEF coverage = annotated / total (NOT total / annotated), times 100, rounded to 1 decimal. Handle total > annotated (partial coverage). If total == 0, coverage = 0.0.
5. num_startpoints = count of lines containing the substring `Startpoint:`.
6. num_violating_endpoints and num_total_endpoints come from the Timing Summary block (authoritative).
7. The critical-path block's `Slack (...):  <num> ns` line (with colon + ns) gives `critical_slack_ns`; the `Data Arrival Time:` / `Data Required Time:` lines give `critical_arrival_ns` / `critical_required_ns`; `Critical Path Levels:` gives `critical_levels`.

Use only Tcl builtins (regexp, split, expr, dict, llength, lindex, lappend, lsort, etc.). No external packages.

Return a Tcl dict via `dict create` with EXACTLY these keys:
  num_startpoints spef_annotated spef_total spef_coverage_pct wns_ns tns_ns
  num_violating_endpoints num_total_endpoints critical_levels critical_arrival_ns
  critical_required_ns critical_slack_ns slack_convention_ok

Parse path-slack lines (type 2) with the regex:
  `^\s*slack\s+\((VIOLATED|MET)\)\s+(-?\d+\.\d+)\s*$`
This deliberately does NOT match the critical-summary line (which has a colon and trailing `ns`).

proc assert {cond msg} {
    set ok [uplevel 1 [list expr $cond]]
    if {!$ok} { error "ASSERT FAIL: $cond -- $msg" }
}
proc feq {a b {tol 0.001}} { return [expr {abs(double($a)-double($b)) < $tol}] }
