# Task
Implement `proc argus_lvs_log_triage {path} { ... }` in Tcl per this spec:

You are triaging an Empyrean Argus LVS log (a file at `path`). Read the file, parse these plain-text markers (one per line), and classify the LVS run into 4 problem categories with a single PRIMARY category by priority.

Markers:
- `LVS TOTAL TIME/MEM: CPU TIME = <cpu>, REAL TIME = <real>, PEAK MEM = <mem>` -- final summary; presence => LVS COMPLETED; <real> = total REAL TIME seconds.
- `LVS ... Done.` -- alternative completion marker.
- `CUMULATIVE REAL TIME = <n>` -- running cumulative REAL TIME (use as total when no final summary).
- `CUMULATIVE CPU/REAL TIME = <cpu>/<real>` -- another cumulative form (use <real>).
- `NE PHASE PROGRESS: <pct>%` -- NE phase completion percent (0..100); -1 if never reported.
- `---- CMD <c>(<m>) OPERATION START ON ... AND <N> PENDING OPERATIONS` -- <N> = concurrent procs (report max, do NOT use for stuck).
- `SHORT: <netA> - <netB>` -- a short. Power/ground iff a net ends with `!` (SPICE global) OR matches (case-insensitive) one of: vcc vss vdd gnd vdda vssa vddq vdpg avdd avss iovdd iovss.
- `TOTAL PIN ERRORS: <n>` -- pin error count summary.
- `============end============` -- end of LVS log; EVERYTHING AFTER is the PVE viewer log and must be IGNORED.

Return a FLAT Tcl dict STRING (key value pairs, space-separated) with EXACTLY these keys:
  lvs_completed        = 1 if a completion marker seen, else 0
  total_real_time_sec  = total REAL TIME (final summary, else max CUMULATIVE REAL TIME, else 0)
  ne_progress_pct      = NE PHASE PROGRESS percent (0..100), or -1 if never reported
  max_pending_operations = max <N> from "AND <N> PENDING OPERATIONS" lines (reported only)
  power_ground_short   = 1 if any SHORT: line is between power/ground nets, else 0
  short_net_pairs      = semicolon-joined list of the power/ground short pairs "netA-netB" (in order seen), empty string if none
  pin_error_count      = TOTAL PIN ERRORS value, else 0
  pin_error_storm      = 1 if pin_error_count > 10000, else 0
  stuck_long_running   = 1 if ne_progress_pct in [0,15) AND total_real_time_sec > 120, else 0
  interrupted          = 1 if (not lvs_completed) AND total_real_time_sec <= 30, else 0
  primary_category     = single result by priority:
                         interrupted > power_ground_short > pin_error_storm > stuck_long_running > completed_clean

REAL-WORLD TRAPS (engineers get these wrong -- the test checks them):
1. "N PENDING OPERATIONS" is NOT a pending backlog -- it is the count of concurrent algorithm processes. A COMPLETED run with full progress can legitimately show hundreds of PENDING. Decide "stuck" ONLY from ne_progress_pct and total_real_time_sec, NEVER from max_pending_operations.
2. A power/ground short can exist EVEN WHEN LVS PASSES. Read the SHORT: lines, NOT the LVS PASS/FAIL verdict. (A real run had vddq!-vdpg! short but LVS verdict PASS.)
3. A SHORT: line between two signal nets (no `!`, no power/ground name) is NOT a power_ground_short.
4. Ignore everything after the `============end============` marker (PVE viewer log).
5. Interrupted (crashed early, small REAL TIME, no completion marker) vs stuck (hung, large REAL TIME, low NE progress) are distinguished by REAL TIME, not by the absence of a completion marker alone.

Use only Tcl builtins (open, read, split, regexp, regexp -nocase, expr, join, lappend, etc.). No external packages. The proc reads the file at `path`.

# assert shim: the runtime Tcl has no native 'assert' command.
proc assert {cond msg} {
    set ok [uplevel 1 [list expr $cond]]
    if {!$ok} { error "ASSERT FAIL: $cond -- $msg" }
}
proc _wlog {path content} {
    set fo [open $path w]
    puts -nonewline $fo $content
    close $fo
}
