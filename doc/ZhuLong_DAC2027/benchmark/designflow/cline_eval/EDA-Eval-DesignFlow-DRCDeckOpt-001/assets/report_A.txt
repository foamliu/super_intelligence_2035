四、Deck 优化建议
================================================================================

--------------------------------------------------------------------------------
建议 1 (最高优先级): R_C_MT2_F_01_M - 空间预过滤 M0C_Total
--------------------------------------------------------------------------------

问题:
  A0 = M0C_Total WITH WIDTH < 0.102 对全芯片 1.7 亿图形全量逐边扫描，耗时 16853s，
  但该 rule 最终 Results = 0。

根因:
  rule 的两个 check (TOUCH EDGE ... MT2_CORE 和 B1 INSIDE A1) 都要求结果靠近 MT2_CORE
  边界。A1 从 A0 最大膨胀 0.30，所以距 MT2_CORE 边界 >0.30 的窄缝不可能产生结果。

改法 (deck 行 775-783):
  用 SIZE MT2_CORE 构造 0.35 边缘条带，INTERACT 筛选 M0C 子集后再做 WITH WIDTH。

改前:
  R_C_MT2_F_01_M{
      @Forbidden - MT2 Coin edge or Cut M0C_Final [width < 0.102um] is not allowed
      A0 = M0C_Total WITH WIDTH < 0.102
      A1 = A0 ENCLOSE RECTANGLE 0.30  0.09
      A2 = TOUCH EDGE (COIN EDGE A1 M0C_Total) MT2_CORE
      LENGTH A2 >= 0.362
      B1 = EXPAND EDGE MT2_CORE INSIDE BY 0.001
      B1 INSIDE A1
  }

改后:
  R_C_MT2_F_01_M{
      @Forbidden - MT2 Coin edge or Cut M0C_Final [width < 0.102um] is not allowed
      mt2_outer = SIZE MT2_CORE BY 0.35 UNDEROVER
      mt2_inner = SIZE MT2_CORE BY -0.35 UNDEROVER
      mt2_edge  = mt2_outer NOT mt2_inner
      M0C_sub   = M0C_Total INTERACT mt2_edge
      A0 = M0C_sub WITH WIDTH < 0.102
      A1 = A0 ENCLOSE RECTANGLE 0.30  0.09
      A2 = TOUCH EDGE (COIN EDGE A1 M0C_Total) MT2_CORE
      LENGTH A2 >= 0.362
      B1 = EXPAND EDGE MT2_CORE INSIDE BY 0.001
      B1 INSIDE A1
  }

  注: COIN EDGE A1 M0C_Total 仍引用完整 M0C_Total (不改为 M0C_sub)，保证 coincident
      edge 检查完整。这步原来耗时 324s，可以接受。

预估: A0 从 16853s 降至 ~500-2000s (降 84-94%)，全 run 从 5.6h 降至 ~1.5-2h。

--------------------------------------------------------------------------------
建议 2 (中优先级): R_C_M0C_ENC_01_H / ENC_02_H / PCU_S_06_H 族 - 缩小 INTERACT 中间层
--------------------------------------------------------------------------------

问题:
  这些 rule 共同模式是 M0C_Total INTERACT PC_Total 产生 TMP 中间层 (FGC=3.57亿，
  放大 5.5x)，后续 NOT COINCIDENT EDGE / INT 操作因此耗时 514-1730s。

改法:
  在 INTERACT 前对 M0C_Total 做空间预过滤，只保留 PC_Total 附近的 M0C。
  由于 ENC/INT 的检查范围都在 0.027-0.086 um 量级，可用 SIZE PC_Total BY 0.1 构造
  缓冲区筛选 M0C_Total。

改前 (R_C_M0C_ENC_02_H, deck 行 663-671):
  R_C_M0C_ENC_02_H {
      A1 = COPY M0C_Total
      A2 = INT (A1 INTERACT PC_Total) < 0.001 ABUT==90 REGION
      A3 = (A1 INTERACT PC_Total) COIN EDGE A2
      A4 = EXPAND EDGE A3 OUTSIDE BY 0.001
      A5 = (A4 OR (A1 INTERACT PC_Total)) NOT COIN EDGE (A1 INTERACT PC_Total)
      ENC PC_Total A5 < 0.035 CORNER TO CORNER REGION
  }

改后:
  R_C_M0C_ENC_02_H {
      A1 = M0C_Total INTERACT (SIZE PC_Total BY 0.1 UNDEROVER)
      A2 = INT (A1 INTERACT PC_Total) < 0.001 ABUT==90 REGION
      A3 = (A1 INTERACT PC_Total) COIN EDGE A2
      A4 = EXPAND EDGE A3 OUTSIDE BY 0.001
      A5 = (A4 OR (A1 INTERACT PC_Total)) NOT COIN EDGE (A1 INTERACT PC_Total)
      ENC PC_Total A5 < 0.035 CORNER TO CORNER REGION
  }

预估: TMP 中间层 FGC 从 3.57 亿降至千万级，NOT COINCIDENT EDGE 从 661-1730s 降至百秒级。

--------------------------------------------------------------------------------
建议 3 (治本): 从源头保留 M0C_Total / PC_Total 的层次
--------------------------------------------------------------------------------

问题:
  M0C_Total 的 FGC 暴涨根源是 M0C_ARRAY (9 个 hier cell -> 2.9 亿 flat 实例) 在 OR 时
  丢失层次。MT2_CORE 的 2663x 放大也源于类似扁平化。

改法:
  审视 M0C_First = OR M0C_CORE M0C_ADDM0C M0C_ARRAY 和 M0C_Total = OR M0C_First
  M0C_Second 的构造，确认是否可通过 PRECISION LAYOUT、FLATTEN PCELL 或调整 OR 顺序
  保留层次压缩。这是架构级改动，建议在前两条优化验证后再评估。
