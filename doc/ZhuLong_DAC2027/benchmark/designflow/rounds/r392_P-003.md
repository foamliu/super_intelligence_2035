## 议题

## 结论（r392 CLOSED）

域级 depth 标签**系统性错配** case 级真实 grounding demand，跨 3 域（A verification+digital / C physical_verify+layout_aether / D analog+schematic+waveform）同构：

1. **错配方向**：系统性**上调**（域级标签比真实 depth 深），非随机噪声。A 9/12 上调 2-4 档，C physical_verify 9/9 上调 +5-6 档（depth 7+ 实为 parse-only），D 5/5 上调均值 +2.6 档。
2. **因果影响**：§5.2 depth→Pass% 斜率被浅 case 虚标的深 bin 拉高/压低（方向取决于 case 通过率），bin 内方差被掩盖。§5.2 line 58「must drive」对 physical_verify 9/9 反因果（C r399 falsify）。abstract line 10 + §4 line 77「7.1× 域差距 → grounding depth 是因」headline 在 physical_verify 子域反因果。
3. **修法**：§5.2 改按 `actual_tool_demand(3) × asset_fidelity(2)` 双轴 sub-bin——depth 7+ 须拆 (a) drive-and-iterate / (b) parse-multi-MB-output 分别报 Pass@1（C r399）；全 bin 加 actual_tool_demand × asset_fidelity 双轴标注（D r522）；line 46「per domain」改「per case × {drive/parse/pure} × {real/synthesized}」；caption line 65「design choice」连到 §2 line 104「judging stdlib only ⇒ depth labels are design-intent, not verified behavior」；abstract/§4 headline 加限定「grounding depth 按 case 级 actual_tool_demand，非域级标签」。
4. **可行性**：actual_tool_demand × asset_fidelity 双轴可由 check.py 源码 + 资产路径静态判定，**不需重跑 696-run 评测**（A 12/12 + C 24/24 + D 5/5 已验证可静态判定）。
5. **与 P-002 联动**：A 域 depth 4/5 bin 修复依赖 P-002 解锁 L2/L3 造题能力，但 r392 post-scan 增量新证（13/13 非 A-domain）显示 L2/L3 A-domain trace 源不会自然出现 ⇒ 若 P-002 PIVOT 选 (d) 接受饱和，A 域 depth 4/5 bin 只能靠改标注（本结论 3）而非补 case 修复。
