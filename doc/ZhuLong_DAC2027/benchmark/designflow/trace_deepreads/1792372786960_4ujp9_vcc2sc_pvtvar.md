The real netlist / foundry model is permission-denied / non-portable to .75, so the DUT is
replaced by a self-contained linear standby regulator that preserves the measurable behavior:
- `Eref nref 0 vol='Vref*(1+a*pt)'`  (controlled reference, pt = process-temp factor)
- `Rout vout nref rout`              (series output resistance)
- `Iload vout 0 pwl (0 0 15n 0 16n 1m 40n 1m)`  (PWL: 0 in standby window, 1 mA in loaded window)
- `Cload vout 0 1p`
- ⇒ vout_stdby = Vref*(1+a*pt)            (measured 8n–10n, load off)
- ⇒ vout_1ma   = Vref*(1+a*pt) − Iload*Rout (measured 18n–20n, load = 1 mA)

## Key HSPICE trap discovered on .75 (the crux)
PrimeSim HSPICE V-2023.12-SP1-1, for a deck with N `.alter` blocks, writes **N separate
`.mt<N>` files** (`.mt0` = base corner, `.mt1` = alter 1, …, `.mt(N-1)` = alter N-1), each
containing a **single row** for that corner's `.measure` results — NOT all corner rows in one
`.mt0`. A naive `parse_mt0(".mt0")` reads only the base corner (1 row, alter# = 1) and silently
drops all other corners. Verified empirically on .75:

```
$ hspice -i alt_test.sp -o alttest
alttest.mt0  (row: vout_stdby=0.985  alter#=1   pt=-1.5)
alttest.mt1  (row: vout_stdby=0.995  alter#=2   pt=-0.5)
alttest.mt2  (row: vout_stdby=1.005  alter#=3   pt= 0.5)
alttest.mt3  (row: vout_stdby=1.020  alter#=4   pt= 2.0)
```

Fix: `run_hspice` globs `*.mt[0-9]+` in numeric order; `main` parses each and concatenates
rows before `analyze`. `.option MEASFORM=1` gives a clean columnar layout. (`.option MEASFORM=1`
does **not** merge per-alter files — it only changes the column format; the per-alter split is
intrinsic to this HSPICE version.)

## Other traps baked into the case
1. `variation = max − min` across all corners (the SPEC = distribution range), **not** adjacent
   (sorted) difference, **not** std. naive_wrong_variation computes adjacent diff → falsely
   passes spec.
2. `spec_pass` requires **both** vout_stdby and vout_1ma variation < spec_var_max.
3. `worst_corner` = corner whose vout_stdby deviates most from the mean (not the max-pt corner).
4. Real HSPICE subprocess run; parse `.mt<N>` raw SI; no print-expected / lookup.
5. `optimization_hint` (when FAIL) must name the violator metric, the worst corner, and give a
   quantitative `a_new < a * spec_var_max / current_range`.
