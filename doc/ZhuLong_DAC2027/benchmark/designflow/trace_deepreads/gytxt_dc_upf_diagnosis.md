## 金标准诊断（助手 msg#47，已用真实文件逐条验证 ✓）
### 问题一：save_upf 输出空 → `-supplemental` 预期行为，非 UPF 加载失败
1. `enable_golden_upf true` → 加载的 UPF 定为 golden 基准，DC 只记**偏差**
2. UPF 无任何电源策略（无 isolation/level-shifter/retention），两域同 0.72V → 不插任何单元（日志 UPF-214/464 证实 0），无 supply exception
3. `set_voltage` 只是电压标注，非结构变化，不写 supplemental
→ **无增量可写**，文件只剩 2 行注释头。电源意图未丢，在 golden UPF + DDC + check_mv_design 验证的内存设计里。
**修复二选一**：(A) `save_upf ${RESULTS_DIR}/${DESIGN_NAME}_dc.upf`（去 `-supplemental`，输出完整）；(B) 保留 `-supplemental`，下游先 load 原始 UPF 再 load 增量。
**附加隐患**：`dc_setup_filenames.tcl` 的 `FINAL_UPF` 变量从未被使用，save_upf 路径硬编码 `_dc.upf`，建议统一用 `${FINAL_UPF}`。

### 问题二：netlist 无 VDD/VSS → DC write Verilog 固有行为，非缺陷
1. DC `write -format verilog` 从不输出 PG 引脚（即使 UPF 流程）；PG 意图由 UPF + DDC 携带
2. RTL 顶层本身无 VDD/VSS/VDD_PM 端口（rtl_power top.v 证实），UPF `create_supply_port` 是"虚拟"电源端口，不进网表端口
3. PG 连接是下游活：ICC2 `connect_pg`/`compile_pg`；Innovus `globalNetConnect`；仿真用 `sim.upf` + power-aware sim
→ **无需修复**。

### 顺带隐患（建议一并处理）
1. **`load_upf` 在 `link` 之后**（dc.tcl: link L~57 → load_upf L~234）。Synopsys 规范顺序 `elaborate → load_upf → link`。本次 check_mv_design 全绿说明 UPF 实际生效，但建议挪到 link 前，避免某些版本 supply network 绑定不完整。
2. **UPF 潜在 bug**：被注释的 `set_port_attributes` 端口列表用**逗号**分隔 `{ClearFreqDiv, SelByFreq0, ...}`，UPF/Tcl 列表必须**空格**分隔，将来取消注释会直接报错。
3. **`create_power_domain pd_aon -include_scope -elements {.}`** 中 `-elements {.}` 与 `-include_scope` 冗余（无害，可删）。
