# P0_设备通路.md — 手机型号 / 系统版本 / 连接通路 / 选定路线

> 生成时间：2026-11-07（robot 线第 1 轮）· 主机 `hx-c1000`（Win11 本机）

## 0. 一句话结论

- **手机未连上本机**：本机 `adb` / `hdc` 都**未安装**（不在 PATH），USB 上**未检测到**任何华为/荣耀/Android/ADB/HDC 设备。
- **选定路线 = R3「不改系统」**：手机只做「眼耳口」（拍照/录音/播放），推理与智能体跑在 PC（本地 `ollama` 大模型 + Python 工具）。
- **最小 demo 已在 PC 端 mock 跑通**：题图 → OCR 识别 → LLM 分步引导（不泄答案）→ Windows TTS 出声，全链路真实产物。
- **需要用户做的事压成 5 条**（见 §4）。

判据对照（任务书 §2.1）：`adb devices` 无响应 且 `hdc list targets` 无响应 ⇒ **手机未连或未开调试，直接报清单**（即 §4）。

## 2. 选定路线：R3「不改系统」（手机采集+播放，推理在 PC）

| 路线 | 结论 | 理由 |
|:--|:--|:--|
| **R3（选中）** | ✅ 手机只做拍照/录音/播放；核心 agent 在 PC（Python + ollama 本地大模型 + Windows TTS） | ① 手机型号/系统未知，R3 不依赖具体系统；② 本机已具备完整推理栈（ollama `qwen3:8b`/`llava` + SAPI TTS），PC 端 mock 已真跑通；③ 零采购/零外部账号，符合红线；④ 最容易验证、逐层给判据 |
| R1 HarmonyOS NEXT | ⏸ 待定 | 需先确认是 NEXT（5.x 纯鸿蒙）；工具链体积大（DevEco Studio 5.x + HDC + HAP 签名），且当前手机未连、无法冒烟 |
| R2 HarmonyOS 4/EMUI | ⏸ 待定 | 需先确认是 4.x/EMUI；无障碍被系统限流、各家 ROM 差异大；同样需手机先连上 |

> 关键裁决依据：**手机未连 + 系统版本未知**，R1/R2 都卡在「必须先确认型号/系统」这一前置条件上；
> 而 R3 的 PC 侧今天就能真跑通。故先走 R3，手机连上后再按实际系统决定是否引入 R1/R2 的手机端采集。

## 3. 最小 demo 结果（第 1 轮验收）

链路：`mock 手机拍照` → `llava OCR 识别` → `qwen3:8b 分步引导` → `SAPI TTS 出声`

```text
PS> py -3.10 ..\proto\mock_device.py --snap "解方程：2x + 3 = 11" --out ..\eval\q1_equation.png
    [mock 手机·眼] 已拍照 -> ..\eval\q1_equation.png

PS> py -3.10 -W ignore tutor_agent.py --image ..\eval\q1_equation.png --speak demo_step1.wav --answer "4"
    [识别] 0.1s
    2x + 3 = 11

    家教（只推进一步，不给答案）：
    你想先做什么呢？比如先移3还是先除以2？

    [出声] 已朗读并保存 WAV：demo_step1.wav
    （demo_step1.wav：48000Hz 立体声，11.53s，峰值振幅 28815 → 真实音频）
```

- ✅ 题干识别正确（`2x + 3 = 11`）
- ✅ 引导**不含最终答案**（`--answer "4"` 红线自检未触发告警）
- ✅ 产出真实 WAV（可证伪的「出声」）

## 4. 需要用户做的事（≤ 5 条，可一次性照做）

1. **告知手机型号 + 系统版本**（设置 → 关于本机：是 HarmonyOS NEXT 5.x，还是 HarmonyOS 4.x / EMUI）—— 决定后续走 HDC 还是 adb。
2. **开启开发者模式 + USB 调试**，并用数据线把手机连到本机 `hx-c1000`，在弹出的调试授权里点「允许」。
3. **装连接工具**（装一个即可，我来自检）：
   - HarmonyOS NEXT → 装 DevEco Studio（自带 HDC），或单独下 HDC；
   - HarmonyOS 4.x / EMUI → 装 Android `platform-tools`（含 adb）。
   装好后我会跑 `hdc list targets` / `adb devices` 复验。
4. **确认产品形态**：A 软件机器人（默认）/ **C 手机+PC 协同（本 demo 路线，推荐先做）** / B 实体机器人（需另配底盘/舵机/摄像头，未确认不采购）。
5. **确认大模型来源**：默认用本机 `ollama`（离线、免费、不买 API）；若已有云端大模型/智能体 API 请提供（未提供前继续用本地 ollama）。

## 5. 本地阻塞项（agent 侧可自解，不占用户条目）
