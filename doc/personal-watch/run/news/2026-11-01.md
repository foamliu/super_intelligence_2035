- **DeepSeek 发布《Super-agent 设计探索：迈向更自主的 Agent 系统》：Router + Worker 双层架构、事件驱动、投机执行、Watchdog 外部回路；初步实验中 Super-agent 任务完成时间 p50 12.4 分钟 / p95 15.7 分钟，单 Session 方案 p95 29.5 分钟**
  摘要：DeepSeek Harness 官方团队 10-31 发布该文，提出「Super-agent」形态及四项基础特征 —— **连续、高效、主动、持久**（跨 IM / GitHub 评论等渠道同一 Agent；并行处理多任务；持续观察环境事件自行推进；长期在线并从异常恢复）。架构由五部分组成：**双层架构**（Router 承接人类交互、维护全局上下文并分派任务；Worker 在相互隔离的会话中并发执行，只向 Router 汇报）· **事件驱动**（群聊消息、邮件日程、代码审查评论、CI 结果等外部信息统称 Trigger，先程序规则过滤再由大模型判断；已分配任务的 Worker 可订阅 Thread 直收后续事件，降低路由负载）· **面向人的交互**（异步 ReAct Loop，耗时工具调用改为异步 start()/stop()，Agent 返回 Started 后不等待；团队说明该异步机制**已在 Harness 中实现但尚未默认开启**）· **计算与状态及环境分离**（计算与持久化状态在云端，执行环境可留在用户本机，仅部署轻量 daemon，支持 **BYOM**「自带机器」）· **Watchdog**（独立会话，监控接口报错 / 状态恢复失败，并用模型判断 Worker 是否取得实质进展、方向是否偏离）。另介绍 **Inline & Spill**（近期可能用到的信息放上下文窗口，超预算 / 低频内容留窗口外按需读取）与**链式召回 Chain of Recall**（沿 Trigger / Thread / Worker Session 的引用关系找回历史任务信息）。实验规模：每次约 **300 条消息**（其中约 **20 条为工作请求**），每种方案重复 **5 次**；Router 压力测试中 Trigger 到达速率从约 **1 条/分钟**升到约 **40 条/分钟**时，平均批处理大小 1.0 → 2.8，单次请求耗时 2.5 秒 → 3.9 秒。
  原文 vs 判断：架构、特征、实验数字全部出自 DeepSeek 团队原文；团队**自述**「实验基于合成负载和简化环境，主要评估系统调度与协作能力，并不衡量单个任务的实际执行能力」。—— 我们的观察：文中给出的瓶颈不是模型能力，而是**人的注意力**（「一个人通常只能同时跟进 3 至 5 个活跃 Session」）；这与本书「注意力主权」的设定同向，但原文只讨论工程架构，不涉及社会后果。
