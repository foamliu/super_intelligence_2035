## 正文段（每行一段，喂给 paras.txt）

微软的老板纳德拉，最近公开认了一件事。

他说，Anthropic 推出 Claude Code 之后，VS Code 这类传统代码编辑器和 IDE，大概六个月就失去了存在感。

这话从微软 CEO 嘴里说出来，分量不太一样。

毕竟 VS Code 就是微软自家的产品，十多年里他们一直想把它做成开发者默认的办公桌。

纳德拉自己也解释了：过去十多年，微软一直在朝这个方向努力，产品经理每天读社区反馈，按用户意见改产品。这套开放式开发的做法，他一直很肯定。

转折点很清楚。AI 浪潮之前，VS Code 已经能做代码补全；后来 Cursor 基于 VS Code 的分支做出智能体模式，微软也很快跟上了。

但纳德拉说，Anthropic 在模型上做得太出色，还让开发者真正接受了命令行这种形态。

写程序这件事，从"输入"变成了"输出"。

大约六个月，老一代的工作台就不太被打开了。

他从中得出的教训只有一句：不要迷恋自己打造的东西。

这句话值得抄在本子上。做产品的人最容易犯的错，就是把自己上一个成功的作品当成护城河，结果护住的是旧的方法。

不过纳德拉并不认为微软没机会了。

他提到，随着新一代决策模型推出，IDE 甚至可能迎来一次复兴。按照他的说法，未来 IDE 的核心不再是手搓代码，而是写出真正的说明文档。

换句话说，人的活从"敲"变成了"说清楚"。说清楚要什么、约束是什么、验收标准是什么，剩下的交给系统去跑。

微软这两周的动作也在这个方向：11 月 11 日发布的 VS Code 1.146 加了智能体收件箱和模型对比，一周后的 1.147 又带来模型路由、定时提交智能体请求和浏览器集成。

把这几件事放在一起看，有意思的不是谁赢谁输，而是速度。

一个工具从"默认选择"到"存在感下降"，用了大约半年。上一轮软件行业的替换周期，通常以年计。

对我们普通人来说，这意味着两件事。

第一，你熟悉的那个按钮和菜单，可能不是被更好的按钮和菜单取代，而是整块界面都不需要了。

第二，能被写清楚的需求，越来越值钱；只会照着旧流程点鼠标的熟练度，贬值很快。

微软会不会靠下一代决策模型把桌子搬回来，现在下结论太早。但纳德拉愿意公开说"我们慢了"，这本身就是一个信号：连最会做开发工具的公司，也在重新学怎么用工具。
