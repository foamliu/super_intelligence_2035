# 漏洞为什么藏不住了：谷歌把公开期限一路压到三十天

十一月十三日，谷歌的漏洞挖掘团队 Project Zero 改了自己的披露规则。

原来的规则叫「九十加三十」：给厂商最多九十天修，再留三十天缓冲推补丁。新的规则把这两段合成一段，并且往后逐年收紧。

具体是三档。今年十一月十三日起，报告给厂商之后九十天公开，那三十天缓冲不再另算。二〇二七年二月二日起，六十天。二〇二八年一月三日起，三十天。

到那时，一家厂商从收到漏洞报告到细节见光，只有一个整月。

更值得注意的是另一处改动：谷歌把原先大把的「特殊情况」基本取消了，只留三条。一是在野利用，也就是漏洞已经被攻击者拿去用；二是细节已经被别人先公开；三是收报告的厂商自己请求公开。

换句话说，修没修好，不再是公开与否的前提。

谷歌给的理由写在公告的动因里：人工智能辅助的漏洞挖掘和利用技术起来了，原有的修复周期跟不上。这句话不长，但把压力点说清楚了——发现漏洞的那一端变快了，修复的那一端还是原来的节奏。

这件事有意思的地方在于，它改的不是技术，是时间。

漏洞从被发现到被修补，中间那段叫补丁空窗期。空窗期里，用户以为自己在用正常的软件，实际上手里是一个已知有洞的版本。政策能调的，就是这段空窗能有多长。

以前调这段的办法是「催」：定个期限，到期再说。现在办法变成「定死」：到期就公开，不管对面修没修。

两种办法的差别在谁承担后果。前者，后果主要由用户承担，因为信息还被捂着。后者，后果有一部分回到了厂商身上，因为细节一公开，全世界的安全团队都会盯着看什么时候发补丁。

对普通用户来说，这条新闻的实际含义很朴素：以后打系统更新的提示，可能来得更勤，也更急。

也可以反过来说：如果一个补丁一直不来，那你至少会更早知道「为什么该来」。

我不打算评价这个改动好不好。它天然有代价——厂商的修复窗口被压缩，赶工出来的补丁也可能带来新问题。

但有一点很清楚。当「什么时候说」被写进时间表，而不是留在谈判桌上，安全这件事就从人情变成了流程。
