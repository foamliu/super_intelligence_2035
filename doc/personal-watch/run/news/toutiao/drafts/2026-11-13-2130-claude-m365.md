# 一个连接器，拖垮两家公司

微软的办公云出了故障，先倒下的是微软自己。隔了一天，另一家公司的人工智能服务也跟着趴了。

十一月十三日，这家名叫 Anthropic 的公司在自家状态页上连发多条通报，把自家部分服务的故障算在了微软办公云的连接上。

通报写得很直白：邮件、日历、搜索这些请求，大多数处理不了，新建连接也可能失败。

后来又把原因往上追了一层，说是上游服务商的问题，正在和对方一起处理。

有意思的地方在这里：一家做模型的，命门握在另一家的办公软件上。

连接器本来是加分的功能。让助手读你的邮件、翻你的日历、查你的文件，它才有用。

可这也意味着，对方一抖，你就跟着抖。

同一天，它自家产品的登录也出了状况，官方公告说正在调查。

两件事是不是一回事，报道里没有下定论。但时间挨得这么近，很难不让人往一处想。

我个人的判断是：这不是哪家的技术不行，是几张网叠在一起，接口太多，谁也没法单独兜住。

你把它当水管看就明白了。上游修管子，下游就得停水，停多久不由你说了算。

对用户来说，最难受的不是出错，是出错的时候你不知道找谁。客服找这家，这家说找那家。

要说建议，倒也不复杂：做工具的，该把「依赖哪家」写在明面上；用工具的，也该有个断网也能干活的备手。

技术越往上叠，这种互相牵连只会更多。

你碰上过这种「一家故障、好几家一起瘫」的事吗？
