  摘要：IT之家 11-05 报道，**OpenAI 于当地时间 11 月 4 日发布安全研究报告**，称用新一代网络安全模型搭了「漏洞发现 → 动态验证 → 可利用性评估 → 补丁生成 → 人工审核」五阶段自动化系统。测试 **2026 年 10 月中旬**进行，模型**尚未正式公布**。规模：先筛出 **5,034 个审计目标、约 280 万行代码（约 Linux 内核总量的 7%）**；分析智能体 **12 小时内生成 2,308 个去重候选漏洞**，该阶段 API 成本 **31.65 万美元**；**30 小时**隔离 VM 动态验证中 **1,724 个复现（约 74.7%）**，未复现者中**仅 3.1% 属模型分析错误**。结果：**291 个信息泄露 PoC + 1,169 个本地提权利用程序**，变体去重后**948 个**作为统计口径；总 API 消耗 **121.34 万美元**，**平均每个提权利用 1,279 美元**（其中利用开发阶段 77.59 万美元最贵）。对照：**2026 年 7 月用 GPT-5.6 Sol 做同类测试只拿到 166 个提权漏洞、成本 51.37 万美元** ⇒ 三个月（内核已加固）后**新发现数量超此前 5 倍**；抽查 166 个利用样本**至少含 10 种此前未见的技术**，已交第三方专家复核。落地：10 天内 **61 个**漏洞在上游修复、**43 个**获暂存补丁、**299 个**在公开讨论；另在谷歌 kernelCTF 加固环境跑 **112 小时、约 3.29 万美元**，得 **25 个信息泄露 PoC + 21 个提权利用**（若全过审理论上可拿约 150 万美元奖励）。OpenAI 强调这是 **Patch the Planet / Daybreak** 计划的一部分，出于安全未公开新技术细节。
  原文 vs 判断：2,308 / 1,724 / 74.7% / 3.1% / 948 / 291 / 1,169 / 121.34 万美元 / 1,279 美元 / 166 / 51.37 万美元 / 61 / 43 / 299 / 112 小时 / 21 个，**全部为 OpenAI 自报口径经 IT之家转述**；⚠️ **原报告与第三方复核结论本轮未直取**。—— 我们的观察：这条真正扎眼的不是「948 个漏洞」，而是**成本曲线的形状**：51.37 万 → 121.34 万（约 2.4 倍），产出 166 → 948（约 5.7 倍）。也就是说，**单位漏洞的发现成本在降**，而且降到 1,279 美元这个量级 —— 低于很多工程师一周的工资。攻防的平衡向来靠「攻击者成本 > 收益」维持，这一项一旦被算力压穿，剩下的防线就只有**补丁速度**。OpenAI 自己也把「维护者要加快修复」写进了结论，这其实是把压力转给了开源社区。
