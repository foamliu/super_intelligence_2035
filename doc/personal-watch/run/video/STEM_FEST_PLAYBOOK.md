## 1. 分镜脚本表格（唯一权威）

**范式**：全片一份 `storyboard.md`，每幕一节，一张**逐镜表**；本仓对应 = 每章一份 `SCENES/<NN>_<标题>.md` 的 `## 逐镜表`（7 列固定，见短剧 README §7.2）。

**列（stem_fest 版，短剧版同义）**：`镜号 | 时长 | 画面 | 运镜 | 景别 | 台词/音效 | 参考图提示`。

**四条硬口径**：

| # | 口径 | 细节 |
|:-:|:--|:--|
| 1 | **时长** | 整数秒，**2–10 s**。H3 侧帧数量化 **`17k+5`**（节点公式：`max(5,round(秒×24)) + (5 - (…%17))%17`）：<br>2s→2.33 / 3s→3.04 / 4s→4.46 / 5s→5.17 / **6s→6.58** / 7s→7.29 / 8s→8.00 / 9s→9.42 / 10s→10.13（秒）。<br>⚠️ 旧文「5s→136 帧 / 6s→136 / 7s→170」**是错的**，实测 124/158/175。**写 6s 比写 5s 实际多 1.41s 时长、也贵 1.41s**。 |
| 2 | **时长怎么算** | `need = 净台词字数 ÷ 角色语速 + 0.8s(起势/收势/气口) + 动作余量 + 换人说话气口×0.5s + 停顿 0.4s`；<br>**无台词镜**：`need = 2.5s + 0.4s×动作数`（上限 6s）；纯反应镜 2–3s；定格/字幕/转场 4–6s（人工锁定）。<br>`说话人：` 前缀不算字数；`音效：`/`音乐：`/`歌词：` 不占说话时间。 |
| 3 | **景别必须写「取景范围」** | 只写「全景」「中景」这种**名词**，H3 会理解成「贴近主体拍清楚」⇒ 配上「手部/衣物」细节描述后**把人物放大到脸出画**（实测大量镜只有躯干、没有脸）。修法：写「全景＝人物全身 + 环境」这类**范围定义**。 |
| 4 | **站位锚点三要素** | ① 左→右顺序 ② 相对关系（前/后/旁边/**对面**、谁站中间、从哪侧入画）③ 姿态/朝向（蹲/站/坐、面向哪、低头还是正视）。<br>只写①就是 V2 里 **33 处「站位错乱/人物不像」的总根源**。高频事故：<br>· 「对面」被渲染成「旁边」⇒ 座位场景必写「面对面坐 ＋ 中间隔桌板」<br>· 「多出一只没有来处的手」⇒ 凡手部动作必写「**谁的**双手」<br>· 「多了/少了个人」⇒ 写明「画面里一共几个人」并**逐个点名，不留「等」字** |

**参考图提示列（按「在场人数」给图）**：

| 画面里该有 | 参考图 |
|:--|:--|
| 4 人 | **四人合影**（拼版） |
| 2 人 | **二人合影**（按组合拼版） |
| 1 人特写但场景里还有别人 | **单人定妆照 + 四人合影**（双图位） |
| 确实只有 1 人 | 单人定妆照 + 场景参考 |
| 纯场景（无人） | 场景参考，**走 T2V** |

> ⚠️ **只给说话人一张脸 ⇒ 其余人会消失、背景空荡**。
> ⚠️ **场景参考图不要用空教室/空场景** —— 模型会优先渲染空背景，人物像贴上去的。

**改表纪律**：改 `duration` / 台词 / 参考图 ⇒ **必须重跑时长审计 + 表结构一致性闸门**；`duration` 与表内时长列必须一致，否则报「漂移」🔴。

## 2. 资产管理

| 主题 | 结论 |
|:--|:--|
| **定妆照 = 外形的唯一权威** | prompt **只能写客观可见的稳定特征**（性别/发型发色/服装/配饰）。<br>🚫 **严禁**写体型/脸型/胖瘦/年龄感（实测：写「圆脸、偏胖」→ 生成结果**真的胖一圈、脸变圆**，而定妆照实为瓜子脸）。<br>🚫 写年龄数字会画苍老 ⇒ 用「精神矍铄、面容紧致、不显老」。<br>🚫 分镜里的性格/印象描述（「胖胖的」「说话慢」）**不可**当外形依据。 |
| **顺序：定妆照 > 分镜表** | 表里写的服装/外观与定妆照冲突时，**以定妆照为准**。 |
| **命名全 ASCII（小写+下划线）** | 角色 `<slug>_hero_v01.png`（**每人一张**，该角色所有镜头都引用它）；场景/道具 `<slug>_<view>_v<NN>.png`，`view = wide / medium / detail / hero`。<br>⚠️ **中文/空格文件名**会被 ComfyUI 上传时改写成随机 `mcp_ref_<hex>.png`，从此无法辨认。 |
| ★★ **合影 = 程序拼版，绝不用图生图** | `image_edit_longcat` 转过的合影**有些身份失真** ⇒ 正解＝① 从各自定妆照**裁出人物** → ② **并排拼进一张宽图**，拼版图**本身就是成品**、直接入库 `ASSETS/CHARACTERS/_group/<slug>_hero_v01.png`。<br>**站位由拼版顺序物理决定**；prompt 里的站位段必须与之**一致**（不一致时 H3 会二选一）。<br>另一教训：用户提供的**真实双人照**当参考图时，可能与定妆照不符（没戴眼镜等）⇒ 优先用「定妆照拼版」。 |
| **seed 固定可复现** | 同角色/同场景固定 seed；候选图用 `seed 基线 + 偏移`；**记录 seed 到台账**。 |
| **素材台账唯一出处** | `ASSETS/README.md`（某角色定妆照→路径 / 造型基串 / seed / 出现镜号；场景/道具规格与参数）。本仓对应 `ASSETS/CHARACTERS/<角色>/定妆规格.md`。 |
| **上传不覆盖同名** | ComfyUI `input/` 里同名文件会存成 `名字 (1).png`。**换图前先删** `E:\code\ComfyUI\input\<名>.png` 再上传，否则「改了没用」。 |
| **入库策略** | 图片/音频/视频**不入 git**（`.gitignore` 挡）；`.md` / `.gitkeep` / `manifest.json` / 脚本入库 ⇒ **「结构随仓库走、大文件本地存」**。`OUTPUT/` 只入库常驻脚本与文档。 |
| **素材不要囤临时脚本** | 一次性脚本量完即删；`OUTPUT/` 只留常驻工具（如分区域色彩量化脚本，因为「整图均值」会被大面积高亮区拉走）。 |

## 3. MiniMax H3 出视频（照抄参数）

| 参数 | **必须用** | 说明 |
|:--|:--|:--|
| `steps` | **4 / 10 / 20**（按镜型） | 4＝静态·单人·对话镜；**10＝角色镜默认**；20＝**环境剧变镜**（航拍跟拍、画面持续剧变）。<br>耗时（1056×608）：4 步 ≈ 3.4 min · 10 步 ≈ 9.5 min · 20 步 ≈ 18–26 min（近线性）。<br>★ 实证：镜「纸飞机掠过校园」`4 步❌ → 10 步❌ → 20 步✅`。<br>⚠️ **但「提步数 ≠ 提画质」**：曾把 65 镜从 10 提到 20 全量重跑，用户判定**画质无提升**、机时 +36%，**全部回退** ⇒ H3 在 10 步已基本收敛，**别默认堆 20**。 |
| `megapixels` | **0.6** | → 1056×608；**0.92(720p) 必 OOM**。R2V 双参考图更吃显存，**建议 0.4**。要 1080p ⇒ 生成后用 `video_upscale_seedvr2` 超分（**帧数与原音轨原样保留**，可直接替换）。 |
| `aspect_ratio` | `"16:9 (Widescreen)"` | |
| `duration` | 照抄表内时长 | 受 `17k+5` 量化（见 §1），实际播放比标称多 0.04–0.58 s。 |
| `ref_image_1` | 角色 / **对话双方合影** → `<Picture 1>` | 竖版头肩特写可直接用，**不必**裁 16:9。 |
| `ref_image_2` | 该镜**场景图** → `<Picture 2>` | 无角色镜走 `t2v`。 |
| `prompt` | `CUT 1:` + **景别** + 动作 + `Audio:`（**只放 L1 台词原文**） | 一镜一个主景别；环境声**不写**在这（见 §5）。 |

- **路由**：有角色 → `video_minimax_h3_i2v`（首帧图）；**多角色锁定** → `video_minimax_h3_r2v`（≤2 张参考图）；无参考图 → `t2v`；屏幕/UI 动态 → 降级备选（LTX）。
- **分辨率反推**（`ResolutionSelector`）：`√(megapixels×1024²/(16×9))` 取 32 的整数倍 ⇒ `0.6→1056×608`、`0.4→832×480`、`0.3→736×416`、`0.2→608×320`。
- **前置**：分镜帧（`image_edit_longcat`）要求**输出画面脸高 ≥ 250 px**（小人脸进 H3 会漂）。
- ★ **验证「这镜到底几步」—— 读 mp4 内嵌元数据**（永远可复算，别用画面统计量猜）：
  ```powershell
  ffprobe -v quiet -print_format json -show_entries format_tags <file.mp4>
  # → format_tags.prompt 是整张工作流 JSON；BasicScheduler.inputs.steps = 真实采样步数
  ```
  ⛔ 反例：曾用「帧间差分闪烁度」推断步数，**完全错误**（它标定画面动势，不是降噪量），8 个「疑似低步数」全是误判。

## 4. prompt 三条禁令

### 4.1 ★★★ 禁写「元信息 / 对模型说的话」（会被渲染成画面字幕）

H3 **分不清「指令」与「台词」**：prompt 里任何「对模型说的话」都会被当词句输出。实锤：

| 案例 | 写进 prompt 的内容 | 结果 |
|:--|:--|:--|
| 镜 91 | 舞台指示「像在消化一件很难立刻接受的事」 | 画面底部**真的出现这行中文字幕** |
| 镜 5 / 110 | 否定式 `NO_SPEECH` 常量「本镜不要生成任何…旁白」 | 底部字幕「本镜不要生成任何可□旁白」（`□` 逐字读不准 ⇒ 也印证「读图判不准逐字」） |
| 镜 19 | 「全镜高适」 | 疑似同类幻觉 |

| 写法 | 判定 |
|---|:--:|
| ✅ 摄影机拍得到的：动作、表情、景别、光线、环境、人数、衣着 | 安全 |
| ❌ 比喻式内心状态：像在… / 仿佛… / 像是… / 显得… | **会被画成字幕** |
| ❌ 镜头用意：暗示… / 表达… / 说明… / 观众要读到… | **会被画成字幕** |
| ❌ 镜头编号指代：本镜 / 该镜 / 这一镜 | **会被画成字幕** |

修法：**改写成可见的物理表现**。
```
✗ 像在消化一件很难立刻接受的事
✓ 面无表情地沉默了几秒，喉结动了一下
```
⚠️ **提 steps 无效** —— 这是**语义层**问题，不是采样不足（镜 5 用 20 步重跑，字幕依旧）。
⚠️ **参考图里的文字**（人名标签、水印）也会被画进画面（定妆照带「新华网 WWW.NEWS.CN」水印 ⇒ 相关镜要抽帧确认未泄漏）。

### 4.2 ★★★ 无台词镜禁写否定式 ⇒ 改「正向音景」

⛔ 旧写法（**本身是污染源**，已作废）：
```
【本镜不要生成任何可辨认的语音或对白。只允许环境音与物件音…不要生成任何词句。】
```
✅ 新写法：**只说有什么声音，音景本身不含可读词句**：
```
Audio: 安静的室内环境底噪；轻微的衣料摩擦声与呼吸声；远处传来模糊的人群杂音，听不清任何词句。
```
实测：写否定式后 H3 幻觉出人声（镜 4 出「啊」、镜 5 出整句胡话）；改正向音景后，镜 5/110 字幕**彻底消失**（A/B 对照已验证）。
模式（各幕定制、照抄脚本常量）：室内＝安静底噪+衣料摩擦+远处模糊人声；野外＝开阔地底噪+风+远处零星人声；田野＝底噪+稻叶虫鸣；车厢＝行进低频嗡鸣+模糊人声。

### 4.3 ★★★ 台词长度必须匹配镜头时长

H3 是「给了 `duration` 就必须生成那么多帧」的生成器 —— **台词说完后的空档它不留白**，而用**口型空转/自己补一句**填满。

- 实证（镜 7 对照实验）：台词 6 字 / 3s（need 2.3s、空档 0.74s）⇒ 历史 **8 个版本全有前导/尾随乱音**，换 seed / 改 prompt / 试 2s/3s **全部无效**；台词加长到 **14 字 / 4s**（need 4.3s）⇒ `qwen3_asr` 回读**逐字一致、零多余语音**。
- 反向也成立：`need − 时长 > 0.5s`（台词偏长）⇒ H3 把台词**挤成乱音**。
- **处置优先序**：① 先跑时长审计核 `need` → ② **调「台词长度」或「镜头时长」**使差值落在 `need + 0.2 ~ 0.8s`（台词太短 ⇒ **优先加长台词**，剧作层解决最有效）→ ③ 才轮到正向音景 / 换 seed → ④ **最后**才后期掐音。
- script 侧：无台词镜必须挂 `NO_SPEECH`（正向音景）；有台词镜挂 `ONLY_THIS_LINE`（禁补话）。

## 5. 音频六层分工（**H3 只出 L1 台词**）

| 层 | 内容 | 谁做 |
|:--:|:--|:--|
| **L1 台词** | 角色**明确台词**（有原文、要对口型） | ✅ **H3**（**只此一项**） |
| **L2 环境声** | 风声/蝉鸣/稻浪/铁轨/键盘/炮响/纸张翻动 | ❌ 不用 H3 → `stable_audio_3_sfx`（点状/短底噪，⭐首选）或 `woosh_sfx`；长氛围 `ace_step_t2audio` |
| **L2b 点状 foley** | 一声纸飞机轻响/一次按键/一声心跳/蝉鸣骤停 | ❌ 不用 H3 → `stable_audio_3_sfx` ⭐（1–10 s 最合适） |
| **L3 群杂人声** | 学生交头接耳（walla、听不清） | ❌ 不用 H3 → `ace_step_t2audio` |
| **L3b 语音播报** | 站名播报等**有词句**的人声 | ❌ 不用 H3 → `qwen3_tts`（音效模型只会出糊状人声，念不出词） |
| **L4 视频配音效** | 给**已拍好的画面**配 foley | `woosh_v2a`（≤8 s，按画面内容，文字只是弱提示） |
| **跨镜 BGM** | 整片配乐 | 现成音源 / `ace_step_t2audio`，后期整体铺（`-c:v copy` 只换音轨） |

**为什么**（实测）：H3 把 `Audio:` 里的一切都当「有人要说话」处理，且**听不进「多人说话」语义** ⇒ 只产出单声道、无空间感、听不清的糊状人声（「讨论声渐起」已踩坑）；**环境声更直接：H3 前后段 ≈ −50 dB（生不出来）**。

**脚本纪律**：表内 `音效：` 列**禁写「讨论声 / 人声 / 说话声」**这类会被 H3 当台词的词 ⇒ 改用显式标记 **`（后期）`** 后缀，生产脚本的 `strip_late_audio()` 在拼 prompt 时**自动剔除该整句**，只把 L1 台词交给 H3。

**电平纪律（违反必削波）**：成片自带音轨 `I≈−12.4 LUFS / 真峰 +0.1 dBFS`，商业母带 `I≈−11.1 LUFS / 真峰 +1.0 dBFS` ⇒ 直接相加必爆。三重保险：① BGM 降 `--level`（≈−14 dB）；② `sidechaincompress` 用**成片音轨自己**当侧链做闪避（有人说话时 BGM 让路 12–24 dB）；③ 总线 `alimiter` 守 −1 dBFS 真峰。母带目标 **≈ −23 LUFS**（YouTube/Vimeo 标准）。

⚠️ **判收口径**：`sound_caption` **不可靠**（把已采纳的稻田蝉鸣说成 *vacuum cleaner*）⇒ 改用**客观画像**（频段/静音/crest/4Hz 调制）+ 同族对比。

## 6. 验收判据（数值化）

> 铁律：**ComfyUI 报 `success` ≠ 产出成功**。

```powershell
# 规格 + 音画时长差（PS 里必须用 cmd /c "… 2>&1" 包一层，否则 ffmpeg 日志走 stderr 抛 NativeCommandError）
ffprobe -v error -show_entries stream=codec_type,codec_name,width,height,r_frame_rate,duration,nb_frames -of default=nw=1 <file>
cmd /c "ffmpeg -nostats -v info -i <file> -vf blackdetect=d=0.2:pix_th=0.10 -an -f null - 2>&1"   # 黑帧
cmd /c "ffmpeg -nostats -v info -i <file> -vf freezedetect=n=-60dB:d=0.5    -an -f null - 2>&1"   # 静帧
cmd /c "ffmpeg -nostats -v info -i <file> -af silencedetect=n=-50dB:d=0.4   -vn -f null - 2>&1"   # 静音
cmd /c "ffmpeg -nostats -v info -i <file> -vf scdet=threshold=10            -an -f null - 2>&1"   # 场景硬切
cmd /c "ffmpeg -nostats -v info -i <file> -filter_complex ebur128=peak=true      -f null - 2>&1"  # 响度
```

参考实测样例（单镜 1056×608@24fps / 73 帧）：视频 3.0417 s、音频 3.0420 s（**音画差 0.3 ms**）；无黑帧/静帧/静音/硬切；`I=−10.3 LUFS / LRA=20.0 LU / 真峰 −2.1 dBFS`（响度偏高、动态过大 ⇒ 后期要压）。

| 要判的事 | 用什么 |
|:--|:--|
| 画面「有没有某物 + 占多大」 | `image_segmentation_sam3`（**可直接喂 .mp4**，抽帧逐帧检测；返回 `_bbox`/`_overlay`/`_mask` + 每帧 `mask_coverage`，**0＝没检出**）。⚠️ 每次提交换模型（1.6 GB）⇒ 跑批期间只用单图，别拿它扫长视频 |
| 台词念对/漏念/多念 | `qwen3_asr`（**可直接喂 .mp4**，内部抽 16 kHz 单声道）→ 与逐镜表原文**逐字**比对，并确认**没有多余语音** |
| 人脸一致性 | `face_feature`（ArcFace）。⚠️ **绝对余弦阈值在本类素材上失真**（跨域比对不可直接用）⇒ 用**相对排名 + 明显差距**，并确认 `face_px_h ≥ 250`，否则判「不可判」 |
| 看画面（定性） | **基模自带视觉**：`read_files` 直接读图 —— **默认第一步就是读图**，别先写像素脚本/找外部 VLM（stem_fest 最贵的一次时间浪费）。⚠️ 额度 ≈**7 张/会话**，超出**静默丢弃**（不报错、agent 无法自救）⇒ 「大而少」：拼**联系表**（1 张 ≈ 6 镜 × 4 帧）、大图先缩 ≤1024 px、一次问清。❌ 读图读不准：低对比度小字/乱码/逐字精确/任何数值（相似度/覆盖率/响度） |
| 崩坏/黑帧/过曝 | **必须读全帧** —— 别把「按缺陷裁剪的条带」当全帧读（曾因此一口气误报 5 个镜） |

★ **出片即停规则**：渲染完成 ⇒ **立刻停下**，把新片路径（文件名+规格）报给用户，**然后等**。默认不跑自查链（抽帧读图 / 人脸比对 / 拼对照图 / ffprobe 复核 / 逐帧挑毛病）、不写长台账（过审后再写，且**只写结论**）。用户说「不好」才动，且只改他指出的地方。

## 7. 拼接的音画漂移（成片级铁律）

**症状**：单镜产物**完全同步**，但拼成片后第 2 幕人声滞后 **1.34 s**、末镜 **2.63 s** —— 问题在**拼接**，不在生成。

**根因（实测）**：**每个 H3 片段音轨解码长度都比画面长 0~32 ms**（音频 AAC 1024 采样/颗，32 kHz 下正好 32 ms/颗，尾部向上取整）⇒ 126 段合计 **+2631 ms**，恰好等于末镜漂移量（因果闭环）。按生成批次分组**无一例外**⇒ 是 H3 封装的**固有属性**。

**五种接法实测（全部证伪，唯有钉长可行）**：

| 拼接方式 | 逐镜漂移 | 画面 | 判定 |
|:--|:--|:--|:--:|
| 视频/音频分两条 `concat`（旧脚本） | 0→+20→…→+90 ms | 715 帧 | ❌ 累积 2.63 s |
| 同一条 `concat=v=1:a=1`（音频不钉长） | 同样累积 | 715 帧 | ❌ |
| `-f concat` demuxer 纯接 + 重编码 | +30→…→+130 ms | 715 帧 | ❌ |
| `-c copy -shortest` 先削尾再纯接 | +30→…→+460 ms | **706 帧（丢 9 帧）** | ❌ 更糟，砍的是**视频** |
| **每段音频 `apad`+`atrim` 钉到本镜时长** | **全 0 ms** | 715 帧 | ✅ |

**修法（已落地）**：
```
AUDIO_NORM = aresample=32000,aformat=channel_layouts=stereo,apad,atrim=0:<本镜时长>,asetpts=N/SR/TB
每路音频过它 → 再用同一条 concat=n=N:v=1:a=1[v][a]
```

**铁律**：
1. **`帧数 ÷ 24` 是画面的权威时间轴**；音频段必须被**钉到它**（不能让音频按自己的采样数推进）。
2. 没有「只接不动」的正确解 —— 素材本身不一致，必须有人把音频对齐到画面。
3. 钉长截掉的**只是尾部补零**（尾部 RMS −77~−240 dB vs 人声 −11~−34 dB）⇒ 人声/环境声一个采样没动。
4. **拼接后必过闸门**：`|音轨长度 − 画面长度| < 0.15 s` ⇒ 旧成片 **+2.631 s** 会被当场拦下。
5. ⚠️ **这个闸门只是必要条件**：修好的新母版音轨也是 525.626 s，与旧片同长 —— 「**被钉到**」与「**被截断到**」会得到同一长度读数 ⇒ **必须逐镜测「内容偏移」**，不能只看时长差。
6. 章节表 / 音频钉长 / `drawtext` 段长**必须同源**（都用同一个 `seg_dur()`），否则又会互相错开。
7. **验证顺序**：**先验母版同步，再叠 BGM/音效**；🚫 **不要在已叠音效的成片上跑同步检测**（音效盖住原音包络 ⇒ 检测器失锁、报**假峰**）。叠层的正确验收是「层」检验（混音后 − 母版应只在铺位窗口抬升）。

## 8. 跑批纪律

| # | 纪律 |
|:-:|:--|
| 1 | ★ **启批前先 `--dry`** 看清任务数/时长/参考图是否都在。曾发生：脚本实参是 8 个镜却被当成 2 个，且**进程后台存活**，LongCat 首帧任务与 H3 视频任务在队列里**交替执行**、每个还要重载 12 GB 模型 ⇒ 纯浪费。 |
| 2 | ★ **跑完确认「进程已退出 + 队列清零」**：`Get-CimInstance Win32_Process -Filter "Name='py.exe'"` + 查 `/queue`（`queue_running` / `queue_pending`）与 `/history`。 |
| 3 | **长任务必须后台**：`Start-Process py -ArgumentList … -RedirectStandardOutput <log> -NoNewWindow`（前台 30s 必超时）。单条 3–26 min，整幕数小时。 |
| 4 | **清队列姿势**：删**排队中** `POST /queue {"delete":[prompt_id]}`；中断**正在执行**先 `POST /interrupt`（空 body）**再删**（**只发 delete 删不掉 running 那个**）；清历史 `POST /history {"clear":true,…}`。 |
| 5 | **跑批期间别调本地**视觉模型（ollama 等常驻 5.5 GB 显存 ⇒ 把 H3 挤到 76 MiB、功耗掉到 30 W）；用完 `Stop-Process -Force`（`ollama stop` 会卡）。 |
| 6 | **每幕一个独立脚本**（互不引用，避免 NameError），产物落对应 `OUTPUT/<scene>/video/`，报告落 `OUTPUT/_act<N>_<scene>_report.txt`。 |
| 7 | **脚本幂等可续跑**（已完成的重跑会跳过；`--force` 才重出）；`--dry` / 单镜抽查（先短镜验证管线再放全量）。 |
| 8 | 不同 batch 的输出前缀要**可区分**；改完 prompt 先过两道闸门（hazard 扫描 + 结构层一致性），**非 0 退出即禁止开跑**。 |
