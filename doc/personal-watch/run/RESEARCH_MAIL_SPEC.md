## 2. 邮件口径（学术请教信）

- **语言（2026-11-14 用户令收紧）**：默认英文；**华人作者一律中文**——**在海外机构任职也算华人**。
  - 判据（**任一命中即按华人处理，必须中文**）：① 姓名是拼音且可还原为常见中文姓名（`Saining Xie` = 谢赛宁、`Kaiming He` = 何恺明）；② 主页 / GitHub / Scholar / X 有中文名或中文自述；③ 本科或硕士毕业于中文机构，或长期在中文机构任职；④ 机构域名 `.cn` / `.edu.cn`。
  - 🚫 **不得以「人在美国/欧洲」「论文是英文」「邮箱是 gmail」为由判成英文**。**2026-11-14 事故**：写给谢赛宁（NYU）用了英文，用户指出「是华人，为什么不用对方母语交流」。
  - 规模警戒：截至 11-14，作者信 40 封中只有 **7 封中文 / 27 封标注英文**，其中至少 3 封对象是华人（Haotian Liu/LLaVA、`yibolin@pku.edu.cn`/PKU、Beidi Chen/CMU）⇒ **应中文而未中文 = 失礼**。
  - 真判不出来（判据全落空）⇒ 英文；**但只要有一条命中，就必须中文**。
  - 篇幅：英文 **≤200 词** / 中文 **≤300 字**。
- **四段式**：
  1. **一句自我介绍（只写身份，不铺项目清单）**：英文 `I am Yang Liu, a researcher working on LLM agents; you can find my work at https://foamliu.github.io/.`；中文 `我是刘杨，做 LLM agent 方向的研究，主页 https://foamliu.github.io/。`。项目名（BaiZe / ZhuLong）如需出现，放第 2 段一句带过，**🚫 不塞进自我介绍**；🚫 不建议在信里报雇主（§8）。
  2. **为什么读你这篇**（点出与我们在研问题的关系）。
  3. **2–3 个具体问题**（**技术细节**，须**能回填研发决策**；逐条写明「答复会改进哪一步」）。
  4. 致谢 + **落款固定两行，其后不得再有任何一行**：
     ```
     Best regards,
     Yang Liu
     ```
     中文信落款：`祝好，` + `Yang Liu`。🚫 `Super Intelligence 2035 / BaiZe-ISEDA2027 / ZhuLong-DAC2027` 一句**禁止出现在落款里**（2026-11-14 用户令：落款要简洁两行）。
- **问题质量（硬）**：🚫 不问摘要里已有的内容；🚫 不问泛泛的「能否分享代码」（除非确需）；须**具体到方法 / 超参 / 失败模式 / 复现细节**。
- **草稿先落盘（入 git，供监督）**：`doc/personal-watch/run/research/mail/drafts/<arXiv_ID>.md`。

## 3. 频率上限（硬）

- **每轮（每个时窗）≤ 3 封**。时窗定义以 `watch_research_loop.sh` 的 `SCHEDULE_HOURS` 为准：**0/3/6/9/12/15/18/21 共 8 个时窗/天**（旧文「06:00 / 18:00 两个时窗」已作废）。
- **每日硬上限 ≤ 12 封**（8 时窗 × ≤3 封 的实测收敛值）。当日满 12 封后，剩余时窗只做选题与草稿，**不发**。
- **同一作者 / 同一论文 ≤ 1 封**；**同一机构 ≤ 2 封/天**。
- 🚫 **不群发 / 不用模板群拷贝**（**一信一作者**，正文须因论文而异）。**同一轮内两封信不得共用开头句与问题句式；每封至少含一个只对该论文成立的技术细节（符号 / 超参 / 失败模式 / 表格编号）。**
- 🚫 **不催**（未回信不发第二封，除非对方回复）。

## 5. 目标论文（从哪挑）

- 来源：本线近期 `research/daily/*.html`（每天 5 篇）+ `TOP_K.md/jsonl` + `papers.jsonl`。
- **优先「与 BaiZe / ZhuLong 强相关」**：vision encoder · 预训练配方 · 数据配比与清洗 · 长上下文 · Mamba/SSM/hybrid · code agent / harness · EDA 相关。
- **选题判据**：作者可联系（有邮箱/主页）· 论文有**可追问的细节缺口** · 答复**对研发有决策价值**。

## 6. 台账（硬性）

- `doc/personal-watch/run/research/mail/发送记录.md`（**只追加**）：
  `日期 | 收件人 | 机构 | arXiv ID | 主题 | 问题摘要 | 发送状态 | 回信状态`。
- **回信状态只允许三值**：`已回复` / `无应答(>14d)` / `未到期`（发出不足 14 天）。每轮回填一次到期项，**不得留空**。
- **备注首项必须写语言与判据**：`语言=中文(判据:拼音名/中文主页/.cn)` 或 `语言=英文(判据:无华人与中文机构信号)`——便于事后审计（2026-11-14 事故：40 封仅 7 封中文）。
- **每轮心跳必报累计回信率** `回复数 / 发出数`（2026-11-14 基线：**0 / 37**，须逐轮更新）。
- **没写台账 = 没发**。

## 7. 回信处理

- 技术信息摘入 `doc/personal-watch/run/research/mail/replies/<arXiv_ID>.md`；**只做信息提取**。
- 目录与字段约定见 `research/mail/replies/README.md`；每份摘录须给「可执行结论 + 归属线」，供日报与各线 MEMORY 引用。
- 回信含敏感信息、或对方索要内部数据 ⇒ **停手报运维**（§8）。

---

## 8. 🚫 红线（硬）

- 不冒充他人身份 · 不群发 · **不发大附件**（≤5MB）。
- 🚫 **不承诺**合作 / 署名 / 资助 / 引用 / 数据共享。
- 🚫 **不透露用户未公开的内部信息**（训练细节 / 数据 / 未发表结果）—— **敏感问题先报运维**。
- 🚫 不回复与研发无关的邮件。
- 遇对方索要敏感信息或敏感提问 ⇒ **停手报运维**。
- 🚫 不做付费 / 挂名交易。
