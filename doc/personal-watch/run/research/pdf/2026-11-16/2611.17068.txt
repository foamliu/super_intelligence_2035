Introduction

Agents powered by large language models, such
as personal assistants and conversational companions (Wang et al., 2024; Xi et al., 2023), increasingly depend on persistent memory of user information to maintain continuity across conversations. Agent memory systems (Packer et al., 2023;
Chhikara et al., 2025; Xu et al., 2025; Rasmussen
et al., 2025; Liu et al., 2026a) address this need
by transforming interaction history into memory
units, organizing them in a persistent store, and

Search starts from minimal seeds, such as a program that stores no memory. The framework tracks

We run MAPE on LoCoMo (Maharana et al.,
2024) and LongMemEval (Wu et al., 2025) under
both objectives, yielding four experimental settings.
For each, we analyze the evolutionary trajectory
and the resulting memory system. All selected
systems outperform the evaluated human-designed
baselines on their respective benchmarks. On LoCoMo, we observe an absolute accuracy gain of
up to 12% at 35% of the serving cost. Further
evaluations include cross-backbone validation using GPT-4.1 mini and Qwen3-30B-A3B-Instruct2507 (Yang et al., 2025), as well as bidirectional
cross-benchmark transfer between LoCoMo and
LongMemEval, all without additional evolution.
These results support the transferability of the discovered memory designs across serving backbones
and benchmarks.
Across the discovered systems, we identify two
recurring design patterns: retaining raw conversations as retrievable evidence and processing retrieved evidence through intent-specific scaffolds
before answering. A case study and component
ablations examine the contribution of each pattern in a representative system. Retaining raw
evidence helps preserve details omitted from extracted memories, while error attribution across
human-designed systems identifies incomplete retrieved information as a major bottleneck. The composition module routes queries to intent-specific
scaffolds that combine targeted extraction, deterministic computation, and deliberation to support
the answering model. Transplantation experiments
test this composition strategy across five humandesigned memory systems, improving accuracy in
every case and demonstrating its utility beyond the
evolved program.
Comparing the two objective settings reveals differences in both search behavior and computation
allocation. In the observed runs, accuracy-only

search progressively adds operations, accepting
substantial cost increases for marginal accuracy
gains. The illustrated joint accuracy–cost trajectory maintains lower serving costs and explores
more branched candidate lineages, retaining inexpensive alternatives as starting points for further
evolution. The resulting designs differ in where
they spend computation. The selected accuracyonly programs invest in LLM-based memory construction, whereas the selected accuracy–cost programs reduce reliance on it in favor of selective
computation at query time, using 90% and 40%
fewer serving calls on LongMemEval and LoCoMo
while retaining strong evaluation-set accuracy.
Our contributions are threefold:
• We introduce MAPE, a framework for discovering and studying agent memory designs
through whole-program evolution from minimal seeds under a standardized lifecycle interface.
• We identify raw-conversation retention and
query-dependent composition as recurring
design patterns, validate their contributions
through ablations, and demonstrate the transferability of composition by transplanting it
into five human-designed systems.
• We show how optimization objectives shape
evolutionary trajectories and computation allocation, with joint accuracy–cost search shifting computation from LLM-based memory
construction to selective processing at query
time.

The candidate first undergoes a small sanity evaluation to identify execution errors. The proposer
can repair these errors within a fixed budget, and
candidates that pass are evaluated on the full fixed
search set to obtain accuracy and lifecycle serving
cost. A separate diagnosis agent then examines
the implementation, design hypothesis, evaluation
results, and available execution traces to assess the
observed outcome and identify potential causes of
failure. The diagnosis informs subsequent proposals without modifying the evaluated candidate.
After evaluation and diagnosis, the candidate implementation, parent references, hypothesis, results,
traces, and diagnosis are added to the archive. All
evaluated candidates are retained, including dominated designs, allowing later proposals to revisit
earlier implementations rather than extend only the
current best program. Search continues until the
proposal budget is exhausted. The evaluation set
remains unavailable throughout evolution and is
used only afterward in the program-selection procedure described below. Figure 1 illustrates the
loop, and Appendix B.1 provides the initialization,
search budgets, and execution settings.

With both metrics recorded, we run the evolutionary search in two modes: MAPE-A optimizes
accuracy alone, whereas MAPE-P treats accuracy
and lifecycle serving cost as separate objectives.
Its Pareto frontier contains programs for which no
other evaluated candidate achieves at least equal
accuracy and no greater cost, with a strict improvement in at least one objective (Deb et al., 2002).
The proposer uses this frontier to guide subsequent
proposals, while the archive retains all evaluated
candidates.

2.5

Program Selection

After evolution, we shortlist candidates using
search-set accuracy for MAPE-A and the searchset accuracy–cost Pareto frontier for MAPE-P,
with additional inclusion criteria described in Appendix B.2. The shortlisted programs are frozen
and evaluated on a larger evaluation set that remains inaccessible during evolution. We then
inspect their implementations and exclude programs with impractical scaling behavior, such as
exhaustive LLM processing of the history during
retrieval. For each setting, we report the remaining
program with the highest evaluation-set accuracy.
The selected programs are denoted MAPE-ALCM ,
MAPE-PLCM , MAPE-ALME , and MAPE-PLME , where A
and P indicate the accuracy-only and joint accuracy–
cost search objectives, and LCM and LME denote
evolution on LoCoMo and LongMemEval, respectively.

Related Work

Agent memory design and empirical analysis.
Agent memory systems organize interaction histories through reflection, selective updates, and
hierarchical storage, as exemplified by Generative Agents, MemoryBank, and MemGPT (Park
et al., 2023; Zhong et al., 2024; Packer et al.,
2023). Mem0 extracts and consolidates memories
(Chhikara et al., 2025), while Zep and A-Mem organize them through temporal knowledge graphs and
linked networks, respectively (Rasmussen et al.,
2025; Xu et al., 2025). LightMem combines topicbased organization with offline consolidation (Fang
et al., 2025). SimpleMem combines semantic compression with intent-aware retrieval (Liu et al.,
2026a). Mem0, Zep, A-Mem, LightMem, and
SimpleMem serve as baselines in our empirical
analysis.
Prior work has explored preserving conversational histories and processing evidence after retrieval. CoM combines lightweight memory construction with query-oriented organization of retrieved fragments into inference chains (Xu et al.,

Recent empirical studies further examine the

Conclusion

We introduced MAPE to study agent memory design
through whole-program evolution from minimal
seeds. Across two benchmarks, the evolved programs instantiate two recurring design patterns: retaining raw conversations as retrievable evidence
and processing retrieved evidence through intentspecific scaffolds before answering. Ablations
highlight the value of preserving raw evidence,
while transplanting the evolved composition module improves all five evaluated human-designed
systems. Under the evaluated workloads, incorporating serving cost into the search objective favors selective query-time processing over LLMbased memory construction, while retaining competitive accuracy. Together, these findings illustrate
how program evolution, combined with component
analysis and transplantation, can produce effective
memory systems and empirically grounded design
lessons.

Evolution of agent memory systems. MetaMem
evolves knowledge-utilization guidance (Xin et al.,
2026). MemTrace uses attribution of failures across
memory operations to guide prompt optimization
(Deng et al., 2026), while EvolveMem adapts retrieval and answer-generation configurations (Liu
et al., 2026b). MemEvolve jointly evolves experiential knowledge and memory architectures within
a modular design space (Zhang et al., 2026). At the
level of agent capabilities, Mem2 Evolve couples
experience distillation with the creation of reusable
tools and expert agents (Cheng et al., 2026). MemPro extends this direction to system-level evolution,
treating memory construction–retrieval pipelines
as executable programs subject to failure-guided
revision (Liu et al., 2026c). MemScope uses execution traces and runtime memory state to guide
localized code repairs to an existing memory architecture (Su et al., 2026). These studies span the
evolution of stored experience, reusable capabilities, and memory system code. MAPE starts from
minimal seeds and permits coordinated changes
across memory construction, retrieval, and composition. By comparing accuracy-only and joint
accuracy–cost objectives, we examine how search

Limitations
Our findings concern conversational memory on
two QA benchmarks, with detailed component analysis centered on one representative program. Transfer and transplantation experiments extend the evaluation across models, benchmarks, and memory
systems, while applicability to experiential memory
and open-ended agents remains to be established.
Evolutionary trajectories and resulting programs
can vary across runs, and program selection and
design interpretation involve empirical judgment.
Our cost comparisons cover serving token charges
for LLM and embedding calls, excluding search
expenses, local computation, and latency. Their
implications depend on workload, particularly how
memory construction costs are amortized across
queries.

Query-Routed Scaffolding: Design,
Ablation, and Transplant

Design. Query-Routed Scaffolding (RQS) implements the compose stage of MAPE-ALME , as shown
in Figure 2. It processes retrieved evidence through
three steps: routing, scaffolding, and deliberation.
Route. Rules based on the query wording assign
each question to one of six intents: temporal, aggregation, difference, current-value, preference, or
direct lookup. The assigned intent determines the
subsequent processing strategy.
Scaffold. For temporal questions, the scaffold extracts event dates and explicitly stated durations. It
anchors relative expressions such as “last week” to
the relevant session date and resolves them through
date arithmetic. For aggregation questions, it extracts matching items from each session, removes
duplicates, and counts or sums the items in code.

Prompt 9: Proposer: Selected Excerpts
ROLE AND SEARCH OBJECTIVE
You are a researcher designing memory systems for AI agents.
[...]
How it does that — what it stores, in what structure, and how it finds things again — is yours to
decide.
Accuracy-only:
WHAT COUNTS AS A BETTER DESIGN, on this run: a higher `accuracy_<dataset>` than the best harness
already has, compared at the same `stage_<dataset>`. That is the entire criterion.
Accuracy--cost:
WHAT COUNTS AS A BETTER DESIGN, on this run: a candidate that NO existing harness beats on BOTH
axes at once — one that would join the Pareto frontier. Pushing EITHER edge outward counts, and
they count equally: more accurate at the same cost, the same accuracy for fewer tokens, or a tradeoff nobody occupies yet.
[...]
INTERFACE AND CONSTRAINTS
Class inheriting from `forge.memo_class.MemoClass`, implementing the two required hooks, and
optionally the third:
async def build_memory_from_data(self, recorder) -> None
async def retrieve_memory_for_query(self, recorder) -> Dict

Every LLM or embedding call inside your harness goes through `common.llm.Agent` / `common.llm.
Embedding` with `model` LEFT UNSET, so it uses the run's unified models.
[...]
DO NOT hardcode shortcuts that game search-set scores.

You decide which priors to study and how deeply.

Prompt 10: Diagnosis: Selected Excerpts
You are handed ONE harness that has finished evaluation. Say what happened and why, from the
evidence, and leave the next proposer something it could not have worked out on its own.
You do not propose a design. You do not write harness code.
[...]
## Method
1. **Read the hypothesis, then the diff.** What did this candidate change relative to its parent,
mechanically — not what its docstring claims.
2. **Read the numbers on every axis this run records**, against the parent. `metrics.json` splits
the dollars by phase, so a cost change can be placed in build, retrieve or answer.
3. **Attribute the failures.** Go through the wrong answers. Group them, then for each group follow
the evidence to the earliest operation that made the outcome inevitable. Cite what you read: a `qa
` record, a `call` record, a line of the harness's code.
4. **Write the leads.** What the evidence says is worth trying next, each one attached to the
finding that motivates it.
[...]
If the evidence does not settle it, use **unattributed** and say what would settle it (a level the
run did not record, a call that was truncated).
[...]
