🎯 为什么选它当今日 TOP-1（科普口径 · 目的 2）

  • 画面自己会说话：一边是悬空乱飞的积木塔（底下有洞、砖块穿模、塔断成两截），一边是整块立住的成品；不用一句解释就能看懂 9% 和 100% 的差别，天然适合竖屏。
  • 反直觉的一刀：大家以为难点是「让 AI 想出 3D 形状」；这篇说难点是没人告诉它「这块砖底下是空的」——模型不是不会想，是缺一个会挑错的反馈。
  • 做法干净、好复述：不训练新模型、不换更强模型，只加两样东西 —— 一套拼装工具（BrickLayer） + 一个物理可行性校验器，然后让 agent 自己「写代码 → 被挑错 → 改代码」。
  • 边界清楚（片中说）：「可行」= 只用真实零件 / 无穿模 / 无悬空 / 尽可能连成一体，不等于承重、不等于拼装顺序、更不等于好看；只在积木这一种玩具上验证；可行性由程序判定、非人工验收；无第三方复现。

3 30–80s（50s） 方法（BrickWright） 作者的做法很朴素。先给 agent 一套 Python 积木工具箱 BrickLayer，用代码把砖一块块放上去；每放完一轮，校验器查四件事：是不是真实零件、有没有穿模、有没有悬空、能不能连成一体。不合格就把原因回传给 agent，它自己改代码，再来一轮。不训练新模型，只把「写—查—改」这个循环接上。模型一次没用过乐高形状的数据。 三段动画循环演示：① 写 —— 屏幕上一行行 place(brick, x, y, z) 滚出，右侧积木同步长高；② 查 —— 四枚检查章依次盖下（真实零件 / 无穿模 / 无悬空 / 连通），前两枚绿、第三枚红；③ 改 —— 红色反馈条「brick #37 unsupported」弹回 agent，代码被改写、那块砖平移补到实心处，第四枚变绿。循环箭头绕两圈，角标「loop × N」。 写 → 查 → 改
