## 对各线的可执行建议（6 线齐全）

- **pretrain**：按 GPT-NeoX 的 few-shot 口径复核我们的评测：同一 checkpoint 固定 5-shot prompt 与 shot 数，报「0-shot / 5-shot」两列；若 5-shot 增益 < 0-shot 的 10%，先查 prompt 模板而不是加数据。
- **vision**：InstructBLIP 式 A/B：冻结视觉塔与 LLM，只训连接器，A 臂「指令只进 LLM」，B 臂「指令同时进 Q-Former 与 LLM」，在 2 个 held-out 文档域各 200 题上比；预注册：B 臂 held-out 增益 <2 pp ⇒ 连接器改造不进入主线。
- **harness**：把「零样本 held-out」与「单任务微调」分成两张表，任何混报视为口径错误；新增判据：每个视觉任务必须标明属于 held-in 还是 held-out。
- **data**：按来源统计图文 / 文档对的占比并留出 1 个完全不参与训练的领域；预注册：该 held-out 域掉点 >15% ⇒ 先补该域数据，不调采样权重。
- **zhulong**：RTLCoder 式「数据 vs 算法」两因素消融：同一 7B 基座分别跑「换数据」「换训练算法」「两者都换」，报 pass@1；预注册：算法单独贡献 <1 pp ⇒ 后续只投数据侧。
- **designflow**：给 L1–L5 每道题补一条「可在仿真器中断言的终态」（参考 RTLCoder 的 testbench 缺口）；预注册：≥90% 题目能自动判定功能正确，否则该题降级为语法题。
