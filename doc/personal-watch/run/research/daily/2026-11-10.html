1MIRA: Mitigating Pole Geometry Bias in Recurrent Language Models

中文一句话
作者把 Mamba（选择性 SSM）、RWKV、RetNet 这类「Transformer 的线性时间替代者」统一刻画成 IIR（无限脉冲响应）滤波器：它们能表示哪些时间模式，由传递函数的零极点几何决定。但为了换并行度，这些架构的参数化结构常把极点压在实轴上（只留实数极点）⇒ 丢掉了复共轭极点对应的振荡/周期模式，这是一种架构层面的偏置。作者借一般 IIR 的 lattice–ladder 实现提出 MIRA：每个 block 用 lattice–ladder 结构实现高阶 IIR，同时表示实极点与复共轭极点，并保持线性时间与可分块并行（相邻时刻的仿射算子可结合 ⇒ 可在 chunk 边界拼接状态）。实验：预训练 MIRA-S（12 层、宽 768、0.14B，训练上下文仅 512 token），在 FineWeb-Edu 上全程 PPL 低于 Mamba-1(S6)/Mamba-2(SSD)/RWKV-6/RWKV-7 且 next-token 准确率更高；把评测上下文拉到 32,768（训练长度的 64×）仍保持最低 PPL，并与带 RoPE 的 MHA「match or improve」（含 YaRN 版对照）；专用 CUDA kernel 在 32K 下前向 11.37 ms（相对 MHA+FlashAttention / Mamba S6 / RWKV-6 / RWKV-7 为 4.13× / 1.32× / 2.15× / 2.85×），吞吐 8.36M tok/s（6.41× / 2.20× / 1.02× / 1.28×）。消融还给出两个可迁移的经验：lattice 阶 K=2（即允许一对复极点）比 K=1（纯实极点）PPL 更低；状态写入门控瓶颈取 dr=d/8 最低。

2One Run Is Not Enough: A Monte Carlo Protocol for Evaluating LLM Reliability on Data Science Tasks

中文一句话
作者指出：只报「一次跑多少分」的评测，分不清「能力不足」与「这次恰好抽到好/坏样本」。他们做了 DS-QA：100 道大学课程级数据科学题，覆盖 16 个数据集、9 个维度（数据理解/清洗/描述统计/可视化/统计模型/假设检验…）、3 个难度；配三层指标（通用属性：运行时长、啰嗦度、文本相似度；粗粒度：准确率、代码可执行性、完整度；任务特定共 35 项）。核心做法是 Monte Carlo 协议：同一题在相同条件下重复 100 次（评测子集 41 题，GPT-4o 等 OpenAI 模型，temperature=1），用分数的标准差（不稳定度）看可靠性。结果：不稳定度随难度上升；GPT-4o 在 Data Pre-processing 上 easy 0%、medium 66%、hard 81%；Data Visualisation 的 medium 不稳定度达 0.99、Supervised Learning 的 hard 达 1.00 ⇒ 同一题重复跑近乎抛硬币。指标间相关普遍很弱（|r| ≤ 0.30）⇒ 不冗余；啰嗦度上「词啰嗦比 +0.1 ⇒ token 啰嗦比 +0.013」（log-log 斜率 1.01，95% CI [0.95, 1.07]，Spearman 0.953）；此外 GPT-4.1-mini 在温度 >1 时更容易出现随机漂移。

3When Instruction Files Go Stale: Documentation Debt and Hidden Cost in Coding Agents

中文一句话
像 Claude Code 这样的 coding agent，每个 session 都会读仓库里的指令文件（AGENTS.md / CLAUDE.md，也叫 context/agent 配置文件）。这些文件会随代码演进过期（例如测试目录搬了，文件还指旧路径）—— 作者把它定义为文档债，利息就是每一次后续 session 都要付的额外操作。他们在 3 个活跃开源仓库里各取 1 条真实过期指令（① 测试命令 ② 代码位置 ③ 添加组件的流程），把代码与任务固定，只把该指令改成 3 个版本（保持过期 / 更正到当前路径 / 删除），用 2 个模型（Claude Haiku 5.5、Sonnet 5.5；Claude Code 2.1.316）× 22 个维护任务 × 5–7 次重复，分析 732 条轨迹的逐次 tool call。结果：是否走旧路径取决于「任务会不会把 agent 领到那一行」——测试命令在 80 次过期跑里 78 次走了旧路，流程类约 2/3，代码位置类 0 次。代价在 Sonnet 的测试命令上可见：过期 6 次 tool call / 120k token vs 更正 4 次 / 78k vs 删除 5 次 / 100k（过期比更正多约 1/3 调用）。最隐蔽的是「失败伪装成成功」：旧命令找不到测试，但输出被 tail 管道，调用仍返回成功 —— Sonnet 的 40 次过期跑里有 19 次「修完后的第一次检查」其实没跑任何测试。而任务成功率几乎不变（每个版本都把 bug 修好了），并且没有任何一次去修那条过期指令（即使 agent 注意到文件里还有别的过期内容）。

  5. 边界（必须写清）：① 只做实验心理学 10 篇论文、100 个错误，不能直接外推到 EDA / 代码评审；② 只测召回，不测误报；埋入错误的分布与真实论文错误分布是否一致未知；③ 错误判定靠 LLM-as-judge + 抽查，不是 100 条逐条人工复核；④ 系统版本是 2026-03 / 06 的快照，作者自己也说「名次别当真」；⑤ 作者自报、本线未复现。

5What the Loss Curve Misses: FP4 Pretraining Slows the Acquisition of Rare Facts

中文一句话
问一个被 loss 曲线盖住的问题：低精度训练在 loss 打平时，学「罕见事实」是不是一样快？ 作者用模拟 4-bit 矩阵乘从零训练小 transformer，在「人物出现 1–256 次」可控的合成传记上测：NVFP4 要达到 BF16 相同的召回，token 对齐下需要 1.32×（合成）/ 1.52×（自然文本）的曝光次数，而验证 loss 只差 0.5% / 2%；越罕见越吃亏（见 64 次的 0.97× → 只见到 2 次的 1.30×）。机制上，噪声进 Adam 二阶矩 ≈ 降学习率（代价会消退），噪声进更新会压低信噪比（约 2/3 代价持续到训练结束），把学习率调大补不回来。
