作者 / 机构Eugene Agichtein · Charles L. A. Clarke · Kaustubh Dhole · William Stern（共 4 位；机构未在 arXiv 摘要页给出 ⇒ 本线不代填）

分类 + 标签cs.IR ｜ 借鉴 评测判分 / 可执行判据 / 检索相关性
中文一句话提出 ExecJudges：让前沿 LLM 针对每个题目写一段可读的程序（只用词法匹配、标准 NLP 库如 parser、以及候选池统计量）来做相关性判定，替代逐文档调 LLM 打分；在 7 个 TREC 集合上，与 NIST 标注员的一致度在 TREC DL 2019–2021 上达到 Claude Sonnet 5.5 级 LLM 判分器的水平；有少量人工标签时 ExecJudges-L 在全部 7 个集合上优于同样标签预算的 per-topic 分类器，且与同预算 LLM 判分器相比「超过或落在约 0.05 Krippendorff 以内」。
链接abs: 2611.24849 ｜ pdf
推荐理由：这篇把「判分器」从黑箱打分改成可读程序，正好命中我们 harness / designflow 最痛的一点 —— 分数不可复现、不可解释。它的三个可借点很具体：① 判据即产物（一段程序就是判分规则，可 diff、可审）；② 成本结构变了（每题写一次程序，而不是每文档调一次前沿模型）；③ 标签预算的对照做得干净（同标签数下与分类器 / LLM 判分器比较，而非只报绝对分）。
我们的观察（非原文结论）：EDA / 设计流程里的「产物是否合格」本来就有一半是可执行检查（DRC/LVS/仿真断言），这篇的形态提示我们：把「程序判据 + 少量人工标签」作为 L1–L3 的默认档，把 LLM 判分留给无法形式化的语义层，而不是全程用 LLM 打分。

2General progress substitutes for specific training data in language models

作者 / 机构Mark Marosi · Peter Antal（共 2 位；机构未在 arXiv 摘要页给出 ⇒ 本线不代填）
提交 / 更新2026-11-18（v1）
分类 + 标签cs.CL ｜ 借鉴 数据配比 / 能力延迟 / 去污染
中文一句话在 chess、Othello、分子字符串、括号语言、网页文本上逐个技能抽掉训练信号，发现「模型在其余数据上的总体进步会替代被抽掉的那部分数据」：被抽技能的延迟可从小模型预测；一个从未被训练过「应对将军」的国际象棋模型，对合法着法的排序几乎与专门训练过的一样好；之后再补该数据时，只需从零训练所需数据的一小部分，且这个比例随模型变强而下降（对照：同难度的另一条规则学得慢得多）；从一个 7B 模型的训练文本中抽掉一门编程语言，也以同样方式被「找回」。
链接abs: 2611.24844 ｜ pdf ｜ 代码
推荐理由：它给「数据过滤 = 延迟能力，而不是删除能力」提供了可测的实验范式，这直接改变我们对「去污染 / 删敏感语料 / 砍低质数据」的成本估算：被删掉的能力可能在后续训练中部分自动长回来，但何时长回来、需要多少补数据是可预测的。对 2B 规模预训练最实用的是它的实验设计：抽技能 → 在小模型上测延迟 → 用比例外推，而不是直接在大模型上做一次昂贵对照。
风险 / 边界：① 结论建立在合成 / 半合成任务（chess、Othello、括号语言）与网页文本上，不能直接外推到 EDA 语料或中文语料；② 「几乎一样好」是作者自报的相对比较，无第三方复现；③ 7B 只涉及一门编程语言的抽除实验，不等于「代码能力可整体删掉又长回来」。

作者 / 机构Disen Lan（复旦大学）· Xuanda Wang（ByteDance Seed）· Jianbin Zheng（ByteDance Seed）（et al.，共 6 位；通讯 Yu Cheng，南洋理工大学；均取自 arXiv 原生 HTML 作者块）
提交 / 更新2026-11-18（v1）
分类 + 标签cs.CL ｜ 借鉴 混合注意力 / 层选择 / 预训练改造
中文一句话把「预训练 Transformer 转混合注意力」的层选择从 off-policy 改成 on-policy：FlashMorph2 指出原方法的两处失配（① 连续分支插值 + teacher-forced 隐状态 ≠ 离散混合计算；② 冻结权重忽略恢复期的参数适应），改为端到端评估采样出的离散架构并联合优化层选择分数与权重；在 Qwen3-0.6B/1.7B/8B 与 Qwen3-30B-A3B、三种线性注意力变体上，平均分比 FlashMorph RULER +2.42 / LongBench +1.08 / recall-intensive +0.76，层选择耗时仅 0.72–3.57 GPU 小时，比 HALO 快 8.4–20.8×、比 KL-LS 快 560–854×（作者自报）。
链接abs: 2611.24809 ｜ pdf ｜ HTML
推荐理由：我们要做「长上下文 / 成本」的取舍，最贵的一步往往不是训练，而是决定哪几层保留全注意力。这篇的可借点：① 选择指标要按部署形态算——用离散混合架构自己的隐状态评估，而不是在连续插值下打分；② 选择与恢复要联合——选完层再恢复训练会改变结论，必须把恢复目标写进选择阶段；③ 预算口径可复用（0.72–3.57 GPU 小时 / 0.6B–8B），适合当预注册成本。
我们的观察（非原文结论）：若 2B 预训练要留「后续转混合注意力」的余地，应在预训练阶段就固定可替换层的命名与形状，否则恢复训练时无法逐层替换而不改 checkpoint 结构。
风险 / 边界：① 全部结果作者自报，无第三方复现；② 评测集中在长上下文 / 召回类，通用能力只作「保持」声明；③ 三种线性注意力实现依赖 flash-linear-attention 库，版本差异可能影响复现。

5Do Frontier Model Ingredients Add Up? A Replicated Factorial Study of Small Language Models

作者 / 机构Biswa Sengupta（单一作者；JPMorgan Chase & Co., LLM Suite，取自论文正文）
提交 / 更新2026-11-18（v1）
分类 + 标签cs.CL ｜ 借鉴 小模型 / 因子实验 / MoE / Muon / Gated DeltaNet
中文一句话在同一 8 层 decoder（51,455,488 参数 / 词表 50,304 / 1,024 token 序列 / FineWeb / 名义 300M token 预算）上比较五个改动（MoE、Muon、Gated DeltaNet 混合、额外归一化、sigmoid 注意力门），32 次核心训练、每配置两个种子：MoE / Muon / GDN 增益最大且多数可叠加，额外归一化有帮助，而匹配参数预算的注意力门平均增益接近零；全开配置 3.6792 / 3.6750 nats，同时 95% 参考边界 ±0.0043 nats；MoE 臂为 161.3M 总参 / 51.6M 激活 ⇒ 增益同时反映路由与约 3× 总容量；论文另记一次数据泄漏（未来 token 泄漏造成异常低 loss）由奇偶位置置换测试发现（均作者自报）。
链接abs: 2611.24540 ｜ pdf ｜ HTML
推荐理由：我们常把「某个组件有效」建立在单次消融上，这篇用重复因子设计把「主效应 / 交互 / 种子噪声」分开，并给出可引用的噪声尺度（±0.0043 nats）。可借三点：① 组件必须一起测——单加注意力门在基线上降 0.019 nats，但在已选组合里重复均值变成 +0.0018 nats（在参考边界内）；② 差异要重复验证——首轮统计当成噪声的小效应，在第二次种子里重现；③ 容量混淆要写明——MoE 臂总参约为基线 3×，不能只报激活参数。
我们的观察（非原文结论）：这套设计可直接搬到 2B 预训练的「配方候选」阶段：先用 50M 级模型做 32 次短跑筛组合，再只把跨种子稳定的组合送进大模型，比逐组件单加更省算力。
风险 / 边界：① 51.5M 激活 / 1,024 token / 300M token 预算，不能外推到 2B / 32K；② 单一语料（FineWeb）与单一 tokenizer；③ 训练时间、能耗、推理速度均未匹配。
