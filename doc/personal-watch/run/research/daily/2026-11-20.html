1Can Programs Replace LLM Judges? Executable Program Judges for Scalable and Efficient Relevance Labeling

作者 / 机构Eugene Agichtein · Charles L. A. Clarke · Kaustubh Dhole · William Stern（共 4 位；机构未在 arXiv 摘要页给出 ⇒ 本线不代填）
提交 / 更新2026-11-18（v1）
分类 + 标签cs.IR ｜ 借鉴 评测判分 / 可执行判据 / 检索相关性
中文一句话提出 ExecJudges：让前沿 LLM 针对每个题目写一段可读的程序（只用词法匹配、标准 NLP 库如 parser、以及候选池统计量）来做相关性判定，替代逐文档调 LLM 打分；在 7 个 TREC 集合上，与 NIST 标注员的一致度在 TREC DL 2019–2021 上达到 Claude Sonnet 5.5 级 LLM 判分器的水平；有少量人工标签时 ExecJudges-L 在全部 7 个集合上优于同样标签预算的 per-topic 分类器，且与同预算 LLM 判分器相比「超过或落在约 0.05 Krippendorff 以内」。
链接abs: 2611.24849 ｜ pdf
推荐理由：这篇把「判分器」从黑箱打分改成可读程序，正好命中我们 harness / designflow 最痛的一点 —— 分数不可复现、不可解释。它的三个可借点很具体：① 判据即产物（一段程序就是判分规则，可 diff、可审）；② 成本结构变了（每题写一次程序，而不是每文档调一次前沿模型）；③ 标签预算的对照做得干净（同标签数下与分类器 / LLM 判分器比较，而非只报绝对分）。
我们的观察（非原文结论）：EDA / 设计流程里的「产物是否合格」本来就有一半是可执行检查（DRC/LVS/仿真断言），这篇的形态提示我们：把「程序判据 + 少量人工标签」作为 L1–L3 的默认档，把 LLM 判分留给无法形式化的语义层，而不是全程用 LLM 打分。

2General progress substitutes for specific training data in language models

作者 / 机构Mark Marosi · Peter Antal（共 2 位；机构未在 arXiv 摘要页给出 ⇒ 本线不代填）
提交 / 更新2026-11-18（v1）
分类 + 标签cs.CL ｜ 借鉴 数据配比 / 能力延迟 / 去污染
中文一句话在 chess、Othello、分子字符串、括号语言、网页文本上逐个技能抽掉训练信号，发现「模型在其余数据上的总体进步会替代被抽掉的那部分数据」：被抽技能的延迟可从小模型预测；一个从未被训练过「应对将军」的国际象棋模型，对合法着法的排序几乎与专门训练过的一样好；之后再补该数据时，只需从零训练所需数据的一小部分，且这个比例随模型变强而下降（对照：同难度的另一条规则学得慢得多）；从一个 7B 模型的训练文本中抽掉一门编程语言，也以同样方式被「找回」。
链接abs: 2611.24844 ｜ pdf ｜ 代码
推荐理由：它给「数据过滤 = 延迟能力，而不是删除能力」提供了可测的实验范式，这直接改变我们对「去污染 / 删敏感语料 / 砍低质数据」的成本估算：被删掉的能力可能在后续训练中部分自动长回来，但何时长回来、需要多少补数据是可预测的。对 2B 规模预训练最实用的是它的实验设计：抽技能 → 在小模型上测延迟 → 用比例外推，而不是直接在大模型上做一次昂贵对照。
风险 / 边界：① 结论建立在合成 / 半合成任务（chess、Othello、括号语言）与网页文本上，不能直接外推到 EDA 语料或中文语料；② 「几乎一样好」是作者自报的相对比较，无第三方复现；③ 7B 只涉及一门编程语言的抽除实验，不等于「代码能力可整体删掉又长回来」。

中文一句话长上下文服务按「重复上下文」收费，但计费权重未必反映它对答案质量的贡献：作者提出三层框架（内容相关性 / 可观测代理量 / 可审计的位置权重），实测相关性压过位置、距离衰减族并不优于「只看相关性」的基线；在真实服务栈上，65,536 token 时缓存命中把重复前缀的算力成本降低两个数量级以上，但冷重发（cold resends）限制了可持续折扣；校准模拟把会话费用的 P99 降低 31–42%，不过「收入中性」的非线性定价也能达到相近降幅，且中位费用上升。作者自述这是有界的逐 token 计费规则，不是已验证的效用估计器。
链接abs: 2611.24071 ｜ pdf
推荐理由：我们把「长上下文 / thinking 成本」当 zhulong 的核心口径，但一直缺一份把「缓存」与「质量」分开定价的实测。这篇的可借点：① 缓存收益要按「冷 / 热」分档报（热命中 >2 个数量级 ≠ 整体折扣）；② 位置权重没有想象中重要（距离衰减族打不过只看相关性）⇒ 做上下文裁剪时先按相关性筛，别先做位置衰减；③ 降 P99 与降中位是两件事，报成本必须同时给两个分位。
风险 / 边界：① 定价实验是校准模拟，不是生产 A/B；② 数字依赖具体服务栈与 provider 定价，跨云不可比；③ PDF 截断 ⇒ 数字取自 arXiv 摘要，未做 PDF 逐页复核。
