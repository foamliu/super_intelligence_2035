1Scaling Laws for Tool-Use Agents via Controllable Environment Synthesis

中文一句话
工具使用 agent 的合成数据该怎么配？作者提出 SynthAPI —— 一条能显式控制多样性的可执行环境合成管线：沿「应用/工具数 A、每应用任务数 T、每任务数据档案数 S（同一指令、不同初始数据库状态）、数据库干扰深度 D」四轴生成带真实 Python API + 初始数据库 + 可执行成功校验器的工具环境，用 GLM-5.2 当「专家」最多试 4 次采轨迹（只留通过校验器的第一次），再只对 reasoning / action token 做蒸馏（SFT，1 epoch），训练 Qwen3.5 家族的 2B / 4B / 9B / 27B 学生。规模：458,752 个任务、849 个训练模型、数据共 5.9B tokens（其中 721M 是 agent 的推理与动作输出）。结论（都在「留出最高 25% 训练 FLOPs、16× 外推」上验证）：① 拟合出数据组成感知的规模律 P̂ = σ(c0 + cA·log2(A·S·D)) · σ(b0 + bT·log2 T)^ν，留出区 MAE 0.0285，而「只看数据量」的规模律 MAE 0.1706；② 预算小时「少应用多任务」更好（A=8 在 64–512 任务最优），预算 > 4096 任务后 A=64 明显更好，且性能天花板 U 随 A 升高；③ 每任务的数据档案数 S 随预算从 1 → 2（512–4096）→ 4（>4096）递增最优；④ 干扰数据 D=4 在高预算下优于 D=1/2。下游：SynthAPI-Big 在 AppWorld Test-C 66.4%（4B）/ 77.0%（9B）/ 81.5%（27B），ASTRA-Bench High 74.2 / 76.8 / 82.3，BFCL-v3 多轮 51.1 / 53.6 / 65.0，SynthAPI-Holdout 53.0 / 64.0 / 69.8；同预算下 SynthAPI-Opt（A=64,T=128,S=4,D=4）全面优于 SynthAPI-SubOpt（A=32,T=1024,S=1,D=2）（例：AppWorld 4B 45.0 vs 38.4；Holdout 4B 56.0 vs 51.3）。

推荐理由（借鉴 · 与 BaiZe / ZhuLong 的关系）
  1. 正对 ZhuLong 的数据来源问题：EDA agent 的合成轨迹常见做法是「让 LLM 假装工具返回（模拟响应）」，而 SynthAPI 用的是真可执行环境 + 成功校验器（生成器产出 Python API 与初始数据库，任务自带 verifier）—— 这与我们 generate–execute–refine 的「执行 + 校验」结构同构，是可直接对照的数据构造范式。
  2. 给出一条可执行的「预算分配规则」：数据预算变大时，加工具/数据库多样性比加任务条数更值（A=64 在 >4096 任务后胜出；S 随预算 1→2→4）—— 对我们「一轮合成多少任务 vs 扩多少个工具/库」这种配比决策，有可试的具体档位，不必只凭经验。

  4. 边界（必须写清）：单一学生家族（Qwen3.5）+ 纯 SFT（无 RL）；下游只有 4 个基准（AppWorld / ASTRA-Bench / BFCL-v3 / 自建 Holdout），且 3 个偏「设备助理 / 客服 API」域，与 EDA 工具链差异大；作者自承与 ToolACE / SimSAT / EnvFactory / EnvScaler 的对比「训练配方不同（小数据 SFT+RL vs 大数据纯 SFT），既不隔离合成方法、也不证明数据效率」；规模律外推区间只是 16× FLOPs；数字作者自报、本线未复现。

2Collective Dynamics of Self-Reinforcement: How Cross-Task Coupling Drives Policy Collapse in Unsupervised RLVR

中文一句话
「无标签 RLVR」（用多数投票当奖励、不需要标准答案）为什么先涨后崩、而且只在题很多时崩？本文给出一套可算的解释：在多题共享参数的可解模型里，只要单题自强化漂移 F 的群体平均斜率 ⟨F′⟩ > 0（题目仍不确定时成立；K=3 时等价于答案 logit |z| < ln(2+√3) ≈ 1.32），任何共享方向的扰动都会被放大（Curie–Weiss 型顺磁不稳定）。关键是两个速率赛跑：单题锐化被 1/N 拖慢，而共享模式以 ∝λ² 增长、与 N 无关 ⇒ 得到闭式临界题量 N_c ≃ ln(1/δ)/(λ²·ln[F*/F(a)])，并把 λ²·N·ln[F*/F(a)] 收敛到单一临界值 Λc ≈ 2.6。四条可证伪预测在随机模拟（REINFORCE, K=3, 二值答案, 普通 SGD）上全部成立：相变陡峭；Nc ∝ λ^−2（拟合斜率 −2.22，含对数修正）；λ=0.1 / a=0.5 时 Nc ≈ 536；GRPO 同 Nc（548）；更大 group size 抬高 Nc（K=5/8/16 → 793/876/1557）。小 Transformer 实验（6 位数比较题 x1+x2+x3 > x4+x5+x6；22 个条件 × 7 个数据集规模 × 6 seeds）：去掉共享方向（反对称网络）则永不坍缩；把共享耦合经 bias 加回 ⇒ 剂量依赖地恢复坍缩（ρb ≥ 1 时几乎全崩）；边际熵奖励在 βc ≈ 12 以上能阻止坍缩，但救不回准确率 —— 不稳定转移到下一个「与任务无关」的集体核模式。

3What Improves During Pretraining? Tracking Knowledge Acquisition with Point-in-Time Models

中文一句话
「预训练到底在学什么」能不能不只靠聚合 benchmark 分数回答？作者提出 TVS（temporal variability score）= 一条样本在各年份「时点模型」上的 per-token NLL 变异系数，用 PIT-4B 系列（8 个 4B 基座，2017–2024 逐年 FineWeb 快照，同架构 / 同分词器 / 同训练配方，只差数据年份）算出每个评测项的「时间稳定度」，再在 6 个多选题基准（HellaSwag / PIQA / WinoGrande / ARC-Easy / ARC-Challenge / MMLU，共 16,239 条，按 token 长度分箱、箱内按 TVS 三分位分组）上跟踪 6 个模型（Pythia 1.4B / 6.9B、TinyLlama 1.1B、SmolLM3 3B、OLMo 1B / 7B；checkpoint 覆盖 0.54B → 11.1T tokens）的机会归一化准确率。发现：① 早期两组几乎无差（24 个设置里低 TVS 组赢 13 个，均值 −0.8 分）；② 后半程高 TVS 组每 10 倍 token 多涨 2.0 分（36 个设置中 26 个为正）；③ 最终高 TVS 组在 34/36 个「模型×基准」设置上胜出，平均 +7.3 分（95% CI [5.5, 9.2]；按 4 个模型家族平均后 CI [4.8, 10.2]，p=.003），每个基准都是正向（WinoGrande +1.7 → PIQA +16.1）；④ 在知识密集型 ARC / MMLU 上，控制平均 NLL 后 18 个设置全部为正（+6.9 分），但再控制「金答案 vs 干扰项 margin」后只剩 +1.4 分（22/36 为正） ⇒ 7.3 分不是「独立的 TVS 效应」。反向对照很硬：按平均 NLL 分组时，高 NLL 组在全部 36 个设置里更差；用未归一化的 NLL 标准差分组则效应反转。

推荐理由（借鉴 · 与 BaiZe / ZhuLong 的关系）
  1. 正对 BaiZe 的「预训练阶段评测」：我们盯 loss 曲线和聚合 benchmark，容易得出「小模型阶段各能力都差不多」的结论；本文的 item 级分层量 TVS 说明聚合分数把两种学习轨迹混在一起：时间稳定项早期就学会、时间波动项后期才涨。作为一个纯离线、不需要训练的诊断层，成本极低。
  2. 可复用的具体做法：用公开的 PIT 年份模型算每个评测项 NLL 的变异系数 → 在长度分箱内切成低/中/高三档（避免 TVS 与题面长度混淆）→ 分别画 checkpoint 学习曲线。这套流水线可以直接套到我们的 eval 集（中文 / 代码 / EDA），检验「高 TVS 项后期涨更快」是否跨语种/跨域仍成立。
