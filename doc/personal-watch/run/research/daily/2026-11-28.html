3 · NEVA: Natural-Language Co-Evolution and Validation of Microarchitectures

原题NEVA: Natural-Language Co-Evolution and Validation of Microarchitectures
中文一句话现有 LLM 驱动的微架构搜索多在演化 C++ 模拟器代码，迫使模型去推理实现细节而非架构机制。NEVA 改为：从已发表研究里抽取「架构概念」成结构化知识库，指导联合自然语言架构规格的演化，并处理三件事——自然语言表示架构、硬件约束下验证候选、借诊断反馈协同各微架构组件。用 SPEC CPU2017/2026 等负载评测，「规格级演化」优于「代码级演化」；Claude Opus 5.5 下 NEVA 设计在 held-out 单核性能上比 Pythia-Mockingjay 基线最高 +4.8%。

4 · When Every Rollout Fails: Splicing Learner-Conditioned Options into Long-Horizon Agent RL

原题When Every Rollout Fails: Splicing Learner-Conditioned Options into Long-Horizon Agent RL
中文一句话长程 agent 任务里，组内 RL（GRPO 类）经常遇到整组全 0 奖励（all-fail），拿不到策略梯度。SPLICE 不灌入强模型的完整轨迹，而是对每个全失败组：由提案模型在当前策略轨迹上选一个拼接点、生成若干有界选项，用重复当前策略延续估每个选项价值，把正估计转成「回报加权局部目标」再拟合策略。在 SWE-bench Verified 与 BrowseComp-Plus 上，四种设置均优于 GRPO 与全轨迹引导，比 GRPO 高 2.8–9.8 个百分点；对初始失败 SWE 任务，把 GRPO 的「毕业率」提高 10.8 个百分点，且降低提案模型算力。
作者 / 机构Haowen Hou · Yicheng Liu · Zhen Huang · Jiaqi Wang（4 位；摘要区未列机构）
提交 / 更新2026-11-25（arXiv v1；published=2026-11-25T17:38:00Z）
分类 + 标签cs.LG ｜ 🏷 借鉴（posttrain self-play RL · harness 指标）
链接arXiv:2611.34777
推荐理由正中我们 posttrain 在真实 EDA 环境做 self-play RL 的痛点：通过率低时 all-fail 组太多，组内优势全为 0。SPLICE 的「局部拼接 + 重估价值」比「喂全轨迹」更省且更 on-policy。可落地：posttrain 预注册一个 SPLICE 对照臂，并在日志里单列 all-fail 组比例与毕业率。⚠️ 任务是 SWE / Deep Research，不是 EDA；奖励仍来自可验证判分，迁移到 EDA 需重新定义「选项」与「拼接点」。

5 · Solve Vision with Code: Coding Agents Are Stronger Visual Reasoners Than Video Models

原题Solve Vision with Code: Coding Agents Are Stronger Visual Reasoners Than Video Models
中文一句话「视频生成模型能原生地做视觉推理」被当作优点，但没人用同条件对比过「写程序」这条符号路线。作者把同一批任务、同输入/输出口径/评分器都给两方：视频模型去噪像素，编码 agent 则写程序渲染答案视频，再由未改动的规则评分器判分。在 VBVR-Pro-Bench（500 实例、5 类认知、符号真值）上，三个闭源 agent（Codex / Claude Code / Gemini CLI）得 0.923 / 0.894 / 0.893，各比最强视频模型高 0.22 以上；23 个可运行开源模型里最好 GLM-5 0.572。结论：答案可由首帧+提示算出的任务，程序合成目前是更可靠的视觉推理路线。
