5 · How Much Do Coding Agents Over-Edit, and Why? An Empirical Study of Unneeded Edits in Repository-Level Agent Patches

原题How Much Do Coding Agents Over-Edit, and Why? An Empirical Study of Unneeded Edits in Repository-Level Agent Patches
中文一句话提出 Delta Residue Attribution（DRA）：回放 agent 轨迹，把最终补丁的每个单元追溯到写入它的步骤，逐个回退并重跑测试以判定是否「不必要」。分析 18 个前沿模型在 SWE-bench Verified / DeepSWE 的 7,660 条已解决轨迹：agent 补丁确实更长，但多出的编辑在 SWE-bench 上 61% 是测试、13% 是文档，DeepSWE 上 58% 是代码；平均 11% 的代码单元仍不必要，且其中 89% 改变了行为。
作者 / 机构Aakash Goel · Benjamin Steenhoek · Yu Hu（3 位；摘要区未列机构）
提交 / 更新2026-11-25（arXiv v1；published=2026-11-25T18:37:06Z）
分类 + 标签cs.SE ｜ 🏷 科普（大众能懂：AI 写代码「顺手多改」）+ 借鉴（harness 判分）
链接arXiv:2611.34875
推荐理由把「AI 改太多」这一常见抱怨量化到单元级，且结论反直觉：agent 的代码平均至少和开发者一样必要（SWE-bench Verified NP_code 0.887 vs 0.864；DeepSWE 0.797 vs 0.785）。可落地一条：harness 在 resolve rate 旁增报「不必要编辑率」，并用「单元回退 + 重跑测试」的审计做抽样复核。⚠️ 目标是 SWE-bench/DeepSWE 的代码仓库任务，不等于 EDA 脚本任务；DRA 剪枝仍会误删必要代码（recall 67% / precision 46%），不可当自动清理工具。
