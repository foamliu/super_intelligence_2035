1What Should SFT Learn? Conditional Information Gain for Generalizable Post-Training 借鉴

原文标题
What Should SFT Learn? Conditional Information Gain for Generalizable Post-Training
中文一句话
指出「模型兼容 ≠ 学习价值」：一个当前模型弱支持的 token，既可能是不该学的错配，也可能恰是示范要教的任务特定决策。提出 CIG-SFT（信息论框架）：在 teacher forcing 下，用冻结的参考模型比较「给定 / 不给任务输入」时示范 token 的似然（gold 前缀固定），得到「条件信息增益」—— 量化任务本身把示范决策的不确定性降低了多少；再把它转成对当前策略的 KL 正则投影，并推导出一个等价的标量加权 SFT 目标（其 logit 梯度与投影目标完全一致）。在数学推理与代码生成基准上，CIG-SFT 稳定优于标准 SFT 与近期自适应微调基线，尤其在难评测分布上的泛化提升明显，且不需要额外训练数据或在线 rollout。
作者
Yuxuan Gu, Kequan Niu, Xiaocheng Feng, Yun Li, Yiqiao Yang, Bing Qin（6 位）

原文标题

中文一句话
研究预训练阶段对时变知识的组织方式如何决定后续知识更新的效率（既有工作多关注「训练之后如何更新更快」）。实验：按时间顺序训练知识的模型专精于最近遇到的知识（称 specialists）；把同样知识随机打乱顺序训练的模型在所有时间段都表现好（称 generalists）。意外发现：specialists 获得新知识所需更新步数远少于 generalists。为解释，作者从第一性原理推导出一条把「更新成本」与「模型优化动力学」联系起来的规律，且与实测吻合。据此设计一种组织预训练数据的策略：既保留稳定的历史知识、又能高效更新当前知识；并证明该时间化知识组织的收益可迁移到真实预训练模型与既有知识更新工具，且推广到其他知识排序。

原文标题
RATED: Reliability-Aware AI Agent Tool Retrieval via Execution Dynamics
中文一句话
随着 AI agent 越来越依赖外部工具，工具检索对可靠行为至关重要；既有方法只优化语义相关性，却基本忽略执行期间的工具可用性。为此提出 RATED：把鲁棒语义匹配与动态可靠性自适应结合 —— 用冻结双编码器 + 对比微调做语义匹配，再用一个轻量上下文 bandit 模块依据实时执行反馈对候选重排序，从而快速适应运行时工具故障、无需昂贵重训。作者同时提出 EcoAgent 基准（5,172 个真实工具、>21 万条 query-tool 对，用于离线检索 + 动态可靠性评测）。实验显示：相对 ToolLLM API retriever，真实查询下 MRR 相对提升 52.2%；在 30% 故障率的严重 API 中断场景，把「错误选择率」从 86.2% 降到 2.9%，而延迟开销相比「仅编码」推理增加不到 1 ms。代码与数据集已公开。

原文标题
Designing Protein Structures from Natural Language
中文一句话
从头（de novo）设计蛋白质的核心难点，是造出具备目标结构与功能的蛋白；而现有设计模型通常要为每种属性专门设计一种输入表示，限制了能支持的设计目标。作者提出 Prompteina —— 据其自述是首个支持「用自然语言指定更新、更广设计目标」的全原子结构生成模型（类比文生图）。为训练它，构造了 Prompteina-Data：180 万条结构 + 5000 万+ 条描述（覆盖全局与残基级结构 / 功能属性）的「文本–蛋白质结构」配对数据；再在预训练结构生成模型 Proteina-Complexa 上做文本条件预训练 + 微调，把残基与其对应文本对齐。据原文：Prompteina 在 18 项结构属性中的 15 项上优于基线；在 binder 设计中，于 20 个靶点中至少 13 个领先基线、界面置信度相对最强基线提升 14%；配合迭代式 in silico 反馈，在最难靶点上相对非迭代生成的增益比次优基线大 57%。作者还做了湿实验验证：针对 GM2A（此前无已报道 de novo binder 的靶点）鉴定出 9 个 binder，最强表观 KD ≈ 107 nM。

5CaptchaAgent: Verifiable Visual Reasoning for CAPTCHA Solving 科普

原文标题
CaptchaAgent: Verifiable Visual Reasoning for CAPTCHA Solving
中文一句话
现代「推理型验证码」要求细粒度感知 + 组合关系推理 + 浏览器内动作执行，而端到端 VLM agent 很脆：漏看一个物体、数错一个数、搞反一个关系，都会让最终点击直接出错。作者提出 CaptchaAgent（结构化视觉推理框架）：先从截图构造视觉中间表示（V-IR），显式记录实体、属性、空间/拓扑关系；再用「纯符号 ASCII 协议」逼解析器给出具体的物体集合与计数；在此全局表示上做局部证据精修（对歧义区域用更高有效分辨率回看）与反事实一致性校验（用「保任务变换」检查动作是否稳定）。在 Open CaptchaWorld 上，相对商用浏览器 agent 基线，三个专有 backbone 的 Pass@1 提升 21.3–25.8 个百分点；在离线 Oedipus-data 上，相对 Oedipus solver，平均 Pass@1 提升 9.2–12.3 个百分点。作者指出：精确计数、连续几何、有序执行仍是主要困难 —— 这为「设计更抗自动化的组合式验证码」提供了方向。
