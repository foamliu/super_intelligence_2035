1Rethinking Routing Exploration in Modern Mixture-of-Experts 借鉴

原题
Rethinking Routing Exploration in Modern Mixture-of-Experts
中文一句话
指出「细粒度专家切分 + 共享专家」组合会让 MoE 路由陷入探索困境，并用 MirrorMoE（按 token 自适应抑制多余专家、缩小探索空间）来兑现细粒度切分本该带来的表达力。
作者
Bingcong Li, Hao Ma, Michael Muehlebach, et al.（共 5 位：Bingcong Li, Hao Ma, Michael Muehlebach, Niao He, Yi Ma；机构见原文）
日期
首次提交 2026-10-15T17:58:02Z（published，来自 id_list 官方 Atom）· 版本 v1（摘要与 updated 时间同源核对）
分类 · 标签
cs.LG · 借鉴 · 关键词：MoE / 路由 / 共享专家 / 细粒度切分 / 预训练
abs 链接
https://arxiv.org/abs/2610.22353
推荐理由（我们判断 · 能用在哪一步）：
① 可直接变成 BaiZe MoE 的一个诊断实验：摘要的核心假设是「共享专家压缩 token 表示多样性 → 路由探索变少；细粒度切分放大路由组合空间 → 本应需要更多探索」，两者叠加产生张力。落到我们这边，可先不改结构，只在小规模预训练里同时记录「路由熵 / 每层专家使用分布 / token 表示方差 / 专家组合覆盖率」，看四个量是否随共享专家比例与切分粒度呈此消彼长 —— 这是一次低成本证伪，不做完不应把「细粒度 + 共享」当默认配方。
② 可试的改动很小：MirrorMoE 走的是「按 token 自适应抑制不必要专家」而非改主干，意味着它可叠加在现有门控 / 负载均衡损失之上。建议在 1–2 个规模点、固定激活专家数（FLOPs 对齐）下做 A/B，并单独监控负载均衡系数是否需要重调（抑制专家可能改变路由分布，与 aux loss 存在耦合）。
③ 边界：摘要只称「多规模一致提升」，未给数值、未给消融；抑制策略的具体判据、额外计算开销、与 dropless / capacity factor 的交互均需读原文。本线未复现，不据此改主配方。
建议动作：读原文（重点看 §方法 的抑制判据与开销表）+ 试跑（小规模路由诊断，产出一页对照图）。

2DeciCAD: Harness-Grounded Learning of Action Policies for CAD Agents 借鉴

原题
DeciCAD: Harness-Grounded Learning of Action Policies for CAD Agents
中文一句话
把「agent 的决策空间由 harness 定义」这件事做成方法论：面向 CAD 设计语义动作 + 决策导向观测 + 持久状态转移的领域原生 harness，并从轨迹里抽因果决策监督做 SFT + 几何约束在线 RL。
作者
Yufeng Peng, Yixin Zhang, Ziyi Liu, et al.（共 8 位：Yufeng Peng, Yixin Zhang, Ziyi Liu, Zhikun Xu, Jiarong Yang, Sijie Wang, Wenjie Feng, Qiyu Kang；机构见原文）
日期
首次提交 2026-10-15T12:11:43Z（published，来自 id_list 官方 Atom）· 版本 v1
分类 · 标签
cs.AI · 借鉴 · 关键词：agent harness / 动作空间 / 观测粒度 / SFT / 在线 RL / CAD
abs 链接
https://arxiv.org/abs/2610.21755
推荐理由（我们判断 · 能用在哪一步）：
① 正对 ZhuLong 的 harness 设计层：这篇不谈「换更强模型」，而谈接口即策略 —— 动作语义（语义 CAD 动作 vs 通用 CLI）、观测粒度（面向决策的观测 vs 原始日志回灌）、状态（持久状态转移 vs 每步重建上下文）共同决定策略能不能学、学得多贵。EDA 侧可类比映射：把工具调用从「shell + 大段文本」改成「语义动作 + 决策所需最小观测 + 持久设计状态」，例如布局/DRC 场景只回传违例拓扑与可行动作，而非整份报告。
② 训练配方可复用：从交互轨迹中抽取因果决策监督（哪一步动作真正改变了结果），先 SFT 再上领域约束的在线 RL；这对应 ZhuLong 的 generate–execute–refine 闭环，把「执行结果」变成「决策级标签」而不仅是成败信号。
③ 有可量化的工程指标：作者称相对通用编码 harness 输出 token 减少 45–88%，同时 F1/IoU 最佳。建议我们把「每步 token 数 / 步数 / 成功率」固化为 harness 改造的硬指标，避免只盯准确率而忽略成本。
④ 边界：4 个 CAD 基准、作者自报 · 未复现；CAD 的几何约束与 EDA 的电学/工艺约束不同构，「几何约束 RL」不能直接等价搬为 DRC 约束 RL，需自行定义可验证的约束奖励。建议先做动作/观测重设计这一层，RL 部分待有稳定执行环境后再上。
建议动作：读原文（重点看 harness 接口定义与 token 统计口径）+ 试跑（选 1 个布局子任务复刻「语义动作 + 决策观测」并对比 token/步数）。

3How to Train Your Little Dragon: Teaching a Small Language Model to Construct and Refine GPU Optimization Scripts 借鉴

原题
How to Train Your Little Dragon: Teaching a Small Language Model to Construct and Refine GPU Optimization Scripts
中文一句话
不让模型「猜 kernel 代码」，而是让 8B 小模型学会写编译器优化脚本：用紧凑无损表示描述 TVM 变换组合、确定性解码回精确 trace，再用「先正确、后性能」的 SFT + RL 把单次尝试正确率拉到 91%+。
作者
Annabelle Sujun Tang, Wei Tang, Songyao Jiang, et al.（共 10 位：Annabelle Sujun Tang, Wei Tang, Songyao Jiang, Tianhui Li, Shengzhe Xu, Jiin Woo, Kaan Ozkara, Youngsuk Park, Zhen Jia, Hadi Esmaeilzadeh；机构见原文）
日期
首次提交 2026-10-14T21:49:24Z（published，来自 id_list 官方 Atom）· 版本 v1
分类 · 标签
cs.LG · 借鉴 · 关键词：SLM / 编译器优化 / GPU kernel / 表示学习 / SFT / RL
abs 链接
https://arxiv.org/abs/2610.20980
推荐理由（我们判断 · 能用在哪一步）：
① 与 ZhuLong 的 generate–execute–refine 同构，但把「生成物」换成了更可控的一层：模型输出的是优化脚本（编译器变换的组合），经确定性解码还原成精确 trace（变换参数 + 依赖）。相比直接生成 kernel 源码，这层抽象让产物可审计、可回滚、可复用，也天然适配「执行—反馈—再改」的闭环。EDA 流程里的等价物是「生成流程脚本 / 约束脚本 / 后端配置序列」而不是直接写实现。
② 数据与奖励配方是可直接抄的工程重点：先用编译器搜索历史造 108,594 条样本（60,236 构造 + 48,358 改进），SFT 后再 RL；奖励形状化为「正确性 + 实测性能」，且只对数值正确的 kernel 给延迟奖励 —— 这是防奖励黑客的关键设计（否则模型会学会「跑得快但算错」）。我们做 code agent 的 RL 时同样应把可验证正确性设为门控，性能只作二级项。
③ 「8B 打好专用任务」的信号价值：作者称单次尝试正确率 91.27%（构造）/ 92.01%（改进），并在 88/102 构造任务与 145/170 改进提示上产出比 SFT 更快的 kernel，且单次正确率与 kernel 性能优于 6 个前沿 LLM。对 BaiZe（~2B 起）与端侧/SLM 路线的启示是：任务专用表示 + 结果奖励可能比「更大的通用模型 + 更长提示」更划算；但这条比较是作者自报 · 未复现，且任务限于 TVM MetaSchedule 的 kernel 族。
④ 边界：需读原文确认「紧凑无损表示」的表达上界（是否覆盖新变换、跨后端可移植性）、搜索数据与评测集是否重叠、以及 RL 的算力成本。名字里的 “Little Dragon” 与我们 ZhuLong（烛龙） 同名纯属巧合，无隶属/合作含义，不应在对外材料中暗示关联。
建议动作：读原文（重点看表示设计 + 奖励门控 + 数据构造流程）+ 试跑（选 1 个 kernel 族做小规模 SFT/RL 复现，先验「正确率门控」是否可稳定实现）。
