1Evolver: Turning Agent Exploration into Evolving Capabilities

中文一句话
agent 每次跑任务都会「摸索」出有用的流程知识，但跑完就随轨迹丢掉，下一次还得重新摸。作者把这部分经验做成不改模型参数的可复用资产：结构化 Gene（策略 + 适用条件）、绑定具体执行案例的 Capsule、以及记录「别这么做」的 AntiGene；执行时在 session 起点注入（注入预算 12,000 字节），可选在提示时机按需检索。评测用 Baseline–Extraction–Gene（B–E–G）配对协议：同题、同 harness、同基座，B = 原生跑，G = 注入经验后在新 session 重跑，两边都保留完整 token 记录。在 Claude Code / Codex × 2 个基座 × 4 个基准（Terminal-Bench 2.1、SWE-bench Multilingual、SWE-rebench、GAIA）的 16 个配置、320 对配对上，成功率 83.13% → 87.50%（+4.38pp）、任务执行 token −24.24%；在两边都成功的 265 对里 token 仍 −17.57%（省的不只是「失败重试」）。分基准：Terminal-Bench 2.1 提升最大（64/80 → 71/80，+8.75pp）、SWE-rebench +5.00pp、GAIA +3.75pp、SWE-bench Multilingual 96.25% 持平；16 个配置中 9 个提升、7 个不变。

2ReproBridge: Building Reproducibility into ML Research Artifacts

中文一句话
复现一篇 ML 论文，成功与否常常不取决于作者放出的代码本身，而取决于复现者能否把散落在论文 / 代码 / 工件里的「做法与决定」补齐。作者把复现沉淀成标准四件套工件：精修代码库（refined codebase）、环境配置（environment setup）、实验启动器（launchers）、复现指南（reproduction guide）——不只是「能跑」，还要把每个设置与修复的理由和影响范围写下来；构建由 agent 做、人定标准，复现时在新 session 里只拿「原始代码」或「四件套」，另有独立 Auditor 核验执行证据（因为「数字对上了」也可能是替换测量得来的）。基准 ReproBridge-Bench：从 742 篇 ICML 2026 Spotlight → 241 篇有代码 → 随机 50 篇 → 排除工件/算力/闭源 14 篇 ⇒ 36 篇论文、502 个实验、1,463 个任务，其中 1,029 个（70.3%）数值兼容进入下游评测（387 个实验）；每个任务配 5 位独立人工复现者的参考分数，并用「参考变异 ≤ 绝对分数的 10%」区分 stable / higher-variability。结果：4 个 coding agent 上复现成功率 76.4% → 92.6%、下游 API 花费 −19.7%（各模型 −16.8%～−23.7%）、跨模型成功率极差 21.6pp → 3.9pp（四个模型都 >90%）；去掉任一组件都会掉，代码与环境缺失损失最大。

3AiXapply: Fast and Reliable Full-File Code Integration with Specialized Small Models for IDE Workflows

中文一句话
上游模型给出的往往只是「一小段改动」，要真正落地必须把它合并回整文件且不碰无关内容。作者把这个动作单独定义成 Apply 任务并做成专用小模型：数据从 CommitPack 5,770 万条真实 commit 出发，规则抽样（单文件、限制文件长度 / 改动大小 / 行变更比、commit message 质量、按语言均衡抽样）压到 24,460 条候选 → LLM 生成显式「改动描述」→ 再生成 update_snippet + 完整 final_code → 一致性校验（diff 必须完全且只能由 snippet 解释，删 2,960 条 = 12.1%）→ 可解性过滤（三个强模型各跑两次共 6 attempts，6 次全败或 5 次败的样本丢弃，删 516 条 = 2.4%）⇒ 20,984 条（19,347 训练 / 1,637 测试，按 commit 切分防泄漏，20 种语言）。训练 Qwen3-4B（64k 上下文）：SFT 用整文件交叉熵（对未改动区域也监督，鼓励「照抄不变」）；GRPO 用语言/格式感知的等价奖励（代码按 Pygments token 序列比、JSON/YAML/XML 先规范化结构、MD/SQL 先格式规范化）+ 按错误类型加权的密集奖励 r = max(0, 1 − 0.25·patch_errors − 0.35·side_effects)（区间外副作用罚得比区间内改错更重）。结果：SFT 版 94.4%（语言感知等价口径）超过 DeepSeek-V3.2 的 91.6%；RL 版在 1.45s 下 0.938（Qwen3.5-397B 为 0.948）；配合无草稿模型的投机解码（n-gram + suffix）单 A100 达 ~2,700 tok/s、端到端延迟约 75× 低于 API 版 DeepSeek-V3.2；在 aiXcoder IDE 插件里把 Apply 平均延迟从 50s 压到 1.89s，按时间容量规划替换 5 个上游实例中的 1 个可省 20% 上游机器成本；100 条真实开发任务中 91 条首次输出可接受。

4Representational drift in a code model: behaviour settles, which neurons carry it does not

中文一句话
一个 15 亿参数的代码模型（OpenCoder-1.5B）在 2.03 万亿 token 预训练里（恒定学习率、每 1,000 step 存一个 checkpoint），作者追踪 169 个 Python 语言构造（关键字/内置名/语法结构）各自的「载体神经元」—— 每层 MLP 里对该构造激活最强的那 5%。结论反直觉：对 16 个「语法决定下一个 token」的构造，这些位置上的 loss 在训练前 4%（84B token）就掉到地板，之后 96% 的训练里几乎不动（24 条序列里 20 条平、4 条略升、0 条继续降）；但承载它们的神经元一直在换——169/169 个构造到最后 checkpoint 都还在换（注入「突然安顿」的检出率 99.1–99.4%，逐步安顿在 500B token 前检出 99.4–100%，未注入序列零误报）。最能说明问题的一步：把 84B token 时的「旧载体」在训练终点挖掉，抬升的 loss 与挖随机同尺寸神经元无法区分（0.14 nats，95% CI [−0.01, 0.42]；14 个构造中 10 个占优，p=0.09）；而挖当前载体是 0.40 nats（终点，16 个里 14 个显著）。换句话说：功能由「当前那批神经元」承担，而不是「最早写进去的那批」；细看是「稳定的池子 + 流动的样本」—— 退出某构造载体集的神经元，回来的概率是同条件神经元的 3 倍，但没有一组会「原样重组」。

5Compaction, decay and reinforcement in a two-tier conversational memory: a paired evaluation against retrieval-augmented generation

中文一句话
会「记住」对话的 agent 必须决定留什么：一条路是 RAG（原样保留聊天记录，用时检索），另一条是压缩（每轮抽成「原子事实」再检索；本文还加了两层记忆 + 按轮数指数衰减 + 「检索到即强化」）。作者把两臂放在同一窗口、同一存储、同一生成器、同一 judge 下回答 LoCoMo 全部 1,985 题，并把两臂预测写在同一行 ⇒ 可在 512 个分歧题上做 McNemar 精确检验（两臂在 1,473 题上一致，只比总分等于丢掉大部分分辨率）。四个可比类别：压缩 71.4% vs RAG 64.6%（+6.8pp，p=5.5e-08），且 prompt token少 34%；把 446 道对抗题也算进来，领先缩到 +2.0pp 且不显著（RAG 在对抗题上领先 14.6pp）。损失有结构：参考答案要求越多原话措辞，压缩越吃亏（1–2 个参考词时领先 9.6pp，超过 8 个词时落后 3.1pp），token 重叠同向变化 ⇒ 不是 judge 造成的。一句话：压缩留下「事实断言」，丢掉「怎么说的」 —— 问「值」它赢，问「原话」它输。文中还有一处诚实的自我更正：早先「慢好几倍」的延迟结论来自两次非配对跑，配对后 p50/p90 几乎不可分（1,741 vs 1,769 ms；p90 3,570 vs 3,360 ms），均值差 19% 全在尾部。

推荐理由（科普 · 大众看点 + 传播力）
  1. 人人有体感：「AI 该像记笔记，还是像录音？」；结论不是站队，而是按问题类型分工（问事实值 → 记笔记；问原话 → 留录音），非常适合做「一张分流图」的画面。
  2. 数字干净、可直接上屏：71.4 vs 64.6、+6.8pp（p=5.5e-08）、−34% token、对抗题 −14.6pp、措辞阈值 +9.6pp → −3.1pp。
  3. 有「翻车—纠正」的叙事：作者公开四个负结果（含功效计算）并撤回自己「慢好几倍」的延迟结论 —— 适合讲「配对实验为什么重要」。
  4. 边界：LoCoMo 是合成长对话；judge 是模型判分（未做人工双评）；压缩臂的事实抽取质量依赖抽取器（十段对话抽出 8,276 条事实 / 11,902 条链接）；对抗类别定义与常见文献不同（文中专门解释）。🚫 不要讲成「压缩一定更好」。
