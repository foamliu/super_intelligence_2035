中文一句话任务「成功」并不等于知道该强化哪种行为：Skill-FT 用自然语言技能抑制教师轨迹里的无依据假设、无效重复与表面验证，并补出被低估的有效行为；AutoMaster 让 LLM agent 闭环做轨迹分析 → 技能设计 → 数据选择 → 回滚反馈。Terminal / Search / 软件工程三类任务、4B 与 9B 目标模型上，比「直接用成功教师轨迹做 SFT」平均高 1.42–8.99 个百分点（教师、题池、训练集大小与 SFT 配方全部固定）；另有反直觉发现：SFT 时保留技能说明比去掉更好（六个设置全部成立），尽管评估时看不到技能、监督输出完全相同（作者自报）。
链接abs: 2611.26510 ｜ pdf
推荐理由：我们把「教师轨迹 → SFT」当作默认低成本路线，但一直没把轨迹里的坏习惯单独建模。可借三点：① 「成功」不是唯一的筛选轴——同一批成功轨迹里，技能描述能把「碰巧成功」与「可复用行为」分开；② 技能说明应作为训练上下文保留，这直接影响我们数据打包格式（每条样本是否带 skill 前缀）；③ 增益区间 1.42–8.99 pp 可作为 harness 侧预注册的最小可检测效应。

2MemFolder: Structure-Guided Memory Folding for Efficient Agent Memory Management

作者 / 机构Xuyang Liu · Chenwen Lu · Junxi Wang（et al.，共 9 位；机构取自 arXiv 元数据，本轮未逐页核）
提交 / 更新2026-11-19（v1）
分类 + 标签cs.CL ｜ 借鉴 长期记忆 / 检索成本 / 上下文压缩
中文一句话长期 agent 的外部记忆有两个耦合成本：记录越多检索越慢，检索到的上下文越长则 prefill 与解码注意力越贵；剪枝会丢证据、合并又会得到更少但更长的检索单元。MemFolder 分两段处理：RecordFolder 先做实体归一，按「代表性 + 互补性」选锚点，再结合语义 / 实体亲和度与时间链把兼容记录折叠成更少的检索单元；ContextFolder 把组内原始记录编码成紧凑文本，并用验证反馈在关键事实无法恢复时回改。三个文本记忆基准（LoCoMo / PersonaMem / LongMemEval）与两个多模态基准（M3-Bench-web / M3-Bench-robot）上，Mem0 上以 50% 更少记录保留 99.0% 原平均性能，比最强基线高 1.9 个百分点；叠加 ContextFolder 后，现有记录压缩方法还能进一步缩短输出（作者自报）。
链接abs: 2611.26427 ｜ pdf
推荐理由：harness 线的记忆模块目前只按「条数」设预算，这篇把条数成本与上下文长度成本拆开，并给出可复用的两段式结构。可借三点：① 「代表性 + 互补性」选锚比相似度 top-k 更抗冗余，适合芯片规格书这种大量近似条款的语料；② 用验证反馈决定是否回改编码，等价于给压缩加一个「关键事实可恢复」判据；③ 50% 记录保留 99% 性能 可作为我们记忆预算的分档起点。
风险 / 边界：① 保留率是「平均性能」而非逐任务最差值，长尾任务可能掉更多；② 基准以对话/个人记忆为主，专业文档（规格书、版图注释）未覆盖；③ 数字作者自报。

3HiSA: Sparsifying the Hidden Dimension of RoPE Attention in LLMs

作者 / 机构Ambroise Borbely · Mathieu Salzmann · Olivier Verscheure（机构取自 arXiv 元数据，本轮未逐页核）
提交 / 更新2026-11-19（v1）
分类 + 标签cs.LG ｜ 借鉴 稀疏注意力 / RoPE / 预训练 / 解码成本
中文一句话不沿 token 轴做稀疏，而是沿隐藏维做：query / key 投影保持不变，只按 token 位置的静态、无参数规则把 RoPE 的 q/k 拆块，省略一部分点积。从零训练 LLM 时只计算约 1/3 的 query-key 乘积，效果不低于完整点积（作者称有提升）；推理时解码更快、显存更小，并给出 FlashAttention-3 的 kernel 实现；作者还展示了稠密注意力确实会学着压低被 HiSA 丢掉的那部分注意力分数（代码已开源）。
链接abs: 2611.26363 ｜ pdf ｜ 💻 github.com/ambroise-b/hisa
推荐理由：pretrain 线在长上下文上最贵的两项就是注意力的 q·k 与 KV 显存，本文给的是与 token 稀疏正交的另一根轴。可借三点：① 规则无参数、按位置静态 ⇒ 不引入额外路由网络，训练/推理同一套 mask，工程风险低于学习式稀疏；② 只算 1/3 q·k 是可预注册的成本目标；③ FlashAttention-3 kernel + 开源 让它比纯方法论文更容易试。
风险 / 边界：① 「效果不降」依赖从零训练，不能直接假定可对已训练 checkpoint 做后处理；② 省的是 q·k 计算，KV cache 的存储节省需看具体实现；③ 作者自报，未见第三方复现；④ 与 GQA / MLA 的叠加效果未知。

对各线的可执行建议（6 线）

  • pretrain：① 把 HiSA 作为「q·k 计算降为 1/3」的候选，先在 0.5B / 4K 上做同 token 预算对照（判据：验证 loss 不回退 + 解码吞吐提升 ≥1.3×，预注册）；② 训练日志固定记录通信占比（allreduce 时间 / step 时间），以 Horovod 的 ring 模型为分母口径。
  • vision：① SigLIP 2 的原生宽高比 + 多分辨率作为视觉塔候选，与我们现用塔在同一图文对上比零样本分类与定位；② 检测头加一组 Deformable DETR 式稀疏采样对照，只测小目标召回与收敛 epoch。
  • harness：① 记忆模块按「记录条数」与「检索上下文 token」两个预算分别报告，参照 MemFolder 的 50% 记录 / 99% 保留作为分档；② SFT 数据打包实验：样本是否携带 skill 前缀，作为单独消融（判据：六设置平均分，参照 AutoMaster 的 +1.42–8.99 pp 区间）。
  • data：① 对教师轨迹做「成功但含坏习惯」标注，先量比例再决定是否清洗（不要默认成功轨迹都可直接 SFT）；② 参考 SigLIP 2 的在线数据治理，记录去偏前后的配比变化。
  • zhulong：thinking 预算实验加一条 skill 前缀 变量（保留 / 移除），检验「行为内部化」是否在中文任务上复现；成本口径同时报 P50 与 P99。
  • designflow：把「漏检 / 误检」拆成两条评分轴（沿用 YOLO #294 的结论），并对稀疏采样检测头单独记录小目标召回，避免与整体 mAP 混在一起。
