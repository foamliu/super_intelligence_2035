1Toward Autonomous RTL and Synthesis Optimization: Benchmarking and Self-Improving Agents

中文一句话
把 RTL/综合优化拆成三条相连路线：①贴近真实 EDA 流程的参考式与开放式优化基准；②Dr. RTL 多智能体框架（关键路径分析 → RTL 改写 → 实现级评估，并把可复用的优化技能沉淀下来）；③面向具体设计的综合脚本调优与可执行综合算法发现。摘要称在 20 个真实 RTL 设计上，相对商用综合取得 WNS +21% / TNS +17%、面积 −6% 的平均改善。
原题
Toward Autonomous RTL and Synthesis Optimization: Benchmarking and Self-Improving Agents
作者 / 机构
Wenji Fang · Yao Lu · Jinghua Wang · Zhiyao Xie（arXiv 作者列表；机构本轮未从 PDF 核验，不以印象补）

链接
https://arxiv.org/abs/2611.13713
推荐理由（借鉴 · 与 designflow / zhulong / harness 直接对口）
  1. 「优化技能可复用」正是 agent 从一次性脚本变成资产的开关：摘要明确写了框架会持续通过 reusable optimization skills 自改进 —— 也就是把「某类关键路径该怎么改 RTL」沉淀成可检索、可复用的技能，而不是每次从零推理。我们的 ZhuLong 闭环同样在重复发现「某类时序违例该调哪一步」，可直接对照：技能以什么粒度存（改写模板 / 工具调用序列 / 检查清单）、怎么判定可复用、失败时怎么回滚。
  2. 它把 benchmark 与 agent 放在同一篇里，给了造题的现成骨架：reference-based（有参考实现，可判接近度）与 open-ended（无唯一答案，看好坏）两类基准，正好对应 designflow L1–L5 里「有 gold」与「只有判据」的两端。可复用的是协议：每类题怎么定义优化空间、怎么固定工具版本、怎么报告相对商用基线的差值。
  3. 数字口径清楚但不可外推：WNS/TNS 与面积都是相对商用综合的平均值，未给方差、未给设计规模分布。作为借鉴可以，作为「21% 提升」的结论不行。
建议动作：让 designflow 先复刻「reference-based vs open-ended」两套题面协议各 5 题（同一设计、同一工具版本），预注册判据：若 open-ended 题的评分者间一致性 <0.6，则该类题暂不进主榜，只作训练信号。

2TAPCO-G: LLM-Guided Design-Adaptive Timing and Power Co-Optimization with Graph-Based Physical Priors

中文一句话
布局后时序-功耗协同优化：外层用 LLM 依据物理设计反馈调工具设置，调参停滞时改写可执行修复策略；内层用图结构物理先验估计单元替换对端点 slack 与功耗的影响（锚定 STA 快照、计入上游驱动负载变化、把延迟变化传播到端点），再由粗到细筛选功耗。摘要称在 MLCAD 2026 Contest 的 8 个 ASAP7 基准上全部优于 CERBERUS，平均质量分 +5.516，比 TAPCO 平均高 21.648 分。
原题
TAPCO-G: LLM-Guided Design-Adaptive Timing and Power Co-Optimization with Graph-Based Physical Priors
作者 / 机构
Wuqian Tang · Zixiao Wang · Che-Chien Lin · et al（共 8 位，含 Bei Yu、Chun-Yao Wang；机构未从 PDF 核验）
日期
首次提交 2026-11-10（published=2026-11-10T11:19:50Z）· 距今 ≈53h（在 72h 内）
分类 / 标签
cs.AR · 借鉴 · 关键词：EDA / 时序 / 功耗 / LLM 调参 / 图先验 / 内外双环
链接
https://arxiv.org/abs/2611.13931
推荐理由（借鉴 · designflow / zhulong）
  1. 「LLM 只改规则，估计交给物理先验」是比「LLM 直接出动作」更稳的分工：摘要直说 LLM 单靠自己无法可靠估计一次 cell replacement 对端点 slack 与功耗的影响 ⇒ 所以让 LLM 调优化器的策略 / 工具设置，把「候选评估」交给图先验 + STA 快照。这与我们「LLM 提方案、工具给真值」的闭环同构，但把评估做成了可解释的代理模型。
  2. 外环停滞 → 改写可执行策略：这是明确的「失败触发重规划」机制，比固定轮数 retry 更像长任务控制流。可复用的是触发条件（调参多久算停滞）与改写对象（策略代码而非提示词）。
  3. 基线可比：同一 MLCAD 2026 Contest、同一 8 个 ASAP7 基准、对 CERBERUS 与 TAPCO 两个基线报告差值，比只报绝对值可信；但仍未给方差与显著性，不能当成稳定增益。
建议动作：designflow 选 2 个 ASAP7 设计，按「固定工具版本 + 固定评估脚本」复现 CERBERUS 基线；预注册判据：若本地复现分与论文差 >10%，先查工具版本与 PDK，不允许直接引用 +5.516。

3LM-SimBench: A Unified Framework, Dataset, and Benchmark for Large Language Model Training Simulation

中文一句话
把 LLM 训练模拟器的评估拆成「模型编译 → 调度聚合」的功能阶段，给出统一框架、剖析数据集与基准：在 Ascend NPU 集群上剖析 10 个稠密/MoE 模型家族的 23 个模型设置，得到 348 组可行配置（联合变化 5 个并行维度与激活重计算），提供 6 种粒度视图（configuration / rank / operator / event / kernel 等），并用 GPU-NPU 配对实验验证跨平台可用性。
原题
LM-SimBench: A Unified Framework, Dataset, and Benchmark for Large Language Model Training Simulation
作者 / 机构
Yu Dong · Hong Li · Qiang Sun · et al（共 7 位；机构未从 PDF 核验）
日期
首次提交 2026-11-10（published=2026-11-10T16:26:19Z）· 距今 ≈48h（在 72h 内）
分类 / 标签
cs.AI · 借鉴 · 关键词：训练模拟 / 并行策略 / 成本口径 / NPU / 数据集
链接
https://arxiv.org/abs/2611.14285
推荐理由（借鉴 · pretrain / harness / zhulong 的成本口径）
  1. 「先模拟再训练」正是我们最缺的一层：换并行策略要真跑才知道贵不贵，成本高到无法穷举。LM-SimBench 把模拟器的评估标准化（阶段分解 + 数据集 + 6 种粒度），让我们可以问更实用的问题：我们信哪一类模拟器的哪一类预测，而不是「哪个模拟器最好」。
  2. 它公开的是「可行配置」而不是「最优配置」：348 组配置联合变化 5 个并行维度 + 激活重计算，恰是我们做 2B 训练时要枚举的空间；可以拿它的视图字段直接对照我们的日志字段（是否记录了 rank / operator / kernel 粒度）。
  3. NPU 为主 + GPU 配对验证：若在国产卡上训练，这类跨平台验证比纯 GPU 论文更有参考价值；但摘要未给误差数值，不能据此判断模拟精度。
建议动作：pretrain 先做一张「2B / 8 卡 / 固定 token 预算」的并行策略表（TP×PP×DP 的 6–8 个候选），用任一模拟器预测吞吐，再实测 100 步；预注册判据：若预测与实测偏差 >15%，该模拟器只用于粗筛、不用于定预算。

中文一句话
面向 LLM 多智能体需求工程框架的开源基准基础设施，给出四个可复用部件：共享 run harness（统一输入 / 阶段产物 / 指标契约）、单适配器接入（框架只需实现一个 adapter，用例与指标不动）、可复现的 GitHub issue 挖掘管线、版本化用例集。演示：从 5 个项目（3 种语言、5 个领域）抓取 3,000 条 issue，沉淀 5 例 + 5 个手写例 = v1.0；三个异构框架（MARE、iReDev、QUARE）在同一协议下运行；随附 651 个测试、1,396 条过滤 issue 池、Docker 镜像与冻结 API 快照。

Haowei Cheng · Milhan Kim · Bowen Jiang · et al（共 8 位，含 Naoyasu Ubayashi、Hironori Washizaki；机构未从 PDF 核验）

推荐理由（借鉴 · harness / designflow 直接对口）
  1. 它把「harness」拆成了可验收的四件套：契约（输入 / 阶段产物 / 指标）、适配器边界、语料生产管线、版本化用例。我们 harness 线目前最容易糊掉的是适配器边界——每接一个新 agent/工具就改判分器。这里明确「框架只实现一个 adapter，用例与其它 adapter 不动」，可直接抄成我们的接入规范。
  2. 「语料从真实 issue 挖」是可复现造题的现成模板：抓取 → 过滤（3,000 → 1,396）→ 选例 → 打包 v1.0，每一步都留了数量与产物；designflow 的「需求 → 设计 → 验证」题面可照这个流水线做，但必须换成 EDA/存储项目的 issue 与规格文本。

建议动作：harness 线先写一页「adapter 契约」草案（输入 schema / 阶段产物 / 指标三项），拿现有 2 个 agent 做接入演练；预注册判据：若接入一个新 agent 需要改动 >1 个判分文件，则契约设计不通过，回炉重写。

5Sanity Checks for Attention Surgery: Null Models and Matched Interventions for Representation-Motivated Design

中文一句话
把「看内部表示 → 发现某统计量很大 → 架构上删掉它 → 报告变好」这条常见链路，拆成三条可复用检查：是否超过噪声底、是否过得了几何零模型、增益是否真需要被删的那个方向。以 self-attention removal（删掉与自身 value 向量对齐的注意力分量）为案例：9 个预训练模型、5,408 个 head（124M–6.9B），一个「更早位置的因果零模型」就能解释 48%–63% 的 head-value 余弦对齐；预注册 3 臂 × 8 种子（每 run 4.0×10⁸ token = 399,900,672）：固定任意秩一方向 +0.0011 nats（p=0.197，不显著），自指方向 −0.0029 nats（Holm 校正 p=0.0023），两者直接比较 −0.0040 nats（p=0.0018）。
原题
Sanity Checks for Attention Surgery: Null Models and Matched Interventions for Representation-Motivated Design
作者 / 机构
Basavaraj R M · Aryan Bharat Kumar（2 位；机构未从 PDF 核验）
日期
首次提交 2026-11-10（published=2026-11-10T04:06:26Z）· 距本轮 ≈71h（在 72h 内，接近窗口边缘，如实标注）
分类 / 标签
cs.LG · 借鉴 · 关键词：消融方法论 / 零模型 / 预注册 / 注意力干预 / 分半信度
链接
https://arxiv.org/abs/2611.13543
推荐理由（借鉴 · zhulong 消融设计 / pretrain 干预实验）
  1. 它给的是一套「消融怎么才算可信」的检查表，正好治我们最常见的毛病：看到一个统计量很大（比如某类 head 的余弦相似度高）就直接下「冗余/可删」的结论。三条检查可原样搬到 ZhuLong 的架构消融：噪声底、几何零模型、匹配干预。
  2. 「统计量可靠 ≠ 干预有效」被量化了：结构统计量的分半信度 >0.99，但干预效应的信度在 GPT-2 是 0.80、Pythia-160M 只有 0.42 ⇒ 同一个指标换模型就可能测不出来。这直接决定我们要跑多少种子、在什么规模上做预实验。
  3. 预注册 3 臂 × 8 种子、每 run 4.0×10⁸ token 的成本口径可参照；但它只到 6.9B 分析 / 50.9M 训练，不能外推到 2B 训练，且只有两位作者、未见会场 ⇒ 当方法论参考，不当结论引用。
建议动作：zhulong 下一轮架构消融先写「零模型 + 匹配干预 + 种子数」三行预注册，再开跑；判据：若某消融效应的分半信度 <0.6，则该结论只进「待复核」，不进决策表。
