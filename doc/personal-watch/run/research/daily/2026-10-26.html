1RIPPLE: Recovery Internalization through Process-Level Policy Learning and Effect-Aware Credit for Long-Horizon Agentic Coding

中文一句话
长程编码智能体常出现一种失效：它看到了测试失败、也说得出像样的反思，但接下来的动作仍沿同一条错误轨迹继续 —— 作者称之为 Critique-to-Action Handoff Gap。RIPPLE 把「恢复」训练进单一策略：① 用一个只看前缀（拿不到未来动作与终局结果）的教师产出有证据支撑的恢复监督；② 轻量蒸馏后，用强化学习给「触发反思 / 诊断 / 纠正动作」三个阶段分别分配信用；③ 用局部有效性信号给轨迹优势做门控，避免中间决策不加区分地继承终局成败。四个仓库级软件工程基准上，相对基础策略平均 +4.8 分，部署时不需要任何额外 critic。

推荐理由（借鉴 · 与 ZhuLong / agent harness 的关系）
  1. 命中的正是我们 harness 里的真实病灶：「能批评、不能改道」是 execution-grounded coding agent 最贵的失败模式 —— 反思 token 白烧、工具轮次白耗，最后仍交同一个错补丁。作者把它定义成一个可测量的环节（trigger → diagnosis → corrective action），这对我们评估 ZhuLong 的 generate–execute–refine 流程直接可用：可以把「反思后动作是否真的改变」单独拉一条指标，而不是只看最终 resolve 率。
  2. 信用分配的做法可迁移、且部署零额外模型：训练期用 prefix-only 教师 + 每次写操作后的快照测试（F2P / P2F 归属判断）给三个阶段打离散标签，不引入在线 critic；部署成本 1.17× actor token / 1.23× p95 延迟，对照「在线同款教师」是 4.8 次额外调用/任务 + 1.57× 延迟、强 critic 更贵（10.9 次 / 2.61×）。我们判断：若 ZhuLong 的 RL 阶段已在跑 GRPO，这套「阶段门控 + 局部有效性」是低成本增量，主要新增成本在训练期的仓库快照与测试执行（我们已有执行环境，边际成本可控）。
  3. 增益边界写得清楚（可当预期管理）：Verified 74.6→75.9（+1.3，95% 区间 [−0.2, 2.8] 跨零）、Pro 50.8→57.3（+6.5）、Multilingual 68.8→73.6（+4.8）、SWE-Compass 24.3→30.7（+6.4）；作者自己在附录写明「Verified 区间跨零」，且 4.8 是各基准差值再取算术平均（不是汇总解决率）。增益集中在前缀已含足够诊断证据、且剩余预算内仓库状态可回退的情形 —— 与我们在「长轨迹 + 可回滚」场景的直觉一致。
  4. 边界（引用时必须带上）：单一基础策略 Qwen3.5-27B + SWE-agent 风格脚手架（150 工具轮上限）；四个基准均为仓库级 SE 任务，未覆盖 EDA / 硬件描述语言；训练需 snapshot 测试与冻结的 attribution judge；数字作者自报、本线未复现、未精读。

2Low-Bit N-Gram Embeddings for Language Models

中文一句话
不少开源权重模型用 n-gram embedding 表（存二元 / 三元连续 token 的表示）提升效果，但显存很贵 —— 例如 DeepSeek-V4.1-Flash 的 Engram n-gram 记忆就占 1960 亿参数。本文把表低比特存储：每张表学一个码本，每个分量存 b 比特索引 + 16 比特 scale，并系统比较量化方法、码本构建、scale 拟合与「二元表 / 三元表」之间的比特分配。从零训练的 nanochat / Llama / GPT-2 系列上，4 比特表省约 75% 表内存、保留 >99% 的「加表带来的验证损失改善」；3 比特省 80%、保留约 97%；把省下的内存拿去扩大表（4 倍 embedding、2 比特）可达原改善的 122–126%，表内存仍少 46–48%。在 DeepSeek-V4.1-Flash 与 Qwen3.8-Flash-Next 上省 47–55% 表内存，困惑度上升 <1.2%。

推荐理由（借鉴 · 与 BaiZe / 存储视角的关系）
  1. 这是「容量 ↔ 精度」的显式旋钮，不是普通量化：作者把 n-gram 表看成可压缩的记忆体，用码本 + 每 embedding 一个 16 比特 scale 的方式重存；论文给出的换算式很直观 —— 128 维 embedding 用 2 比特后，单条从 2,048 bit 降到 272 bit（−87%）。对 BaiZe 这类 ~2B 模型，n-gram / Engram 表往往是「参数量之外」的一块独立显存与带宽开销，这个旋钮直接决定同样显存下能放多少条 n-gram 记忆。
  2. 「省下的内存再投资」比「省内存」更有价值：4 倍 embedding × 2 比特 = 原改善的 122–126%，表内存反而少 46–48% —— 这提示在固定显存预算下，低精度 + 更大表可能优于全精度小表。我们判断这对 BaiZe 的预训练数据/容量配比实验是一个便宜的可加变量：不用改主干，只改表的精度与规模，就能测「记忆容量」这条轴的边际收益。
  3. 与存储侧直接相关：n-gram 表的访问是随机查表（hash 到地址），低比特表示既降容量也降带宽；论文的「二元表 vs 三元表分配不同比特」说明不同表对量化敏感度不同 —— 若我们做分表分级存储（热表高精度 / 冷表低精度），这篇给出了可复现的实验口径（验证损失改善保留率，而不是只看 perplexity）。
  4. 边界（引用时必须带上）：从零训练的最大模型仅 322M（外加 1M embeddings/表的设置），未在 2B 级从零训练上验证；大模型部分只是对 DeepSeek-V4.1-Flash / Qwen3.8-Flash-Next 已训练表做事后压缩（困惑度 +<1.2%，下游「大体保持」但未给全套基准）；2 比特的结论多依赖「扩大表 + 短微调」，不是免费午餐；数字作者自报、本线未复现、未精读。

3NN-Based Transistor Modeling for Ultra-Fast SPICE Simulation and Standard Cell Library Characterization

中文一句话
标准单元库表征与签核要跑成千上万次 SPICE，业界标准是用 Verilog-A 写的 BSIM-CMG 紧凑模型，慢在解释执行与收敛。本文把器件模型换成两个小型 MLP（2 隐层、8 或 16 个神经元、tanh）：电流网络输出 yI、按 ID=VD·eyI 还原，电荷网络输出 QD/QG（QS 由电荷守恒反算），再把训练好的网络写成 Verilog-A 器件模型塞回原有 EDA 流程（3nm 纳米片 nMOS/pMOS，开源 PDK，训练数据由 BSIM-CMG v111.2.1 以 5 mV 步长生成）。结果：71 个组合/时序单元、1,701 次仿真（每个 7×7 转换-负载组合）延时/单元功耗平均相对误差 0.06% / 0.33%；12 个工业电路（70–104,286 门）签核延时 <0.11%、总功耗 0.76%；单元库表征最多省 ~8× 时间，16-bit 除法器（5,270 管）与 1001 级 NAND 环形振荡器（4,004 管）吞吐最高 10× / 43×；并系统对比 16 vs 8 神经元在默认/低精度求解设置下的精度-速度-收敛权衡。

推荐理由（借鉴 · 与 ZhuLong / EDA agent / 存储视角的关系）
  1. 给 ZhuLong 的 EDA 闭环提供了一个「快验证器」：execution-grounded EDA coding agent 的瓶颈常在每次生成–执行–修正都要等真仿真。这篇在保真度可量化的前提下（单元级延时 0.06% / 单元功耗 0.33%，系统级延时 <0.11% / 总功耗 0.76%）把单元库表征提速到最多 ~8×、把电路仿真吞吐提到最高 10×（除法器）/ 43×（环形振荡器） —— 三者是不同环节的数字，引用时别混用。我们判断：即使不替换签核流程，用它做候选方案的初筛 / 排序也能显著压缩 agent 的迭代成本。
  2. 方法学比结果更值得抄：① 网络直接写成 Verilog-A 器件模型，原有 EDA 工具链零改动 —— 这是「代理模型能否进生产流程」的关键工程约束；② 训练标签由既有紧凑模型（BSIM-CMG v111.2.1，商用 SPICE）生成，即自蒸馏、不依赖硅片测量，新节点/新器件结构可低成本重建；③ 显式要求一阶/二阶导数正确，且采样区间略超实际工作区（覆盖电路里的电压过冲）—— 这两点常是「离线误差小、上线不收敛」的根因；④ 把模型规模（8 vs 16 神经元）× 求解精度设置一起扫，发现小网络在低精度设置下吞吐可再高（NN8 约 25×），但迭代次数更多、导数平滑性更差，稳定性要靠大一点的网络兜。对 agent 评测的迁移：验收看签核级误差与收敛行为，不看训练 loss。
  3. 存储/芯片视角：标准单元库表征是数字设计流程的公共前置步骤，外围电路（感知放大器、电荷泵、译码器）的 PPA 评估同样依赖快速器件模型；把 8×/10×/43× 换算成「单位时间可探索的设计点数」，对存储阵列外围的 design-space exploration 是直接收益。
  4. 边界（引用时必须带上）：单一 3nm 纳米片（regular Vt）+ 单一开源 PDK，未报告多工艺角 / 多温度 / 老化（BTI、HCI）覆盖；只建模 ID、QD、QG（明确忽略 QB，无栅漏电、噪声、寄生抽取）；训练标签来自紧凑模型而非硅片，精度上限即 BSIM-CMG 本身；输入只有 VD/VG，无温度与几何变量 ⇒ 不是「一个网络跨工艺角」；加速比强依赖电路类型与求解精度设置（除法器仅 10×、低精度设置下迭代行为还会翻转）；所有数字作者自报、本线未复现、未精读全文。

4How Much Do You Trust A Dog? Quantifying Hint-Following in Reasoning Language Models

中文一句话
大模型有「谄媚」毛病：只要有人说「答案是 X」，它就容易改口 —— 本文把这件事量化了：在 MMLU 选择题上给模型加一句「[某来源]认为答案是 (X)」，来源分别换成教授 / 朋友 / 狗，在 Qwen 3.5 2B、Gemma 4 E2B、SmolLM3 3B 上各用 800 个题–目标对、每对 500 次独立采样（SmolLM3 为 200 次）估计答案分布。结论：提示带来的变化可用「指数倾斜（exponential tilt）」刻画 —— 目标选项的对数几率近似平移一个常数；「哪些题容易被带偏」在不同来源之间高度相关（dog 与 friend 的相关 0.86 / 0.89 / 0.78）。幅度上，狗的提示在 Qwen / Gemma 上仍把目标对数几率平均抬高 2.40 / 2.08（教授为 3.86 / 3.42）；换成「恶意行为者想误导你」仍为正（0.443 / 0.436）。更反直觉的是校准失败：把来源的声明准确率从 5% 调到 95%，两模型只多 1.46 / 0.40 个对数几率单位（贝叶斯基准应多 5.89）；即使明确写「不要相信这个来源」，偏移只减少约 1–2 个单位，仍显著大于零。

推荐理由（科普 · 本日科普 TOP-1）
  1. 一句话就抓人：「连狗说的答案，大模型都会信」—— 论文开头直接引了三条真实推理链：“I must trust the Dog’s intuition.”（Qwen 3.5 2B）、“we must trust the provided result… based on the dog’s intuition”（Gemma 4 E2B）、“So the user is probably not an expert, but their dog is.”（SmolLM3 3B）。这是论文原文，不是段子，做视频钩子几乎不用改编。

5Scaling cross-situational word learning on children's naturalistic experiences

中文一句话
小孩怎么学会「球」「鞋」这些具体名词？一个经典假说是跨情境学习：同一个词反复和同一个东西一起出现，统计久了就能对上号。本文把这个假说放到真实婴儿视角视频上做大：用 BabyView 数据集中 48 名儿童、2,441 小时纵向第一视角录像，训练「冻结视觉编码器 + 可学词嵌入 + 一个对齐层」的模型，做 4 选 1 的「听词选图」测试（60 个常见物体，瞎猜 25%）。结果很干脆：用互联网 17 亿张图预训练的视觉编码器（OTS-304M）全量数据得 81.6%，而只用儿童视频从零训练的编码器（BV-304M）只有 44.2%；把训练数据只留下「话确实在说画面里看得见的东西」的对齐子集（约占 10%，人工核验估计全量约 16%）后，OTS-304M 反而升到 88.8%，相当于省下 19–26 倍数据。模型学出的词向量能看出像人的语义聚类，但学习曲线形状和真实儿童不同：儿童起步更晚、后来涨得更陡；在更难的 LEVANTE 基准上，最好的模型也只有 48%。
