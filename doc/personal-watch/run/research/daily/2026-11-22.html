1SheetAlign: Grounded Interaction and Stage-Isolated Learning for Spreadsheet Agents

作者 / 机构Yuxiang Wang · Junhao Gan · Jianzhong Qi（共 3 位；机构取自 arXiv 元数据，本轮未逐页核）
提交 / 更新2026-11-19（v1，UTC 13:13:12Z）
分类 + 标签cs.CL ｜ 借鉴 表格 agent / 工具接地 / 分阶段训练 / 执行一致性
中文一句话把表格操作拆成「在哪操作 → 改什么 → 怎么实现」三段，先让模型看一眼工作簿再做 API 接地，再用编辑进度奖励分阶段训练生成与复核，推理时用多程序执行后工作簿状态的一致性选程序。SpreadsheetBench 上，仅换「接地后的任务接口」就让 Qwen3-4B 从 13.5% 提到 29.2%（不训练）；加训练与执行一致性后达 32.8%，Domain-Spreadsheet 上 30.1%（作者自报）。
链接abs: 2611.26069 ｜ pdf
推荐理由：我们的 harness 里「工具调用失败」有很大一块不是模型不会写代码，而是没看清状态就动手。可借三点：① 先观测后生成的两段式（task-guided inspection + API grounding）不需要训练，可直接当 prompt / 工具层改造，+15.7 pp 是不训练就能拿的量级参照；② 按阶段隔离训练（生成 / 复核分开）比端到端更易定位退化，适合我们已经在跑的多阶段流水线；③ 用执行结果一致性投票替代多数投票，判分信号来自环境而非模型自评，cost/benefit 更可控。
风险 / 边界：① 只在 4B 级开源模型上验证，未给 30B+ 或闭源强模型曲线；② 表格任务的可执行验证天然容易，版图 / 规格书类任务的状态比对更贵，迁移收益未测；③ 数字作者自报，无第三方复现；④ 代码「录用后公开」⇒ 当前不可复现。

2RL Can Only Reinforce What It Sees Succeed

作者 / 机构Ruben Sanchez-Corcuera · Unai Zulaika · Aritz Bilbao-Jayo（et al.，共 4 位；机构取自 arXiv 元数据，本轮未逐页核）
提交 / 更新2026-11-19（v1，UTC 13:24:40Z）
分类 + 标签cs.LG ｜ 借鉴 强化学习 / GRPO / 稀疏奖励 / 后训练稳定性
中文一句话在「先验与正确答案都已知」的谜题世界里从零训小模型，发现结果奖励 RL 只能强化它采样到过的成功：正确动作稀少时，每条 run 要么全学会要么完全学不会，而哪条 run 会起飞可在训练前用一个计数预测——「动作获胜的尝试组数」；约 35 组时胜负各半，该计数在 4–256 次尝试的组、不同学习率 / 优化器 / GRPO 变体与 1.3M–85M 参数上成立（只移动阈值，不改变「数什么」）（作者自报）。
链接abs: 2611.26084 ｜ pdf
推荐理由：我们做 RL 后训练最常踩的坑是「跑了一次不涨就换超参」，而这篇给的是训练前可算的判据。可借三点：① 把「成功样本组数」做成开跑前的一次性统计（我们离线数据上就能数），低于阈值就先加采样 / 改课程，而不是调 lr；② 「rare success ⇒ 全或无」解释了为什么同一配方在不同种子下方差巨大 ⇒ 预注册时必须报多条 run 的分布而非单次最好；③ 结论跨 1.3M–85M 稳定，可先在 2B 以下的代理模型上定阈值，再迁到主模型。
风险 / 边界：① 环境是合成谜题世界（先验可控），真实任务的奖励噪声与多解会让「组数」难以界定；② 只测结果奖励 RL，未覆盖过程奖励 / 偏好学习；③ 阈值 35 是特定任务族的经验值，不可直接照搬到我们的题池；④ 作者自报。

3dLoop: Looped Diffusion Language Models via Recurrent Latent Refinement

作者 / 机构Handa Li · Pengxiang Li · Mingyu Cao（et al.，共 7 位；机构取自 arXiv 元数据，本轮未逐页核）
提交 / 更新2026-11-19（v1）
分类 + 标签cs.CL ｜ 借鉴 扩散语言模型 / 并行解码 / 循环深度 / 推理成本
中文一句话扩散语言模型每步只有一部分位置「够可靠」才敢提交，瓶颈在单次前向里信息没整合完；dLoop 把预训练 DLM 改造成 Prelude–Loop–Coda 结构，对同一个部分掩码状态循环复用一块参数共享的中间层，用额外循环换潜空间计算（而非推进去噪步）。GSM8K / MATH / MBPP / HumanEval 上取得最高或并列最高准确率，且在按循环计算折算的 tokens-per-forward 口径下同时优于 Fast-dLLM（四项）与 dParallel（三项）（作者自报）。
链接abs: 2611.26275 ｜ pdf
推荐理由：我们在 zhulong 上关心的是每 token 成本，而「并行解码」类的加速经常靠降置信度阈值，代价是质量；本文给的是另一根轴：在提交前多算几次潜变量。可借三点：① 参数共享的循环块只增加计算不增加参数量，是「用算力换质量」的可控旋钮，适合放在成本分档里；② TPF 折算这个口径值得照搬——比较解码加速必须把额外计算算进去，否则数字不可比；③ 只改结构不改预训练目标，理论上可在现有 DLM checkpoint 上做最小改造。
风险 / 边界：① 只覆盖四个推理 / 代码基准，长文生成与多语未测；② 「DP 加速」的对手选择有限，未与自回归 + 投机解码做同成本对比；③ 循环次数与质量的曲线需读正文，摘要未给拐点；④ 作者自报。

00:00 时窗 · 对各线的可执行建议（6 线）

  • pretrain：把 RL 侧的「成功组数」判据做成开跑前检查项——在现有离线题池上先数「至少有一次采样成功的尝试组数」，低于 ~35 组就先加采样或改课程，再谈超参；判据：同一配方连跑 3 个种子，若成功率分布跨 0 与 1 两极化即判「信号不足」，禁止据单次最好结果立项。
  • vision：视觉塔选型表新增两列 「见到的样本数」与「增强策略」，与参数量并列；判据：任一新塔必须给出「同参数量、不同样本数」的对照，缺该对照的结论不写入选型结论。
  • harness：照 SheetAlign 的两段式改工具层——先让 agent 读一次环境状态再生成调用（不改训练）；判据：在固定 50 题子集上做 A/B，若工具调用失败率不降 ≥5 pp 则回退，避免把「模型能力」与「接口设计」混为一谈。
  • data：启动「纯网页 vs 混合策展」小规模对照臂（同 token 预算、同去重规则），把去重率与过滤阈值记为超参；判据：对照差距 <1% 时，后续统一走网页数据路线并停掉高成本策展。
  • zhulong：所有解码 / 生成加速数字一律折算成 tokens-per-forward 或「每样本 GPU·s」后再比较（按 dLoop 的 TPF 口径）；判据：报告缺折算口径的加速比不予采纳。
  • designflow：造题时把「阶段」显式建模（在哪操作 / 改什么 / 怎么实现），每阶段单独给分；判据：任一题目若无法把三阶段拆开判分，则降级为参考题、不进正式集。
