1CAMP: Context-Aware Mapping and Placement for LLMs on 3D-IMC Arrays

中文一句话
大模型推理受限于把大权重矩阵和 KV cache 反复搬进内存的开销。模拟内存计算（AIMC）把计算直接放在静态权重所在的存储阵列上，能大幅降能耗与延迟；3D-IMC 再把存储阵列垂直叠成多层以提升容量，但引出新问题：权重怎么摆进存储层，决定了哪些矩阵-向量乘（MVM）能并行执行，进而影响延迟与吞吐，而 3D-IMC 的权重映射「并发性」此前研究不足、算力利用率偏低。作者提出 CAMP（上下文感知映射与放置）：用一张「冲突矩阵」把架构、目标网络与运行时上下文造成的资源争用刻画出来，据此做吞吐最优的权重映射，再用基于 profiling 的反馈环剪枝搜索空间、在可用时间内返回优化映射。CAMP 是离线、纯软件方案、不需改硬件；把 3D-IMC 算力利用率从 42.4% 提到 60.3%，相对 SOTA 映射最高 2.0× 的 IMC 吞吐、1.74× 的端到端吞吐。

推荐理由（借鉴 · 与长鑫存储视角 / BaiZe·ZhuLong 的关系）
  1. 正对「存算一体 + 内存层级」这条存储侧主线：我们关注的不只是「模型跑多快」，而是权重与 KV 放在哪一层存储、怎么放、能并行取多少。本文把「权重摆放 → 哪些 MVM 可并发 → 吞吐/延迟」这条链路显式建模成冲突矩阵，是「存储布局直接决定算力利用率」的一个可读样本。
  2. 硬数字可回查（摘要）：3D-IMC 算力利用率 42.4% → 60.3%；相对 SOTA 映射算法最高 2.0× IMC 吞吐、1.74× 端到端吞吐。它给出的核心量是「放置算法」本身的增益（不改硬件），正好对应「同一套存储阵列，换一种数据摆放能多榨出多少算力」。

  4. 口径要点：AIMC（模拟内存计算）的增益本质是「计算贴着存储做、免去数据搬运」，与数字 SRAM/DRAM 的工程口径不同；本文结论建立在 3D-IMC 模拟器上，不是实测芯片。
  5. 边界（必须写清）：① 全部为仿真结果（3D-IMC 模拟器 + profiler），无流片实测；② 针对「权重静态驻留、适合 MVM」的推理负载，不覆盖训练；③ 收益依赖具体网络结构、batch 与上下文，换个模型/上下文需重跑映射；④ 作者自报、本线未复现。

2StrataFlux: Memory-Hierarchy-Native Low-Bit LLM Inference

中文一句话
量化能降低 LLM 推理的显存与带宽需求，但会掉精度；而把高精度数据放到外部、需要时再取回，又会让生成卡顿。StrataFlux 挑战这个权衡：在保留量化省显存/加速优点的同时，把低比特权重与 KV cache 量化损失掉的精度补回来 —— 它把「细化精度」的表示、选择与投递三者协同设计，让主机内存（RAM）与固态硬盘（SSD）成为额外精度的可用来源；选择性精度流式加载减少传输量、把加载与计算重叠、并在多个解码步之间复用已取回的精度，使生成不必等每一次传输。评测覆盖 2–4 bit 权重、2–3 bit KV（独立 GPU 与统一内存平台）：2-bit Llama-3.1-8B-Instruct 把 WikiText-2 困惑度从 9.46 降到 8.40，同时在 RTX 5090 上保持量化版 95.4% 的吞吐；2-bit 权重 + KV 让 Qwen3-8B 的 AIME 2024/2025 从 11.0% 提到 47.1%，GPU 显存占用不变；128K 上下文下，3-bit 权重 + 2-bit KV 的 Llama-3.1-8B-Instruct 在 RTX 5090 上困惑度与速度接近 vLLM 的 4-bit AWQ + 8-bit KV，而显存约用一半。

推荐理由（借鉴 · 与长鑫存储视角 / BaiZe·ZhuLong 的关系）
  1. 把「存储层级」直接变成「精度预算」：传统做法是「量化到低比特，认掉精度损失」或「offload 到内存/SSD，认掉延迟」。本文的核心观点是把 RAM / SSD 当成「可回收的精度来源」——不是把整层搬回来，而是选择性地流式取回少量高精度数据、与计算重叠、并跨解码步复用。这正是存储系统（长鑫视角）与推理引擎的交叉点：外存带宽/层次能不能被「用对地方」。
  2. 硬数字可回查（摘要）：2-bit Llama-3.1-8B-Instruct，WikiText-2 困惑度 9.46 → 8.40，RTX 5090 上保持量化版 95.4% 吞吐；2-bit 权重+KV 让 Qwen3-8B 的 AIME 2024/2025 11.0% → 47.1%（GPU 显存不变）；128K 上下文用 3-bit 权重 + 2-bit KV 追平 vLLM 4-bit AWQ + 8-bit KV 的质量与速度、显存约减半。这些是「低比特 + 外存补精度」可直接对标的量。
  3. 对 BaiZe / ZhuLong 的实际可用点：① 我们若已上量化推理，本文给出「什么时候量化掉的那点精度值得用外存补回来」的判断框架；② 「选择性精度流式 + 跨步复用」是一条不重训的精度回收路径，可用于对精度敏感的评测/关键任务；③ 与 vLLM/AWQ 的直接对照，便于我们横向比较。
  4. 口径要点：这是「用外存换精度、但要隐藏其延迟」的思路，收益强依赖外存带宽、预取与计算重叠的工程质量；「显存占用不变」「显存约减半」都是在特定硬件（RTX 5090 / 统一内存平台）测得。
  5. 边界（必须写清）：① 主要在单机 GPU / 统一内存平台评测，未覆盖大规模多卡服务与国产加速器；② 依赖对特定推理栈/加速库的适配（流式加载、kernel 融合）；③ 精度回收靠「选哪些数据补精度」的启发式，极端分布下未验证；④ 作者自报、本线未复现。

3Beyond K/V Caches: Cross-Model State Handoff in Hybrid Linear-Attention LLMs

中文一句话
生产部署常用不同模型来平衡成本与质量（级联、路由、长对话中切换模型），上下文跨轮累积，每次切换都要让目标模型对这段上下文重跑 prefill。已有方法只迁移全注意力（FA）的 K/V cache；而混合线性注意力模型还保留循环状态（REC）与卷积历史（Conv），Conv 与 REC 的交互使跨模型状态转移变复杂：Conv 扰动量会改变循环层里的 key/value 并影响 REC 更新；conv 历史可被覆盖，但 REC 的变化仍会影响后续输出，而且更精确地重建 REC 不一定带来更好的续写。作者提出 HST（Hybrid State Transfer）处理 FA/REC/Conv 三类状态：用结构化 REC 映射、Conv 对齐时保留历史顺序、以冻结目标模型的输出校准适配器、离线合入 FA cache 映射。在 5 个基准上，Qwen3.5 4B→27B、9B→27B 的平均任务保留率分别 89.88%、94.11%；在源 cache 已就绪时，16K 合成输入上「交接主体」加速 21.66×、21.91×。

推荐理由（借鉴 · 与 BaiZe / ZhuLong 的关系）
  1. 正对「多模型服务 + 长对话」的真实成本点：生产里常见「小模型起手、难问题切大模型 / 长对话中途换模型」的级联与路由。默认做法是切换后让目标模型把整段上下文重跑一遍 prefill，这是长上下文服务里最贵的一段。本文要省的就是这段 prefill。
  2. 点出了一个被忽视的难点：当模型是混合线性注意力（部分层是线性注意力/循环）时，光搬 K/V cache 不够，还要搬 REC 循环状态 + Conv 卷积历史，而且三者的耦合会让「精确重建」≠「续写更好」。这条「状态搬得准 ≠ 生成得好」是需要实验校准（用冻结目标模型输出对齐）才能发现的坑。
  3. 硬数字可回查（摘要）：5 个基准上，Qwen3.5 4B→27B / 9B→27B 平均任务保留率 89.88% / 94.11%；源 cache 已就绪时，16K 合成输入上交接主体加速 21.66× / 21.91×。注意加速的前提是「源模型 cache 已经算好」，省的是目标模型的重算，不是总预算。
  4. 对 BaiZe / ZhuLong 的可用点：① 若我们的服务用了级联/路由或长对话中换模型，本文给出一份「切换时该搬哪些状态、怎么校准」的清单；② 「用冻结目标输出校准适配器」是一个低风险的工程手段（不动权重）；③ 对混合线性注意力架构的支持是相比「只搬 FA K/V」旧方法的关键增量。
  5. 边界（必须写清）：① 收益以「源模型 cache 已就绪」为前提，端到端节省要看源/目标分工；② 只在 Qwen3.5 家族（同家族不同规模）上验证，跨家族/跨架构迁移未充分验证；③ 任务保留率 <100%（89.88% / 94.11%）说明切换有损，精度敏感任务需评估；④ 作者自报、本线未复现。
