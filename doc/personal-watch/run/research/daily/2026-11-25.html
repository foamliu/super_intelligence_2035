1 · Unlocking the Power of Loops in Pretrained LLMs with Loop Residuals

原题Unlocking the Power of Loops in Pretrained LLMs with Loop Residuals
中文一句话不改预训练权重，把「循环复用同一组层」从只涨一点点的 SFT 微调变成稳定大幅增益：让每层直接注意更早各轮输出，并只保留最近 W 轮的残差窗口；2× 算力下 Qwen3-1.7B-Base 比 SFT 高 29.1%。
作者 / 机构Xuanlei Zhao · Hailun Xu · Kai Wang（等；摘要区未列机构）
提交 / 更新2026-11-23（arXiv v1；citation_date = 2026/11/23）
分类 + 标签cs.CL（primary；另 cs.LG）｜ 🏷 借鉴（pretrain 架构 / posttrain 测试期算力）
链接arXiv:2611.31094
推荐理由它把「循环深度」的失败原因说清楚了：同一组层的多轮输出越来越像，普通残差无法区分，于是循环几乎等价于重复计算。LoopRes 的两个具体旋钮可搬到我们的小模型上：① loop-aware key——给每一轮一个可训练的结构身份，让注意力能分辨「这是第几轮」；② 残差窗口 W——只允许注意最近 W 轮，强制逐轮增量而不是全部混在一起。证据面也够：6 个预训练模型 / 3 个模型族 / 9 个基准，2× 算力下 Qwen3-1.7B-Base 比 SFT 高 29.1%、称超过 SOTA 基线增益两倍；1.7B→8B 随算力增长比 SFT 更陡，最大验证到 30B。⚠️ 所有数字为作者自报，本线未复现；「更高天花板」属其外推结论。

2 · Precision-Aware Learning Rate Transfer Across Block Count in LLM Post-Training

原题Precision-Aware Learning Rate Transfer Across Block Count in LLM Post-Training
中文一句话只训最后 k₀ 个 block（通常 k₀=1）搜学习率，再用随精度变化的缩放律推全模型最优学习率：FP32 主权重约按 k⁻¹，BF16 直接更新约按 k⁻¹ᐟ²；6.7B 上可在单张 16 GiB 消费卡上完成搜索。
作者 / 机构Nan Chen · Soledad Villar · Soufiane Hayou（等；摘要区未列机构）
提交 / 更新2026-11-23（arXiv v1；citation_date = 2026/11/23）
分类 + 标签cs.LG（primary；另 cs.CL）｜ 🏷 借鉴（posttrain / pretrain 调参成本）
链接arXiv:2611.31166
推荐理由直接服务我们「SFT → DPO → RLVR 每步都要重调 LR」的痛点。做法是先只在末 k₀ 个 block 上网格搜，再按 block 数 k 外推；关键的工程细节是缩放指数取决于精度：有 FP32 master weights 时约 k⁻¹，直接更新 BF16 权重（无 master copy）时约 k⁻¹ᐟ²，并用考虑更新舍入的解析模型解释两者。落地价值是成本：6.7B 模型两套原型——一套塞进 16 GiB 单卡，另一套在一次数据遍历里并行评估所有候选，使 5 候选搜索约为一次全深度（k=L）训练 GPU 时的一半。可拿来做「换 block 数 / 换精度后 LR 该乘多少」的预注册规则。范围仅 1–7B，30B 以上未验。

4 · CO-GRAFT: Attributing Reinforcement Learning Gains in Search Agents via Role-Level Policy Grafting

原题CO-GRAFT: Attributing Reinforcement Learning Gains in Search Agents via Role-Level Policy Grafting
中文一句话把 RL 训练后的搜索 agent 与 RL 前初始化拼成同一条实时检索轨迹，按四种功能角色做 2⁴=16 种干预指派，用 Shapley 值分解 RL 总增益；作者实测「查询生成」只占 ≤15%，增益主要由 RL 前答案有效率、检索保留率、模型规模与固定检索预算决定。
作者 / 机构Ramraj Chandradevan · Sayontan Ghosh · Vinoth Selvendran（摘要区未列机构）
提交 / 更新2026-11-23（arXiv v1；citation_date = 2026/11/23）
分类 + 标签cs.IR（primary）｜ 🏷 借鉴（posttrain RL 归因 / harness 实验设计）
链接arXiv:2611.31185
推荐理由我们的 RLVR 目前只报总通过率，答不出「哪一步、哪种能力在涨」。CO-GRAFT 给了一个不重训就能做的干预归因：四个互斥角色（中间推理 / 搜索或作答决策 / 查询生成 / 最终答案抽取），枚举全部 2⁴=16 种角色指派，且不修改权重、不重训；16 个混合策略构成合作博弈，用 Shapley 值分摊总增益，再用 Möbius 交互项区分「单角色独立提升」与「多角色耦合」。覆盖 Search-R1 agent × Qwen2.5 / Llama-3.2 × 两个规模 × base / instruct × GRPO / PPO × NQ / HotpotQA。可直接搬来的教训：上大算力 RL 前先量 RL 前的答案有效率与检索保留率——它们决定了增益天花板；大模型 / 答案格式好的 checkpoint 会把功劳从推理挪到答案抽取，小 base 模型则依赖「推理–决策耦合」。⚠️ 32 EM 点是其设定下的作者自报，本线未复现。

5 · Attention Temperature Confounds Zero-Shot Context Extension

原题Attention Temperature Confounds Zero-Shot Context Extension
中文一句话零样本上下文扩展的「提升」可能只是注意力温度失校准：在默认 τ=1 下比较时，基线本身在训练长度之外失校准；按模型与长度各校准一个温度后，块稀疏注意力 / attention dropout / ALiBi 的多数优势消失，ALiBi 反而落后 RoPE 5%。
作者 / 机构Ruben Navasardyan（单作者；摘要区未列机构）
提交 / 更新2026-11-23（arXiv v1；citation_date = 2026/11/23）
分类 + 标签cs.LG（primary）｜ 🏷 借鉴（pretrain 长上下文评测口径）
链接arXiv:2611.31113
推荐理由它直接质疑我们评测长上下文扩展时的默认做法。核心量是基线在训练长度外的失校准程度（logits 被一个标量锐化后能恢复多少困惑度）。证据：3 对 seed 配对的 365M twins 里，8k 训练基線在 30k 处失校准 8–15%，其中一对让块稀疏 twin 看起来好 7%，校准后归零。更狠的是纯 bf16（无 master weights）：AdamW（β₂=0.95）在峰值学习率 <1.7×10⁻³ 时对初始为 1.0 的 gain 的单步更新不到半个 bf16 spacing ⇒ gain 根本不动（22 个 checkpoint），基线失校准 37–58%，块稀疏 / attention dropout / ALiBi 看起来好 6–35%；逐模型逐长度校准一个温度后三者优势全消，ALiBi 反而落后 RoPE 5%，只保留 NTK-aware scaling 正控制的一部分增益；解冻 gain 后 365M 处块稀疏优势反转、1.2B 处被削掉 71–89%。可落地规则：长上下文结果必须在校准温度下报，并检查 normalization gain 是否真的移动了。⚠️ 单作者、规模到 1.2B，作者自报。

vision视觉编码器容量与融合的对照（1312.6114）：VAE 的 encoder-decoder 隐变量结构可作「专用视觉容量 vs 通用主干」的最小生成式对照基线；工具链可演化（2611.31198）：视觉取证工具先做「基础库 + 自动生成」两档，域内 1 项 + 域外 1 项。无其它可执行视觉建议（不凑数）。
harnessRL 增益按角色分解入回归（2611.31185）：固定 RL 前后两个策略，枚举 16 种角色指派（推理 / 搜索或作答决策 / 查询生成 / 答案抽取），报 Shapley 分摊；先单列「RL 前答案有效率 + 检索保留率」两个天花板指标。可执行判分优先（2211.10435）：程序化中间步骤由解释器执行判分，LLM 评审只作辅助，并锁 judge 版本 / prompt / 温度。
data1T token 量级配方对照（2401.02385）：把 token 数 × epoch × 模型规模写成三列，复测时不得只报 token 数；程序化轨迹配比（2211.10435）：SFT 数据里「自然语言分解 + 可执行程序」必须成对，缺执行结果的样本单列，不与可执行样本混算通过率。
zhulong成本表加「调参搜索成本」与「词表/分词成本」（2611.31166 / 1310.4546）：LR 搜索候选数 × block 数 × GPU 时、词表训练时间与有效 token 变化单列；1T token 级训练预算（2401.02385）作小模型成本标尺。
designflow「可执行中间步骤」写进题型（2211.10435）：判分优先用程序 / 解释器执行结果，而不是最终自然语言答案；单列「解释器失败」「外部工具不可用」两类 infra 错误，不计入能力失败。短语与定长压缩两个失败模式（1310.4546 / 1406.1078）继续保留。
