1A Scaling Theory of Multi-Epoch Pretraining: Late-Time Overfitting and Ensembling

中文一句话
未来预训练会先被数据总量卡住，而不是算力。固定数据反复训多轮时，验证损失先降后升：作者在 10–100M 唯一 FineWeb token 的小模型上复现 U 形曲线（最优约 9–14 轮后回升），并用 logit 平均（独立训练模型的集成）削弱晚期过拟合、推迟最优停止；在匹配参数–token 预算下，4 个基座模型的集成比「宽度翻倍」的单模型验证损失低 0.16 nats。理论上给出 power-law 随机特征集成的多轮 SGD 的 DMFT（跟踪轮内 / 跨轮 / 跨成员误差相关），并导出固定数据与单模型规模下的算力分配律：集成规模随算力增长至少不慢于单成员训练时长，超出极限损失的余量按算力幂律下降。

推荐理由（借鉴 · 与 BaiZe / ZhuLong 的关系）
  1. 直击「数据墙 / 多轮回放」这条主线：若高质量唯一 token 的增长慢于算力，多轮训练是必选项。论文回答的正是「该训几轮、什么时候停、剩下的算力买集成还是买更久训练」—— 这三问对 BaiZe 的数据配比与训练预算规划是直接可用的决策变量。
  2. 硬数字可回查：① 10–100M 唯一 FineWeb token 上，最优约 9–14 轮后验证损失回升；② 匹配算力下 E=4 集成比 2× 宽单模型低 0.16 nats（Figure 2B；Appendix A.2）；③ 分配律：集成规模随算力增长至少不慢于单成员训练时长，余量按幂律下降。这些都能直接变成我们 scaling 实验的对照臂。
  3. 实验成本低、适合先做小规模验证：作者用的是 L12/W768 级别的模型（Figure 1 最大约 679M 非嵌入参数）与单张 H100，每配置跑一次；我们可以先在自有 0.5B 级模型上复现「U 形 + 集成推迟停止」，再决定是否进大模型配方。
  4. 与既有 BaiZe 规模律工作的接口清楚：把 epochs 作为独立的预算维度，与「模型宽/深」「唯一 token 数」一起做三维扫描；论文给的是「固定数据、固定单模型规模」下的分配，正好补上我们过去只扫一遍数据（single-epoch）的空缺。
  5. 边界（必须写清）：① 实验规模仅 10–100M token / ≤679M 参数，不能直接外推到 2B+ 前沿预训练；② 单张 H100-80GB、每配置一次训练（集成成员靠独立初始化，非多种子重复）；③ 理论假设为 noiseless Gaussian random-feature、N=P、power-law 谱、固定顺序 SGD，真实 Transformer 的有限宽度 / 数据顺序 / 正则化会带来偏差；④ 「集成更好」是匹配参数–token 预算与共同训练时域下的结论，推理成本按 E 倍增加，论文未做端到端 serving 成本核算；⑤ 数字作者自报、本线未复现。

2Sonar-MoE: In-Backward Expert Updates for Memory-Efficient Mixture-of-Experts Training

中文一句话
MoE 的绝大部分参数在专家里，标准训练要把所有专家梯度留到 optimizer step：OLMoE-1B-7B 的 6.92B 参数中 6.44B 在专家，bf16 梯度就 12.9 GB。作者提出 Sonar-MoE：反向传播中按整批专家张量触发 fused AdamW 更新并立即释放梯度，GPU 最多只保留一层专家梯度；关键是按 batch 张量触发（每层 2 次）而不是逐专家（OLMoE 每步 2,048 次），避免 20%–72% 的慢速；同时保留 dense 参数的 global-norm clipping。微调 OLMoE 与 Granite-3.1-3B-A800M（bf16、SonicMoE / ScatterMoE 两种 kernel 后端）：峰值显存降 19%–22%（OLMoE 55.6 → 43.6 GB），无专家裁剪时更新逐位相同、held-out loss 差 ≤0.003，每步比带 global clipping 的标准训练快 17%–23%，吞吐 +20.2%–30.4%。

推荐理由（借鉴 · 与 BaiZe / ZhuLong 的关系）
  1. 正对 BaiZe 的 MoE / 混合架构训练：显存是「能否在既定卡数上开大 batch、拉长序列、少切分专家」的硬约束；Sonar-MoE 不改模型结构、不改优化器数学，只改「梯度何时释放、更新何时执行」，属于低侵入的系统级收益。
  2. 等价性证据硬、风险可控：作者报告在不做专家梯度裁剪时，更新与标准训练逐位相同（bitwise identical），held-out loss 与所有基线差 ≤0.003 —— 这比「精度略降换显存」的方案更容易被训练团队接受。
  3. 收益量级可直接对标：OLMoE 55.6 → 43.6 GB（−21.6%）、Granite −21.4%；步时 −17%–23%；吞吐 +20.2%–30.4%。若我们的 MoE 微调也卡在「专家梯度 + 激活」峰值上，这是先量「专家梯度占峰值多少」就能判断的收益。
  4. 工程细节值得抄：① 必须按 整批专家张量 挂 hook（每层 2 次），逐专家 hook 会慢 20%–72%；② 只提前更新专家、dense 参数仍留到最后做 global-norm clipping；③ 与 LoRA / 8-bit optimizer / gradient checkpointing 等省显存手段可叠加（论文 §5.5 给了操作区间）。
  5. 边界（必须写清）：① 单卡实验，未覆盖数据并行（作者说下一步接通信 hook；DDP 下更新需在梯度 all-reduce 之后）；② 只测 ≤7B 的 OLMoE-1B-7B / Granite-3.1-3B-A800M，Alpaca 单数据集、单种子（同种子重复估噪声：步时 ≤1.4%、loss ≤0.0016）；③ 显存收益在 batch 小、激活不主导时最大，激活占大头时会缩小；④ 只适用于逐元素优化器（AdamW / SGD / Lion），需要跨张量统计的优化器未覆盖；⑤ 硬件为 2× RTX PRO 6000 Blackwell 96GB（两块卡功耗上限不同，作者只做同卡同后端对比）；⑥ 数字作者自报、本线未复现。
建议动作：读原文（§3 方法、§5.1 设置、§5.5 与省显存手段的叠加、§5.6 边界）+ 试跑（中风险）：先在我们 MoE 微调脚本里量「专家梯度 / 峰值显存」占比，再做单层「早释放 + 无裁剪 baseline 逐位对比」的等价性测试；不要直接在主训练上开，先离线验证。

3Pretraining Data Scale Reverses the Muon-AdamW Fine-Tuning Gap

中文一句话
Muon 在预训练损失上常胜 AdamW，但「预训练赢」不等于「微调后还赢」。作者用 OLMo 式 30M–600M 模型、150M–154B DCLM token、约 600 次预训练 + 29,000 次微调（GSM8K / StackMathQA / Alpaca / MusicPile 四数据集）发现：小数据预算下 Muon 微调损失更低、遗忘更少；超过交叉预算后 AdamW 反超，且模型越大交叉点越早（StackMathQA：30M 需 320 TPR，600M 仅 10 TPR）。机制上用 margin-to-spread ratio（正确 logit 高出错误 logit 的余量 / 错误 logit 的离散度）解释：小预算 Muon 的比值更大、大预算 AdamW 更大；在线性联想记忆里证明该比值随数据预算增长向梯度下降倾斜。

推荐理由（借鉴 · 与 BaiZe / ZhuLong 的关系）
  1. 直接影响 BaiZe 的优化器 / 后训练决策：很多团队按「预训练损失最低」选优化器；本文说明在大数据预算下，Muon 的预训练优势可能在微调后反转 —— 若 BaiZe 的路线是「大规模预训练 + 指令/数学后训练」，这正好是选型时必须看的第二指标（学习–遗忘权衡），而不只是预训练 loss。
  2. 给出可操作的判据与阈值趋势：用 TPR（token–parameter ratio）作横轴，交叉点随模型增大而左移（30M：320 TPR → 600M：10 TPR，StackMathQA）；意味着「模型越大，越早需要担心 Muon 的微调劣势」。我们可先在 30M–600M 上做廉价 A/B，估计自家目标规模的交叉点。
  3. 机制可测量、可当代理指标：margin-to-spread ratio 不需要重训即可在自有 checkpoint 上计算；若它随数据预算的变化趋势能复现，可作为「微调鲁棒性」的早期信号，用于在预训练中途预警。
  4. 实验规模与 BaiZe 的可负担区间接近：30M–600M、150M–154B token、约 600 次预训练 + 29,000 次微调，说明这不是只能在大厂做的结论；我们可用小模型先验证方向，再决定是否在大模型上改配方。
  5. 边界（必须写清）：① 模型只到 600M，未验证 2B+；② 微调数据集为 GSM8K / StackMathQA / Alpaca / MusicPile 四个，分布有限；作者明说「若微调数据与预训练数据很近，等价于继续预训练」，此时结论未必成立；③ 主结果是「最低预训练损失」设置，另附 best-frontier 设置；④ 线性联想记忆是简化证明，不是 Transformer 的严格结论；⑤ 未给出训练吞吐/显存成本对比（Muon 的工程成本未计入）；⑥ 数字作者自报、本线未复现。
建议动作：读原文（§3 预训练/微调设置与交叉点、§4 margin-to-spread 机制、§5 线性联想记忆证明、附录 C 超参）+ 试跑（低风险）：在我们现有的 0.3–0.6B 预训练消融里加一条「AdamW vs Muon → 微调后学习–遗忘」对照，先看交叉 TPR 是否落在自家数据预算附近；暂不据单篇结论改主配方。
