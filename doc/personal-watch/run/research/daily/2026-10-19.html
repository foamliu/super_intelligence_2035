1FlashMask-3: Efficient and Expressive Mask-Aware Distributed Attention 借鉴

原题
FlashMask-3: Efficient and Expressive Mask-Aware Distributed Attention
中文一句话
面向长上下文训练，把结构化注意力掩码（document / prefix-LM / share-question / sliding-window / block-sparse）与多机 context parallelism 结合，用 Hopper 上掩码感知 kernel + 零通信掩码定位 + 稀疏感知负载均衡 + 计算-通信重叠缓解「掩码成为瓶颈」。
作者
Guoxia Wang, Qianyue He, Siming Wu, et al.（共 9 位：Guoxia Wang, Qianyue He, Siming Wu, Haoyang Xie, Qiwen Bao, Jinle Zeng, Jiabin Yang, Tian Wu, Dianhai Yu；机构见原文）
日期
首次提交 2026-10-13T07:55:51Z（published，来自 id_list 官方 Atom）· 版本 v1 · comment 自述「Published as a main conference paper at NeurIPS 2026」（本线未核会务）
分类 · 标签
cs.LG · 借鉴 · 关键词：长上下文 / attention mask / context parallelism / Hopper / 分布式训练
abs 链接
https://arxiv.org/abs/2610.17901
推荐理由（我们判断 · 能用在哪一步）：
① 正对 BaiZe 长上下文训练的成本项：document packing、prefix-LM、sliding-window 等结构化 mask 与 CP 组合是长上下文预训练的常见配置；论文把「每个 rank 的掩码定位」化为边界向量上的零通信 clip–shift–max，在任意多 chunk CP 分配下仍与单卡 kernel 兼容 —— 这对应我们训练栈里「mask 计算 + CP 通信」这一段，而不是换模型结构。
② 指标可直接拿来做对照：单 H100、12 种 mask、4K–128K 上下文，TFLOPs 较 FlashMask / FlexAttention / MagiAttention 提升 45–141% / 34–71% / 2–44%；CP 度 4–32（每卡 8K 序列）达 31–75% 计算-通信重叠效率，吞吐较 Megatron-Core CP ring / all-gather / MagiAttention 提升 1.80–3.71× / 1.71–2.92× / 1.09–1.46×；128 卡 H100 训练 118B-A14B MoE @128K，较 Dual Chunk all-gather 吞吐 +7.3–11.0%，attention 前反向快 24.5–44.9%（作者自报 · 本线未复现）。
③ 建议的落地顺序：先做单机 microbenchmark（同一 mask 配置、同一序列长度，对比我们当前 attention 实现），确认我们用的 mask 类型是否在其覆盖的 12 种之内；再评估 Hopper 依赖（H100/H800）与 Megatron-Core CP 集成成本。若集群以 Ampere 为主，收益需另测（原 FlashMask 面向 Ampere）。
④ 边界：论文是 kernel/系统层优化，不改变模型质量结论；摘要未给与我们训练栈的集成细节；「NeurIPS 2026 主会」仅为作者 comment，本线未核。
建议动作：读原文（重点看零通信 mask 定位的证明与 CP 负载均衡）+ 试跑（单机 kernel microbenchmark，不改主训练）。

2FDE-Gym: The Last Mile of AI Delivery 借鉴

原题
FDE-Gym: The Last Mile of AI Delivery
中文一句话
提出面向「AI 交付最后一公里」的 agent 基准：95 个端到端交付任务 / 20 个客户场景 / 18 个行业，在带脚本化 stakeholder 与可修改客户系统的模拟环境中，用客户业务指标提升（0–1 归一化）评分，并对消息、试跑、等待时间罚分。
作者
Dongxu Yang, Hongda Yan, Renxin Wang, et al.（共 26 位；机构见原文）
日期

分类 · 标签
cs.AI · 借鉴 · 关键词：agent 评测 / 交付 / stakeholder 交互 / 约束发现 / 基准
abs 链接
https://arxiv.org/abs/2610.22350
推荐理由（我们判断 · 能用在哪一步）：
① 补的是 ZhuLong 评测里最容易缺的一环：现有 benchmark 多在 issue / spec / ticket 已写清的任务上打分；真实 EDA / 客户交付里需求模糊、约束没明说、系统还在运行。FDE-Gym 的「脚本化 stakeholder + 可修改系统 + 业务指标归一化 + 交互成本罚分」是一套可直接借的评测设计模板，尤其适合改造我们内部的 agent 交付评测。
② 关键发现值得写进评测规范：7 家厂商 13 个模型配置中，最佳配置平均分仅 0.56，95 题只解 14 题（≥0.8 且无事故）；发现未明说约束是主要瓶颈；即便最佳配置已拿到全部关键事实的 23 题中，也只有 10 题业务提升 ≥0.8（作者自报 · 本线未复现）⇒「会问问题」不等于「能交付」，只看最终代码/答案会高估能力。
③ 可用在哪一步：给 ZhuLong harness 评测增加三类指标 —— 需求澄清质量、未明说约束发现率、交互成本（消息/试跑/等待）；先在小规模内部任务上复刻评分卡，再决定是否扩到 EDA 场景。
④ 边界：面向企业软件交付而非 EDA / 芯片设计；模拟环境不能替代真实客户；95 题规模有限；不据此做模型能力排名。
建议动作：读原文（重点看评分函数与 20 个场景如何构造）+ 仅备忘（评测设计借鉴，暂不接入训练）。

3MemDuet: Learning Dual-Process Memory for Long-Context Reasoning 借鉴

原题
MemDuet: Learning Dual-Process Memory for Long-Context Reasoning
中文一句话
双过程记忆：小模型（System 1）并行从原始 chunk 选证据，大模型（System 2）按文档顺序验证并更新记忆；三阶段训练（SFT System 1 → GRPO System 2 → 联合优化），在长上下文推理上换 accuracy–efficiency。
作者
Jiangcheng Song, Haodong Jing, Yulin Mu, et al.（共 10 位：Jiangcheng Song, Haodong Jing, Yulin Mu, Lesong Tao, Jixin Wang, Jin Cui, Tianjing Ren, Runxuan Xie, Yongqiang Ma, Nanning Zheng；机构见原文）
日期
首次提交 2026-10-14T10:16:13Z（published，来自 id_list 官方 Atom）· 版本 v1 · comment 为空
分类 · 标签
cs.CL · 借鉴 · 关键词：长上下文 / 记忆 / SLM-LLM 协同 / GRPO / 推理效率
abs 链接
https://arxiv.org/abs/2610.19928
推荐理由（我们判断 · 能用在哪一步）：
① 对应 BaiZe 长上下文推理的 serving 思路：把「读长文档」拆成 SLM 粗筛证据 + LLM 维护/验证记忆，避免每一步都把全文塞给大模型；与「小模型做检索候选、大模型做精读与决策」的级联一致，也便于控制输出 token。
② 有明确的效率指标：RULER-HQA / LongBench v2 / 2WikiMultiHopQA 上，相对 RL-MemAgent 平均端到端推理加速 9.74×、输出 token 减少 73.91%（作者自报 · 本线未复现）。建议我们把「准确率 / 输出 token / 端到端延迟」三指标一起做 A/B，而不是只看加速比。
③ 可用在哪一步：先在长文档 QA / 代码库理解 / 设计文档检索等内部场景做离线原型，重点监控 System 1 证据选择的召回率（这是级联的上限）；再评估是否接入 BaiZe 推理服务。
④ 边界：依赖一个可训练的小模型与 GRPO 流程，训练成本不低；摘要未给各数据集绝对准确率、也未给失败模式；9.74× 是相对特定 baseline（RL-MemAgent），不是对我们栈的收益。
建议动作：读原文（重点看三阶段训练与记忆更新顺序）+ 试跑（离线长文档 QA 原型，先测召回率与 token 成本）。
