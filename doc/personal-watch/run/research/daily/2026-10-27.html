1Where Rounding Happens Matters: Rounding-Location Alignment Stabilizes LLM Reinforcement Learning

中文一句话
LLM 的 RL 后训练通常用两套系统：vLLM 采样、Hugging Face 重算 logprob。即使权重与张量类型（BF16）完全相同，kernel 实现差异也会让「本应 on-policy」的更新变成 off-policy 并把训练打崩。本文不改全局精度、不改学习目标、不改推理引擎与 GEMM/attention kernel，只把三个区域的「舍入位置」对齐（RoPE 路径 / SwiGLU / 残差 RMSNorm：中间量先留 FP32，输出时再舍入到 BF16）。在 4 个 Qwen 系模型（DeepSeek-R1-Distill-Qwen-1.5B、Qwen3-1.7B、Qwen3-4B-Base、Qwen3-8B-Base；PPO-clipped GRPO；Sanity-Test-R1D-1.5B 训练 → AIME 2025 评测）上：默认 BF16 基线全部崩塌；三区域全对齐全部稳定，只对齐 RoPE 路径也足够；静态 per-token KL 仅降 9.1–25.5%（RoPE 的 Shapley 贡献 81.5% / 91.8% / 76.9%），而「训练与推理同一后端」（Zero-mismatch）时 KL 严格为 0。

  2. 改动面积极小、可局部验证：只在 RoPE / SwiGLU / 残差 RMSNorm 三处保留 FP32 中间量，不动推理引擎、矩阵乘与 attention kernel、学习目标 —— 对既有训练栈是「加开关」而非「换框架」，比全栈对齐（要求两边 reduction 顺序一致）更现实。

  5. 边界（引用时必须带上）：仅 2 个数学数据集（Sanity-Test-R1D-1.5B 主文 + DAPO-Math-17k 附录）、单一架构族（Qwen2/Qwen3）、最大 8B；MoE 只在相关工作里提，未在本文验证；数字作者自报、本线未复现、未精读全篇。

2NgramRL: Accelerating RL Post-Training for Structured Generation via Rollout-Aware N-gram Speculative Decoding

中文一句话
RL 后训练的开销主要不是前向/反向，而是自回归 rollout（作者引述可占 step 时间 70%+）。常规投机解码在这个场景不好用：草稿模型要占本来就紧张的 GPU 显存，而且策略一路漂移、固定草稿会越来越被拒。本文的观察是 —— 同一个 prompt 在训练中会被反复采样（GRPO 多步多 epoch 重访），所以它自己近期的 rollout 就是一份免费、自更新的草稿源。据此提出 NgramRL：为每个 prompt 用有界的历史 rollout 建一张 n-gram 查表（放 CPU，不需要草稿模型 / 不需要训练 / 不占常驻 GPU 显存），target 模型验证保证输出分布不变；再加一个自适应 fan-out 预取器预测验证结果 (j, b)（j = 被接受的草稿长度、b = target 续出的 token），用因果预算分配把预取集中在高概率分支上。结果：Qwen3-8B / DeepSeek-LLM-7B × GSM8K / Spider 1.0 / CodeContests，warm-cache 下每步提交 3.60–7.77 token（比 SuffixDecoding 高 1.2–1.99×、比 prompt-lookup 最高 7.0×）；Spider 上预取器在候选预算 16 时覆盖 96.6% 的 Qwen3-8B 结果，rollout 吞吐比同步版高 1.38×（重叠理论上限 1.40×），decode 迭代 26.1 ms → 19.2 ms。

推荐理由（借鉴 · 与 BaiZe 后训练效率 / ZhuLong 结构化生成的关系）
  1. 打的是 RL 训练里最贵的一段：rollout 生成占 step 时间 70%+，而本文的加速手段不加显存（表放 CPU）—— 对显存已经被策略 / 优化器状态 / KV cache 挤满的训练节点，这比「再挂一个 draft model」现实得多；分布式训练下也不会与 tensor/pipeline 切分抢资源。
  2. 机制与我们高度契合：GRPO 类算法天然重复采样同一 prompt（多步 + 多 epoch），「历史 rollout 当草稿」这条信号在我们的训练循环里必然存在，不需要改算法、不需要额外数据；target 验证无损（分布不变），是可以「先开着不动、只观察加速比」的低风险改动。
  3. 结构化输出收益最大：Spider（text-to-SQL）上 6.37 → 7.71 token/step，作者归因于 SQL/代码这类格式规整的输出重复率高 —— 这对 ZhuLong 这类 execution-grounded EDA / 代码 agent 的结构化生成（网表、脚本、约束）是同一类负载，值得记一笔。
  4. 工程细节可直接抄：历史窗口 w 的扫描（w=4/8/16/32）显示 w>16 后不再涨、GSM8K 上还会掉（旧 rollout 过期）⇒ 缓存要截断而非累积；n_max=6、k=16 都在加速曲线的拐点；这些是调参起点，不是理论最优。
  5. 边界（引用时必须带上）：规模只到 7B/8B、单机、2 个模型族、3 个数据集；加速是相对同步基线（26.1→19.2 ms，约 1.36×），不是端到端训练加速 1.38×（1.38× 是 rollout 吞吐）；CodeContests 上收益最小（跨 prompt 样板多，全局缓存更占优）；n-gram 表要占 CPU 内存，CPU 弱 / 表过大时会退化；数字作者自报、本线未复现。

3When Agents Fail: Model or Harness--Who's to Blame?

中文一句话
agent 的跑分是「模型 × harness（执行外壳）」的联合结果，只报任务成功率会掩盖失败来源。本文把评测拆成五个互补指标：① VCR（Valid Completion Rate）—— 不管对错，能否正常结束并交出可评测结果；② Model–Harness Fit—— 某 harness 对某模型「有效完成」的支持度；③ Cross-Model Fit—— 某 harness 跨模型的整体适配；④ Interaction Residuals—— 扣掉「模型主效应 + harness 主效应」后的配对专属强弱；⑤ Token Load—— 含失败重试在内的 token 消耗。实验：4 个通用 harness（OpenCode / Codex CLI / Pi CLI / DeepAgents）× 4 个模型（DeepSeek V4 Flash Preview、MiniMax M3、Kimi K2.7、Qwen3.6-35B-A3B）+ 2 个原生固定系统（GPT-5.5 xhigh + Codex CLI、DeepSeek V4 Pro 0813 + DeepSeek Harness），跨 6 个基准（SWE-bench-45 / Terminal-Bench 2 / VitaBench / LOCA-Bench / ClawMark / AgentSkillOS），共 111 个评测设置 / 52,168 条轨迹。结论：harness 排名随模型与基准变化（同一模型下最优 harness 会换人）；OpenCode 在跨模型聚合上第一；DeepSeek V4 Flash Preview 在 4 个 harness 上 Mean VCR 稳定在 91.30%–93.98%（极差仅 2.68 个百分点）；任务分相同 ≠ 执行画像相同（VitaBench 上各配置 VCR ≥ 98%，但 Mean-of-4 仍横跨 28.1 个百分点）；资源侧也更依赖配对（VitaBench 上 DeepSeek 用 Pi CLI 每 attempt 的 token 不到 Codex CLI 的一半，Mean-of-4 只差 <0.2 个百分点）。

推荐理由（借鉴 · 与 ZhuLong code agent harness / 评测基准的关系）
  1. 把平时混在一个成功率里的两件事拆开了：「任务做对了」与「跑完了、交出的东西能被评测器接住」是两件事，而且会互相掩盖 —— 正常结束可以解错，异常终止也可能拿到部分分。ZhuLong 的 generate–execute–refine 链条里，「工具调用崩了」与「EDA 流程报错」必须能分开计数，VCR 正是这个计数器的定义（只看是否正常终止 + 有效 handoff，与任务正确性无关）。
  2. 「先量配对、再谈 harness 好坏」的方法论可直接搬：Interaction Residuals 在不同基准上会符号翻转（例：Kimi×Codex 在 SWE-bench-45 低于加性基线、在 LOCA-Bench 高于基线）⇒ 只做「全基准平均」时，真实存在的配对优势会被正负抵消。这对我们做 harness A/B 的统计口径是硬提醒。
  3. Token Load 让「便宜」变成可判定的：把失败重试也计入消耗，并要求 100% token 覆盖才做比较 —— 否则「省钱」很可能只是「早早放弃」。对 ZhuLong 这种单任务可能跑几十轮工具调用的 agent，成本口径应与成功率同表报告。
  4. 「harness 使用能力可作为训练目标」与我们的路线一致：作者建议把 harness-use（动作构造、反馈利用、恢复、停止）当作可迁移能力训练，并在训练时没见过的 harness 上保持表现 —— 这正是 ZhuLong 从「单一工具链」走向「换外壳仍能干活」的目标。
  5. 边界（引用时必须带上）：4 harness + 4 模型 + 2 原生参考，面板有限（ClawMark / AgentSkillOS 因多模态缺失只跑 3×4）；作者自述 Cross-Model Fit 的领先者依赖其选定的模型与基准，不可外推成「OpenCode 天下第一」；本文为 Preprint under review；数字作者自报、本线未复现、未精读 43 页附录。
