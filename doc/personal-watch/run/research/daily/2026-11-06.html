1Accelerating Long-Context Decoding in Large-Scale Hybrid LLMs Without Retraining

中文一句话
混合注意力大模型（多数层已换成线性/滑窗注意力）在长上下文解码时，剩下少数全注意力层仍吃掉大部分单 token 成本。作者不改权重、不重训，只把每个全注意力层的注意力限制成三部分：固定前缀 256 token、最近 W 个 token 的滑窗、以及按 Quest 在分页 KV 上挑出的 Q 个最相关 token；再用 NSGA-II 为每一层单独搜 (W,Q)。6 个混合模型 / 3 个家族 / 21 个长上下文基准上，每个模型都至少有一种配置逐项保住基线精度（平均差 ≤0.5 个百分点）；batch 4 下 64k/256k 解码最多快 1.26×/2.22×（Qwen3.5-4B）、1.20×/2.23×（Qwen3.5-122B-A10B）、1.16×/2.06×（Ornith-1.0-397B）。

推荐理由（借鉴 · 与 BaiZe / ZhuLong 的关系）
  1. 命中「长上下文 / 长 CoT 的 decode 账单」：我们真正付费的是全注意力层在长序列上的 KV 读取，不是参数量。本文把改动限定在「每层看多少 token」，不动权重、不动训练，是那种能在现有推理栈上先量收益再决定要不要接的改动。
  2. 硬数字可回查（摘要 + §5 结论，batch 4）：64k/256k 解码 1.26×/2.22×（Qwen3.5-4B）、1.20×/2.23×（Qwen3.5-122B-A10B）、1.16×/2.06×（Ornith-1.0-397B）；稠密 Qwen3.5-27B 仅 1.11×、Gemma-4-31B 1.09×，gpt-oss-120b 在接近上下文上限时收益很小 —— 「混合 + MoE」结构收益最大，这与我们关注的架构方向一致。
  3. 方法可直接照做：① 每个全注意力层三个旋钮 = 前缀 256（固定 sink）+ 滑窗 W + Quest 预算 Q；② 用 NSGA-II 在「精度 × 估计解码成本」上做多目标搜索，得到 Best Accuracy / Best Speed / Balanced 三套逐层配置；③ 搜索成本可控：4–120B 在 A100 上 8.6–34.2 GPU-hours，122B/397B 在 4 卡 GB200 上 31.3–58.4 GPU-hours（每模型 ≤60 GPU-hours），已装进 vLLM。
  4. 口径要点：作者称这是「首个在 100B+ 规模上评测的免训练稀疏注意力方法」——这是作者的自述，我们只做转述、未独立核验。
  5. 边界（必须写清）：① 短上下文反而更慢，要到 32k–64k 之后才转为净收益 ⇒ 不适合短 prompt 为主的在线服务；② Quest 保留完整 KV cache（任意页都可能被选中）⇒ 只省计算、不省显存；③ 配置要逐模型逐层搜，换模型需重搜；④ 实验在 A100 / GB200 上，未覆盖国产加速器；⑤ 数字作者自报、本线未复现。
建议动作：读原文（§3 逐层搜索目标与代价模型、§4 六种配置对比、§5 精度无损的证据链）+ 试跑：先在我们长上下文流量最高的模型上量「全注意力层占 decode 时间比例」，再决定是否值得付 ≤60 GPU-hours 的搜索成本。

2SafeStart: Mitigating the Overlooked Safety Cost of Active Expert Reduction in MoE LLM Serving

中文一句话
MoE 推理常见的加速手段是「每 token 少跑几个专家」，过去只按精度基准验收。作者在 vLLM 上审计 9 个 MoE 模型，发现削减专家会削弱拒答：保留约 2/3 已选专家时离线解码（batch 8）快 15%–28%、MMLU 掉不到 2 分，但在「要求不要拒答」的越狱模板下，有害回答率在 Qwen1.5-MoE 上升 18.4 个百分点、OLMoE 9.5、DeepSeek-V2-Lite 6.6。作者把升高定位到「处理 prompt + 生成最初几个 token」这一段，提出 SafeStart：prompt 与最初 8 个生成 token 跑全专家，之后才切到削减集，并在 vLLM 里用融合 kernel 落地 —— 保住 ≥85% 的加速，把上述变化压到 −2.1 ~ +1.3 个百分点。

推荐理由（借鉴 · 与 BaiZe / ZhuLong 的关系）
  1. 给我们提了一个「验收项」而不是一个技巧：MoE 服务侧削专家（少跑 k 个）几乎是一定会做的降本动作，但我们的验收清单上通常只有 MMLU / GSM8K。本文证明还漏了一项：拒答（refusal）。这一条可以直接写进我们推理侧的回归测试。
  2. 硬数字可回查（摘要 + 附录）：保留约 2/3 专家 ⇒ 离线解码 15%–28%（batch 8，单卡 RTX A6000，vLLM 0.11.0）；越狱（refusal suppression / prefix injection 两种模板）下有害服从变化：Qwen1.5-MoE +18.4 pp、OLMoE +9.5 pp、DeepSeek-V2-Lite +6.6 pp（9 个模型中这 3 个显著），MMLU 掉 <2 分；top-p 路由（按累计路由权重阈值选可变个数的专家）精度代价更大，却把有害服从最多推高 30.1 pp —— 说明「省专家」和「省得不安全」不是同一件事。
  3. 修法极简、工程代价可测：SafeStart 只在「prompt + 前 8 个生成 token」跑全专家，之后回落到削减集；用 vLLM 融合 kernel 实现后，不削专家时只给在线服务每输出 token 的中位时间加 ≤2.4%；削专家时保住 ≥85% 的离线加速（batch 8 与 32）。另有 889 条预留请求的预注册分析：直接截断使有害服从升 5.8–21.4 pp，SafeStart 只剩 0.6–2.6 pp（3 个模型中 2 个非劣于原模型）；保留约一半专家时 batch 8 解码快 38%–44%，仍消掉 ≥86% 的上升。
  4. 为什么「前 8 个 token」够用：作者发现有害服从的上升主要发生在 prompt 处理与最前面几个生成 token（拒答/服从的决定点），一旦进入正文，削减专家的影响就小得多 —— 这是「按 token 位置给不同专家预算」的一个可复现证据点。
  5. 边界（必须写清）：① 单卡 RTX A6000 + vLLM，未覆盖多卡 / 国产加速器；② 判定用 Llama Guard 3 8B 为主、HarmBench 为副，另有人工双标注 587 条（一致率 97.3%、κ=0.93）—— 裁判本身仍有误差；③ 主结论绑定「确认性设置」（k′ = ⌈2k/3⌉、两种越狱模板），其他越狱/模型需再验；④ 数字作者自报、本线未复现。
建议动作：试跑（成本低、收益明确）：在我们 MoE 模型的推理回归里加一组「越狱模板下的拒答率」对照，先确认削专家是否已经把拒答打穿；若打穿，再按 SafeStart 的「prompt + 前 8 token 全专家」做一个最小改动版本量代价。读原文：§3 实验设计（framings / 三种削减方法 / McNemar）与 §4 定位分析。

3Systolic Linear Attention: Co-Designing Tile-Grouped Gated Delta Attention for TPUs

中文一句话
门控 delta 线性注意力（GDN / Kimi Delta Attention / GDN-2）是按 GPU 的小 tensor-core 分块与快速向量寄存器设计的，直接搬到 TPU（256×256 脉动矩阵单元 + 较慢的向量单元）会有一半矩阵块空着、并卡在向量操作上。作者提出 SLA：把 key 宽度加宽到 256 并做 value head 分组共享、把衰减门分成 4 个 64 通道 tile、把 chunk 求解（含反向）全部改成块矩阵乘并融进一个 kernel。TPU v7x 上单层 SLA-R4 比开源 Tokamax KDA kernel 快 1.6×–2.5×（精确 chunk 求逆时 1.4×–2.4×）、临时 HBM 少 52%–61%；在最多 512 卡、6.5B–63.1B 稀疏 MoE 预训练里，同等困惑度下训练比 MaxText KDA 快 8%–24%，且任何规模都不需要给线性注意力门做 clamp。

推荐理由（借鉴 · 与 BaiZe / ZhuLong 的关系）
  1. 这是一篇「算子—硬件形状对齐」的方法论样本：同样一个线性注意力层，在 GPU 上写成「小 tile + 逐通道门 + 块内三角求解」最快，在 TPU 上就变成 半个矩阵块空着 + 向量单元堵死。我们要搬的不是代码，而是这条思路：先看目标加速器的矩阵块形状与矩阵/向量算力比，再决定 recurrence 怎么切。
  2. 硬数字可回查（摘要 + §结论）：TPU v7x 单层 1.6×–2.5× 快于 Tokamax KDA（精确求逆 1.4×–2.4×），临时 HBM −52%–61%；最多 512 卡、6.5B–63.1B 稀疏 MoE：同等困惑度下训练比 KDA 快 11%–24%（结论段按 MaxText KDA 口径写 8%–24%），小规模同种子下困惑度还略低；RoPE 骨干 8K→64K 零样本、63.1B NoPE 上 32K 8-Needle 83.2%–84.4%。（摘要称整个研究跨 2,048 卡，单次运行最多 512 卡。）
  3. 三个动作都能被我们复用：① head 共享（用 256 宽 key 填满矩阵块，value head 分组共享）；② 门分组（把逐通道衰减压成 4 个 64 通道 tile，让 decay 退出 matmul）；③ block-doubling 求逆（把 chunk 求解与反向都留在矩阵单元里，一个 VMEM kernel 做完）—— 这三条与加速器品牌无关，属于「线性注意力怎么落到宽矩阵单元上」的通用清单。
  4. 一个容易忽略的工程结论：作者报告无需对线性注意力门做 clamp（8K→64K 全程稳定）—— 这直接对应我们长上下文外推时常见的「门饱和 / 数值发散」补丁，值得核对是否是我们自己实现里的问题。
  5. 边界（必须写清）：① 收益主要来自 head 共享 + kernel 融合，方法针对「宽矩阵块 + 大矩阵/向量差距」的加速器，GPU 上未必成立；② 匹配种子下仍比宽 key KDA 差约 0.1 困惑度（用 1 步 Neumann 逆时 0.3）；③ 63.1B 为单种子、64K QA 集偏小，BF16 MoE 路由方差（≈0.18 PPL）会掩盖小差距；④ 全部在 TPU 上，未涉及国产加速器；⑤ 作者自报（Google）、本线未复现。
建议动作：读原文（§3 SLA 的三处改造、§4 单层 kernel 基准、§5 预训练缩放研究）+ 仅备忘：把「head 共享 / 门分组 / 块矩阵求逆 / 免 clamp」四条写成我们线性注意力实现的检查项，等有对应硬件档期再试跑。
