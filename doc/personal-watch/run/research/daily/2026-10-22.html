1BitMTP: When Multi-Token Prediction Meets Low-Bit Large Language Models

英文原题
BitMTP: When Multi-Token Prediction Meets Low-Bit Large Language Models
中文一句话
超低比特主干（降权重存储 / 访存 / 线性层开销）与多 token 预测（MTP，一次并行出多个未来 token）本应互补，但直接拼接在同等质量下并不加速（masked drafting 缺少中间 token 输入；更宽的计算与因果 KV 更新抵消了步数收益）。BitMTP 做算法–系统协同设计：联合 NTP + MTP 目标让单模型同时具备自回归生成与 block-causal drafting；提供 confidence-only / speculative-only / hybrid 三种解码工作点；用 accepted-prefix alignment 保持「已提交前缀 / 已物化的因果 KV 边界 / CUDA Graph 重放状态」一致；再据此选择宽度特化的低比特执行并在共享 KV 上复用已捕获的图。NVIDIA H20 上 hybrid 解码：BitNet b1.58-2B 五任务平均 2.2×、1.7B–4B Bonsai 2.1–2.4×；RTX 3090 / Jetson Orin 上五任务平均吞吐最高 2.0×、MBPP+ 最高 3.3×（作者自报）。

推荐理由（对应 BaiZe 的 ~2B 规模 / 高效推理 / 端侧路线）
  1. 它回答的是「两个加速手段为什么叠加不起来」：我们在 BaiZe 上同时考虑低比特与 MTP/投机解码时，最容易踩的正是这篇点出的两个坑——masked drafting 拿不到中间 token、更宽计算与因果 KV 更新把收益吃回去。这是一份现成的「负结果清单」，可用来判断我们自己的组合方案是否只是看起来更快。
  2. accepted-prefix alignment 是可搬的工程契约：把「已提交前缀」「因果 KV 边界」「CUDA Graph 重放状态」三者在继续生成时对齐——这正是投机解码 + 图捕获 + KV 复用三者共存时最容易出正确性 bug 的地方。即便不上低比特，这套契约也可以写进 BaiZe 推理框架的验收清单。
  3. 三种解码工作点 + 单模型双能力：confidence-only / speculative-only / hybrid 覆盖不同质量–吞吐取舍，且不需要额外的 draft 模型与 verifier 模型，对显存与部署复杂度友好（~2B 端侧场景尤其相关）。
  4. 我们判断的适用边界（先读再试）：① 必须用超低比特主干（BitNet b1.58 / Bonsai 类），属于量化感知训练路线，不是给现有 BF16 checkpoint 后贴即可；② 加速比是作者自报，且为「五任务平均」口径，摘要未给逐任务数字，也未给困惑度等绝对质量指标（只说 comparable task quality）；③ 硬件只在 H20 / RTX 3090 / Jetson Orin 上测，未覆盖我们实际训练/推理卡型；④ 与 EDA / 存储负载无关；⑤ 未做全文精读，本线未复现。

2RACE: RoPE-Aligned Attention Compression Based on Query-Key Activation Energies

英文原题
RACE: RoPE-Aligned Attention Compression Based on Query-Key Activation Energies
中文一句话
KV cache 的 head-dimension 压缩能省显存，但现有方法常在推理时重建全维表示，反而增加 decode FLOPs。作者先形式化「把预训练 attention 转成原生降维形式」的三个条件（Q / K 共享投影到同一降维空间；投影由 Q、K 激活联合导出；与预训练 RoPE 兼容），再证明：若要免重建而把降维限制为「坐标选择」，则 RoPE 兼容 ⇔ 保留完整 rotary pair。据此提出 RACE：用 Q–K 联合激活能量挑选 rotary pair，理论上最小化一个可分离的、依赖校准集的上界（post-RoPE QK 乘积近似误差）；降维结果折进模型权重，无需运行时重建、也无需专用 kernel。三个模型族、不同压缩比下，在语言建模 / zero-shot / 长上下文任务上优于结构化剪枝、与基于重建的方法相当；在 50% KV 保留 + 256K 上下文时，总推理 FLOPs −47.8%、吞吐 1.79×、TTFT −43.2%、分配显存 −28.1%（作者自报）。

3Object-Oriented Harness: Evolving Agent Harnesses through Object-Oriented Design

英文原题
Object-Oriented Harness: Evolving Agent Harnesses through Object-Oriented Design
中文一句话
agent harness 就是围绕模型、可执行的 prompts + tools + control flow 代码；单一全局 harness 难以应对异构任务。OO-Harness 用面向对象设计进化出一棵可执行 harness 类层级：训练时一个 evolution agent 依据执行记录创建一组专用 harness，每个都是基类或已有专用 harness 的子类（继承）；测试时 harness router 用训练中积累的「路由经验」为每个任务挑一个具体 harness。在覆盖业务流程 / 工作区任务 / 工具使用的三个 long-horizon 基准上，该方法在对比方法中最好，相对 base 绝对提升最高 15%（作者自报），并给出核心组件的消融。

4Single-Image Food Mass Estimators Do Not Transfer Their Gram Scale Across Datasets

英文原题
Single-Image Food Mass Estimators Do Not Transfer Their Gram Scale Across Datasets
中文一句话
拍一张照片就报出「这盘菜多少克」，是图像化饮食记录的核心能力。本文的答案是：换个场景就不准了。作者用 Nutrition5k 的 2,253 个已称重餐盘微调 DINOv2-base 从单张 RGB 图回归质量：域内 MAE 24.8 g，不到零样本 Qwen3-VL-32B 的一半；但换到三个外部数据集（ASA24 studio portions / ECUSTFD whole foods / Food Portion Benchmark 餐盘）并没有赢过 Qwen。对没见过的食物它会按大小排序，但不比「数食物像素」更强；克数尺度错在两处——随照片里场景占比变化，且每种食物的偏移因子不同。用同数据集里的其他食物 / 餐盘训练可把外部误差降 38–65%；更大的 DINOv2-large 没有降低外部误差；同一食物加一张有标注照片可把 ASA24 误差降到 28.3 g（好于该照片单用）。在 Nutrition5k 上覆盖 90% 真值的预测区间，在外部照片上至多覆盖一半；且 Nutrition5k 常对同一餐盘多拍，随机切分会与训练集共享近似重复照片、夸大精度。结论：单图质量估计需要来自实际使用场景的标注照片（作者自报）。

5Plausible but Unimplantable: A Trustworthiness Audit of Shape Completion Foundation Models for Cranial Defect Reconstruction

英文原题
Plausible but Unimplantable: A Trustworthiness Audit of Shape Completion Foundation Models for Cranial Defect Reconstruction
中文一句话
缺了一块颅骨、要补一块严丝合缝的植入物，目前仍靠专家在 CAD 里手工画，慢且贵。作者把这件事看成 shape completion（形状补全），于是审计了 3 个公开预训练补全模型（其中 2 个是 foundation model），零样本用在 239 个颅骨缺损上（210 个从公开颅骨数据集人工「挖」出 + 29 个真实去骨瓣术后病例）。每个输出都与一个「什么都不做」基线（直接返回患者剩下的骨）比较，并检验预测材料能否在不与现存骨相交的前提下放置。结果：210 个挖出缺损上，3 个模型没有一个超过「什么都不做」；29 个真实病例上只有一个超过随机水平；而且没有任何一个输出是可植入的——没有一个同时做到「避开现存骨」且「比什么都不做放置更多材料」。对照之下，一个为此任务专门训练、并在这些病例上选型的体素模型除 1 例外全部可植入。最像颅骨的那个输出并不比其它更可放置；在这些点密度下植入物厚度无法从输出点云读出——这是输出表示本身的属性，不是某个模型的毛病。结论：这些模型按发布状态不可信、不可用于临床（作者自报）。

  1. 标题就是最好的钩子：「看起来像、但装不上去（Plausible but Unimplantable）」——一句话讲清「像」与「能用」之间的鸿沟，比任何抽象宣传都更有冲击力，且天然适用于所有「生成式 AI 进医疗」的讨论。
  2. 评测设计本身就是可讲的方法论：不用 FID / Chamfer 这类「像不像」的指标，而是直接问能不能装——① 是否超过「什么都不做」；② 是否不与现存骨相交。普通人一听就懂「像不像 ≠ 能不能用」，这一条能直接搬去任何 AI 医疗讨论。
  3. 有强对照、结论不含糊：同一个任务，专门训练的体素模型几乎全部可植入，而通用 foundation model 全军覆没 —— 说明问题不在「AI 不行」，而在「通用预训练 + 零样本」不适用于强几何约束的临床任务；并且给出了机理（点云密度不足 ⇒ 厚度不可读），不是只报个分数。
  4. 我们判断的适用边界（先读再试）：① 结论只针对作者能拿到并审计的 3 个模型，不能推广成「所有 shape completion 基础模型都不可用」；② 29 个真实病例样本量小，「只有一个超过随机」的统计功效有限；③ 「可植入」是几何判据（不侵入现存骨 + 材料量），不等于临床可用（未含力学、感染、长期随访）；④ 已投 ACCV 2026 Workshop（workshop 论文），非顶会主刊；⑤ 数字作者自报、本线未复现；⑥ 未做全文精读。
建议动作：列为《论文两分钟》备选脚本 No.2（若本期想走「AI 进医疗的边界」主题可直接替换）；如与我们工作结合，价值在于「把可用性判据写进评测」这一范式 —— 任何生成式产出（含代码、布局、PDK 约束下的版图）都该问「能不能直接用」，而不只是「像不像」。
