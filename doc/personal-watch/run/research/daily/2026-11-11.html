1Safe Reinforcement Learning for Multi-Turn Clinical Agents: When Dense Rewards Beat Outcome Rewards

中文一句话
在多轮临床 agent（该问什么、何时停止收集证据、采取哪个动作）上做受控实验：只用最终结果奖励的 GRPO 常把平均分刷上去，却同时制造过早承诺、只问一个问题就收手、在罕见高危病例上崩掉；给「能降低不确定性的提问」加稠密过程奖励（λ=0.2）后，在 3 个训练种子上留出集价值 +0.285→+0.313、高危价值 +0.098→+0.157、高危支持率 0.33→0.50、中等病例支持率 0.38→0.67，且不再出现 outcome-only 的高危种子崩坏；但过程奖励的强度是任务相关的（滴定任务里 λ=0.1 才把提问数从 1.24 拉回 2.67，λ=0.2 则过度提问、价值掉到 −0.091），且 RL 修不好有偏 SFT 留下的稀有行为缺口。

推荐理由（借鉴 · 与 vision 的 v6 奖励重设直接对口 / 与 zhulong 的「分数 + 成本」口径侧向相关）
  1. vision 的根因就是「奖励离散、组内全同」：v5 诊断显示 78.7% 的组 advantage 标准差为 0、全 0 组 0%、全同档组无信号。本文的对照组正是outcome-only GRPO，并把它拆成三类失败模式（过早承诺 / 只问一次 / 高危崩坏），与「离散档位把过程压扁」是同一类病。它给的解法不是调温度，而是把过程信号显式写进奖励，且用 λ 做强度旋钮 —— 这正好对应 v6 要做的「奖励连续化」。
  2. 有可用的量化对照与安全护栏：3 个种子、留出集、support@k（不是只看均值）——高危支持率 0.33±0.29 → 0.50±0.00，中等 0.38±0.18 → 0.67±0.10，同时提问数只从 1.82 增到 2.08。说明「加过程奖励」不是无代价地鼓励多动作，而是把「有效动作」与「凑动作」区分开。v6 若只看总分，会把「多测几次波形」误判为变好。

  4. 边界：① 临床多轮决策，不是波形，数值不可移植，只有奖励结构/报告口径可移植；② 高危子群只有 2 个病例（support 只能取 0/0.5/1），统计力极弱；③ 主实验 3 seeds，滴定/解耦实验是单种子；④ 作者自报、本线未复现。

重打分 8 个基准的已发布运行（含 SWE-bench Verified、Terminal-Bench 2.0、OSWorld-Verified、ALE-Bench、MLE-bench、METR、SWE-fficiency、AlgoTune），结论是「榜单饱和」很大一部分来自测量方式，而不是任务被做完。两种失效：A 太粗 —— 一次运行被压成 1 个 pass/fail 比特，SWE-bench Verified 前十名今天只差 3.6 分、统计上同属一档（2024-09 还是 19.2 分、三档），Terminal-Bench 2.0 差 8.5 分一档、OSWorld-Verified 差 12.0 分两档；三榜单前十里没有任何相邻对显著可分，且校正 verifier 误差后的重排不比随机删掉每个 agent 六分之一的通过更多。B 封顶在参考解 —— ALE-Bench 官方分把前十分成三档（饱和度 S=0.07），二值化成「是否超过人类中位数」后变一档（S=1.00），按「目标函数」打分（参考处 = 1、超过按截断对数比、封顶 3）则恢复三档（S=0.03）—— 因为 47.8% 的运行其实超过参考。同分模型在 Terminal-Bench 复跑里，在被丢弃的「量」上可差 10 倍以上；57 份旗舰模型卡（7 家实验室）里只有约 三分之一 的结果与上一代旗舰可比。方案 = 带日期锚点的截断对数比分数 + 成本单列 + 冻结锚点保证版本可比。
