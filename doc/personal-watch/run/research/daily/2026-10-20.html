1FuTransformer: FP8 prefill and INT4 decode for Llama-style inference on Hopper

FuTransformer: FP8 prefill and INT4 decode for Llama-style inference on Hopper
中文一句话

推荐理由（对应 BaiZe 推理效率 / 我们自己写 kernel 的路线）
  1. 切分方式与我们一致、可直接对照：把 Llama 风格推理拆成「prefill 复用权重 → 受 matmul + 激活搬运限制」与「单 token decode 复用少 → 受权重 + KV-cache 读取限制」两条不对称瓶颈，分别配 FP8 / INT4 两套路径 —— 这正是BaiZe 部署阶段要回答的「哪一段该量化、量化到几位」的问题，比笼统报「整模型 INT4 快 N 倍」更有工程指导性。
  2. 两个可迁移的具体手法：① 把量化嵌进 epilogue / MMA 操作数（权重与 key 按 Tensor Core fragment 布局直接反量化，不生成完整中间 tile、不多占寄存器/SMEM）——我们若在自研 kernel 里做低精度，这是省带宽又不炸 occupancy 的通用套路；② block-diagonal Hadamard 变换压 outlier 通道，把 cache 量化误差再降 0.20 ppl —— 比逐通道 scale 更省，值得在长上下文 KV 量化上试。
  3. 代价被明确写出来了，方便我们做取舍：全 token 走 INT4 权重后困惑度 6.24 → 7.23（RTN）/ 6.99（同格式 GPTQ），即约 +12% ~ +16%；作者同时说明 kernel 与量化参考计算差异在 0.001 ppl 内（即误差来自量化本身，不是实现走样）。做 2B 规模（BaiZe）时，这种「精度-带宽」账本比加速比更有用。
  4. 我们判断的适用边界（先读再试）：单作者、无 comment、无代码地址 ⇒ 可复现性未知；只覆盖单卡 prefill/decode kernel，未做端到端服务（无 continuous batching / 调度 / 多卡 TP），batch 只测到 32；未做全文精读，加速比均为作者自报、本线未复现。
建议动作：先当「kernel 设计参考」读（尤其 fragment 内反量化 + Hadamard 两节），再在我们的 H100 上用 2B 模型复现 decode batch=1 的单步耗时与困惑度代价；不建议直接据此改训练精度。

3DLite: History-free Speculative Decoding for Agentic AI

推荐理由（对应 ZhuLong 的 agent 服务效率 / 多轮工具调用）
  1. 问题选得准，而且是我们会遇到的：ZhuLong 是 generate–execute–refine 多轮循环，上下文只增不减；常规投机解码的 draft 模型越到后面越猜不准。作者给出「接受长度最多下降 80%」这一量化现象，等于把「投机解码在 agent 上不划算」从感觉变成了可测指标 —— 我们线上若挂了 draft 模型，值得先量这条曲线。
  2. 解法思路可迁移、且省系统开销：不走「draft 模型也要读全部历史 KV」的路，而是复用目标模型已经算过的 hidden states，把「随历史增长的复杂预测」压成「局部简单预测」；顺序 head 只负责恢复块内因果依赖。对我们意味着：不必为 draft 额外保留一份长上下文 KV-cache，显存与带宽都省——这比单纯换更小的 draft 模型更对症。
  3. 训练侧有可操作的配方：两阶段训练（先对齐局部预测、再联合优化）针对「异构无历史架构」设计，属于我们做推理加速微调时能直接照抄的流程骨架。
  4. 我们判断的适用边界（先读再试）：摘要只报接受长度（2–6）与对 DSpark 的相对提升（最多 70%），没有端到端延迟 / 吞吐，也没有精度损失数据 —— 接受长度涨不等于 wall-clock 一定降（顺序 head 有额外前向）；需要训练 draft head，落地成本高于「换个现成 draft 模型」；comment 未给代码；未做全文精读，数字为作者自报、本线未复现。
建议动作：先在我们 agent 轨迹上复现「接受长度随轮数衰减」这一现象（不改变任何训练），确认痛点存在；再评估 DLite 的两阶段训练是否值得投入。

  3. 结构清晰、好拆成动画：creator / reviewer / 选择机制 / 双层反馈四块，正好对应分镜的四段讲解，不需要碰公式。
  4. 我们判断的适用边界：① 摘要只给定性结论（更忠实、更一致），没有具体指标数值，用户研究的样本与评分细节在正文 ⇒ 不得据摘要写「提升 X%」；② 只验证「已有漫画改编」，未证明可稳定处理长篇连载；③ 改编他人漫画涉及版权，科普时须说明这是研究演示、不是可直接商用的工具；④ 未做全文精读，本线未复现。
