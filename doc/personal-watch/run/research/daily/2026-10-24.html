1HGM-Dual: Lineage-Aware Guided Agent Harness Optimization for Long-Horizon Planning

中文一句话
agent harness 优化（改 prompt / 工具 / 工作流）是在冻结或闭源 LLM 之上提升 agent 的常用手段；但 Darwin–Gödel Machine / HGM 这类「递归自改」方法是为代码任务设计的 —— 那里「改 harness 所需的能力」与「要被提升的能力」恰好重合。规划任务要求产出一串联合满足相互约束的工具调用，重合被打破，开放式自改就会反复做无效修改、烧掉大量评测预算。作者给出 HGM-Dual：把 agent 演化写成谱系感知上下文（记录每个祖先改了什么、哪些行为变好/变差、哪些修改无效），并做错误条件化的双路子代生成（通用探索子代 + 针对「父代排名最高的约束违反」的专用子代）。结果：相对最强基线 case accuracy 最多 +14.45%，且以 2×–4× 更少的评测预算达到 HGM 变体的最终性能。

推荐理由（借鉴 · ZhuLong agent harness）
  1. 正落在「harness 层」而非「权重层」：方法只改 prompt / 工具 / 工作流的组合，不改模型参数 —— 与 ZhuLong 在 execution-grounded EDA coding agent 上「generate–execute–refine」的调优空间同构，可直接借它的搜索框架。
  2. 「谱系感知」解决我们实际踩过的坑：harness 迭代到第 N 版时，人（和 agent）都会忘记「上一版为什么改、改了之后哪条指标掉了」；它把编辑 → 结果的归因显式写进上下文，等价于给 harness 版本管理加了一张可检索的变更-效果表（我们判断：这一条比 +14.45% 更有迁移价值）。
  3. 「错误条件化的双路子代」是预算分配策略：一半预算留给开放探索、一半精准打「当前最疼的约束违反」，比纯开放式自改少2×–4× 评测调用 —— 对我们这种评测本身要跑 EDA 流程、单次很贵的场景，预算项比精度项更关键。
  4. 边界（我们判断）：任务域是「带相互约束的工具调用序列规划」，不是 SWE-bench 式改仓库；+14.45% 是相对最强基线的 case accuracy 相对提升（摘要口径），基准名与所用 LLM 摘要未给，需读原文；无 EDA 实验，跨域迁移未验证；数字作者自报、本线未复现；未精读。

2LongZero: Enhancing Long-Context Reasoning in LLMs from Zero Data

中文一句话
用 RL 强化 LLM 的长上下文推理，卡在训练数据：人工标注贵、自然语料撑不起 RL、已有合成方法要么依赖外部语料、要么依赖更强的教师模型（模型越强越难找教师）。已有「零数据 RL」（模型自己出题自己做）只在短上下文任务上奏效。LongZero 把它推到长上下文：不让模型在已有文档上写问答，而是先自写「问题 + 答案 + 支撑证据」的紧凑结构，再把证据单独展开成长篇多文档上下文；把这种自写多跳推理任务与自写多轮检索任务结合，用 GRPO 训练。在 2 个 LLM、5 个长上下文推理基准上，LongZero 能泛化到真实任务，并优于「用外部语料合成数据做 RL」的基线。

推荐理由（借鉴 · BaiZe 长上下文后训练）
  1. 「零数据」直接对上我们的算力/数据约束：BaiZe 是从零训练 ~2B、数据配比敏感的小模型线；长上下文后训练若要外部语料或教师蒸馏，等于再引一条依赖。这条路只需自己的模型 + 可验证的答案就能起 RL，是成本最低的长上下文能力补充方案。
  2. 「先写证据再展开」是个可复用工程技巧：把答案正确性与上下文长度解耦 —— 先在短形式里保证可验证（答案 + 证据），再把证据铺成长多文档上下文。对我们「造长上下文评测/训练样本」同样适用，且不需要长文档原文。
  3. 两类任务合练：多跳推理（要串证据）+ 多轮检索（要决定何时再查）—— 这正是长上下文里最容易只训一半的两件事，作者把它们放在同一个 RL 里（我们判断：这个组合比单看某个基准分数更有参考价值）。

3Target Regeneration Shrinks the Gains of Draft-Training Objectives in Speculative Decoding

中文一句话
投机解码靠并行验证 draft token 来加速 LLM；新的 draft 训练目标通常把「相对外部撰写回答上的交叉熵所提升的接受率」记作功劳 —— 但很多流水线会让 target 模型重写这些回答。作者用视觉语言 target + block drafter，在同一语料的 4 个版本上训练 3 种目标（语料 token 上的交叉熵 / 来自 target 的 token 级蒸馏 / 只在「能通过验证的位置」上做门控的蒸馏），分别在外部回答与target 贪心重生成之后测增益。结果：蒸馏与门控在外部回答上增益很大，重生成后蒸馏只剩较小增益、门控几乎没有；这种收缩在数据顺序、位置权重、验证器、解码温度、蒸馏的初始化与学习率下都成立，在匹配监督长度、各目标最佳训练长度下也仍成立，第二个视觉语料与纯文本复现同样观察到。作者的结论是评测口径问题：收益应在「target 重生成的基线」上、并跨训练长度测量。

作者

推荐理由（借鉴 · BaiZe 高效推理）
  1. 它质疑的是「怎么算收益」，不是「怎么训」：投机解码论文常报「接受率提升 X 点」，但若 target 会重写这些回答，基线本身就变强了，增益被重复计入。这类口径问题一旦成立，会直接影响我们选 draft 目标时的判断（我们判断：这是本轮最容易被低估的一篇）。
  2. 收缩是稳健的，不是一次实验的偶然：数据顺序、位置权重、验证器、解码温度、蒸馏的初始化与学习率、监督长度匹配 —— 逐项扫过仍收缩，并做了第二个视觉语料 + 纯文本复现。这种「把结论往死里打」的做法，正是我们对内部结论的要求。
  3. 门控蒸馏在重生成后几乎归零：说明「只在能通过验证的位置上学」更多是在拟合外部回答的分布，而非提升对 target 的匹配 —— 对「我们要不要上 gated distillation」是一个明确的负面线索（可省一次试错）。
  4. 边界（我们判断）：主实验是 block drafter + 视觉语言 target，纯文本只是复现口径之一，不能直接外推到我们的文本 LLM 投机解码；摘要不给加速比 / 接受率绝对值，只给「增益收缩」的相对结论；作者自报、本线未复现；未精读（4 个语料版本与 3 个目标的定义需看原文）。
建议动作：读原文 §实验设置（4 个语料版本怎么造、重生成用什么解码）→ 我们自己的 draft 目标对比实验默认加一行「target 重生成基线」，并把评测长度扫到 2–3 个点，避免单点最优造成的假增益。
