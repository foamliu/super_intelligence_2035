1TokenGate: Adapting LLMs for Fast and Memory-Efficient Prefill with Learned Token Pruning

英文原题
TokenGate: Adapting LLMs for Fast and Memory-Efficient Prefill with Learned Token Pruning
中文一句话
让模型像人读长文一样先略读再精读：一个即插即用的小组件为每个 token 学出重要性分数，只把重要 token 送进后续层；在多种任务上 prefill 首 token 时延（TTFT）快 1.4–11.3×、峰值显存降 1.5–3.4×且精度不降，相对此前最好的 token 剪枝方法最多快 6.4×、省 2× 显存；原生支持标准 transformer（Qwen3）与混合注意力模型（Qwen3.5）。

推荐理由（对应 BaiZe 的长上下文 prefill 成本 / 混合注意力架构）
  1. 咬住的是我们真正贵的那一段：长上下文的主要开销在 prefill（每个 token 过每一层），而不是 decode。TokenGate 把「哪些 token 值得算」做成可学习的，直接压 TTFT 与峰值显存 —— 对应 BaiZe 在长文档 / 代码库类输入上的首 token 延迟与显存峰值。
  2. 「可学习 top-K 不可导」的解法可直接借用：作者用 token-gated attention（受 MoE 启发的门控，用重要性分数重加权 attention logits）绕开 top-K 的不可导问题，从而端到端训练。这是一个通用技巧：凡是「硬选择 + 需要训练」的场合（token 选择、专家路由、KV 淘汰）都能套。
  3. 适配成本低、且明确覆盖混合注意力：摘要说适配量级「与标准 PEFT 相当」，并原生支持 hybrid-attention 模型（Qwen3.5）——这正是 BaiZe 的 Mamba-2×attention 混合路线需要的能力（纯 transformer 的剪枝方法未必能直接搬到混合层）。
  4. 我们判断的适用边界（先读再试）：① 加速比是作者自报、且为「prefill 阶段」指标，decode 吞吐未给；② 「精度不降」依赖其评测任务集，摘要未给逐任务数字与剪枝率上限；③ 需要额外训练门控组件（不是纯推理期技巧）；④ 面向通用长文本 / 代码，不涉及 EDA 或存储负载，迁移到 ZhuLong 的 EDA 上下文需自建评测；⑤ 未做全文精读，本线未复现。
建议动作：先读其门控结构与训练目标两节，在 BaiZe 现有长上下文评测集上做一次「只加门控、不改主干」的小规模适配，量 TTFT / 峰值显存 / 精度三点；同时确认其 hybrid-attention 实现是否覆盖 Mamba-2 层。

2Kronecker Delta Rule for Long Context Linear Attention

英文原题
Kronecker Delta Rule for Long Context Linear Attention
中文一句话
给线性注意力的关联矩阵记忆换了条更新规则（Kronecker Delta Rule）：修正目标关联时只沿矩阵空间的单一方向改动记忆，从而比 delta-rule 更少干扰已存信息；作者证明其记忆动力学是一条收敛到稳态分布的马尔可夫链、记忆矩阵的期望范数在整条输入序列上一致有界，因此不需要额外的归一化/稳定机制；在长上下文基准上与其竞争的 (Gated) DeltaNet 家族相比「有竞争力、且常常更优」，代码与模型已开源。

推荐理由（对应 BaiZe 的 Mamba-2×attention 混合架构 / 长上下文记忆）
  1. 正打在混合架构的「记忆」部件上：BaiZe 走 Mamba-2 与 attention 混合，状态空间/线性注意力那条支路的长期记忆稳定性是关键。KronLSTM 直接改的是记忆更新规则，而不是外围技巧——它声称「无需额外归一化与稳定机制」，若能成立，等于省掉一类工程补丁（数值不稳、需要 clipping/renorm 的常见麻烦）。

3Same Simulation, Different Evidence: Where Retrieved Tool Output Costs LLM Agents Accuracy

英文原题
Same Simulation, Different Evidence: Where Retrieved Tool Output Costs LLM Agents Accuracy
中文一句话
用真实科学工具（USGS 地球化学模拟器 PHREEQC，单份报告可达 846.8k 字符）做 158 道执行可验证选择题：当 harness 把长工具输出存成文件、让 agent 按 section index 检索而不是放进上下文时，GPT-5.1 / GPT-5.2 准确率分别掉 11.3 / 7.9 分，Claude Opus 4.6 / Sonnet 4.6 无可测损失；复跑 11,007 次模拟调用发现失败不是「没算对」，而是证据替换——agent 跳过权威报告、拿自己更高精度的输出文件作答并舍入到邻近选项；点名权威输出可回升 6.3–7.9 分。

推荐理由（对应 ZhuLong 的 MCP 工具层 / generate–execute–refine harness）
  1. 正好是我们 harness 的设计取舍：ZhuLong 调工具（MCP）会返回很长的输出，我们的做法也是「落文件 + 按需读」。这篇把该做法单拎出来做受控对照（同一模拟器、同一批题，只改「报告在上下文 vs 通过索引检索」），并给出按模型不同的精度代价——这是我们此前没有量化过的。
  2. 失败机理非常具体、可直接在我们系统里查：证据替换（evidence substitution）——agent 明明跑对了模拟，却跳过权威报告、拿自己另存的更高精度输出文件作答并舍入错。我们可以在 ZhuLong 的工具返回链路里加一条检查：最终答案引用的证据，是不是工具官方的权威输出？
  3. 有一个低成本、可立刻试的修法：点名权威输出（naming the authoritative output）比普通检索回升 6.3–7.9 分；对 GPT-5.1/5.2，能放上下文就直接内联同样有效，而「要求正确舍入」无效。这条可以直接写进我们的 harness 规范（工具输出落文件时，显式标注「以下文件是唯一权威结果」）。
  4. 我们判断的适用边界（先读再试）：① 只测了一个工具 / 一个领域（地球化学 PHREEQC）+ 多选题，不是 EDA，也不是开放式代码修复；② 受测模型是 GPT-5.x / Claude 4.6 系列，与 BaiZe / 本地模型不同，结论不能直接外推到我们自研模型；③ 题目数 158、部分差异的统计显著性需看正文；④ comment 未声明代码，复现成本较高；⑤ 未做全文精读，数字为作者自报、本线未复现。
建议动作：先在 ZhuLong 现有 1–2 个长输出工具（如仿真/日志类）上复现「内联 vs 落文件检索」的精度差，并加上「权威输出点名」标注；把「最终答案的证据来源」纳入 harness 的回归检查项。

WildAIGC-Bench: Can AI Image Detectors Handle the Wild? A Benchmark of Generated and Edited Images in Online Circulation
中文一句话
实验室里「AI 图检测器」准确率很高，但网上流传的图被压过、被截图、被翻拍。作者持续从新闻网站、事实核查源与相关社交媒体收集，经自动筛选 + 人工逐图核验，做成 407 张「真在网上跑过」的 AI 生成/编辑图基准 WildAIGC-Bench，每张附来源网页链接与证据摘要；拿专门的检测器、多模态大模型和一个简单基线去测，发现相对既有基准出现明显的召回缺口——也就是该认出来的假图，没认出来。

推荐理由（对应《两分钟论文》的「大众看点 + 传播力」）
  1. 每个人都有体感：家族群里转发的「现场照片」、新闻配图、带货图——观众自己就见过。把「检测器在实验室很强、到了网上就不行」讲成一句话，比任何抽象指标都好懂。
  2. 「Wild」这个词就是全部卖点：不是重新生成一批干净图，而是保留图片在线上经历过的处理（压缩、截图、二次翻拍），并且每张都有人工核验的来源与证据。这让它更像「真实案件卷宗」，而不是又一张排行榜。
  3. 结论是可传播的警示：专门的检测器、多模态大模型、简单基线都存在明显召回缺口——即漏检。对普通观众的落点是「别把检测器当测谎仪」；对做内容/风控的人则是「上线前必须用脏数据验一遍」。数据集已开源，媒体与二创可直接引用。
  4. 我们判断的适用边界（先读再试）：① 摘要只给定性结论（「substantial recall gaps」），没有具体数值 ⇒ 本页不给任何百分比；② 407 张的规模适合做压力测试，不足以覆盖所有生成器与所有编辑手法；③ 数据来自新闻/核查/社媒，存在采集源偏置；④ 「漏检」高不等于「误报」低，实际部署要两者一起看；⑤ 未做全文精读，结论为作者自报、本线未复现。
建议动作：分镜用「一张图的三次转世」开场（原图 → 压缩 → 截图翻拍），再切检测器逐级失效；结尾落在「检测器不是测谎仪」，并提示数据集已开源可自查。
