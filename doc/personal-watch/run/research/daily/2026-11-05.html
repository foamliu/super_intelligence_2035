1ARLoop: Fully-Open Pre-trained Looped Transformers with Attention Residuals

中文一句话
Looped transformer 反复复用同一套层来「用参数换计算」，但标准残差把所有循环深度压成一条流、无法选择该复用哪一层的表示。作者把标准 transformer 的 attention residuals（按深度做注意力聚合）搬到循环深度上，并发现 looped 模型不需要完整残差历史——滑动窗口深度注意力在更大循环深度下即匹配或优于全历史。140M / 370M 受控实验（R=1–5）一致优于既有残差设计；再扩到 0.6B / 1.2B 的真实预训练配方，1.2B 仅用 0.5T token、3 次循环就在全部 8 个评测上超过唯一「全开放」的 looped LLM Huginn-3.5B，并与同量级非 looped 的 Qwen3.5-2B 有竞争力。
原题
ARLoop: Fully-Open Pre-trained Looped Transformers with Attention Residuals
作者 / 机构

推荐理由（借鉴 · 与 BaiZe / ZhuLong 的关系）
  1. 正中「用更少参数换更多计算」这条路线：R 次循环 = 共享参数、摊薄参数内存，是长鑫 AI 研究院关心的训练/推理总成本问题；论文给的不是「能省」，而是「怎么把循环深度用起来」——这正是我们过去只调宽/深/数据时缺的一维。
  2. 硬数字可回查：① 受控设置下相对 PreNormLoop，140M R=3 验证 PPL 16.59 → 16.03、370M R=3 12.28 → 12.17；② 收益随循环深度变大：R=1 约 −0.11 PPL，R=3 约 −0.53 PPL（作者原文口径），说明残差设计让「多循环」真的换到了计算；③ 1.2B / 0.5T token / R=3 在 8 个评测（ARC-C、HellaSwag、WinoGrande、OpenBookQA、GSM8K、MATH、MBPP、HumanEval）上全部超过 Huginn-3.5B，数学与代码提升最明显。
  3. 工程上更好抄的是「省」的那一半：looped 模型不需要保留完整残差历史，滑动窗口深度注意力即可 ⇒ 深度方向的激活存储 / 带宽按窗口大小截断，而不是随循环数线性增长。对显存紧的训练栈，这条比「换架构」更轻。
  4. 配方与基线都摆明了：PreNormLoop-0.6B（18 层 / R=3 / 180B token）↔ ARLoop-0.6B（同架构同预算），ARLoop-1.2B（24 层 / R=3 / 500B token）；复现时不必猜超参、只需对齐数据混合。
  5. 边界（必须写清）：① 最大只到 1.2B 参数 / 0.5T token，不能外推到 7B+ 前沿规模；② 作者自述 1.2B 在多数任务上仍低于 Ouro，归因于对方数据预算与数据质量更高（未做同数据对照）；③ 评测为 8 个基准的 zero-shot / few-shot 常规口径，未做长上下文与 agent 任务；④ 数字作者自报、本线未复现；⑤ attention residuals 源自 Kimi Team 2026 的既有工作，本文的贡献是把它适配到循环深度。
建议动作：读原文（§4 滑动窗口深度注意力的消融、§5.1 真实配方结果）+ 试跑（低风险）：在自有 0.3–0.6B 级模型上只替换残差聚合方式，QK 结构、数据、优化器全不动，先量「同 token 预算下的 PPL / 下游均值」差。

2LoopVQ: Sub 1-bit KV Cache Quantization for Looped Transformers

中文一句话
Looped 模型每循环一次就要各存一份 K/V ⇒ KV cache 随循环数线性膨胀，成了比参数内存更硬的瓶颈。作者观察到：looped 模型的 KV 沿 loop 轴高度冗余，且不同循环步对量化的敏感度差异很大。于是提出 LoopVQ：把多个循环步的通道联合编码进同一个向量量化码字，并用全精度模型的输出微调码本。0.5 bit/元素 时在通用、长链式思考、长上下文检索三类任务上超过面向标准 LLM 的 KV 量化方法；与 TaSQ 正交叠加后在 0.25 bit 仍保留大部分 BF16 精度；在 SGLang 中实现后，32K 上下文的 decode 延迟近乎减半，峰值服务吞吐最高 4.3× / 6.1×（Ouro-1.4B / 2.6B）。

推荐理由（借鉴 · 与 BaiZe / ZhuLong 的关系）
  1. 直接命中我们的推理成本结构：长上下文 / 长 CoT 下 KV cache 是显存与带宽的第一瓶颈；本文不换模型、不换解码策略，只改 KV 的存储编码，属于「改一条 slab 就能量到收益」的系统级改动。
  2. 硬数字可回查（Table 2，greedy，准确率 %）：Ouro-1.4B GSM8K BF16 78.77 → CQ 46.78 / TaSQ 57.32 / LoopVQ 75.82 / TaSQ+LoopVQ 77.56；MATH500 BF16 77.20 → CQ 17.80 / TaSQ 38.80 / LoopVQ 69.40 / TaSQ+LoopVQ 75.20 —— 0.5 bit 下两种基线明显崩，LoopVQ 基本守住，叠加后逼近 BF16。
  3. 系统收益量级明确：SGLang + 单张 RTX 6000 Ada（sink 8 / recent 64 留 bf16）上，32K 上下文 decode 延迟近乎腰斩；峰值吞吐相对 BF16 4.3×（Ouro-1.4B）与 6.1×（Ouro-2.6B）；0.25 bit 时 KV 压缩比达 64×（Figure 1a）。
  4. 工程细节可直接照做：① 缓存按 8 token / page 组织，sink 与最近窗口留 bf16 ⇒ 每页整体 bf16 或整体量化；② 一个 index 跨 Tc 个循环步共享，量化页只存「每 Tc 步一行 index」，因此不额外吃内存；③ 校准成本可忽略：Ouro-1.4B k-means 6.1 min + 微调 2.3 min（2.6B 为 14.3 / 5.9 min），16 条 × 2,048 token 的 GPQA 集外样本。
  5. 边界（必须写清）：① 只在 looped 族（Ouro-1.4B / 2.6B、Huginn-3.5B）上验证，标准 transformer 上未见收益证据；② 需逐模型校准 + 码本微调，不是零成本上线；③ 服务实验在 RTX 6000 Ada + SGLang，A100 数据在附录，未覆盖国产加速器；④ 精度损失在小模型上仍可见（如 Huginn-3.5B GSM8K BF16 34.04 → LoopVQ 32.37）；⑤ 数字作者自报、本线未复现。

3Stabilizing On-Policy Targeted Guidance in Agentic Reinforcement Learning

中文一句话
朴素 on-policy RL 常被基座能力卡住（某些行为一次都采不到 ⇒ 永远学不会）；而现代后训练的反馈往往是带评分细则的文本。作者把这类文本反馈变成方向性监督：仅在策略失败的轮次注入反馈、把「带反馈前缀的同一策略」当专家做 on-policy 自蒸馏（OPSD），再与逐准则 RL 奖励叠加。在 Qwen3-Coder-30B + 多轮软件工程环境里，7 项风格准则从基线 0.00–0.70 提到 0.55–0.99，而coding pass-rate 保持 0.33 不降；并给出两条稳定化做法：限制蒸馏权重（避免熵尖峰导致双崩）、把 KL 也施加到 thinking token（消除准则间振荡）。

推荐理由（借鉴 · 与 BaiZe / ZhuLong 的关系）
  1. 正对 ZhuLong 的 agentic RL 后训练：我们真正缺的不是「pass-rate 再提几个点」，而是「主奖励之外的一堆工程准则（工具调用格式、汇报结构、变更说明）能不能在不掉主指标的前提下学会」。本文正是这个问题的最小可复现实验。
  2. 硬数字可回查（Table 1，最后 32 步均值 ± 标准差）：TG = Markdown 0.85(基线 0.00) / Sol. Desc 0.95(0.70) / Req. Order 0.77(0.04) / Approval 0.55(0.00) / Cmd Ran 0.99(0.43) / Suggest 0.64(0.00) / Work 0.85(0.03)，pass-rate 0.33 ± .05（与基线 0.33 ± .05 持平）；对照组：GRPO Markdown 仍 0.00、OPSD pass-rate 掉到 0.30、Online SFT / LaTRO / Verifree 多数准则 < 0.05。
  3. 「只在失败轮注入」是关键设计，不是细节：论文给了反面证据——若反馈每一轮都给，coding pass-rate 反而回归；只在未满足准则的轮次蒸馏，修正后信号自动衰减到近零，因此既能探索又不污染主任务。
  4. 稳定性两条经验可直接进我们的训练脚本：① 崩溃前兆是策略熵尖峰（伴随输出变长、pass-rate 下滑）⇒ 蒸馏权重保持静态小值即可留在稳定区；② 把 KL 施加到 thinking token 上，策略不再在准则间来回振荡（Figure 7），thinking 轨迹里会主动出现「我要用 markdown 表格」这类自提醒。
  5. 边界（必须写清）：① 单一基座与自家 harness（Qwen3-Coder-30B + agentic coding SFT），换基座未验证；② 单一数据集、单 epoch、200 步、batch 32 groups × 32 rollouts、lr 3e-6、异步 RL（推理策略可落后于训练策略）；③ 准则由外部 judge 二值判定 + 固定反馈串，judge 质量就是上限；④ 风格准则偏「沟通规范」，不等于能力提升（论文明确目标不是提 pass-rate）；⑤ 数字作者自报、本线未复现。

4Same Layout, Different Count: What Number Words Do Past Ten in Text-to-Image Models

中文一句话
让文生图模型画「十二个」和「二十五个」同一种东西、只改提示词里的数字、其他全不动（同一物体 + 同一份起始噪声），画面布局几乎不变，而数量变得跟换一个随机种子差不多、且方向不定。作者用「同噪声」协议在 5 个开源模型（SDXL / SD3.5-M / FLUX.1-dev / FLUX.2 [klein] base 4B / Qwen-Image 20B）上逐个量「数字词的有效范围」：十出头就守不住（SD3.5-M、FLUX.1-dev 在十几之后不再跟随，SD3.5-M 的中位数量不管要求多少都停在 4.5–8.5；FLUX.1-dev 到「三十」反而缩到 1–2 个），FLUX.2 [klein] 与 Qwen-Image 能松散地跟到 25。反过来，把数量以噪点网格直接「画」进起始 latent（而不是只写在提示词里），人眼在 59% 的生成图里数出想要的个数，而只写在提示词里只有 4%。

推荐理由（科普 · 大众看点与传播力）
  1. 人人有的体验，被量化了：「让 AI 画 20 个杯子，它画不出 20 个」是公开吐槽；本文不靠模型自评，而是找没看过提示词的人去数 3,088 张生成图，把「十以上崩」变成一个可复现的实验。
  2. 反直觉且好讲：固定同一份起始噪声、只把「十二」改成「二十五」，布局留着、数量随便变；更妙的是只重画「比图像的八分之一更细」的那部分噪声，就既保住布局、又把数量挪动了「换新数字」的 2/3（0.69 倍） —— 一条两分钟视频能讲清的因果链。
  3. 结论可迁移到日常使用：想要数量准，别只在提示词里写数字，把数量当成构图信息给进去（59% vs 4%）。这是普通人立刻能试的操作。
  4. 连评测方法一起纠错（有科普深度）：超过十个之后，「精确匹配率」几乎分不开「大致跟随」与「完全忽略」（SD3.5-M 精确率 4%，「松散跟随」的模型 5–7%），相对误差甚至更偏爱固定猜 16 ⇒ 必须用同噪声对照才能分辨。这条对大众也有教育意义：看指标会被骗。
  5. 边界（必须写清）：① 只测 5 个开源模型，未测闭源模型（作者只引用他人结论说闭源同样很少精确）；② 计数用人工 + 检测器（SAM 3 等三种）交叉，物体类型限定在受控集合；③ 结论是「十以上数量词作用变弱/无方向」，不等于「模型完全没有计数能力」；④ 数字作者自报、本线未复现；⑤ 43 页含大量附录，公开数据以论文承诺为准。
建议动作：读原文（§4 同噪声协议、§5 细尺度噪声重画、§7 评测指标的可分性）+ 作为 《论文两分钟》当期 TOP-1（见 research/video/SCENES/11_05.html）。

5Where It Breaks: Diagnosing Perception, Memory, and Decision Failures of a Vision-Language Agent in Pac-Man

中文一句话
训练一个只会「上下左右」四个动作的吃豆人 agent（基座 Qwen3.5-9B），作者不满足于「一个漂亮分数」，而是把「看屏幕」与「选动作」拆开查：在主实验里把图像转录移出决策接口（改用文本棋盘），8 个固定留出迷宫 × 每格 96 局的通关从优化前 0/96 提到选定 checkpoint 的 77/96（论文另一处口径写作 0% → 80.2%，带三条命）；但完整轨迹并不单调 —— 最高 78/96（@335），最后一次完整校验（@425）回落到 60/96。感知侧则发现：静态截图读得很准的 agent，在实际交互中仍会误读；另一条 ASCII 策略线在继续优化后反而掉分，回放里出现「明明有出口却选了立即致命的动作」。

Where It Breaks: Diagnosing Perception, Memory, and Decision Failures of a Vision-Language Agent in Pac-Man

推荐理由（科普 · 大众看点与传播力）
  1. 画面自带：吃豆人是最广为人知的游戏画面之一，四方向动作人人都懂；「AI 为什么玩不好」比「新 SOTA」更容易让路人停下来看。
  2. 反直觉结论（本期最强钩子）：分数最好的 checkpoint 不是最后那个 —— 最高 78/96（@335），最后一次完整校验（@425）却是 60/96。「训练越久越好」的默认直觉在这里不成立。
  3. 拆解方式可复述：把「读屏」与「决策」分离 —— 感知用 RGB 截图 + 结构化盘面判读，决策用 纯文本棋盘，各自单独验；于是能说出「不是看不清，而是不会选 / 或选错」。
  4. 对普通观众的迁移价值：它给出的三条检查（在用中评测感知 · 区分训练成功与整局验证 · 别只看一个选定分数）可以平移到任何「AI 能不能真干活」的讨论，也顺手解释了很多 demo「演示很好、上线就崩」的现象。
  5. 边界（必须写清）：① 单一模型家族（Qwen3.5-9B）、单一游戏（吃豆人）、留出集仅 8 个固定迷宫；② 主实验用文本棋盘，作者自己强调该结果不等于图像策略的效果；③ 论文明确不给出 RL 失败的单一原因（prompt 兼容性、观测条件、起始分布、学习目标需要分开测）；④ 属「开发记录式」经验研究，非受控大样本对照；⑤ 机构未标注、数字作者自报、本线未复现。
