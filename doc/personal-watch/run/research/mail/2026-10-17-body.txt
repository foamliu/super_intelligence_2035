1. Compression Does Not End at Selection: Post-Selection Positional Geometry for Sparse KV Caches
   arXiv:2610.21126 ｜ 附件：是
   为何值得读：稀疏 KV 压缩只决定了「留下哪些历史状态」，但留下的 token 仍沿用原始全长位置坐标 —— 在 RoPE 下，被逐出 token 留下的位置空隙会继续干扰 query–key 匹配。本文研究「选择之后的位置几何」，提出 RoPERelay：给缓存键换一套紧凑且保序的 RoPE 坐标（逆旋转 + 再旋转迁移已缓存 key 的相位，并同步当前 query 与后续生成），复用既有 K/V，不重选、不重预填、不加缓存预算。跨 2 个模型 × 6 个稀疏选择器 × 3 个任务的 36 组对比。对口 BaiZe 的长上下文 / 高效推理 / KV cache 主线：与本线 10-16 已入库的 PN-Mix 正好互补（一个管「选哪些、存多精」，一个管「选中之后位置怎么摆」）；后处理式接入成本低，可叠在现有稀疏 / 窗口 KV 方案之上。⚠️ 数字为作者自报，未复现。

2. HPCAgent-Bench: A Framework for Sound Benchmarking of Code-Optimizing Agents, Harnesses, and Skills
   arXiv:2610.20673 ｜ 附件：是
   为何值得读：现有 coding-agent 基准把加速器 / 编程模型 / harness 固定死，拆不出各组件贡献，也看不出新增技能与工具是否值回成本。本文给出 689 个 kernel、3 条赛道（循环级优化 / 从 HPC 代码抽取的 kernel / 机器学习模型）；每个 kernel 只在 NumPy 写一次，再派生 C 与 Fortran 参考实现，提交经统一 C ABI 或 Python 接口接入，可跑 CPU/GPU、单机/多机；外部裁判用隐藏 fuzz 输入校验正确性并计时，堵住「针对测试系统作弊」。对口 ZhuLong 的 execution-grounded code agent / harness / 评测：其「harness、技能、工具的贡献」配对实验 + 加权 token 成本，可直接借用为「加一个 MCP 工具 / 技能是否值回成本」的度量方法学。⚠️ 数字为作者自报（comment 自述 20 页 / 9 图 / 17 表），未复现。

3. MLExpert: Towards a Generalist Agentic Model for Autonomous Machine Learning Engineering
   arXiv:2610.22344 ｜ 附件：是
   为何值得读：面向「AI 自主开发与改进 AI 系统」的长时程 MLE 任务，难点是每次实验的反馈混着此前多个决策的影响、且一轮 MLE 含大量昂贵实验。本文用后训练得到 MLExpert —— 35B MoE agentic 模型，配套 Kaggle-MLE Factory 造可执行任务与交互 harness；训练上做分层 agentic SFT + 窗口化交互 RL（WIRL，把两次结果之间的多轮决策打包成一个执行窗口共享结果奖励）+ 异步采集与策略校正。桥接 BaiZe（MoE / 后训练）与 ZhuLong（长时程执行）两条主线：其 credit assignment 设计与「可执行任务 + 长时程环境」构造范式都可迁移。⚠️ 数字为作者自报，未复现。

   arXiv:2610.22372 ｜ 附件：是
