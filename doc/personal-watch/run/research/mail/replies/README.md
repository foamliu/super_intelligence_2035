# research/mail/replies/ — 作者回信摘录（只做信息提取）

> 依据：`RESEARCH_MAIL_SPEC.md` §6/§7；用户令 2026-11-14（作者请教信「值得鼓励」+ 回信跟踪制度化）。
> **一个回信一个文件**：`replies/<arXiv_ID>.md`（无 arXiv 的用 `replies/<DOI-slug>.md`，如 `dramsim3.md`）。

## 文件模板

```markdown
# <arXiv_ID> · <论文短名> · 回信

- 收件人：<姓名>（<机构>）
- 发信时间：YYYY-MM-DD HH:MM  ·  回信时间：YYYY-MM-DD HH:MM  ·  延迟：N 天
- 我们问的（原文摘要）：① … ② … ③ …
- 对方答的（**原文关键句，英文照抄，不翻译不改写**）：
  1. …
  2. …
  3. …
- **可执行结论**（一句话，能落到动作）：…
- **归属线**：pretrain / vision / data / harness / designflow / zhulong（可多选）
- **建议采纳点**（写清改哪个文件/哪个判据）：…
- 是否含敏感信息：否 / 是（是 ⇒ 已报运维，未扩散）
```

## 纪律

- **只做信息提取**，不在回信里转述我们的内部训练细节。
- 回信若索要内部数据 / 未发表结果 / 合作署名 ⇒ **停手报运维**（§8 红线）。
- 每轮回信落盘后，**同时**更新 `发送记录.md` 的「回信状态」列（三值：`已回复` / `无应答(>14d)` / `未到期`）与心跳里的累计回信率。
- 摘录里出现的、对某条线直接可用的结论，必须在该线日报的「可执行建议」节被引用一次；否则视为没闭环。
