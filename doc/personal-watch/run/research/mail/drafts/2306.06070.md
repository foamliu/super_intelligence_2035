苏老师您好：

我是刘杨，做 LLM agent 研究，主页 https://foamliu.github.io/。我们在搭 Web 与工具任务的评测，需要决定「候选召回」与「动作预测」哪一段更值得投入。

读 Mind2Web 有一处想不透：86M 的 DeBERTa 做候选生成，三切分 Recall@50 达 88.9% / 85.3% / 85.7%，端到端成功率却低得多。这个差距主要来自动作预测的排序与定位，还是「正确元素在 top-50 内却未被选中」？候选池放宽到 top-100，端到端还能拿多少？

第二，137 个网站的快照会漂移，你们如何保证 2,000+ 任务半年后重跑仍可比（托管快照，还是定期重采并标版本）？我们想复刻三切分，这决定要不要自建快照仓。

第三，若判分从「元素匹配」改为「任务终态达成」，哪一档最先失效？会不会改写「跨域泛化差」的结论？

这三点分别决定我们的评测报告格式、快照治理与终态奖励定义。多谢您抽空。

祝好，
Yang Liu
