二、精选清单（3 篇「借鉴」）

1. HGM-Dual: Lineage-Aware Guided Agent Harness Optimization for Long-Horizon Planning
   arXiv:2610.30042 ｜ cs.AI ｜ Samsung Research America（6 位署名，前两位共同一作）｜ 附件：是（16 页 / 511,421 B）
   为何值得读：harness 优化（改 prompt / 工具 / 工作流）是在冻结或闭源 LLM 上提升 agent 的常规手段，但 Darwin–Gödel Machine / HGM 这类递归自改是为代码任务设计的 —— 那里「改 harness 所需能力」与「被提升的能力」恰好重合；规划任务要求一串联合满足相互约束的工具调用，重合被打破，开放式自改就会反复做无效修改、烧掉大量评测预算。HGM-Dual 做两件事：把 agent 演化写成谱系感知上下文（记录每个祖先改了什么、哪些行为变好变差、哪些修改无效，让编辑器能做「编辑—结果」归因）；错误条件化的双路子代生成（一半预算开放探索，一半精准打「父代排名最高的约束违反」对应的 harness 组件）。结果：相对最强基线 case accuracy 最多 +14.45%，且以 2×–4× 更少的评测预算达到 HGM 变体的最终性能。对我们的用处：ZhuLong 的 harness 调优可直接借它的搜索框架；对我们更有迁移价值的是那张「变更—效果台账」，能解决 harness 迭代到第 N 版后「忘了上一版为什么改」的老问题。边界：任务域是带相互约束的工具调用规划，不是改仓库；无 EDA 实验，跨域未验证；摘要未给基准名与所用模型，需读原文。

2. LongZero: Enhancing Long-Context Reasoning in LLMs from Zero Data
   arXiv:2610.30132 ｜ cs.CL ｜ 清华大学（2 位署名，通讯作者 Jianfei Chen）｜ 附件：是（17 页 / 574,366 B）
   为何值得读：长上下文 RL 卡在数据 —— 人工标注贵、自然语料撑不起 RL、已有合成方法要么依赖外部语料、要么依赖更强的教师模型（模型越强越难找）。已有「零数据 RL」只在短上下文任务上奏效。LongZero 的做法是：先让模型自写「问题 + 答案 + 支撑证据」的紧凑结构（短形式里保证可验证），再把证据单独展开成长篇多文档上下文；把这种自写多跳推理任务与自写多轮检索任务合练，用 GRPO 训练。2 个 LLM、5 个长上下文推理基准上能泛化到真实任务，并优于「外部语料合成数据」的基线。对我们的用处：BaiZe 长上下文后训练若不想再引外部语料 / 教师蒸馏依赖，这是成本最低的一条路；「先写证据再展开」也可直接用来造长上下文评测样本（不需要长文档原文）。边界：上限受自出题与自验证质量约束；摘要未给模型规模、上下文长度上限与训练算力；「优于外部语料基线」为作者自报、未复现。

3. Target Regeneration Shrinks the Gains of Draft-Training Objectives in Speculative Decoding
   arXiv:2610.29013 ｜ cs.CL ｜ 高丽大学 + 延世大学未来校区（4 位署名）｜ 附件：是（19 页 / 543,617 B）
   为何值得读：它质疑的不是「怎么训 draft」，而是「怎么算收益」。投机解码论文常报「接受率提升 X 点」，但这些增益通常是相对「外部撰写的回答」测的；若流水线里 target 会重写这些回答，基线本身就被抬高了，增益等于被重复计入。作者用视觉语言 target + block drafter，在同一语料的 4 个版本上训练 3 种目标（语料 token 交叉熵 / target token 级蒸馏 / 只在能通过验证的位置做门控的蒸馏），分别在外部回答与 target 贪心重生成之后测：蒸馏与门控在外部回答上增益很大，重生成后蒸馏只剩较小增益、门控几乎没有；该收缩对数据顺序、位置权重、验证器、解码温度、蒸馏初始化与学习率、监督长度匹配都成立，第二个视觉语料与纯文本复现同样观察到。对我们的用处：我们做 draft 目标对比时，「target 重生成基线」这一行应当默认加上，且评测长度扫 2–3 个点，避免单点最优造成的假增益；门控蒸馏在重生成后几乎归零，是一条明确的负面线索，可省一次试错。边界：主实验是 block drafter + 视觉语言 target，纯文本只是复现口径之一，不能直接外推到我们的文本 LLM 投机解码；摘要不给加速比 / 接受率绝对值。
