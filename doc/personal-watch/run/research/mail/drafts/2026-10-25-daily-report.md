二、早报精选（3 篇「借鉴」）

1. RIFT: KV Cache Compression for Draft Models with Complementary Compressibility Training
   arXiv:2610.31098 ｜ cs.CL ｜ NVIDIA（10 位署名）｜ 27 页 / 466,531 B ｜ 附件：是
   为何值得读：投机解码里，draft 模型要维护自己的 KV cache；这篇指出长输出时会发生「decode staleness」—— prefill 阶段选出的 KV 预算随生成长度推进而失准，draft 的接受率逐段下滑。做法是「基于选择的 KV 压缩」+ 生成期刷新 KV 选择 + 自适应刷新（少打分保延迟）+ 用稀疏注意力掩码驱动「可压缩性 draft 训练」；配合可压缩性训练后，Qwen3.5-4B → Qwen3.5-122B、32K 入 / 4K 出、8K KV 预算下仍保住 >98% 的满缓存接受长度。对我们的用处：长上下文推理成本是我们 P0 的硬约束，这套「KV 预算 + 生成期刷新」组合可以直接进投机解码方案的成本模型里试。边界：98% 是「接受长度」不是端到端加速比；主实验是 external draft，不在 MTP / EAGLE 类上验证；作者来自硬件/服务栈视角。

2. Edit, Don't Imitate: Minimal-Edit On-Policy Distillation for Multimodal Reasoning
   arXiv:2610.30231 ｜ cs.LG（+cs.AI）｜ Meta Superintelligence Labs 等（11 位署名）｜ 28 页 / 1,877,199 B ｜ 附件：是
   为何值得读：小模型多模态差，到底差在「看错图」还是「不会推」？作者用忠实图注做诊断：2B 模型接上正确图注后 Geometry3K pass@1 从 0.32 提到 0.46（8B 为 0.49）—— 说明相当一部分是感知瓶颈，可以分离。训练方法是「最小编辑纠错」的 on-policy 蒸馏：teacher 只对「它不认可的 token」给纠错损失，正确 rollout 走任务奖励 RL，且测试时不需要任何图注，零额外开销。对我们的用处：这是「小模型能力上限」主线的一个清晰拆解范式 —— 先判断瓶颈在感知还是推理，再决定是补数据还是补蒸馏；最小编辑损失的思路也能直接用到我们的多模态蒸馏配方里。边界：主战场是视觉数学 / 几何；teacher 名称与规模未披露；通用图像、OCR、图表未验证。

3. Forging More Tasks into Better Harnesses: Agentic Harness Evolution via Successive Scale Racing
   arXiv:2610.28815 ｜ cs.AI ｜ Michigan State University + Snap Inc.（5 位署名）｜ 28 页 / 605,702 B ｜ 附件：是
   为何值得读：直觉上「给 agent 的任务池越大越好」，这篇给出反例：任务池从 40 扩到 200 时，现有 harness 演化方法性能全面下降，作者把根因定位为「证据选择」而非任务数量。方案是 SSR：按质量与覆盖度造多样化证据组合，再小预算「竞速淘汰」筛选。3 基准 × 6 配置 SOTA，任务池 40→200 时通过率 64.3%→68.3%（基线全降），验证执行量还少 60%。对我们的用处：我们自己的 harness / 工作流自演化如果要上量，需要先解决「挑哪些任务当证据」，而不是堆任务数；竞速筛选也是一种低成本淘汰机制。边界：摘要未给 3 个基准名、harness 的表示形式与所用 LLM；「通过率」未必对应我们的正确性 / PPA 口径。

三、晚报精选（2 篇「科普」）

4. Can LLMs Improve Their Own Harness? A Controlled Study on ARC-AGI-3
   arXiv:2610.30499 ｜ cs.AI（+cs.SE）｜ Jens Lehmann, Sahar Vahdati（2 位）｜ 25 页 / 571,302 B ｜ 本日科普 TOP-1 ｜ 附件：是
   为何值得读：这是「AI 能不能自己改自己」这个问题少有的可复现对照实验。对象是包在模型外面的 harness（怎么观察屏幕、怎么记住上一关、什么时候调工具、失败怎么重试、一次想多久），模型自己写、自己改两轮；固定 5 个开发游戏，20 个从不参与改写的留出游戏，整个代码库只改两轮，共 27 条独立 lineage、81 个冻结快照、2,025 次游戏评测。结果很冷静：开发集平均 +8.42 分，留出集只 +2.80，95% 区间 [-1.44, 7.35] 跨过零，适应差 5.62；同一份冻结 harness 重复评测 10 次，样本标准差就有 3.99 分 —— 也就是说「涨 3 分」可能只是噪声。20 个留出游戏里 13 涨 7 跌（最大 +20.44 / -15.03）；27 条里只有 9 条既更好又更便宜（平均省 2.72 美元，中位只省 0.54 美元，平均数被少数大赢家拉高）。对我们的用处：① 评测纪律 —— 「自己考的」和「没见过的」必须分开报，且要报重复评测的方差；② 内部做 harness 演化时，留出集隔离与冻结快照是必须品。边界：单一基准、只改两轮、留出集 20 个游戏、成本按美元计价随供应商价格变化、人类主导系统流程不同不可直接比。

5. BeNice! Closing Looping's Inference-Memory Gap via KV-Sharing
   arXiv:2610.31633 ｜ cs.LG ｜ UCSD + Together AI（4 位署名）｜ 37 页 / 3,593,462 B ｜ 附件：是
   为何值得读：looped（循环）架构把同一组层反复过几遍，不增加参数就提升质量，但推理时每遍都生成独立 KV cache，显存随循环次数线性增长。已有工作发现「最后一遍的 KV 可以共享给前面几遍而不掉质量」，但机制不明，也不是所有同配方模型都具备（Parcae 1.3B 直接共享，困惑度 0.601 恶化到 2.281）。这篇给两阶段办法：预训练用 stochastic depth 诱导「收缩型残差动力学」，让各遍表示收敛到同一不动点；后训练 BeNice! 把最后一遍的 KV 广播给第一遍，并训练它产生兼容残差。共享时验证困惑度相对标准微调改善 9.75 分，不共享时质量持平；模拟低显存长上下文服务下缓存命中 +31.4%、吞吐 +23.6%、p90 首字延迟 -83.6%。对我们的用处：长上下文推理显存是我们绕不开的账，这条路线可以和 MLA / 量化等其他压缩手段叠加。边界：以困惑度与服务端模拟为主，未做端到端任务质量评测。
