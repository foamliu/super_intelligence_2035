我是刘杨，做序列建模与 agent 长上下文方向的研究，主页 https://foamliu.github.io/。TTT 把隐藏状态本身当成在线训练的模型，我们想借它判断「线性复杂度的状态容量」能换回多少长上下文能力，所以有三个实现层面的问题。

1. 你们取 TTT mini-batch b=16，消融说更小的 b 困惑度更好。推到 1.3B、上下文 32k 时，b=1 的精度收益是否还值得那份额外显存与 I/O？b 的敏感曲线是什么形状？
2. 内层学习率 η 做成输入 token 的函数、随外层一起训练，初始值与上界怎么定？早期有没有出现内层发散，用什么判据截断或回滚？
3. TTT-MLP 的瓶颈你们归到 memory I/O：状态放片上还是 HBM、隐维多大时性价比开始掉？

如方便，盼简短指点；答复会直接用于我们长上下文方案选型与成本口径。

祝好，
