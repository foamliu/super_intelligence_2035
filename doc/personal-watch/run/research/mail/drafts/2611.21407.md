王浩老师，您好：

我是刘杨，做 LLM agent 方向的研究，主页 https://foamliu.github.io/。我们在给 2B 级小模型搭执行外壳，读到你们把「外壳差异」和「模型规模」放进同一张 360 格梯子上评的工作，很受启发。

三个细节想请教：

1. 六个可执行检查全部禁用后，均值只动 +0.080 / +0.117 / +0.003 / −0.004，而单独去掉一条 repeat-blocking 规则在 0.75B 就掉 0.411。这是否说明收益主要来自「防止重复劳动」，而非完成判定本身？若要在小模型上把「停机判定」和「进度控制」的贡献拆开，你们会加什么对照？

2. 357 个可用单元里 127 个没留下声明的产物、其中 85 个正常退出。你们判分只认产物，还是同时保留 exit code / 文本匹配口径？这三种口径的分数差，在 4.7B 上是否比 0.75B 更大？

3. 18 个 artifact-producing 任务若换成依赖编译器、仿真器等外部工具的任务，Mingbird 的优势会不会被工具超时与重试吃掉？你们测过工具失败率对排名的敏感度吗？

这些答复会改我们的判分口径与任务集选型。谢谢公开预注册对比与失败分析。

祝好，
Yang Liu
