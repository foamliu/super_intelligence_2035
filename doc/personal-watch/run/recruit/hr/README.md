## 三、记忆系统（怎么用）

仿 **OpenClaw** 的四层写法 —— 纯 Markdown、无隐藏状态、**只有写进磁盘的才算记住**。

| 文件 | 层级 | 写什么 | 什么时候读 |
|---|---|---|---|
| `USER.md` | 用户模型 | **刘杨的稳定偏好**、沟通风格、授权边界（写成祈使句 directive，带 `observed/status`） | 每次会话开头 |
| `MEMORY.md` | **长期记忆** | **稳定的非档案事实与决策**：身份、判定标准、达标名册、铁律、平台事实 | 每次会话开头 |
| `memory/YYYY-MM-DD.md` | **情景记忆** | **当天发生了什么**：观察、动作、原文、结果 —— 细节都放这 | 按需检索（今天+昨天自动带） |
| `DREAMS.md` | 整理审核面 | 「做梦」整理时，**什么被提升进 `MEMORY.md`**、什么被取代 | 人工复核 |

**三条规矩**（详见 `memory/README.md`）：

1. **写，比检索重要** —— 没写下就等于没发生。
2. **细节进 daily，结论进 MEMORY.md** —— 别把流水账塞进长期记忆。
3. **偏好变了就原位取代**，不要追加一条打架的新指令。

## 六、铁律

| 🚫 红线 | 原因 |
|---|---|
| **不群发 / 不复制粘贴同一段** | Boss 反骚扰检测，雷同内容会被折叠甚至限流 |
| **批次人数（★ 2026-09-26 刘杨放宽）** | 原话「**不需要每批三人，可以更多**」→ **放宽的只是条数**；**逐人定制 1 行 / 每人之间 20–30s 停顿 / 全程盯风控**三项不变（09-19 实测 3 次触发风控的成因是**雷同内容 + 高频连发**，不是单纯条数） |
| **首句必须因人而异** —— ⛔ **不是「引用对方原话」**（那是错的，见 `MEMORY.md` §九 #12）；**只写你要他做的动作** | 同上 |
| **不发微信号 / 外部邮箱** | Boss 判私域引流 → 降权限流 |
| **不碰 Boss 约面控件** | 面试统一由 HR 约；草稿也不要发 |
| **简历接口不批量拉** | `/wapi/zpgeek/resume/...` 有独立风控 + 配额，返回 `code 7` |
| **不用新建 context** | 登录态只在 **MCP 默认 context** 里 |
| **不把「他投了什么岗」当「他是谁」** —— 判**在校 / 社招只看 Boss 会话头「简单简历」**（届别标签 / 教育在读区间 / 工作年限标签）；**「投社招岗」不是社招的证据** | 2026-09-23 刘杨纠正：一个字段没定义的分类，**不许自己补一个「看起来合理」的值** |
