### 发送前置检查（以后每次开跑先执行）

```js
// 在 www.zhipin.com 页面上下文内执行
```

## 2026-09-20 08:00–08:10 登录态恢复 + 新消息处理（刘杨提供新 cookie）

### 🔑 登录态恢复：cookie 必须用 `url` 形式注入

- **现象**：`www.zhipin.com/web/chat/index` 反复 302 到 `login.zhipin.com`，聊天页显示「**当前登录状态已失效**」。
- **根因（实测）**：
  1. 用 `domain:'.zhipin.com'` 注入 cookie 串时，**`wt2 / zp_at / bst / wbg` 四个鉴权 cookie 根本写不进去**（其余 11 个正常）；
  2. 页面里**残留着 `login.zhipin.com` 的旧标签**，`ctx.pages()[0]` 常取到它 → 每次「导航后仍跳登录」其实是在操作那个旧标签，**误判了 3 轮**。
- **解法**：改用 **`{ name, value, url: 'https://www.zhipin.com/' }`** 形式 `addCookies` → 再用 **全新标签页** 打开 `web/chat/index` → **一次成功**（显示「刘先生」+ 完整沟通列表，`li` 级别 DOM 齐全）。
- ⚠️ **教训**：判断登录态**必须新开标签页**再读 `.chat-message-list`，**旧标签的 URL 不可信**。
- 🕐 **时间基准**：本机时钟比 Boss 服务器**慢约 8 小时**（本机 00:05 时 Boss 页面显示 **08:05**）。
