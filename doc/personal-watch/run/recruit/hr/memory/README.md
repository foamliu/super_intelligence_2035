# memory/ · 情景记忆与写入规范

> 这套记忆系统仿 **OpenClaw** 的写法：**纯 Markdown、无隐藏状态、只有写进磁盘的才算记住**。
> 本文件是**规范**；`MEMORY.md` 是**长期记忆**；本目录里 `YYYY-MM-DD.md` 是**情景记忆**。

---

## 一、四层职责

| 文件 | 层级 | 内容性质 | 读取时机 |
|---|---|---|---|
| `../USER.md` | 用户模型 | 刘杨的**稳定偏好 / 沟通风格 / 授权边界**，写成祈使句 | 每次会话开头 |
| `../MEMORY.md` | 长期记忆 | **稳定的非档案事实与决策**（身份、口径、名册、铁律、平台事实、教训） | 每次会话开头 |
| `YYYY-MM-DD.md` | **情景记忆** | **当天发生了什么**：观察、动作、原文、结果、失败 | 按需检索（今天 + 昨天自动带） |
| `../DREAMS.md` | 整理审核面 | **什么被提升进长期记忆、取代了什么** | 人工复核 |

**分层原则**

- **细节进 daily，结论进 `MEMORY.md`。**
  daily 可以有 300 行原文与试错过程；`MEMORY.md` 一条结论一行。
- **`MEMORY.md` 不是日志。** 发现它开始记流水账，就把细节挪回 daily。
- **同一事实只在一个地方有权威版本**，其余地方只引用。

## 二、daily 文件格式

文件名：`YYYY-MM-DD.md`，**日期用 Boss 页面时间**（~~本机时钟慢约 8 小时~~ → 2026-09-26 实测：本机时间 = Boss 页面时间）。
一天一个文件；跨天续写请新建文件，**不要**把两天混在一起。

模板：

```markdown
# 2026-09-20 · Boss 招聘日结

**参与方**：刘杨（PI）· AI 代理
**Boss 时间跨度**：08:00 – 08:10
**一句话**：登录态恢复；回复 4 位达标者；顾嘉伟简历归档。

## 一、发生了什么
### 08:00 登录态恢复
- 观察：…
- 动作：…
- 结果：…

## 二、对外发出的消息
| 时间 | 姓名 | 内容 | 状态 |

## 三、候选人回复与判定
| 姓名 | 原话 | 判定 |

## 四、产物与文件
| 文件 | 说明 |

## 五、失败与误操作（必写）
- …

## 六、待办 / 需要刘杨决策
- …

## 七、候选记忆（待整理进 MEMORY.md）
- …
```

### 条目写法

- **事实优先，带证据**：写「他回『可以的 我学校就在上海』」，不要写「他同意上海」。
- **时间必有**：用 Boss 时间。
- **失败必写**：误触、误判、被风控、脚本报错 —— 这些是最值钱的经验。
- **区别「我做的」与「看到的」**：代理只做文本发送与简历抓取。
- 长度不设限，但**当天结束前必须写完**。

## 三、写什么去哪里

| 信息类型 | 去处 |
|---|---|
| 刘杨的偏好变了 / 新的授权边界 | `USER.md`（**原位取代**） |
| 新的稳定事实、决策、铁律、平台特性、教训 | `MEMORY.md` |
| 达标者、简历状态、口径变化 | `MEMORY.md` §三 / §八 |
| 当天的原文、观察、试错、清单 | `memory/YYYY-MM-DD.md` |
| 需要条件触发的未来动作 | `README.md` 待办 / `MEMORY.md` 未决 |
| 整理记录（提升 / 取代 / 待审） | `DREAMS.md` |

## 四、整理流程（「做梦」）

**触发时机**：一轮任务结束、或刘杨说「整理一下记忆」时。

```
1. 读最近几天的 daily
2. 提取「候选长期记忆」：稳定 + 会反复用到 + 不是当天才有的事
3. 对每条候选做三选一：
   ├─ 已有等价条目 → 合并（补证据，不加新行）
   ├─ 与旧条目冲突 → 原位取代（旧标 superseded，紧挨着写新条）
   └─ 全新 → 在 MEMORY.md 合适的小节新增一行
4. 检查 USER.md 是否超过约 4000 字符 → 超出就把细节挪去 memory/
5. 把本轮「谁被提升 / 谁被取代 / 为什么」写进 DREAMS.md
6. 清理 daily 里已提升的「候选记忆」段落（保留原文，只标注「已提升 YYYY-MM-DD」）
```

**原位取代示例**

```markdown
<!-- observed: 2026-09-19 | status: superseded -->
- 判定口径：学科顶会（含 EMNLP / MICCAI）。
<!-- observed: 2026-09-22 | status: active -->
- 判定口径：严格 CCF-A（EMNLP 不计）。
```

> 目的：**当前指令永远唯一、无歧义**。绝不在文件另一处再追加一条打架的新条款。

## 五、不要写进来

- 🚫 **凭据**：cookie、`securityId`、`wt2/zp_at/bst/wbg` 的值 —— 工作区可能被提交到 Git。
- 🚫 **大段聊天原话**：只引用**能支撑结论的那一两句**。
- 🚫 **简历里的个人信息**（身份证、手机号、邮箱、住址）。
- 🚫 猜测：**没核实的写「待核实」**，不要写成事实。
