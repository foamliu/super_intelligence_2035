| 项 | 口径 |

#### 2. 手机定位（定稿）

手机 = **眼 / 耳 / 口**：拍照取题、录音提问、播放讲解、显示引导。**不做推理、不跑大模型**。

#### 3. 智能体位置：三种方案都要给结论（用户明确在问这条）

| 方案 | 形态 | 优点 | 短板 | 本轮要求 |
|:--|:--|:--|:--|:--|
| **S1 云端 agent（推荐主路径）** | 手机上传（裁剪后的题干图/语音）→ 云函数/服务跑工具循环（题库/计算器/错题本）→ 返回 `{引导文本, 下一步指令}` → 手机朗读与显示 | 可随时升级模型/工具；手机端极薄；多端一致 | 依赖网络；原图上云需脱敏与告知 | ✅ **本轮必须真跑通一题**（真实 DeepSeek 调用） |
| **S2 PC agent（同构备选）** | 同 S1 的接口，实现在本机 PC（Python），手机连同一局域网调用 | 断网可用、演示稳、调试快 | 需要 PC 常开 | ✅ 与本轮 demo 复用同一接口（`/tutor`），作为 fallback |
| **S3 手机端 agent（用户设想）** | App 内跑 function-calling 循环（HarmonyOS NEXT 用 ArkTS + `fetch`；4.x 用 Kotlin/Java），工具限本地：相机 OCR(Core Vision Kit/MLKit)、TTS、本地题库、计算器 | 隐私最好（题图可不出端）、省云端编排成本、离线可用（模型仍可云端） | 后台任务受限（NEXT 后台时限、Android 易被杀）、长任务耗电、端侧工具弱、调试/回归成本高、模型仍在云端 | ✅ **给可行性结论 +（若时间允许）最小 demo**；结论写进 `P0_设备通路.md` 的「S3 评估」节，含：能否后台长连、能否调云 API、端侧 OCR 支持哪些语言/公式、包体与签名成本 |

**2.2 确认形态（影响硬件预算，先按 A+C 做）**：
