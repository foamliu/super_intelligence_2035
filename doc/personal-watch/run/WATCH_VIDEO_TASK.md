### 🔴 用户令 · 2026-11-07 11:55（**连续对话（免唤醒）：手机固定+常插电，进入"常听"模式，说话即答**）· 用户直令 · 最高优先 · 未完成

> **用户原话**：「因为这手机位置不动，可以时刻连接电源，因此可否连续对话而非每轮对话都要唤醒？」

#### 0. 结论（先给答案）

**可以，且应作为主交互形态。** 常插电 + 固定位置消除了连续对话最痛的两点（功耗、移动噪声误触发）；真正要解决的是三件事：**① 自听回声（AEC，TTS 被麦克风收回形成自激）② 端点判定（什么时候算"说完了"）③ 误触发（没人说话时不能乱答）**。§3 给出硬指标与降级路径。

#### 1. 交互形态（覆盖 11:40 令里的"每轮唤醒"假设）

1. **常听（ambient）是默认态**：上电即进入监听，**不需要唤醒词**；学生直接说话即可开始一轮。
2. 状态机在 11:40 四态前加一个**常听态**：
   `ambient(常听) --检测到人声--> listen --静音>=1.2s--> think --> speak --> wait_student --> (3s 无输入) ambient`
3. **不说话不算一轮**：只有「有效人声 + 端点」才触发识别与上传；环境噪声、翻书声、电视声不得触发。
4. **打断仍是最高优先**：`speak` 中一旦检测到人声 -> 300ms 内停播、丢弃在途回复、回 `listen`（学生抢话是常态）。
5. **控制权在用户手上**（必须有，不可省）：
   - 屏幕一键「静音」/物理可选静音；静音时麦克风**真关闭**（不是软件忽略）；
   - 麦克风被占用时**常亮指示**（状态栏/角标）；
   - 「结束会话」后回 `ambient` 但仍听，只有「静音」才真停。
6. **不追问轰炸**：`wait_student` 3s 无输入 -> 回 `ambient` 静默；🚫 不允许"你还在吗"式连环追问。

#### 2. 供电与设备保护（常插电的代价，必须处理）

| 项 | 要求 |
|:--|:--|
| 持续解码 | 允许（常插电），但**功耗要记录**：待机监听 <=1.5W，对话中 <=4W（估算值与实测都要给） |
| 电池健康 | 建议开启系统「智能充电/电池保护（上限 80%）」或旁路供电；连续满电 24h 视为不当使用，报告里要提示 |
| 温度 | 机身 >42℃ 自动降级为「按键说话（半双工）」并提示；>45℃ 暂停语音、只留文字 |
| 屏幕 | 常亮模式可配；默认「对话中亮、ambient 时熄屏但保持监听」；防止烧屏（静态元素每 5 分钟微移） |

#### 3. 硬指标（在 11:40 时延表基础上新增，全部要实测）

| 指标 | 目标 | 备注 |
|:--|:--|:--|
| **自听误触发率** | **0 次/10 分钟**（TTS 播放期间不得触发 ASR） | 这是连续对话的生死线；AEC 不过关就退半双工 |
| **无人声误触发率** | <=1 次/小时（安静房间 + 有人翻书/走动） | 记 false-accept/hour |
| **漏触发率** | <=5%（正常音量说第一句被漏） | 与端点阈值一起调 |
| **端点判定延迟** | 说完 -> 判定"说完" <=600ms | VAD 静音阈值可配（默认 1.2s） |
| **唤醒延迟** | **0ms（无唤醒词）** | 直接进入识别 |
| 首字出声 | <=800ms（沿用 11:40） | 配合流式 TTS |
| 打断延迟 | <=300ms（沿用 11:40） | 且不得把 TTS 自己的声音当打断源 |

#### 4. 降级与容错（写进 `INTERACTION_SPEC.md`）

1. **AEC 不达标** -> 自动切半双工：说话期间静音麦克风、说完才录（提示一次，不反复弹）；
2. **噪声高**（>65dB 估算）-> 提示靠近/换位置，并提高 VAD 阈值；
3. **网络差/断网** -> 端侧 VAD + 端侧 ASR 兜底或转文字输入；
4. **连续 3 次没听懂** -> 主动改成"文字输入 + 语音朗读"，并在报告里记录触发次数。

#### 5. 本轮验收（连续对话专项）

1. **10 分钟连续自由对话录音**（含：正常问答、学生抢话打断、走神静默、翻书噪声、TTS 播放中说话）；
2. **自听自激测试**：让 TTS 连播 60s，统计被自身语音触发的次数（**必须 0**）；
3. **误触发统计**：静音房间 1 小时（或加速等价样本）false-accept/hour；
4. **功耗与温度**：待机/对话两档的功率与机身温度曲线（可用系统 API/日志抓）；
5. 更新 `INTERACTION_SPEC.md` 的「常听态 + 降级矩阵」两节，并在 HTML 报告里给出上述 4 组数字。

> 🚫 不要为了"能连"而牺牲「可停」：静音必须真关麦；🚫 不要在未见 AEC 数据前就宣称"支持全双工"。

#### 1. 交互模型（定稿，照这个做，先写进 `INTERACTION_SPEC.md`）

1. **一次只推进一步**：每次回复 <=2 句、每句 <=20 字；说完立即进入「等学生」状态，🚫 不连续刷屏、不重复同一句。
2. **四态状态机**：`listen(听) -> think(想) -> speak(说) -> wait_student(等)`，外加 `clarify(澄清)` / `encourage(鼓励)` 两个异常态；**任一时刻只处于一态**，状态必须在日志与界面上可见（调试与评测都靠它）。
3. **打断（barge-in）**：学生一开口 -> **立即停 TTS** 并翻转到 `listen`，打断响应 <=300ms。
4. **三层提示阶梯**（禁止跳级、禁止给最终答案）：
   - L1 反问思路（"你打算先处理哪一项？"）
   - L2 拆一小步（"先把 3 移到右边看看"）
   - L3 给同类示例（**换掉原题数字**，不泄漏答案）
   连续 2 次答错 -> 自动降一级 + 一句鼓励；连续 3 次 -> 建议休息或换题。
5. **指认联动（先做轻量版）**：学生说"这一步/第二行" -> 屏幕对应行高亮；摄像头手势指认**本轮不做**。
6. **语音优先、文字兜底**：默认 TTS 朗读；屏幕同步显示**同样内容** + 当前步骤高亮；静音/嘈杂环境可切纯文字。
7. **会话边界**：开场一句说明"我只提示思路，不直接给答案"（<=15 字）；结束给一句总结 + 下一步建议。

| 指标 | 目标 | 实现要点 |

| 静默超时 | 6s 无输入 -> 轻声追问 1 次；再 10s -> 休眠 | 🚫 不连环追问 |
