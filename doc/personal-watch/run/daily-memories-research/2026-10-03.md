### 坑 / 修复
1. HTTP 端点是 **301** → 必须 HTTPS。
2. **`200 ≠ 有料`** → 必须校验类型 + 解析 + 非空 + 日期。
3. 12 查询 ×3s 超 30s 命令上限 → 后台 `nohup` + 轮询。
4. `--query` 分支原先忽略 `--out`（只打印不落盘）→ **已修**。
5. `--query` 人类可读输出**三处硬取键**导致崩溃：`window_hours` 用 `%dh` 却收到 `"n/a"`、`per_query` 硬取 `name`/`kept`、entry 硬取 `areas`（后者只有 `fetch_all` 才补）→ **均已修**（`%s` + `.get(...)` 兜底）。
6. 空 feed 原先 `ok=True`（违反"空 feed 一律判失败"铁律）→ **已修**（改 `ok=False`）。
7. 并发请求 → **HTTP 429**（实测）。故新增 **429/503 有界退避重试**（`retries=2` / `retry_backoff_seconds=20`）；**其余失败仍一律判 FAIL**、不静默。
8. 新增**离线回归测试** `research/test_arxiv_fetch.py`（**不联网**，31 项断言）：覆盖 Atom 解析 / `200≠有料` / 空 feed / 429 重试 / 时间窗 / `_fmt_human` 两种形状 / `--query --out` CLI → **`31/31 PASS`**。
