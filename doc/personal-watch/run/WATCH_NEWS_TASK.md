## 0.1 什么是「新闻」（入账判据 · **硬性**）

> ⚠️ 本线**只收"新闻"**。**不符合下面 4 条的一律不算新闻** —— 它们可能仍有价值，但必须**移入文末「非新闻」区**并打类型标签，**不得混进"新闻"条目里**。

**新闻 = 对「刚发生的、可核验的具体事件」的时效性报道。4 条必须同时成立：**

| # | 判据 | 说明 |
|:--|:--|:--|
| 1 | **时效** | 事件发生于最近：**日报口径 ≤ 72 小时**（周报 ≤ 7 天）。**过期长文不算。** |
| 2 | **事件性** | 报道一个**具体发生的事**：发布 / 决定 / 事故 / 数据 / 人事 / 诉讼 / 收购 / 政策落地…。**泛论、专栏、教程、心得不算。** |
| 3 | **报道体** | 来源是**新闻机构**或**官方公告**（在报道他人）；**不是**作者第一人称观点、公司软文、Show HN 自述、论坛讨论。 |
| 4 | **可核验** | 有具体事实点：**谁 / 何时 / 什么数字或决定**。 |

**典型反例（一律不进"新闻"）**：
- 特稿 / 长读（feature / long-read）、观点 / 专栏（opinion / op-ed）；
- 个人博客 / Substack / Medium 分析；
- 论文 / preprint（**例外**：当"某机构发布了某论文"本身是**事件**时，按**发布事件**报并注明"论文发布"）；
- 论坛帖（Ask HN）、Show HN 自述；
- 工具 / 仓库上线（**例外**：有官方**发布公告**时按公告报）；
- 软文 / 赞助内容。

**非新闻怎么处理？** **单列**到文末「**附录 · 非新闻（分析/观点/论文/工具/讨论）**」区，并打**类型标签**：
`🏷 类型：news | analysis | opinion | feature | paper | tool | discussion`
（只有 `news` 进各大类的"新闻"条目。）

**每条新闻必带字段**：`标题` + `来源` + `发布日期` + `🔗 链接` + `🏷 类型：news`。

## 2. 每轮采集 SOP（**每次唤醒照此执行**）

1. **读现状**：`MEMORY_NEWS.md` 顶部快照 + `news/SEEN.md`（已收录，避免重复）+ `news/<今天>.md`（已写部分）。
2. **定窗口**：确认**上次采集时间**（见 `MEMORY_NEWS.md` 流水）→ 本轮优先覆盖**上次之后**的新增。
3. **逐类搜索**：对 §1 每类跑 1~3 条查询（**优先用 `search_news`**；中文补充用 `web_search`），拿到候选列表。
4. **筛与去重**：
   - 与 `SEEN.md` 比对**链接**（主键）与**标题**（近似）→ 命中即跳过；
   - 只保留**与关注清单相关**且**有明确来源**的条目；
   - 目标量：**每轮 8~20 条**（宁精勿多，**不凑数**）。
5. **落盘**：把新条目**追加**到 `news/<YYYY-MM-DD>.md`（格式见 §3），并把其链接/标题写入 `news/SEEN.md`。
6. **更新索引**：更新 `news/INDEX.md` 的当日计数。
7. **回写状态**：更新 `MEMORY_NEWS.md` 顶部快照 + `WAITING`；当日流水追加 `daily-memories-news/<date>.md`。
8. **提交**：`git add` **只加本线文件**（`MEMORY_NEWS.md` `news/` `daily-memories-news/`）→ `commit -m "news <date> <n> 条"` → `push`。

> ⏱ **不要 sleep / 不要等待**：一轮做完就更新记忆并退出（loop 会按 `WAITING` 决定何时唤醒下一轮）。

## 3. 输出格式

### `news/<YYYY-MM-DD>.md`（当日摘要，同轮多轮则追加）

```markdown
# 新闻摘要 · <YYYY-MM-DD>

> 采集窗口：<上次时间> ~ <本次时间> ｜ 本轮新增：<n> 条 ｜ 来源：<...>

## 1. 前沿模型与能力
- **[标题]**（<来源>，<YYYY-MM-DD>）
  摘要：<2~3 句，忠实原文>
  🔗 <URL>
  🏷 关联：<可选，本书章节/主题，如"第32章 制度新生">

## 2. AI 安全与对齐
- ...（无新增则写：_本类无新增_）
```

**字段硬要求**：`标题` + `来源` + `发布日期` + `🔗 URL` **缺一不可**。
可选 `🏷 关联`（与本书的连接）**属判断**，若写必须措辞为**我们的观察**，不得冒充原文。

### `news/SEEN.md`（去重台账）

```markdown
# SEEN — 已收录条目去重台账

| 首次收录 | 标题 | 来源 | 链接 |
|:--|:--|:--|:--|
| 2026-10-03 | <标题> | <来源> | <URL> |
```

> **主键 = 链接**；标题近似亦视为重复。每轮落盘后**同步追加**。

## 4. 铁律（红线，**违反即失败**）

1. 🚫 **不许编造**：**必带**链接 + 发布日期 + 来源；**无来源不收录**。搜不到就写"未找到"。
2. 🚫 **不许把推测写成事实**：摘要区分「原文说了什么」与「我们的判断（须显式标注为观察）」。
3. 🚫 **不采集需登录/付费墙的正文**：只引用公开可见的标题/摘要 + 链接。
4. 🚫 **不整篇转载**：只做摘要 + 链接（版权）。
5. 🚫 **不 `git add -A`**：只加本线文件（共享工作副本，会卷入他人在途文件）。
6. 🚫 **不在正文/快照/流水写以 `WAITING:` 开头的行**（会误触发 loop 长睡）。
7. ⚠️ **控制频率**：单轮查询数受限（§2.3），避免对同一站点高频抓取；尊重 robots。
8. ⚠️ **不占 GPU、不登录训练机**：本线只做网络采集与文本整理。

## 5. 记忆维护（**硬性**）

> 理由：`MEMORY_NEWS.md` **每次唤醒都被 agent 全文读取** → 越大越烧 token。

- **上限**：`MEMORY_NEWS.md` 控制在 **≤ 32KB**；一旦超限即执行滚动。
- **滚动**：把**较早的流水条目**（保留最近 ~20 条）**追加**到 `daily-memories-news/<条目日期>.md`（原文不改），再从 MEMORY 删除。
- **顶部必须保留**：① `WAITING:` 行（**仍只出现一次**）② 状态头 /「进度快照」③ 「运维问答」④ 最近 ~20 条。
- **纪律**：归档**不改变任何结论**；`WAITING:` 纪律不变。
