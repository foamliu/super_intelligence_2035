### 🖼 运维指令 · 2026-11-11（**配图双令：采集存图片 URL + 试切「图文文章」通道**）· 用户直令 · 最高优先

> 用户原话：「1.采集层只需要存图的URL；在发表前下载图片就够了。」
> 「2.让news自己尝试一下发 /w/ 微头条（改用「图文文章」入口）。如果顺利就切过去。」

**背景**：news 现在走的是 `/w/` 微头条（纯文字、≤400 字），`news/<date>.md` 采集记录只存标题/摘要/链接，**无图片 URL**；发文一律无图。用户要求补上配图能力。

**① 采集层：每条入账记录必须多存一个图片 URL 字段（不做下载）**

在 `news/<YYYY-MM-DD>.md` 每条新闻下，除现有「摘要 / 🔗 链接 / 🏷 关联」外，**新增**：

```bash
  🖼 图片：<首图绝对 URL>
```

- **只存 URL，不下载、不落盘、不入 git**（下载留到发布前，见②）。
- 取图优先级：① RSS `enclosure` 的 `url`（`type` 为 `image/*`）→ ② `content:encoded` 里第一个 `<img src>` → ③ 正文页第一个 `<img>`（取 `src` 或 `data-src`，排除 `logo`/`icon`/`avatar`/`1x1`/`base64:`）。
- 相对路径必须补成绝对 URL。
- **取不到就写 `🖼 图片：无`**，不许留空、不许编造、不许拿别的新闻的图顶替。
- 每轮在采集总结里报一句：`本轮 11 条 · 有图 N 条 · 无图 M 条`。

**② 发布前才下载，且只下当次要用的那 1 张**

- 只对**本轮要发布的那一篇**下载图片，存到 `run/news/toutiao/imgs/<YYYY-MM-DD-HHMM>-<slug>.<ext>`。
- 下载后**必须校验**：文件存在、大小 > 5KB、扩展名与 Content-Type 一致；任一不过 ⇒ 该篇放弃配图，走纯文字（不要卡住发布）。
- 🚫 图片**一律不 `git add`**（沿用 2026-10-24 截图禁令，`.gitignore` 已覆盖位图）。
- 发布证据仍按老规矩用**文字数值**记录（post_id / 计数变化 / 图片文件名），不用截图。

**③ 通道切换：先实测，顺利再切（本令的核心）**

**本轮（下一次唤醒）必须做一次实测，不许跳过：**

1. **保留现有的 `/w/` 微头条发布**（本日配额照常，不要因为测试停发）。
2. **额外做一次「图文文章」发布实测**（新通道，用一篇已入库的选题）：
   - 打开头条**图文文章**（长文）发布入口，不是 `/w/` 微头条入口；
   - 正文用草稿（≥300 字，可基于当日已入账新闻扩写，**数字仍须先入账**）；
   - 上传②下载的那 1 张图（单图即可，不追求九宫格）；
   - 完成发布，记录**文章真实 URL**（`/article/` 或 `/item/` 形态，不是 `/w/`）。
3. **判定「顺利」的四条硬标准**（全过才算顺利）：
   - ① 发布成功，拿到非 `/w/` 的文章 URL；
   - ② 打开该 URL，**图片正常显示**（不是破图、不是占位）；
   - ③ 后台**无版权/搬运/低质警告**；
   - ④ 页面「作品声明：内容由AI生成」正常展示。
4. **结果处理**：
   - **四条全过 ⇒ 下一轮起切换主通道为「图文文章（带 1 图）」，微头条降为辅助（话题性强/时效急的走微头条）。** 切换时同步更新 `MEMORY_NEWS.md` 的 PHASE 与 `STYLE.md` 的相关约定。
   - **任一条不过 ⇒ 保持微头条为主，不切。** 把**卡在哪一条、报错原文、现场 URL**写进 `daily-memories-news/<date>.md` 与 `MEMORY_NEWS.md` 阻塞区，**下一轮不许重复试同一个失败路径**，先报 blocker 等用户裁断。
5. 🚫 **不许伪造结果**：没发出去就写没发出去；图没显示就写没显示。测不出来也是有效结论。

**④ 版权红线（配图必守）**

- 只配**单张**、且**在正文注明来源**（如「图：IT之家」）或改用平台免费图库图。
- 🚫 不搬他人多图图集、不搬带水印的独家图、不把别人的图当自己的现场图。
- 🚫 图上不得出现二维码 / 微信号 / 外链短址 / 其他平台水印（下载后肉眼或 OCR 检一遍，有就换图或不配）。**外链判定口径见 §4「④-a」，与此处一致。**
- 拿不准就不配图——**纯文字发布永远优于违规配图**。

**⑤ 位图纪律（本条**取代**原「禁止上传截图」令，是位图的唯一口径）**

> 原 2026-10-24 令：「为什么 news 上传很多截图呢，删掉，不要上传截图。」→ 已并入本条，2026-11-11 起不再单独列条。

位图分两类，**规则只有一条：任何位图都不进 git**。

| 类型 | 用途 | 可生成 | 可上传平台 | 可入 git |
|:--|:--|:--:|:--:|:--:|
| **截图**（`shots/`） | 发布自证 | ✅ | ❌ | 🚫 |
| **新闻配图**（`imgs/`） | 文章配图 | ✅ 仅发布前下 1 张 | ✅ | 🚫 |

- 🚫 **一律不 `git add`** `.png/.jpg/.jpeg/.webp`；`.gitignore` 已覆盖 `run/**` 下所有位图。
- 历史已清理：**255 个截图（~65MB）** 已 `git rm --cached`，本地文件保留。
- **配图可上传到平台，但不入库**；截图只作本地自证，不上平台。
- 如需入库单张图，**必须用户明确授权**后 `git add -f`。
- **证据写法**（截图不得作为唯一证据）：用文字给「时间戳 + 数值 + 路径」，
  例：`15:02 微头条已发布 · 后台计数 481→482 · post_id=1879883432500423 · 截图存 shots/xxx.png（未入库）`。
- **提交前自检**：`git status --porcelain | grep -Ei '\.(png|jpe?g|webp)$'` —— **有输出即误提交，立即撤出**。

## 0.1 什么是「新闻」（入账判据 · 硬性）

> ⚠️ 本线只收"新闻"。不符合下面 4 条的一律不算新闻 —— 它们可能仍有价值，但必须移入文末「非新闻」区并打类型标签，不得混进"新闻"条目里。

新闻 = 对「刚发生的、可核验的具体事件」的时效性报道。4 条必须同时成立：

| # | 判据 | 说明 |
|:--|:--|:--|
| 1 | 时效 | 事件发生于最近：日报口径 ≤ 72 小时（周报 ≤ 7 天）。过期长文不算。 |
| 2 | 事件性 | 报道一个具体发生的事：发布 / 决定 / 事故 / 数据 / 人事 / 诉讼 / 收购 / 政策落地…。泛论、专栏、教程、心得不算。 |
| 3 | 报道体 | 来源是新闻机构或官方公告（在报道他人）；不是作者第一人称观点、公司软文、Show HN 自述、论坛讨论。 |
| 4 | 可核验 | 有具体事实点：谁 / 何时 / 什么数字或决定。 |

典型反例（一律不进"新闻"）：
- 特稿 / 长读（feature / long-read）、观点 / 专栏（opinion / op-ed）；
- 个人博客 / Substack / Medium 分析；
- 论坛帖（Ask HN）、Show HN 自述；
- 工具 / 仓库上线（例外：有官方发布公告时按公告报）；
- 软文 / 赞助内容。

### 🆕 论文 / preprint 口径（2026-11-11 用户令 · **取代旧禁令**）

> 用户原话：「把news（论文 / preprint不能做新闻）的禁令清理掉，允许「引用 research 已核验条目」。news 的选题标准在 research 领域放宽。」
> 「论文中就有图，也有研究机构和个人联系方式，很有话题性，属于第一手新闻（直接接触信源不通过新闻社），很有价值」

**旧口径「论文 / preprint 不进新闻」已作废。** 新口径：

| 情形 | 处理 |
|:--|:--|
| **A. 引用 research 已核验条目** | ✅ **直接可入"新闻"**，走 §0.1 例外，标 `🏷 类型：news · 来源：research` |
| **B. 自行发现的论文（有机构/公司正式发布）** | ✅ 可入，按"发布事件"报（如「OpenAI 发布 X 模型技术报告」） |
| **C. 纯方法论文、无机构发布动作** | ⚠️ 进「附录 · 非新闻」，除非能提炼出**大众可感的事件点** |
| **D. 论文本身无话题度（过于垂直）** | 🚫 不报 |

**论文作为第一手信源的合法性（用户明确认可）**：
- 论文**自带图片**（架构图/结果图/示意图）→ 可直接作为配图（须注明「图：论文 <arxiv_id>」）
- 论文**自带研究机构与作者联系方式** → 属**一手信源**，优先于二手新闻社转载
- 但要守：**不直接联系作者**（研究线的作者信职能另计，本线不得擅自发信）

非新闻怎么处理？ 单列到文末「附录 · 非新闻（分析/观点/论文/工具/讨论）」区，并打类型标签：
`🏷 类型：news | analysis | opinion | feature | paper | tool | discussion`
（只有 `news` 进各大类的"新闻"条目。）

每条新闻必带字段：`标题` + `来源` + `发布日期` + `🔗 链接` + `🏷 类型：news`。

## 2. 每轮采集 SOP（每次唤醒照此执行）

1. 读现状：`MEMORY_NEWS.md` 顶部快照 + `news/SEEN.md`（已收录，避免重复）+ `news/<今天>.md`（已写部分）。
2. 定窗口：确认上次采集时间（见 `MEMORY_NEWS.md` 流水）→ 本轮优先覆盖上次之后的新增。
3. 逐类搜索：对 §1 每类跑 1~3 条查询（优先用 `search_news`；中文补充用 `web_search`），拿到候选列表。
   - **🆕 3-b 先查 research 日报（2026-11-11 用户令）**：每轮开工先看 `run/research/daily/<今天>.html` 与 `index.html`。
     日报里凡标了 `news_ready` 的条目（含大众化标题 + arXiv 链接 + 已核验数字 + 可选配图 URL），**直接列为候选**，
     按 §0.1「论文口径 A」处理。**不重复做 research 已做的核验**（PDF 下载 / 数字比对），但要自行确认
     「该论文是否已被主流媒体报道」——若已被 IT之家/量子位等报过，则改引媒体报道，不重复造标题。
4. 筛与去重：主键 = 链接 + 标题近似（查 `SEEN.md` 中英文专名 + 译名双查）；只留有明确来源的相关条目；每轮 8~20 条（宁精勿多）。
   - 与 `SEEN.md` 比对链接（主键）与标题（近似）→ 命中即跳过；
   - 只保留与关注清单相关且有明确来源的条目；
   - 目标量：每轮 8~20 条（宁精勿多，不凑数）。
5. 落盘：把新条目追加到 `news/<YYYY-MM-DD>.md`（格式见 §3），并把其链接/标题写入 `news/SEEN.md`。
   - **每条的 `🖼 图片` 字段必须填**（2026-11-11 令）：按优先级取首图绝对 URL（RSS `enclosure` → `content:encoded` 首个 `<img>` → 正文页首个 `<img>`，排除 logo/icon/avatar/1x1/base64）；取不到写「无」。**只存 URL，不下载。**
   - 顶部「配图覆盖：有图 N 条 / 无图 M 条」必须与实际条目数一致。
6. 更新索引：`news/INDEX.md` 当日计数 +1 行摘要。
7. 回写状态：更新 `MEMORY_NEWS.md` 顶部快照 + `WAITING`；当日流水追加 `daily-memories-news/<date>.md`。
8. 提交：`git add` 只加本线文件（`MEMORY_NEWS.md` `news/` `daily-memories-news/`）→ `commit -m "news <date> <n> 条"` → `push`。

> ⏱ 不要 sleep / 不要等待：一轮做完就更新记忆并退出（loop 会按 `WAITING` 决定何时唤醒下一轮）。

## 4. 操作要点（禁令见文首「📋 禁令总表」，本节只讲**怎么做**）

1. **数字先入账，再发布**：正文里任何数字/比例/奖项/金额，发布前须满足「`news/<date>.md` 有对应条目 + 可点链接 + `SEEN.md` 已登记」，否则只写定性表述。
   - **例外（2026-11-11）**：引用 `research/daily/<date>.html` 已核验条目视为已入账，需 ① `news/<date>.md` 写 `📄 引用 research <date> · 论文 <arxiv_id> · <一句话>`；② 附 `https://arxiv.org/abs/<arxiv_id>`；③ 数字后标「论文作者自报，本号未复现」。二手转述不算。
3. **不占 GPU、不登录训练机**：本线只做网络采集与文本整理。
4. **台账诚信**：台账/日志只记真实发生的事；允许标 `record-only(补记/自检)`；跨天重复运行只算 1 天。
5. **指标未达标如实写**：写「未达标 + 当前实际值」，不许改口径/挑样本/刷台账/改时间戳。
6. **审批后方可执行的技术细节**：
   - **后台批处理必须 `setsid`**：`nohup setsid python3 x.py > out 2>&1 < /dev/null &`（否则 shell 退出会连带杀掉）。
   - **`RECHECK mine=false` 不作失败判据**：新楼常落进「查看全部 N 条评论」折叠区 ⇒ 判据 = **评论计数 +1**。
   - **IT之家正文只认 RSS 原链 + 先比对 `<title>`**：省略日期的短链会回落到同 ID 旧文；标题不一致 ⇒ 不得标「正文全文已读」、不得入账。
   - **前台 30s 超时 ≠ 作业被终止**：`nohup setsid … &` 报超时后作业常已跑完 ⇒ 读日志判结果，**不要重复发布/评论**。
7. **大文件（≥5MB）走网盘**：首选 `bypy`，备选 `BaiduPCS-Go`；路径/提取码/文件名登记进 `INDEX_FILES.md`。
   - 目录须先有 `.gitignore` 规则；`git add` 前用 `git check-ignore -v <file>` 自查。
   - **元数据仍要入 git**：`INDEX_FILES.md` 记 路径/行数/字节数/sha256/存放位置。
   - 网盘也不可用 ⇒ 宁可不传（本地保留 + 清单登记 + `PROGRESS.md` 写「未上云」）。
   - 📌 存量：`news/archive/chinanews-2016~2025.jsonl.gz`（≈94MB，单个 5.4–12.3MB）为旧口径遗留，存量迁移由 ops 统一处置；本轮起不得再 `git add` 任何 ≥5MB 文件。
