L3 算法交易❄️ 冻结不做❄️ 冻结

阶段门：G1（L1 内部）· G2（L2 自身：价格复测 + 方法预注册 + 默认只做描述性统计）· G2′（L1"扎实"标准：基线 + 提前期 + 覆盖 + 连续 N 周）· G3（L3 解冻）。

9附：一个可观测性问题（静默期无法区分"在跑 / 停了"）

现象：本报告生成时（12:30），personal-watch 最后一次提交在 09:27/09:31，已静默 ≈3h；而 BaiZe 线同期一直在提交。从 git 端无法判断"是在跑长任务，还是已经停了"。
根因（机制）：① news 的 N1 续抓 / L1 链重跑 是长任务（单轮可跨小时）； ② agent 只在有文件变更时才提交； ③ loop 的兜底 auto-commit 间隔 = PUSH_INTERVAL=18000s = 5h（实测 auto-commit 在 04:23 / 09:27）。 → 三者叠加 ⇒ 3–5h 的静默既有可能是"在干活"，也可能是"停了"，无法区分。
建议（低成本）：
  1. 缩短兜底提交间隔（如 1800s）—— 最省事，但需改 loop.sh + 重启；
  2. 或让 agent 每轮写一行心跳（如向 daily-memories-*/<date>.md 追加时间戳）→ 有提交即证明活着（只改任务书，不需重启）；
  3. 或在 MEMORY 快照里加 LAST_WAKE: 字段（每轮更新）。
👉 推荐第 2 种（零重启成本）。
