supervisor 的四个动作

  1. 派活：在任务书「🔧 运维指令区」加带日期的 block（新块放最前），commit + push。
  2. 巡检：git pull 读 MEMORY_*.md 顶部快照 + 产物目录（不登录服务器）。
  3. 验证：不只看 agent 自述——亲自复跑它的输出（如 §3.4 的 --cn-news）。
  4. 回写：把结论/教训写进 MEMORY.md + daily-memories/。

worker 的自适应唤醒

MEMORY_<线>.md 顶部的 WAITING 驱动 loop 睡眠：

  • WAITING: 0（有近期待办）→ 睡 60s，连续推进；
  • WAITING: 1（无近期待办）→ 睡 1800s（30min）省 token。

两条线的数值与已生产验证的 BaiZe loop 完全一致（这不是巧合，是 §5 第 4 条）。

5⭐ 核心产出：关键教训与铁律

今天最有价值的东西不是那 54 条新闻或 61 篇论文，而是这 13 条被"打脸"换来的规则 —— 它们已写进任务书与 supervisor 记忆。

  1. 🔴 「接口 200 ≠ 有料」（本线最有价值的产出）。 死源与活源在 HTTP 层长得一模一样：新华网 RSS 返 200/300 条却停在 2022；央视 RSS 返 200 却停在 2006。 只有 pubDate ≤72h 的硬校验能区分它们。 → 已入两线任务书铁律。
  2. 关键术语必须在任务书里给出可操作定义。 "新闻"没定义 → agent 收了一堆特稿/观点/博客。没定义的词，agent 会按最宽口径填充。
  3. 连 LLM 的建议/诊断也要实测。 ① DeepSeek 力荐"央视 RSS 是官方长期维护通道"→ 实测是 2006 死源； ② "联合国源 unable to parse 是 UA 被拦" → 实测 4 种 UA 全 200，真因是 URL 写错（/zh/rss 404 返 HTML）。 "想当然"今天已错两次。
  4. 别自创数值，先照抄已验证的模板。 loop 睡眠我一度自造 6 小时 → 用户质问"BaiZe 有 6 小时吗？" → 核查：BaiZe 实为 SLEEP_BUSY=60 / SLEEP_WAIT=1800，从无小时级睡眠。已完全对齐。
  5. 模型名必须用「规范 ID」。 照抄 BaiZe 的 deepseek-v4-pro-fp4 → 本机网关不认；实测 GET api.deepseek.com/models → 官方只有 deepseek-flash / deepseek-v4-pro（deepseek-v4-flash 也不是官方 ID）。
  6. cline 报错可能仍返回 exit 0。 模型名错/额度耗尽时 cline 打印 error: 却退 0 → loop 分辨不出，会"静默白睡"。→ loop 现会 tee 输出 + 命中致命特征即强制短睡重试。
  7. 记忆文件 ≤ 32KB（照 BaiZe）。 理由：MEMORY_*.md 每次唤醒被全文读进上下文 → 越大越烧 token，且会无上限增长。超限即滚动到 daily-memories*/。
  8. 验收标准要钉在「产出物」上，不能停在「接口通不通」。 agent 曾"验证 12 个 API 都 200"却一条真新闻都没产出。→ 现在验收看的是条目、pubDate、中文占比，并由 supervisor 亲自复跑。
  9. 「200 ≠ 有料」的第 3 次命中：连"官方 RSS"也会空。 rss.arxiv.org/rss/cs.LG → 200 application/rss+xml 但 0 条目， 原因写在 feed 里：<skipDays>Saturday/Sunday</skipDays>（arXiv 周末不发）。 → 官方/权威 ≠ 有内容；只有"日期 + 条目数"能证伪。
    （三次命中：新华 RSS 2022 / 央视 RSS 2006 / arXiv RSS 周末空）
  10. 顶流源也会"滞后"，别当新鲜源用。 HF Daily Papers API 实测 publishedAt 滞后 3~8 天（09-25~09-30）—— 它是"人工/社区精选"，天然晚于 arXiv。 → 定位为质量加权/标注，不是"最新"源。
  11. 规则要有"周期适应"，否则会误杀。 news 线的 ≤72h 直接搬到论文线就错了：arXiv 工作日公告、周末停更 → ≤72h 在周末/周一早会把真有货的窗口判成"无新增"。 → 改为「≤72h，周末/周一放宽到最近公告批次，并标注实际区间」。同一铁律，换场景要重新校准。
  12. 源不可达时，"如实说不"比"编一个"更有价值。 research 的 R1′ 复验：arXiv ✅ / HF Daily Papers ❌ 不可达 / arXiv RSS 周末空 —— 它没有伪造 hf_daily，而是改用 HN 热度并注明替代关系。 → "做不到"要写进产物，不许用假数据填。
  13. 规则写对了，agent 会自己按规则"报 0"。 R2′（周末放宽 120h + weekend_batch）上线后，第 3/4 轮 如实报"新增 0（周六 arXiv 未公告）" 而不是硬凑—— 这正是 supervisor 预判的场景。→ 好的规则让"没有"也能被正确表达。
  14. 估算前先问"计量单位是什么"。 我一度把"10 年 ≈200 万条 × 2s"算成 >45 天 → 结论"不可行"；错在按"条"算。 方案 C 是按"天"枚举（1 天 1 个列表页）→ 3650 请求 ≈ 2–3 小时，完全可行。 → 量级估算的"单位"错了，结论就会南辕北辙。
