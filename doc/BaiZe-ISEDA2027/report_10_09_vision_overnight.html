2. Why the Old Conclusion Was Invalidated

The original scaling report (report_vision_aimv2_scaling.html) concluded that widening the vision tower from 512→768 decreased linear-probe accuracy by 5.59pp (29.35% → 23.76%, Protocol B). However, operator review of §11 (reproduction commands) revealed a critical confound:

PropertyOld (§7, superseded)Problem
--lr3e-3High lr designed for short runs
--warmup20 steps0.01% of 187,101 steps — effectively no warmup
ScheduleConstant (no decay)No annealing — lr stays at 3e-3 for 99.99% of training
Origin30k-step short-run recipeCarried over unchanged to 187k steps + wider model

The 3e-3 / warmup 20 / const schedule was originally designed for 3,000-step ablation runs (R8 recipe). When applied to a 187k-step long training with a wider model (284.54M for E2), the near-absent warmup + high constant lr may have systematically disadvantaged the wider arm — making it impossible to attribute the Δlp to model scale rather than schedule pathology.

Decision: The old conclusion is invalidated. A fair rerun is required with a schedule appropriate for long training. The old report now carries a ⛔ banner; old results are preserved as "schedule sensitivity evidence."

5. Code Changes

5.1 r9_train.py — Cosine Scheduler Support

The training script r9_train.py previously only supported a constant lr after warmup. The following changes were made:

  • New CLI arguments: --scheduler {const,cosine} (default const for backward compatibility) + --min-lr (default 5e-5).
  • lr_at function rewritten: Warmup phase unchanged (lr*s/warmup); after warmup, cosine mode computes min_lr + 0.5*(lr−min_lr)*(1+cos(π*(s−warmup)/(steps−warmup))), const mode maintains original behavior.
  • LoRA branch synchronized (text_finetune path) to avoid leaving a half-broken schedule.
  • 4-point lr self-check printed to train.log before training starts: lr@step0, lr@warmup, lr@50%, lr@last — with monotonicity verification.

Verified via py_compile + smoke_cos test (30-step run confirming lr trajectory).

13. Limitations

  • Single budget point: This experiment tests only one training budget (~187k steps, ~96M pairs, 1 epoch). A single point does not constitute a scaling law. The "indistinguishable" conclusion is specific to this budget.
  • Data-limited regime: Our ~96M image-text pairs are 102× smaller than AIMv2's ~12B. R9/R10 already established a data-limited regime where tower widening yields no lp benefit. This fair rerun is consistent with that finding.
  • Two widths only: Only two model widths (w512=126.78M, w768=284.54M) were tested. A fuller scaling study would need ≥3 points to fit a power law.
  • Single training seed: Training uses seed=1234 (single run). Only evaluation uses 3 seeds. Training-seed variance for Δlp is not measured.
  • Old results not re-evaluated: The old E1/E2 checkpoints are preserved but were not re-evaluated under Protocol B with 3 seeds — only original single-seed numbers exist for them.

What this report covers vs. what it does NOT cover

  • Covers: The complete overnight scaling fairness rerun — from invalidating the old "bigger is worse" conclusion, through the new fair cosine recipe design, code changes, data fairness fix, to final results for all four stages (E1fair + E2fair, training + evaluation). Both Protocol B (3-seed mean±σ) and Protocol A results are reported. The key finding: Δlp (Protocol B) = +0.17pp → indistinguishable; the old −5.59pp was a schedule artifact.
  • Does NOT cover: A scaling law. This is a single budget point (~187k steps, ~96M pairs, 1 epoch) with two model widths. The "indistinguishable" conclusion is specific to this budget and data scale. Extrapolation to other budgets or data scales is not supported.

  • Sign flip note: Δlp is +0.17pp under Protocol B but −0.17pp under Protocol A. The sign reversal across evaluation protocols means there is no systematic width effect in either direction — the magnitude (0.17pp) is well within noise of cross-protocol variation.
  • Training loss ≠ lp: E2fair has lower training loss (0.1579 vs 0.2545), meaning the wider model fits training data better, but this does not translate to higher linear-probe accuracy. This is consistent with the data-limited regime hypothesis.
