BaiZe Stage(iii) 视觉编码器 · Round 3 根因诊断报告（R3）

判定 eval5k 检索 R@1/5/10 = 精确随机 的根本原因：模型训练坍缩（非训练不足 A / 非评测 bug B）
📅 完成：2026-10-01 🖥️ 诊断跑在 10.239.2.12（GPU 0–7 空闲） 🧪 三架构复证：OpenVision2 / MambaEye / 双目标 SigLIP+CLIP 📦 数据：en500k（训练）/ eval5k（检索）

🎯 R3 一句话结论

eval5k 检索 R@1/5/10 = 1/5000·5/5000·10/5000（精确随机）不是「训练不足（A）」，也不是「评测脚本 bug（B）」，而是模型训练中 vision+text 双塔发生表征坍缩（退化为常量输出，余弦相似度 = 1.0），检索排序纯随机。这是第三条成因，且比 A/B 更根本。

  • 🔑 双塔坍缩实锤：OpenVision2 与 MambaEye（纯 SSM）的 image/text 特征 same-tower 余弦 min=max=1.0000；CLIP 臂也近坍缩（cos≈0.99）。
  • 🔑 「loss=4.45」= 坍缩均衡：scale=5.68 / bias=−9.09 代入 SigLipLoss 算术得 3.467 + 31×0.0320 = 4.459 ≈ 实测 4.456 —— Round 1/2 的「loss 四架构不可区分」是坍缩均衡点，不是有效学习结论。
  • 🔑 300 步即复现：单卡短训 300 步即精确坍缩到 cos=1.0；冻结 text 塔 / 固定 bias=0 均不能阻止坍缩 → 根因是「从零 + 每-batch 对比 + 少量负样本 + 可学习 scale/bias」整套 recipe。
  • 📌 对论文：loss 与 eval5k R@K 一律作废为「坍缩伪阅读数」；仅保留不受坍缩影响的计算侧结论（OpenVision2 训练 2017 img/s / 推理 6.87ms 双最优）。

1.2 检索本身 = 精确 chance（坍缩外显症状）

eval5k（n=5000）上所有余弦相似度相等（mean_diag=0.9961 = mean_offdiag，max_offdiag=1.0000）→ ranking 由数值噪声决定，R@1/5/10 恰等于 1/5000=0.0002, 5/5000=0.0010, 10/5000=0.0020，与 R2 落盘值完全一致（n=1000 复测 = 0.001/0.005/0.010）。

SigLipLoss = −logsigmoid(label·(sim·scale+bias)).sum()/N，坍缩态（sim≈0.9956）代入 S8 的 scale/bias：logit=0.9956×5.6827−9.0937=−3.4361 → f_pos=−logsigmoid(−3.4361)=3.467、f_neg=−logsigmoid(+3.4361)=0.0320 → loss=3.467+31×0.0320=4.459 ≈ 实测 4.456。✅ 分毫不差 —— 「loss 4.45 四架构不可区分」是坍缩均衡 loss；CLIP 臂把温度 exp(scale)=410 放大去锐化噪声，同为坍缩自一致读数。

2R3.1 裁定：A / B / 第三条

  • 不是 A（训练不足）：S3 已跑到 10k 步仍钉在 4.45（R2-0 结论），延长 horizon 无意义；修复探针更进一步——坍缩在 300 步内就已精确达成（§4），证明它是损失地形的吸引子/均衡，而非收敛不充分。
  • 不是 B（评测脚本 bug，狭义）：eval_downstream.py 正确、r3_stepA_diag.py 复算一致；自检索 sanity 也“看似 100%”（diag≈offdiag≈0.996）——但这是因为连 off-diagonal 也是 0.996（坍缩签名），而非评测配对正确。
  • 是「训练坍缩」（representation/modal collapse）：vision 与 text 双塔均退化为近常量输出（cos 1.0），与输入无关，因此检索排序全随机。这外显为 B 的症状（精确 chance），但要靠训练侧修复而非评测侧。

一句话：eval5k R@K=精确随机 是「特征坍缩」的下游症状；真正需要修的是预训练 recipe。

3步骤 B / C 裁减说明（优先级 A>B>C，逆序裁剪）

  • B（R3.3 延长至 20k 步）裁减：坍缩是损失均衡平台（S3 10k 已平台），延长 horizon 不会离开坍缩态；证据充分（§1.5 算术值 + §4 三百步内坍缩）。
  • C（R3.4 换同源 held-out）裁减：特征与输入无关（恒为常量），同一源/跨源/自检索都只能是随机；换 eval 集不解决「模型已坍缩」。
  • 二者浪费预算且无信息增益，按任务书「超时按逆序裁剪」原则裁减，预算让给「控制实验 + 修复探针」。

r3_fix_probe.py：单卡、en500k、batch=64、SigLIP、300 步、随机 init，末态量双塔 same-tower 余弦。三配置：

  • 300 步、单卡、64 batch 即精确复现全量训练（3000 步·6 卡·32 batch）的坍缩 → 坍缩不是 DDP/batch-size/horizon 副产物，是 objective 的固有吸引子。
  • 冻结 text 塔（随机 init）不够：视觉塔仍坍缩到 0.9965。随机 text 塔自身特征高度相关（cos≈0.67），视觉塔可直接退化到「平均文本方向」而不必学到区分。
  • 固定 bias=0 也不够：偏置只是坍缩「模式」的旋钮（同向→反平行），不是坍缩「是否发生」的开关。真正驱动力是「从零/随机 init + 每-batch 对比（少量负样本 32/64）+ 500k 对 + 可学习 scale/bias 梯度饥饿」整套 recipe。
  • 学到的 scale→5.68 / bias→−9.09（4 架构几乎同值）是坍缩态的共点解：bias≈−9 使正例对 logit 恒为负、scale 只放大噪声；特征梯度被 scale/bias 吸收（梯度饥饿），特征本身走不动。

结论：修复不能靠一行改动；需要换 recipe（§6）。这解释了为什么 R2 的“提高 LR / 换分辨率 / 换架构 / 换目标函数”全都钉在坍缩态。

5论文回填建议（关键，直接可用）

原则：R2 及更早的「loss」与「eval5k R@K」读数全部作废为「坍缩伪阅读数」，不得作为 encoder 质量的代理指标。

  • tab:visobj（目标函数 SigLIP vs CLIP）：❌ 不可用 4.456 vs 3.270（SigLIP 是坍缩均衡 loss、CLIP 是温度爆表后的锐化噪声，量纲与含义都无意义）。✅ 表注如实写：「从零 recipe 下，SigLIP 与 CLIP 均发生表征坍缩，无有效 loss 代理指标」；仅「训练吞吐≈相等（1645 vs 1657 img/s）」可保留。
  • tab:visarch（架构对比）：❌ 不可用「loss 4.45 四架构不可区分」——它只是坍缩均衡点，与架构无关，不是「架构对表示学习无影响」的证据。✅ 保留吞吐/延迟排序（OpenVision2 训练 2017 img/s / 推理 6.87ms 双最优），此为架构结构属性、不受坍缩影响。
  • tab:visres（分辨率对比）：❌ 不可用「256/576/1024 token 的 loss 并列」——同样坍缩。✅ 仅保留吞吐/延迟随 token 的趋势（注意 R2-3 已记的 batch 不一致 caveat）。
  • 总建议（R3.5 允许的「如实写无有效代理指标」）：论文应落一句方法论说明——「在 500k 对、从零初始化、双塔联合训练的 recipe 下，contrastive 预训练双塔发生表征坍缩，loss 与检索 Recall 均为坍缩的下游读数；本项目现阶段不提供有效的 semantic 质量代理指标，仅提供计算侧（吞吐/延迟）对比。」
  • 把坍缩本身写成发现：这本身就是个可发表的方法论警示（contrastive collapse under small-data from-scratch joint training），比硬凑一个不存在的指标更诚实、更有价值。

6修复方向（Stage iv / 未来工作，超出 R3 范围）

  1. 换初始化：text 塔用预训练/固定的语义 text encoder（设计意图本就是「固定 text tower，只动 vision」——当前代码 train.py 把双塔都塞进 optimizer 联合训练，偏离了设计意图）。仅冻结随机塔不够（§4），需要有语义的 text 塔让 diag/offdiag 可分。
  2. 压住 scale/bias：冻结 logit_scale（合理初值）与 logit_bias（0 或冻结），阻断梯度饥饿。
  3. 加大负样本 / 更大 batch：标准 CLIP 需数百万对与上千负样本，500k 对 + 32 batch 的每-batch 对比先天易坍缩。
  4. 换目标：若要小数据自监督，用重构型（MAE/MIM）或加 uniformity/anti-collapse 正则，而非纯 contrastive。
  5. 上述均需重训并重评；在此之前，论文不要给出任何 semantic 代理指标读数。
