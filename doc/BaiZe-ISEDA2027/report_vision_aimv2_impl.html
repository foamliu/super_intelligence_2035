2. 视觉 Trunk — OpenVision2（纯 Attention ViT）

代码：run/vision/models.py。OpenVision2 是一个标准纯-Attention ViT，从零初始化。

2.1 PatchEmbed (L144–153)

144class PatchEmbed(nn.Module):
145    def __init__(self, image_size, patch_size, width):
147        self.grid = image_size // patch_size
148        self.conv = nn.Conv2d(3, width, patch_size, patch_size, bias=False)
149        self.pos = nn.Parameter(torch.randn(self.grid * self.grid, width) * (width ** -0.5))
151    def forward(self, x):
152        x = self.conv(x).flatten(2).transpose(1, 2)
153        return x + self.pos
  • 224 / 16 → grid = 14×14 = 196 patches。
  • 位置编码 = 可学习 randn × width^−0.5，196 个 token。

2.2 AttentionBlock (L53–64) — Pre-norm ViT block

53class AttentionBlock(nn.Module):
56        self.norm1 = LayerNorm(dim)
57        self.attn = Attention(dim, heads)
58        self.norm2 = LayerNorm(dim)
59        self.mlp = SwiGLU(dim, mlp_dim)
61    def forward(self, x):
62        x = x + self.attn(self.norm1(x))
63        x = x + self.mlp(self.norm2(x))
  • Attention 用 F.scaled_dot_product_attention（flash attention，L48）。
  • FFN = SwiGLU（silu(gate(x)) * up(x) → down，L24–32）。

2.3 OpenVision2 + ReadoutHead (L156–185)

156class ReadoutHead(nn.Module):
159        self.norm = LayerNorm(width)
160        self.proj = nn.Linear(width, embed_dim, bias=False)  # width→768
162    def forward(self, x):
163        x = x.mean(dim=1)           # global average pool over patches
164        return self.proj(self.norm(x))
168class OpenVision2(nn.Module):
169    def __init__(self, image_size=224, patch_size=16, width=1024, depth=30, heads=16, mlp_dim=4096):
174        self.embed = PatchEmbed(image_size, patch_size, width)
175        self.blocks = nn.ModuleList([AttentionBlock(width, heads, mlp_dim) for _ in range(depth)])
177        self.norm = LayerNorm(width)
178        self.head = ReadoutHead(width)
179    def forward(self, x, return_patch=False):
180        x = self.embed(x)
181        for b in self.blocks: x = b(x)
183        x = self.norm(x)
184        pooled = self.head(x)
185        return (pooled, x) if return_patch else pooled

关键设计：return_patch=True 时返回 (pooled, patch_features)：

  • pooled = ReadoutHead 输出 = mean(dim=1) → LayerNorm → Linear(512→768) → 768 维，用于 InfoNCE 和 lp 评测。
  • patch_features = x（196 个 patch token，512 维），用于 PatchPredictor 的 masked-patch 重建。

trunk forward 在 AIMv2 模式下完全不变：所有 196 patches 都被看到，没有 mask token、没有 token drop。这是 frozen-trunk lp 可比性的关键设计理由（见 §5）。

3. PatchPredictor — Masked-Patch 像素预测头

代码：run/vision/models.py:478–510。这是 AIMv2-style 唯一新增的模块，从零实现。

478class PatchPredictor(nn.Module):
479    """R11-L arm6 (AIMv2-style): masked-patch pixel predictor head.
480    Maps a patch feature (width-dim) to the normalised raw pixels of that patch
481    (patch_dim = patch**2 * 3). MAE-style two-layer decoder
482    (Linear -> LayerNorm -> GELU -> Linear), applied only at masked positions.
485    Reference for the norm_pix target: OpenVision src/losses/common.py:mae_loss
486    (norm_pix_loss=True, Apache-2.0). Implemented from scratch -- Apple ml-aim
487    ships no loss code and is Apple Sample Code License, so nothing is copied.
489    The vision *trunk* forward is unchanged (all patches seen, no token drop
490    and no mask token), so frozen-trunk linear-probe eval stays directly
491    comparable to the InfoNCE baseline (arm1); the dense reconstruction
492    gradient reaches the trunk only through the patch features.
495    def __init__(self, width, patch_dim, hidden=None):
497        hidden = hidden if hidden is not None else width
498        self.fc1 = nn.Linear(width, hidden, bias=True)     # 512→512
499        self.norm = LayerNorm(hidden)
500        self.act = nn.GELU()
501        self.fc2 = nn.Linear(hidden, patch_dim, bias=True) # 512→768
502        nn.init.normal_(self.fc2.weight, std=0.02)
503        nn.init.zeros_(self.fc2.bias)
505    def forward(self, x):
507        x = self.fc1(x); x = self.norm(x); x = self.act(x)
510        return self.fc2(x)
层形状初始化参数量
fc1Linear(512 → 512, bias)默认 (Kaiming)262,656
normLayerNorm(512)默认1,024
fc2Linear(512 → 768, bias)weight: N(0, 0.02), bias: 0393,728
总计≈0.66M

patch_dim = patch² × 3 = 16² × 3 = 768（一个 patch 的 RGB 像素数）。fc2 用 N(0, 0.02) 小初始化 + bias=0 → 预测头从近零输出开始（MAE 范式），避免早期大梯度冲击 trunk。

实测单测：PatchPredictor(w=512, patch_dim=768) = 0.6577M params（EXPERIMENTS_VISION_ROUND11.md §14.6 S1）。

5. 前向计算与目标函数（--loss aimv2）

代码：run/vision/r9_train.py:556–575。这是 AIMv2-style 的核心前向分支。

5.1 前向分支 (L556–575)

556            elif args.loss == 'aimv2':
557                pooled, patches = vision(imgs, return_patch=True)
558                # masked patch reconstruction (MAE norm_pix_loss; Apache-2.0 ref)
559                B, N, _W = patches.shape
560                target = mae_norm_pix_target(imgs, args.patch)      # (B,N,patch_dim)
561                mrand = torch.rand(B, N, device=device) < args.mask_ratio
562                pred = predictor(patches[mrand])                    # (n_masked, patch_dim)
563                tgt = target[mrand]                                 # (n_masked, patch_dim)
564                patch_loss = torch.mean((pred.float() - tgt.float()) ** 2)
565                if args.contrast_weight > 0:
566                    If = torch.nn.functional.normalize(pooled, dim=-1)
567                    Tf = torch.nn.functional.normalize(text(txts), dim=-1)
568                    contrastive = loss_fn(If, Tf, logit_scale.exp(), None)
569                    cur_loss = args.contrast_weight * contrastive + args.patch_loss_weight * patch_loss
571                else:  # R11-H (arm 6-B): pure AR, NO contrast term
573                    cur_loss = args.patch_loss_weight * patch_loss

总损失：loss = contrast_weight × InfoNCE(pooled, text) + patch_loss_weight × MSE(predictor(patches[mask]), target[mask])

项权重（R11-G/R12 默认）计算
InfoNCE（对比项）contrast_weight = 1.0ClipLoss(If, Tf, scale, None)，512 负样本（bs64×8 all-gather）
Masked-patch MSE（稠密项）patch_loss_weight = 1.0mean((pred - target)²)，fp32 精度
  • mask_ratio = 0.6：torch.rand(B, N) < 0.6 → 每 batch 随机掩码 ~60% 的 patch 位置（196 个中约 118 个被掩码）。
  • 随机掩码（非 MAE 的 block-mask，也非 AIMv2 的 prefix/causal）：每个 patch 独立以 0.6 概率被选。
  • predictor 只在掩码位前向：patches[mrand] 取出被掩码的 patch 特征 → 预测对应位置的像素目标。
  • MSE 在 fp32：pred.float() - tgt.float()，避免 bf16 精度损失。

5.2 MAE norm_pix 目标 — mae_norm_pix_target() (L154–174)

154def mae_norm_pix_target(imgs, patch_size):
155    """MAE norm_pix_loss target (OpenVision src/losses/common.py:mae_loss, Apache-2.0).
157    imgs: (B,3,H,W) normalised with CLIP MEAN/STD. Returns (B, N, patch**2*3)
158    per-patch normalised pixels: un-normalise to [0,1], fold into patches, then
159    subtract the per-patch mean / divide the per-patch std over the full patch
160    vector (standard MAE norm_pix_loss). N = (H//patch)**2."""
162    from data import MEAN, STD
163    mean = torch.tensor(MEAN, device=imgs.device, dtype=imgs.dtype).view(1, 3, 1, 1)
164    std = torch.tensor(STD, device=imgs.device, dtype=imgs.dtype).view(1, 3, 1, 1)
165    raw = imgs * std + mean                       # (B,3,H,W) in [0,1]
166    B, C, H, W = raw.shape; p = patch_size
169    g = H // p
170    raw = raw.reshape(B, C, g, p, g, p)           # (B,C,g,p,g,p)
171    raw = raw.permute(0, 2, 4, 1, 3, 5).reshape(B, g * g, C * p * p)  # (B,N,C*p*p)
172    mean_pp = raw.mean(dim=-1, keepdim=True)
173    std_pp = raw.std(dim=-1, keepdim=True).clamp(min=1e-6)
174    return (raw - mean_pp) / std_pp               # (B,N,patch_dim)

三步处理：

  1. 反 CLIP 归一化：raw = imgs * STD + MEAN → 还原到 [0,1] 像素空间（CLIP MEAN/STD 见 data.py:10-11：MEAN=(0.481,0.458,0.408), STD=(0.269,0.261,0.276)）。
  2. Fold 成 patch：reshape → permute → reshape → (B, 196, 768)，每个 patch 是 16×16×3=768 个像素值。
  3. 逐 patch 标准化：每个 patch 向量减自身均值、除自身 std（clamp(min=1e-6)）→ 这就是 MAE 的 norm_pix_loss，让重建目标尺度无关。

实测单测：mae_norm_pix_target(randn(8,3,224,224), 16) → (8, 196, 768)，mean≈0, std≈0.999 → 逐 patch 标准化正确。

6. 关键设计理由：trunk forward 不变 → frozen-trunk lp 可比

这是整个 AIMv2-style 设计中最重要的一点。

标准 MAE 在训练时丢弃被掩码的 patch token、用 mask token 替代 → trunk 只看到 ~40% 的 patch → 训练时的 trunk 行为与评测时（看到 100% patch）不一致。

我们的设计不丢弃任何 patch：vision(imgs, return_patch=True) 的 trunk forward 与纯 InfoNCE 基线完全相同——所有 196 个 patch 都被看到、都经过全部 30 层 AttentionBlock。掩码只发生在 predictor 层：从 trunk 输出的 patch 特征中选取被掩码的位置去预测像素，但 trunk 本身看到的是完整图像。

后果：

  • frozen-trunk lp 评测时也是 100% patch 前向 → 训练/评测一致 → AIMv2-style 的 lp 与纯 InfoNCE 基线的 lp 直接可比（同一 trunk forward，唯一区别是训练时多了一个 patch-MSE 梯度）。
  • 稠密重建梯度通过 patches[mrand] → predictor → MSE → backward 回传到 trunk 的 patch 特征 → trunk 同时受 InfoNCE（全局）+ patch-MSE（局部稠密）双重监督。
  • 这不是标准 MAE（MAE 丢弃 token）也不是标准 AIMv2（AIMv2 用 prefix-attention AR）——是我们自研的改编（C2 限定）。

代码证据：models.py:489-492 的 docstring 明确写了 "The vision *trunk* forward is unchanged (all patches seen, no token drop and no mask token), so frozen-trunk linear-probe eval stays directly comparable to the InfoNCE baseline (arm1)"。

8. 与官方 AIMv2 的差异（C2 限定）

C2 限定（诚实披露）：我们的实现是 AIMv2-style 自研改编，非官方 AIMv2 复现。结论只对我们 recipe 成立，不得推广成「官方 AIMv2 会翻盘」。

项官方 AIMv2 (Apple, arXiv:2411.14402)我们 R11-G / R12（自研改编）
架构范式纯 AR（vision AR + text AR）非 AR：标准双向 ViT + 随机掩码
对比项❌ 无（纯生成式，无 InfoNCE）✅ 保留 InfoNCE (weight=1.0)
稠密项normalized MSE (pixel_loss)normalized MSE (patch_loss) — 同 MAE norm_pix
α (pixel loss 权重)≈ 0.41.0（patch_loss_weight）
掩码方式prefix-attention（causal，前面 token 可见后面不可见）随机掩码（torch.rand < 0.6，每个 patch 独立）
mask_ratioprefix 长度比例0.6
trunk forwardAR：前面 patch 可见、后面 mask token全 patch 可见、无 mask token（trunk 不变）
文本塔可训 text AR decoder冻结 CLIP-768（只用于 InfoNCE）
预训练数据~12B 样本（DFN-2B + COYO + HQITP）58.8M 对（GPIC+CC12M+Amshaker）
caption 类型LLaMA-3 长合成 caption短 alt-text（CC12M/Amshaker/GPIC short）
损失公式cap_loss + α × pixel_loss（caption CE + pixel MSE）1.0 × InfoNCE + 1.0 × patch_MSE

核心差异：官方 AIMv2 是纯生成式 AR（无对比项），我们是 对比 + 稠密 的混合。R11-H 实验证明：去掉对比项（纯 AR）→ 无翻盘（lp 6.23% ≈ 基线 6.08%）。因此我们的翻盘依赖对比项与稠密项的协同，这与官方 AIMv2 的「纯生成式翻盘」机制不同。

官方 AIMv2 原文逐字引用（§1）："AIMv2 extracts a training signal from every image patch and text token, providing denser supervision compared to discriminative objectives."（https://arxiv.org/html/2411.14402v1, 2024-11）—— 我们的「稠密监督」机制与此一致，但实现方式不同。

9. 四臂因果分解（为什么保留对比项）

R11 的四臂对照构成完整因果分解，证明翻盘 = 对比项 × caption-无关稠密的协同：

臂目标函数稠密项对比项lp@15.36M翻盘？因果结论
①纯 InfoNCE无✅6.08%—（基线）基线锚点
④CoCacaption-依赖 (CE)✅0.47%否（坍缩）caption 依赖的稠密 → 打回随机
⑥-B纯 ARcaption-无关 (MSE)❌6.23%否稠密本身不足以翻盘
⑥-AAIMv2-stylecaption-无关 (MSE)✅12.08%✅ 是 (+6.00)对比 + 稠密 = 翻盘

因果结论：

  • ④ vs ⑥-A：稠密项类型是关键——caption-依赖（CE）→ 坍缩，caption-无关（patch-MSE）→ 翻盘。坍缩归因于 caption 依赖，非稠密监督本身。
  • ⑥-B vs ⑥-A：对比项是关键——去对比项 → 无翻盘（6.23% ≈ 6.08%）。caption-无关的稠密 patch 监督本身不足以翻盘，需与 InfoNCE 协同。
  • → 翻盘 = 对比项（InfoNCE） × caption-无关的稠密 patch 监督 的协同效应。

证据：EXPERIMENTS_VISION_ROUND11.md §14.4（⑥-A 裁定）+ §9（④ CoCa）+ §17.4（⑥-B 纯 AR 裁定）。
