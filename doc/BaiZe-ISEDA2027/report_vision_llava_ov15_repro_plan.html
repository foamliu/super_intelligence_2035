§1 · HERO 结论 + 详细可行性判定

能否复现？

有条件可行 复现 LLaVA-OneVision-1.5 的整体流程可行（数据已基本就绪、ms-swift 已支持 Qwen3.5），但「Qwen3.5-4B 替换 Qwen3-4B」不是参数对等的直接替换，而是架构级的重新设计：

  1. 架构差异（🔴 高风险）：Qwen3.5-4B 使用 Gated DeltaNet（线性注意力 3:1 比例混合 Gated Attention），不是 Qwen3-4B 的标准 Transformer。影响：注意力计算、序列处理、显存占用、flash-linear-attention 依赖。
  2. 原生多模态（🟠 中风险）：Qwen3.5-4B 是「统一视觉语言基模」，自带视觉编码器（早期融合训练）。原版 OV1.5 假设 LLM 是纯文本，外挂 RICE-ViT + MLP projector。Qwen3.5-4B 场景下需决定：① 禁用内置 ViT 外挂 RICE-ViT？② 用内置 ViT 替代 RICE-ViT？③ 双 ViT 融合？
  3. 词汇表差异（🟡 低风险）：Qwen3-4B vocab=151,646 → Qwen3.5-4B vocab=248,320（+64%）。影响 embedding 参数量、token 化、训练效率。
  4. 训练栈迁移（🟠 中风险）：原版用 Megatron-LM mcore 格式 + 离线 packing。ms-swift 用 HF 格式 + DeepSpeed ZeRO。需重新设计 checkpoint 管理和数据 packing。
最大阻塞（一句话）：Qwen3.5-4B 自带视觉编码器——原版 OV1.5「纯文本 LLM + 外挂 RICE-ViT」的架构假设被打破，需重新设计视觉塔接入方案，这是整个复现的最大不确定性。

🔴 架构不兼容点：
  • 线性注意力：Gated DeltaNet 使用递归状态而非完整注意力矩阵 → 影响序列内信息交互，对视觉 token 融入有结构性影响

  • 扩展词汇表：248K vocab → embedding 层 +64% 参数，CE loss 计算量增大
  • 依赖链：需 flash-linear-attention + causal_conv1d + transformers≥5.9 → 与 BaiZe 现有环境可能冲突

§7 · 风险 & 阻塞清单

#风险等级描述缓解措施
R1Qwen3.5-4B 架构不兼容🔴混合 GatedDeltaNet + 原生多模态，与原版「纯文本 LLM + 外挂 ViT」设计冲突。线性注意力的梯度行为可能对 lr 敏感。S0 跑 10 步 fwd+bwd 确认 loss 正常；lr sweep {1e-5,5e-5,1e-4,5e-4}
R2双视觉编码器冲突🔴Qwen3.5-4B 自带视觉编码器。外挂 RICE-ViT 导致双视觉路径。禁用内置 ViT 可能破坏预训练知识。三选一：① 用内置 ViT 替代 RICE-ViT；② 禁用内置 ViT 外挂 RICE-ViT（风险最高）；③ 双 ViT 融合
