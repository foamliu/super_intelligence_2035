1目标与背景

BaiZe 前序任务（1B 架构与超参搜索）已收官，胜出配置为 MiniCPM5-1B（S4-01 loss 4.9690@160）。 在架构类型维度扫描中，早前结论为「Nemotron / Hymba 无 1B 变体」，但后续修正发现： 底层 megatron-core 原生包含 Mamba/SSM hybrid 能力（mamba_hybrid_layer_allocation 即 attention+SSM 混合层分配）， 只是官方没有现成的 ~1B hybrid recipe（最小 hybrid 为 8B）。

本评估的目标是：验证一个 ~2B 的 Mamba2-hybrid（attention + SSM 混合）模型能否通过 Megatron-SWIFT 生态真正跑起来做预训练， 并在不修改 site-packages 的前提下把 provider + recipe + 数据 + 环境全部打通到「可启动训练」的临门一脚。

评估的三个问题

  • Q1（架构）：能否造出 ~2B 的 Mamba2-hybrid 模型定义？→ 可，复用 8B hybrid 的 56 层 pattern，宽度减半。
  • Q2（框架接驳）：能否经 swift megatron pt 直接启动？→ 不可，需走 NVIDIA/NeMo recipe 路径。
  • Q3（数据/tokenizer）：能否用真实 tokenizer 把 1.8T 数据预处理到位？→ 可，DeepSeek-V4.1-Flash 已接入并冒烟通过。

3.1 provider.py

NVIDIAMambaHybridModelProvider2B 继承 megatron.bridge.models.mamba.MambaModelProvider， 复用 8B hybrid 的 56 层 hybrid_override_pattern（M=SSM / *=attention / -=MLP）：

_HYBRID_OVERRIDE_PATTERN = "M-M-M--M-M*-M-M-M-M--M*-M-M-M-M-M*--M-M-M-M-M*-M--M-M-M-"

@dataclass
class NVIDIAMambaHybridModelProvider2B(MambaModelProvider):
    hybrid_override_pattern: str = _HYBRID_OVERRIDE_PATTERN
    num_layers: int = 56
    seq_length: int = 4096
    hidden_size: int = 2048          # 4096 -> 2048
    ffn_hidden_size: int = 8192      # 16384 -> 8192
    num_attention_heads: int = 16    # 32 -> 16
    num_query_groups: int = 4        # 8 -> 4
    mamba_num_groups: int = 8        # SSM 分组，保持与 8B 一致
    make_vocab_size_divisible_by: int = 128

hybrid 层分配由 megatron/core/ssm/mamba_hybrid_layer_allocation.py 的 allocate_layers() 决定， 与模型规模无关，因此 2B 直接复用 8B 的 56 层 pattern，无需改动层分配逻辑。

3.2 recipe.py

model_config() + pretrain_config() 完全镜像 mamba2_hybrid_8b.py， 仅 model_config() 返回 NVIDIAMambaHybridModelProvider2B。 pretrain_config() 返回 ConfigContainer，可喂给 megatron.bridge.training.pretrain.pretrain()。 默认 tensor_parallelism=8 / pipeline=1 / seq_length=4096 / micro_batch=1 / global_batch=8， 优化器 distributed_fused_adam_with_cosine_annealing(lr=3e-4, min_lr=3e-5, weight_decay=0.1)。

4步骤 2 · swift bridge 两后端调研

swift 的 megatron pt 有 两条 bridge 后端（swift/megatron/model/utils.py）， 据此判定能否通过 --model_arch / --model_type 把自定义模型接进去。

(a) 默认 mcore-bridge

第三方 mcore_bridge v1.6.4

入口 get_model_meta(get_mcore_model_type(model_type))。 MODEL_MAPPING 里 无 standalone Mamba；唯一涉 Mamba 的 nemotron_h.py 是 Nemotron-H（30B MoE）。

后果：给 mamba2_hybrid_2b model_type → get_model_meta() 返回 None → ValueError("Model ... is not supported")。

(b) megatron-bridge

NVIDIA megatron.bridge.AutoBridge

入口 AutoBridge.from_hf_config(hf_config) → get_model_bridge._exact_types（HF 架构名 → MegatronModelBridge）。

conversion/model_bridge.py 里 grep mamba 为空：Mamba 只有 provider/recipe， 没注册任何 HF↔Mcore 转换桥。

后果：即便伪造 Mamba2ForCausalLM HF config，supports() 也 raise ValueError("architecture ... not yet supported")。

判定

把 mamba2_hybrid_2b 接进 megatron pt --model_arch 不是改一个注册表条目就能解决， 需同时补「swift model_type / template + 合成 HF Mamba2 config + 一个继承 MegatronModelBridge 的 Mamba 转换桥 （HF↔MambaModelProvider 权重映射与 selective-scan 语义）」。自建 Mamba bridge 风险高、收益低 → 路径 B 不建议。

5.1 关键数值（已实测）

  • 源词表 129280 → 追加 EOD 后 vocab=129281，eos_id=129280（即 HuggingFaceTokenizer.eod）。
  • 模型侧 make_vocab_size_divisible_by=128 → embedding 自动 pad 到 129408（TP 正交分配时再乘 TP）。
  • 冒烟 --max-docs 3000 取首个 part 文件 3000 条 → 2,480,398 tokens（6.4s）； IndexedDataset 回读通过，每文档末尾 = EOD 129280，token id 范围 [0, 129280]。
  • 环境链验证：PYTHONPATH=/tmp/omegaconf_230 下 import megatron.bridge 成功； NVIDIAMambaHybridModelProvider2B 实例化成功； pretrain_config(tokenizer_path=...) → build_tokenizer 产出 _HuggingFaceTokenizer(vocab=129281, eod=129280)。

6环境阻塞点与规避

import megatron.bridge 在本环境直接失败：

ModuleNotFoundError: No module named 'omegaconf._utils'

根因：omegaconf==2.4.0.dev14（dev 预发布）里 base.py 仍 from ._utils import ...， 但包内已无 _utils.py（仅剩 _impl.py），属残缺安装。

方面影响
影响面megatron.bridge.* 全链（含 AutoBridge、mamba_provider、本项目 provider.py 的 import）都触发
不影响默认 mcore-bridge 路径（S1~S4 的 MiniCPM5 训练）不 import omegaconf，照常可用
修复（已非破坏性落地并验证）pip install --target /tmp/omegaconf_230 --no-deps 'OmegaConf==2.3.0' + PYTHONPATH=/tmp/omegaconf_230 前缀，main 环境 antlr4-runtime 已备；不动 site-packages，也不影响 swift / mcore-bridge 现有训练

7可行路径与剩余步骤（步骤 4）

路径 A（推荐）· NVIDIA/NeMo recipe

绕过 swift，直接：

pretrain(
    pretrain_config(tokenizer_path=..., data_paths=[...]),
    forward_step_func=forward_step,
)

pretrain_config 返回 ConfigContainer（本仓库 recipe.py 已就绪）。 启动由 NeMo Run 驱动（nemo_run.Partial），但 nemo_run 仅编排用，可直接 torchrun 驱动。

已打通：provider / recipe / tokenizer / 数据；待做：launcher + forward_step + 冒烟。

路径 B（重）· swift 自建 bridge

为使 megatron pt --model_type mamba2_hybrid_2b 可用，需新增：

  • swift model_type + template
  • 合成 HF Mamba2ForCausalLM config
  • 继承 MegatronModelBridge 的 Mamba 转换桥（注册进 model_bridge 或 mcore_bridge.MODEL_MAPPING）

工作量大、权重映射 / SSM 正确性风险高。

不建议

剩余步骤（步骤 4，未做，仍阻塞）

  1. launcher：落地一个 torchrun 启动脚本，串起 pretrain_config(tokenizer_path=..., data_paths=[.../.bin 前缀], forward_step=...) + pretrain(cfg, forward_step_func)。nemo_run 仅编排用，可 bypass（pretrain() 自带 nvidia_resiliency_ext.CallWrapper，已确认可用）。
  2. forward_step_func：走 megatron-core megatron.bridge.training.gpt_step.forward_step （Mamba 层前向与 gpt 一致，hyper-grid 也复用）。
  3. 资源：完整 1.8T 数据切词约 1.9e9 tokens，.bin 约 7.6GB（int32），需大磁盘节点 + 足够时间； GPU 训练侧 Mamba2 2B 参数需按 20 GPU·h 预算谨慎规划（共享 LLaVA 8 卡场景下 mb=1）。
