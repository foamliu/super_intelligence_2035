2已定前提（架构 / 框架 / 数据 / 环境）

架构（已定，不再变）

  • Mamba2-hybrid（56 层，Nemotron-H 式顺序混合）
  • 参数量 2,220,268,032（numel() 实测）
  • 多数层为 SSM（Mamba2）+ 3~4 个稀疏注意力层
  • provider：NVIDIAMambaHybridModelProvider2B（宽度减半至 ~2B）

框架 / 环境（锁定）

  • NeMo pre-training 入口 + Megatron-Core 0.16.1
  • tensor_model_parallel_size=1（TP=1 / DP 分片）
  • CUDA 12.8 · PyTorch 2.8.0 · Python 3.10
  • 硬件：主训练 10.239.2.29（8×H100，GPU0~7，TP1/DP8）；辅助 10.239.2.12（GPU0~5）

数据（就绪）

  • Ultra-FineWeb-L3 英文子集（~1.8T tokens）
  • 流式打包至 seq_length=4094
  • tokenizer：DeepSeek-V4.1-Flash（vocab 129,281，pad 129,408）
  • 短地平线用已切子集（200k docs / 165M tokens，.bin/.idx）

固定超参（跨配置一致）

  • optimizer：distributed AdamW（β1=0.9 β2=0.95 eps=1e-5 wd=0.1）
  • bf16、seed=1234、序列 4094
  • 全局 batch / 序列 / packing 跨配置固定，S3 单独扫 batch sizing
  • 融合 kernel + 选择性激活重计算 + CE-loss 融合（提吞吐）

3架构选择结论（已完成，作为 rationale）

在启动超参搜索前，已通过 从零、匹配数据/seed/GPU 足迹 的 head-to-head 对比，在 ~2B 尺度选定 hybrid 骨架（对应 EXPERIMENTS_2B.md 与论文 tab:archcomp）。三条采用依据：

  1. 推理效率：SSM 层逐 token O(1) 循环解码，decode 快一个量级，直接命中推理密集型、成本敏感部署。
  2. 受控对比：等参数口径下 hybrid 以更少参数（2.22B vs 2.51B，-11.6%）收敛到更低 loss。
  3. 可行性：Megatron-Core 自带 Mamba-hybrid provider，56 层交叠模式降宽至 ~2B，NeMo recipe 下无需自研 kernel 即可执行。

⚠️ MiniCPM5 的 decode 慢已用 torch.profiler 定位：非 KV-cache 未命中，而是 mcore 直驱（无 CUDA-graph/flashinfer）下 TE fused-attention 逐层 CPU launch 开销（FusedAttnFunc 42 层占单步 Self CPU 的 93.4%），属 CPU-bound 非 GPU-bound。Mamba2 仅 ~4 个 attention 层 + SSM/MLP，故 decode 快 ~10×。两架构同一代码路径测量，相对结论可信。

4超参搜索协议 S1–S4

完整网格不可行，采用 分阶段、单变量一次只动一个 的协议（对应论文 sec:search）。每个阶段相对「当前最优」只改一个变量，隔离贡献、压住 GPU·时。所有短地平线实验 validation loss 在匹配步数上报，保证跨配置可比。

WSD 阶段设计（占比 + 数据构成）

WSD（warmup–stable–decay）调度下按 token 占比切为三段（sec:wsd）。warmup 不扫：全量训练直接复用 LLaMA 的 warmup_steps=2000；试验期（每个 sweep 共 1000 步）用固定占比 ~5% 即可。

阶段占比试验期步数（共 1000）LR数据构成
warmup~5%≈500 → stable LR（线性）Ultra-FineWeb-L3 英文（常规混合）
stable~85%≈850恒定 stable LRUltra-FineWeb-L3 英文（常规混合，主训练）
decay~10%≈100stable LR → mini LR退火：混入代码 / 数学 / SFT 语料

decay 数据：退火阶段可直接使用代码（UltraData-Code）、数学（UltraData-Math）、SFT 语料，无需为 post-training 预留——预训练退火与 post-train 监督微调属不同阶段、互不冲突。全量训练的 warmup 固定复用 LLaMA warmup_steps=2000，不参与扫描。

5预算分配

预训练搜索受 ~84 GPU·hour 总预算约束（跨所有实验与重试累计）。每组 1000 步（Mamba2-hybrid，10.239.2.29 8 卡 ≈ 0.8 GPU·h），8 组实验约 ~6.4 GPU·h，预算充裕。

⏱️ 时间估计（8 卡，不闲置）

单步 ~350ms/iter（8 卡 TP1/DP8；SSM 串行是 bottleneck，6 卡基准 ~340ms 外推，S0 冒烟实测校准）。每组含一次性启动开销（SSM 编译 ~12s + CUDA-graph 捕获 ~5s）+ 1000 步 ≈ ~6.1 min。8 组（S1:1 + S2:4 + S3:2 + S4:1）在 10.239.2.29 单节点 8 卡串行 ≈ ~49 min 墙钟 / ~6.5 GPU·h；端到端（含 S0 launcher 扩展 ~30–45 min 编码 + 10 步冒烟）≈ ~1.5 h。
