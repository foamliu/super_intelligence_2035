2已定前提（架构 / 框架 / 数据 / 环境）

架构（已定，不再变）

  • Mamba2-hybrid（56 层，Nemotron-H 式顺序混合）
  • 参数量 2,220,268,032（numel() 实测）
  • 多数层为 SSM（Mamba2）+ 3~4 个稀疏注意力层
  • provider：NVIDIAMambaHybridModelProvider2B（宽度减半至 ~2B）

框架 / 环境（锁定）

  • NeMo pre-training 入口 + Megatron-Core 0.16.1
  • tensor_model_parallel_size=1（TP=1 / DP 分片）
  • CUDA 12.8 · PyTorch 2.8.0 · Python 3.10
  • 硬件：10.239.2.29（8×H100）、10.239.2.12（GPU0~5）

数据（就绪）

  • Ultra-FineWeb-L3 英文子集（~1.8T tokens）
  • 流式打包至 seq_length=4096
  • tokenizer：DeepSeek-V4.1-Flash（vocab 129,281，pad 129,408）
  • 短地平线用已切子集（200k docs / 165M tokens，.bin/.idx）

固定超参（跨配置一致）

  • optimizer：distributed AdamW（β1=0.9 β2=0.95 eps=1e-5 wd=0.1）
  • bf16、seed=1234、序列 4096
  • 全局 batch / 序列 / packing 跨配置固定，S3 单独扫 batch sizing
  • 融合 kernel + 选择性激活重计算 + CE-loss 融合（提吞吐）

3架构选择结论（已完成，作为 rationale）

在启动超参搜索前，已通过 从零、匹配数据/seed/GPU 足迹 的 head-to-head 对比，在 ~2B 尺度选定 hybrid 骨架（对应 EXPERIMENTS_2B.md 与论文 tab:archcomp）。三条采用依据：

  1. 推理效率：SSM 层逐 token O(1) 循环解码，decode 快一个量级，直接命中推理密集型、成本敏感部署。
  2. 受控对比：等参数口径下 hybrid 以更少参数（2.22B vs 2.51B，-11.6%）收敛到更低 loss。
  3. 可行性：Megatron-Core 自带 Mamba-hybrid provider，56 层交叠模式降宽至 ~2B，NeMo recipe 下无需自研 kernel 即可执行。

⚠️ MiniCPM5 的 decode 慢已用 torch.profiler 定位：非 KV-cache 未命中，而是 mcore 直驱（无 CUDA-graph/flashinfer）下 TE fused-attention 逐层 CPU launch 开销（FusedAttnFunc 42 层占单步 Self CPU 的 93.4%），属 CPU-bound 非 GPU-bound。Mamba2 仅 ~4 个 attention 层 + SSM/MLP，故 decode 快 ~10×。两架构同一代码路径测量，相对结论可信。
