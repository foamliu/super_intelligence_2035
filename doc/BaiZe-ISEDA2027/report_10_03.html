3.2 为什么「MBS 小」和「FP8 没收益」是同一个问题

现状：--micro-batch-size 1，GBS=1024，DP=8 → 每步 1024 ÷ 8 ÷ 1 = 128 次 grad-accum；显存只用 ~39/80 GB。

关键量：每 GEMM 的 M ≈ MBS × seq（seq=4096）：

MBS每 GEMM 的 MFP8 单算子 s（bf16/fp8）预期
1~4,0960.65（P-4R 实测，倒挂）FP8 反而慢 ~35%
2~8,192< 1（仍 < 交叉点）FP8 预计仍倒挂
4~16,384≈ 1.0（交叉点）FP8 开始打平
8~32,768→1.34（饱和区）（与 Xmodel-2.5 反推一致）FP8 才有真收益

→ 抬 MBS 有两个好处：① 减少 grad-accum 次数（少 128→64→32→16）；② 把 M 推进到 FP8 的收益区。这就是 P-9 把两者捆在一起测的原因。

📐 口径不变量（运维 2026-10-03 定）：每步更新固定 ≈ 4M token（GBS × seq ≈ 4.0M；SLM 公认口径，决定总体训练速度）→ seq=4096 ↔ GBS=1024 · seq=8192 ↔ GBS=512。
seq 今后统一 4096（P-9 / P-8）；seq=4094 仅存于正在跑的 P-5b（不动、不参与对比）；seq=8192 是否上 P-8，由 P-9a-ext 的 G 项结果决定。
📌 总步数 = 总训练 token ÷ 4M，与 seq 无关（总 token 由数据量决定）→ seq 翻倍只使每步样本数（4M/seq）与总序列数（总token/seq）减半，总步数与 LR 计划不变；seq 的代价只体现在每步耗时/显存（由 G 项实测）。

10.1 pretrain 能否对进行中的训练做 profiling？— 能

结论：能，但必须做在「短测」上，绝不扰动正在跑的 P-5b。已下发 P-9d。

层次手段说明

重点怀疑（hybrid 先验）：① grad-accum 空隙（MBS=1 → 每步 128 段）② 访存受限的 SSM scan / elementwise / LayerNorm（M=4094 下 GEMM 亦访存受限）③ recompute 过重 ④ mamba 自定义 kernel 路径。

2026-10-03 追加：P-9 尽早跑（严格早于 P-6②）；除 MBS 外新增 P-9a-ext 可变参数扫描（重计算 / 通信重叠 / 并行切分 / 数据加载 / 注意力内核 / 上下文）。

🔎 已有实测证据（P-4 profile，80 步 torch.profiler）：attention flash 仅占 GPU 自耗时 0.7%（SSM 8.4% / GEMM ~28.6% / NCCL 41.7% / norm+act 10.5%）→ seq 翻倍使注意力项 ~×4，最坏 0.7%→~2.8%（+~2pp）；其余按 token 计价、与 seq 无关。
预注册预测：r = t_step(8192)/t_step(4096) 应落在 1.05–1.20（若为纯 Transformer 会是 2–4×）；判据 r≤1.2 → 8192 作 P-8 候选，r≥1.5 → 沿用 4096。
seq 多点扫描（保持 4M/步）：seq ∈ {2048, 4096, 8192, 16384} → GBS ∈ {2048, 1024, 512, 256}；16384 是 O(n²) 首次冒头的边界点（注意力 ~11%，显存 ~4×，可能 OOM）。
⚠️ FP8 按 M = MBS × seq 扫，不按 seq 扫（seq4096+MBS4 与 seq8192+MBS2 命中同一 M=16384）→ 扩 P-4R 的 s(M) 曲线到 M∈{4K,8K,16K,32K,64K}。
