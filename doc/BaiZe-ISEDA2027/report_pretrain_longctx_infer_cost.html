5. Key Findings

VRAM (core advantage): Hybrid near-constant ~26GB across 128K-1M (Mamba2 SSM state O(1) for 52/56 layers + small KV for 4 attn). Dense grows 27→29GB at 128K-256K then OOMs at 512K — KV cache pool cap = 455K tokens at mem-frac 0.3 on 80GB H100 (prompt 504K > 455K).

Prefill: Dense faster at 128K (3.3x) and 256K (1.7x) — attention matmul parallelism wins at medium ctx. Hybrid prefill throughput INCREASES with ctx (1591→6484 tok/s, 128K→1M) due to Mamba2 parallel scan efficiency. Crossover extrapolated ~512K but dense OOMs before it can be measured.

Decode: Dense faster at all valid ctx levels (2.6x at 128K, 2.2x at 256K). Hybrid decode slows with ctx (71→34 tok/s) due to 4 attn layers' growing KV. No crossover in valid range — dense always faster where it can serve.

Capacity ceiling: Hybrid serves 1M ctx in 26.5GB; dense cannot serve 512K+ (would need >80GB for 512K KV cache alone). This is the decisive advantage for long-context inference.

P-9.11 ref (different 口径: mem-frac 0.85, likely bf16 SSM): At 64K bs1, hybrid prefill 2.18x faster, decode 1.18x faster. 口径 change (0.3 mem-frac + float32 SSM) reduces hybrid absolute throughput; relative hybrid-vs-dense comparison within P-9.11-E is valid.

Limitations: Both trained max_pos=4096; beyond=extrapolation (cost valid, quality not eval). No ABF/YaRN (wouldn't change cost). float32 SSM dtype penalizes hybrid; production bf16 would improve hybrid speeds.

6. 2M Extension & VRAM Diagnosis (P-9.11-F, 2026-10-07)

V2 Finding: "VRAM constant ~26GB" is a mem-fraction=0.3 artifact — at 0.6, 2M prompt drives VRAM to 75.91GB. Mamba SSM cache scales with mem-fraction (8.34→18.56→29.02GB). 8M/16M not servable on single 80GB H100.

⭐ Key Finding: --mamba-ssm-dtype float32 (used in P-9.11-E) artificially depresses hybrid prefill by 40%. With bfloat16 (sglang default from model config), hybrid @1M prefill jumps from 6,484→10,820 tok/s — 1.67× faster than the float32 baseline, and faster than dense @1M (~6,484 tok/s in P-9.11-E). This explains the 口径 contradiction: P-9.11 (0.85, likely bf16) showed hybrid 2.18× faster @64K, while P-9.11-E (0.3, float32) showed dense 3.3× faster @128K. Decode and VRAM are unaffected (bf16 = half memory per SSM state → 2.16× more cache slots, but per-request cost identical).
Implication for P-9.11-E conclusions: The "dense faster than hybrid at 128K-256K" finding in §5 is partially an artifact of float32 SSM. With bf16 SSM, hybrid prefill would be ~1.67× faster at all ctx levels, potentially closing or reversing the gap at 128K-256K. However, the 4-layer attention O(n²) bottleneck (≥512K, B1: 77% of prefill) remains — at very long ctx, attention dominates regardless of SSM dtype. Reproducible: SSM_DTYPE=bfloat16 MEM_FRACTION=0.3 BATCHES="1" bash p911e_matrix_launch.sh "2 hybrid 1048576"
