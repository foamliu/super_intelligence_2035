1. TL;DR — 最值得做的 10 条

① 把"混合架构 → 长会话服务成本"写成论文核心卖点（支撑 §0 命题）
BaiZe 的 4 层 attention + 52 层 Mamba-2 意味着只有 4/56 的层携带 session-growing KV cache —— 这是"1/100 成本"命题的架构根基，且已有实测数据（decode 22.8 tok/s vs dense 2.2 tok/s = 10.3×）。论文 §4 tab:archcomp 已有此数，但 §1/§8 未把它与"成本救场"叙事挂钩。零成本。
② 引用 Xmodel-2 的"decay 段 = 带 SFT 的退火"（64% SFT 占比）作为 P-8 配方的文献锚点（方向 1+2）
Xmodel-2 跑 400+ 次试验得出 SFT 占比 60–69%（取 64%），复杂推理 +29.31%，SimHash 去重 +1.7% —— 这些数字在本地 xmodel-2.tex:142-154 中已验证。BaiZe 的 P-8 配方正在 follow 这条路线，但论文 §4 没有引用 Xmodel-2。零成本。
③ 引用 Data Mixing Laws（Ye 2024, arXiv 2403.16952）为"小规模配比搜索可迁移"的法理依据（方向 1）
这是 BaiZe "reduced-horizon proxy search" 支柱的直接文献支撑 —— 论文 §1 列了三个 design pillar 但 related work 只引了 MiniCPM，没引 Data Mixing Laws。已在本地 xmodel-2.bib 验证。零成本。
④ 引用 μP / Tensor Programs V（arXiv 2203.03466）为超参迁移性的第二条法理（方向 1）
μP 是"小模型超参排名迁移到大模型"的经典锚点，与 BaiZe 的 S1–S5 proxy search 方法论直接对应。已在本地 Xmodel-2.5/reference.bib 验证。论文 §2 和 §4 均未引用。零成本。
⑤ 引用 Chinchilla（arXiv 2203.15556）并在 Limitations 中诚实交代"655M token = Chinchilla 下限的 1.5%"（方向 1+6）
Chinchilla 20:1 token:param → 2.2B 需 44B token；BaiZe 只跑了 655M = 1.5%。已在本地 DATA_RESEARCH.md:70 引用（含 URL）。把这一 limitation 主动写出来比被审稿人发现强得多。零成本。
⑥ 补 §2 related work 的"视觉编码器"一线（方向 6 · PAPER_STALENESS_AUDIT 已标红）
论文 §2 只有三个 subsection（SLM、Hybrid SSM、VLM），完全没有视觉编码器预训练的 related work —— 但 §6 整节都在讲视觉编码器。AIMv2（arXiv 2411.14402，本地验证）、SigLIP（arXiv 2303.15343）、MAE（arXiv 2111.06377）应各引一句。零成本。
⑦ 把 R8/R9/R10 的 scaling law 写成"诚实的负结果 + 方法论贡献"（方向 3+6）
BaiZe vision 的 R9 scaling 拟合（幂律渐近 25.1%，本地数据够不到 20%+）和 R10（加宽塔是负收益，−2.2 lp pp/翻倍）已在 PAPER_STALENESS_AUDIT.md 中回填到 §6。"够不到 20% 但给出了 scaling law + 瓶颈诊断"本身是技术深度的体现。零成本。
⑧ 在"成本救场"叙事中引用推测解码 + 级联/路由作为"分档承接流量"的机制（方向 0 ⭐）
BaiZe 的成本命题不仅是"单模型便宜"，还是"分档承接"——简单请求走小模型、复杂请求升级到大模型。推测解码（Leviathan 2023, ⚠️未在线核验）让小模型生成 + 大模型验证；级联/路由（FrugalGPT 2023, RouteLLM 2024, ⚠️未在线核验）做请求分流。这是"1/100 成本"命题的机制层证据。零成本。
⑨ 引用 DeepSeek-V3 / DeepSeek-R1 的成本数据作为"大模型成本基线"（方向 0 ⭐）
DeepSeek-V3 报告了训练成本和推理成本（⚠️具体数字未在线核验），是"大模型有多贵"的公开锚点。"70–80% @ 1/100 成本"命题需要一个大模型成本基线来对比。DeepSeek-Flash 是运维指令中点名的对标对象。需运维在线核验具体数字后写入。
⑩ 引用 GRPO（DeepSeekMath, arXiv 2402.03300）+ DPO（arXiv 2305.18290）为 Stage (ii) RL/SFT 的文献锚点（方向 2）
论文 §5 已写"group-relative policy optimization and no value network"（即 GRPO）但未引用出处；DPO 在 xmodel-2.bib 已有（arXiv 2305.18290，本地验证）。GRPO 的 arXiv ID 来自训练知识（⚠️未在线核验）。零成本。

关键洞察：成本优势来自两个独立维度的乘积——参数量小（~1/32）× 混合架构解码快（~10×）。纯参数量小的 dense 小模型只有 ~1/32；纯混合架构的大模型只有 ~10×；BaiZe 的 2.2B + hybrid 是两者叠加 → 接近 ~1/100。

长会话成本（agentic 场景的关键）：agentic session 的成本不是 prompt throughput 而是随 session 增长的 KV cache 内存。BaiZe 只有 4/56 层的 KV cache 随会话增长 → 长会话成本优势比短 prompt 更大。这是论文 §1 和 §8 应重点写的。
