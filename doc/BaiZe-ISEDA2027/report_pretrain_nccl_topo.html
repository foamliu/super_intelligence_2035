⭐ 核心结论（TL;DR）
① NCCL 已在用 NVLink P2P（非 PCIe）—— via P2P/CUMEM = 100%，via NET = 0，via SHM = 0。
② 用户假设证伪：不存在「NCCL 走 PCIe」问题 → 换 NVLink 拓扑无可换（硬件已是 NV18 full-mesh NVSwitch）。
③ 默认配置已最优：Ring + P2P + LL 在 ≥100MB 大消息上全面胜出（1GB busbw=164.56 GB/s = algbw 329 GB/s = 69% NVLink 峰值）。
④ NVLS 不可用：NCCL_NVLS_ENABLE=1 无效（"0 nvls channels"）—— 此 H100 NVSwitch + NCCL 2.27.3 组合不支持 NVLS。
⑤ 无 env 组合能提升大消息带宽 → NCCL 不是提速瓶颈，应转向 Step 2（训练配置优化）。

8-GPU 可迁移性：本次只能测 2-GPU（GPU2-7 被 data BO 占用）。但结论可外推：
  • 8-GPU Ring 同样用 P2P/CUMEM over NVLink（NV18 全连接）
  • 所有 env 改动在 2-GPU 均不改善或恶化 → 8-GPU 不会有不同表现
  • NVLS 不可用是硬件/驱动级限制，与 GPU 数量无关
  • 结论可迁移到 8 卡：P-8 训练应沿用 default NCCL 配置，无需任何 env 覆盖

6. 结论

✅ 用户假设证伪：NCCL 已在使用 NVLink P2P（100%），不存在「走 PCIe」的问题。硬件已是 NV18 full-mesh NVSwitch，无可换的「更好拓扑」。
✅ 默认 NCCL 配置已最优：Ring + P2P/CUMEM + LL 在 ≥100MB 大消息上全面胜出。1GB busbw=164.56 GB/s（algbw=329 GB/s = 69% NVLink 峰值）。7 个 env 改动均不改善或恶化。
✅ NCCL 不是提速瓶颈 → 应转向 Step 2：训练配置提速候选清单（MBS/GBS/seq 组合、recompute 档位、CUDA-graph、数据管线、TP/DP 拓扑、kernel/backend 选择等）。
⚠️ NVLS 不可用：若未来要启用 NVLink SHARP，需安装 NCCL NVLS 插件 / 升级驱动 / 确认 NVSwitch firmware 支持。
