1. TL;DR

  • Question: Under the AIMv2-style dense objective (InfoNCE + masked-patch-MSE), does widening the vision tower from 512→768 (126.78M→284.54M, 2.24×) improve frozen-trunk linear-probe top-1 on IN-1k, at a fixed 1-epoch budget over ~95.7M image–caption pairs?
  • Design: Pre-registered two-arm comparison — only width differs (512→768); depth (30), patch (16), resolution (224), objective, data, optimizer, and step count (187,101) are all identical. This is a clean model-scaling axis.
  • Training: Both arms completed 187,101 steps with no collapse (C1 < 0.5, C2_gap > 0, C4=OK throughout). E1 final loss=1.3036; E2 final loss=1.9992 (higher loss but larger model capacity — loss values are not directly comparable across widths).
  • E1 Protocol B result: lp = 29.35 ± 0.00% (3 seeds: 29.34 / 29.35 / 29.35).
  • E2 Protocol B result: lp = 23.76 ± 0.04% (3 seeds: 23.74 / 23.82 / 23.73).
  • Result: Δlp = 23.76 − 29.35 = −5.59 pp (σ = 0.04, σ ≪ |Δ|). Δ ≤ −1.5 pp → Bigger is WORSE. The larger model (2.24× params) scores significantly lower at the same 1-epoch budget — confirming the data-limited regime finding from R9/R10 that widening is negative.
  • Protocol A (secondary): E1 = 19.70%, E2 = 15.59%, Δ = −4.11 pp — same direction, consistent across both protocols.
  • Pre-registered judgment: Δlp = lp(E2) − lp(E1). If Δ ≥ +1.5pp → supports scaling claim; |Δ| ≤ 1.5pp → not supported; Δ ≤ −1.5pp → bigger is worse; σ > |Δ| → indistinguishable. No post-hoc changes to criteria.

10. Limitations

  • Two points ≠ scaling law: This experiment tests a single budget point (1 epoch, 95.7M pairs). It does not extrapolate to other budgets or widths. R9/R10 established the (N, M) scaling surface; this experiment tests one point on that surface under the AIMv2 objective.
  • NFS contention confounds wall time: E2's 5.45× wall time is dominated by NFS I/O contention, not model size. The fair compute comparison is 1.36× (ms/step). Training quality (loss, collapse guards) is unaffected — only wall time is confounded.
  • Single seed for training: Both arms use seed=1234 for training. Only the evaluation uses 3 seeds (0, 1, 2). Training-seed variance is not measured.
  • Loss not comparable across widths: E2's higher final loss (1.9992 vs 1.3036) does not mean E2 trained worse — larger models have higher capacity and may converge to different loss floors. The linear-probe metric is the intended comparison.
  • Step-count audit: GPIC grew from 6,233 to 6,754 tar files between E1 and E2 launches. E2 was explicitly launched with --steps 187101 to match E1 exactly. This preserves the "same budget" constraint.
