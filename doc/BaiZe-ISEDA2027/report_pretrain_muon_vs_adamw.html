BaiZe Mamba2-Hybrid 2.2B · Muon vs AdamW 优化器对比

2026-10-10 · 8×H100 @ 10.239.2.29 · 真实预训练数据（P-5b 16-shard blend ~20.6B tokens）

⭐ 核心结论

Muon 在相同 1000 步 / 6.55M tokens 下显著优于 AdamW：最终 loss 3.11 vs 4.00（低 22.3%），梯度范数更稳定（0.26 vs 0.48）。 但 Muon 的代价是：吞吐慢 26%（87K vs 118K tok/s）、显存多 38%（53.8 GB vs 39.0 GB）。

建议：P-8 正式预训练考虑采用 Muon（或 layer-wise distributed Muon），以更少步数达到更低 loss；吞吐劣势可通过缩短总训练步数来补偿。

6 · 分析与建议

6.1 为什么 Muon 的 loss 更低？

Muon 对 2D 权重矩阵执行正交化后的动量更新（momentum=0.95, Nesterov, ns_steps=5），等效于在权重矩阵的奇异值空间中施加均匀步长。这种正交化使梯度更新的各个方向被均衡化，避免了 AdamW 中可能出现的方向偏置。对于 Mamba2-hybrid 架构（52 层 SSM + 4 层 Attention），大量权重是 2D 矩阵（SSM 的 A/B/C/D 投影、Attention 的 QKV），Muon 的正交化恰好作用在这些参数上，而 1D 参数（norm、bias、embedding、lm_head）仍由标量 AdamW 优化。

6.2 显存代价分析

Muon 额外显存 ~14.8 GB 主要来自：(a) 正交化过程中的中间矩阵（Newton-Schulz 迭代需要 5 步，每步产生临时矩阵）；(b) Muon 的动量缓冲区与 AdamW 的二阶矩缓冲区共存（标量参数仍用 AdamW）。在 80GB H100 上 53.8 GB 峰值仍有余量（26.2 GB headroom），不会成为瓶颈。

6.3 吞吐代价分析

Muon 的 Newton-Schulz 正交化在每步迭代中需要 5 次矩阵乘法（对 2D 权重矩阵），这是额外的计算开销。在 TP1/DP8 配置下，这些计算无法被通信隐藏，直接增加了每步耗时（753 ms vs 555 ms = +36%）。但在 layer-wise distributed Muon（dist_muon）配置下，正交化可以与梯度同步重叠，NVIDIA blog 报告在 GB300 上 Muon 吞吐接近 AdamW 持平。

6.4 P-8 建议

方案 A（推荐）：P-8 采用 dist_muon（layer-wise distributed Muon），兼顾 loss 优势与吞吐。需额外验证 dist_muon 在 8×H100 上的实际吞吐。

方案 B（保守）：P-8 沿用 AdamW（249K tok/s），但训练步数增加 ~25% 以达到 Muon 的 loss 水平。

方案 C（折中）：P-8 用 Muon（TP1/DP8），接受 26% 吞吐损失。以 100B token / 87K tok/s 计算，训练时间从 ~4.6 天延长至 ~13.2 天 — 需评估是否在时间预算内。

6.5 局限性

  • 本 A/B 仅跑 1000 步（6.55M tokens），远低于 P-8 的 44B-100B token 预算。Muon 的优势在长训练中是否持续，尚需验证。
  • 两臂使用相同的 LR schedule（peak 3e-4），未对 Muon 单独调参。Muon 通常受益于更高的 LR（官方建议 ~1e-3），单独调参可能进一步扩大优势。
  • 未测 dist_muon（layer-wise distributed）配置的吞吐，无法确认 NVIDIA blog 声称的“持平”在本硬件上是否成立。
  • 显存测量在 iter 10 后采样，checkpoint 保存时的瞬时峰值未记录。
