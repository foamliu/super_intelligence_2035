2.2 关键策略差异分析

Xmodel-2 的 Stable 单段 vs Xmodel-2.5 的 S1/S2 分段

Xmodel-2（xmodel-2.tex:136）：单段 Stable，batch 3.93M tokens，~1.5T tokens，LR 0.01。Loss 曲线显示 batch 从 2M→4M 时出现台阶下降（xmodel-2.tex:183："The initial drop corresponds to increasing the batch size from 2M to 4M, which likely replicates the stabilizing effect of a reduced learning rate"）。

Xmodel-2.5（method.tex:40-41）：将 Stable 分为 S1（270k 步，batch 1.78M）和 S2（260k 步，batch 3.56M），batch 翻倍。总 Stable ≈ S1 481B + S2 927B = ~1.41T tokens。S1/S2 的步数接近 1:1，但 S2 的 token 是 S1 的 2×（batch 翻倍）。

差异本质：Xmodel-2 的 batch 2M→4M 是 训练中途增大（loss 曲线可见台阶），Xmodel-2.5 把这个策略显式化为 S1/S2 两段。两者的理论依据相同：增大 batch ≈ 等效降低 LR（Smith et al. 2018 / 批量缩放定律），在训练后期增大 batch 可在不改变 LR 调度的情况下获得额外的收敛稳定性。

Decay 阶段对比

Xmodel-2 decay = 5000 步 × 3.93M = 20B tokens（xmodel-2.tex:138），指数退火 f(s-T)=0.5(s-S)/T，T=5000 步。SFT 占比经 400+ 次试验搜索，最优 64%（区间 60-69%）（xmodel-2.tex:144-146,154）。SFT-Mixed 由 Math/Code/Logic/Knowledge/Commonsense 5 类构成，指令格式 > 预训练格式，SimHash 去重 +1.7%，整体复杂推理 +29.31%。

Xmodel-2.5 decay = 20k 步 × 3.56M = ~71B tokens（method.tex:42），SFT 占比 66.9%。关键增量：AdamW→Muon 优化器切换（method.tex:46-49），13 任务均分 +4.58pp。随后 LCR（长上下文推理）10k 步，13 任务均分 52.36→52.49（result.tex:37）。

BaiZe P-8 decay = 1149 步 × 4.19M = 4.8B tokens（EXPERIMENTS_PRETRAIN_2B.md:151），远短于 Xmodel-2 的 20B。LR 线性退火 1e-3→1.85e-5，loss 2.456→1.357（含 SFT blend 的分布偏移成分）。SFT 64% + L3 24% + code 8% + math 4%。

MiniCPM5 数据落盘状态（以 v4 §1.2 + 运维实测 RUN_ID 98/99 为准，DATA_RESEARCH.md v1.1 的落盘状态已过时）：

§3 BaiZe-2B 推荐训练策略

3.1 问题①：Stable 要不要分 S1/S2？

结论：
• 200B 档（推荐起步）→ 不分。BaiZe GBS=1024 × seq=4096 = 4.19M tokens/batch，已与 Xmodel-2 的 3.93M 同级、超过 Xmodel-2.5 的 S2 (3.56M)。在 200B 规模（~42k 步），单段 Stable 足够，分段增加复杂度但收益有限。
• ≥500B 档 → 建议分。S1 (GBS=512, ~2.10M) 占 stable 总量的 ~40%，S2 (GBS=1024, ~4.19M) 占 ~60%。切换点制造 loss 台阶（Xmodel-2/2.5 均观察到），等效于训练后期降低 LR。
• ≥2000B 档 → 分段 + 可选三段。S1 (2.10M) → S2 (4.19M) → S3 (8.39M, GBS=2048)（如显存允许），每段约 stable 总量的 1/3。

分段依据与折算

Xmodel-2.5 的 S1/S2：S1 = 270k 步 × 1.78M = 481B tokens（占 stable 的 34%），S2 = 260k 步 × 3.56M = 927B tokens（占 66%）。总 stable ≈ 1.41T。

注：墙钟按 ~249K tok/s（P-8 实测，EXPERIMENTS_PRETRAIN_2B.md:120）折算。GBS=512 时吞吐可能略降（更多 kernel launch overhead），实际墙钟可能 +5-10%。S1/S2 的总 token 和总算力与单段相同，差异仅在优化动态。
不确定性标注：
① LR 差异影响：Xmodel-2/2.5 的 LR=0.01/1.67e-3，BaiZe LR=1e-3。batch 增大的「等效降 LR」效果在低 LR 下边际递减——BaiZe 的 LR 本已低至 Xmodel-2 的 1/10，batch 翻倍的等效降 LR 幅度可能不足以制造显著 loss 台阶。
② 架构差异：Mamba2-hybrid 的 SSM 层（52/56 层）与 Attention 层（4/56 层）对 batch size 的响应可能不同。SSM 的递推计算使梯度噪声结构与 Dense Transformer 不同，batch scaling 定律能否迁移未经验证。
③ 建议验证方式：若决定分段，先在 P-8 ckpt 基础上做 ≤30 GPU·min 的小规模测试（GBS 512 vs 1024 各跑 200 步，对比 loss 曲线是否有台阶）。

3.2 问题②：GBS 是否「先 2M 再 4M」？依据？

结论：与问题①联动。200B 档全程 GBS=1024（4.19M），不分段。≥500B 档 GBS=512（2.10M）→ GBS=1024（4.19M）。

seq=4096 下的换算

BaiZe: 8×H100, TP1/DP8, MBS=2, seq=4096 GBS = MBS × grad_accum × 8 (GPU数) GBS=512 → grad_accum = 32 → batch = 2,097,152 ≈ 2.10M tokens GBS=1024 → grad_accum = 64 → batch = 4,194,304 ≈ 4.19M tokens GBS=2048 → grad_accum = 128 → batch = 8,388,608 ≈ 8.39M tokens

依据：

  1. Xmodel-2 loss 曲线（xmodel-2.tex:183）：batch 从 2M→4M 时 loss 出现台阶下降，论文解释为"likely replicates the stabilizing effect of a reduced learning rate"（Smith et al. 2018）。
  2. Xmodel-2.5 显式分段（method.tex:40-41）：S1 batch 1.78M ≈ 2M，S2 batch 3.56M ≈ 4M，batch 翻倍是核心设计。
  3. 批量缩放理论（NeurIPS 2024, Surge Phenomenon）：对 Adam 类优化器，最优 LR 随 batch size 先升后降，大 batch 时最优 LR 趋于稳定值。增大 batch 在训练后期等效于降低 LR 的噪声成分。
  4. BaiZe P-8 的 batch 已大：P-8 GBS=1024 × seq=4094 = 4.19M，已处于 Xmodel-2 的 4M 档。若全程 4M，则没有"先小后大"的台阶效应。
关键不确定性：Xmodel-2/2.5 的 LR=0.01/1.67e-3，batch 增大等效降低的 LR 幅度 = LR × (噪声缩减因子)。BaiZe LR=1e-3（低 10×），等效降低的绝对幅度仅 Xmodel-2 的 1/10。在 BaiZe 的低 LR 下，batch 翻倍的 loss 台阶可能很小或不可见。这支持 200B 档不分段的结论。

3.3 问题③：Decay 用多少 token？

结论：
• 推荐 20B 起（Xmodel-2 标准，5000 步 × 3.93M = 20B），对应 BaiZe GBS=1024/seq=4096 = ~4,770 步，~24h 墙钟。
• 500B 档备选 30B（~7,150 步，~35h）。
• 2000B 档备选 50B（~11,920 步，~58h）。
• 判定依据：用 P-8 现有 ckpt（iter_9441，stable 末点）沿 LR 衰减做小规模外推，不重训。

为什么 20B 而非 P-8 的 4.8B？

  • P-8 decay 仅 1149 步（4.8B），loss 从 2.456→1.357 的骤降含大量 SFT 数据分布偏移成分（S4 实验已警示：EXPERIMENTS_PRETRAIN_2B.md:14："code/math 源本身熵更低，loss 降幅含分布偏移成分"）。这不是纯退火增益。
  • Xmodel-2 用 20B（5000 步）做 decay，在其 1.5T 总量中仅占 1.3%，但论文报告复杂推理 +29.31%。
  • WSD 调度的核心优势（WSD Schedule）：stable 段不编码训练长度，可从任意 plateau ckpt fork 出来做 decay。BaiZe 可从 stable 末点 ckpt 做 decay，不需要预知总步数。

判定方法（小规模外推，≤30 GPU·min）：

# 从 P-8 stable 末点 ckpt (iter_9441) 做 LR 衰减外推 # 不加载 optimizer/scheduler state（finetune mode，同 P-8 decay fix 方法） # 跑 500 步 decay (1e-3→1e-5 线性)，观察 loss 是否持续下降 # 若 500 步后 loss 仍在降 → 20B (4770步) 合理 # 若 500 步后 loss 已平台 → 可缩短至 10B # 若 500 步后 loss 仍快速下降 → 可延长至 30-50B

§4 数据配比实验：做不做 / 怎么做 / 优化指标

4.1 Stable 段：已做，不需要再做

结论：已做，不需要再做。
R1/R2/R3 三轮 BO 已完成 300+ trials（DATA_MIX_RECIPE.md:275-318）：
  • R1：200 trials，3 维 (web:code:math)，18.36M 代理，Spearman ρ=−0.43（代理↔目标相关性）
  • R2：200 trials，3 维，best t23=0.4155
  • R3：100 trials，6 维单纯形 (en/zh/l1/ultrax/code/math)，best #8=0.4032，landscape 平坦：top-5 Δ=0.0053（均值的 1.3%）
  • Top-K 相关性 ρ=−0.80（top 候选的代理↔目标相关性显著强于全量 ρ=−0.43，说明 BO 的方向是对的）
R3 核心结论：在 18.36M 代理 + 1B token 规模下，精确配比对 lm_eval 8 集均分影响很小（DATA_MIX_RECIPE.md:310）。这意味着正式训练不需要过度优化配比，合理范围即可。

4.2 Decay 段：可做，但建议跳过

结论：建议跳过，直接用 64% SFT。 把握：高（85%）。
理由：
  1. Xmodel-2 已做 400+ trials（xmodel-2.tex:144-146），SFT 60-69% 最优，取 64%。这是 1.2B Dense Transformer 上的结论。
  2. BaiZe P-8 已实证 64% 可用（EXPERIMENTS_PRETRAIN_2B.md:150），decay loss 2.456→1.357。
  3. Xmodel-2.5 用 66.9%（method.tex:42），在 64% 的区间内。
  4. Decay 段的核心变量不是配比而是 LR 退火策略 + 数据质量（Xmodel-2 原文：xmodel-2.tex:146 "instruction-formatted datasets in mathematics and code outperform pretraining-format data"）。

4.3 优化指标定义（若做配比实验）

🚫 不要只盯 loss。Xmodel-2 原文已证明：xmodel-2.tex:154 "These adjustments, combined with optimized data mixing and processing, improved complex reasoning performance by 29.31%"——loss 与下游任务的因果关系在 decay 段不成立（SFT 数据的熵更低，loss 下降含分布偏移成分）。

推荐优化指标：加权平均分

Score = 0.30 × CS8_avg + 0.40 × Complex6_avg + 0.30 × Chinese_avg CS8_avg = mean(ARC-Challenge, ARC-Easy, BoolQ, HellaSwag, OpenBookQA, PiQA, SciQ, Winogrande) [0-shot] Complex6_avg = mean(GSM8K, MATH, BBH, MMLU, HumanEval, MBPP) [shot 数用 lm-eval 默认] Chinese_avg = mean(C-Eval, CMMLU) [5-shot]
组件权重理由
常识推理 8 集 (CS8)0.30基础语言能力，stable 段已优化，decay 段权重可降
复杂推理 6 集 (Complex6)0.40decay 段的核心目标（Xmodel-2 +29.31% 复杂推理），最高权重
中文 (C-Eval + CMMLU)0.30BaiZe 是中英双语 Mamba2-hybrid，中文能力不可忽视
权重理由：
• Complex6 权重最高 (0.40)：decay 段的核心价值是复杂推理提升（Xmodel-2 的 +29.31% 主要来自 decay 配比优化）。P-8 实测 Complex6 Avg=6.81%（EXPERIMENTS_PRETRAIN_2B.md:236），远低于 Xmodel-2 的水平，说明 decay 段有大量提升空间。
• CS8 权重 0.30：P-8 实测 CS8 Avg=49.21%，在 20B token 后已趋饱和（P-5b 20B = 49.22% vs P-8 44.4B = 49.21%，EXPERIMENTS_PRETRAIN_2B.md:224），decay 段对 CS8 的边际增益有限。
• Chinese 权重 0.30：BaiZe 的中文 web 数据占 Web 总量的 ~15%（R3 BO），但 C-Eval/CMMLU 是中文能力的直接度量。Xmodel-2.5 Table（result.tex:26-27）显示 C-Eval=45.54% / CMMLU=47.16%，BaiZe 需要追赶。

4.4 代理↔目标相关性验证与迁移依据

既有口径（DATA_MIX_RECIPE.md:14 + R1/R3 结果）：
• R1 Spearman ρ=−0.43（全量 200 trials，代理 18.36M → 目标 2.22B）
• R3 Top-K ρ=−0.80（top 候选子集，方向性更强）
• 理论依据：Ye et al. 2024, Data Mixing Laws —— 小模型配比实验可迁移到大模型（Xmodel-2 xmodel-2.tex:142 引用）。
迁移边界：
① ρ=−0.43 是全量相关性，说明代理模型对配比的排序与目标模型只有中等相关。Top-K ρ=−0.80 更强，意味着 BO 筛选出的 top 候选方向可信，但精确排名不一定一致。
② 代理 18.36M → 目标 2.22B 是 121× 参数差距。Data Mixing Laws 的验证范围通常在 10× 以内。121× 的迁移未经独立验证，但 R3 landscape 平坦（Δ=0.0053）意味着即使迁移有误差，对最终性能的影响也极小。
③ Mamba2-hybrid vs Dense Transformer：Data Mixing Laws 在 Dense Transformer 上验证，Mamba2-hybrid 的 SSM 层可能对配比的响应不同。这是本报告最大的未验证假设。

5.2 数据风险

SFT 过采样（v4 §3.3）：SFT 总量 29.0B，在 decay 段占 64%。D=200B 时 SFT epoch=0.44（安全）；D=50B decay 时 epoch=1.10（轻微过采样）；但若 decay 延长至 100B，epoch=2.2（需关注）。decay ≤50B 安全。

数据可用量：v4 §3.2 统计已分词 2,015B + en_v1_4 下载中 ~217B = ~2,232B。200B 档仅用 9% → epoch < 1（不过采样）；2000B 档用 90% → Web epoch ~1.0、L3 epoch ~0.3、Code epoch ~0.5。全量 2000B 档 Web 接近 1 epoch，安全。

5.3 算力风险

8×H100 独占假设：P-8 吞吐 ~249K tok/s 基于独占 8 卡。若与 vision 任务（10.239.2.12）或其他任务争用 NFS 带宽，吞吐可能降 10-20%。200B 档墙钟 232h → 可能延至 ~260h。

Chinchilla 最优 vs 过训练：2.22B 的 Chinchilla 最优 = 44B token（P-8 已达）。200B = 4.5× Chinchilla，500B = 11×，2000B = 45×。Hoffmann et al. 2022 指出过训练对小模型有益（SmolLM3 3B/11T = 3,667 tok/param），但收益递减且主要为常识/知识，复杂推理仍受模型容量限制（v4 §4.4 已标注：P-8 Complex6 Avg=6.81%，GSM8K=1.52%，MATH=0%）。

5.4 BaiZe 早期学习能力评估

基于 P-8 中间 ckpt + Xmodel-2/2.5 history ckpt 的 14 集 eval（MEMORY_PRETRAIN_2B.md:5）：
• BaiZe P-8 iter_9441 (39.6B tok) CS8 = 49.21% vs Xmodel-2 s1/10K (39.3B tok) CS8 = 46.65% → BaiZe +2.56pp，早期学习不弱于 Xmodel-2（但参数量不同：BaiZe 2.2B vs Xmodel-2 1B，需注明）。
• Xmodel-2 final (1.5T) CS8 = 64.82%，Xmodel-2.5 final (1.4T) CS8 = 65.40% → BaiZe 200B 档预期 CS8 ~53%（v4 §4 外推），距 Xmodel 系列 ~12pp（34× token 差距 + 架构差异）。
• 结论：BaiZe 在相同 token 量下的早期学习能力不显著弱于 Xmodel 系列。差距主要来自训练量（44B vs 1.5T），而非模型本身的学习效率。

6.5 诚实条款（Honesty Clause）

本报告的局限性，明确声明：
  1. 所有定量推荐均基于 P-8 的 44.4B token 实验 + Xmodel-2/2.5 论文数据的外推。从 44B 外推到 200-2000B 是 5-45× 外推，缩放曲线 R²=0.964 仅在 0.65-20B 范围验证（v4 §4），200B 以上的外推置信度递减。
  2. 架构迁移未经验证：Xmodel-2/2.5 是 Dense Transformer，BaiZe 是 Mamba2-hybrid（52 SSM + 4 Attention）。batch scaling 定律、LR 调度、配比迁移定律均在 Dense Transformer 上验证。Mamba2-hybrid 的 SSM 层对 batch size / LR / 配比的响应可能不同。这是本报告最大的系统性风险。
  3. MiniCPM5 的预训练策略细节不公开：仅知数据源相同（UltraData 家族）+ post-training 400B SFT。无法做精确的逐阶段对照。
  4. P-8 的 Complex6 Avg = 6.81%（GSM8K=1.52%, MATH=0%），极低。200B 档预期 Complex6 仍受模型容量限制（v4 §4.4），不会因 4.5× 训练量而有质变。复杂推理的突破可能需要 ≥500B + 更高质量数据 + 可能的架构改进。
  5. 本报告不保证 200B 档能达到任何特定的下游 benchmark 分数。所有预期分数（如 CS8 ~53%）均为外推估计，实际结果取决于训练动态、数据质量、随机种子等不可控因素。
  6. Muon 优化器在 BaiZe 上已发散（dist_muon step 8490），Xmodel-2.5 的 +4.58pp 增益无法迁移。BaiZe 全程使用 AdamW，这限制了 decay 段的优化空间。
