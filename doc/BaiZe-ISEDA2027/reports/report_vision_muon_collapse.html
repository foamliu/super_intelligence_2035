BaiZe Vision — V2 Muon 优化器坍缩根因分析报告

生成时间：2026-10-11 · 线：vision · 性质：纯分析（读已有日志/曲线/实验记录，未新跑 GPU） · 关联文件：EXPERIMENTS_VISION.md §9.2

1. TL;DR — 一句话结论

Muon 优化器（Newton–Schulz 正交化动量）在 BaiZe 视觉编码器的 AIMv2 式联合目标（InfoNCE + masked-patch-MSE）下，于所有测试学习率均引发对比坍缩（contrastive collapse），不可用。

  • 坍缩边界：lr=5e-4 于 step 2,100 坍缩（C1=0.99）；lr=1e-4（5× 更低）于 step 4,200 坍缩（C1=0.9569）—— 降低 LR 仅延缓、不阻止坍缩，坍缩终点相同。
  • 坍缩模式：C1 单调加速上升（0.18→0.96），零回退；Loss 同步下降（7.39→7.30）—— 模型在"降重构 loss"的同时特征坍缩（典型对比学习失效模式）。
  • AdamW 基线对照：同配置仅换优化器 = C1 稳定在 0.10–0.55（全程 187k 步无坍缩），C2_gap 恒正（+0.15~+0.27），Loss 强劲下降（7.19→0.79）。
  • 根因：推断+实测佐证 Newton–Schulz 正交化将每模块梯度投影到谱范数≈1 的正交矩阵，放大了对比目标的主导坍缩方向；AdamW 的逐参数自适应缩放天然抑制该方向。
  • 不泛化：pretrain 线用 Muon/dist_muon 训练 2.2B LLM（纯 CE loss）成功（loss −22.3% vs AdamW，无坍缩）—— Muon 的不兼容仅限于"含 InfoNCE 对比项的联合目标"，不是 Muon 本身有问题。

Muon 实现细节

因 emerging_optimizers 在 vision 环境不可 pip install（超时），采用 r9_train.py 中的独立实现（r9_train.py:45-147）：

  • zeropower_via_newtonschulz5(G, steps=5)：5 步 Newton–Schulz 迭代逼近矩阵符号函数（= SVD 的正交因子 U·Vᵀ），系数 (a,b,c)=(3.4445, -4.7750, 2.0315)。
  • Muon 类：momentum → Nesterov → Newton–Schulz 正交化 → 更新。1D 参数回退到 plain momentum SGD。
  • MuonAdamW 混合包装器：2D 权重 → Muon；1D → AdamW。参数分组遵循 pretrain dist_muon 约定。

4.2 哪一层先崩？

未直接测量 训练日志未输出 per-layer C1/梯度范数，无法确定"哪一层先崩"。但从机理推断 推断：

  • 对比头（projection head）最可能先崩：InfoNCE 梯度直接作用在 projection head → image/text features 的对齐上，正交化后的等范数更新会均匀放大所有方向的投影，使所有图像特征趋向同一方向。
  • ViT trunk 随后坍缩：一旦 projection head 坍缩，回传到 trunk 的梯度也将沿坍缩方向，加速整体 C1 上升。
  • 文本塔冻结：CLIP 文本塔不更新，所以坍缩仅发生在 vision 侧——这与 C2_gap 恒负（vision features 协方差非对角占优）一致。

5. 根因分析（核心）

为什么 Muon 与「InfoNCE + masked-patch-MSE 联合目标」不兼容？以下逐条机理假设，每条标注「实测 / 推断」。

假设 ①：对比目标的梯度各向异性 vs Muon 逐模块正交化 推断+实测佐证

InfoNCE 损失的梯度天然具有强各向异性——沿"坍缩方向"（所有特征趋向同一向量）的梯度远大于正交方向。AdamW 的逐参数二阶矩估计会自适应缩放每个参数的更新幅度，自然抑制主导方向。而 Muon 的 Newton–Schulz 正交化将梯度投影为谱范数≈1 的正交矩阵，消除了方向间的幅度差异——主导坍缩方向被等比例放大，正交（有信息）方向被等比例缩小。

实测佐证：C1 单调加速上升（0.18→0.96，零回退），表明坍缩方向被持续放大而无任何阻尼；AdamW 下 C1 在 0.10–0.14 波动（step 300–3000），表明坍缩方向被有效抑制。

假设 ②：两目标梯度尺度失衡被 Muon 放大 推断

联合目标 1.0×InfoNCE + 1.0×masked-patch-MSE 中，InfoNCE 梯度（对比温度 × 余弦相似度导数）与 patch-MSE 梯度（L2 导数）的尺度量级不同。在 AdamW 下，每个参数的更新由两个梯度分量的加权和经二阶矩归一化后决定，尺度差异被吸收。在 Muon 下，正交化作用于合并后的梯度矩阵，尺度较大的梯度方向（InfoNCE 对比项）主导正交化结果，尺度较小的方向（patch-MSE 重构项）被进一步压制。

实测佐证：Muon 下 contrast loss 几乎不动（6.30→6.32），而 patch_mse 微降（1.08→0.99）——重构项在学习但对比项被"锁死"在坍缩方向上。

假设 ③：等范数更新与冻结文本塔 / InfoNCE 头不匹配 推断

InfoNCE 依赖 image features 与 text features 的相对几何关系（余弦相似度排序）。文本塔冻结意味着 text features 固定，只有 vision 侧在更新。Muon 对 vision 侧的每层权重做等范数正交化更新，导致各层输出的范数不受控（只有方向被正交化，幅度由 LR 决定）。这破坏了 InfoNCE 所需的"特征范数与余弦相似度的稳定关系"——logit_scale 从 10.0 仅降至 7.22（vs AdamW 降至 4.0），对比温度过高加剧坍缩。

实测佐证：scale 值在 Muon 下保持高位（7.22 vs AdamW 4.0），对比温度高 → softmax 分布尖锐 → 坍缩加速。

假设 ④：LR 只是触发因素而非根因 实测

5× 更低的 LR（1e-4 vs 5e-4）将坍缩从 step 2,100 延缓到 step 4,200（2× 延迟），但坍缩终点完全相同（C1≈0.96）。这证明 LR/warmup 只是控制坍缩速率的触发因素，根因是 Muon 的正交化机制本身——无论多慢，正交化都会放大坍缩方向。如果根因是 LR 过高，降低 LR 应该能完全避免坍缩；但实际上只是推迟。

6. 排除项（反证）

排除假设反证依据结论
LR 太高？AdamW 同 LR=5e-4 不坍缩（C1 稳定 0.10–0.55，全程 187k 步）；Muon 5× 更低 LR=1e-4 仍坍缩（仅延缓 2×）✅ 排除
Schedule/warmup？Muon 和 AdamW 用完全相同的 cosine + warmup=2000；坍缩发生在 warmup 结束后的稳态阶段（step 2100/4200，均在 warmup=2000 之后）✅ 排除
数据问题？Muon 和 AdamW 用完全相同数据（shards=10,787）；V3（AdamW + 全量 11,350 shards）也不坍缩（C1 稳定 0.50–0.53）✅ 排除
分辨率/架构？Muon 和 AdamW 用完全相同架构（OV2 w512/d30, 224/p16）；E2fair（w768/d30）用 AdamW 也不坍缩✅ 排除
Muon 实现 bug？zeropower_via_newtonschulz5 系数与 Keller Jordan 原版一致 (3.4445, -4.7750, 2.0315)；pretrain 线用 emerging_optimizers 库版 Muon 在 LLM 上也不坍缩——两组实现行为一致✅ 排除
Seed/初始化？两次 Muon 启动用相同 seed=1234，坍缩模式一致（C1 单调加速，终点 C1≈0.96）；AdamW 同 seed 不坍缩✅ 排除

所有非优化器因素均已通过同配置对照排除。唯一变量 = 优化器类型（AdamW vs Muon），唯一结果差异 = 坍缩 vs 不坍缩。

7. 结论与边界

✅ 确切结论

  • Muon 在 BaiZe 视觉编码器栈（OV2 w512/d30 + AIMv2 式 InfoNCE+masked-patch-MSE + 冻结 CLIP 文本塔）下不兼容——在 lr=5e-4 和 lr=1e-4 两个学习率下均坍缩，C1 单调加速至 >0.95。
  • 不兼容的根因是 Muon 的 Newton–Schulz 正交化与 InfoNCE 对比目标的坍缩方向放大效应——正交化消除了梯度方向间的幅度差异，使主导坍缩方向被等比例放大。
  • 降低 LR 仅延缓不阻止坍缩（5e-4@2100 → 1e-4@4200），坍缩终点相同——根因不是 LR 而是优化器机制。

🚫 边界（不要泛化）

  • 不能泛化为「Muon 不行」：pretrain 线用 Muon/dist_muon 训练 2.2B LLM（纯 CE loss）成功（详见下表）。
  • 不能泛化为「Muon 不能用于视觉」：我们只测了 AIMv2 式联合目标，未测纯 MAE/DINOv2 等纯视觉自监督目标——这些目标不含 InfoNCE 对比项，可能不存在坍缩问题。
  • 不能泛化为「正交化优化器都不能用于对比学习」：我们只测了 Muon（Newton–Schulz），未测 Lion（符号函数）、Shampoo（预条件）等其他正交化类优化器。

8. 后续建议（可执行）

#建议思路GPU 成本判据风险
1MuonClip（梯度裁剪+正交化）在 Newton–Schulz 前加梯度裁剪（如 ‖g‖₂<τ），限制坍缩方向放大倍数；或对 C1 敏感层（projection head）做额外缩放~3 GPU·hC1 在 5k 步内保持 <0.5中：阈值需调参
2混合优化器（trunk→Muon, head→AdamW）仅对 ViT trunk 的 attention/FFN 权重用 Muon，projection head 和 logit_scale 用 AdamW——隔离对比头不受正交化影响~3 GPU·hC1 稳定 + loss 正常下降 + lp≥baseline低-中
3排除 projection head 用 Muon当前 MuonAdamW 已将 1D 参数分给 AdamW；可进一步将 projection head 的 2D 权重也分给 AdamW，只对 ViT 层用 Muon~3 GPU·hC1<0.5 + lp≥baseline低：最小改动
4换目标（去 InfoNCE，纯 MAE/DINOv2）如果目标是"用 Muon 加速视觉训练"，可考虑去掉对比项、只保留 masked-patch-MSE——无对比坍缩风险，但丢失文本对齐~80 GPU·hlp≥60% + 无坍缩 + Muon 收敛更快高：放弃 zs 能力
5不重试，保持 AdamW当前 AdamW 基线已稳定收敛（lp=62.34%），Muon 的潜在收益（更快收敛）在本栈上不确定——机会成本可能不值得0—无（最保守）

推荐优先级：③（成本最低，风险最小）→ ②（隔离对比头）→ ①（MuonClip 调参）。④不推荐（与本线目标冲突）。⑤是默认选项——如无运维特别要求，保持 AdamW。

  • Muon 实现为独立版本：未用 emerging_optimizers 库（pip 超时），但系数与原版一致，且 pretrain 线用库版也不坍缩——两组实现行为一致，排除实现差异。
  • 仅测 2 个 LR：未测 lr=2e-4 / 5e-5 等中间点——但 lr=1e-4 已坍缩且 5× 延迟规律清晰，额外 LR 点 unlikely 改变结论。
