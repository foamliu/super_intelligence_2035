2. ③ Protocol Revision — Reference System & Non-Comparability

⚠️ Non-Comparability Declaration

All linear-probe (lp) accuracies in this report are measured under the BaiZe internal evaluation protocol (Protocol A or Protocol B) and MUST NOT be directly compared with published external numbers (e.g., CLIP zero-shot, OpenCLIP, MAE, DINOv2, iBOT linear-probe). The absolute lp values are only meaningful relative to other BaiZe-internal arms using the same objective, same data scale, same epoch count, and same evaluation protocol.

3. ① Same-Model Zero-Shot — "Did features benefit from text alignment?"

Protocol

We evaluate the model's own zero-shot classification on the official IN-1k validation set (50,000 images), using the frozen CLIP text tower and the trained contrastive projection head. This is not an external benchmark — it uses the same model components that were trained together.

Construction: image features → trained projection head → 768-d → cosine similarity with CLIP text embeddings of "a photo of a {class_name}" prompts (1000 IN-1k classes). Text tower (CLIP-ViT-L/14-336, 768-d) is frozen throughout.

5.3 C1 Trajectory (3rd attempt, lr=1e-4, 14 PROBE points, zero reversals)

5.4 Key Observations & Root Cause

  • C1 rise is monotonic and accelerating: 0.18 → 0.96 in 3,900 steps. Zero reversals across 14 PROBE points.
  • Loss IS decreasing (7.39 → 7.30): model reduces reconstruction loss but features collapse — known failure mode of contrastive objectives.
  • C2_gap always negative (off-diagonal > diagonal): C2 guard never fires; only C1 catches collapse.
  • 5× lower LR delays but does not prevent collapse: 2,100 → 4,200 steps, same endpoint C1≈0.96.
  • Root cause: Newton-Schulz orthogonalization forces unit-norm gradients, amplifying the dominant collapse direction. AdamW's per-parameter adaptive scaling naturally damps this. Muon works for pure language modeling (pretrain line) where there is no contrastive collapse pressure, but is fundamentally incompatible with the InfoNCE contrastive component of our AIMv2-style objective.

9. Summary of Findings for External Reviewer

Question: Why is E1fair ProtB = 62.34% "low" compared to published benchmarks?

Answer: It is NOT low — it is a genuine result under a fundamentally different protocol

  • Not an evaluation artifact: Probe is well-converged (×5 epochs → 62.15%, lower than 90ep). No probe config exceeds 62.68% (+0.35pp). 62.34% is a feature quality ceiling.
  • Not a training budget issue (pending ④ confirmation): V3 with +23% more data/steps gained only +1.18pp (Null). If ④-2ep also shows Null, then 1 epoch is sufficient and bottleneck is objective+data, not budget.
  • Not comparable to external numbers: Different objective (AIMv2-style ≠ CLIP/MAE/DINOv2), different data (95.8M/1ep ≠ LAION-2B/multi-ep), frozen text tower, different evaluation protocol. See §2.
  • Not a data scale issue (at this range): V3 (118.1M) vs E1fair (95.8M) = +1.18pp Null. Consistent with R9/R10: data-limited regime, ~649× data gap to reach AIMv2-level performance.
  • Not an optimizer issue: Muon (stronger optimizer for LLMs) causes collapse with contrastive objectives. AdamW is correct choice.
  • Features DID benefit from text alignment: zs=34.10% >> 0.1% chance. But lp=62.34% >> zs=34.10% (+28pp), showing dense reconstruction adds substantial representation quality.
