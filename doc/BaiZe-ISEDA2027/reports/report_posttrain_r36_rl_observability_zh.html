1. 摘要

R22 在 RL config YAML 中注释了"Monitoring & early stopping"但从未实现。GRPO 训练可能静默发散——KL 爆炸、奖励坍缩、熵坍缩、梯度爆炸——若无监控，GPU 时间可能被浪费数小时而不自知。

R36 交付：baize_posttrain_rl_monitor.py（~445行）——7种发散检测+早停+检查点建议+恢复程序，纯标准库零依赖，已通过 py_compile + 合成日志测试。

3. 恢复程序

模式恢复命令备选
P1 KL爆炸--kl_loss_coef 0.04 --lr 1e-6减ppo_epochs 2→1
P2 奖励坍缩--reward-arm R0(骨架模式)混入L1/L2易题
P3 方差坍缩--group_size 16R1→R2切部分分
P4 熵坍缩--entropy_coeff 0.01增采样温度
P5 梯度爆炸--lr 1e-6 --grad_clip 0.5停训resume
P6 NaN立即停训 --resume-ckpt检查fp16溢出
P7 作弊率--reward-arm R4(API合法性)收紧ngram 8→5

4. 集成方式

# Terminal 1: 训练
bash baize_posttrain_rl_grpo.sh --reward-arm R2 --gpu-ids 0,1,2,3

# Terminal 2: 监控 (独立进程，不占GPU)
python baize_posttrain_rl_monitor.py \
    --log-dir $OUTPUT_DIR/logs \
    --save-dir $OUTPUT_DIR \
    --poll-interval 30 \
    --output /tmp/rl_monitor_state.json

STOP信号：CRITICAL连续5步→写RL_STOP_SIGNAL文件，训练wrapper每epoch检查。
