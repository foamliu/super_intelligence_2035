1. 摘要

在 11/9 GPU 到位前 2 天，对全部 posttrain 脚本进行端到端审计，发现并修复 6 类 critical 缺陷（路径不存在、占位入口、推理后端不匹配、预检过时），创建 master 编排脚本，并与 DeepSeek-R1 (Nature) 论文进行 GRPO 超参对账。全部 14 个文件通过语法检查，dry-run 验证通过。

2. 🔴 Critical 路径发现：/nas_train 空目录

问题：.17 上 /nas_train → /H100_train（空目录），实际 NFS 数据在 /nas_data（127T）。5 个脚本 + 1 个 YAML 硬编码 /nas_train，全部会失败。
修复：创建 baize_posttrain_paths.sh 自动检测模块。所有脚本 source 此文件，用 $NAS_ROOT 替代硬编码路径。6 个文件已修复，bash -n 全部通过。

3. 🔴 RL 入口：占位 → verl

问题：baize_posttrain_rl_grpo.sh 使用不存在的 grpo_train.py 占位入口。
修复：重写为 python -m verl.trainer.main_ppo --config baize_posttrain_rl_verl_config.yaml --reward.arm R2。默认替身 MiniCPM5-2B，R2 部分分奖励，4×A40。dry-run 验证通过。

4. 🔴 诊断脚本：vLLM → SGLang

问题：R8 发现 MiniCPM5-2B 使用 XML 格式工具调用，vLLM 无法解析 → tool_calls 为空 → 36% 基线不可比。
修复：vllm serve → python -m sglang.launch_server --tool-call-parser minicpm5。venv 切换到 cu124 兼容环境。
