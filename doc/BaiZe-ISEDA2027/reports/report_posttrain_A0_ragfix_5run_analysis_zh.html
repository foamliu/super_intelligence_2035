6.3 各方法要点与适用性

  • 蒸馏（SFT from teacher traces）：直接把大模型「正确做法」压进 2B，对 F1/F4（不会调用工具）最有针对性。CodeV-R1 验证「蒸馏冷启动 + RL」两阶段在 EDA 代码生成上超越 671B 教师蒸馏基线（VerilogEval v2 68.6%，二手·未核）。
  • DPO / 偏好优化：不直接优化绝对正确率，而是学习「好轨迹 vs 坏轨迹」的相对排序，适合稳定蒸馏结果、剔除 reward hacking 噪音。Tulu 3（AI2, 2024）证明 SFT→DPO→RLVR 组合 recipe 有效。
  • RLVR / GRPO：用可验证奖励（check.py 断言、编译通过、仿真比对）做强化学习，直接攻克 F5 逻辑错误——因为只有「在真实环境跑通」才给奖励，模型被迫学会从 AssertionError 中自我修正。VeriReason 用 SFT+GRPO+testbench 反馈把 Verilog 生成准确率推到 83.1%（二手·未核），与我们的 85% 目标量级吻合。
  • OPD（On-Policy Distillation）/ ReST 自训练：RL 负责「探索新轨迹」，蒸馏负责「把探索成果压缩回小模型」，且用 token 级 KL 约束避免学生偏离教师。针对我们的 F3 超时（9.4%）与 34 万 token/题的成本，OPD 可显式惩罚长轨迹。

6.4 风险与诚实话术（铁律 3/5）

  • 蒸馏泄漏风险：教师轨迹若直接暴露「参考答案」，学生会作弊式拟合而非学会推理——必须用 PreToolUse hook + 逐题扫 trace，命中即判 cheat 单列。
  • OPD token 级 KL 压实风险：过强压缩会把「错误中间步骤」一并压进去（Thinking Machines 2025 明确警告），需保留 RL 探索阶段。
  • reward extrapolation cliff：RL 奖励只在训练分布内可信，偏离分布会崩塌——需用 RAG 白名单 + 冻结评测协议兜底。
  • 负面先例：本线 A1 SFT 曾退化 −38.73pp，说明「随便做 SFT 会退化」，必须用「教师蒸馏 + RLVR」的正确 recipe，且每步同尺重测，负结果如实写。

6.5 可行性结论

文献量级（VeriReason 83.1%、CodeV-R1 68~73%、我们的教师 82.1%）与「教师示范天花板 = 82%」的判读共同表明：2B 模型经「蒸馏冷启动 → RLVR/GRPO → DPO/OPD」三步，提升到 85%+ 是文献可支撑、且有真实 EDA 沙盒与 check.py 可验证奖励落地条件的路线；但每一步必须按 §6.4 反作弊与预注册纪律执行，且当前 45% 的基线天花板在模型本身、不在环境。
