1 TL;DR

  • cline-patched & Pi tied at 60.0% (18/30) highest resolve rate among 7 harnesses on same 30 SWE-bench Lite instances with kimi-k2.6-cloud backbone.
  • cline-patched resolved set is a strict superset of ALL other harnesses no harness solves any instance that cline-patched doesnt also solve. Strong evidence that the model is the ceiling not the harness.
  • 7-way resolution spread: 40.0% to 60.0% (20 pp) with clear tiers: T1 (cline/Pi 60%) T2 (Hermes 53%) T3 (opencode 50% codex 47%) T4 (claude-code 43% deepseek 40%).
  • 12/30 instances (40%) unsolved by ANY harness model capability ceiling. 8/30 solved by ALL 7.
  • Pi is the most efficient (18 resolved at 275s avg = 235 res/h) while codex is slowest (843s avg) despite middling resolve rate. Tool count inversely correlates with speed.

Expected BaiZe 2.2B Performance

Given kimi-k2.6-cloud (much larger) achieves 40-60% BaiZe 2.2B would likely score 15-30% due to: smaller model weaker code gen limited context less tool-use training.

Recommendation: Use Pi architecture (7 tools diff-based concise prompt print mode) as BaiZe harness template.

9 Limitations

  • Small sample: 30 instances only 2 repos not representative of SWE-bench Lite 11 repos
  • Single seed: no variance estimation
  • kimi != BaiZe: backbone is kimi-k2.6-cloud not BaiZe 2.2B
  • Non-Docker evaluation: r1_eval.py unshare sandbox not official SWE-bench Docker results not comparable to leaderboard
  • cline-patched: custom modifications may not reflect stock cline
  • No token data: wall time proxy only
  • Limited discriminating power: 12+8=20/30 non-discriminating only 10/30 discriminate
  • Bimodal distribution: may over-represent easy and hard instances
