2. Wrapper 架构设计

2.1 设计目标

将 run/vision/models.py:OpenVision2 的 from-scratch ViT 封装为 HuggingFace PreTrainedModel 子类（model_type: baize_vision），使其可通过 AutoModel.from_pretrained() 加载，无需依赖训练代码库。

2.2 架构参数（④-4ep checkpoint 实测）

参数值来源备注
image_size224ckpt configStage-1 固定
patch_size16ckpt config
width512ckpt configOpenVision2 类默认 1024，④-4ep 实际用 512
depth30ckpt config
heads8512//64ckpt config 中 heads=None，自动推导
mlp_dim20484×512ckpt config 中 mlp_dim=None，自动推导
embed_dim768ckpt configReadoutHead 输出维（对齐 CLIP-L/14-336）

2.3 Forward 路径

pixel_values [B, 3, 224, 224]
  → PatchEmbed (Conv2d + learned pos)     → [B, 196, 512]
  → 30 × AttentionBlock (norm→attn→norm→SwiGLU)
  → final LayerNorm                        → [B, 196, 512]  ← patch features (默认返回)
  → [ReadoutHead: mean→norm→proj]          → [B, 768]       ← 仅 return_pooled=True

默认输出: patch_features [B, 196, 512]
ReadoutHead 权重被加载 (strict=True) 但 forward 中跳过
为什么跳过 ReadoutHead？ ReadoutHead 是对比学习专用（mean-pool → 768-dim → 与 CLIP 文本塔对齐）。 MLLM 桥接需要 patch-level 特征（每个 patch 一个 token）， 而非 pooled 全局向量。因此 forward 取 self.norm(x) 之后的 patch 特征，跳过 self.head(x)。

5. 与 RICE ViT 的差异处理

维度RICE ViT (LLaVA-OV1.5)BaiZe OpenVision2处理方式
架构patch14/d24/w1024/h16 · GELU MLPpatch16/d30/w512/h8 · SwiGLU MLPWrapper 原样复现 SwiGLU 架构
分辨率336px（动态）224px（固定 Stage-1）Stage-1 固定 224；高分辨率留待 Stage-2+
Patch tokens576 (24²) → merge → 144196 (14²) → 无 merge → 196spatial_merge_size=1，直出
Spatial merge有（size=2，576/4=144）无（size=1）config + modeling 均跳过 merge
CLS token有（prepended）无（mean-pool 在 ReadoutHead 内）MLLM forward 不用 CLS，直接取 196 patch tokens
ProjectorRicePatchMerger（vision tower 内）独立 2-layer MLP（512→2560→2560）见 §6 BaizeMultiModalProjector
ReadoutHead不适用存在（对比学习用），MLLM forward 跳过权重加载（strict=True）但 forward 不调用
特征维度1024 → 2560512 → 2560Projector 输入维 = 512
参数量~304M (vision)126.78M + 7.87M (projector)显著更轻量
Spatial merge 跳过的原因：RICE ViT 在 336px 输出 576 patch tokens， 经 spatial_merge_size=2 合并为 144。BaiZe 在 224px 仅 196 tokens， 已足够紧凑（比 RICE 144 多 36%），无需合并。如未来升级到 336px（576 tokens），可考虑启用 merge。

6. 自定义 LLaVA Modeling

6.1 组件

类名功能关键参数
BaizeMultiModalProjector2-layer MLP 投影器Linear(512→2560) → GELU → Linear(2560→2560) · 7.87M
LlavaBaizeModel组合 vision + projector + LLMget_image_features() → [B, 196, 2560]
LlavaBaizeForConditionalGenerationHF 兼容 forwardimage_token scatter → LLM forward

6.2 Forward 流程

input_ids [B, seq_len] (含 image_token_id=151655 标记位)
  ↓ LLM embed → inputs_embeds [B, seq_len, 2560]
  ↓ vision_tower(pixel_values) → patch [num_img, 196, 512]
  ↓ projector(patch) → image_embeds [num_img, 196, 2560]
  ↓ scatter: inputs_embeds[image_token_pos] = image_embeds
  ↓ LLM forward(inputs_embeds, attention_mask, labels) → CausalLMOutput

6.3 Image token 占位

每图像在 input_ids 中占 196 个 image_token_id（= patch 数）。 image_token_id = 151655（与 LLaVA-OV1.5 一致）。 masked_scatter 将 196×2560 的 image embeddings 填入对应位置。

6.4 Projector 设计依据

采用 LLaVA-1.5 式 2-layer MLP（而非单层 Linear），原因： ① BaiZe vision 输出 512-dim → Qwen3-4B 需要 2560-dim，维度差 5×，单层 Linear 信息损失大； ② 2-layer MLP 是 LLaVA-1.5/OV1.5 的标准做法，经验上优于单层； ③ 7.87M params 相对 126.78M vision + 4B LLM 可忽略。
