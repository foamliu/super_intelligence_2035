2. 4 臂奖励设计

臂名称逻辑理由
R1二值exec + 全断言通过 → 1.0，否则 0.0太稀疏，仅 baseline
R2部分分exec=0.2 + 每通过断言+0.2，全通过=1.0默认臂——GRPO advantage ≠ 0
R3R2+工具惩罚R2 + 0次=-0.05 / >20次=-0.1 / 3-15次=+0.05对齐 harness 成本模型
R4R3+API合法性R3 + 幻觉API=-0.15/次 + 未知API=-0.05/次抑制 API 幻觉

4. 关键设计决策

  1. R2 为默认臂：R1 太稀疏，2B 大部分 rollout 得 0 → 无法学习
  2. 部分分上限 0.99：保证 full_pass=1.0 的唯一性
  3. 格式奖励 +0.02：仅 score > 0 时生效，鼓励产出可执行代码
  4. API 合法性 lazy-load + 缓存：避免每 step 读取 16926 API 的 JSON
  5. 工具调用双格式提取：XML（MiniCPM5-2B 原生）+ Python（代码块内）
  6. Clamp [0, 1.1]：不允许负奖励，避免 reward hacking
