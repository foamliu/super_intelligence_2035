① 两种口径并列（🚫 不混为一谈）：

3.2 LR 缩放规则分析（3-臂扫描 · 文献依据）

背景：GBS ×4（512→2048）后，LR 应如何调整？运维指令（2026-10-13）要求「按文献规则定，不要拍脑袋」。以下为带出处的文献核查结果。

缩放规则建议 LR（×4 GBS）文献出处适用范围
线性缩放（LR ∝ GBS）5e-4 × 4 = 2e-3Goyal et al. 2017《Accurate, Large Minibatch SGD》(arXiv:1706.02677) — 「hyper-parameter-free linear scaling rule」+ warmup；ResNet-50/ImageNet batch 到 8192 无精度损失SGD / SGD+momentum（经典 ImageNet 分类）
B ∝ LR 等价性（含 Adam）同上 2e-3Smith et al. 2017《Don't Decay the Learning Rate, Increase the Batch Size》(arXiv:1711.00489) — 对 SGD / SGD+momentum / Nesterov / Adam 均成立：「B ∝ ε」SGD / Adam 均适用（本项目用 AdamW）
次线性 √缩放（LR ∝ √GBS）5e-4 × 2 = 1e-3⚠️ 工程惯例 · 无一手引用：大批量训练中常被使用，但本轮未取得可引一手出处 → 不当「权威规则」写工程惯例 · 非权威

实证硬结论（Shallue et al. 2019《Measuring the Effects of Data Parallelism》JMLR 20 / arXiv:1811.03600 + Google《Deep Learning Tuning Playbook》）：

  • ① 换 batch 必须重新调 LR（及动量/正则）——「optimizer hyperparameters (e.g. learning rate, momentum) and the regularization hyperparameters」最敏感
  • ② perfect scaling 仅在 critical batch size 以下成立，超过则收益递减（McCandlish et al. 2018, arXiv:1812.06162「gradient noise scale」）

对比学习专属：SimCLR (arXiv:2002.05709) —「contrastive learning benefits from larger batch sizes and more training steps」⇒ 欠缩放导致收敛慢，正确补救是加步数，不是降低要求。

3-臂扫描方案

臂LR缩放倍数规则warmupmin_lr理论依据预期
A1e-3×2次线性 √缩放40001e-4工程惯例 · 无一手引用收敛最慢；ProtB 最低
B1.5e-3×3线性与 √ 之间60001.5e-4插值折中
C（默认）2e-3×4线性缩放80002e-4Goyal 2017 + Smith 2017（含 Adam）有理论依据；预期最优

结论：按文献办事 = 做 3 臂小扫描，以 ProtB 取优，而非「拍一个数再预言会变差」。默认臂 C（×4 线性，Goyal 直接依据）；若预算只允许 1 臂 → 取臂 C，并显式声明「未做 LR 扫描」的局限。warmup 必须同比放大（Goyal 要求），否则大 batch 初期训练不稳定。

净效应估计：臂 A (×2 LR) 负面（更新数↓ + LR 偏低）vs 正面（负样本↑）大致相抵，负面略占优 → ProtB 可能略低于基线。臂 C (×4 LR) 线性缩放补偿了更新数减少的效应 → ProtB 预期接近或持平基线。3 臂扫描的目的正是确定哪个 LR 缩放规则在本数据/模型上最有效。

8. 诚实条款

  1. 本文件是计划，不是结果：所有 ProtB 数字（§5.3 表）均为基于基线曲线 + 理论分析的外推估计，标注 外推·待验。实测前不得引用为结论。
  2. 不编造数字：基线数字（62.34% / 65.37% / 67.05% / 2818 img/s / 10787 shards 等）全部来自 EXPERIMENTS_VISION.md / MEMORY_VISION.md 实测记录，可溯源。
  3. 时间估算有不确定度：24h 可跑真实 epoch 区间 2.2–3.3（按快照 110.9M），取决于 NFS I/O 瓶颈程度。中位估计 ~2.85 真实 epoch ≠ 保证值。⚠️ 3 真实 epoch（162,525 步）在中位吞吐下需 ~25.2h（略超 24h）。
  4. LR 3-臂扫描 · 文献依据：本计划将 LR 从单一 ×2 改为 3-臂扫描 {×2 (1e-3, 次线性) · ×3 (1.5e-3) · ×4 (2e-3, 线性)}，默认臂 C（×4 线性，Goyal arXiv:1706.02677 + Smith arXiv:1711.00489 含 Adam）。次线性 √缩放 (×2) 无一手引用，标为「工程惯例」。Shallue et al. (arXiv:1811.03600) 实证：换 batch 必须重新调 LR → 3 臂扫描正是按此办事。若预算只允许 1 臂 → 取臂 C，并显式声明「未做 LR 扫描」的局限。McCandlish et al. (arXiv:1812.06162) 提示 perfect scaling 仅在 critical batch size 以下成立 → ×4 可能已超临界 → 收益递减风险。
  5. 数据口径（⚠️ 2026-10-13 订正）：快照实盘 110.9M 对（7437 GPIC tar × 12,639 + CC12M 11.0M + Amshaker 5.95M，wc -l 已核）；全量 118.1M 对（8000 GPIC tar）。旧版报告写「95.8M」系 6233-tar 时代旧值（EXPERIMENTS_VISION.md L489），快照冻结到 7437 tar 后未重算 → 陈旧引用，已订正。基线「1 epoch」= 187,101 × 512 = 95.8M 样本，实际仅覆盖快照 86.4% = 0.86 真实 epoch。两种口径并列（数据集大小 vs 训练实际喂入样本数），🚫 不混为一谈。
  6. 未启动训练：本计划严格遵守「只出计划不启动」纪律，不占 GPU，不打断在飞的外部编码器评测。
  7. 预注册判据（建议）：① 臂间比较：臂 C (×4) ProtB ≥ 臂 A (×2) → 线性缩放优于次线性 → 确认 Goyal 规则适用；② vs 基线：最优臂 ProtB ≥ 67%（= ④-4ep 基线）→ 大 batch 至少持平 → 可继续探索；③ 64% ≤ 最优臂 < 67% → 大 batch 略差 → 可能需更多 epoch；④ 最优臂 < 64% → 大 batch 显著不利 → 回退基线配置。判据须运维确认后定稿。
