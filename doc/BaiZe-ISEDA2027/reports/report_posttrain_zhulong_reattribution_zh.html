8. 总结论

  1. 口径：36.15 zhulong 口径 5-run 基线 = 6.84%±6.12%（n=5，rca_status=CLEAN，见 §10），序列 [18.99, 4.43, 2.53, 3.80, 4.43]%。cline 版本：zhulong 3.0.29 / cline 3.0.51。⚠ 更正：旧 interim 报「run2/3/4 各=0.0% = 模型 degenerate collapse」已作废——根因是管线 ws/no-ws 路径失配（抽取器只读 ws/，丢 no-ws 代码），经 rca_recover_extract.py 回补后 run2/3/4 = 4.43/2.53/3.80%（execution_results 43/28/35 ≫1），非模型 collapse。run1=18.99% 为 ws-only 锚点 outlier（caveat 见 §10）。⇒ 5-run mean±std 为准，单 run 不可代表能力。
  2. 旧归因作废（PENDING-REMOTEST）：「模型不会按 MCP 协议调工具」「损失大头在提交协议」——前提（80.6% run_commands 拒绝=能力缺陷）错误。run_commands 是被 hook 主动禁用的内置工具。
  3. 真归因：真 MCP 拒绝率 6.0%、run_code 3.0%——模型会检索、会执行。损失大头 = 45 题静默未进入 agent 回路（28.5%）+ 76 题把 turn 烧在被禁的 run_commands 上。
  4. 新旧基线：zhulong 口径 6.84%±6.12% vs 旧 .17 口径 3.04%±0.74%，Δ=+3.80pp，McNemar chi2=13.5（p<0.001，显著）。+15.95pp 的 run1 单点跳升主因 = 环境（RAG+沙盒可达），非 prompt、非工具协议。
  5. 下一步：5-run zhulong 口径复测 已完成（2026-11-17 08:43，rca_status=CLEAN）——见 §10；用全 recovered 同口径 fresh 5-run 定论 run1 outlier；并推进 SFT/RL 主线。
