R46: GPU Auto-Watcher + NFS Warm-up + T-0 Launch Auto-Pilot

日期：2026-11-08（T-1）
类型：零 GPU · 运维自动化
交付物：baize_posttrain_gpu_watcher.sh + 本报告

1. 问题背景

R45 发射前物理资产核验确认所有资产就绪（GO for 11/9），但发现两个运维级操作缺口： (1) GPU 释放无自动检测——11/9 需人工盯着 nvidia-smi 等待 4×A40 释放后手动启动 launch 脚本； (2) NFS 冷启动延迟——R45 实测 import torch >30s（NFS page cache 冷）。 本节创建 baize_posttrain_gpu_watcher.sh，解决上述两个缺口。

2. 脚本设计

2.1 三种运行模式

模式命令用途
完整监控bash baize_posttrain_gpu_watcher.sh自动等待 GPU → 预热 → 启动
Dry-run--dry-run验证逻辑，不执行任何操作
仅检查--check-now一次性 GPU 状态查询
仅预热--warmup-only仅执行 NFS warm-up（可提前运行）

2.2 关键参数

参数默认值说明
--poll-interval60snvidia-smi 轮询间隔
--min-free-gpus4最少需要多少张空闲 GPU
--min-free-mib40000 (40GB)每张 GPU 至少多少 MiB 空闲
--max-wait86400 (24h)最大等待时间
--gpu-idsauto指定 launch 时使用的 GPU ID
--launch-steps1-5launch 脚本执行哪些步骤

5. 11/9 操作清单

步骤 1（提前，零 GPU）：NFS 预热

bash baize_posttrain_gpu_watcher.sh --warmup-only

步骤 2（启动监控）：等待 GPU 释放 → 自动启动

nohup bash baize_posttrain_gpu_watcher.sh \

  > /tmp/baize_gpu_watcher.log 2>&1 &

步骤 3（监控）：tail -f 日志

步骤 4（GPU 释放后自动触发）：warmup → launch steps 1-5

7. 与既有资产的关系

watcher 调用 baize_posttrain_launch_11_9.sh（R12/R42），后者依次执行： preflight（R7）→ SGLang serve → baseline eval → D1-D6 提取 → contamination gate → RL smoke test（R0 reward, R42 fix）。 结果用 baseline_gate.py（R44）和 smoke_calibrator.py（R43）判定。 路径由 baize_posttrain_paths.sh（R25）统一提供。

8. 局限性

  • 无 GPU 释放通知机制（仅日志，不发邮件/消息）
  • warm-up 依赖 NFS 带宽（被 pretrain/data 占满时可能慢）
  • GPU 空闲判定基于 memory.free（40GB 阈值已保守）
  • 非替身模型：使用 MiniCPM5-2B，结果不可迁移到 BaiZe

9. 结论

R46 填补了 R45 发现的两个运维缺口（GPU 释放无自动检测 + NFS 冷启动延迟）， 使 11/9 launch 从"人工盯屏 + 手动启动"升级为"自动检测 + 预热 + 一键启动"。 脚本已通过 bash -n 和 dry-run 验证。累计成果：R1-R46 + E1。
