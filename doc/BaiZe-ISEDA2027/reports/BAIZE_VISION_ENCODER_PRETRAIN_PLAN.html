1任务目标与三层次结论（P0–P3）

在 24 小时墙钟预算内，对四个 ~500–600M 视觉编码器做从零预训练（随机初始化，不加载任何上游权重）的公平对比，产出三层次结论：

loss 曲线
同一对比目标下的收敛（1000 步 + 长地平线 5–10k 步）
训练速度
image/s（或 pair/s）
推理速度
图像→token/s（统一前向 bench / SGLang）
层级性质内容
P0 基础必做三项硬指标（loss / 训练 / 推理），锁定「默认配置 + 胜出架构」
P1 稳健优先长地平线 + 多种子复现 + 下游代理评估，让排名可信
P2 核心自由度论文重点分辨率 / patch / 目标函数 / 数据侧消融
P3 超参/推理有余量LR/warmup 扫描 + 推理深挖 + SGLang

最终交付：1 份胜出架构 + 可复现训练命令 + 多阶段对比报告（写入 run/EXPERIMENTS_VISION.md 顶部）+ 自包含 HTML 结果报告 BAIZE_VISION_ENCODER_RESULT.html，并把胜出架构 config/results 回填 ISEDA2027/6_vision_encoder.tex。

2四个候选架构（500–600M）

四个架构均在「图像→视觉 token 序列 →（下游 MLLM Stage iv 对齐）」职责下对比，差异点为核心 token 混合算子：

架构核心算子设计假设（待验证）参数量目标
OpenVision 2
纯 Attention（ViT 式基线）		 多头自注意力 + MLP（SigLIP/LlamaVision 风格） 成熟稳定、易对齐 MLLM，但随分辨率升高复杂度 O(n²) ~550M
MambaEye
SSM（视觉 Mamba）		 双向视觉 Mamba（SSM 扫描 + 少量 attention 混合） 线性复杂度，高分辨率更友好，与语言骨干 Mamba2-hybrid 同源 ~550M
MoE-ViE
稀疏 MoE		 FFN 替换为稀疏专家（top-k 专家路由） 同算力下总参数更大、每 token 激活更少；需区分总/激活参数 ~550M（激活）
DeepEncoder V2
Attention+SSM 混合		 顺序混合（Mamba2 + GQA + MLP，Nemotron-H 式，与语言骨干同构） 对齐语言骨干架构哲学，便于视觉/语言统一推理栈 ~550M

具体 config（patch / hidden / layers / heads）由 agent 在 arch_prepare 落地，把每个架构实测参数量压到 500–600M（±10%）；MoE 额外记录「总参数 vs 激活参数」并在报告注明「非等参对比」影响。

4四个必须遵守的关键决策（公平口径）

决策 1：统一「从零」——四架构均随机初始化

沿用 2B 架构搜索方法论：四架构均随机初始化，不加载任何官方/上游预训练权重（禁用 timm/open_clip 的 pretrained 入口）。仅对比架构本体带来的收敛/速度差异。任何架构若确需用上游权重「冒充从零」，必须在 EXPERIMENTS_VISION.md 记录并说明。

决策 2：统一训练栈与目标函数

统一到 OpenCLIP（open_clip 3.2.0） 训练栈（自定义 vision tower + 固定 text tower），Mamba/MoE 层需手写模型（mamba_ssm 2.2.6 已装可直接用）。四架构必须：

  • 同一对比目标：默认 SigLIP（sigmoid 对比），S7 做 SigLIP vs CLIP InfoNCE A/B；
  • 同一 text tower（固定同一 small transformer + 同一 BPE，四架构共用，只动 vision tower）；
  • 同一分辨率 / patch / 增强（除 S6 显式消融外）。

决策 3：参数量对齐 500–600M

四架构实测参数量（sum(numel())）须落 500–600M，偏差 >10% 注明「非等参对比」。MoE 同时报告「总参数」与「每 token 激活参数」，训练速度按激活参数算力归一说明。

决策 4：推理基准——SGLang 未装，退化到统一前向 bench

⚠️ 已实测 import sglang 报 ModuleNotFoundError。P0 主口径退化为统一前向 benchmark 脚本（torch.cuda.Event / torch.benchmark），四架构同一代码路径、batch=1 / 固定分辨率 / bf16 测量图像→token/s；S9 可选择性安装 SGLang（MLLM Stage iv 反正要用）补生产级吞吐，并在报告注明测量栈。

项取值说明

9风险清单与待确认项

  1. open_clip 自定义 Mamba / MoE vision tower：open_clip 对标准 ViT 友好，SSM/MoE 层需手写模型注册；mamba_ssm 2.2.6 已装，代价可控；必要时退回统一手写对比训练循环。
  2. GPU 后两卡占用：卡 6–7 被占 ~72GB，他人进程默认不动；扩展前先确认 pid；优先 6 卡内完成。
  3. SGLang 未装（已实测）：推理按决策 4 退化为统一前向 bench（batch=1、固定分辨率、bf16），相对结论可信；S9 可选装 SGLang（MLLM Stage iv 需要）复测生产级吞吐。
  4. ckpt → HF 转换：无现成 bridge 时手工权重映射（记录脚本）。
  5. 参数量调平 & MoE 口径：MoE 区分总/激活参数，避免「参数更多但算力更少」的伪优势。
  6. 短地平线局限：1000 步只能看早期趋势，故 S3 延长 5–10k 步 + S5 下游代理评估交叉验证；最终性能仍以 Stage(iv) MLLM 对齐为准。
  7. 预算超支：S9 阶段多，24h 上限可能触顶；按预算守卫裁剪，P0/P1 必保。
