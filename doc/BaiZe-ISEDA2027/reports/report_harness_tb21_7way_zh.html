根因 = (a): 容器内确实没有 python3/python。ubuntu:24.04 默认不含 python3; 这 4 个 task 的 Dockerfile 从未 apt install python3。hermes 适配器需 python3 来 pip install hermes-agent，故 setup 阶段即 127 退出。

交叉对照 (最直接的证据): 这 4 题在 Node.js/Bun 型 agent (cline/pi/opencode) 上未发生 setup 失败 —— 它们通过 npm/bun 安装，不需要 python3。仅 Python 型 agent (hermes/deepseek) 在这些 bare ubuntu:24.04 镜像上命中 python3: command not found。这直接确认根因 = (a)。

Web search 发现 (2026-11-14, via curl + proxy):

  • GitHub Issues API 搜 laude-institute/terminal-bench + 'python' → 0 条; 框架不文档化 '容器缺 python3' 的处理。
  • 搜 laude-institute/harbor + 'python install' → 0 条; harbor 的 BaseInstalledAgent 无 _ensure_python —— 每个适配器假设 python3 已存在。aider.py 等同样 pip install 假设 python3 在位。
  • 标准修法: 用基础镜像的包管理器安装 python3 (apt-get/apk/dnf/yum)，PEP 668 用 --break-system-packages 解决。

修复: _base.py:245 _ensure_python() —— 先探测 python3/python，若均无则用 apt-get install python3 python3-pip python3-venv (apk/dnf/yum fallback); _ensure_pip() 现先调 _ensure_python()。PATH fix: 所有 exec 命令前缀 export PATH=/usr/local/bin:/usr/bin:/bin:$PATH。
