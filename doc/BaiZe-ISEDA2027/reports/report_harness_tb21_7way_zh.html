3. 失败归因分析

3.1 网关 429 quota 耗尽（基础设施问题 · 已解决）

现象：glm-5.3-flash 网关 keyB 于 11-07 多次返回 HTTP 429，持续约 3.3h。

影响：TB-2.1 codex 路首次运行期间 docker down + 429，结果废弃（存 codex.failed-dockerdown-1107/）；其余路排队等待。

现状：网关于 11-08 恢复 200 OK（curl 探针 /v1/models=200），5 路已全部启动运行。

归因红线：429 不得写成「模型能力」结论。

3.2 能力失败 vs infra 失败（归因红线）

  • 能力失败（真实做错）：agent 生成 patch 但未通过 verifier — cline 81 题失败属此类（verifier reward=0 非 None）
  • 超时（TB_AGENT_TIMEOUT=3600s）：部分复杂编译任务未在时限内完成
  • 429 阻塞（已解决）：网关额度耗尽期间 agent 无法获取 LLM 响应 — 不得计入能力分母
  • errored：hermes 35 题 verifier 异常（docker-down 期遗留），需单独归因，不计入能力结论

归因红线：能力差不得用「基础设施问题」掩盖；infra 问题不得写成「模型能力」。

research 2611.08285 建议：单次运行无法区分能力与运气，需重复跑 + 难度基线分。本报告为单次 7-way，结论标注「single-run」。

# TB-2.1 各路 reward 聚合（bare number 0/1 in verifier/reward.txt）
python3 - <<'EOF'
import os, glob
JOBS="/tmp/tb21_glm53_jobs"
for h in sorted(os.listdir(JOBS)):
    hp=os.path.join(JOBS,h)
    if not os.path.isdir(hp): continue
    scored=passed=0
    for rf in glob.glob(os.path.join(hp,"*","*__*","verifier","reward.txt")):
        scored+=1
        if open(rf).read().strip() in ("1","1.0"): passed+=1
    print(f"{h:22s} scored={scored:4d} passed={passed:3d}")
EOF
