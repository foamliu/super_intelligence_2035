1. 核心发现：verl 原生支持 SGLang

R5 选定 verl（默认 vLLM 后端），R8 发现 MiniCPM5-2B 工具调用是 XML 格式，必须用 SGLang。调研确认：verl 将 SGLang 与 vLLM 并列为两大推理后端，且多轮工具调用（multi-turn rollout）仅 SGLang 支持。

维度结论
SGLang 推理后端✅ 原生支持
安装pip install verl[sglang]
多轮工具调用✅ 仅 SGLang（vLLM 不支持 multi_turn）
配置rollout.name: "sglang" + multi_turn: True
异步 rolloutrollout.mode: async + return_raw_chat: True
自定义工具实现 BaseTool 子类 + YAML 配置

2. 多轮 Rollout 架构与 EDA 沙盒契合

verl Agentic RL 采用 Client-Server 架构，三组件对应 EDA 场景：

组件verl 角色EDA 场景
AgentLoopClient：Agent 循环模型→读 API→写代码→调 run_eda_code
LLMServerClient推理网关（token 级 generate）SGLang server（含 minicpm5 parser）
AsyncServerServer：连接推理引擎 DP 组每个 A40 一个 SGLang 实例
关键设计：Client-Server 间用 token 级 generate（非 Chat API），确保 EDA 工具返回文本与 LLM 生成 token 的正确对应。异步 rollout让 GPU 在等沙盒返回时不空转——对 SSH 隧道延迟场景至关重要。

5. Delta-based Tokenization

verl 多轮训练只优化 assistant 生成的 token（工具返回文本不进 loss）：

prev = tokenizer.apply_chat_template(messages[:i], add_generation_prompt=True) curr = tokenizer.apply_chat_template(messages[:i+1], add_generation_prompt=False) token_ids += tokenizer.encode(curr[len(prev):]) # 只 tokenize delta loss_mask += [1] * len(delta_tokens) # 只 mask assistant token
