1. 多轮工具调用状态机

PENDING → RUNNING → SGLang generate → 检查 finish_reason LENGTH → BREAK | STOP → BREAK | TOOL_CALL → parse → TOOL_CALLING TOOL_CALLING → asyncio.gather(*[tool.execute()]) → add_tool_response → 检查 input_ids >= max_model_len → 是则BREAK / 否则RUNNING循环 [结束] calc_reward_and_release_fn() → finalize()

2. 关键发现

CRITICAL F01: BaseTool.__init__

问题: verl BaseTool.__init__(self, config, tool_schema) requires TWO params. Our EDASandboxTool.__init__(self, config) only takes ONE.

证据: base_tool.py line 31

修复: Add tool_schema param and pass to super().__init__()

状态: IDENTIFIED

CRITICAL F02: BaseTool.create()

问题: verl create() returns str. Our tool returns Tuple. verl uses return as instance_id.

证据: base_tool.py line 39: -> str

修复: Change create() to return just instance_id (str)

状态: IDENTIFIED

CRITICAL F03: BaseTool.execute()

问题: verl execute() returns Tuple[str, float, dict]. Our tool returns Tuple[Dict,...]. verl passes response string to add_tool_response_message(tokenizer, resp).

证据: base_tool.py line 52

修复: Serialize response dict to JSON string before returning

状态: IDENTIFIED

CRITICAL F09: tool_config_path

问题: RL config v2 has tool_config_path: null. verl returns empty lists when None. NO tools loaded, multi-turn cannot work.

证据: sglang_rollout.py line 427

修复: Create tool_config.yaml. Set tool_config_path when enabling multi_turn.

状态: IDENTIFIED

HIGH F04: BaseTool.calc_reward()

问题: verl calls calc_reward(instance_id) at episode end. Our 0.0 return is correct.

证据: sglang_rollout.py line 839

修复: No fix needed.

状态: OK

HIGH F05: max_turns default

问题: verl sets max_turns = max_model_len // 3 if None. With 16384 gives 5461 turns.

证据: sglang_rollout.py line 331-332

修复: Set max_turns: 3 explicitly (done in config v2)

状态: FIXED_IN_CONFIG

HIGH F06: Context overflow mid-turn

问题: Tool response pushing input_ids >= max_model_len forces STOP. False negatives possible.

证据: sglang_rollout.py line 760-764

修复: Mitigate with ctx=16384+ (done). Monitor false_negative_rate in smoke.

状态: IDENTIFIED

HIGH F10: Tool initialization flow

问题: verl loads tools from YAML via OmegaConf. Class loaded via importlib. Tool must be importable from verl venv Python path.

证据: sglang_rollout.py line 440-461

修复: Ensure tool v2 on PYTHONPATH. Use full module path in class_name.

状态: IDENTIFIED

HIGH F11: Dual reward system

问题: Two mechanisms: (1) per-tool calc_reward() at episode end, (2) external compute_score via NaiveRewardManager. Our design uses (2), returns 0 from (1).

证据: sglang_rollout.py line 838-848

修复: Document. Verify compute_score receives tool responses in smoke.

状态: IDENTIFIED

HIGH F13: Chat format: chatml vs qwen

问题: verl supports 'chatml' and 'qwen'. MiniCPM5-2B uses ChatML.

证据: schemas.py line 89-105

修复: Use 'chatml' (done). Verify tokenizer has <|im_start|>tool tokens.

状态: IDENTIFIED

MEDIUM F07: Tool call JSON decode error

问题: Malformed tool call args are SILENTLY DROPPED. Model thinks it called a tool.

证据: sglang_rollout.py line 802: if has_decode_error: continue

修复: Log decode_error_count. Penalize in R4 arm.

状态: IDENTIFIED

MEDIUM F08: LENGTH finish reason

问题: Generation hitting response_length limit breaks rollout with already_over_long=True.

证据: sglang_rollout.py line 773-780

修复: Accept. response_length=8192 sufficient.

状态: IDENTIFIED

MEDIUM F12: Reward scores storage

问题: tool_reward_scores in _req.reward_scores. May not propagate to training loop.

证据: sglang_rollout.py line 849

修复: Verify in smoke test.

状态: IDENTIFIED

MEDIUM F14: Function call parser type

问题: get_tool_call_parser_type(tokenizer) may return None for MiniCPM5-2B. If None, tool calls NOT detected. POTENTIAL BLOCKER.

证据: sglang_rollout.py line 471

修复: Check parser type in smoke. If None, register custom parser.

状态: IDENTIFIED

MEDIUM F15: Async rollout concurrency

问题: Multi-turn processes each prompt individually. Tool calls run via asyncio.gather.

证据: sglang_rollout.py line 742

修复: Ensure execute() is async. Use asyncio.to_thread() for CPU-bound Tier3.

状态: IDENTIFIED

LOW F16: Rate limiting

问题: SandboxFusionTool uses Ray TokenBucketWorker. Our tool has no rate limiting.

证据: sandbox_fusion_tools.py line 43-62

修复: Add if needed. Not needed for Tier3.

状态: IDENTIFIED
