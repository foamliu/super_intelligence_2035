1. 识别的空白

空白 1：launch_11_9.sh 有 Step 0-6 但缺少 Step 7：RL 后评测 + 统计比较。eval.sh 和 eval_analysis.py 存在但未链接。

空白 2：72h 无人工值守 RL 运行没有墙钟预算执行器——RL 超时可能没时间评测，外部无法监控。

空白 3：verl save_interval=200 存多个 ckpt，但没有自动选择最佳检查点逻辑。

2. 解决方案

R63-A: baize_posttrain_ckpt_selector.py（~312 行，纯 stdlib）

  • 解析训练日志提取 per-step 指标（reward/cheat/std=0/KL/entropy/grad）
  • 排除 NaN/OOM/reward<0.01/std=0>80%(R57)/cheat>5%(§5.2)
  • 按 avg_reward 降序 → avg_cheat 升序 → step 降序排序
  • 输出 JSON + HTML

R63-B: baize_posttrain_post_rl_pipeline.sh（~90 行 Bash）

  • 7a: ckpt_selector → 最佳 checkpoint
  • 7b: eval.sh → 158-case 5-run 评测
  • 7c: eval_analysis.py → McNemar + bootstrap vs baseline
  • 7d: baseline_gate.py → M1-M4 里程碑

R63-C: baize_posttrain_72h_guardian.sh（~180 行 Bash）

  • 心跳：每 5min 写 heartbeat.txt
  • 看门狗：每 60s 检查墙钟；T-4h 标记 eval_window；T-0 SIGTERM
  • Phase 1: launch steps 0-6 · Phase 2: post_rl_pipeline（剩余>1h 自动触发）
