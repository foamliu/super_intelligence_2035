1. 🔴 关键发现：DeepSeek 轨迹 = 评测题本身

红线确认：DeepSeek full-harness 轨迹（cline_trace_v1_3/cline_trace/）的 task prompt 包含 158 评测题的函数签名和断言代码。101/103 条轨迹的 entry_point 与评测数据集匹配（98.1%）。剩余 2 条（create_schematic_pins / create_wrapped_qstring_list）可能为评测集变体。

影响：此前 R1-R22 多处假设"DeepSeek 轨迹可用作 SFT gold data"，本次实测推翻此假设。直接使用将违反污染隔离红线（§5.1）。

2.3 错误恢复模式

从成功轨迹中提取了 9 对 error→fix 模式：

  • ImportError：模块路径错误 → 检查并修正 import 路径
  • AttributeError：API 名称拼写错误 → 重新 search_apis 查找正确名称
  • TypeError：参数类型不匹配 → 查 get_api_details 确认参数类型
  • AssertionError：断言失败 → 调整代码逻辑

4. EDA 沙盒连通性分析

测试项结果说明
SSH .17 → 36.15❌ 超时Connection timed out（可能防火墙/网络隔离）
pyAether 在 .17 可导入❌ 不可用ModuleNotFoundError（系统 Python 和 .venv）
pyAether 在 .17 .venv❌ 未安装~/code/eda_fastmcp/.venv 无 pyAether 包
eda_fastmcp 本地克隆✅ 存在含 scripts/、docs/、pyAether-eval/
评测驱动脚本✅ 存在run_cline_script.sh 可用

结论：RL 沙盒不能在 .17 本地运行（pyAether 未安装）。SSH 到 36.15 不通。R22 的 R0 auto-fallback 是必要的保险措施。

沙盒方案（按优先级）

方案描述可行性
A（推荐）运维建立 36.15→.17 反向 SSH 隧道需运维配合
B评测机部署 sandbox server，HTTP API 调用中等
C（fallback）RL 首日用 R0 skeleton reward，无需沙盒✅ 已就绪
D（长期）在 .17 安装 Aether EDA 环境需许可+安装
