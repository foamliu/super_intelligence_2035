1. 摘要

  • 本报告把调研报告的「单一建议」(路纽①)细化为可照着做的 OCR 专项 SFT 执行方案: 用 trdg/SynthTIGER/自研渲染器 合成 50-200 万对, 在 ArmE-R2 现行 ckpt 上加一轮 Stage-2.5 SFT.
  • 基纽配比一览: 英文词句 30% / 中文词句 20% / 中英混排 10% / 文档版面 15% / 图表 10% / 数学公式 10% / 低质手写场景 5%; 总量 P0=20万(pilot), P1=150万(全量). 候选 A(英6中3混1) 为默认, B(中英1:1) 供中文场景备选.
  • 数学公式三通道: (a)纯公式图 im2latex/LaTeX 5% · (b)正文夹公式 arXiv+KaTeX 3% · (c)公式+表格混排 2%; 公式总占 ≤10%, 主价值在符号词表与版面解析, 不期望公式子集独立抬升 OCRBench.
  • SFT 口径: 起始 ckpt = ArmE-R2 Stage-2 step3500·LoRA r=64继续·LR 1e-5/5e-6·224px 单块·256 tokens; 与 Stage-2 780k 混 70%OCR:30%780k 防遗忘; 336+anyres 为阻塞项(需工程改造+scope).
  • 预注册判据: 主 OCRBench ≥ +2pp(1.60%→≥3.60%); 副 DocVQA/ChartQA/InfoVQA 各 ≥+1pp; 护栏 MMStar/AI2D/RealWorldQA/MMBench 退化 ≤1pp. 含决策树: pilot达标→全量; 不达标→改一维再试; 两次不达→停+负面结论.
  • 本轮只出方案报告, 不启训练、不生成全量数据(等用户看完批预算). 诚实条款: 外部数字均为论文自报未复现; 成本为估算; 本项目数字全部实测可溯源.

5. SFT 配方与混合策略

5.1 SFT 配方（对齐现有 stage2_train_armE_r2.py 口径）

起始 ckptArmE-R2 全链最终(Stage-2 step3500): vision tower ViT-L/14(冻结) + projector 1024→2560 + LoRA r=64 + Qwen3-4B-Instruct
方法新增「Stage-2.5 OCR 专项 SFT」: 在 Stage-2 最终 ckpt 上继续训练, 不动 vision tower(冻结), 只更新 projector + LoRA
LoRAr=64, alpha=128, dropout=0.05 (与 Stage-1.5/2 一致, 复用现有配置)
LRLoRA 1e-5, projector 5e-6, cosine→1e-7, warmup 0.01 (同 Stage-2 起点, 防止遗忘过快)
步数P0 pilot: 2000 步(20万样本/GBS=8≈2500步取整); P1 全量: 8000-12000 步
GBS/MBSGBS=8, MBS=1 (与 Stage-2 一致, 显存安全)
图像224×224 单块, 256 patch tokens, CLIP norm, 无 spatial merge (同 Stage-2; 336+anyres 为阻塞项, 见下)
LoRA vs 全参推荐 LoRA 继续(参数小、防遗忘、与现有链一致); 若 pilot 不达标且怀疑容量不足, 再考虑全参(需运维批准)
336+anyres336+anyres 需工程改造 mllm_bridge(动态 num_image_tokens × 多块拼接) + scope 批准, 属阻塞项; 若批准, 增量收益估计 = DocVQA/InfoVQA 额外 +0.5~1.5pp(估算, 源于公开 MLLM 分辨率消融报告)

5.2 与 Stage-2 780k 混合策略（防灾难性遗忘）

阶段混合
P0 pilot (20万)OCR 新数据 100% (不混 780k, 纯探针看是否能动)
P1 全量 (150万)OCR 新数据 70% : Stage-2 780k 采样 30% (采样同样本量约 50万), 防遗忘
P2 混合再调 (若 P1 护栏退化)OCR 60% : 780k 40%, 或提高 780k 中原有 OCR/文档样本权重
原理: 纯新数据 SFT 易压坎原有能力; 混入 30% 原版 780k 是主流 MLLM 防遗忘的常见做法(参考 LLaVA/DocOwl 调优路线)。P0 pilot 故意不混, 是为纯探针看「合成数据能否动」。

7. 判据与决策树

主判据: OCRBench ≥ +2pp (基线 ArmE-R2 1.60% → 目标 ≥ 3.60%)

副判据:

  • DocVQA(val) ≥ +1pp (基线 7.35% → ≥ 8.35%)
  • ChartQA ≥ +1pp (基线 12.16% → ≥ 13.16%)
  • InfoVQA(val) ≥ +1pp (基线 16.18% → ≥ 17.18%)

回归护栏(防以退化换分):

  • MMStar 退化 ≤ 1pp (基线 ArmE-R2 ↖, 待读数据)
  • AI2D 退化 ≤ 1pp (基线 ArmE-R2 ↖)
  • RealWorldQA 退化 ≤ 1pp (基线 ArmE-R2 45.49%)
  • MMBench(en_dev_static) 退化 ≤ 1pp (基线 ArmE-R2 23.88%, 单独调用)

决策树

P0 pilot(20万, 2000步, 不混 780k) → 测 OCRBench/DocVQA/ChartQA/InfoVQA + 四护栏
  ├─ 主判据 OCRBench ≥ +2pp 且护栏全过 → 进 P1 全量(150万, 70%OCR:30%780k)
  ├─ OCRBench +0.5~2pp 但护栏退化超 1pp → 退一步: 混 30% 780k 重跑 P0, 判护栏是否恢复
  ├─ OCRBench < +0.5pp (几乎不动) → 改一维: ①提高中文占比(试 B 配比) ②增加退化领样比例 ③提高分辨率(若批准 336) → 再跑一次 P0
  └─ 两次调整后仍不达标 → 停并写负面结论(记录哪一维调过、结果), 不继续烧资源

8. 风险与坑

风险缓解
域差太大: 合成图过于干净, 模型学到「合成印」而非真实文档重退化管线(模糊/透视/压缩/背景纹理), 保持 ≥20% 带退化领样
字体与语言覆盖: 中文字体集不全 → 生咇字变体识别差用 Noto Sans CJK + Source Han 全量字重; 含 简/繁 两套
渲染伪影: 抗锯齿/边缘过锐 → 与真实扫描件不同分布参数随机化 + 预检查边缘锐度分布
评测泄漏: OCRBench/ChartQA 可能含与合成语料重叠的文本语料不取 OCRBench/ChartQA/DocVQA/InfoVQA 的原文; 公式语料取 arXiv 不取上述评测集
灾难性遗忘: 专项 SFT 压坎原有能力(MMStar/AI2D 退化)混合 30% 780k + 护栏监控 + LoRA 而非全参
公式 token 预算吾: 公式图 token 占比过高挤压其他类别公式总占 ≤10%, (a)5%(b)3%(c)2%; 不超 15万
训练卡 I/O 冲突: 渲染重 I/O 影响 .12/.29 训练渲染走其他机器/夜间, 存到 NFS 后再启训练
