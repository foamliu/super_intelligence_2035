1. 评测概述

本报告对比三个 ~2B 参数量大语言模型在 SGLang 0.5.9 推理框架下的长上下文推理成本。 上下文长度从 64K 开始翻倍（64K → 128K → 256K → 512K → 1M → 2M），直至模型因显存不足（OOM）无法服务。

每档上下文记录：峰值显存(GB)、首Token延时(TTFT, s)、 Prefill吞吐(tok/s)、Decode吞吐(tok/s)、端到端延时(s)。

评测方法：每模型独立起SGLang服务，每档1次预热+2次正式测量取中位数。生成长度128 tokens。 环境变量 SGLANG_ALLOW_OVERWRITE_LONGER_CONTEXT_LEN=1 允许超出 max_position_embeddings 限制。

8. 结论与建议

1. 最大可服务上下文：BaiZe-2B=512K / MiniCPM5-2B=512K / Qwen3.5-2B=1M

2. 64K速度对比：BaiZe-2B=24712tok/s(prefill),203tok/s(decode)；MiniCPM5-2B=24805tok/s(prefill),233tok/s(decode)；Qwen3.5-2B=70776tok/s(prefill),341tok/s(decode)

3. 64K显存对比：BaiZe-2B=72.66GB / MiniCPM5-2B=72.85GB / Qwen3.5-2B=72.84GB

注意事项：
  • Qwen3.5-2B 为混合线性注意力架构（每4层1层全注意力），KV cache 占用更少，长上下文更有优势。
  • BaiZe-2B 和 MiniCPM5-2B 的 config max_position_embeddings 均为 128K，超出后通过环境变量强制覆盖。
  • Qwen3.5-2B 原生为多模态模型，本次仅测试纯文本推理。
  • 所有测试在单张 H100-80GB 上进行，--mem-fraction-static 0.88，注意力后端 flashinfer。
  • BaiZe-2B 原始架构为 XmodelForCausalLM，已转换为 Llama 格式以兼容 SGLang。
