1. 摘要

  • 本项目四臂 (ArmB/C/D-R2/E-R2) 在 OCR 相关四集均极低: OCRBench 1.6-1.8%、DocVQA(val) 7.35-7.58%、ChartQA 12.16-12.92%、InfoVQA(val) 16.18-17.09%; 四臂之间差异 ≤1pp, 与编码器容量/ProtB 无关 (ArmE-R2 ProtB 68.2% 最强但 OCRBench 仍 1.6%)。
  • 证据指向: 问题位于 数据/任务缺位 而非编码器容量; 现有训练数据 (图文对比/AIMv2-style) 几乎不含专项 OCR/文档/图表识别监督。
  • 调研覆盖 7 类 18 个方法 (文字识别合成/文档合成/文档 MLLM/图表数据/OCR 引擎/RL 可验证奖励/公式), 来源为经代理检索的 arXiv 摘要 (2026-10-25)。
  • 单一建议: 优先执行 路线① — 用 trdg/SynthTIGER 低成本合成 50-200 万 OCR 识别对, 在现有 ckpt 上加一轮专项 SFT; 预注册判据 = OCRBench 提升 ≥ 2pp。
  • 本轮仅调研 + 写报告, 不启训练、不动已落盘产物、不伪造 API key。
  • 诚实条款: 外部效果数字均为论文自报、未在本项目复现; 成本为估算; 本项目数字全部实测可溯源。

成本数据少但 RL 训练较贵; 需运维预算批准
ETA待路线①/②验证后再评估
可证伪判据在路线①基础上 OCRBench 再提升 ≥ 1pp 且无回退

成本与 ETA 均为估算, 非实测; 需运维预算与 GPU 排期批准后方可执行。

6. 风险与坑

  • 域差 (domain gap): 合成文字/文档与真实扫描、手机拍照的光照/模糊/纸质差异大; 需充分退化沉淀真实分布, 否则合成上过拟、真实下掉。
  • 字体与语言覆盖: 中文/小语种字体、手写、公式、表格覆盖不足会留下盲区; 须明确字体清单与语言比例, 避免英文为主、中文坐冷板决 (本项目语料以英文为主)。
  • 渲染伪影: 合成图片易出现不自然贴合边缘、锉齿、光照不一致; 需多样退化与真实背景混合, 评测时注意合成泄漏 (评测集与训练集不得同源)。
  • 评测泄漏: OCRBench/DocVQA/ChartQA/InfoVQA 为公开评测集; 合成数据年不得直接含评测集原文; 以模板/语料重新生成, 并在报告中披露是否使用了评测集的模板/语料。
  • 指标口径: 本项目 OCRBench 用 lmms-eval ocrbench_accuracy (0-1 逐题 exact-match), 与原版 OCRBench 满分 1000 不同; 与外部榜横比前必须标注口径, 否则与 LLaVA/Qwen-VL 的 “57” 类数字不可比。
  • 容量→MLLM 不传递: ArmE-R2 (ViT-L/14, ProtB 68.2%) 编码器最强但 OCRBench 仍 1.6% → 表明再加编码器容量不解决 OCR; 问题在数据/任务位, 而非编码器。

7. 优先级排序

单一下一步: 执行路线① (低成本合成 OCR 识别对 + 专项 SFT)。

理由: (a) 成本最低 (渲染 CPU + 1-2 GPU·日); (b) 不动编码器, 复用现有 ArmB/ArmE-R2 ckpt; (c) 直击最低分 (OCRBench 1.6%); (d) 可证伪 — 预注册判据明确。

预注册判据: 在现有 ckpt 上加一轮 OCR 专项 SFT 后, OCRBench 提升 ≥ 2pp (1.6%→≥3.6%); 未达则写负面结论并排查数据质量/过拟。

仅当路线①验证为正后, 再依次评估路线②(文档) 与路线③(RL)。未经运维批准, 本轮不启任何训练。
