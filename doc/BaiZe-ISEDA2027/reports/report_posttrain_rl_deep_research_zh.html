一、EDA 环境接口架构（R1）

1.1 run_code 工具链路

模型/Agent 生成 pyAether 代码
  ↓ run_code(code, encoding, probe, endpoint, lang)  [tools/run_code.py:96]
  ↓ validate_ascii_code → probe(可选) → run_code_http
  ↓ HTTP POST → http://<SANDBOX_HOST>:<PORT>/v1/run_code
  ↓ payload = {"code": code, "lang": "pyAether"|"skill"}
沙箱服务端（36.15）→ 隔离 workdir 执行 → 返回 JSON:
  {"response":"执行成功", "error_log":"", "print_log":"print()输出"}

1.2 返回字段语义

字段含义判分用途
response执行状态/返回值摘要辅助信号
error_log空字符串 ⇔ 执行无异常主判分信号（R1 二值）
print_log所有 print() 输出断言通过/失败计数（R2 部分分）
关键发现：error_log == "" 是最天然的执行成功信号；print_log 中的 AssertionError 计数提供断言通过率。两者组合即可实现 R2 部分分奖励，无需额外标注。

信号来源判定对应臂

2.1 R2 部分分公式（推荐起步）

reward = 0.0
if error_log == "":                          # 执行成功
    reward += 0.2
    assertions_passed = count_pass(print_log)
    assertions_total = count_total(test_code)
    if assertions_total > 0:
        reward += 0.8 * (assertions_passed / assertions_total)
elif "ImportError" in error_log:             # 导入失败
    reward = 0.0  # 防虚构 API
else:                                        # 运行时错误
    reward = 0.0
设计决策：不给运行时错误部分分（防「能跑但不对」）；导入失败给0（防虚构API）；断言率0.8权重（缓解2B全0梯度）。

五、GRPO 核心公式与已知偏差（R3）

5.1 原始 GRPO

A_i = (r_i - mean(r)) / std(r)
L = -1/G Σ 1/|o_i| Σ [min(ρA, clip(ρ,1-ε,1+ε)A) - β·KL]

5.2 三个已知偏差（2025年研究揭示）

偏差原因对2B影响修复
长度偏差1/|o_i|使长回答每token权重低2B易生成冗长无意义代码Dr.GRPO:用1/Σ|o_i|替代
难度偏差std分母在接近全对/全错时爆炸简单题大量全对→std≈0→无效Dr.GRPO:去掉std,只用A_i=r_i-mean(r)
熵坍缩对称clip(1±0.2)限制低概率好token增长2B探索弱,更易坍缩DAPO:clip-higher(ε_high=0.28,ε_low=0.2)
来源：Dr.GRPO (arXiv:2503.20783, 2025-03) · DAPO (arXiv:2503.14476, 2025-03) · DeepSeek-R1 (arXiv:2501.12948, 2025-01)

1.3 沙箱多端口并发模型

源码 main.py:19-46 + exec_code.py：SANDBOX_ENDPOINTS="8653:workdir_a,8654:workdir_b,..." → 每端口独立 workdir → 物理隔离 lib.defs/TECHLIB → 无污染真并行。asyncio.Queue 端口池 → N 路并行。当前 36.15 配 4 个隔离端口，RL 起步用 2 路并发。
