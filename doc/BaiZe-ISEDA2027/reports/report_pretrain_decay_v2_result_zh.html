BaiZe 预训练 · Xmodel-2.5 Decay v2 实验结果报告

报告时间：2026-10-21 | 实验线：BaiZe Stage(i) 预训练 | 硬件：10.239.2.29（8×H100）
起点：Xmodel-2.5 stable 末点 step_532000（≈1.41T tokens） | decay 规模：71.2B tokens（19,980 步）
一句话结论：decay v2 从 61.03% 的起点基线出发，经 71.2B tokens 退火后 CS8 反而跌至 44.97%（−16.06pp），全面落后于 Xmodel-2.5 官方 final 的 65.40%（−20.43pp）。判定：decay 段把模型训坏了（而非“没练出来”），根因集中于双移位 bug + 过高 LR。

关键判定：起点基线 CS8 = 61.03%，decay 71.2B 后跌至 44.97%，即 decay 把起点模型练退化了 16.06pp。问题不在“起点/加载”，而在 decay 段配方本身有缺陷。Xmodel-2.5 官方同起点、相近配比、同量 71.2B decay 得 65.40%，本实验却 −20.43pp，属“训坏”而非“略差”。
对照口径：decay v2 与 Xmodel-2.5 final 起点相同（step_532000）、decay 量相同（71.2B）、配比相近、优化器同属 decay 段，构成近似单变量公平对照。早期报告曾误用 P-8（2.22B Mamba2-hybrid / 从头 44.4B）作主对照，因架构与参数量均不同，不可作归因依据，现仅作旁注。CX6 32.90% 为 Xmodel-2.5 官方数值。

§5 失败归因（引用 #648/#649 已交付结论）

序根因证据验证方向
1高双移位 bugbaize_xmodel25_decay_v2.py:547-548 预移位 + :567-568 chunked-CE 再移位，注释自认 “HF model double-shifts. Replicate here”。训练移位两次、评测只一次 → 训练/评测不一致，step0 loss 飙至 11.72短程 A/B：修掉预移位（仅 forward 移位一次）vs 现状，比 loss 与 CS8
2高peak LR 1.67e-3 过高stable 末 LR 通常 1e-4~3e-4，decay 重新 warmup 到 6~17×；高 LR 叠加移位错误放大破坏LR 扫描：1.67e-3 / 5e-4 / 3e-4 / 1e-4
3中code 26 epochs 过采样code 实测仅 0.270B token 却被训 6.98B（≈26 epochs），严重过采样；math 同理不足降 code 配比或补全量数据
4中step0 loss=11.72 异常compile + 双移位 + 分布突变叠加；正常起点应 ~1.7（见短途实验 L1 step0=1.75）双移位修复后 step0 loss 已降至 1.75（见报告二）
根因优先级：①双移位（代码级确认，影响最大）＞ ②LR 过高 ＞ ③code 过采样 ＞ ④step0 异常（①的下游表现）。短途实验 L1（修双移位 + LR 5e-4 + warmup 100）的 step0 loss 已从 11.72 降至 1.75（降 6.7×），直接证实双移位是主因 —— 详见报告二。

§6 结论与后续

  • decay v2 是一次失败的退火实验：71.2B tokens 退火使 CS8 从起点 61.03% 退至 44.97%，落后 Xmodel-2.5 官方 final 20.43pp。
  • 主因是代码级双移位 bug（训练移位两次 / 评测一次），叠加过高 LR（1.67e-3）与 code 过采样（26 epochs）。
  • 后续：已启动短途 20B decay 实验（L1/L2/L3 三变体，见报告二），用 2×2 因子分析隔离“双移位 vs LR”两个主因的贡献，判定门槛 CS8 ≥55%。L1 step0 loss=1.75 已证实双移位修复有效。
  • v2 原始产物与既有报告保留留档，作为失败证据，不作修改。
