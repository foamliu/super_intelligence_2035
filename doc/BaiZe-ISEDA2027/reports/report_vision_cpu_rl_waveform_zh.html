5.3 S3 后端联动（KTransformers 角色判定）

KTransformers 是异构推理框架（attention 上 GPU、MoE experts 卸载到 CPU/内存/磁盘）， 面向 MoE 大模型（DeepSeek-V2/R1、Mixtral 等）的推理加速，非训练后端。判定：

判据本环境适用？
需要 CUDA/GPU（attention kernel）本机 CPU-only（H100 全占给 pretrain）❌
价值在于 MoE experts 卸载Qwen3.5-2B 是 dense VLM（非 MoE）❌ 无收益
定位推理后端不能做训练

S3 结论：KTransformers 不适用于本场景（CPU-only + dense 2B + 需训练）。 按令"如实说明并退回 LoRA(peft) 直训"——两段式可行路径为：训练用 transformers 5.x + peft（已验证）， rollout/评测用原生 HF generate（CPU）；待 GPU 释放后，推理可考虑 vLLM（py310 env 已装 0.9.2）做加速 rollout。

5.4 ③ 综合结论

用户指定栈（LLaMA-Factory + KTransformers + Qwen3.5-2B）在 CPU 上不可行： ① LLaMA-Factory 0.9.3 强制 transformers 4.52.4，与 Qwen3.5-2B 所需的 transformers 5.x 互斥； ② KTransformers 是 GPU 异构 MoE 推理框架，CPU-only + dense 模型下无适用性。

已验证的可行退路（令内预授权）：transformers 5.20.2 + peft LoRA 直训 Qwen3.5-2B 原生权重， CPU 单步 loss 有限且下降（2.86→2.83）。Qwen3.5-2B 是多模态 VLM （Qwen3_5ForConditionalGeneration，含图像/视频预处理器），可直接吃波形图， 比 v2 用的 text-only 工具交互路径更接近"看懂波形图"的目标——这是下一步的关键升级方向。

六、下一步建议

  1. 切换到 Qwen3.5-2B 多模态 + peft 直训：放弃 LLaMA-Factory（架构不兼容）， 用已验证的 transformers 5.x + peft 路径，以波形图像为视觉输入重做 SFT/GRPO， 替代 v2 的 text-only 工具交互——这是"看懂波形图"能力的真正升级。
  2. 扩大评测提统计功效：n_eval 从 15/task 提升到 40/task（120 题），≥3 run 给 mean±std， 使 McNemar/bootstrap 有机会达到 p<0.05（v2 仅 +4.4pp 但 p=0.625，功效不足）。
  3. 增加 GRPO 步数：15 → 50~100 步，观察连续奖励曲线是否持续上升。
  4. 课程学习：先 type_classification（二值）→ frequency_comparison → period（连续值）。
  5. 诚实边界：连续 3 轮无显著提升即换方向；CPU 结论不外推为 GPU 结论。
