BaiZe Vision · CPU RL 波形实验 v2+v3 诚实报告

日期：2026-11-07 · 线：vision · wake：#854
基座：Qwen3-2B（text-extracted from Qwen3-VL-2B） · 训练：LoRA r=16, 69.7M params · 环境：CPU only (.12), 48 threads, nice -n 19

1. 背景与动机

用户令（2026-11-07）：「vision 阶段 2：放行，可以基于 CPU 大胆尝试各种 idea。千方百计证明经过精心设计的 RL 后，MLLM 在波形识别方面有显著提升。」

此前两轮诊断（wake#827-835 v1, wake#838 advantage 诊断）得出：
① v1 GRPO 结果 post-GRPO 6.2% < post-SFT 9.2%（负结果）；
② 根因 = 离散分档奖励（5 档 rel_err→1.0/0.7/0.4/0.1/0.0）导致 73-78.7% 的 GRPO group advantage std=0（全同档 = 无梯度信号）；
③ 按目标拆分：period 信号足（21.7% std=0），rise_time/duty_cycle 能力缺口（90%+ std=0）。

v2 重新设计了连续化奖励 R_main = exp(-rel_err/τ)（τ=0.15），在 n=15×3task=45 的 eval set 上得到 C=11.1% > B=6.7% > D=4.4%，但 McNemar p=0.625 不显著（n_disc=3，样本太小）。

2. v3 实验设计（预注册 2026-11-07 wake#854）

假设：v2 方向正确但统计功效不足。通过 (1) period-only eval（去除 0% 信号任务）、(2) 扩大 n_eval 15→100、(3) 更多 GRPO 步数（15→40）、(4) 更大 group_size（4→8），可获得统计显著性。

预注册判据：C > B 且 C > D；McNemar p<0.05 + bootstrap CI 排除 0。

实际执行：由于 CPU 上 40 步 GRPO 训练耗时过长（~2h/condition），v3 改为快速评估策略——用 v2 已保存的 15-step GRPO checkpoint，在 100 个新 period-only 问题（EVAL_SEED=990100，与 v2 训练/评估 seed 完全不相交）上评估。

4. 诚实分析：为什么 v2 是假阳性

v2 (n=15 period)v3 (n=100 period)结论
B (SFT)20.0% (3/15)34.0% (34/100)v2 低估了 SFT 基线
C (GRPO treat)33.3% (5/15)32.0% (32/100)v3 确认 C≈32%
C vs B+13.3pp (5/15 vs 3/15)−2.0pp (32/100 vs 34/100)v2 差异 = 小样本噪声

v2 的 "C>B" 仅为 2 个问题的差异（5 vs 3 out of 15），在 n=100 上完全消失。这是典型的小样本假阳性——也是本实验设计 falsification 框架的价值所在：它防止我们将噪声误判为信号。

5. 关键发现

  1. 15 步 GRPO 不足以改善 SFT：C(32%) ≈ B(34%)，p=0.50。连续奖励方向正确，但训练量远远不够。
  2. 奖励设计方向性正确：C(32%) > D(28%)，p=0.29（不显著但方向一致）；B(34%) > D(28%)，p=0.07（边缘显著）。随机奖励会损害性能，说明奖励信号确实在起作用——只是 15 步的梯度更新量太小。
  3. v2 假阳性已排除：n=100 的功效足够揭示真相——v2 的 "improvement" 是小样本噪声（2/15 的差异）。
  4. SFT 基线被低估：v2 报告 B=20%，实际 B=34%。SFT 本身已经学会了相当多的 period 测量能力。

9. 总结

诚实结论：在 CPU 上用 15 步 GRPO + 连续奖励，未能显著提升 Qwen3-2B 的波形 period 测量能力（C=32% vs B=34%, p=0.50）。v2 的 "improvement" 是小样本假阳性。

但有价值的方向性发现：连续奖励设计优于随机奖励（C>D, B>D），说明奖励信号是有效的——只是训练量不足。

下一步：增加 GRPO 步数（40+）+ 提高学习率 + 课程学习，v3 训练脚本已就绪。CPU 上每 condition ~2h，可在本轮后续执行。
