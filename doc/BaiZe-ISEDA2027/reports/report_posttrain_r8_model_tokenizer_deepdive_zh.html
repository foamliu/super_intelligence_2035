3. Chat Template 分析

MiniCPM5-2B 使用 ChatML + 思考/答案分离 格式（chat_template.jinja，112 行）：

<|im_start|>system
{system_content}<|im_end|>

<|im_start|>user
{user_content}<|im_end|>

<|im_start|>assistant
think_begin
{reasoning}
think_end

answer_begin

{answer}<|im_end|>

工具调用格式（assistant 输出）：

<function name="search_apis"><param name="keyword">layout</param></function>

思考模式控制：

  • enable_thinking=True → 生成 prompt 追加 think_begin（模型进入思考模式）
  • enable_thinking=False → 追加 think_begin + think_end + answer_begin（跳过思考，直接输出答案）

4. 🔴 工具调用后端选择（关键发现）

MiniCPM5-2B 工具调用是 XML 格式（<function name="..."><param>...</param></function>），不是 OpenAI function calling 格式。

后端工具调用解析推荐用途
SGLang (--tool-call-parser minicpm5)✅ 自动转 OpenAI tool_calls评测 / full harness
vLLM❌ 不解析 XML纯文本推理 / verl RL rollout

SGLang 启动命令：

python -m sglang.launch_server --model-path /tmp/models/MiniCPM5-2B --port 30000 \
    --tool-call-parser minicpm5

SGLang 安装：pip install "sglang[srt]>=0.5.16"

对 36% 基线复测的影响：EDA-Eval-PyAether 的 full harness 模式（cline 作为 agent）需要模型支持工具调用。如果用 vLLM serve，cline 收到的 tool_calls 字段为空 → cline 无法解析模型意图 → 模型被 handicapped → 分数被低估。必须用 SGLang + minicpm5 parser 复测基线。

6. 对 SFT 数据格式化的影响

  • SFT 数据必须按 ChatML + 思考/答案分离格式构造
  • assistant 消息含 think_begin...think_end + answer_begin...answer 结构
  • 工具调用用 XML <function> 格式
  • loss 只在 answer 块后内容上计算（response-only loss）
  • sft_pyaether_corpus.jsonl（19610 对，wake53 生成）需验证格式合规

7. 对 RL Rollout 的影响

  • vLLM 的 stop_token_ids 必须包含 [1, 130073]
  • verl 需自行解析 XML 工具调用（vLLM 不提供解析）
  • RL rollout 建议 enable_thinking=False（减少生成长度、加速 rollout）
  • max_model_len=8192（覆盖 95%+ 轨迹）
