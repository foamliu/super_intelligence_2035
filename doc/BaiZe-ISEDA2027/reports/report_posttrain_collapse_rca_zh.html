4. 四个异常的逐一解释（A/B/C/D）

异常 A：completed 158 行 vs execution 仅 1 行；run_eval「有效生成」判定在哪？

判定位置：run_cline_script.sh:556-578(Step 7.1) 调用 run_eval.py -g completed_code_generation_<BATCH>.jsonl；该 jsonl 由 complete_code_generation.py 生成，completion 为真实代码的题才被 assemble_for_execution.py 拼装送沙盒 → 产生 execution_results。completion 为 "pass"（哨兵）= 该题无 .py 被抽取。

complete_code_generation.py:69（无 .py 的题写哨兵）：
record = {"task_id": task_id, "completion": "pass", "status": status}
format_cline_cli_output.py:166（只读 ws 子目录）：
folder_path = os.path.join(cli_output, folder_name, "ws", "pyAether_code")
→ run2/run3 仅 1 题落 ws/pyAether_code → 仅 1 条 execution_result。run1 有 36 题落 ws（36 条），其产物真实。

run4 的 1 行另有原因：run4 未产新 output_evaluation 目录，链脚本 ls -dt|head -1 拷了 run3 的 20261115_1834 → 与 run3 字节相同。

异常 B：completion/status 字段语义？谁写？和 run_eval 读的是同一个吗？

由 Step 6 complete_code_generation.py 写。completion=抽取到的代码原文（无代码时哨兵 "pass"）；status=success(有代码)/fail(无)/timeout。run_eval 正是读这个文件（-g 指定 → patch_config 写 config.yaml 的 generations_file → assemble 读取）。是同一个文件。run1 本机那份「全 pass」是链脚本串文件拷错（从另一 degenerate batch 拷来），与其真实 final_report(generation_success=36) 不符。

异常 C：唯一被执行 task vs failed task trace 对比

trace 在 ~/eda_code_eval/<batch>/cli_data/worker_*/data/sessions/*/*.messages.json。run2 batch 抽样：

另有 48 题（run2）把代码写到 pyAether_code/（无 ws）→ trace 里写了文件、但被抽取丢弃。「failed task」分两群：① 真没写代码（submit_and_exit/循环，约 104 题）；② 写了代码但被管线丢（48 题）。后者是坍塌数字主因。

异常 D：codegen_rejection_stats.json 为 0 字节

该文件不是 codegen 阶段产出，是此前 RCA 手动统计的拒绝画像（run1 的 1509B 是手算的 1304 次拒绝）。eda_fastmcp 管线本身不产此文件 → run2 缺失 / run3·4 为 0B 属预期，不代表「codegen 没产码」。真实产码见 §3（code/ 实测 54/49 题）。

5. 根因定论：管线 vs 模型

层级性质证据影响
主因 抽取路径 bug管线format_cline_cli_output.py:166 只读 ws/pyAether_code；run2 丢 48、run3 丢 37 个真实 .pygeneration_success 被压成 1；execution_results 被压成 1

结论：排除管线 bug 之前，不得将 run2/3/4 写成「模型 degenerate collapse」。坍塌数字（1/158）由管线抽取 bug 主导；模型真实生成率约 1/3，代码质量通过率需回补后重测定论（8 题验证 1/10=10% 通过）。

8. 结论与后续

  • 根因：管线抽取路径 bug（主）+ 链脚本陈旧拷贝 bug（次）。run4 = run3 陈旧拷贝，作废。
  • 模型：真实生成率约 31–34%，存在 submit_and_exit 风暴/长循环退化（约 2/3 题零代码），属真实但非「1/158 坍塌」级别，需修复管线后重测才能定通过率。
  • 5-run mean 在 RCA 结论前不得引用；run2/3/4 的 0.0% 是管线 bug 压制结果，不可作为模型能力结论。
  • 后续：① 经 zhulong 协调应用 6.1 抽取回补（或沿用 6.3 wrapper）；② 用 6.2 已修链脚本重跑 5-run；③ 重测后再与 run1(18.99%) 同表对比；④ 模型侧 submit_and_exit 退化缓解（强制写文件/工具校验/重试）另列。
