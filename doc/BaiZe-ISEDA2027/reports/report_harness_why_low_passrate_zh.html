结论：28.7% 偏低但合理——它准确反映了「kimi-k2.6-cloud + 当前 harness 工程 + 受限评测环境」的组合能力。 不是评测环境完全崩坏导致的虚假低分（env-fail 仅 21.5%，且有 574 条真实 resolved 做支撑）， 也不是 LLM 能力完全不行（psf/requests 0/42 才是纯能力天花板信号）。

§5 结论与诚实条款

5.1 主要结论

  1. 通过率偏低但合理：28.7%（cline）处于 2024 年中 SOTA 水平带（Aider 26.3%, CodeR 28.3%），与当前 leaderboard 顶部（60%+）的差距主要来自模型差异。
  2. 不是评测环境完全崩坏：env-fail 占 21.5%，且有 574 条真实 resolved 做支撑。fix1+fix2 修复后 43 题翻转为 resolved，证明环境修复有效但有天花板。
  3. LLM 能力是最大瓶颈：48.0% 的 wrong-fix 中，89.2% 是完全错误（f2p=0）。fix3/fix4 修复 48 条 env-fail 后 0 resolved，证实修好环境后 LLM 能力成为唯一瓶颈。
  4. harness 工程差异显著：0-byte patch 率 codex 27.7% vs opencode 5.0%（5.5 倍差距），说明 harness 对模型输出的捕获/格式化能力差异巨大。
  5. psf/requests 0/42 是纯能力信号：无 env-fail、全 patch applied、0 resolved——这是 kimi-k2.6-cloud 模型能力天花板的最清晰证据。

5.2 诚实条款

  • 本评测使用 SWE-bench Lite（300 实例），非 SWE-bench Verified（500）或 Full（2294）。Lite 是最简单的子集，绝对分数不能直接与其他子集比较。
  • 所有 7 个 harness 使用 同一模型 kimi-k2.6-cloud，横评结论仅适用于该模型下的 harness 差异。
  • 评测环境非官方 Docker 容器，而是自建 conda env + chroot 方案——已修复已知 env-fail，但可能与官方评测存在细微差异。
  • 外部对照数据来自 web 搜索（llmrun.dev, swebench.com, aider.chat 等），各来源的评测时间、口径、harness 版本可能不同，仅作量级参考。
  • Kimi K2 官方 65.8% 是 Agentless 模式（非 agent 交互），与我们的 agent 模式不直接可比。
  • stdout_tail 仅保留最后约 500 字符，无法还原完整交互轨迹——部分轨迹分析基于推断而非完整日志。
  • fix4 评估正在进行中（30/61），最终 resolved 数可能变化——但 fix3 的 0/64 resolved 已充分说明 env 修复后的能力瓶颈。
