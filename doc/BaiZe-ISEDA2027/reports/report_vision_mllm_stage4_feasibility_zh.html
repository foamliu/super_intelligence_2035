4.2 BaiZe编码器架构（vision/models.py:OpenVision2）

class OpenVision2(nn.Module):
    def __init__(self, image_size=224, patch_size=16,
                 width=1024, depth=30, heads=16, mlp_dim=4096):
        self.embed = PatchEmbed(224, 16, 1024)  # Conv2d(3,1024,16,16)+pos_emb
        self.blocks = [AttentionBlock(1024,16,4096) for _ in range(30)]  # SwiGLU
        self.norm = LayerNorm(1024)
        self.head = ReadoutHead(1024)  # LN→Linear(1024,512)→mean-pool
    def forward(self, x, return_patch=False):
        x = self.embed(x)       # [B,196,1024]
        for b in self.blocks: x = b(x)
        x = self.norm(x)         # [B,196,1024]
        pooled = self.head(x)    # [B,512]
        return (pooled, x) if return_patch else pooled

4.3 桥接方案（如何接入ms-swift/LLaVA）

🔴核心挑战：BaiZe编码器是完全自定义的PyTorch模型，非open_clip、非HF Transformers原生支持。LLaVA-OV1.5的stage0使用RICE ViT vision tower，modeling代码(modeling_llavaonevision1_5.py,99KB)硬编码了RICE ViT接口(spatial_merge_size=2,patch_size=14,动态分辨率)。直接替换vision tower不可行，需编写自定义wrapper。

推荐桥接路径（3步）：

  1. 编写BaiZe vision tower HF wrapper(~200行)：将OpenVision2包装为HFPreTrainedModel子类，输出patch-level features(return_patch=True→[B,196,1024])；添加config.json(model_type:baize_vision)；加载vision.pt并映射参数名。
  2. 编写自定义LLaVA modeling文件(基于modeling_llavaonevision1_5.py改写)：替换vision tower调用(RICE ViT→BaiZe wrapper)；修改projector为2层MLP(1024→2560)；处理spatial_merge_size差异(BaiZe无merge,196tokens直出vs RICE 576/4=144tokens)；处理分辨率(固定224或位置编码插值)。
  3. 注册到ms-swift：通过llava_onevision1_5模板+自定义model path加载；在SftArguments中指定自定义模型目录。
⚠️关键注意：
  • spatial_merge_size：RICE ViT用merge_size=2(576→144 tokens)，BaiZe无merge(196 tokens直出)→LLM的image token占位需调整(196 vs 144)。
  • 分辨率策略：BaiZe训练于224×224。MLLM评测图像多高于224。策略：①固定224(简单,损失信息)②位置编码插值(需验证)。建议Stage-1用224固定,评测时做消融。
  • ReadoutHead：BaiZe的ReadoutHead做mean-pool→Linear(1024,512/768)用于对比学习。MLLM需patch-level features(非pooled)，应使用return_patch=True取x([B,196,1024])，跳过ReadoutHead。

§9 总结与建议

9.1 可行性判断

方案技术上可行，且有如下优势：

  • 🟢数据、LLM、训练框架、评测框架全部在盘就绪，无外部下载依赖
  • 🟢ms-swift原生支持llava_onevision1_5模板，训练管线成熟
  • 🟢BaiZe encoder的patch-level特征维度(1024)与RICE ViT一致，projector维度映射(1024→2560)可复用
  • 🟢算力充裕(8×H100 80GB)，预估~2天可完成全流程

主要风险与工作量：

  • 🔴视觉编码器桥接是最大工作量(~1-2天工程)，需编写HF wrapper+改写modeling
  • 🔴框架不匹配：train_4b.sh用AIAK Megatron，需改用ms-swift训练管线
  • 🟠分辨率/merge差异需在modeling中处理，对效果有潜在影响

9.2 建议执行路径

  1. 立即可做(不占GPU)：编写BaiZe vision tower HF wrapper+自定义LLaVA modeling，在ArmC训练期间并行完成
  2. ArmC完成后：Smoke test→Stage-1 alignment(冻结LLM+vision,只训projector)
  3. Stage-1通过后：Stage-1.5 mid-training(解冻LLM或LoRA)→Stage-2 instruct
  4. 训练完成后：lmms-eval 17 benchmarks评测，产出对比报告
  5. 消融建议：①224 vs 336分辨率消融②BaiZe encoder vs RICE ViT对比(用stage0做基线)③projector结构消融(2-MLP vs linear)

9.3 方案B备选（降低工程复杂度）

若视觉编码器桥接工程量过大，可考虑方案B：直接使用LLaVA-OV1.5-4B-stage0(RICE ViT+Qwen3-4B)，仅用ms-swift做下游SFT(Stage-2 instruct)。
  • ✅无需编写wrapper(stage0已HF格式)
  • ✅可直接swift sft --model .../LLaVA-OneVision-1.5-4B-stage0 --template llava_onevision1_5
  • ❌不使用BaiZe自研视觉编码器(放弃Stage(iii)成果下游验证)
  • ⚠️仅作为快速验证ms-swift+lmms-eval管线可用性的先行smoke，不替代BaiZe encoder方案
