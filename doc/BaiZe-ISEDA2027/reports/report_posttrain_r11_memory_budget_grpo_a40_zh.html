R11: GRPO 内存预算与超参校准（4×A40 48GB）

BaiZe Stage(ii) Post-Training · 2026-11-07 · 零 GPU · 文献+计算分析

摘要

针对 verl GRPO 在 4×A40 (48GB/卡) 上运行 MiniCPM5-2B 的显存可行性进行了逐项计算。核心发现：当前 gpu_memory_utilization=0.35 在多轮工具调用（3-turn）场景下可能 OOM——KV cache 需 13.8GB 超过分配 11.9GB。已校准为 0.50 + max_num_seqs=12，并添加 entropy checkpointing 等 verl 推荐优化。提供 5 级 OOM 降级阶梯和 smoke test 验证方案。

1. 硬件基线对照

模型方法最低资源后端

结论：2B 全参在 4×A40 48GB（总 192GB）是充裕配置——2.4× 于 1×H100 总显存。风险在"配置是否合理利用显存"。

3. 多轮 KV Cache 分析

逐 token：2 KV heads × 128 × 2 (K+V) × 2 bytes × 42 层 = 42 KB/token

轮次累计 tokenKV/seq
初始 prompt4096172 MB
Turn 1~10240430 MB
Turn 2~16384688 MB
Turn 3~20480860 MB

并发总量：16 × 860 MB = 13.8 GB（prefix cache ~12.4 GB）

🔴 发现：当前 0.35 分配 11.9 GB，3 轮峰值需 13.8 GB → 可能 OOM！

4. 配置校准

参数原值校准理由
gpu_memory_utilization0.350.50KV cache 13.8GB, 0.50→17GB 充裕
max_num_seqs161212×860MB=10.3GB 更安全
entropy_checkpointing—Truevocab=130560 logits 优化
entropy_from_logits_with_chunking—True分块 logits 熵
tokenization_sanity_check_mode—strictdelta tokenization 检查

5. OOM 降级阶梯

Level 0 (推荐): gpu_mem=0.50, max_num_seqs=12, micro_batch=4
  ↓ SGLang OOM → Level 1: gpu_mem=0.45, max_num_seqs=8
  ↓ SGLang OOM → Level 2: gpu_mem=0.40, max_num_seqs=4, max_turns=2
  ↓ 训练 OOM   → Level 3: micro_batch=2, max_token_len=8192
  ↓ 优化器 OOM → Level 4: offload=True, gpu_mem=0.60
  ↓ 仍 OOM     → Level 5: LoRA r=64, offload=True, gpu_mem=0.70

7. Delta Tokenization 注意

verl 多轮用 delta-based tokenization（只对 assistant token 算 loss）。MiniCPM5-2B 双 EOS [1, 130073] 可能误截断 → smoke test 检查每 turn token 长度。
