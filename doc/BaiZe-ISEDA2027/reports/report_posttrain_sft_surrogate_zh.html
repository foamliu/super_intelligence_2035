10. 关键发现与结论

10.1 SFT recipe 可执行性验证

  • verl 0.4.0 FSDP2 SFT 在 A40 上稳定运行：2×A40 (46GB) 足以支撑 2B 模型全参微调（bf16 + gradient checkpointing），无 OOM。
  • multiturn SFT 的 tools_key=null 修复有效：R170 发现 verl 默认 tools_key=tools 与 parquet schema 不匹配，设为 null 后 smoke test 通过。此修复已写入训练脚本。
  • 1029 对小数据集 + 5 epoch 配比合理：train/val loss 差距仅 0.055，未见过拟合；Epoch 3 后进入平台期，cosine 退火有助于平滑收敛。
  • checkpoint → vLLM serve 链路无障碍：verl FSDP2 保存的 HF safetensors checkpoint 可直接被 vLLM 加载，无需格式转换。

10.2 对 BaiZe 正式训练的启示

  • 替身预演证明 SFT 管线端到端可行：数据准备 → 污染隔离 → verl SFT → checkpoint 保存 → vLLM serve → 推理验证，全链路打通。
  • BaiZe Mamba2 架构需额外验证：verl/vLLM 对 Mamba2 的支持需单独确认（替身用 LlamaForCausalLM）。
  • 数据量需要扩展：1029 对仅为替身预演规模；正式 SFT 应混合 UltraData-SFT-2605（18.89B tok）+ agentic + PyAether API 语料。
  • 收益不可迁移声明：本报告的 loss 数字仅证明 recipe 可行性，不预测 BaiZe 在 EDA-Eval 上的 Pass@1。
