🎯 摘要 (TL;DR)

共发现 4 项 🔴硬伤（必须修正的数字/逻辑矛盾）、10 项 🟠建议（可提升严谨性的改进点）、3 项 🟢可回填（已有数据可填入 [TBD] 的条目）。

  • 最严重硬伤：论文声称 "adopt delayed-FP8" 但实际生产训练用 BF16（T3 实测 FP8 在 TP1/MBS2 下慢 9%）；"20B-token checkpoint" 实际只有 655M token；"24 Mamba-2 layers" 应为 52。
  • 口径不统一：seq 4094 vs 4096 在论文内出现 6 处，3 处写 4094、3 处写 4096，未做解释。实际训练命令用 --seq-length 4094。
  • 数据一致性：摘要/表格中的 val loss、3-seed σ、LR、退火配比等核心数字与台账 全部吻合 ✅；架构对比 Δ≈0.30@5000步 有 P-3 实验支撑 ✅。
  • P-8 生产训练（44B token / GBS=1024）尚在进行中，完成后可大幅丰富论文 §4 结果。

🔴 硬伤（Critical Issues）

🔴 H1

FP8 采用声明与实际生产训练直接矛盾

论文原文（4_llm_pretrain.tex:161-162）：

"A 1000-step A/B comparison between BF16 and delayed-FP8 precision (FP8 with delayed scaling, M=65536) shows no persistent loss divergence… FP8 delivers a 19.4% throughput gain (233K vs. 195K tok/s) and saves 5.6GB per GPU. We therefore adopt delayed-FP8 as the precision for the full pre-training run."

但紧接其后（4_llm_pretrain.tex:165）的生产吞吐段写道：

"At the production configuration (TP=1, DP=8, micro-batch 2, seq 4094, BF16), the hybrid backbone sustains 249,040 tok/s…"

台账实际（BAIZE_PRETRAIN_2B_TASK.md P-8 配方表 + MEMORY_PRETRAIN_2B.md）：

P-8 训练配方精度 = BF16（"FP8 在 TP1 上 s=0.91 慢 9%，不用"）。
T3 Test 4 实测：FP8 TP1 MBS2 M=8192 → s=0.915（228K tok/s，慢 9%），因 M=8192 ≪ FP8 交叉点 M*≈30–32K。
FP8 A/B 测试（19.4% 加速）使用 M=65536（大 M），与生产 M=8192 不可同日而语。
P-8 训练命令：--precision bf16_mixed --optimizer adam（非 FP8）。

问题本质：FP8 A/B 测试在大 M（65536）下做，确实有 19.4% 加速；但生产配置用小 M（8192），FP8 overhead 超过加速，实测慢 9%。论文从大 M 测试外推到小 M 生产配置，结论 "adopt FP8" 是错误的，且与同文后段的 "BF16" 矛盾。

删除 "We therefore adopt delayed-FP8 as the precision for the full pre-training run"。改为如实陈述："FP8 with delayed scaling (M=65536) delivers a 19.4% throughput gain in the large-M regime, but our production configuration uses MBS=2×seq=8192, well below the FP8 crossover point M*≈30–32K, where FP8 overhead exceeds its acceleration (measured s=0.91, i.e. 9% slower). We therefore adopt BF16 for the production run." 这样既保留了 FP8 实验发现，又解释了为什么不用。
🔴 H2

"20B-token checkpoint" 实为 655M-token

论文原文（4_llm_pretrain.tex:115 及 :120 表标题）：

"the 20B-token checkpoint sustains near-constant perplexity from 4K to 1M tokens"
表标题："Training-free long-context perplexity of the Mamba2-hybrid (20B-token checkpoint, ABF θ=10⁶, b=1)."

台账实际（EXPERIMENTS_PRETRAIN_2B.md:16 + 4_llm_pretrain.tex:75）：

S5-01 长跑 = 20000 步 × GBS=8 × seq=4094 = 655,040,000 ≈ 655M tokens。
论文自己在 line 75 正确写了 "20000 steps (≈655M tokens)"，但 line 115/120 却写 "20B-token"。
P-8 训练（进行中）到 step 8510 约消耗 35.7B token，但未完成，且 P-8 checkpoint 尚不可用于 PPL 测试。
没有任何 checkpoint 达到 20B token 规模。

判断："20B-token" 疑为 "20K-step" 或 "0.65B-token" 的笔误（20K 步 → 误写为 20B token）。长上下文 PPL 测试用的是 S5-01 的 20000 步 checkpoint（655M token），不是 20B token。

将 4_llm_pretrain.tex:115 和 :120 中的 "20B-token checkpoint" 改为 "655M-token checkpoint" 或 "20K-step checkpoint (≈655M tokens)"，与 line 75 的表述一致。
🔴 H3

"24 Mamba-2 state-space layers" 应为 52

论文原文（出现 2 处）：

3_architecture.tex:11："the 24 Mamba-2 state-space layers are position-agnostic"
4_llm_pretrain.tex:116："the 24 Mamba-2 state-space layers have no position dependency"

台账实际：

架构 = 56 层 - 4 attention 层 = 52 非 attention 层（Mamba-2 + MLP）。
MEMORY_PRETRAIN_2B.md 顶部状态："52 SSM + 4 Attn"。
EXPERIMENTS_2B.md:4："Mamba2-hybrid（56 层，Nemotron-H 式顺序混合）"。
论文自己的摘要 / intro / architecture 节均写 "56 layers interleaving Mamba-2 state-space layers, four GQA layers, and MLP layers" → 56 - 4 = 52。
line 11 还据此算出 "4/56=7.1%"，这个比例正确（4 attention / 56 total），但 "24" Mamba-2 层数错误。

判断：Megatron-Core 的 Mamba2-hybrid 每个非 attention 层都含一个 Mamba-2 SSM + MLP，故 52 个非 attention 层 = 52 个 Mamba-2 SSM 层。"24" 来源不明，可能是早期草稿残留或计算错误。

将 3_architecture.tex:11 和 4_llm_pretrain.tex:116 中的 "24 Mamba-2 state-space layers" 均改为 "52 Mamba-2 state-space layers"。

🟠 S1

Table archcomp 仅展示 1000 步 loss（Δ=-0.12），但正文引用 5000 步 Δ≈0.30

Table tab:archcomp（4_llm_pretrain.tex:102）："Final loss (1k steps) 4.81 vs 4.68, hybrid (-0.12)"。正文（:9）："the gap widening to Δ≈0.30 by step 5000"。台账 P-3 延长实验 5000 步 Δ=0.301 有数据支撑 ✅。但表格只展示 1k 步数据，读者无法看到 5k 步 Δ≈0.30。

🟠 S2

训练量极小（655M token）未充分声明为 "代理实验"

论文 Intro 提到 "Reduced-horizon proxy search" 但未量化。§4.5 给了 "655M tokens" 但未对比数据池。655M / 2,015B = 0.033%，仅为 Chinchilla 最优 (44B) 的 1.5%。论文核心 loss 2.2054 来自代理实验，但未声明。

在 §4.5 或 §4.7 加一段："The search horizon (655M tokens) represents ~0.03% of the corpus and ~1.5% of Chinchilla-optimal (44B). The reported loss is a proxy-search outcome, not a converged result. A production run (44B tokens) is underway."
