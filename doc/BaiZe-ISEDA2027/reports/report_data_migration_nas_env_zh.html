3. 迁移怎么做（方法学，可复现）

3.1 工具：rsync（不用 mv）

为什么不用 mv：/nas_train 和 /nas_env 是不同的 NFS 挂载点（分别挂载 10.239.22.31 和 10.239.22.32），跨挂载 mv = copy + delete，如果中途中断，两边都不完整且无法恢复。rsync -a 是幂等的——中断后重跑会自动跳过已完整传输的文件、续传未完成的。

3.2 命令

nice -n 10 rsync -a --bwlimit=50000 \
  /nas_train/.../data/full_ultradata_math_l3/ \
  /nas_env/app.e0031982/baize-data/full_ultradata_math_l3/
  • -a：archive 模式，保留权限/时间戳/软链接
  • --bwlimit=50000：限速 50 MB/s，为 85M 下载留 NFS 带宽
  • nice -n 10：降低 CPU 优先级，不抢占其他工作

3.4 目录结构与断点续传

保持原目录结构完整迁移（.bin + .idx + .json + manifest 全部复制）。rsync -a 天然支持断点续传——中断后重跑同一命令，已完整传输的文件自动跳过，未完成的文件从断点继续。迁移脚本 migrate_to_nas_env.sh 还会在每源开始时检查目标是否已有完整 shard 数，若已完整则跳过 rsync 直接校验。

4.4 原目录何时删

迁移脚本的流程是 rsync → 校验 → rm 源 → ln -s，即校验通过后立即删除源目录并建软链接。这是因为在 NFS 上保留两份相同数据会浪费 ~4.24 TB 空间。如果校验失败，脚本不会删除源（保留两份，等待人工排查）。
