1. 实验概述

ArmB 是 BaiZe 视觉编码器系列中与 ArmA 配对的对照实验。它在 同一个 open_clip 标准 ViT-B/16（224px）视觉塔上，将 ArmA 的纯对比目标（InfoNCE）替换为 BaiZe 主线采用的 AIMv2-style 稠密目标（InfoNCE + masked-patch-MSE，权重 1:1，mask_ratio=0.6），以回答核心问题：

在同一视觉塔、同一数据源下，把目标函数从纯对比切换为"对比 + 稠密重建"，在线性探针（lp）与 k-NN 检索两个维度上，表征质量如何变化？

结论（一句话）：ArmB 在两个探针上均优于 ArmA —— lp 62.09±0.01% vs 58.03±0.02%（+4.06 pp），5-NN 58.10% vs 53.98%（+4.12 pp）。与主线 ④-4ep 基线（lp 67.05% / k-NN 42.35%）"检索弱、线性可分性强"的模式不同，ArmB 呈现"双探针齐升"的均衡模式（详见 §6）。

预注册验收判据（均已通过）：

  • lp ≥ 58.03%（相对 ArmA 不倒退）→ ✅ 62.09% > 58.03%
  • lp ≥ 61.0% 且 5-NN ≥ 48.98% → 接受混合配方 → ✅ 62.09% ≥ 61.0% 且 58.10% ≥ 48.98%

⚠️ 注意：判据针对"配方整体效果"而非"目标函数独占贡献"——ArmB 与 ArmA 在 batch/epoch/lr 上亦有差异（见 §6.2），故 +4 pp 是"配方切换"的综合效应，不能全部归因于目标函数。

6. 关键解读

6.1 核心发现：同塔上双探针齐升（与 ④-4ep 的"取舍"模式不同）

ArmB 与 ArmA 共享同一视觉塔（open_clip ViT-B/16, 86.2M）与同一数据源，目标函数从纯 InfoNCE 切换为 AIMv2-style（InfoNCE + masked-patch-MSE）。结果是：

  • 线性探针 lp +4.06 pp：稠密重建项促使 patch token 编码更丰富的局部信息，提升了特征空间的线性可分性。
  • 5-NN +4.12 pp：与主线 ④-4ep（AIMv2-style 在 custom 126.8M 塔上 k-NN 仅 42.35%，低于其 lp 67.05%）形成鲜明对照 —— 在 open_clip ViT-B/16 塔上，稠密目标没有牺牲检索质量，反而同步提升。

这提示一个比"目标函数谁更好"更细致的结论：塔的归纳偏置与稠密目标存在交互。open_clip ViT-B/16（CLIP 风格全局池化 + 强对比预训练结构先验）似乎能更好地"吸收"稠密重建信号而不损害近邻结构；而 custom 126.8M 塔在相同目标下呈现"lp↑ / k-NN↓"的取舍。

6.2 ⚠️ 严禁过度解读：这不是严格单变量对照

ArmA 与 ArmB 在 batch / epoch / lr 上亦有差异，因此 不得 将 +4 pp 完全归因于"目标函数差异"：

变量ArmAArmB是否单变量？
视觉塔open_clip ViT-B/16 (86.2M)open_clip ViT-B/16 (86.2M)✅ 相同
数据源≈118M 对≈118M 对（同源）✅ 相同
目标函数InfoNCEInfoNCE + patch-MSE✅ 不同（设计主变量）
全局批大小2,0488,192（4×）❌ 不同
epoch / 样本量2.7 / 316M4.0 / 469M（1.48×）❌ 不同
学习率2e-31e-3❌ 不同
warmup8,0002,000❌ 不同

正确表述：ArmB = "BaiZe AIMv2-style 标准配方（大 batch + 4 epoch + AIMv2-style 目标）" 应用在 open_clip ViT-B/16 塔上；ArmA = "open_clip 标准配方（小 batch + 2.7 epoch + 纯 InfoNCE）"。+4 pp 反映的是"配方整体切换"的综合效应（目标函数 + batch + epoch + lr 联动），不能在控制其他变量的前提下量化"目标函数独占贡献了多少 pp"。

含义：ArmB 训练了 1.48× 的样本量、用了 4× 的 batch —— 部分增益可能来自"更多训练"而非"更好目标"。要得到目标函数的纯单变量贡献，需固定 batch/epoch/lr，仅切换目标函数的后续实验（建议：ArmB-config 但 contrast_weight=0 / patch_weight=0 的消融）。

对预注册判据的影响：判据（lp≥58.03% 不倒退；lp≥61.0% 且 5-NN≥48.98% → 接受）针对的是配方整体效果（"换上 AIMv2-style 配方后是否更好"），不要求隔离目标函数贡献。故判据通过 = "AIMv2-style 配方可接受"，≠ "证明 patch-MSE 目标本身贡献了 +4 pp"。

6.3 塔效应：为何 ArmB 与 ④-4ep 在 k-NN 上表现相反？

配置塔目标lpk-NN模式
④-4epcustom 126.8M (w512/d30)AIMv2-style67.05%42.35% (k=20)lp↑ / k-NN↓ 取舍
ArmBopen_clip ViT-B/16 (86.2M)AIMv2-style62.09%58.10% (k=5)lp↑ / k-NN↑ 齐升

两个 AIMv2-style 实验在 k-NN 上方向相反：④-4ep 的稠密目标"牺牲"了检索（k-NN 远低于 lp），而 ArmB 没有牺牲。最可能解释是塔的归纳偏置：open_clip ViT-B/16 的 CLIP 式全局池化 + class token 结构，在与 InfoNCE 共训时强约束了 pooled 特征的语义聚类（C1 0.86–0.93），使 patch-MSE 的局部信号"补强"而非"挤占"全局表示空间。custom 126.8M 塔缺乏这一约束，patch-MSE 主导了表示，检索质量下降。

⚠️ 此为假设性解读：④-4ep 与 ArmB 的塔、参数量、k 口径均不同，不能严格归因。需"同塔同目标、仅换 k"或"同塔同 k、仅换目标"的消融来确证。

6.4 验收结论

预注册判据阈值ArmB 实测判定
不倒退（相对 ArmA lp）lp ≥ 58.03%62.09%✅ 通过（+4.06 pp）
接受混合配方lp ≥ 61.0% 且 5-NN ≥ 48.98%62.09% & 58.10%✅ 通过（双探针均超阈值）

结论：在 open_clip ViT-B/16 塔上，BaiZe AIMv2-style 配方（InfoNCE + masked-patch-MSE, 1:1, mask 0.6, GBS 8192, 4 epoch）相对 open_clip 标准 InfoNCE 配方，在 lp 与 5-NN 上双探针均显著提升且不倒退，接受该混合配方作为该塔上的训练方案。

后续建议：① batch/epoch/lr-matched 消融（固定 ArmB 配方仅切目标函数）以隔离 patch-MSE 的纯贡献；② 在 open_clip ViT-B/16 上延长训练（8 epoch）看 lp 是否逼近 ④-4ep 的 67%；③ 统一 k 口径（k=5 与 k=20 都跑）使 ArmB ↔ ④-4ep 的 k-NN 可严格比较。

7. 诚实条款

  • 内部 ProtB 口径：本报告所有 lp/k-NN 数字使用 BaiZe 内部 Protocol B，非官方排行榜协议。Protocol B 设计目标是与公开主流值对齐，但仍是内部实现。
  • 非严格单变量（最重要）：ArmA 与 ArmB 在塔、数据源上相同，但在batch（2048 vs 8192）、epoch（2.7 vs 4）、样本量（316M vs 469M）、lr（2e-3 vs 1e-3）、warmup（8000 vs 2000）上均不同。+4 pp 是"配方整体切换"的综合效应，不能全部归因于目标函数。需 batch/epoch-matched 消融才能隔离 patch-MSE 的纯贡献（见 §6.2）。
  • 单 backbone / 单训练 seed：ArmB 仅训练了一个 checkpoint（训练 seed=1234），ProtB 评测用 3 seeds（0/1/2）。σ=0.012 pp 极小但仅反映评测端随机性，不含训练端随机性。不代表 open_clip ViT-B/16 + AIMv2-style 在所有训练 seed 下的上界。
  • 5-NN 与 lp 口径不同：k-NN 用 cosine + k 近邻投票，lp 用线性分类器 + softmax；两者衡量表征的不同性质。且 ArmA/ArmB 的 k=5 与 ④-4ep 的 k=20 口径不同（见 §5.1），跨配置比 k-NN 须谨慎。
  • 5-NN 仅单 seed：5-NN 无随机性（确定性近邻投票），但只评了一个特征集，未做 bootstrap 置信区间。
  • 塔效应解读为假设：§6.3 对"为何 ArmB 与 ④-4ep 在 k-NN 上相反"的解释是假设性机制，未经同塔同 k 消融确证。
  • 数据量标注：ArmA/ArmB 数据源相同（≈118M 对），但 epoch 数不同（2.7 vs 4），ArmB 多见 1.48× 样本。
  • 效率数字：0.87 it/s 为 ArmB 稳态值；ArmB 因额外 patch 前向 + Predictor，比 ArmA（3.37 it/s，更小 batch）单步更重，但 GBS 大 4× 故总样本吞吐更高。两者效率不可直接比（配置不同）。

A.2 实现要点（ArmB 已落地）

  1. 挂 PatchPredictor：在 open_clip ViT 上挂 PatchPredictor（Linear→LN→GELU→Linear，1.18M 参数），作为独立 DDP 模块。
  2. 取 patch tokens（复用同一次前向）：单次 vision 前向后通过 forward hook / forward_features 取 patch tokens，禁止二次 forward（实测 0.87 it/s，无额外 35–45% 开销）。
  3. 自定义 loss + 训练步：model(imgs, texts) 后取 patch tokens → mask 采样（mask_ratio=0.6）→ predictor 前向 → MSE → 与 InfoNCE 加权（1:1）求和。
  4. checkpoint 存取：剥离 predictor：保存 open_clip_state_dict.pt（剥离 predictor，571M）+ predictor.pt + config.json；验收 open_clip.create_model_and_transforms('ViT-B-16', pretrained=<ckpt>) strict load 通过 → 评测侧无感知 predictor。
