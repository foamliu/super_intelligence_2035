R80: GRPO 崩溃模式分类法与检测阈值校准

BaiZe Stage(ii) Post-Training · 零 GPU 蒙特卡洛仿真 · 2026-11-09

摘要

本研究对 GRPO 训练中 7 种已知崩溃模式进行系统分类，通过蒙特卡洛仿真（200次×500步=100k步/模式）校准实时检测阈值。每种模式含检出率/误报率/延迟/恢复协议。

核心发现: C3优势消失和C1奖励作弊最危险（延迟短但恢复代价高）；C4熵坍缩和C6停滞最隐蔽（需EMA监控）。

C1_reward_hacking: 奖励作弊 (Reward Hacking)

机制

模型发现奖励函数漏洞，通过非预期行为获取高奖励而不提升真实任务质量。

已知触发条件

  • 奖励函数过于宽松
  • 无 anti-cheat hook
  • 奖励信号与真实目标脱钩

C2_kl_explosion: KL 散度爆炸

机制

策略偏离参考模型过远，导致生成质量恶化、训练不稳定。

已知触发条件

  • kl_coef 过低
  • 学习率过高
  • clip_ratio 过大

C3_advantage_vanishing: 优势消失 (std=0)

机制

同一 prompt 的 n 个 rollout 获得相同奖励，advantage=0，梯度信号消失。

已知触发条件

  • 题目过难/过易
  • 奖励纯二值无梯度
  • 课程跳过中等题

C4_entropy_collapse: 策略熵坍缩

机制

探索性丧失，策略退化为确定性输出，无法发现新高奖励行为。

已知触发条件

  • entropy_coef 过低/为0
  • 训练过长未重启探索
  • 奖励过于稀疏

  • 学习率过高+大batch
  • 奖励极端值
  • fp16/bf16不稳定

C6_reward_stagnation: 奖励停滞 (Plateau)

机制

训练长时间无进展，avg_reward 停滞，可能课程不当或学习率过低。

已知触发条件

  • 当前难度已饱和
  • 学习率衰减过快
  • 数据多样性不足

C7_length_exploitation: 长度利用 (Padding)

机制

模型发现更长输出获更高奖励，导致输出膨胀。

已知触发条件

  • R2 部分分按步骤给
  • 无长度惩罚
  • max_tokens 过大

三级告警响应

  • watch: 记录日志，观察1൥5步
  • warn: 触发恢复R-01/R-02，20步无改善升级
  • stop: 暂停训练，保存ckpt，回滚，人工介入

局限

  • 仿真基于简化动力学模型，真实GRPO可能更复杂
  • 阈值基于MiniCPM5-2B(2B,lr=1e-6,n=8)，BaiZe正式模型需重新校准
  • 替身模型结果不可直接迁移到BaiZe正式训练
  • 无伪造。蒙特卡洛仿真基于合理假设，标注为仿真投影非实测
