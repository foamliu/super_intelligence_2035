背景：11/9 GPU 到位后，GRPO 训练将从 3347 个合成 RL prompt 中选题。 R57（Vision GRPO 失败教训）揭示了 std=0 是 GRPO 失效的根因—— 当 G 条 rollout 全部落入同一奖励档时，advantage=0，零梯度。 本工具在训练前预筛分每个 prompt 的预期信号强度，避免在零信号 prompt 上浪费 GPU。

核心结论：在 36% base rate + G=8 条件下，2037 个 prompt（60.9%）预期产生 GRPO 信号。 预期 std=0 率 = 26.9%（R1 二值臂），远低于 Vision 线的 78.7%（3.4× 信号改善），验证了 R57 的判断：BaiZe 36% base >> 9.2% → 更多组内方差 → 更少 std=0。

2. 预期通过率模型

使用 logistic 模型对每个 prompt 估计预期 Pass@1，校准到 36% base rate：

raw = base_rate + difficulty_mod + template_pen + api_count_pen + techlib_pen + return_type_pen + loc_pen
pass_rate = sigmoid(5.0 * (raw - 0.5))

分类阈值（G=8，P(all same) > 0.30 → 排除）：

  • TOO_EASY：p > 0.875 → P(all pass) = p⁸ > 0.30 → 无信号
  • SIGNAL：0.125 ≤ p ≤ 0.875 → P(mixed) > 0.30 → 有信号
  • TOO_HARD：p < 0.125 → P(all fail) = (1-p)⁸ > 0.30 → 无信号

8. 11/9 操作建议

  1. 基线复现后（~13h）：用 R55 D1-D6 分析器提取实测 pass rate，替换本工具的估计值
  2. RL Smoke（Phase 1）：仅用 Phase 1 的 50 个 prompt，10 步验证管线
  3. RL 主训练（Phase 2）：用全部 2037 个 SIGNAL prompt，从 R2 部分分档起步
  4. Step 200 首次评估：std=0 > 60% × 3 步 → Dr.GRPO；> 70% → G=12
  5. Step 500 held-out 检查：无改善 → per-scenario 分析 → 排除 0%/100% 场景

9. 方法论说明

局限性：预期通过率是启发式估计，非实测。11/9 基线跑完后需用实测值替换。Logistic 模型权重基于 D1-D6 诊断数据和领域经验标定，未经 GPU 验证。
