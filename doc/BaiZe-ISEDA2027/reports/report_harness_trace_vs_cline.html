HERO 一句话结论：在同一 backbone (kimi-k2.6-cloud) 下，7 个 harness 的 resolve rate 从 23.7% 到 30.3%——6.7pp 方差完全由 harness 架构差异造成。 cline (28.7%) 排第三，但暴露两个硬伤：① 99.5% 的 PBF 尾部有 ai@7.0.49 transform error（211/212），② patch_not_applied 率 35.4%（75/212，高于 codex/claude-code/hermes）。 pi (30.3%) 最强且最快（resolved wall 358s），opencode (29.0%) 与 cline 最相似（head-to-head both=75），codex 最慢但 token 计量最精确（服务端 usage 优先）。

1. HERO 结论 + TL;DR

TL;DR：
• resolve rate 排名：pi (30.3%) > opencode (29.0%) > cline (28.7%) > hermes (27.0%) > codex (26.7%) > claude-code (26.0%) > deepseek-harness (23.7%)
• 速度排名：opencode (460s) < deepseek (491s) < pi (492s) < cline (498s) < claude-code (620s) < hermes (792s) < codex (922s)
• 速度-精度 Pareto：pi 是最优 Pareto 点（最高 rate + 第三快）；codex 是最差（resolve rate 偏低 + 最慢）
• instance 重叠：300 个 all-7 instances 中 182 个 nobody solved (60.7%)、30 个 everybody solved (10.0%)、88 个 some solved (29.3%)
• cline 独解能力：2 个 instances 只有 cline 解出；head-to-head 与 opencode 互补性最弱（both=75），与 deepseek 互补性最强（cline_only=31）
• eval 环境限制：matplotlib/sphinx/pytest 全部 0%（7 harness 全 0%），这些 0 分不代表 harness 能力
• cline 硬伤：ai@7.0.49 transform error (99.5% PBF 尾部) + patch_not_applied 35.4%

2. 方法与口径

7 harness 版本：cline · opencode · pi · codex · claude-code · deepseek-harness · hermes
同一 backbone：kimi-k2.6-cloud（所有 entries 的 model 字段一致）
题集：SWE-bench Lite 300 条（12 repo 全集）；100-set ⊂ 300-set
判据：SWE-bench 官方 f2p (fail-to-pass) + p2p (pass-to-pass) test；resolved = patch_applied=True AND f2p 全通过 AND p2p 全通过
R1/R2 并发口径与不可比性声明：R1（第一轮 7×30/7×100）为串行执行（serial, N=1）；R2（7×300）为 7 路并行（每 harness 内 N=1），wall time 含并发资源争抢开销——R1 与 R2 的 wall time 不可直接比较。本报告数据为 R2 口径（7×300，含 --resume 复用）。
轨迹数据可得性 + 缺失：每个 entry 的 harness_result.stdout_tail 字段保留最后 500 字符——仅存活尾部，非完整轨迹。harness_result.eval 含 patch_applied/f2p_pass/f2p_total/p2p_pass/p2p_total/resolved。缺失：无 per-turn 轨迹（工具调用序列、token 计数、压缩事件均不可得）；仅 wall_s 和 stdout_tail 可用。
数据量：2100 entries（cline 300 / opencode 300 / pi 300 / codex 300 / claude-code 300 / deepseek-harness 300 / hermes 300）

7.4 ★ 改进意见清单（TOP-8）

P0 修复 ai@7.0.49 transform error 新增 已验证

证据211/212 cline PBF 的 stdout_tail 出现 node_modules/ai@7.0.49+.../dist/index.js:637 transform error（99.5%！）。这是 cline 依赖的 ai SDK 版本在序列化/反序列化时的报错。kimi_pilot_results.json cline entries 的 stdout_tail 字段。
预期收益消除 99.5% PBF 尾部的 transform error 噪音；可能减少 patch_not_applied（75/212=35.4%，部分可能由 transform error 导致 patch 格式损坏）。
实现示意升级 ai SDK 依赖或 patch transform 函数；在 PreToolUse hook 中增加 patch 格式校验。

P0 降低 patch_not_applied 率（35.4% → 目标 <25%） 新增 已验证

证据cline 75/212 PBF = patch_not_applied（35.4%），高于 codex (29.4%) 和 claude-code (27.8%) 和 hermes (24.3%)。kimi_pilot_results.json eval.patch_applied=False。
预期收益即使 patch 不正确，至少让 patch 能 apply——这样 f2p test 能跑起来，给出有价值的失败反馈。
实现示意在 patch 写入前增加格式校验 + git apply --check 预检；对 diff 格式做 normalization。

P1 token 计量改「服务端 usage 优先 + 保守兜底」 已提过 已提过（O5）

证据cline 用 3 字符/token 静态系数（tokens.ts:8 CHARS_PER_TOKEN=3）；codex 用 ServerObserved(i64) vs Estimated(i64) 双路（auto_compact_window.rs:24-30）。cline resolve rate 28.7% 但可能因 token 计量不准导致过早/过晚压缩。
预期收益阈值准确 → 少溢出、少过早压缩；本地模型不踩 128K 假窗口（Issue #7772）。
实现示意在 API 响应中提取 usage.prompt_tokens，缓存为 ServerObserved；无 usage 时回退 3 字符/token。

P1 补回 TodoWrite 等价物（跨压缩持久任务状态） 已提过 已提过（O4）

证据cline Focus Chain 已移除（task-proxy.ts:144 currentFocusChainChecklist?: null）；codex 有 ThreadGoal；claude-code 有 TodoWriteTool + SessionMemory。cline 压缩后「从停止处继续」只能依赖摘要文本。
预期收益压缩后进度不丢；减少重复探索。
实现示意在 session 状态中加 todos 数组（不随压缩丢）；UI 侧渲染为 checklist。

P1 补 PreCompact/PostCompact 压缩生命周期 Hook 已提过 已提过（O3）

证据cline compaction.ts:251-254 自认「compactions performed via plugin registerMessageBuilder() or beforeModel hook bypass this wrapper entirely, so they do not emit compaction telemetry」。codex 把压缩做成带 sidecar 的检查点事务。
预期收益压缩行为可端到端审计；插件可干预压缩策略。

11. 诚实条款

① matplotlib/sphinx/pytest 全 0%：这 3 个 repo（56 instances × 7 harness = 392 entries）的 patch_applied=False，0 分不代表 harness 能力。有效比较仅限 django/sympy/sklearn 三个 eval-可用 repo。
