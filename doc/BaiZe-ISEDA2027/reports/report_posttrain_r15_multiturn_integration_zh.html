日期：2026-11-07 · wake：63 · 方法：verl v0.5.x 文档 + SGLang 文档 + 代码审计

摘要：发现 5 个 critical bug（SGLang parser 缺失 / 两套系统混用 / YAML 格式错 / 接口签名错 / config key 错位）+ 2 项注意事项。修复 4 文件，全量验证通过。残余风险 = SGLang minicpm5 parser 的 CUDA 12.4 兼容性。

1. 🔴 SGLang minicpm5 parser 不在 pip 发行版

官方文档列 16 个 parser，minicpm5 不在其中。该 parser 在 PR #25600（2026-05-22 合入 main）但未进 pip。且 sglang>=0.5.16 需 CUDA 13.x，.17 是 CUDA 12.4。

修复：setup 脚本先从 main 安装（含 minicpm5），失败回退 pip 0.5.6.post3。verl config 移除 tool_call_parser（非 verl key，是 SGLang server 参数）。回退方案：BaseTool.execute() 中自行解析 XML。

2. ✅ multi_turn: True 正确

verl v0.5.x 文档确认 multi_turn: True 是布尔值。无需修改。

3. 🔴 两套多轮系统混用

Tool Agent Loop（tool_kwargs）vs Interaction System（agent_name_key）。我们同时有两者，不应混用。

修复：移除 agent_name_key，仅保留 Tool Agent Loop。

4. 🔴 Tool YAML 格式错

class_name 缺模块路径 + tool_schema 缺 type: function 包装。

修复：改为 baize_posttrain_eda_tool.EDASandboxTool + OpenAI Function 格式。

5. 🔴 BaseTool 接口签名错

create() 缺 instance_id；execute() 应为 (instance_id, parameters) 而非 (code, host)。

修复：create() 加 instance_id → execute() 改 (instance_id, parameters) dict 提取 → dry-run ✅

6-7. 📝 其他发现

6：SandboxFusionTool 参考实现已从 verl 源码移除（commit f5e21df6），但 BaseTool 模式有效。我们的实现路径正确。
