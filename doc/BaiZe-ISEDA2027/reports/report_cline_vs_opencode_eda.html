2.2 当年为何选 Cline

  1. Human-in-the-loop 契合芯片设计安全：EDA 操作不可逆性强，逐操作审批符合变更管控流程
  2. MCP 生态加速开发：官方 Marketplace → 快速构建 pdk_mcp_server

4 · 代码架构对比

架构差异本质：Cline 是投影非破坏式设计（原始消息永不改写，编辑在读取期应用），OpenCode 是SQL 截断式设计（seq 阈值 + baselineSeq）。两者都把「上下文压缩」硬编码在核心、把「观察与外围改写」开放给 Hook。

4.1 工具集

Cline

  • 文件：read_file / write_to_file / replace_in_file（EditType 逐块编辑）
  • 搜索：search_files / list_files / search_codebase（ripgrep）
  • 执行：execute_command（逐操作审批）
  • MCP：use_mcp_tool / access_mcp_resource（官方 Marketplace）
  • 子 Agent：dispatch_subagent（IDE 可调用 CLI）
证据：cline/sdk/packages/core/src/session/tools/ · cline_SOURCE_ANALYSIS.html §1

OpenCode

  • 文件：read / write / edit / grep / glob
  • 执行：bash
  • 差异：unified_diff（patch 生成格式）
  • MCP：支持 MCP 协议（社区贡献为主）
  • LSP：自动加载正确的 LSP
证据：opencode_SOURCE_ANALYSIS.html §0 · TypeScript + bun@1.3.14, Effect DI

4.2 循环控制与停手

循环模式Plan/Act 双模式 — Plan 只规划不执行，Act 逐步执行+审批Build/Ask 模式 — 类似但审批粒度更粗
何时停手模型自行决定 / 用户中断 / turn cap / timeout模型自行决定 / timeout / compaction 触发

5 · EDA 场景契合度

EDA 核心需求 = 不可逆操作安全 + 变更管控 + MCP 封装 PyAether + 本地化离线 + 多模态扩展。Cline 在前两项有结构性优势；OpenCode 在后两项更具前瞻性。

5.1 不可逆操作安全（PDK 改参 / 仿真提交）

7 · 综合结论

最终建议：维持 Cline 作为 EDA Agent Harness 主基座，同时关注 OpenCode 的架构优势以汲取改进方向。EDA 核心需求（不可逆操作安全 + 变更管控 + MCP 生态）上 Cline 仍具结构性优势（加权 7.75 vs 6.05），而 OpenCode 在效率、架构现代性、多模态上的优势可通过改进 Cline 来吸收（与 O1–O5 一致）。不建议「双轨并行」——维护成本高且收益有限（resolve rate 无统计差异）。

7.2 核心理由（证据链）

  1. SWE-bench 实测打平：28.7% vs 29.0%，McNemar p≫0.05 → resolve rate 不构成选型依据（证据：kimi_pilot_results.json）
  2. EDA 不可逆操作安全是硬需求：Cline 的 pre-approval + git Checkpoint 是结构性优势（证据：cline_SOURCE_ANALYSIS.html §2）
  3. MCP 生态加速 PyAether 封装：Cline 209 providers / 6237 models + 官方 Marketplace（证据：gradually.ai v4.1.22）
  4. OpenCode 优势可通过改进 Cline 吸收：O1–O5 改进建议已系统性列出（CLINE_IMPROVEMENT_OPPORTUNITIES.md）
  5. 迁移成本高于改进成本：已基于 Cline 构建 MCP 适配 + 审批流程 + Checkpoint → 迁移需重建

7.4 是否需要「双轨并行」

结论：不建议双轨并行。

  • 理由 1：SWE-bench resolve rate 无统计差异（28.7% vs 29.0%），双轨不带来能力增量
  • 理由 2：维护两套 MCP 适配 + 审批流程 + Checkpoint 成本远高于改进 Cline
  • 理由 3：OpenCode 架构优势已通过 O1–O5 转化为 Cline 改进方向
  • 例外：若未来 EDA 对多模态（版图截图/波形图）有强需求，可考虑 OpenCode 作为多模态扩展的辅助工具

8 · 诚实条款

8.1 样本量限制

  • SWE-bench Lite 300 条：覆盖 12 个 Python repo，不代表 EDA 场景（无 PDK 操作、无仿真提交、无版图编辑）
  • 单一 backbone：所有评测使用 kimi-k2.6-cloud，未测试其他模型，结论可能因模型不同而变化
  • 同题重叠仅 300 条：McNemar b/c 仅 11/12，统计功效有限——更准确的说法是「在此样本量下无法拒绝零假设」
  • Cline 版本：评测使用 cline（含本项目 patch），不完全等于上游最新版（v4.1.22）

8.2 评测环境限制

  • 并行条件：7×300 在 7 harness 全并行下运行，有 API 配额争用（但仅 2/300 quota-blocked）
  • 无 Docker：使用 rootfs template + git clone 替代官方 Docker，不是标准 SWE-bench 分数，不能与 leaderboard 直接比较
  • Wall Time 含评测：wall_s 包含 agent 运行 + patch 评测时间
  • Transform error 噪声：Cline 187/300 条有弃用警告，虽不影响功能但可能干扰日志分析
