1. 架构选型（R2→R8）：六架构四指标对比，OpenVision2 胜出

动机：从零预训练对比 6 种视觉编码器架构（500–600M 等参改编），验证「架构对表征质量是否有真实差异」——此前 R1/R2 因随机文本塔 + 退化评测指标（R@1≈1/5000）得出「架构不可区分」的旧结论需推翻。

判定：OpenVision2 胜出 —— 四指标全第一（loss 最低 / IN-1k lp 最高 / 吞吐 3052 img/s 接近最快）。

1.2 三条最终结论

① 架构有真实差异：修复 recipe 下 loss 4.8646~5.6683、IN-1k lp 0.25%~1.14% 可分 → OpenVision2 全指标第一 → 作废旧「loss 与架构无关」结论。

② 坍缩是 SSM 特异：含 SSM 子结构（MambaEye、DeepEncoderV2）即 @300 步坍缩，纯 Attention 系 4 架构全健康。

③ IN-1k 成功替换退化指标：frozen-trunk zero-shot / linear-probe 替换了退化的 R@1（旧 R@1=1/5000 零区分度）。

⚠️ C2 限定（EXPERIMENTS_VISION.md §line 21）：6 架构全是自研 from-scratch 等参改编（非官方模型），「SSM 坍缩」只能表述为「我们 recipe 下、我们自研改编版的坍缩」，🚫 不得推广成「官方 MambaEye/DeepEncoderV2 会坍缩」。

1.3 后续影响

OpenVision2（纯 Attention ViT）锁定为后续所有实验的基础架构；SSM 系架构不再纳入候选。

最终 recipe（GPIC short + InfoNCE + 冻结 CLIP-768 + lr 3e-3）成为 R9~R14 的统一基线。

2. 缩放定律（R9/R10）：「塔越小越高」，w512=126.8M 定位

动机：R8 锁定 OpenVision2 后，R9 扩数据（~2.77M→18.5M）、拉步数到 108k，画 IN-1k 随样本数的 scaling 曲线并外推；R10 补模型规模轴（M），拟合 (N,M) 二维 scaling。

判定：w512=126.8M 最优 —— 「塔越小、每样本效率越高」，数据受限区间加宽塔是负收益。

3. 目标函数（R11）：AIMv2-style 翻盘，loss 轴主线确立

4. E1/E2 公平重跑：Δlp +0.17pp 不可分辨，旧「−5.59pp」= schedule 伪影

动机：2026-10-08⑤ 初版缩放对比 E1(w512) vs E2(w768) 得出 Δlp=−5.59pp（「Bigger is WORSE」），但两臂均用 lr=3e-3 / warmup=20（warmup=20/187101=0.01%，几乎无 warmup），长训练下可能系统性偏害更宽的 E2 臂 → 需公平重跑验证。

判定：NULL（不可分辨） —— 公平 schedule 下 Δlp=+0.17pp（|Δ|<1.5pp），符号跨协议翻转（ProtB +0.17, ProtA −0.17），旧「−5.59pp」纯属 schedule 伪影。

6. 变体实验：V2 Muon 全 LR 坍缩、V3 全量数据 Null

动机：以 E1fair（1ep, ProtB=62.34%）为基线，单变量消融 3 个方向：V1 分辨率 224→336、V2 优化器 AdamW→Muon、V3 数据量 94M→118M（全量 GPIC）。每个变体除被考察变量外与基线逐字节一致。

判定：V2 Muon ❌ 全 LR 坍缩 · V3 全量数据 NULL（Δ+1.18pp 不可分辨） · V1 分辨率暂缓。

6.1 V2 Muon 优化器（🔴 全 LR 坍缩）

7. 外部编码器 ProtB 参照：5 模型 81.72~87.46% vs BaiZe 67.05%

动机：用统一 Protocol B 评测 5 个公开视觉编码器，作为 BaiZe 从零训练模型的同协议参考对照，量化差距并验证「瓶颈在数据规模而非架构」。

判定：参照完成 —— 5 模型 81.72~87.46%（304M~1B 参数 + 336~560px + 大规模预训练）vs BaiZe 67.05%（126.8M + 224px + 从零），差距来自预训练规模，非架构。

7.3 后续影响

同族 OpenVision2（官方预训练 84.97% vs 从零 67.05%）证实：瓶颈在「数据量 + 目标函数」，不是「我们 tower 写得烂」。

此参照为 Stage(iv) MLLM 桥接提供了选型依据—— BaiZe wrapper 使用 OpenVision2 w512/d30 架构，与官方同族但从零训练。

8. merge3ds ArmC：GBS/MBS×4 + LR×4 结果

动机：④-4ep（67.05%）<70% 胜利阈值，epoch 缩放递减 → 转向「合并三数据集 + 大 batch」策略。ArmC 将 GPIC + CC12M + Amshaker 合并（~111M pairs），GBS/MBS×4（512→2048）、LR×4（5e-4→2e-3，Goyal 线性缩放），24h ≈2.85 epoch。

判定：NULL（严格判据） —— ProtB Δ=+1.20pp <1.5pp 阈值；但 zero-shot +5.53pp 和 ProtA +2.71pp 显示表征通用性有实质提升。

  1. ProtB Δ=+1.20pp 未达 1.5pp 阈值 → 严格判据 NULL；但 4 指标全部提升（zs +5.53pp, ProtA +2.71pp, k-NN +2.53pp）→ 合并三数据集 + 大 batch 训练改善了表征通用性

  3. 多变量变更（数据组成 + GBS/MBS + LR），无法隔离单一因素贡献；后续可考虑消融
  4. 训练耗时 22.7h（vs ④-4ep 16.8h）——MBS=256 单步更慢但总步数更少；吞吐 9,978 img/s（vs ④-4ep 2,818 img/s）得益于大 batch

9. 总结与关键结论

🎯 全景 TL;DR

  • 架构：OpenVision2（纯 Attention ViT, w512/d30, 126.8M）六架构四指标全胜 → SSM 系在 InfoNCE recipe 下坍缩
  • 缩放：「塔越小越高」（w384 > w512 > w768 > w1024），数据受限区间加宽塔是负收益；从零对比学习渐近 25.1%（InfoNCE），够不到 20%+ 需 619 亿样本
  • 目标函数：AIMv2-style（InfoNCE + masked-patch-MSE, mask=0.6, 1:1）翻盘 → lp 7.40%→19.76%（+12.36pp），渐近明确 >>25.1%
  • 公平性：E1/E2 公平重跑 Δlp=+0.17pp 不可分辨，旧「−5.59pp bigger is worse」= schedule 伪影
  • Epoch：1ep 62.34% → 2ep 65.37% → 4ep 67.05%（ProtB），递减比≈0.55，<70% 胜利阈值
  • 变体：Muon 全 LR 坍缩❌；全量数据 Δ+1.18pp NULL
  • 参照：5 公开模型 81.72~87.46% vs BaiZe 67.05% → 差距来自预训练规模（649× 数据缺口），非架构
  • merge3ds：ProtB 68.25%（Δ+1.20pp NULL），但 zs+5.53pp 显示通用性实质提升

9.3 核心科学发现

  1. 架构在固定 recipe 下有真实差异（推翻旧「架构不可区分」），OpenVision2 全胜；SSM 特异坍缩（C1=1.0 @300步）。
  2. 数据受限区间「塔越小越高」：M 边际效应 ≈ −2.2pp/参数翻倍，w384(71.5M) lp=7.99% > w512(126.8M) 6.08% > w1024(505M) 0.93%。
  3. AIMv2-style 密集监督翻盘：lp 7.40%→19.76%（+12.36pp），渐近明确 >>25.1%（InfoNCE）。epoch 数比 unique 数据量更重要。
  4. schedule 伪影可制造虚假 scaling 结论：lr=3e-3/warmup=20 在 187k 步下等价于无 warmup + 高常数 LR，不成比例伤害更宽模型 → 旧「−5.59pp bigger is worse」消失为 +0.17pp。
  5. Muon 正交化与对比学习不兼容：Newton-Schulz 放大坍缩方向，全 LR 坍缩（5e-4@2100步, 1e-4@4200步），AdamW 自适应缩放天然抑制。
  6. 瓶颈在数据量 + 目标函数，非架构：同族 OpenVision2 官方预训练 84.97% vs 从零 67.05%（ProtB），649× 数据缺口。
