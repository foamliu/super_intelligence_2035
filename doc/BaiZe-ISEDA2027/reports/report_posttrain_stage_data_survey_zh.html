1. 摘要与核心结论

本报告通过 Web search 调研了 2024–2026 年主流大语言模型（Qwen 系列、DeepSeek-V3/R1、Llama 3 等）后训练各阶段所使用的数据选择策略，并对照 BaiZe 项目已有资产，给出差距分析与可执行建议。

核心结论（5 条）：
  1. 领域退火是预训练末尾的高杠杆操作：在最后 10–30% 训练步上切换到高质量策展数据（教材/代码/数学/领域文档），配合学习率线性衰减至峰值的 1%。Llama 3 报告此操作带来约 4 分提升；Qwen3 在 S2 阶段大幅提升 STEM/代码比例并加速 LR 衰减；DeepSeek-V3 在 14.8T 预训练后用数千步做上下文扩展+退火。对应 BaiZe：用 PyAether API 语料（~4–5M tok）做领域退火是低成本高回报项。
  2. SFT agentic 轨迹是当前 58pp 差距的最大可回收来源。DeepSeek-V3 SFT 用 1.5M 条多域指令（推理任务用 R1 变体生成，非推理用 V2.5 生成）；AgentTrove 汇集 170 万条轨迹（219 源数据集，4x Nemotron Terminal Corpus）；SWE-smith 用 5 万条实例训出 SWE-bench Verified 40.2%。关键发现：仅 10% 的轨迹包含「错误后恢复」决策——这正是 BaiZe 需要补的「缺信号→重试→修正」链。
  3. RLVR 难度筛选直接对应我们 CPU GRPO「advantage=0 无梯度」问题。最新研究（arXiv 2605.28388）表明：样本难度对 RLVR 有非单调效应——中等难度问题提供最强且最稳定的信号，过难问题导致退化行为（答案重复/跳步）。sGPO（arXiv 2606.08854）用一次 8 样本 profiling 过滤全对/全错题，3x 计算效率提升。建议 BaiZe RL 用 pass@8 取 1/8~7/8 区间。
  4. 奖励设计趋势：从二值 outcome reward（RLVR）向 process reward + 工具调用惩罚演进。DeepSeek-V3 RL 用 GRPO（组内比较无需 critic），结合 rule-based + model-based 奖励。对应 BaiZe 四臂设计（R1 二值 / R2 部分分 / R3 R2+工具惩罚 / R4 R3+API 合法性）与前沿方向一致。
  5. 若只有 3 周训练窗口，先补 2 项：PyAether API 语料合成 SFT 轨迹（含工具调用+错误恢复链，~50–100K 条）；RLVR 任务集难度筛选（pass@8 中间区间，~2–5K 题）。前者回收 ~20pp（M1→M2），后者打磨 ~5–10pp（M3）。

2. 领域退火（Domain Annealing / Decay）数据调研

领域退火（又称 annealing phase、decay phase、mid-training）是预训练末尾的一个有界阶段——仍使用 next-token 目标，但学习率衰减、数据混合向高质量和特定领域倾斜、上下文窗口可能扩展。这一阶段介于大规模预训练和 post-training 之间，在近年前沿模型中已接近标配。

2.1 Llama 3：退火数据上采样 + 上下文扩展

Llama 3 在大规模预训练后设计了退火阶段：使用上采样的高质量数据（upsampled high-quality data），跟随在分阶段的上下文扩展之后。上下文长度从 8K 逐步增长到 128K，分 6 个阶段，使用约 800B 训练 token。退火阶段在最后 10–30% 的训练步上切换到策展数据集（教材、代码、数学、清洁对话），学习率线性衰减至峰值的 1%。报告称退火后评测分数比同等计算量继续 bulk 训练高出约 4 分。

来源：Grattafiori et al., 2024 (Llama 3 Technical Report)；ossaihub.com/glossary/annealing-phase（2026-06-10）；labhub.hopto.org（Llama 3 annealing 分析）

2.2 DeepSeek-V3：上下文扩展 + LR 衰减

DeepSeek-V3 在约 14.8T token 主预训练后，分两阶段扩展上下文（4K→32K→128K），每阶段约数千训练步，使用 YaRN 调整旋转位置编码，学习率在退火阶段完成最终衰减。这一披露的价值在于其明确性：上下文扩展仅占千步级（小于 1% token 预算），退火是收尾打磨。SFT 使用 1.5M 规模多域指令数据集（推理任务用 DeepSeek-R1 变体合成，非推理任务用 DeepSeek-V2.5 合成）。RL 使用 GRPO 减少显存并加速训练。

来源：DeepSeek-AI, 2024 (DeepSeek-V3 Technical Report)；jas.ia.ac.cn/article/doi/10.1109/JAS.2025.125495（2026 综述）；scixa.com/article?slug=mid-training-phase-design（2026-10-09）

2.3 Qwen3：三阶段预训练 + S2 知识密集数据上采样

Qwen3 预训练分三阶段：
S1（通用阶段）：30T+ token，4096 上下文，建立基本语言技能和通用知识。
S2（推理阶段）：5T token，4096 上下文，增加 STEM、编程和推理任务的数据比例，并加速学习率衰减（动态调整）。
S3（长上下文阶段）：数百 B token，32K 上下文，数据配比 75% 为 16K~32K + 25% 为 4K~16K，使用 RoPE 参数调节。
总数据量约 36T token（Qwen2.5 为 18T），覆盖 119 种语言。为增加数学和代码数据，使用 Qwen2.5-Math 和 Qwen2.5-Coder 专家模型合成数据（教科书、问答对、代码片段）。数据配比通过在细粒度数据标签的小型代理模型上做消融实验确定——在实例层面而非仅数据源层面优化混合。

来源：qwen.ai/blog?id=qwen3（2025-04-29）；adg.csdn.net/695338005b9f5f31781be2eb（2025-08-05 CSDN 技术解读）；InfoQ 中文站 Qwen3 报道

2.5 对 BaiZe 的映射

BaiZe 2B 模型复用 Stage(i) WSD（Warmup-Stable-Decay）机制。退火语料配比建议（基于 P2 方案书）：
  • Domain（PyAether API 参考/EDA 工具文档）：30%（约 2.5B tok）—— 提供领域知识
  • Web（通用高质量文本）：50%（约 4.2B tok）—— 防遗忘
  • Code（代码语料）：12%（约 1.0B tok）—— 强化代码生成
  • Math（数学推理）：8%（约 0.7B tok）—— 强化逻辑推理
  • 总退火步数：约 4000 步，LR 5e-4→1e-5，总约 8.4B token
退火数据来源：PyAether API 语料约 4–5M tok（已调研，eda_fastmcp API_INFO_MERGED_V3.json 含 8463 个 API）+ 通用/代码/数学语料复用预训练已有数据。

3.2 Agentic 轨迹数据

Agentic 轨迹是当前 post-training 领域最活跃的研究方向——模型需要在多步交互中使用工具、根据反馈调整策略。以下是关键数据集：

AgentTrove（最大开源 agentic 轨迹集）

OpenThoughts-Agent 团队于 2025 年 12 月发布。包含 1,696,847 条轨迹，来自 219 个源数据集，覆盖代码修复、Shell 脚本、数学求解、竞赛编程和通用计算机任务。规模是此前最大开源 agentic 轨迹集 Nemotron Terminal Corpus（430K 行）的 4 倍。所有轨迹采用统一的 terminus-2 harness 格式（ShareGPT 风格对话布局），每条记录包含工具调用、环境响应和最终推理。轨迹由多个教师模型生成（GLM-4.6、GPT-5.1 Nano、Kimi K2.0 等）。每条记录含 messages（轨迹对话）、original_source、original_teacher、reward（奖励值）、task_id。

来源：selectdataset.com/dataset/.../open-thoughts-agenttrove（2026-05-07）；HuggingFace: open-thoughts/AgentTrove

SWE-smith（软件工程 agent 训练数据生成）

NeurIPS 2025 spotlight。提出「环境优先，任务在后」范式：对任意 Python 代码库自动构建执行环境，合成数百至数千任务实例（导致已有测试用例失败）。核心技术包括 4 种故障注入策略（LM 生成错误重写、AST 修改、撤销已有 PR、组合多个缺陷）+ 严格验证流程。仅用 295GB 存储创建 50,137 个任务实例（来自 128 个 GitHub 仓库）。训练 SWE-agent-LM-32B 在 SWE-bench Verified 上达 40.2% Pass@1（开源最优）。关键洞察：基于执行的验证不仅验证解决方案，还能识别导致测试失败的 bug。

来源：CSDN SWE-smith 解读（NeurIPS 2025）；swesmith.com

Nemotron-Cascade 2（NVIDIA）

30B MoE 模型（3B 激活参数），在 2025 年 IMO/IOI/ICPC 达金牌水平。关键技术：Cascade RL 扩展到更广泛的推理和 agentic 领域（在 SFT 精心策展数据集之后）；多域 on-policy 蒸馏从最强中间检查点。训练流程：SFT（策展数据集）-> Cascade RL（多域推理+agentic）-> on-policy 蒸馏。是 DeepSeek-V3.2-Speciale 之后第二个达 IMO 金牌的开权重模型。

来源：blog.expo.dev（Papers Explained 552: Nemotron Cascade 2, 2026-03-31）；alphaxiv.org

DeepSeek-V3 SFT 数据

1.5M 规模多域指令数据集，使用专家模型合成：推理任务用 DeepSeek-R1 变体生成，非推理任务用 DeepSeek-V2.5 生成。这种「强模型 + 执行反馈」的合成策略确保了数据质量和多样性。

来源：jas.ia.ac.cn/article/doi/10.1109/JAS.2025.125495（DeepSeek 综述, 2026）

3.3 工具调用 / 多轮 / 错误恢复轨迹

这是 BaiZe 最需要关注的数据类型——EDA-Eval-PyAether 评测要求模型在多轮交互中使用 PyAether API 工具、根据执行反馈修正代码。

Trajectory2Gym（合成多步依赖结构）

核心发现：在收集的 34,772 条候选轨迹中，仅 40.9% 有 2 个以上决策点，仅 10% 包含错误后的恢复决策。方法三阶段：(1) 组合交互合成——在共享能力词汇中表达动作、观察、恢复、分支，选择数据中代表性不足的路径，生成匹配请求和初始状态，教师模型在真实环境中执行；(2) Grounded supervision——检查每个动作是否可执行(e)且参数和工具是否被 agent 可见记录支持(v)，仅训练满足两者的动作；(3) 基于结构支持的训练——选择轨迹填补每条路径的不足。结果：Tau1/Tau2/BFCL 在所有 Qwen3 尺寸（1.7B~30B-A3B）均有提升，Qwen3-14B 的 Tau1/Tau2 均值从 28.52 提升到 69.44（+40.92pp）。

来源：ai-trend.me/en/research/2610.33568（2026-10-28 Trajectory2Gym）

多工具编排范式转变

从单工具调用到多工具编排：agent 需要在长轨迹中处理中间状态、执行反馈、变化环境和安全/成本/可验证性约束。策略在每步选择动作（工具调用或终止命令），目标是最大化任务奖励同时最小化成本。这一范式直接对应 BaiZe 的「查 API -> 写代码 -> 执行 -> 看报错 -> 改代码」闭环。

来源：alphaxiv.org/vi/abs/2603.22862（2026-04-02 综述）

3.4 领域数据合成（强模型 + 执行反馈造轨迹）

领域数据合成的主流方法是「强模型 + 执行反馈」：

  • DeepSeek 模式：用 R1 变体生成推理轨迹，V2.5 生成非推理轨迹，合成 1.5M 条 SFT 数据
  • SWE-smith 模式：自动构建执行环境 -> 合成任务实例 -> 用单元测试验证 -> 生成 agent 轨迹 -> 按测试结果过滤
  • Trajectory2Gym 模式：教师模型在真实环境中执行 -> 检查动作可执行性和信息可见性 -> 仅训练 justified 动作
  • BaiZe 适用：用 DeepSeek-V4-Pro 在 PyAether 沙盒中跑 158 评测任务（已排除评测集本身）外的类似任务 -> 生成「查-写-改」轨迹 -> 按执行结果过滤成功轨迹 -> 合成 SFT 数据。关键：必须按 API 名/函数签名隔离评测集 158 题（红线）

4.2 奖励设计（outcome vs reward-model vs process）

RLHF vs RLVR 对比（来源：cloud.tencent.com.cn，2026-06-19）：

维度RLHFRLVR
奖励来源人类标注 -> 奖励模型程序自动验证
信号质量有噪声、主观干净、客观、二值化
人力成本大量标注员只需正确答案/测试用例
奖励模型需要（额外神经网络）不需要
适用场景主观任务（风格、安全）可验证任务（数学、代码）
奖励黑客风险高极低

DeepSeek-R1 GRPO 流程：(1) 给模型一道题 -> (2) 生成一组（如 8 个）不同解答 -> (3) 验证器检查每个解答 -> (4) 在组内算每个解答相对于组平均的优势值 -> (5) 用优势值更新参数。GRPO 精妙之处：不需要单独训练价值网络（critic），只靠组内比较计算优势值，比 PPO 省约一半计算量。

来源：jas.ia.ac.cn（DeepSeek 综述, 2026）；cloud.tencent.com.cn（RLVR 详解, 2026-06-19）

对 BaiZe 四臂奖励设计的映射（与前沿方向一致）：

  • R1（二值）：PyAether 断言 pass=1 / fail=0 —— 对应标准 RLVR
  • R2（部分分）：按断言通过比例给 0~1 分 —— 对应 process reward 趋势
  • R3（R2 + 工具调用惩罚）：过度调用工具扣分 —— 对应成本约束
  • R4（R3 + API 合法性）：调用不存在的 API 扣分 —— 对应 anti-cheat

4.3 数据难度筛选（pass@k 中间区间）

这是直接对应 BaiZe CPU GRPO「advantage=0 无梯度」问题的关键发现：

样本难度的非单调效应（arXiv 2605.28388）

研究表明样本难度对 RLVR 有非单调效应：

  • 简单和中等难度问题：提供最强且最稳定的推理提升
  • 过难问题：提供弱学习信号，诱发退化行为（答案重复、跳过必要计算），最终可能降低模型已有能力
  • 中等难度：提供更平衡的信号，同时强化计算和多步推理特征

机制分析（T-SAE）：简单问题主要强化直接回答和基础计算特征，抑制深思熟虑推理特征；困难问题激活推理相关特征但仅在有成功轨迹采样时有用。

来源：ar5iv.arxiv.org/html/2605.28388（2026 RLVR 样本难度机制分析）

sGPO：推理 FLOPs 换训练效率（arXiv 2606.08854）

标准 RLVR 对每个 query 分配固定 rollout 预算，导致两个对称失败模式：简单 query 产生近零优势（策略已解决）和不可解 query 无信号（策略永远解决不了）。sGPO 用一次 8 样本 profiling pass 获取模型感知的经验成功率，然后：(1) 过滤平凡 query；(2) 自适应 group size = 1/成功率；(3) 课程排序（easy->hard）。结果：3x 计算效率提升（含 profiling 成本），精度持平或提升。

来源：emergentmind.com/papers/2606.08854（2026-06-07 sGPO）

直接对应 BaiZe CPU GRPO 的问题：当所有 rollout 全对或全错时，组内优势 = 0 -> 无梯度 -> 浪费计算。解决方案：
  • 用 pass@8 profiling 取 1/8~7/8 成功率区间（即 8 次 rollout 中 1~7 次成功）的题目做 RL
  • 过滤全对（8/8）和全错（0/8）的题目
  • 按难度课程排序：先 easy->medium，后 hard
  • Group size 自适应：成功率低的题用更大 group
