R33: RL 训练排程优化与 11/9 逐日执行时间线

BaiZe Stage(ii) Post-Training · 2026-11-08 · 零 GPU 纯计算分析

⚠️ 替身 RL 预演结果不可迁移到白泽。本分析为排程规划与配置优化，基于 R32 实测 smoke test 数据外推。

§1 摘要

R32 发现全量 RL（2000 iters, batch 128, 3 turns, 8×GPU）需 30–34 天，超出 21 天训练窗口。本节（R33）系统计算 12 种 GRPO 配置在 4×A40 上的精确时间预算，提出三档可执行方案，并生成 11/9–11/15 替身预演逐日时间线与 12/25–01/15 白泽正式训练投影。

核心结论：

  1. 替身预演（11/9–11/15, 7天）：surrogate-C（500 iters, batch 64, 2 turns）= 5.4 天，余量 1.6 天 ✅
  2. 白泽正式训练（12/25+, 21天）：baize-C（1000 iters, batch 64, 3 turns）= 14.3 天，余量 6.7 天 ✅
  3. 保守备选：baize-B（800 iters, batch 64, 2 turns）= 8.6 天，余量 12.4 天 ✅
  4. 评测策略：4 次 quick 1-run + 1 次 full 5-run = 约 6.1 小时
  5. 磁盘：10 个 ckpt × 16GB = 160GB，可用 386GB ✅

§10 风险与缓解

风险概率影响缓解措施
训练时间超预期（开销系数 > 3.5×）中超出窗口备选 baize-B (800 iters, 2 turns) = 8.6 天，余量 12.4 天
OOM（多轮 KV cache 膨胀）低训练中断5 级降级阶梯 (R11): 降 batch → 降 turns → 降 gpu_mem_util → CPU offload → LoRA
Reward hacking（模型学会作弊）中结果无效PreToolUse hook 全程启用 + cheat rate 监控 + anti-cheat 验证 (R30)
SGLang/verl 版本冲突低环境损坏cu124 venv 已隔离 (R25/R27)；setup 脚本可重建
pretrain ckpt 延迟中窗口压缩替身预演验证管道 + 脚本骨架已就绪，ckpt 一到即可起跑

§11 结论

  1. R32 的 30-34 天瓶颈已解决：通过缩减 iters (2000→1000) + turns (3→2) + batch (128→64)，4×A40 可在 14.3 天完成 baize-C 配置，余量 6.7 天
  2. 11/9 替身预演可行：surrogate-C (500 iters, 5.4 天) 在 7 天窗口内完成，含基线评测+smoke+训练+最终评测全流程
  3. 评测非瓶颈：每次 quick eval ~2.5h，final eval ~10.4h，可在 checkpoint 间隙插入
  4. 磁盘非瓶颈：10 个 checkpoint = 160 GB < 386 GB 可用
  5. 6 个决策门确保训练过程可控：每个关键节点有明确的通过/不通过判断标准和回退方案
  6. 下一步：11/9 GPU 到位 → 执行 §6 逐日时间线 → 12/25 pretrain ckpt → 执行 §7 正式训练投影
