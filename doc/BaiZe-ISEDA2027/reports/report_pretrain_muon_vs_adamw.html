6 · 分析与建议

6.1 为什么 Muon 的 loss 更低？

Muon 对 2D 权重矩阵执行正交化后的动量更新（momentum=0.95, Nesterov, ns_steps=5），等效于在权重矩阵的奇异值空间中施加均匀步长。这种正交化使梯度更新的各个方向被均衡化，避免了 AdamW 中可能出现的方向偏置。对于 Mamba2-hybrid 架构（52 层 SSM + 4 层 Attention），大量权重是 2D 矩阵（SSM 的 A/B/C/D 投影、Attention 的 QKV），Muon 的正交化恰好作用在这些参数上，而 1D 参数（norm、bias、embedding、lm_head）仍由标量 AdamW 优化。

6.2 显存代价分析（⚠️ 实现伪影，非算法固有）

本地实测 Muon 显存 +38%（53.8 GB vs 39.0 GB），与理论方向相反。Muon 理论上应更省显存：每 2D 参数只存一个 momentum（4B），而 AdamW 存 m+v（8B）→ optimizer-state 应省 ~45%。PyTorch DeepSpeed blog 实测端到端 peak memory 反而降 ~9%（Qwen2.5-3B fine-tune 34.5→31.4 GiB）。

本地 +38% 最可能的原因：Muon 动量缓冲区 与 标量参数走 AdamW 的二阶矩缓冲区并存 / buffer 未复用。具体来说：(a) Newton-Schulz 迭代（ns_steps=5）每步产生临时矩阵未被及时释放；(b) Muon 的 momentum buffer 与 scalar AdamW 的 m+v buffer 同时驻留显存。在 dist_muon + buffer 复用后，显存应转正为省。此项标注「待查」——换 dist_muon 后需复测显存验证。

6.3 吞吐代价分析（⚠️ 实现伪影，非算法固有）

本地实测 Muon 吞吐 −26%（87K vs 118K tok/s），并非 Muon 固有代价。NVIDIA 官方博客（2026-04-22）在 GB300 NVL72 上测得 Muon 吞吐 near-parity to AdamW（NeMo Megatron Bridge 26.02）。关键差异 = layer-wise distributed optimizer（dist_muon：整层分给各 DP rank，正交化零额外通信） + 分布式 Newton-Schulz（duplicated/distributed/blockwise）。

本地 −26% 的主因 = 用的 plain Muon、非 dist_muon：正交化计算（Newton-Schulz 5 步矩阵乘法）与梯度同步未重叠，直接串行叠加在每步耗时上（753 ms vs 555 ms = +36% per step）。在 dist_muon 下，正交化可与梯度同步重叠，且 Newton-Schulz 理论计算开销仅 ~0.5–0.7%（Keller Jordan 博客：NanoGPT ~0.7% / Llama-405B ~0.5%），不会构成显著瓶颈。

6.4 P-8 建议（外部基准对照后更新）

方案 A（推荐 · 升级）：P-8 采用 dist_muon（layer-wise distributed Muon）。从「可能消除吞吐差距」升级为「NVIDIA near-parity 实证支撑」——NVIDIA 官方在 GB300 上已实测 Muon 吞吐 near-parity to AdamW。需在 8×H100 上验证 dist_muon 实际吞吐（预期收窄至 near-parity）。

方案 B（保守）：P-8 沿用 AdamW（249K tok/s），但训练步数增加 ~25% 以达到 Muon 的 loss 水平。

方案 C（折中）：P-8 用 plain Muon（TP1/DP8），接受 26% 吞吐损失。以 100B token / 87K tok/s 计算，训练时间从 ~4.6 天延长至 ~13.2 天 — 需评估是否在时间预算内。不推荐，因 −26% 是实现伪影而非固有代价。

⚠️ P-8 前待查项：换 dist_muon 后复测显存，验证 buffer 复用是否将 +38% 转正为省 ~45% optimizer-state。此为启动 P-8 前的 prerequisite。

6.5 局限性

  • 本 A/B 仅跑 1000 步（6.55M tokens），远低于 P-8 的 44B-100B token 预算。Muon 的优势在长训练中是否持续，尚需验证。
  • 两臂使用相同的 LR schedule（peak 3e-4），未对 Muon 单独调参。Muon 通常受益于更高的 LR（官方建议 ~1e-3），单独调参可能进一步扩大优势。
  • 未测 dist_muon（layer-wise distributed）配置的吞吐/显存，无法确认 NVIDIA blog 声称的“持平”在本硬件上是否成立。此为 P-8 前待查项。
  • 显存测量在 iter 10 后采样，checkpoint 保存时的瞬时峰值未记录。
  • ⚠️ 诚实声明：§7 的 overhead 归因引用外部文档（NVIDIA blog / arXiv 论文 / Keller Jordan blog），未在本地复现 dist_muon。“待查”≠“已修”。本地 plain Muon 的 −26% 吞吐 / +38% 显存是实测事实，归因分析指明其来源为实现伪影而非算法固有，但修复效果需在 dist_muon 实测后才能确认。

8.5 结论

  1. dist_muon 完全消除了 plain Muon 的两项代价：吞吐 +40.8%（超过 AdamW）、显存 −30.7%（低于 AdamW），而 loss 保持 Muon 级别优势（−22.3% vs AdamW）。
  2. §7 预测全部确认：「−26% 吞吐 / +38% 显存系 plain Muon 实现伪影」由 dist_muon 实测验证——layer-wise distributed 将正交化通信开销消除，optimizer state 分片将显存降至 AdamW 以下。
  3. P-8 最优 = dist_muon：收敛快（Muon 级 loss）+ 吞吐高（≥ AdamW）+ 显存省（37.3 GB，可支持更大 MBS/seq）。
  4. 诚实声明：仅 1000 步短地平线验证，长训练待 P-8 确认。PyTorch max allocated 仍高于 AdamW，但 nvidia-smi 峰值已低于 AdamW。
