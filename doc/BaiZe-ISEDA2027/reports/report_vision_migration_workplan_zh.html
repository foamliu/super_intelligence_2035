四、工作计划（3 阶段 / 8 项任务）

阶段一：基础设施修复 + 真实波形数据合成（第 1-3 天）

任务 1：修复 /nas_train 挂载或迁移数据

  • 问题：v9 结果、原基座模型 qwen3vl_2b、baize-vision 数据集均在 .12 的 /nas_train 上，.12 SSH 超时不可达
  • 方案 A：申请网络团队打通 .17->.12 SSH（优先，因 .12 上有大量历史产物）
  • 方案 B：经隧道 SSH 到 .15，检查 .15 的 /nasdata 是否有副本（.15 有 NFS /nasdata -> 10.251.9.180:/g0tedaap）
  • 方案 C：在 .17 上重新下载 Qwen3-VL-2B（HuggingFace 或内部镜像），用 Qwen3.5-2B 作为纯文本替代（v10 已验证可行）
  • 验收：基座模型可加载，vision 线可在 .17 上独立运行训练脚本

任务 2：WaveView 真实波形合成 Pipeline

  • 目标：利用 WaveView 沙盒的 SPICE 仿真能力，生成真实电路仿真波形（而非纯数学合成的正弦/方波）
  • 技术路径： 
    # 1. 在 WaveView 沙盒中跑 SPICE 仿真 -> 生成波形
python3 -> HTTP POST -> 127.0.0.1:8664/v1/run_code
  -> tcl: wvpp_setup_simulation / wvpp_mtb_run_start
  -> tcl: sx_wave_to_list -> 提取数据点
# 2. 数据点通过 HTTP response 返回 .17
# 3. .17 端 matplotlib 渲染为 PNG 波形图
# 4. PNG + label -> 多模态训练数据
  • 波形类型：
    • 反相器链瞬态仿真：inv chain -> 延迟波形（上升/下降沿、过冲、振铃）
    • RC 网络充放电：RC 电路 -> 指数充放电波形
    • 振荡器起振：ring oscillator -> 周期波形 + 起振包络
    • 差分对放大器：AC 分析 -> 正弦响应 + 增益/相位
    • ADC 动态测试：斜坡输入 -> 阶梯码 + DNL/INL
  • 产出：500-2000 张真实 EDA 波形 PNG + JSON 标注（波形类型、关键参数、仿真网表）
  • 验收：合成 100 张样本，人工检查 10 张确认波形真实性和图像质量

任务 3：WaveView -> matplotlib 波形图渲染标准化

  • 目标：建立从 WaveView 数据点到标准化 PNG 的自动化 pipeline
  • 关键参数：
    • 图像尺寸：512x512 或 1024x512（适配 VLM 输入）
    • 波形样式：黑色背景 + 绿色波形线（仿 WaveView 默认风格）或白底蓝线
    • 标注类型：时间轴（ns/us）、电压轴（V）、网格、游标
    • 数据点密度：128-1024 点/周期（从 16 点升级）
  • 多通道支持：同一 PNG 中显示 2-4 路信号（clock + data + output）
  • 产出：waveview_to_png.py 标准化渲染脚本 + 渲染样式规范
  • 验收：渲染 5 种波形类型各 10 张，全部通过视觉检查

阶段二：多模态波形理解实验（第 4-10 天）

任务 4：构建波形图像-文本对数据集

  • 数据来源：
    来源波形类型数量标签
    WaveView SPICE 仿真反相器/RC/振荡器/放大器/ADC1000+类型/参数/网表
    数学合成（matplotlib）正弦/方波/三角/锯齿 + 噪声2000+频率/幅度/相位/噪声
    混合（真实 x 数学）真实波形 + 参数扰动1000+参数差异标签
  • 任务设计：
    • T1 频率比较（继承 v8-v10）：给定两波形图，哪个频率更高
    • T2 波形类型识别：给定波形图，分类为 sine/square/triangle/RC/exponential
    • T3 参数估计：给定波形图，估计频率/幅度/上升时间
    • T4 异常检测：给定波形图，判断是否有振铃/过冲/毛刺
    • T5 波形描述生成：给定波形图，生成自然语言描述（用于 SFT）
  • 产出：4000+ 图文对 JSONL + train/val/test 分割

任务 5：多模态 SFT 训练（GPU7 -> GPU4-7）

  • 模型选择：
    • 首选：Qwen3-VL-2B（若 /nas_train 修复后可用，支持图文输入）
    • 备选：Qwen3.5-2B + 16 点数值文本输入（v10 已验证，纯文本路径）
    • 升级：在 GPU7（46GB A40）上跑 LoRA SFT，batch_size=4-8
  • 训练配置： 
    CUDA_VISIBLE_DEVICES=7 python train_wave_vision.py \
  --model_path Qwen3-VL-2B \
  --train_data wave_image_text_pairs.jsonl \
  --epochs 5 --lr 2e-5 \
  --lora_r 16 --lora_alpha 32 \
  --batch_size 4 --grad_accum 4 \
  --image_size 512
  • 对比实验：
    实验组输入训练预期
    A: 纯文本 16 点数值序列文本SFT（v10 复现）B~55%
    B: 图像 512x512PNG 波形图SFT（新）B>60%?
    C: 图像 + GRPOPNG 波形图SFT + RLC>B?
    D: 图像 + 数值（融合）PNG + 数值SFT最佳?
  • 关键假设：图像输入比 16 点数值文本包含更多信息（波形形状、边沿、过冲），可能突破 v10 的 55% 瓶颈
  • 产出：4 组对比实验结果 + 统计分析（McNemar + paired bootstrap）

任务 6：GRPO 升级——从 CPU 到 GPU + 真实波形

  • v10 负结果根因分析：n_disc=29（有分歧样本）但 C < B -> GRPO 在数值文本输入上无法有效区分波形差异；可能原因：16 点数值输入信息量不足
  • v11 改进方案：
    • 输入升级：16 点数值 -> 512x512 PNG 图像（信息密度 100x↑）
    • GPU 训练：CPU 50 步 GRPO ~5h -> GPU 200 步 ~2h（40x 加速 + 4x 步数）
    • 真实波形：数学合成 -> WaveView SPICE 仿真波形（更复杂的边沿/振铃）
    • reward 设计：正确/错误 -> 分级 reward（类型正确 +0.3，参数 +-10% 内 +0.5，完全正确 +1.0）
    • grpo_lr：1e-5 -> 5e-6（v10 的 1e-5 可能仍偏高）
  • 预注册判据（先写后跑）：
    • SUCCESS：C > B（mean），McNemar p < 0.05，3 seeds 一致，n_disc > 10
    • FAIL：C <= B 或 p >= 0.05 或 seeds 不一致
    • 新增诊断：图像输入的 B > 数值输入的 B（验证信息密度假设）
  • 产出：v11 实验报告 + 更新 HTML 报告 + 论文 4.7 节素材

阶段三：面向论文的扩展实验（第 11-20 天）

任务 7：WaveView 波形分析 Agent（Tool-Use 验证）

  • 目标：训练模型通过 WaveView Tcl 命令分析真实波形文件（FSDB/WDF），而非仅看预渲染 PNG
  • 技术路径： 
     User: "分析这个 FSDB 波形文件中 CLK 信号的频率"
 Model: sx_open_sim_file_read("input.fsdb")
        sx_signal("CLK") -> wave_obj
        sx_gmeas_data(wave_obj) -> period=10ns -> freq=100MHz
        "CLK 信号频率为 100MHz"
  • 意义：验证"小模型 + EDA 工具调用"范式在波形分析领域的可行性，与 BaiZe 主线（代码生成 + 沙盒执行）形成互补
