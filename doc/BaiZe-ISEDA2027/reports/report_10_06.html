4pretrain：NCCL 证伪 + 空窗提案裁决 + ⭐提速令

4.1 ⭐ P-9.12 NCCL / NVLink 拓扑核查 ✅ COMPLETE —— 用户假设被证伪

你的假设：「若当前 NCCL 实际走的是 PCIe P2P，换更好的 NVLink 拓扑会有改善」。实测结论：不成立 —— NCCL 本来就在用 NVLink。

项目实测
硬件拓扑（nvidia-smi topo -m）8×H100 = NV18 full-mesh NVSwitch（18×NVLink @ 26.562 GB/s = 478 GB/s/GPU，全部 UP）
NCCL 实际通道（NCCL_DEBUG=INFO）via P2P/CUMEM = 42 次（100%） · via NET = 0 · via SHM = 0 ⇒ 走 NVLink，不是 PCIe
对照实验（7 组，2-GPU all_reduce）default（Ring+P2P+LL）最优：1GB busbw = 164.56 GB/s（algbw 329 GB/s = 69% NVLink 峰值）
反证NCCL_P2P_DISABLE ⇒ 3.44 GB/s（48× ↓）—— 说明 NVLink 确实在起作用；ib_disable/algo_tree ≈15.6（10×↓）；nvls_on/proto_simple/shm_disable ≈66（2.5×↓）
NVLS不可用（即使 NCCL_NVLS_ENABLE=1 仍报 "0 nvls channels"）
判据（全给）① 通道 = NVLink 100% ② 最佳 = default ③ tok/s 提升 0% ④ 可迁移 8 卡
📄 产出：report_pretrain_nccl_topo.html（11.3KB，自包含：topo 矩阵 + NCCL 日志关键行 + busbw 表 + tok/s 表 + 结论）
⇒ 价值：虽然证伪，但把 NCCL 这条线彻底排除了（69% 峰值 + default 已最优）——瓶颈在别处，直接指向 Step 2 的数据管线 / 并行 / backend。
