BaiZe 预训练 · Xmodel-2.5 Decay「训坏 → 修复」完整报告与下一步建议

报告时间：2026-10-23 | 实验线：BaiZe Stage(i) 预训练 | 硬件：10.239.2.29（8×H100-80GB）
起点：Xmodel-2.5 stable 末点 step_532000（起点基线 CS8 = 61.03%） | 主对照：Xmodel-2.5 官方 final（CS8 65.40% / CX6 32.90%）
一句话结论：decay v2（自写脚本）把起点模型「训坏」（CS8 44.97% vs 官方 65.40%，Δ −20.43pp）；改用官方 train_decay_fp8_1113.sh 配方（use-mup + Muon 0.2 + FP8 hybrid + 无 warmup + MBS=5）做 5000 步 decay 后，能力基本回到起点：CS8 58.97% / CX6 28.02%，较旧 v2 +14.00 / +21.81pp，仅比起点基线 CS8 低 −2.06pp。判定：decay 训坏已被官方 μP+Muon+FP8 配方修复。

§1 全历程概览（训坏 → 归因 → 修复）

阶段时间事件与关键数字
训坏10-16 ~ 10-20decay v2（自写脚本）：71.2B tokens / 19,980 步，从 step_532000 冷启动。最终 CS8 44.97% / CX6 6.21%，vs Xmodel-2.5 官方 final 65.40% / 32.90%（Δ −20.43 / −26.69pp）→ 判定「decay 训坏」（起点 61.03% → 44.97%，退化了 −16.06pp）。
归因10-20 ~ 10-21归因取证（#648/#649）：①双移位 bug（py:547-548 + :567-568 双重移位）；②peak LR 1.67e-3 过高；③自写脚本缺 μP；④code 26 epochs 过采样；⑤step0 loss 11.72 异常。
排查10-21 ~ 10-22排查实验（仍自写脚本）：L1（修双移位 + LR 5e-4 + warmup 100）→ CS8 59.03%（step0 loss 1.75 vs v2 11.72，双移位确认修复）；L2（只修双移位 + 高 LR）被直令 kill@step2370，转官方方案。
修复10-22 ~ 10-23decay-5000（官方 1113.sh）：use-mup + Muon 0.2 + FP8 hybrid + 无 warmup + MBS=5 + WSD exponential 5000 步（≈18.1B tokens）。最终 CS8 58.97% / CX6 28.02%，vs 旧 v2 +14.00 / +21.81pp，vs 起点基线 61.03%（Δ −2.06pp）。

§6 训坏根因回顾（引用 #648/#649 已交付结论）

序根因证据 → 本次修复如何消除
1高双移位 bugv2.py:547-548 预移位 + :567-568 chunked-CE 再移位 → 训练移位两次、评测一次。L1 修掉后 step0 loss 11.72→1.75。官方 Megatron 无此 bug（标准单移位）→ 根因①消除。
2高peak LR 1.67e-3 过高疑似过高放大移位破坏。官方同量级 LR（1.66667e-3）但在 μP 作用下是可控的 → 说明「LR 过高」的实质是「缺 μP 下裸用高 LR」，属③的下游表现。
3高自写脚本缺 μP官方 stable/decay 全程 use-mup；自写脚本无 → 高 LR 直接打乱表征。官方 1113.sh 自带 use-mup → 根因③消除。
4中code 26 epochs 过采样code 仅 0.270B 却被训 6.98B。decay-5000 沿用 4 源配比，code 占比温和（8%），未复现极端过采样。
5中step0 loss 11.72①+②+③ 叠加的异常，是结果不是独立根因。decay-5000 从转换后 ckpt 加载，loss 从 1.1x 平滑下降起步。
根因优先级：①双移位（代码级确认）＋ ③缺 μP（配方级）是主因；②高 LR 与 ⑤step0 异常本质是它们的下游表现。官方 1113.sh（μP + Muon + FP8 + 标准单移位）一次性同时消除了主因①③与②⑤，这是本次修复能一步到位的根本原因。

§7 残余 gap 分析（58.97% 为何仍未到 65.40%）

gap差值归因假设（按可能性排序）
decay-5000 vs 起点基线−2.06pp5000 步 / 18.1B 的 WSD 尾段尚未充分展开（相当于官方 71.2B 的 1/4），退火收益未吃满。
decay-5000 vs 官方 final−6.43pp①decay 量不足（18.1B vs 71.2B）为主要候选；②数据配比不同（官方 11 源 vs 当前 4 源 64/24/8/4）；③官方 final 的 CX6 32.90% 口径含其完整评测（我们 CX6 逼近到 28.02%，仅差 4.88pp）。
注意：CS8 gap（−6.43pp）明显大于 CX6 gap（−4.88pp），且当前 CS8 仅回撤起点 2.06pp，说明模型「基本回到起点」但「尚未重现官方 final 的额外增益」。这部分增益最可能来自 更长的 decay（71.2B） 与 更全的数据配比，正是下一步实验要验证的两点。

§8 下一步实验建议（按价值排序）

1延长 decay：5000 → 20000 步（对齐官方 71.2B 量级）

  • 价值：🔝 直接验证核心假设 —— 当前 CS8 58.97% 接近起点但未到官方 65.40%，最可能是 decay 量不足。20000 步 × 960 × 3776 ≈ 72.4B tokens，对齐官方 1113.sh 原设 lr-decay-iters 20000，看 CS8 是否逼近 65.40%（若能到 ~63–65%，即可判定残余 gap 主体来自 decay 量）。
  • 成本（GPU 时）：5000 步实耗 ~17h 墙钟（8×H100）× 4 倍步数 ≈ ≈2.5–3 天墙钟（约 3–4× 当前 5000 步 GPU 时）。
  • 风险：低 —— 配方 100% 沿用已验证的 1113.sh，仅把 --train-iters / --lr-decay-iters / --lr-wsd-decay-iters 三项 5000 → 20000；需按 1000 步间隔盯 val 曲线，确认 WSD 尾段无二次发散、loss 继续单调降。
  • ETA：≈2.5–3 天（8×H100 连续）。

2对齐官方数据配比（11 源 → 隔离数据贡献）

  • 价值：官方 1113.sh 使用 11 源配比，当前仅有 4 源（SFT 64% : UFW-L3 24% : code 8% : math 4%）。若「延长 decay」后 CS8 仍卡在 ~61–63%，数据配比差异即为下一个主嫌疑，本实验可单独隔离数据贡献。
  • 成本（GPU 时）：取决于数据获取。官方 11 源数据在 Xmodel 机 /data1/i_line_data/（本机无），需先下载/补齐并 tokenize 成 Megatron text_document 格式；数据就绪后仅需 ~18h×（与候选 1 同量级）训练。
  • 风险：中 —— 首要风险在数据获取是否完整可行（若无完整 11 源，只能近似配比，结论需打折）；建议先做 100 步冒烟确认 loss 接得住，再起短程 5000 步 A/B。
  • ETA：数据准备 1–2 天 + 短程 5000 步检验 ~1 天。

3补跑起点基线 CX6（sdpa 同口径，量化 gap）

  • 价值：本次起点基线 CS8=61.03%，但 CX6 崩于 flash_attn varlen 兼容性问题（#658），导致「decay-5000 相对起点的 CX6 变化量」目前无法精确计算。用 decay-5000 已跑通的 sdpa + confirm_run_unsafe_code 修复膜补跑起点 step_532000 的 CX6，得到起点 CX6 基线。
  • 成本（GPU 时）：仅评测、零训练，~1h（8×H100 并行）以内。
  • 风险：极低 —— 复用已验证的 sdpa 修复脚本。
  • ETA：~1h，可在候选 1 训练期间并行完成。

4超参微调（min-lr / decay-iters / warmup，定点榨取残余 gap）

  • 价值：在候选 1/2 确定 gap 主因之后，若仍差 1–3pp，可对 min-lr（1.04e-4 ↑↓）、decoded-min-lr、decay-iters 尾段形态或加少量 warmup 做小尺度扫描，追求最后一两个 pp。
  • 成本（GPU 时）：短程 5000 步级实验 × 2–3 组，每组 ~17h 墙钟。
  • 风险：低，但边际收益有限，建议放在候选 1/2 之后按残差定点，避免过早陷入局部调参。
  • ETA：每组 ~1 天（可串行/并行）。
建议执行顺序：先并行做 ③（补 CX6 基线，~1h）；同时启动 ①（延长 decay 20000 步，~3 天） —— 这是价值/信息量最高的选项；①结束后若 gap 仍未闭合，再做 ②（对齐 11 源数据）；最后视余量做 ④（超参微调）。

§9 结论

  • decay 训坏已被修复：官方 1113.sh 配方（μP + Muon 0.2 + FP8 hybrid + 无 warmup + MBS=5）5000 步后，CS8 从旧 v2 的 44.97% 恢复到 58.97%，CX6 从 6.21% 恢复到 28.02%（+14.00 / +21.81pp），能力基本回到起点基线（CS8 61.03%，Δ −2.06pp）。
  • 训坏根因已定位并消除：①双移位 bug（代码级）＋ ③缺 μP（配方级）为主因；②高 LR 与 ⑤step0 异常为其下游表现。官方脚本一次性消除主因，L1 实验（step0 loss 11.72→1.75）独立证实了双移位修复。
  • 残余 gap 主嫌疑 = decay 量不足（18.1B vs 官方 71.2B）＋ 数据配比差异；建议按 §8 顺序推进：①延长 decay 至 20000 步 → ②对齐 11 源 → ③补 CX6 基线（可并行）→ ④超参微调。
