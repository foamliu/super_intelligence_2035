1. 背景与口径

  • 评测集：princeton-nlp/SWE-bench Verified（500 题，非 Lite）。
  • 模型：统一骨干 kimi-k2.6-cloud（7 路仅 harness 不同）。
  • 打分：官方 swebench v5.0.2 docker harness。
  • 此前 R1567 已做一次归因（cline 326 阶段，3 类根因 = 静默退出 35 / 超时卡死 18 / 补丁质量 116，McNemar 极显著）；R1569 适配器修复（commit 29df7ba7f）+ R1633 rerun 58/58 后 cline 抬到 356（比 326 时 +30）。本轮回答的是修复后仍存在的差距。
  • 本轮「cline」= 适配器修复后的终态数据（eval_cline-patched.json，resolved=356）；与 opencode（resolved=401）逐实例配对。
  • 铁律：infra-or-fetch-timeout 单列不计能力；结果 JSON 不入库；所有数字可由本脚本复算。

2. 方法（逐实例配对拆解）

  1. 取 cline 与 opencode 的 per-instance eval 结果（eval_*.json 的 resolved/failed/no_patch）。
  2. 交集 common = 两路均有明确 eval 状态的实例 = 500 题。
  3. 差距集 gap = opencode resolved ∩ cline 未 resolved = 58 题。
  4. 逐题看 cline predict 行为（progress_cline-patched.json：model_patch_len/wall_s/returncode/quota_blocked），归因：① 补丁质量/能力（产了 patch 但测试不过）② 静默退出/超时（无 patch，wall≥1700s 超时墙或 wall<300s 秒级静默）③ no-patch 其它 ④ infra（quota_blocked）。
  5. McNemar 精确双侧检验（cline vs opencode，common 题配对）。
  6. 对补丁质量子集，对照 opencode 同题 patch 大小/耗时/repo 分布。

5. 补丁质量/能力深挖（50 题）

这 50 题 cline 都产出了 patch 但测试不过，属「能力差」而非「没跑通」。对照 opencode 同题：

cline patch 字节数均值 6177 · 中位 2876 · min 448 · max 56655
opencode patch 字节数均值 5887 · 中位 3362 · min 636 · max 85150
cline wall_s（秒）均值 620 · 中位 481 · min 129.0 · max 1739.8
opencode wall_s（秒）均值 501 · 中位 425 · min 86.7 · max 1612.3
opencode patch 比 cline 更大的题数30 / 50

解读：补丁质量子集里 cline patch 中位 2876B vs opencode 3362B，opencode 在 30/50 题上 patch 更大；但「更大」不等于「更好」——多数是 cline 改对了位置但不够完整（漏改关联文件/测试覆盖不足）或改错方向。cline 平均耗时 620s 略高于 opencode 501s，说明 cline 多花了时间却没换来更高 resolved 率，提示其工具循环/上下文组织效率偏低。

9. 根因结论：能力差 vs 接入损耗

能力差（补丁质量/模型底座）50 题（86%） —— cline 产了 patch 但测试不过
接入损耗（harness 适配/超时/静默退出）7 题（12%）
infra（不计能力）1 题（2%）

结论：R1569 适配器修复后，cline 与 opencode 的差距已从「接入损耗为主」转为「能力差为主」。修复前（326 阶段）静默退出 35 + 超时 18 占主要矛盾；修复后静默退出/超时仅 7 题，50/58=86% 的差距是 cline 产了 patch 但不完整/不正确——这是 kimi-k2.6 底座在 cline harness 的上下文组织与工具循环下「能定位但改不全/改不对」的能力问题，而非 harness 没跑通。统计上该差距极显著（McNemar p=6.27e-08）。

注：能力差≠「cline harness 设计差」。同一 kimi-k2.6 底座在 opencode harness 下 resolved 401，说明 harness 的上下文组织/工具授予/探索策略会显著放大或抑制底座能力。cline 的差距可拆为「底座固有上限」与「harness 对底座能力的利用率」两部分，后者是可改进的接入损耗-能力复合项。

方向措施预期收益置信度

能力复合对 cline 工具循环加「测试自检」步骤：产 patch 后本地跑目标测试，失败则迭代，对标 opencode 探索策略回收 5–10 题（估）中
底座换更强底座或 kimi-k2.6 更新版本（同 harness 对比可隔离 harness 因素）回收 10–20 题（估）低
