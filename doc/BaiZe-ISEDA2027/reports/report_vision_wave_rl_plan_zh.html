1. 为什么必须「交互」而非「看图猜」

1.1 静态截图的原理性上限

单凭静态截图做数值量测存在不可消除的原理性上限——这不是"模型不够大"能解决的，是信息论意义上的信息丢失：

表 1.1 静态截图量测的四重信息损失
损失源机制不可恢复性实例
像素量化连续值->离散像素栅格；224px 宽对应整个时间轴，每像素 ~T/224不可逆1us/224px -> 每像素 ~4.5ns，上升沿 <1ns 不可见
抗锯齿渲染器对曲线做亚像素平滑，边缘像素颜色是信号值与背景混合不可逆蓝色波形+白底 -> 边缘浅蓝，无法推断精确过零时刻
分辨率 vs token提高分辨率可增信息，但 MLLM token 预算固定（2B ~4096 token）权衡上限1024px 波形 ~1024 image token -> 占 25% 上下文
轴刻度 OCR数值精度依赖先正确读轴刻度文字再像素->物理量换算，两步串联误差累积不可靠"1e-6" 读成 "1e-5"？量级差 10x

关键论证：波形截图 W×H 像素，时间轴跨度 T，电压轴 V。像素级时间分辨率 dt=T/W，电压分辨率 dv=V/H。基于像素的量测不确定度下界为 max(dt,dv) 量级——不是模型能力问题，是采样定理决定。增大模型参数（2B->70B）不改变此下界，因为输入信息量（像素数）没增加。这与烛龙论文一致：grounding gap 受 Omega 约束而非模型规模。截图是有损通道（Omega_lossy），工具读出是无损通道（Omega_exact）。

1.2 分工：看图定性 -> 调工具定量

表 1.2 MLLM 与 WaveView 工具的分工
能力由谁为什么举例
趋势识别MLLM 看图定性判断不需精确值"信号在 0-100ns 内整体上升"
异常定位MLLM 看图异常"位置"是视觉特征"50ns 处有尖峰"

分工原则：模型负责决定看什么、量哪里（policy），精确值由工具读出（execution）。这正是烛龙「freeze K, maximize Omega, run Phi」三原则的实例化：freeze K = 视觉理解能力通过 SFT 获得后冻结；maximize Omega = WaveView 替代截图，Omega 从有损到无损；run Phi = 每调一次工具更新信念决定下一步。

2. 与烛龙的接口契约：waveform_read 工具与 Omega 保真度

2.1 工具定义

工具名：waveform_read

输入（自然语言问题 + FSDB 路径）：

{ "question": "clock 信号的周期是多少？", "fsdb_path": "/path/to/sim.fsdb", "context": { "signal_hints": ["clock","reset"], "time_window": ["0","1u"], "design_scope": "top" } }

输出（结构化 JSON，非自然语言）：

{ "status": "ok", "answer": { "value": 10.0, "unit": "ns", "measure_type": "period", "signal": "clock", "method": "sx_wave_to_list + edge_detection" }, "evidence": { "tool_calls": [ {"cmd":"sx_open_sim_file_read sim.fsdb","result":"handle_ok"}, {"cmd":"sx_signal v(clock)","result":"handle_nonempty"}, {"cmd":"sx_wave_to_list $h","result":"0 1 0 1 ... (297 samples)"} ], "coordinates": { "fsdb":"/path/to/sim.fsdb", "signal":"clock", "first_edge_rise":5.0e-9, "second_edge_rise":15.0e-9 } }, "confidence": 0.95, "raw_observation": "..." }

为什么 JSON 而非自然语言：烛龙需将量测结果用于后续推理（"周期 10ns -> 100MHz -> 满足约束？"）。自然语言需再解析引入不确定性；JSON 可直接被烛龙推理引擎消费，且证据坐标允许回溯验证。

2.3 理论锚点：为何 waveform_read 提升 Omega 保真度

烛龙论文核心论断（来源：ICML2028/4_collapse.tex + 10_conclusion.tex + 6_implications.tex）：

Agent Harness H = (S, O, A, B, T, Omega, Pi)，其中 K=离线知识（L1-L3 先验），T=转移模型，Omega=观测似然（运行时观测通道），Phi=信念更新。

核心洞见：grounding gap 受 Omega（观测似然）保真度约束，而非 T（模型先验/规模）容量。形式化地，D_grounding(t) <= ||p_tilde - p_real|| — 上界与模型规模无关。

若 I(Theta_t; O_t | K) = 0，再多的先验改进也无法恢复当前状态。观测通道是约束性瓶颈。

三原则：冻结 K（知识）；最大化 Omega（观测）；持续运行 Phi（信念更新）。

表 2.2 waveform_read 如何提升 Omega 保真度
烛龙概念无工具（纯截图）有工具（交互）提升
观测通道 Omega截图->像素级量测（有损）Tcl->FSDB 原始采样（无损浮点）lossy->exact
信息量 I(Theta;O|K)受像素分辨率限制FSDB 完整采样序列~0 -> >0
Grounding gap D下界=像素量化误差下界=仿真精度（远小）大幅降低
模型规模依赖增大模型不改变像素下界增大模型不改变 FSDB 精度规模无关，但下界更优
信念更新 Phi单次截图->单次推断多步工具调用->迭代更新单步->递归

结论：waveform_read 将波形观测通道从 Omega_lossy升级为 Omega_exact，直接降低 grounding gap 上界。此上界与模型规模无关，所以即使 BaiZe 只有 2B，只要观测通道无损，量测精度可达仿真精度级。这是本计划书的理论基石。

3. RL 环境设计：把 WaveView 包成 Gym

3.1 环境架构总览

将 WaveView Tcl 后端 wv -ace_no_gui 封装为 Gym 风格确定性环境（相同 FSDB + 相同动作序列 -> 相同观测，因 FSDB 是静态文件，wv 不含随机性）。

表 3.1 环境接口定义
组件定义说明
State S(FSDB 文件, 已打开信号句柄集, Tcl 命令历史, 观测缓存)FSDB 在 episode 内不变
Observation O紧凑文本/数值观测：已打开信号列表(name+type+bits+nsamples) + 最近工具返回值摘要 + 可选截图文本观测省 token；截图观测信息量大但昂贵
Action A受控 Tcl 子集（§3.2，7 类模板）非任意 Tcl，兼顾安全与可判分
Reward R数值相对误差分档 + 证据奖励 + 稠密中间奖励（§4）主奖励 episode 终止时；中间奖励每步
Transition T执行 Tcl -> wv 返回 -> 解析输出 -> 更新 State确定性
Done Dsubmit / 步数耗尽 / wv 调用耗尽 / 环境崩溃（§3.4）—

3.2 动作空间：受控 Tcl 子集

为什么不是任意 Tcl：WaveView Tcl 解释器可执行任意 Tcl（文件读写、进程调用），RL 训练中是安全隐患。动作空间限制为受控子集：预定义模板化命令，参数由模型填充，命令结构由环境固定。

表 3.2 受控 Tcl 动作空间（7 类）
动作模板参数（模型生成）对应 API安全
A1: opensx_open_sim_file_read {fsdb}fsdb_path（环境注入）sx_open_sim_file_read只读打开
A2: get_signalsx_signal v({name})signal_namesx_signal只读查询
A3: get_typesx_wave_is_logic $h; sx_wave_is_analog $hhandle（环境维护）sx_wave_is_logic/is_analog只读
A4: get_bitssx_number_of_bits $hhandlesx_number_of_bits只读
A5: get_valuessx_wave_to_list $hhandlesx_wave_to_list只读取值，无时间戳
A6: dump_hiersx_dump_hier [sx_current_sim_file] {outfile}outfile（环境指定 tmp）sx_dump_hier只列 scope

非法动作处理：信号名含非法字符（; | &）-> 环境 mask（返回 "INVALID_ACTION"，不执行 wv）。JSON 格式错误 -> 返回 "PARSE_ERROR"，不终止（允许重试）。

分层设计：Level 0（必选）A1->A2->A7 最小有效序列；Level 1（推荐）+A3 先判数字/模拟；Level 2（进阶）+A4 get_bits + A6 dump_hier；Level 3（完整）+A5 get_values。分层对应模型能力梯度，RL 奖励中更高 Level 正确使用得额外奖励。

3.3 崩溃阈值与环境重启

关键工程约束（实测，来源: trace_deepreads/as67p）：wv -ace_no_gui 单进程内连续调用 >=5 次会 S01 crash（sx_crash.sx），fresh tmp + HOME 隔离无效。工程实践：每次最多 3 次。

表 3.3 崩溃阈值对 episode 设计的影响

步数上限由问题复杂度决定由 wv 预算决定：3 次 wv ~ 3-7 步
环境重启不需要每 episode 开始前 fresh wv 进程

4.2 R_main：数值相对误差分档

主奖励不是文本相似度，而是数值相对误差的分档函数。确保可验证（有 GT 数值）、不可被语言技巧 hack。

R_main = { 1.0 if |v_pred - v_gt| / |v_gt| <= 0.01 // 1%: 满分 0.7 if |v_pred - v_gt| / |v_gt| <= 0.05 // 5%: 良好 0.4 if |v_pred - v_gt| / |v_gt| <= 0.10 // 10%: 合格 0.1 if |v_pred - v_gt| / |v_gt| <= 0.25 // 25%: 部分分 0.0 otherwise // >25%: 零分 } // v_gt=0 改用绝对误差；非数值答案用 exact match；v_pred 缺失 -> R_main=0.0

双盲抽检：训练集嵌入隐藏 FSDB + 隐藏题（训练时不可见，RL 偶尔抽检）：隐藏 FSDB 使用 power/cpf_demo/demo.fsdb（实测信号/采样数/值/missing 集均不同——来源: as67p §demo FSDB 探明）；每 100 episode 插入 5 个隐藏题，结果不进主奖励但记录监控日志；判据：隐藏题准确率不应显著低于训练题（>20% 差距=过拟合信号）。

6. 训练配方：SFT 冷启动 -> GRPO 强化

6.1 两阶段训练总览

阶段 1: SFT 冷启动（必须）：用合成数据+Oracle Tcl 轨迹做监督学习，教会模型"基本工具调用格式和流程"。没有 SFT 冷启动，2B 模型在受控 Tcl 子集上的有效动作分布极稀疏，RL 探索效率接近零。

6.5 动作合法性 mask

动作必须是合法 Tcl 子集，非法动作直接 mask（不执行、不进入梯度）：语法 mask（不在 7 类模板中）、参数 mask（信号名含 shell 元字符）、预算 mask（wv 耗尽后仍请求）、重复 mask（同信号重复 get_signal 转 no-op）。mask 在 logits 层面实施（非法 logit=-inf），比"执行后惩罚"更高效——不浪费 wv 预算。

  • 从通用到领域：论文是通用框架，本计划书是 EDA 波形领域实例化
  • 从 claim 到 evidence：论文 claim "gap 受 Omega 约束"，本计划书提供实验证据——同一 2B 模型，纯截图 vs 工具交互，量测精度差距应显著

3: RL vs SFTSFT only vs SFT+RL同模型同数据RL 在工具调用效率和错误恢复上优于纯 SFTRL 优化策略，SFT 优化先验
4: 信念更新(Phi)1 步 vs 多步同模型限制步数多步交互准确率优于单步Phi 递归更新比单次更有效

期望结论叙事框架：1) 问题：MLLM 看波形图有原理性上限（像素量化），是 Omega 有损性导致；2) 方法：WaveView 包成 Gym，RL 训练 MLLM 主动调工具获取无损观测；3) 理论：接上烛龙 Omega bound——工具交互将 Omega 从 lossy 到 exact；4) 实验：2B+工具 vs 2B+截图，+25pp（假设），证明 Omega 是瓶颈；5) 推论：模型规模不是 EDA MLLM 的约束性瓶颈，观测通道设计才是。

B.2 数据安全

  • 真实 FSDB 脱敏：698 机 trace FSDB 可能含设计敏感信息，使用前确认脱敏要求（或仅用公开 demo FSDB）
  • 训练数据隔离：合成数据用开源仿真器，不涉真实设计；真实数据需确认授权
  • 评测数据 held-out：WaveQA-RL 的 FSDB 与训练集完全隔离

B.3 模型安全

  • 输出结构化：JSON 非自由文本，限制输出空间
  • 动作合法性 mask：非法动作 logits 层面 mask
  • 防 hack：§4.5 anti-hacking 措施防止编造

总结

本计划书将前作"可选 Stage-3W RL"展开为完整技术路线，核心要点：

  • 为什么交互：静态截图有原理性数值量测上限（像素量化），工具交互提供无损观测通道
  • 烛龙接口：waveform_read 输出结构化 JSON，嵌入 run_code 闭环；理论锚点=Omega 观测保真度 bound（gap 与模型规模无关，2B 也能达仿真精度）
  • 环境设计：WaveView 包成 Gym 确定性环境，7 类受控 Tcl 动作，崩溃阈值决定单 episode<=3 次 wv 调用
  • 奖励设计：数值相对误差分档(1%/5%/10%)+证据奖励+稠密中间奖励+anti-hacking
  • 数据三级：合成(GT 天然可得)+真实(Oracle Tcl 回放)+派生(换信号/时间窗/量测目标)
  • 训练配方：SFT 冷启动(必须)->GRPO 强化(无 value 网络，2B 省显存)
  • 评测：WaveQA-RL 300 题+双参照线(纯看图/Oracle Tcl)+回归护栏
  • 成本：Pilot ~4 GPU·h+~6 CPU·h/~2 天；全量 ~12 GPU·h+~16 CPU·h/~4 天；wv 调用是瓶颈不是 GPU
  • 论文贡献：从"烛龙的一个 tool"->"multimodal grounding 实证"，将 ZhuLong Omega bound 从纯文本扩展到多模态

本轮零实验：不训练、不起 RL、不跑 WaveView、不动 GPU。所有实测事实引用自 repo 内已核实深读笔记。不伪造任何评测数字或 API key。
