1Conditional Transfer from Controlled Pretraining Mixtures to Code TOP-1 ✅ 方法论可借鉴

原文标题
Conditional Transfer from Controlled Pretraining Mixtures to Code
arXiv
https://arxiv.org/abs/2610.11548 · cs.CL
日期
2026-10-08（v1，published=2026-10-08T06:23:21Z）
关注面
配比/退火 合成数据 规模 vs 质量
一句话摘要
区分三个信号——diagnostic（loss 是否跟踪全局预训练进展）、teachable（loss 是否响应自身 token 预算）、transfer（纳入后是否改善下游目标）——在受控预训练里固定 70% 通用 Python、30% 做单纯形配比扫描，发现「可教 ≠ 有用」且基于 loss 的自适应调度器会背离下游目标（Ado 把 OpenCodeInstruct 压到 ~1% 后比固定配比差 2.4–11.0 pp）。

🔧 与本线的关系（具体到源/脚本）

直击 P-8 数据配比核心问题，给出一个可直接搬用的方法论判据：不要把「加数据后 loss 降了」当成收益证据，要把 diagnostic / teachable / transfer 三个信号分开测。

  • P-8 配比搜索（baize_mix_optuna.py + BO R2）：可直接套用其「固定主干 + 30% 单纯形扫描」的受控消融协议。当前 BO R2 用 lm_eval 8 集均分作 objective（Spearman ρ=−0.80），与本文「以下游 transfer 而非残余 loss 为准」的结论方向一致——本文提供了额外理论支撑：「loss 自适应调度器会背离下游目标」，警示我们 BO 搜索的目标函数不能用预训练 loss。
  • 合成数据准入（Code/Math 退火料）：其「精选合成 vs 文献探针」的来源分层（精选 10/12 可教 vs 文献 4/15 可教）可直接映射到 UltraData-Code / UltraData-Math 合成数据准入——先过 transfer 关，而非 loss 关。
  • R3 分词后数据质量评估：三信号框架可用于评估 R3 全量分词（1483.91B tok / 5.94TB）后各子集的 teachability 与 transferability。

💰 借鉴成本

GPU·h：~0（纯方法论借鉴）；若做「固定主干 + 单纯形扫描」验证，约 ~50 GPU·h（proxy 92.7M × ~10 组配比 × 5K 步）。墙钟：读论文 ~2h；跑验证 ~1 天。数据依赖：已有（UltraData-Code / UltraData-Math 全在盘上）。

⚠️ 风险/不确定性

① HumanEval pass@20（15.9→22.6→19.5）与 Ado 差 2.4–11.0 pp 均为作者自报、未复现，任务仅限 Python code、规模未展开；② 「可教性」判据依赖「loss 响应 token 预算」的测量，在超大规模（1483.91B tok）上噪声可能更大；③ 本文测的是 code 领域，迁移到 base(web)/math 的有效性未知。

🏷️ 价签（可行性 × 潜力）

维度分理由
可行性9 / 10纯方法论，无需新数据/新算力，读论文即可复用框架
潜力8 / 10直接对应 P-8 配比 + BO 搜索目标函数设计，有反直觉结论可避免踩坑
综合72TOP-1：最高可执行价值，建议立即将三信号框架纳入 P-8 实验设计

2CoTrace: Data Recipes for Training Terminal Agents with Harness-Model Co-Evolution TOP-2 💡 方法论灵感

原文标题
CoTrace: Data Recipes for Training Terminal Agents with Harness-Model Co-Evolution
arXiv
https://arxiv.org/abs/2610.10426 · cs.CL
日期
2026-10-07（v1，published=2026-10-07T17:06:59Z）
关注面
配比/退火 合成数据
一句话摘要
提出 harness-aware 数据配方 CoTrace：显式管理轨迹路由、来源匹配（provenance matching）、课程刷新——反复出现的执行失败驱动 harness 合成，策略训练严格条件于「与所采纳运行时匹配、经核验的 rollout」（SFT）或新鲜在线交互（RL）。原文称紧凑的 harness-匹配语料比跨同类 harness 汇聚的大语料更省算力。

🔧 与本线的关系（具体到源/脚本）

  • SFT/Agent 数据管线（UltraData-SFT-Agent-2609，50 shard / 51 GiB）：CoTrace 的「provenance matching（轨迹 ↔ 生成它的 harness）」概念可迁移到 SFT-Agent 数据质量分筛——当前 SFT-Agent 数据是混池的，若按来源 harness 分层标记，可避免异构 harness 轨迹混池导致的训练-评测错配。
  • 数据课程设计（P-8 退火阶段）：「执行失败驱动 harness 合成 → 课程刷新」可映射到退火数据的动态调整——根据 proxy 模型在 BO 搜索中的失败模式，动态增加特定领域退火料比例。
  • 污染隔离设计：其「只留经核验的 rollout」可对照本线 check_contamination.py 的「只留经扫描的数据」——两者都是「数据准入需过验证关」的原则。

💰 借鉴成本

GPU·h：~0（方法论借鉴）；若对 SFT-Agent 数据做 provenance 分层标注，约 ~5 CPU·h。墙钟：读论文 + 评估接口差异 ~3h。数据依赖：已有（SFT-Agent-2609 在盘上）。

⚠️ 风险/不确定性

① 原文面向 terminal agent（SWE-bench / Terminal-Bench），与 BaiZe 预训练数据管线定位不同——借鉴面限于 SFT/退火阶段；② 原文数字（Qwen3.5-9B 从 78 提升到 88 SFT / 90 RL）为自报、未复现；③「provenance matching」需要 SFT 数据自带 harness 来源标签，UltraData-SFT-Agent-2609 是否有此元数据需核实。

🏷️ 价签（可行性 × 潜力）

维度分理由
可行性7 / 10需先核实 SFT 数据元数据是否含 harness 来源标签
潜力6 / 10对 SFT-Agent 数据分筛有方法论价值，但非 P-8 核心瓶颈
综合42TOP-2：对 SFT 数据管线有方法论借鉴，建议读论文后评估 SFT-Agent 元数据

一句话摘要
「扩 RL 算力」技术报告：RL 前先做多模态 mid-training（扩探索空间），沿三维度扩 RL 算力——① 更大 batch + 更高吞吐（异步训练，每步 1,568 样本 / 2.7–3.7B token，上下文最长 1M）；② 更多样更复杂的环境（code/general/visual/cyber 混合多种 agent harness）；③ 更多 grader 算力（groupwise agentic grading）。冻结 MoE router + 多层反 reward hacking 防线。开源训练动态/RL 环境/RL 框架。

🔧 与本线的关系（具体到源/脚本）

  • 多模态数据构造（85M 下载 + GPIC）：其「多模态 mid-training 扩探索空间」直接对应本线 85M（LLaVA-OneVision-1.5-Mid-Training-85M，46.7TB / 12,124 parquet）的定位——85M 本就是 mid-training 数据。MiMo 的做法是「先 mid-training 再 RL」，对 BaiZe 多模态训练阶段排序有参考：多模态 mid-training → 后训练 RL。
  • 退火课程设计（P-8 annealing）：其「混合任务课程（code/general/visual/cyber）」可对照 BaiZe 退火配比（base 86 : code 10 : math 4）——MiMo 的四领域混搭提示退火阶段可考虑加入 visual 数据。
  • 数据质量评估：「groupwise agentic grading 为长程任务给出更准 reward」可迁移到数据质量评估——用代理模型对候选数据做 groupwise grading 而非单点打分，可能更鲁棒。

💰 借鉴成本

GPU·h：~0（方法论借鉴）；若在 proxy 上试 groupwise grading，约 ~20 GPU·h。墙钟：读技术报告 ~3h（32 页 7 图 17 表）。数据依赖：85M 下载进行中（65.6%），GPIC 已完成（8128 tar）。

⚠️ 风险/不确定性

① MiMo-V2.6 是大规模技术报告（150 位署名），模型规模未在日报中展开，在 ~2B 规模的适用性未知；② 其 RL 基建远超 BaiZe 当前基建，工程借鉴成本高；③「多模态 mid-training 扩探索空间」的具体数据配方未在日报中给出，需读原文。
