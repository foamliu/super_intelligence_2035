OpenVision2（纯 Attention） vs MambaEye（视觉 SSM） vs MoE-ViE（稀疏 MoE） vs DeepEncoderV2（Attention+SSM 混合） —— loss 收敛 / 训练吞吐 / 推理吞吐 对比
📅 完成：2026-09-30 🖥️ GPU：6×H100·80GB / 架构（DP6） 📦 规模：500–600M / 从零预训练（随机初始化） 🎯 目标：SigLIP 对比学习 + 固定 text tower

🏆 胜出架构：OpenVision2（纯 Attention ViT，w1024·d30·h16·mlp4096，505.0M）

四架构在 5000–10000 步长地平线上 loss 全部收敛到 ~4.45–4.47（差 <0.02，噪声级，架构不可区分），因此架构选择 完全由吞吐/延迟决定：OpenVision2 训练 2139 img/s（最快，比混合/SSM/MoE 快 1.47×–2.7×）且推理 6.51 ms/img（最快，比 DeepEncoderV2 快 2.7×）。

loss：四架构并列（不可区分） 训练吞吐：OpenVision2 胜（2139 img/s） 推理延迟：OpenVision2 胜（6.51 ms）

🔑 关键方法学发现：S1 观察到的「四架构 loss 全停 6.7342 平台」是 cosine LR 坍缩伪影（--steps 1000 令 cosine 在 ~700 步就把 LR 从 1e-3 衰减到 ~2.6e-4→1e-5，loss 卡死），并非架构等价；延长训练（cosine 跨 5k–10k 步）后 loss 继续降至 4.45–4.47，才得到这一结论。

1任务与公平口径

  • 三层次结论：P0 三硬指标（loss / 训练吞吐 / 推理吞吐）→ P1 稳健（长地平线 / 多种子 / 下游检索）→ P2 核心自由度（分辨率·patch·目标函数·数据侧）→ P3 训练超参与推理深挖。
  • 决策 1（从零）：四架构均随机初始化，不加载任何 ImageNet/CLIP/SigLIP 上游权重，仅对比架构本体。
  • 决策 2（统一栈）：统一 open_clip(3.2.0) + SigLIP（sigmoid 对比）+ 固定 shared text tower（12L·512w·8h，同一 BPE，四架构共用，只动 vision tower）+ 同分辨率/patch/增强。
  • 决策 3（等参）：四架构实测参数量落 500–600M（MoE 同时报告总参数与每 token 激活参数）。
  • 决策 4（推理基准）：sglang 未装，P0 主口径退化为统一前向 benchmark（torch.cuda.Event，同一代码路径 / batch=1 / 固定分辨率 / bf16）；相对结论可信，生产级吞吐见 S9 备注。

2环境与配置

  • 环境：conda py310（CUDA 12.8 / PyTorch 2.8.0 / open_clip 3.2.0 / mamba_ssm 2.2.6 / flash_attn / webdataset 1.0.2）。
  • GPU：主节点 10.239.2.12，GPU 0–5（6×H100·80GB，DP6，CUDA_VISIBLE_DEVICES=0..5，torchrun 直驱）；四架构同卡数、同 batch、同 seed。
  • 数据：LLaVA-OneVision-1.5 imagenet/EN 统一子集 500K 对 → webdataset tar（en500k/*.tar，25 shard）；S5 检索 held-out 集 eval5k（laioncn/EN 5000 对，与训练源不同→真 zero-shot）。
  • 默认配置（锚点）：cls=224 / patch=16 / SigLIP / lr=1e-3 AdamW(0.9,0.95) / warmup 100 + cosine / seed=1234 / bf16 / batch=32×6=192 / text tower=12L·512w·8h。

9综合结论

  • 质量（loss）：四架构在 5k–10k 步长地平线上 loss 全部 ~4.45–4.47，差异 <0.02（噪声级）——等参、从零、同一固定 text tower 的 SigLIP 下，架构不改变可达到的 loss（224/16 的 196 token 小序列不足以让 SSM/MoE 发挥长序列优势）。
  • 训练吞吐：OpenVision2 2139 img/s 最快（DeepEncoderV2 1459 / MoE-ViE 852 / MambaEye 790），纯 Attention 无逐 token 循环（SSM）或路由（MoE）开销。
  • 推理延迟：OpenVision2 6.51 ms/img 最快（DeepEncoderV2 17.8ms / MoE-ViE 141.7ms / MambaEye batch=1 停摆），batch=1 单图是 MLLM 最常见场景，SSM/MoE 劣势在推理端被进一步放大。
  • 最终推荐：OpenVision2（纯 Attention ViT，505M） 为 Stage(iii) 视觉编码器胜出架构 —— 3 项硬指标中 2 项（训练/推理吞吐）决定性占优、1 项（loss）并列。
  • 局限：① 从零预训练仅到 ~4.45 loss（远未收敛），下游仅在 5k held-out 检索上验证；② 统一子集 500K（未到千万级），数据侧（caption 粒度·规模·中英比例）因预算裁剪/defer；③ 推理基准为统一前向 bench（非 SGLang 生产栈）；④ 共享集群争用（S1/S2 与另一项目并发）对早期吞吐测量带病（S3 干净实测已修正）。
