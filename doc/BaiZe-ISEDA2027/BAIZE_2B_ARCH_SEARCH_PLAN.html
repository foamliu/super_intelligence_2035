3三个必须遵守的关键决策

防止 agent 走弯路、保证三组指标可比的三条铁律（已确认）：

决策 1 · 统一到 NVIDIA/NeMo recipe（已确认）

两个架构训练入口不对等，必须统一，否则指标不可比：

架构问题结论
Mamba2-hybrid 2B只能走 NeMo recipe pretrain(pretrain_config(...), forward_step_func)都走 NeMo recipe，各写一个 2B provider + recipe
MiniCPM5-2Bswift --finetune 无纯随机初始化入口；vocab 130560 与 DeepSeek 129281 冲突

决策 2 · tokenizer / 词表统一为 DeepSeek

两架构嵌入层词表都按 DeepSeek vocab=129281 → pad 129408，不用 MiniCPM5-2B config 的 130560。 数据用同一份 DeepSeek 切词的 .bin/.idx（复用 preprocess_data.py），两架构共用，避免 tokenizer 影响对比。

决策 3 · 训练口径对齐（唯一变量 = 架构本身）

  • seq_length=4096、micro_batch_size=1（共享 GPU 下 mb2 易 OOM）、bf16
  • 相同 global_batch_size、AdamW、LR=3e-4、warmup/decay、weight_decay、train_iters(~1000)、数据子集、seed
  • 两架构同卡数（建议各 6 卡）

5执行状态机与阶段划分

agent 每次被唤醒只走一步（读记忆 → 判断 → 执行 → 回写记忆 → 退出）。

data_check→ env_check→ arch_prepare→ experiment_run→ experiment_wait→ infer_bench→ converged
PHASE目标关键产出
data_check确认可用数据子集够 ~1000 步选定数据集路径、切词产物
env_check验证环境 + omegaconf 规避 + import megatron.bridge确认阻塞已规避
arch_prepare落地 NeMo launcher（torchrun + forward_step）+ MiniCPM5-2B 新建 GPT/Llama provider，各跑 10 步冒烟「从零可跑性」+ 实测参数量 + 冒烟 loss/吞吐
experiment_run启动一个「已打通的」架构跑 1000 步训练日志

infer_bench测推理 tok/s（prefill/decode 分开）写入 EXPERIMENTS_2B.md
converged汇总三张对比表 + 胜出架构 + 生成 HTMLBAIZE_2B_ARCH_RESULT.html

阶段划分（S1~S4）

  • S1 打通从零冒烟：两架构随机初始化、跑 10 步前向+反向、输出 loss；任一架构 3 次冒烟失败 → 标记 ❌ NOT_RUNNABLE 并跳过。
  • S2 1000 步训练：两架构各跑 ~1000 步，输出 loss 曲线 + 训练 tok/s（相同数据/超参）。
  • S3 推理 benchmark：统一 SGLang 栈（MiniCPM5→Llama、Mamba2-hybrid→nemotron_h），前置 ckpt→HF 转换；batch=1、固定 seq、prefill/decode 分列。
  • S4 收敛报告：汇总三张表 + 胜出架构 + 可复现命令 + HTML。

6公平对比口径

三组指标各自的口径约定，确保「只差在架构」：

指标口径约定易踩坑
