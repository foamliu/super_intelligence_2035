\section{Post-Training for EDA Agentic Capability}\label{sec:llm-posttrain}

Stage~(ii) is where the domain prior enters: the pre-training corpus of Section~\ref{sec:llm-data} is general web, code and mathematics text and contains no EDA artifacts, so every EDA fact the model holds must be installed here.
% 中文：第 (ii) 阶段是领域先验的入口：第 \ref{sec:llm-data} 节的预训练语料是通用网页、代码与数学文本，不含 EDA 产物，因此模型掌握的每个 EDA 事实都必须在此装入。
This is also what makes the small model interesting: ZhuLong supplies API knowledge through retrieval, whereas \llm can, in principle, carry some of it in weights---a difference RQ2 measures directly.
% 中文：这也正是小模型的有趣之处：ZhuLong 通过检索提供 API 知识，而 \llm 原则上可以把一部分装进权重——这一差异由 RQ2 直接测量。
The stage has three steps---domain annealing, supervised fine-tuning and RLVR---and terminates in the preference-based adaptation of Section~\ref{sec:domain}.
% 中文：该阶段分三步——领域退火、监督微调与 RLVR——并以第 \ref{sec:domain} 节的基于偏好的适配收尾。

\subsection{Common Protocol}\label{sec:posttrain-eval}
All variants are scored on \textbf{EDA-Eval-PyAether}~\cite{liu2026zhulong} and, where stated, on the full 449-task suite of that benchmark ($158$ PyAether, $157$ SKILL, $134$ Tcl, the latter pooling WaveView $77$ and Innovus $57$).
% 中文：所有变体在 EDA-Eval-PyAether 上评分，并在注明处使用该基准的完整 449 任务（158 PyAether、157 SKILL、134 Tcl，后者合并 WaveView 77 与 Innovus 57）。
We follow the benchmark protocol exactly---five runs, reshuffled order, fresh context, mean Pass@1 with run-to-run s.d., $2500$\,s per task---and hold the harness byte-identical (Table~\ref{tab:harness}).
% 中文：我们严格遵循基准协议——五次运行、打乱顺序、重置上下文、平均 Pass@1 及运行间标准差、单任务 2500 秒——并保持框架逐字节一致（表 \ref{tab:harness}）。
A second control is contamination: the 13-gram blacklist of Section~\ref{sec:llm-data} covers $193{,}295$ entries drawn from $536$ tasks, and any task whose overlap exceeds threshold is reported rather than dropped silently.
% 中文：第二项对照是污染：第 \ref{sec:llm-data} 节的 13-gram 黑名单覆盖来自 536 个任务的 193,295 条，任何越阈任务如实报告而不静默丢弃。

\subsection{RQ2: Does a Small Model Need Retrieval More?}\label{sec:rq2}
ZhuLong reports that removing retrieval costs $10.7$\,pp pooled, but that the loss is toolchain-specific ($15.1$\,pp on SKILL, $9.1$\,pp on PyAether, $7.7$\,pp on Tcl) because PyAether traces can partly rebuild API knowledge by introspecting the sandbox.
% 中文：ZhuLong 报告移除检索合并损失 10.7 pp，但高度工具链特定（SKILL 15.1 pp、PyAether 9.1 pp、Tcl 7.7 pp），因为 PyAether 轨迹可通过沙盒自省部分重建 API 知识。
A 2.2B model has fewer parameters in which to store that knowledge, so the natural prediction is a \emph{larger} retrieval delta everywhere, and a larger gap between PyAether and SKILL.
% 中文：2.2B 模型可存该知识的参数更少，故自然预测是各切片检索差值\emph{更大}，且 PyAether 与 SKILL 之间的差距更大。
This is the test of whether ``weights can replace retrieval''---the assumption a local subagent must rely on (Table~\ref{tab:retrieval}).

\subsection{RQ3: Is the Belief-Update Budget Still Monotone?}\label{sec:rq3}
ZhuLong bounds the number of \texttt{run\_code} calls per trace and finds accuracy monotone in $k$ on PyAether ($63.8\%$ at $k{=}1$, $69.1\%$ at $k{=}3$, $77.7\%$ at $k{=}10$, unsaturated), with a \emph{lagged} channel---returning the previous execution's state---landing between $k{=}3$ and $k{=}10$ at $73.0\%$.
% 中文：ZhuLong 限制每条轨迹的 \texttt{run\_code} 次数，在 PyAether 上发现精度随 k 单调（k=1 为 63.8%、k=3 为 69.1%、k=10 为 77.7%，未见饱和），而「滞后」通道（返回上一次执行的状态）落在 k=3 与 k=10 之间（73.0%）。
On a smaller model the same budget may bind earlier or later; both directions are informative, so we pre-register the shape, not the numbers (Table~\ref{tab:budget}).

\subsection{RQ4: Re-measuring the Read-Back Ladder on 2.2B (Claim~C)}\label{sec:rq4}
This is the load-bearing experiment of the paper.
% 中文：这是全文的承重实验。
ZhuLong operationalizes observation fidelity as three closed-loop variants that differ only in what \texttt{run\_code} returns: (N$'$) nothing, (B) pass/fail, (F) full state; pooled accuracy moves $69.8\to72.2\to76.9$, a span of $7.1$\,pp.
% 中文：ZhuLong 把观测保真度操作化为三种仅「返回值」不同的闭环变体：(N′) 无、(B) 二值、(F) 全状态；合并精度 69.8→72.2→76.9，跨度 7.1 pp。
Repeating that ladder on \llm produces one of two readings, and both are decisive:
% 中文：在 \llm 上重测该阶梯会产生两种解读之一，且都有决定性：
\begin{itemize}
\item \textbf{Span $>7.1$\,pp} (expected): a model with weaker weight priors depends \emph{more} on observation, so $\varepsilon$ binds harder as scale falls; ZhuLong's $\varepsilon$-bound is then \emph{strengthened} by the continuation rather than merely repeated.
% 中文：跨度 >7.1 pp（预期）：权重先验更弱的模型更依赖观测，故随规模下降 ε 更紧；这样 ZhuLong 的 ε 界被续作加强，而不只是被重复。
\item \textbf{Span $<7.1$\,pp}: the small model substitutes priors for observation, and the $\varepsilon$-bound is conditional on backbone capacity; the paper then reports the substitution ratio and revises the framing.
% 中文：跨度 <7.1 pp：小模型以先验替代观测，则 ε 界以骨干容量为条件；论文随后报告替代比并修正表述。
\end{itemize}

\subsection{Reward Design and Its Ablation}\label{sec:reward}
An execution sandbox turns correctness into a verifiable signal, so we optimise with group-relative policy optimisation and no value network---cheaper in memory, which matters at 2.2B on one node.
% 中文：执行沙盒把正确性变成可验证信号，故我们采用无价值网络的 GRPO——更省显存，这对单节点上的 2.2B 很重要。
Table~\ref{tab:reward} separates four rewards; a binary signal is the baseline, partial credit addresses its sparsity, a tool-call penalty aligns the policy with the harness cost model, and an API-legality term penalises hallucinated symbols.
% 中文：表 \ref{tab:reward} 区分四种奖励：二值信号为基线，部分得分缓解稀疏性，工具调用惩罚使策略对齐框架成本模型，API 合法性项惩罚虚构符号。
Because the reward is computed from assertions a policy could target directly, the anti-cheat hook stays on in every run and a cheat rate is reported beside every accuracy figure.
% 中文：由于奖励由策略可直接瞄准的断言计算而来，反作弊钩子每轮开启，并在每个精度数字旁报告作弊率。

\subsection{Stage (v): Preference-Based Domain Adaptation}\label{sec:domain}
Stage~(v) differs from stage~(ii) in two respects, stated explicitly because otherwise the two coincide: the reward is learned from human judgement rather than verified, and the target behaviour is a team's internal conventions---naming rules, layer policies, review checklists---which no public benchmark measures.
% 中文：第 (v) 阶段与第 (ii) 阶段有两点不同（必须明说，否则二者重合）：奖励来自人类判断而非可验证；目标行为是团队内部约定——命名规则、层次策略、评审清单——没有任何公开基准衡量。
We collect pairwise judgements from in-house reviews over the stage-(iv) task families, fit a reward model, and optimise under a KL-regularised objective from the stage-(iv) checkpoint, since preference data is far scarcer than the verifiable signal.
% 中文：我们从内部评审中围绕第 (iv) 阶段任务族收集成对偏好，拟合奖励模型，并从第 (iv) 检查点出发在 KL 正则目标下优化，因为偏好数据远比可验证信号稀缺。
The rationale for a 2.2B core is strongest here and it is a constraint, not a preference: proprietary layouts and preference data cannot leave the premises, so the choice is a small local model or no model at all.
% 中文：2.2B 内核的理由在此最充分，且是约束而非偏好：专有版图与偏好数据无法出内网，所以选择只是「小模型本地」或「根本没有模型」。
Evaluation uses held-out review items scored by expert agreement, reported beside the execution-based numbers so that verified and preference-based adaptation are compared on one system.
% 中文：评测用留出评审条目、以专家一致性打分，并与基于执行的数字并列，使可验证适配与偏好适配在同一系统上比较。
