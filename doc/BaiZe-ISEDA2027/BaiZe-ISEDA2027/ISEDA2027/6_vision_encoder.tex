\section{Vision Encoder Pretraining}\label{sec:vision}

Stage~(iii) pre-trains a custom vision encoder from scratch for the multimodal stage (Section~\ref{sec:mllm}).
This section presents the architecture-selection rationale, the pre-training recipe, and the resulting measurements.

\subsection{Architecture Selection}\label{sec:vis-rationale}
We compare four candidate vision encoders at an iso-parameter $500$--$600$\,M scale, all \emph{randomly initialized} (no upstream ImageNet/CLIP/SigLIP weights) so that only the architecture body is contrasted.
All candidates are trained under a unified stack: \texttt{open\_clip}~3.2.0, a frozen shared text tower (12 layers, width~512, 8 heads, one BPE for all towers), the SigLIP sigmoid-contrastive objective, and a unified 500K subset of LLaVA-OneVision-1.5 (\texttt{imagenet/EN}), at resolution~224 / patch~16 / bf16, learning rate $10^{-3}$ (AdamW, warmup~100 + cosine), seed~1234, batch $32{\times}6$.
The four candidates are:

\begin{itemize}
\item \textbf{OpenVision2} — a pure-attention ViT (width~1024, depth~30, heads~16, MLP~4096), $505.0$\,M parameters.
\item \textbf{MambaEye} — a pure visual state-space model (Vim-style bidirectional SSM, width~1024, depth~40, $d_{\mathrm{state}}{=}16$, expand~2), $534.9$\,M.
\item \textbf{MoE-ViE} — a sparse Mixture-of-Experts encoder (8 experts $\times$ ff~512, top-2 routing), $505.2$\,M total / $222.0$\,M active per token.
\item \textbf{DeepEncoderV2} — an Attention+SSM hybrid (Alternating Attention Mamba blocks), $516.9$\,M.
\end{itemize}

Table~\ref{tab:visarch} summarizes the measured parameter counts and the three hard metrics (loss, training throughput, inference latency), all measured under DP6 on 6$\times$H100 with matched batch and seed.

\textbf{Finding.} Over $5000$--$10000$-step horizons all four architectures converge to $\approx4.45$--$4.47$ loss, with inter-architecture differences $<0.02$ (within multi-seed variance).
Loss is therefore \emph{architecture-invariant} at this scale and token count: at $224/16$ the encoder produces only $196$ tokens, too short for the SSM recurrence or MoE routing to amortize their per-token overhead into a quality gain.
Consequently the architecture choice is driven solely by efficiency, where the pure-attention \textbf{OpenVision2} dominates---$1.47\times$ the training throughput of the next-best (DeepEncoderV2) and $2.7\times$ lower inference latency, and full-SSM MambaEye even stalls at batch~1.

\textit{Methodological note.} Two apparent results in this section are artifacts of the cosine schedule collapsing the learning rate to $\approx10^{-5}$ before the run ends, and we flag both rather than report them.
The first is the ``loss plateau'' of $6.7342$ in a $1000$-step sweep, which continues to $\approx4.45$ once the cosine span is extended to $5000$--$10000$ steps.
The second is the flat $4.9962$ that $lr{=}10^{-3}$ produces in every ablation cell at $3000$ steps: the same run at $lr{=}3\times10^{-3}$ reaches $4.4562$, a gap of $0.54$.
Sub-$1$k-step comparisons, and any $3000$-step comparison at $lr{=}10^{-3}$, are therefore uninformative.

Downstream validation would ideally use task metrics; lacking ImageNet-style class labels we tried a zero-shot text$\leftrightarrow$image retrieval proxy ($R@1/5/10$ on a held-out 5K subset from \texttt{laioncn/EN}, disjoint from the training source).
\textbf{That proxy is degenerate}: $R@1{=}0.0002$, which is exactly chance for $5000$ candidates, and it separates neither learning rates nor architectures.
We report this as a negative result rather than ranking configurations with it, and we note that this stage therefore has \emph{no} working downstream metric---the main limitation of the comparison.
Under the corrected learning rate the resolution/patch sweep is flat: loss varies by less than $0.001$ over $196$--$784$ tokens (Table~\ref{tab:visres}), so loss is genuinely insensitive to resolution and patch in this range, and the earlier all-identical column was a schedule artefact layered on top of a real null result.
The informative signal is throughput, which falls with the token count ($1645 \rightarrow 972$ train img/s from $224/16$ to $448/16$).
One cell is an apparent exception and must not be read as a win: $448/14$ reaches $3.7461$, but the memory guard halved its batch and the SigLIP objective is sensitive to the number of in-batch negatives, so the drop is confounded by the batch rather than attributable to the $1024$-token inputs.
The objective switch (CLIP InfoNCE) yields a different loss scale ($2.894$ vs $4.996$) that cannot be compared without negative-logit calibration.
The learning-rate sweep is the decisive result: raising $lr$ from $10^{-3}$ to $3\times10^{-3}$ / $5\times10^{-3}$ lowers the final loss from $4.996$ to $4.4562$ / $4.4542$, so the original anchor plateau was a schedule collapse rather than a data ceiling.
We therefore report the corrected $lr{=}3\times10^{-3}$ numbers throughout this section; the full reproduction commands are in the companion result report.
