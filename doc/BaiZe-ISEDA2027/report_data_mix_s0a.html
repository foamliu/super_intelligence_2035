1. 这个实验是什么？

一句话：这是 BaiZe 论文 Stage (i) 正式预训练（P-8）之前的 「数据投料配比」搜索实验 —— 用 MiniCPM5 / Xmodel-2 的 WSD（Warmup-Stable-Decay）双阶段配比思路，在小规模代理预算下，搜索 Stable 段（base 主体）与 Decay 段（L3+Math+Code+SFT = 带 SFT 的退火）的最佳数据配比。

1.1 背景：为什么要「做实验定配比」而不是拍脑袋？

BaiZe 的正式预训练采用 WSD 学习率调度，数据分两段喂：

阶段数据源（工作假设）主次用途
Stable（S 段）Ultra-FineWeb(base) · UltraX-Preview · UltraData-Math · UltraData-Code以 web 主体为主模型主体的「常识打底」
Decay（D 段）Ultra-FineWeb-L3 · UltraData-Math · UltraData-Code · UltraData-SFT-2605 · UltraData-SFT-Agent-2609适当配比带 SFT 数据的退火（提升复杂推理）

配比不能凭直觉拍。Xmodel-2 论文（本地 xmodel-2.tex）给了两条关键依据：

依据 ①「小模型配比可迁移到大模型」（xmodel-2.tex:142 引 ye2024datamixinglaws）：在小模型 / 短跑上搜出的配比，可以有效迁移到更大模型 → 所以我们用 2.47B 模型 + 5000 步短跑 搜配比，不必在全量上试，省算力。

依据 ② Xmodel-2 自己跑了 400+ 次试验（xmodel-2.tex:144-154）：把搜索空间收敛到两个问题 —— ① SFT 数据的总体占比（最优落在 60%–69%，实际取 64%）；② SFT 内部的类别分布（Mathematics / Code / Logic / Knowledge / Commonsense 五类）。结论：SFT 数据是喂进预训练 decay 段的，而不是事后再做一遍独立 SFT → decay 段 = 带 SFT 的退火，这模糊了 Stage (i)/(ii) 的边界。

2.1 数据 Blend 的实际写法

Megatron 用扁平 weight/prefix格式指定混合权重（权重是相对值，内部归一化）：

# 4 base shards × 22 = 88（base 88%）+ code 8 + math 4 → 总 100
BLEND="22 ${DATA}/mix_base/mix_base_train_s0 \
  22 ${DATA}/mix_base/mix_base_train_s1 \
  22 ${DATA}/mix_base/mix_base_train_s2 \
  22 ${DATA}/mix_base/mix_base_train_s3 \
  8 ${DATA}/anneal_code \
  4 ${DATA}/anneal_math2"

其中 ${DATA} = /nas_train/app.e0031982/code/BaiZe-ISEDA2027/data。base 分 4 个 shard（s0–s3），每个 ~5.5B tokens，合计 22.05B tokens。

3.3 为什么先跑 Stable 段、再跑 Decay 段？

WSD 的逻辑顺序是 Stable 在前、Decay 在后（先打基础再退火）。配比实验也遵循这个顺序：先把 Stable 段的 base/code/math 三轴搜好（用 Table 2 的 8 个常识集做代理），再搜 Decay 段的 SFT 占比与类别分布（用 Table 3 的 6 个复杂推理集做代理）。S0a 是 Stable 段的第一个点（基线配比 88:8:4），后续 Stable 臂会调 base 内部 shard 权重、code/math 比例做对比。

7. 它最终服务于什么？

Stable S0a 配比实验最终服务于 P-8（正式预训练）的投料配比 —— 即论文 Stage (i) 的配方依据。

BaiZe 论文规划了三个阶段：

Stage是什么数据配比实验的角色
Stage (i)LLM 主体预训练（WSD）配比实验直接服务于此 —— 搜出的 Stable/Decay 配比 = P-8 的投料配方
Stage (ii)领域适配（本季度留白）—（10 月不涉及）
Stage (iii)多模态视觉编码器—（独立线，由 vision agent 负责）

核心逻辑链：

小模型短跑代理实验（S0a 等，2.47B / 5000 步 / 6 卡）→ 两套代理指标实测（Table 2 常识 8 集 + Table 3 推理 6 集）→ 选出最优配比（Stable 的 base:code:math + Decay 的 SFT 占比/类别分布）→ 定稿 P-8 投料配方（写入 DATA_MIX_RECIPE.md）→ P-8 正式预训练（8 卡全量，Stage (i) 主体）→ 论文 Stage (i) 的实验依据（“我们用 Xmodel-2 的配比搜索方法，在小规模上搜出 XX 配比，迁移到正式训练”）

这套方法论的法理依据是 Xmodel-2 引用的 Data Mixing Laws（ye2024datamixinglaws）：「小模型上的配比实验可以有效迁移到更大模型」 —— 所以我们可以在 2.47B / 5000 步的小规模上搜配比，而不必在 P-8 的全量训练上试错，大幅节省算力。

#!/bin/bash
# BaiZe 数据配比实验（§0.6-B）— Stable 段 S0a 臂：base:code:math = 88:8:4
# 口径：6 卡 · TP1/DP6 · seq=4094 · mb=1 · GBS=1020 · 5000 步 · bf16_mixed
# GPU：CUDA_VISIBLE_DEVICES=2,3,4,5,6,7（GPU2-7，data 名下）
set -uo pipefail
BASE=/nas_train/app.e0031982/code/BaiZe-ISEDA2027
PY=/nas_train/app.e0031982/miniforge3/envs/py310/bin
export CUDA_VISIBLE_DEVICES=2,3,4,5,6,7
NAME="mix_stable_s0a"
ITERS=5000  WARMUP=250  DECAY=0  LR="1e-3"  MIN_LR="1e-5"
SAVE_INTERVAL=5000  SEQ=4094  GBS=1020  MBS=1  TP=1  NP=6
# 数据 blend：4 base shards × 22 = 88 + code 8 + math 4
DATA="$BASE/data"
BLEND="22 $DATA/mix_base/mix_base_train_s0 22 $DATA/mix_base/mix_base_train_s1 "\
"22 $DATA/mix_base/mix_base_train_s2 22 $DATA/mix_base/mix_base_train_s3 "\
"8 $DATA/anneal_code 4 $DATA/anneal_math2"
"$PY/torchrun" --nnodes=1 --nproc_per_node="$NP" \
    --master_addr=127.0.0.1 --master_port=29950 \
    pretrain_launcher.py --arch mamba2 --name "$NAME" \
    --train-iters "$ITERS" --global-batch-size "$GBS" --seq-length "$SEQ" \
    --save-interval "$SAVE_INTERVAL" --lr "$LR" --min-lr "$MIN_LR" \
    --lr-warmup-iters "$WARMUP" --lr-decay-iters "$DECAY" --lr-decay-style WSD \
    --seed 1234 --precision bf16_mixed
