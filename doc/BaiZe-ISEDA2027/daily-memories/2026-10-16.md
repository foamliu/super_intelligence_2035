# 2026-10-16 运维日志

## 80B Decay 训练启动

### 背景
- 用户令：在 Xmodel-2.5 稳定末ckpt（step_532000）上用 BaiZe 自定义数据配比 + Muon optimizer 跑 80B decay，目标超越 Xmodel-2.5 final（CS8=65.40% / CX=32.90%）。

### 过程
1. 确认 `emerging_optimizers` v0.5.0a0 已安装，`TensorParallelMuon` 可导入。
2. 验证 Xmodel checkpoint：1.35B params（2.70GB BF16），支持 gradient checkpointing + flash attention 2。
3. 编辑 shell 脚本 `baize_xmodel25_decay.sh`：MBS=2, SEQ=4096, ITERS=20346, grad_accum=60。GPU pre-flight check 因 nvidia-smi/awk race condition 暂时禁用。
4. Python 脚本 `baize_xmodel25_decay_train.py`：`gradient_checkpointing_enable(use_reentrant=False)` + `enable_input_require_grads()`。
5. Smoke test #7 崩溃：`p.grad = p.grad.float()` 导致 TypeError（PyTorch 不允许 FP32 grad 赋给 BF16 param）。
6. 修复：monkey-patch `newton_schulz` 接受 BF16 输入，内部转 FP32 做正交化，结果转回 BF16。删除 `p.grad = p.grad.float()` 块。
7. Smoke test #8 启动成功：步骤 1-2 完成，loss 下降（11.76→11.57），无 TypeError。
8. Smoke test 进展到 step 30/100：loss 11.76→6.55→3.23→2.18，GPU 58.5GB/80GB，util 97-100%，~182K tok/s。
9. Kill smoke test，启动全量训练。
10. 第一次 SSH 启动超时但实际成功（PID 2080678 torchrun + 8 workers）；第二次启动失败 EADDRINUSE（预期，因端口已被第一次占用）。

### 结果
- 全量 80B decay 训练在 .29 上运行中：20346 步，~4.7 天，输出 `xmodel25_baize_80b_decay`。
- commit: `pretrain decay80b: monkey-patch newton_schulz for BF16 compat + smoke test running`

### 关键经验
- Muon + BF16：Newton-Schulz 需要 FP32 内部计算，但不能把 FP32 grad 赋回 BF16 param。解法 = monkey-patch NS 函数做 dtype 转换，保持 grad tensor 原始 dtype。
- SSH `setsid ... &` 超时不代表启动失败：进程在远端继续运行，需用 `pgrep` 确认。
- Sparse file：当文件被第二次 `>` 截断但第一次的 fd 仍在写，会产生 null byte 空洞。读 log 需用 `cat /proc/<pid>/fd/1 | strings | grep '^\[step'`。

## 80B Decay v2 性能优化 + 生产启动

### 背景
- v1 全量训练在 .29 上以 183.5K tok/s 运行至 step 420（21:44），被 SIGTERM 终止（profiling 腾 GPU）。
- 目标：通过 profiling 找到瓶颈，用 recipe-neutral 优化将吞吐从 183K 提升到 249K+。

### Profiling 实验结果
| 配置 | tok/s | 显存/GPU | 备注 |
|:---|---:|---:|:---|
| Baseline (v1) | 184.1K | 58GB | MBS=2, GC ON, no compile |
| MBS=2 + GC OFF | 203.0K | 58GB | 去掉 grad checkpointing |
| + no_sync | 221.2K | 58GB | DDP 延迟 all-reduce |
| + compile default | **299.7K** | **44GB** | kernel fusion, **+62.8%** |
| + compile reduce-overhead | — | — | CUDA graphs 与 Xmodel-2 MLP in-place ops 不兼容 |

**最佳配置**：MBS=2 + no_sync + compile mode=default + GC OFF -> 299.7K tok/s (+62.8%), 44GB (36GB headroom), 11.9s/step。

### v2.py 代码改动
1. `--compile_model` + `--compile_mode` 参数：torch.compile(model, mode=...)，DDP 之前 compile。
2. `--no_ddp_no_sync` 参数：grad accumulation 时用 no_sync() 延迟 all-reduce（默认启用）。
3. `--no_ddp_static_graph` 参数：static_graph=True 与 no_sync() 不兼容，仅当 no_sync 禁用时启用。
4. Checkpoint 修复：save_hf_checkpoint() 中 unwrap OptimizedModule (_orig_mod) 后再调 save_pretrained()。

### v2.sh 生产脚本
- baize_xmodel25_decay_v2.sh：加 --compile_model --compile_mode default。
- seq=3712, GBS=960, MBS=2, ITERS=19980, WARMUP=100, LR=1.67e-3->1e-5 (WSD exp)。
- 投影：~300K tok/s, ~11.9s/step, ~66h 总时长。

### 生产启动 (22:59 on .29)
- 编译预热期 step 0-10 吞吐攀升：63.6K -> 105K -> 134K -> 172.5K -> 225.1K。
- Step 30-40 瞬时吞吐：3,563,520 tok / 11.9s = ~299.5K tok/s（与 profiling 一致）。
- 运行平均（含编译期）：step 40 = 275.7K，持续攀升中。
- GPU 显存：44GB/GPU，util 97-100%。Loss 正常下降：11.58 -> 2.36。
