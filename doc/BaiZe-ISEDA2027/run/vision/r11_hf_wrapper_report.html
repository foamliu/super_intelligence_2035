6. Key Design Decisions

6.1 Why 512 width (not 1024)?

The OpenVision2 class in models.py has a default width of 1024, but the actual ④-4ep checkpoint was trained with width=512. The from_baize_checkpoint() method auto-derives the config from the checkpoint's embedded config dict, so the correct width is always used.

6.2 Why skip spatial merge?

BaiZe's OpenVision2 does not have a spatial merge module. The spatial_merge_size=1 setting means all 196 patch tokens are passed directly to the projector. This is in contrast to RICE ViT in LLaVA-OV1.5, which uses spatial_merge_size=2 to reduce 576 tokens to 144.

6.3 Why load ReadoutHead but skip it in forward?

The checkpoint includes a ReadoutHead (norm + proj, ~0.39M params) used for contrastive learning during pre-training. Loading it with strict=True ensures all 277 keys match. In the MLLM forward pass, only the patch features (output of norm + blocks) are used; the ReadoutHead is bypassed.

6.4 Why a separate 2-layer MLP projector?

In RICE ViT, the PatchMerger inside the vision tower doubles as both the spatial merge and the projector. Since BaiZe has no PatchMerger, we use a separate BaizeMultiModalProjector (Linear→GELU→Linear, 7.87M params) following the standard LLaVA convention.
