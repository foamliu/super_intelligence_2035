BaiZe 视觉编码器 — 外部评审回应综合报告

生成时间：2026-10-12 · 线：vision · 语言：中文 · 性质：纯写作（零 GPU）· 数据来源：MEMORY_VISION.md / EXPERIMENTS_VISION.md §8.3–§9.6

1. 背景与动机

外部评审专家对 BaiZe 视觉编码器基线模型 E1fair 的 ProtB（BaiZe internal protocol）linear-probe top-1 准确率 = 62.34% 提出质疑，认为该数值偏低。为系统性地回应这一质疑，运维侧下发了 ③→①→②→④ 四步复核链路指令：

  • ③ 口径修订：明确绝对 lp 数字所用的评测协议，声明不可与外部方法同表比较的原因
  • ① 同模型 zero-shot 评测：验证冻结文本塔是否带来了实际收益
  • ② probe 对照实验：排查 linear probe 是否存在欠拟合
  • ④ epoch 缩放实验：判断 62.34% 是"预算不足"还是"特征质量天花板"

同时补充了两组变体实验（V2 Muon 优化器、V3 全量数据），以及一份 lp–epoch 曲线图。本报告按时间/逻辑顺序完整呈现全部实验结果与结论。

🎯 一句话总结

62.34% 是 当前数据规模（95.8M 图文对 · 1 epoch）与目标函数（AIMv2-style）下的特征质量天花板——不是评测方法的缺陷，也不是 probe 的欠拟合；将训练 epoch 翻倍（2 epoch）可将 ProtB 提升至 65.37%（Δ+3.03pp），收益中等且呈递减趋势。

所有后续实验均以 E1fair 为基线，除被考察变量外逐字节一致。基线配置如下：

3. ③ 口径修订：为什么 62.34% 不可与外部方法同表比较

3.1 标注规则

凡出现绝对 lp / zs / k-NN 数字，均须标注所用评测协议：

标注含义适用场景
BaiZe internal protocol (ProtB)SGD+momentum0.9+cosine，90ep，mini-batch 1024，IN-1k full train，IN-1k val 50k，IN-1k norm，3 seeds主结果（与主流协议对齐，可与 DINOv2/MAE/iBOT 公开值横比）
BaiZe internal protocol (ProtA)AdamW lr=3e-3，full-batch，100ep，probe 50/类，自切分 val，CLIP norm，seed 0旧实验（R2–R14 消融），相对排序有效但绝对数字偏低 ~10pp
ExternalCLIP zs / OpenCLIP / MAE / DINOv2 / iBOT 等公开报告值🚫 不得与 BaiZe 数字同表

3.2 不可比原因（逐条）

维度BaiZe（本线）外部方法不可比原因
目标函数AIMv2-style：1.0×InfoNCE + 1.0×masked-patch-MSE（双向 ViT + 随机掩码）CLIP = 纯对比学习；MAE/DINOv2 = 纯视觉自监督（无文本塔）；iBOT = dense + self-distill目标函数不同 → 学到的表征空间性质不同 → lp 不可直接比较
数据图文对 95.8M（GPIC + CC12M + Amshaker），1 epochLAION-2B（多 epoch / batch 32k）；IN-1k / LVD-142M（纯视觉）数据量级差 10–100×；数据类型不同（图文对 vs 纯图像）
文本塔冻结 CLIP-ViT-L/14-336（768-d），不解冻 / 不用 LoRACLIP/OpenCLIP = 文本塔端到端训练；MAE/DINOv2 = 无文本塔冻结文本塔限制了对比学习的对齐能力 → lp 上限不同
评测协议ProtA vs ProtB 相差 ~10pp公开 lp 通常用主流协议（≈ProtB）不同协议的绝对数字不可同表；ProtA 比主流低 ~10pp
训练规模~118M 上限（从零训练，1 epoch）AIMv2-L = 12B 样本；DINOv2 = LVD-142M / 多 epoch规模差 100× → 绝对 lp 不可比

结论：BaiZe 的 ProtB = 62.34% 只能与同目标函数 + 同数据量级 + 同 epoch + 同评测协议的内部基线直接比较；与 CLIP / DINOv2 / MAE 等外部方法的绝对数字不可同表。

4. ① 同模型 zero-shot 评测：文本对齐带来了实际收益

将 E1fair 和 E2fair 的冻结 trunk 直接用于 zero-shot 分类（zs，即不训练任何分类器，直接用图文相似度匹配类别），结果如下：

模型zs top-1lp top-1 (ProtB)lp − zs gap
E1fair（w512/d30）34.10%62.34%+28.24pp
E2fair（w768/d30）35.45%62.51%+27.06pp
随机基线0.1%（1/1000）——

关键发现

  • zs 远高于随机（34.10% ≫ 0.1%）→ 视觉特征确实学到了与 CLIP 文本空间的对齐关系，冻结文本塔带来了实质性的语义对齐能力。
  • lp ≫ zs（+28pp）→ linear probe 从特征中提取的判别信息远超直接的文本相似度匹配。这表明 dense reconstruction 目标（masked-patch-MSE）贡献了对比学习本身无法捕获的表征质量。
  • E2fair zs > E1fair zs（+1.35pp），但 lp gap 仅 +0.17pp → 更宽的模型在 zero-shot 文本对齐上有小幅优势，但在 linear probe 上无显著差异。

5. ② probe 对照实验：62.34% 是特征质量天花板，非 probe 欠拟合

5.1 k-NN probe

k-NN（k 近邻）是无需训练的纯特征质量度量。将 E1fair 特征用于 k-NN 分类：

probe 类型E1fair top-1V3 top-1vs lp (E1fair 62.34%)vs zs (E1fair 34.10%)
k-NN (k=5)35.63%35.63%−26.71pp+1.53pp

k-NN（37.68%）< lp（62.34%）属正常现象（高维特征中线性分类器远强于最近邻）；k-NN > zs（37.68% > 34.10%）确认特征空间具有合理的类结构。

5.2 ProtB probe sweep：×5 epoch + wd/Lr 扫描

为排查 90-epoch probe 是否欠拟合，我们系统性地扫描了 6 种 probe 配置：

配置E1fair top-1Δ vs 基线 (62.33%)解读
基线（90ep, lr=0.1, wd=0, seed=0）62.33%—与注册值 62.34±0.01% 一致
×5 epoch（450ep, lr=0.1, wd=0）62.15%−0.18pp训练 5 倍 epoch 反而略降（轻微过拟合）
wd=1e-4（90ep, lr=0.1）62.68%+0.35pp边际改善，在噪声范围内
wd=1e-3（90ep, lr=0.1）61.25%−1.08pp正则化过强
lr=0.01（90ep, wd=0）62.39%+0.06pp基本相同
lr=0.3（90ep, wd=0）60.39%−1.94pp学习率过高，发散

② 结论（决定性）

  • ×5 epoch（450ep）= 62.15% < 90ep 基线 62.33%：训练 5 倍 epoch 反而略降 → probe 不存在欠拟合，90-epoch ProtB probe 已充分收敛。
  • wd/LR 扫描：无任何配置比基线高出 >0.35pp（最佳：wd=1e-4 → +0.35pp，在 1.5pp 噪声阈值内）→ probe 配置接近最优。
  • 总结论：62.34% 是真实的特征质量天花板，不是 probe 的限制。瓶颈在特征质量（即目标函数与数据规模），不在评测方法。

6. 变体实验：V2 Muon 优化器 与 V3 全量数据

6.1 V2 Muon 优化器：❌ 所有测试 LR 下均坍缩

尝试LR坍缩步数坍缩时 C1根因
第 1 次5e-4step 2,1000.99Muon 正交化放大对比坍缩方向
第 2 次1e-4（误报）—C2 guard bug（gap<=0.005 在负 gap 时误触）→ 已修为 abs(gap)<=0.005
第 3 次1e-4step 4,2000.9569真实坍缩（与第 1 次同模式，但更慢）

C1 轨迹（第 3 次，lr=1e-4，14 个 PROBE 点，零回退）：

step 300→0.18, 600→0.18, 900→0.23, 1200→0.32, 1500→0.44, 1800→0.60, 2100→0.74, 2400→0.82, 2700→0.86, 3000→0.89, 3300→0.92, 3600→0.93, 3900→0.95, 4200→0.9569

  • C1 上升单调且加速（0.18→0.96，3,900 步内）
  • 坍缩时 loss 仍在下降（7.39→7.30）——排除了优化失败（梯度爆炸/NaN），指向表征坍缩
  • 5× 降 LR 仅将坍缩步数从 2,100 延缓到 4,200，终点相同
  • 根因：Newton-Schulz 正交化强制梯度为单位范数，放大了主导坍缩方向；AdamW 的逐参数自适应缩放天然抑制了这一效应

裁定：❌ Muon 与 AIMv2-style 对比+重建目标函数不兼容。Δlp 无法计算（坍缩后 C1=0.9569 → 特征趋近常数 → lp≈随机）。已终止评测以释放 GPU 供 V3 使用。

7. ④ epoch 缩放（核心发现）：2 epoch → ProtB 65.37%，收益中等

7.1 实验设计

问题：E1fair ProtB=62.34% 是预算不足还是特征/目标函数天花板？

设计：与 E1fair 同数据/目标/协议/调度，仅增加 epoch 数。E1fair = 1 epoch（187,101 步，95.8M 对）；④-2ep = 2 epoch（374,202 步）。若 2ep ≥ 70%（Δlp ≥ +7.66pp）则启动 4ep；否则报告为"中等收益，递减"。

字段值
测试变量epoch 数：1 → 2
④-2ep 步数374,202（= 2 × 187,101）
数据E1fair 冻结快照（total_shards=10,787，95.8M 对，非 V3 全量数据）
调度lr=5e-4, warmup=2000, cosine, min_lr=5e-5（与 E1fair 相同）
其余配置与 E1fair 基线逐字节相同（AdamW, seed 1234, w512/d30, 224/p16, AIMv2-style）

7.2 训练状态

✅ 训练 + 全量评测完成（2026-10-11 18:25 → 10-12 13:42）：

7.4 预注册裁定

裁定区间条件含义
正面Δlp ≥ +7.66pp（lp ≥ 70%）预算不足 → 启动 4ep
中等（MODERATE）Δlp +1.5~7.66pp有收益但递减 → 不启动 4ep（除非运维要求）
零结果|Δlp| < 1.5pp1 epoch 足够 → 特征/目标函数是瓶颈
负面Δlp ≤ −1.5pp更多 epoch 有害（过拟合）→ 保持 1 epoch

🎯 裁定结果：MODERATE（中等收益）

Δlp(ProtB) = +3.03pp，落在预注册的 +1.5~7.66pp 区间内 → "有收益，但呈递减趋势"。

决策：不启动 4 epoch 训练（除非运维明确要求）。2 epoch 的 +3.03pp 增益虽真实，但边际收益递减（从 1→2 ep 获 +3.03pp，推测 2→4 ep 增益将更小），不值得 ~160 GPU·h / ~20h 的额外成本。

10. 结论与下一步

对外部评审的完整回应

外部评审质疑 E1fair ProtB=62.34% 偏低。经 ③→①→②→④ 四步系统复核，结论如下：

  1. ③ 口径：62.34% 标注为 BaiZe internal protocol (ProtB)，与外部方法因目标函数/数据/文本塔/评测协议/训练规模五维不同而不可同表比较。
  2. ① zero-shot：E1fair zs=34.10% ≫ 随机 0.1% → 冻结文本塔带来了实质对齐收益；lp−zs gap +28pp → dense reconstruction 目标贡献了对比学习之外的表征质量。
  3. ② probe：×5 epoch（450ep）= 62.15% < 90ep 基线；wd/LR 扫描最高 +0.35pp → probe 不存在欠拟合 → 62.34% 是真实的特征质量天花板。
  4. 变体：V2 Muon 全 LR 坍缩（与 AIMv2-style 不兼容）；V3 全量数据 +1.18pp → Null（不可分辨）。
  5. ④ epoch 缩放：2 epoch → ProtB 65.37%（Δ+3.03pp），四指标一致 +3~4.4pp → MODERATE（有收益但递减）→ 不启动 4ep。

最终判断：62.34% 是当前数据规模（95.8M · 1ep）与目标函数（AIMv2-style）下的特征质量天花板。增加训练预算（2 epoch）可获得 +3.03pp 的中等收益，但边际递减；换优化器（Muon）不可行；加 7.6% 数据不可分辨。瓶颈在数据规模与目标函数，不在架构、评测方法或 probe 配置。
