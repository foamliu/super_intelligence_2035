D2 · 对 cline 的改进机会点（摘要）

完整四段式（① 其它 harness 做法 → ② cline 现状 → ③ 差距 → ④ 建议+收益+风险+优先级，均贴 路径:行号）见 harness/CLINE_IMPROVEMENT_OPPORTUNITIES.md。

可直接借鉴 O1 · 线1 注入/投影 —— 补单一 memoized 归一化终点 + 全链路 Telemetry

其他（claude-code）getSystemContext/getUserContext memoize + normalizeMessagesForAPI 收口；cline 现状 = 每请求重走 MessageBuilder（message-builder.ts:105-107）+ 自认的投影旁路 Telemetry 盲区（compaction.ts:251-254）。→ 收口投影 + 补齐埋点。

需架构改动 O2 · 线2 检查点 —— 把文件快照与压缩状态收进同一原子事务

其他（deepseek）事件流「重放即回滚」/（codex）单事务 Rollout + window_id 链；cline 现状 = git checkpoint + 独立 sidecar 双事实源（checkpoint-hooks.ts:16-26，PR#12747 的 bug 根源）。→ 消除「sidecar 与文件状态不一致」整类 bug。

可直接借鉴 O3 · 线3 Hook —— 补 PreCompact/PostCompact 压缩生命周期 Hook

其他（claude-code）HOOK_EVENTS 27 个显式含 PreCompact/PostCompact（coreTypes.ts:25-53）；cline 现状 = 7 回调 + prepareTurn（agent.ts:374-402/485）无压缩 Hook。→ 直接回答「Auto Compact 能否插件化」= 能观测/干预、不能替换核心。

需架构改动 O4 · 线4 焦点链 —— 补回任务目标/记忆持久层，解耦长期目标与可压缩对话

其他（claude-code）TodoWrite + Session Memory + auto-memory（TodoWriteTool.ts:65-94 等）；cline 现状 = Focus Chain 已移除（task-proxy.ts:144「stub — focus chain removed」）。→ 压缩后进度不丢、跨会话记忆复用。

可直接借鉴 O5 · 线5 模型适配 —— token 计量改「服务端 usage 优先 + 保守兜底」

其他（codex）AutoCompactWindowPrefill{ServerObserved,Estimated}（auto_compact_window.rs:24-30）+ 压缩为降级闸门；（claude-code）tokenCountWithEstimation（tokens.ts:226）；cline 现状 = 纯 3 字符/token（tokens.ts:8）、无窗口信息返回 undefined（compaction-shared.ts:67-68）→ 正面撞 Issue #7772。→ 阈值准确、本地模型不踩 128K 假窗口。

🔑 共同结论（五份分析的收敛点）：「状态 ≠ 文本」 —— 五个 harness 不约而同把「意图/目标/环境快照」放进不可压缩的侧表，只让「对话文本」进可压缩历史；且「压缩引擎」几乎都硬编码在核心、「观察与外围改写」才开放给 Hook。这正是 BaiZe/ZhuLong「情境化观测保真度」论点在工程层上的体现。
