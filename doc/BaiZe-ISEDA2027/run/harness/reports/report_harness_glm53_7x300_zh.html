④.3 对「passrate 低主因是模型能力」判断的影响

此前（2026-10-13 why-low-passrate 报告）判断「passrate 低主因是模型能力（非 infra）」， 依据是 fix3/fix4 修复后 0-flip → 排除了基础设施因素。本轮用「更强的」glm-5.3-flash 重测， 预期若能力是主因，则换强模型应带来显著提升。

实测结果：passrate 基本持平（27.2% vs 27.3%）， McNemar p=0.688 不显著。这意味着：

  • kimi-k2.6-cloud 与 glm-5.3-flash 可能处于相近的能力档位，两者间的差异不足以撬动 SWE-bench Lite 的通过率——「换一个同级/略强的 API 模型」不是有效的提分手段。
  • 真正能显著提升 passrate 的杠杆，更可能在更大幅度的能力跃迁（如顶级闭源模型）、或harness 工程改进（更深的 repo 探索、更好的定位/验证策略、更稳健的 patch 生成）上。
  • 注意：这不否定「能力是主因」——它说明的是这两个特定模型间的能力差不足以体现。要证实/证伪，需引入能力差距更大的模型做对照。
