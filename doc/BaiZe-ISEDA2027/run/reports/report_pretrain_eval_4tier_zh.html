🔬 生成退化诊断（#1984 · 2026-11-11 18:10 · curl 直查 llama-server port 8083）

核心发现：模型的首 token logit 正确（L1 MCQ 正常、"2+3=5" → 首 token="5"✅），但多 token 自回归生成时 SSM 状态崩溃，退化为重复"1"×200+。repeat_penalty=1.3 可部分打破循环，暴露出零星连贯英文。
探测prompttemp输出诊断
1. GSM8K"Q: Natalia sold clips..."0 greedy" The video111111..."(重复1×200+)🔴 退化
2. 简单加法"What is 2+3? Answer:"0 greedy" the111 2nd333..."(首token="the"→退化)🔴 退化
3. 代码生成"def fibonacci(n):..."0 greedy"/examples111111..."(重复1×200+)🔴 退化
4. True/False"True or False: 2+3=5. The answer is "0 greedy"5"(✅正确!)→"th century"(退化)🟡 首token✅
5. 知识问答"The capital of France is Paris. The capital of Japan is "0 greedy"50xxxx111"(错误→退化)🔴
6. temp=0.7"What is 2+3? Answer:"0.7" Would it was easier than the obese?..."→"111..."🔴 先连贯后退化
7. repeat_penalty"What is 2+3? Answer:"0, rp=1.3"...The simplest possible way to solve this problem..."(✅连贯英文!)🟡 rp打破循环
诊断结论：
① 首 token logits 正确：L1 MCQ 58.13%（正常），"2+3=5"→首token="5"✅ → 模型权重/加载/分词无误
② SSM 状态在多 token 生成时崩溃：2-5 token 后退化为重复"1" → Mamba2 recurrent state 未正确维护
③ repeat_penalty 可部分修复：rp=1.3 打破"1"循环后模型能生成连贯英文 → SSM 状态并非完全损坏，而是陷入"1"吸引子
④ HF transformers 无法 CPU 验证：causal_conv1d_cuda 仅支持 CUDA → 无法在 CPU 上对比 HF vs llama.cpp 生成质量
⑤ 双重根因：模型能力不足(26% code+math，远低于 60% 最优)+ llama.cpp SSM 生成路径可能放大退化
建议（待用户拍板）：① 生成评测加 repeat_penalty=1.1-1.3（可能小幅改善 L2 分数）；② 等 GPU 窗口用 vllm/sglang 对比 HF 生成质量；③ decay 阶段混入 4:2:4 数据改善模型基础生成能力
