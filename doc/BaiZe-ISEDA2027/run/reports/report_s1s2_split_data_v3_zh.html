§0 — S2 零重叠方案（新增 · 基于 overlap 研究）

来源: reports/report_s2_data_overlap_study.md（455 行 / 6 方案 / Megatron 源码逐行分析）
用户原话: 「blend TSV 时会确保 S1 训练过的数据不会混入，对吧」「这个问题你不要轻率的回答」

0.1 现状：当前 blend 机制是否排除 S1 已训数据？

结论：否。Megatron 的 GPTDataset 使用固定 random_seed=1234（见 common.env）生成 shuffle_index。S2 如果使用与 S1 相同的 7 个数据源且不修改随机种子，则 S2 将以 ~83-100% 的概率重复采样 S1 已看过的文档——相同种子 + 相同文档池 → 相同排列 → 相同前缀。

0.2 六方案评估摘要

方案描述重叠率可行性实施成本结论
Ashard 级排除（S1 用 0-7，S2 用 8-15）~0%❌ 不可行低S1 已用全部 shard，无剩余可分
B样本级排除（记录 S1 消费 sample index）~0%❌ 不可行极高Megatron 无跨 run 消费追踪，需深度改源码
C完全换源（S2 全用新数据源）~0%❌ 不可行—无 Web 替代源（en_v1_4 2237B 是唯一 web 主体）
D补新源（stack-v3 + MegaMath + Nemotron + finemath 天然零重叠）新源 0%✅ 已实施低新源不在 S1 blend 中 → 天然零重叠，占 S2 总 token ~28%
E换随机种子（S2 设 SEED=5678）~30%✅ 推荐实施极低（5 分钟）将旧源重叠从 ~83-100% 降至 ~30%
D+E推荐组合方案~12%✅ 推荐低新源 0% + 旧源 30% → 累计总重叠 ~12%（可接受，累计 epoch <1.2）

0.3 推荐操作（D+E 组合）

  1. S2 设置 SEED=5678（在 common.env 中修改，5 分钟即可完成）→ 旧源 shuffle_index 与 S1 不同 → 重叠从 ~83-100% 降到 ~30%
  2. 确认 S2 blend TSV 包含 stack-v3 + MegaMath + Nemotron-CC-Math + finemath + MegaMath-web（已在 PC-4 blend_s2_preblend.tsv 中落盘 main 版，12 源 / prop=1.0 / web40:code40:math20 / gen_blend.py --verify 通过）→ 新源天然零重叠
  3. S2 启动前清理旧缓存 .npy 文件（因 SEED 变更，shuffle_index 缓存需重新生成）
  4. 累计 epoch 影响：补新源后累计 epoch — Web 0.67 / Code 0.88 / Math 0.77（均 <1.2 ✅）。如完全排除 S1 数据，code_l2/l3 剩余量不足 → 证明完全排除不可行

§1 — 最终配比表（S2 shard 级 blend TSV）

1.1 设计原则

  1. web:code:math = 4:4:2 严格满足（各类别 prop 加和 = 目标值，总 prop = 1.0）
  2. 优先使用预训练语料（非 SFT）—— SFT 推理链数据留给 decay 段或 post-train
  3. Code 混合 3 源（UDC L2 + UDC L3 + stack-v3 L4 filtered）增加多样性、降低单源 epoch
  4. Math 混合 6 源（UDM L1 + UDM L3 + MegaMath Batch1 + MegaMath-web + Nemotron-CC-Math + finemath）增加多样性 [v3 新增 Nemotron + finemath + MegaMath-web]
  5. Web 以 en_v1_4 为主体，少量 L1-HQ + ZH 补充（与 S1 一致，保持连续性）
  6. 每源累计 epoch（S1+S2）控制 < 1.2，避免过拟合
  7. S2 换 SEED=5678（见 §0），降低与 S1 的样本重叠 [v3 新增]
