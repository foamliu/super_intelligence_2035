§1 — 最终配比表（S2 shard 级 blend TSV — 已落盘）

1.1 设计原则

  1. web:code:math = 4:4:2 严格满足（各类别 prop 加和 = 目标值，总 prop = 1.0）
  2. 优先使用预训练语料（非 SFT）—— SFT 推理链数据留给 decay 段或 post-train
  3. Code 混合 3 源（UDC L2 + UDC L3 + stack-v3 L4 filtered）增加多样性、降低单源 epoch
  4. Math 混合 4 源（UDM L1 + UDM L3 + MegaMath + finemath）增加多样性
  5. Web 以 en_v1_4 为主体，少量 L1-HQ + ZH 补充（与 S1 一致，保持连续性）
  6. 每源累计 epoch（S1+S2）控制 < 1.2（megamath 单源 1.69 为新数据首训，过拟合风险低于重复数据；Nemotron 分词完成后下调）
  7. 新源天然零重叠：stack-v3（430.7B）+ MegaMath（64.97B）+ finemath（9.4B）均不在 S1 blend 中，与 S1 零重复

§8 — S2 零重叠方案（基于 overlap 研究报告）🆕 v3 新增

本节基于 report_s2_data_overlap_study.md（455 行 / 6 方案 / Megatron 源码逐行分析）。用户令 2026-11-18：「blend TSV 时会确保 S1 训练过的数据不会混入，对吧」「这个问题你不要轻率的回答，可以下发给 data，请他研究一下。」

8.1 核心结论

当前 blend 机制不会排除 S1 已训数据。 Megatron 的 GPTDataset 使用固定 random_seed=1234 生成 shuffle_index，相同种子 + 相同文档池 → 相同排列 → 相同前缀。S2 如果使用与 S1 相同的 7 个数据源且不换种子，则 S2 将以 ~83-100% 的概率重复采样 S1 已看过的文档。

8.2 重叠率分析

S2 token 来源S2 占比与 S1 重叠（同种子 SEED=1234）与 S1 重叠（换种子 SEED=5678）
7 个共享源（旧数据）72%~35% → 25.2% of S2~17% → 12.2% of S2
stack-v3（新数据）17%0%0%
MegaMath + finemath（新数据）11%0%0%
S2 总体重叠率100%~25.2%~12.2%

同种子重叠 = min(S1比例, S2比例)（相同 shuffle 前缀）。换种子重叠 = S1比例 × S2比例（独立随机采样的期望交集）。

8.3 六方案评估

方案原理可行性效果结论
A. Shard 级排除S1 用 shard 0-7，S2 用 shard 8-15❌ S1 已用全 16 shard不可行排除
B. 样本级排除记录 S1 消费的 sample index，S2 排除🟡 理论可行，实现复杂可完全排除排除（时间不允许）
C. 完全换源S2 全部用新数据源❌ 无 Web 替代源不可行排除
D. 补新源 ⭐S2 补入 stack-v3 + MegaMath（天然零重叠）✅ 已实施28% of S2 零重叠采用
E. 换种子 ⭐S2 设置 SEED=5678✅ 5 分钟工作量旧源重叠 ~35%→~17%采用
F. 部分排除仅 code/math 做 shard 排除，web 不排除❌ S1 已用全 shard不可行（同 A）排除

8.4 推荐方案：D + E 组合

采用方案 D（补新源）+ 方案 E（换种子）的组合：

  1. 配比方案（D）：沿用 S2 blend TSV（4:4:2），补入 stack-v3-train（430.7B）+ MegaMath（64.97B）+ finemath（9.4B）作为新数据源 → 天然零重叠，占 S2 的 28%
  2. 换种子（E）：为 S2 设置 SEED=5678 → 旧源重叠从 ~35% 降到 ~17%
  3. 不需要复杂排除机制：预训练规模（2.94T tokens）下，12% 文档级重叠不会造成过拟合（远小于 1 个 epoch 重复）

S2 总体重叠率：~12.2%（换种子后），其中 28% 确定不与 S1 重复（新源），72% 中 ~17% 有重叠（旧源随机交集）。S2 有 ~88% 的 token 不与 S1 重复（72% × 83% 未重叠 + 28% 新源）。

8.6 为什么不做更复杂的排除？

考量分析
预训练 vs SFT 容错差异预训练阶段同一文档被看两次影响远小于 SFT；LLaMA/DeepSeek/Qwen 预训练普遍 1-3 epoch 重复
累计 epoch 均 <1.2补新源后所有源 S1+S2 累计 ≤ 1.15（code_l2 最高），15% 文档被看两次在可接受范围
时间约束S2 ~11-27 启动（距当前 ~8 天），样本级排除需改 Megatron 源码 + 测试，时间不允许
ROI换种子（5 分钟）已将重叠 ~25%→~12%；样本级排除（数天）仅再降 ~12%，ROI 极低
业界惯例DeepSeek-V2/V3、Qwen2.5 等预训练阶段均未实现跨阶段样本排除；换源+换种子+控制 epoch<1.5 是标准做法

8.7 完全排除不可行的证据

如果完全排除 S1 已训数据，code_l2 和 code_l3 的剩余量不够 S2 需求：code_l2 需 264B 但剩余仅 201B（差 63B），code_l3 需 73B 但剩余仅 70B（差 3B）。这进一步证明了完全排除不可行，必须补入新数据源（stack-v3 填补 code 缺口）。
