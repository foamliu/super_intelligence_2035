2. 问题从哪来（溯源）

这条强化线不是凭空起的，而是被真实评测缺口逼出来的。在「把 Qwen3.5-2B 封装成 VQA tool 给 designflow 线做波形题」的探针实验（用户令 #3 后半，wake#1227/#1228）中，我们用 designflow 公开的波形参数在本机重生成忠实副本 PNG，让 Qwen3.5-2B 逐量回答，按 designflow 容差判 pass/fail。结果发现一个稳定模式：

Qwen3.5-2B 原生视觉语言（VL）能力能「看懂图是什么」，但「读不准图上的数」。

  • 探针实测：6 个 designflow 恢复后用例合并 14/46 = 30.4%（round-1 β9/α4/β10 = 6/22 = 27.3%；round-2 a1/b8/b11 = 8/24 = 33.3%），而基线（纯文本、无多模态）= 0/46（designflow r650–r655 已证全 FAIL、无 submit.zip 产出）。
  • 答对的项集中在：分类标签（信号类型 square/sine/...）、轴标签单量（峰值电压 = 坐标轴刻度）、约束筛选（多脉冲 / 单脉冲判定）。这些只需「认出图的整体形态」。
  • 答错的项集中在：
    • 精确计数：如激活脉冲数 GT=5 模型答 54、时钟周期 GT=1ns 答 2ns、过渡次数 GT=2 答 0；
    • 精确数值：如占空比、峰峰值读成阈值线值而非曲线值；
    • 跨面板反推：β10 题需由底板 v(det) 的翻转时刻反推顶板 v(temp) 的上下阈值 vth_high/vth_low/迟滞 hysteresis，三项全 fail。

数据源：vision/vqa_tool/restored_probe_results.json（round-1）、restored_probe2_results.json（round-2）。说明：探针图据 designflow 公开参数重生成，与 designflow 等价但非字节相同，属能力探针而非官方通过率。

这个缺口意味着：单纯拿模型「看图」不够，得让它学会「从坐标轴读出数值」这道中间工序。这正是本报告要解决的问题。

3. 方法：为什么是「推理链」

3.1 v1 为什么失败（plain target，wake#1209）

第一版（v1）的 SFT 监督目标只给最终答案（如 "3"、"75"），分类/比较/上升沿类技能提升明显，但三个回归类技能反而变差：amplitude_read 40%→20%（SFT 反降）、duty_cycle 0%→0%（无改善）、cycle_count 80%→66.7%（SFT 反降）。v1 的 RFT 对 SFT 的 McNemar 检验 b=2, c=0, p=0.5，未达 p<0.05 判据，按预注册如实判为负结果。

诊断假设：v1 的 target 只告诉模型「答案是多少」，没有教它「怎么从坐标轴把数读出来」。模型本就看得见图，缺的是这道读数中间过程。

3.2 v2 的单一变量（预注册）

v2 相对 v1 只改一个变量：把 cycle_count / amplitude_read / duty_cycle 三个回归类技能的 assistant 监督目标，从「裸答案」改成「读数推理链 + Final Answer: X」；分类 / 比较 / 上升沿三类 target 保持 v1 原样。举例如下：

  • cycle_count：「Counting complete oscillations from left to right across the plot, I can see 3 full waveform cycles. Final Answer: 3」
  • amplitude_read：「The grid has 1 division per square. The peak is 3 divisions above the center axis and the trough is 3 divisions below it, so the peak-to-peak amplitude is 2 × 3 = 6 divisions. Final Answer: 6」
  • duty_cycle：「A square wave's duty cycle is the fraction of each period spent high. Here the high portion takes 25 percent of one period, so the duty cycle is 25%. Final Answer: 25」

这样改的意图：把「读数」拆成可学习的显式步骤（认网格 → 量半幅 → 算峰峰值 / 认高电平占比），让模型不再跳过坐标轴直接猜数。

3.3 防泄漏设计（由构造保证，不是事后过滤）

  • 训练集：合成波形图 + 问答，随机种子 seed=20261114，每技能 25 条共 150 条（vision/vqa_tool/sft_cot.jsonl）。
  • 评估集（held-out）：用不同的随机种子 seed=20261115 重新合成 30 题（每技能 5 题）。
  • 由于两套种子不同，评估图与训练图无重叠，cheat_rate = 0 由构造保证，不是靠事后比对过滤出来的。

强化栈：LLaMA-Factory + LoRA，CPU 可跑（本线无 GPU 争用）。基模 Qwen3.5-2B 原生多模态 VL，VQA 服务起在 127.0.0.1:30001。

5. 诚实性声明（必写）

  1. scope 限定：本结论仅适用于合成波形识图。训练 / 评估数据均由 synth_waveform_qa.py 程序化合成（正弦/方波/锯齿/三角 + 可控占空比/幅值/周期/上升沿）。不可外推到 designflow 真实 EDA 波形（真实波形含噪声、多信号叠加、不规则面板），需 #3 跨线对照验证。
  2. 跨面板反推仍待解：探针 β10 题需由底板信号翻转时刻反推顶板阈值（vth_high / vth_low / hysteresis），三项全 fail。本合成数据集未覆盖「跨面板反推」技能，故 v2 也未触及该缺口。
  3. 探针图非官方：#3 后半探针的波形图是据 designflow 公开参数在本机重生成的忠实副本，与 designflow 等价但非字节相同，30.4% 是能力探针值，不可当作 designflow 官方通过率。
  4. RFT 选择偏差：rejection-sampling FT 从 600 个采样（每题 k=4）中按 reward ≥ 0.5 接受 207 个（接受率 34.5%）。被接受的样本天然是模型「已能做对」的，RFT 会对「能做对但偶尔做错」的题更有效，对「完全不会」的题帮助有限——这是 RFT 的固有性质，解读 +25.6pp 时应计入。
  5. RFT 单 seed：v2-RFT 仅跑了 seed=11（90.0%）；v2-SFT 跑了 3 seed。预注册判据只要求 SFT ≥3 seed + RFT 显著性，已满足；但 RFT 的种子稳定性尚未单独验证。

7. 下一步与可复用价值

7.1 这套「CoT 读数推理链」能否迁移

本实验的真正贡献不是「某个合成数据集上 90%」，而是验证了一个可迁移的方法论：当多模态模型的失败模式是「看得见图但读不准数」时，把「从坐标轴 / 刻度 / 比例尺读出数值」这道隐式工序写成显式推理链放进监督目标，比只给裸答案有效得多。这一思路可外推到其他「读数类」任务：示波器截图读电压/时间、电路图读器件参数、眼图读张度/抖动、散热曲线读阈值——只要能程序化合成带真值的训练样本，就能复制这套 SFT(CoT) → RFT 流水线。

7.2 对 #3（与 designflow 官方对照）的意义

探针已证明 Qwen3.5-2B 在真实波形题上「读不准数」。下一步应把 v2 强化后的 adapter 接回 VQA tool，在 designflow 恢复原形态的同一批用例上重跑「无 VQA vs 有 VQA(强化后)」对照，量化「读数推理链」对真实 EDA 波形的增益是否仍成立（预计对「单面板精确数值」类有效，对「跨面板反推」仍无效——后者需新技能与新数据）。

7.3 对 #4 后续强化的意义

v2 闭合了 v1 在 duty_cycle / amplitude_read / cycle_count 上的缺口，但留下两个明确的未解项：(a) 跨面板反推（β10 全 fail）需新建合成数据集，训练「由一面板事件反推另一面板阈值」的推理链；(b) 真实波形噪声鲁棒性需在合成时加入噪声/多信号叠加，验证 CoT 推理链在非干净波形下是否仍稳。这两点是比「再刷几个点」更有价值的下一步。
