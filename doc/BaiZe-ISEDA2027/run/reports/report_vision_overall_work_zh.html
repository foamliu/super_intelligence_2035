4.3 方法学诚实结论

VQA 对 code_gen 的适用性（让实验说话）：code_gen 类题的波形数据是文本文件（如 v_dq_A.txt），编码 agent 可用 read 工具直接读文本做测量，不需要把波形当图像看；又 VQA 服务器在 .17 只能读 .17 路径，36.15 工作目录文件它看不到。故对 code_gen 文本波形题，VQA-vision 在机制上不适用——试点 4 道上 V0=V1=V2=2/4（VQA 可用但对文本波形题 N/A，未带来通过率变化）。MLLM-as-VQA 的通过率增益集中在 image_reading 子队列（只有 PNG、无原始数据文本的题，VQA 直接产出被判分的读数）。这正是用户「让 V0 vs V1/V2 实验说话」要检验的。

6.2 根因与整改（worktree 隔离 git 推送协议）

历史 push/rebase FAILED 的根因：旧 git_sync_and_push() 在共享树直推 + pull --rebase --autostash，多线共享 origin 下反复 non-ff 拒绝 / rebase 冲突；白名单仅 8 条路径（缺口 ≈ 417 个产出文件）。整改把推送改为worktree 隔离：

位置旧实现（硬伤）新实现（worktree 隔离）
rebase共享树 git pull --rebase --autostash（运维协议禁项：→别线冲突）共享树不再 rebase；rebase 只在隔离 worktree 内
push共享树直推（origin 被各线前进→non-ff 必拒）detached worktree 内 push origin HEAD:main（fast-forward，5 次 fetch+rebase 重试）
白名单仅 8 条路径（缺口 ≈ 417）补全至 13 段（含 baize_posttrain_*/bpt_*/posttrain_*/rca_*/reports/report_posttrain_*/reports/archive/posttrain/*）
