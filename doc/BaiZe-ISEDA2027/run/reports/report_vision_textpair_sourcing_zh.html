TL;DR — 核心发现

  1. 已下载数据未用 = 格式不兼容 + 无人接管线：2026-10-13 下载的 4 路图文对（WebMix-38M 38.8M 对、wit_base 6.48M 对、InternVL-SA1B 22.4M 对、the_cauldron 1.9M 对）全部在盘上且 0 incomplete，但 vision 训练管线 data.py::build_mixed_loader 只读 webdataset tar 格式。WebMix/wit_base 是 parquet（需转码或加 parquet reader），InternVL-SA1B 是 tar（可直接读但从未接入），the_cauldron 是 VQA 格式（非简单图文对）。
  2. 零成本即可扩 ~28M 对：InternVL-SA1B（22.4M 对，tar 格式，已在盘上）只需在训练脚本中加一行路径即可接入。若再加 parquet reader（约 20 行代码改动），WebMix-38M（38.8M）+ wit_base（6.48M）也可立即解锁。
  3. 中文图文对的最大两个源均非商用许可：Wukong（100M 对）和 TaiSu（166M 对）都是 CC-BY-NC-SA-4.0。商用可用（CC-BY-4.0）的 LAION-Chinese 仅 2.66M 对且为 URL 形式（需爬图）。
  4. TaiSu 是最可落地的中文源：HF 上 Ajax102/Taisu 为 webdataset tar 格式、image bytes 内联、中文 caption、166M 对、~7.9TB。非商用许可，但研究用途可用，且格式与现有管线完全兼容（零转码）。
  5. EDA/版图/电路类图文对在 HF/ModelScope 上未找到。领域多样性的最佳补充是 DocVQA/ChartQA/PlotQA（文档/图表/数据可视化），但有格式改造成本。

1.2 下载了却没进训练——逐项归因

数据集是否进了训练？原因证据出处
WebMix-38M未进格式不兼容：3886 个 parquet 文件，但 vision 训练管线 data.py::build_mixed_loader 只支持 webdataset tar（--data-source wds）。需加 parquet 直读分支（~20行代码）或转成 tar（需 >=2.3TB 余量）。ARCHIVE_OPERATOR_VISION.md L2198: "parquet 需转换"; L2205-2206: 方案A加parquet reader / 方案B转tar
wit_base未进同上：330 个 parquet，同样格式不兼容。同上 L2199
InternVL-SA1B未进格式兼容但从未接入：2000 个 webdataset tar，可直接读，但 R11 系列实验的基线臂只用 CC12M+Amshaker（约18.5M），没有把它加入 --data-source 路径列表。属于「能接但没人接」。同上 L2200: "tar (wds) 直读"; R11-E/F/G实验配置(L367-368,L227)均只列CC12M+Amshaker
the_cauldron未进格式不匹配：50个子集(ai2d,aokvqa,chartqa,docvqa,clevr等)，是VQA/SFT格式(image+multi-turn QA)，不是简单(image,caption)对。需要提取/改造成(image,text)对才能用于对比预训练。同上 L2200: "VQA/SFT格式"; 目录实测: ai2d/ aokvqa/ chart2text/ chartqa/ clevr/ ...
GPIC部分用了R11-E臂B使用了GPIC short子集(约10.9M对,从1926 tar提取)，与CC12M+Amshaker基线做了同N对照。但全量8000 tar(约40.5M对)未全部用于训练——R11-E因「可比区间窄」被暂停(等>=18.5M唯一对再跑,截至归档时GPIC short约10.9M < 18.5M)。同上 L350: "R11-E GPIC数据轴 暂停等条件"; L359-368: R11-E配置

1.3 结论

核心归因：缺口未补上 不是因为缺数据（4路约69.6M对已在盘上），而是因为：

  1. 格式壁垒：WebMix-38M(38.8M)和wit_base(6.48M)是parquet，训练代码不读parquet -> 需代码改动或数据转码，两者都没做。
  2. 接入遗漏：InternVL-SA1B(22.4M)是tar格式、可直接读，但从未被加入训练路径列表 -> 纯粹是「没人接」。
  3. 格式不匹配：the_cauldron是VQA格式，不是简单图文对 -> 需改造，未做。
  4. 实验设计限制：R11系列实验有意控变量(只变数据源/caption粒度)，基线臂固定用CC12M+Amshaker。即使数据在盘上，也没被纳入实验设计——因为实验目的是做controlled comparison，不是最大化数据量。

一句话：数据下了、格式不对/没人接/实验没设计进去。把InternVL-SA1B接上+给data.py加parquet reader，即可零成本从18.5M -> 约85.7M对。

② 缺口分析

vision线当前基线用 CC12M + Amshaker 约18.5M对（英文caption + 通用网络图）。根据任务书和ARCHIVE_OPERATOR_VISION.md，缺口有三：

缺口现状目标差距边际收益
规模18.5M对(CC12M+Amshaker)>=18.5M唯一对做GPIC数据轴对比(R11-E要求)GPIC short仅约10.9M < 18.5M；但盘上有约69.6M已下载未用高：InternVL-SA1B(22.4M tar)零成本可接
中文/多语言caption几乎为0(CC12M/Amshaker/GPIC全是英文alt-text)>=一定比例中文caption现有数据0中文；最大中文源Wukong(100M)/TaiSu(166M)均非商用最大：中文caption对vision encoder在中文下游任务(OCR/文档理解/中文VQA)有直接增益
领域多样性通用网络图(alt-text噪声高)技术图/图表/文档/EDA类现有数据0领域图；HF上EDA/版图/电路类图文对未找到中：对EDA-Eval等领域评测有潜在增益，但数据稀缺

优先级判断：

  1. 先接已有数据(零成本)：InternVL-SA1B + WebMix-38M + wit_base -> 规模从18.5M -> 约85.7M，解决缺口1。
  2. 再补中文(最高边际收益)：TaiSu(166M中文，webdataset tar，非商用但研究可用) -> 解决缺口2。
  3. 领域图视情况：DocVQA/ChartQA/PlotQA可少量补充(约300K)，但格式需改造 -> 解决部分缺口3。

  1. 接入InternVL-SA1B(22.4M对，webdataset tar，已在盘上)：
    在vision训练脚本的--data-source路径列表中加入/nas_user/app.e0031982/datasets/hanlincs/InternVL-SA1B-Caption-WebDataset/webdataset/*.tar
    无需任何代码改动，webdataset tar格式与现有管线完全兼容

    当前R11-E只用了short子集(约10.9M)，可扩到全量(short+medium+long+tag约40.5M)

6.4 验证方法

  1. 格式验证：对已在盘上的parquet文件，用pyarrow.ParquetFile(fn).schema_arrow打印前3个字段名，确认image列名和caption列名。
  2. 解码验证：对InternVL-SA1B tar，用webdataset.Dataset读1个tar，确认能正确解码image bytes。
  3. 规模验证：接入后跑100步smoke test，确认data loader吞吐正常(目标>=R11-G steady 2485 img/s)。
  4. 质量验证：对TaiSu，抽5个tar检查中文caption质量(是否为有效中文、是否与图像内容匹配)。
