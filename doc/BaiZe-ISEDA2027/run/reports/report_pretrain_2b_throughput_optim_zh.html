4. 瓶颈归因与下一步建议

瓶颈分析

基线:252K tok/s

最佳:CUDA Graphs=259K tok/s(+2.7%)

  • CUDA Graphs(e01)+2.7%：消除kernel launch开销，对Mamba2频繁小kernel有效
  • FP8(tensorwise/delayed)反而慢~10%：Mamba2 SSM层GEMM占比低，量化开销>节省
  • FP8 blockwise不可用：TE要求CUDA≥12.9，当前12.8
  • overlap-param-gather崩溃：框架IndexError，与Mamba2自定义层不兼容
  • 显存:基线54.7GB→CG 65.3GB(+10.6GB)→FP8 ~54GB，80GB充足
  • NaN计数：grep误匹配，实际训练0 NaN(iteration log均显示"number of nan iterations: 0")

下一步建议

  • 组合优化:CUDA Graphs+CE Fusion+更大MBS(当前54.7GB,可试MBS=4)
  • 升级CUDA 12.9+:解锁FP8 blockwise
  • 序列并行(SP):--sequence-parallel减activation显存
  • 数据侧:num_workers/pin_memory/mmap预取
  • NCCL调优:NCCL_ALGO/NCCL_PROTO+NVSwitch拓扑
  • 更大GBS:减optimizer step频率提有效吞吐
