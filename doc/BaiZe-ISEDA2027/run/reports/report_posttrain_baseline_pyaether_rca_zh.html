八、结论与下一步

3.04% 主要卡在哪一层：agentic 执行层（推理/规划 + 工具协议），而非代码语义层。790 样本中 489（61.9%）是「根本没写出文件」、54 是「调用不存在的 API」——二者合计 ~69% 的失败是协议/执行可回收损失，与 R0 诊断 D1（工具调用合法率低）一致。真正的「写了代码但逻辑错」（③ 去除 ② 后约 117 样本，14.8%）才是纯能力差距。

若只修一件事：修「未产出文件就 submit_and_exit verified=true」——加 PreSubmit 文件存在闸门 + prompt 硬约束。这是 ROI 最高、成本最低（3 人时）、且不依赖 GPU 的一刀。

下一步：① 落地 P0 两件（文件闸门 + API 名校验）后重跑 5-run baseline，验证「协议可回收」能拿回多少 pp；② 再决定 RL（R2 已显负信号，先回收协议层再 RL 更可能产生正向增益）；③ SFT 语料按 ②③⑤ 比例补样本。
