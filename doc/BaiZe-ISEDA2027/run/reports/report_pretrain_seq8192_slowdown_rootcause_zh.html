BaiZe-2B（Mamba2-hybrid）预训练 seq=8192 吞吐骤降 —— 根因分析报告

序列长度 4096→8192「悬崖」被证伪为「批几何混淆」：决定性对照实验 cfg0a 复现 5.2× 跌幅
模型 BaiZe-2B 硬件 2×8 H800（双节点 NVLink+IB） 框架 Megatron-LM 日期 2026-10-25 状态 ✅ 根因锁定
▍ 结论（ROOT CAUSE）
吞吐 5.6× 骤降的根因是 批几何（gbs/accum/mbs）过小导致的 GPU 饥饿，不是序列长度 4096→8192。

决定性证据：对照实验 cfg0a 固定 seq=4096、仅把批几何缩到与 cfg1 相同的小批（gbs512/accum8/mbs4，2.1M tok/step）→ 吞吐 117K tok/s，相对基线 606K tok/s 下跌 5.2×，与 seq=8192 的 cfg1（109K）几乎一致。

机制：MFU 从 73.6% → 14%。每步只做基线一半的 token（2.10M vs 4.13M），墙钟却花 2.64× 时间（17.9s vs 6.8s）——GPU 在 kernel launch 间隙与每步固定开销（优化器步、grad all-reduce、dataloader、Python 编排）中大量空闲。CUDA graph 在两组均成功 capture 同样的 112 张图，排除图回退。

处置：seq=8192 应保持 ≥4M tok/step 的有效批规模（用更大 accum 补偿 mbs 因显存下调），预期可回到 ~500–600K tok/s，而非 108K。

一、问题与实验设计

原始 6 格扫描在「seq 翻倍」的同时同步缩小了 gbs/accum（为适配显存），构成一个双变量混淆：观测到的 4096→8192 悬崖无法区分「序列长度效应」与「批几何效应」。为此设计两组对照实验，固定 seq=4096、仅复刻小批几何，以隔离变量：

cfg0a（对照·已收敛）

seq=4096, gbs=512, accum=8, mbs=4
2,097,152 tok/step
复刻 cfg1 的小批几何，但序列长度保持 4096

cfg0b（验证·排队中）

seq=4096, gbs=1008, accum=21, mbs=3
4,128,768 tok/step
全尺寸批 + 短序列，预期回到 ~600K，反向印证

逻辑：若悬崖真由 seq 引起，cfg0a（seq=4096）应保持高吞吐；若由批几何引起，cfg0a 应复现 cfg1 的低吞吐。实验结果 unequivocally 支持后者。

五、机制详解：为什么小批会让 MFU 从 73.6% 崩到 14%

5.1 算术分解

baseline : tok/step = 4,128,768  ms/step = 6,808   → 606,415 tok/s  (MFU 73.6%)
cfg0a    : tok/step = 2,097,152  ms/step = 17,940  → 116,898 tok/s  (MFU 14.2%)
                                                                       ↑ 5.19× 跌幅

拆解 5.19× 跌幅的两个因子：
  ① 每步工作量减半 : 2,097,152 / 4,128,768 = 0.508×   (批几何直接效应)
  ② 每步墙钟变长   : 17,940 / 6,808     = 2.636×   (GPU 饥饿效应)
  合成 : (4.13M/6.8s) / (2.10M/17.9s) = 5.19×

关键签名：若 MFU 恒定，①减半工作量应只需 0.5× 墙钟(≈3.4s)，tok/s 不变(仍≈606K)。
实际却花 2.64× 墙钟(17.9s) —— 多出的 ~14.5s 几乎全是 GPU 空闲，而非真实计算。

5.2 GPU 饥饿的两个来源

来源 A · Kernel launch 间隙放大

一次前向是数百个小 CUDA kernel 的串行组合。每次 launch CPU 耗 5–20µs。大微批时每个 kernel 计算量大、launch 占比小；小微批(mbs4, accum8 → 每步仅 128 个微批)时计算短、kernel 之间 GPU 空等 CPU 发指令的间隙占比骤升，nvidia-smi 观测到 util≈0%。

来源 B · 每步固定开销不被摊薄

每个优化器步有固定墙钟开销：grad all-reduce、optimizer step、dataloader 取下一批、Python 编排、checkpoint hook。这些开销与批大小无关。baseline 用 4.13M token 摊薄它；cfg0a 只用 2.10M token 摊薄同一开销 → 单位 token 的固定开销翻倍以上。
CUDA graph 为何没救回来：两组都成功 capture 了 112 张图（attn-local 模式），replay 消掉了单次 forward 内部的 launch overhead。但 graph 无法覆盖微批之间与优化器步之间的 host 编排（grad sync、optimizer、dataloader fetch），而这些正是小批下占比最大的空闲源。因此 graph 配置一致、吞吐仍差 5× —— 进一步坐实根因在批几何而非 graph。

六、外部对标与文献引用

  • 批几何与 MFU：VAHU《Mastering LLM Training: Batch Size, Gradient Accumulation, and Throughput》(2026-07-07) 明确——有效批 = mbs × accum × world_size，小微批导致 GPU 利用率不足、训练低效，应「找最大 mbs 使吞吐最大」。与本报告 MFU 73.6%→14% 的观测一致。
  • Kernel launch → GPU 饥饿：marsggbo《CUDA Graph 是怎么解决这件事的》(2026-07-08)——单次 launch 5–20µs × 数百 kernel 累积达毫秒级，小 batch 时 GPU 经常空闲等待 CPU 发指令；CSDN flyfish《enforce_eager 参数》(2026-04-03) 同指「小模型、小 batch 时 launch overhead 占很大比例，GPU 利用率低」。这正是 5.2 节来源 A 的机制出处。
  • 分阶段上下文扩展是工业标准：charles2530《Qwen3 Technical Report 深读》(arXiv:2505.09388)——Qwen3 预训练 S1/S2 用 seq=4096（30T+5T tokens），Long Context Stage 才升至 32768（仅数百 B tokens，占总量 <2%）。说明长序列阶段本就是小数据量阶段，天然适合用更大 accum 维持 tok/step，而非缩小批。
  • MFU 定义与重算：Neel Mishra《Megatron-LM: 3D Parallelism》——MFU 度量硬件峰值 FLOPS 用于有效计算的比例；selective recompute 可省 ~60% 激活显存、仅 ~5% 额外开销，是上调 mbs 的可用杠杆。

七、处置建议

  1. 纠正 seq=8192 的批几何：保持有效批 tok/step ≥ 4M（基线水准）。显存若迫使 mbs 从 3 降到 2（8192 更吃激活），则把 accum 从 21 提到 ≥32，使 gbs×seq ≥ 4.1M。目标量是 tok/step，不是 seq 专属常数。
  2. 重测 8192 真实吞吐：以纠正后的批几何重跑，预期回到 ~500–600K tok/s（受 8192 激活显存约束，可能略低于 4096 的 606K，但绝不应是 108K）。cfg0b（seq=4096 全批）跑完将给出 4096 的上界反向印证。
  3. 若需纯 seq-吞吐曲线：原 6 格是双变量混淆，不能作为 seq 效应的依据。应重做单变量扫描——固定 tok/step≈4M，仅变 seq（用 accum 补偿 mbs 的显存差异），才能得到真实的 seq-吞吐关系。
  4. Profiling 确认空闲源：用 Nsight Systems 抓一次小批 vs 全批的 timeline，确认 GPU 活跃段之间的空隙（launch gap / inter-microbatch gap）。若空隙集中在 optimizer/dataloader，可尝试 overlap dataloader、异步 optimizer、增大 graph 覆盖模块。
  5. 显存杠杆：开启/调参 selective recompute（省 ~60% 激活），为 8192 下上调 mbs 腾出空间——mbs 越大，单微批计算越饱满，launch 间隙占比越低。
  6. 修记忆体：MEMORY #779「Mamba2 SSM 超线性致慢」标记为已证伪；根因改为「小批几何→GPU 饥饿（MFU 14%）」。本次结论同步写入 EXPERIMENTS_PRETRAIN_2B_ROUND2.md。
方法论警示：本次「seq 悬崖」本质是一次双变量混淆实验错误——在调 seq 的同时改了 gbs/accum。今后凡涉及吞吐的扫描，必须锁定 tok/step（用 accum 补 mbs 显存差异），否则任何观测到的「seq 效应」都可能是批几何伪迹。这是比本次根因更重要的教训。
