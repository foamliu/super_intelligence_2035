§八 核心结论：哪些能力接近，哪些明显不足

接近的能力：
1. 工具协议掌握——F2 工具格式错误仅 2 题，agent 回路进入率 100.00%，广度 6–7 种/题 ⇒ MiniCPM5-2B 已能正确发起多工具 agent 回路，与 DeepSeek 失败结构（都不卡协议）一致。
2. 简单题覆盖——25 题 5/5 全过，trivial/easy 档有相当通过率。
3. RAG 检索使用——RAG 查询率 100.00%，能主动检索 API 文档（⚠️ 但向量召回 infra 自 11-13 失效、实为 BM25 兜底退化口径，见首屏「检索 infra 降级声明」；不应解读为「完整检索能力已接近 DeepSeek」）。
明显不足的能力：
1. 逻辑/语义正确性——F5 逻辑错 51 题（38.35%）为主，AssertionError 100 条；代码跑通但断言不满足，这是与 DeepSeek 拉开差距的主因（~38.8pp 含能力+环境）。
2. 稳定产出可执行代码——F1 未产出代码 36 题、Generation fail 137 条；部分题 2500s 内未稳定产出。
3. 自纠错闭环——run_code 沙盒执行仅 0.80 次/题（两组皆≈0.8），几乎不靠「执行-看错-修」回路；FAIL 组过载检索（32.2 次搜索）却不收敛。
4. 难题/极端题覆盖——51 题 0/5 全挂，T4/T5 档覆盖远低于 DeepSeek。
5. SFT 后退化——当前 SFT 配方使 Pass@1 暴跌 -38.73%（F1 未产出代码 127），base 产出能力被打掉，配方须重做。
口径再申：以上「接近/不足」均为同 harness（含 RAG+沙盒+hook）下的行为学对照；~38.8pp 裸差不等于纯能力差（规模 2B vs V4-Pro、机器 .17 vs 36.15 均不同）。要量化纯能力差，需在同机器、同 harness 下对两模型做 5-run 逐题配对——DeepSeek 侧目前无逐题数据，列为 TODO。
