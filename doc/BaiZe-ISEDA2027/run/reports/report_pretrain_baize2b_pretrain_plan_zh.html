四、商榷点与建议

4.1　4M tok/step 下吞吐是否仍 613,992（S1 2M 需重测）

事实：613,992 是在 4M tok/step（tok/mb=16,384/GPU，accum16）档实测的，恰为 S2/Decay 配置。S1 用 2M tok/step，每步 token 减半 ⇒ 单步计算量减半，但每步的通信/启动开销不随 batch 线性下降，因此 S1 的稳态吞吐大概率 < 613,992（每秒 token 数可能下探，步时 < 3.257 s 但不成比例减半）。

建议：S1 开跑前用 20–40 步 smoke 实测 2M tok/step 的真实 tok/s，把实测值回填 §3 的 ETA（若 S1 实测降到 ~550K，则 S1 天数从 26.4 上浮到 ~29.4，总纯训练升至 ~57 天）。本报告的 54.3 天对 S1 段属乐观估计。

4.2　LR 保持 1e-3 + WSD 2000 步 warmup 的含义与注意点

WSD 释义：Warmup-Stable-Decay。本计划 = ① 2000 步线性 warmup 到 1e-3 → ② LR 保持 1e-3 跨 S1+S2 稳定段共 1,048,000 步 → ③ Decay 段 20,000 步从 1e-3 衰减到 min-lr。

注意点：

  • 1e-3 偏高（2.2B / AdamW 口径）：本项目 decay 参考实验（1113.sh）用 muon 优化器、decoupled-lr 1e-2、min-lr 1.04e-4。若本计划沿用 AdamW，1e-3 是合理但偏激进的上界，建议确认优化器选型（AdamW vs muon）—— muon 通常允许更高 LR 但需 matched-adamw-rms。
  • Decay 形状未指定：WSD 的 D 段可为 linear / sqrt / exponential 衰减。1113.sh 用 exponential。建议明确 decay 曲线与 min-lr（推荐 min-lr ≈ 0.1×peak = 1e-4，与 1113.sh 的 1.04e-4 一致）。
  • 2000 步 warmup = 4B token：对 2.2B 模型偏短但可接受；若开训早期 loss 不稳可加长到 5000 步（= 10B token）。
  • μP 一致性：本项目历史 decay 训坏（v2 44.97%）曾归因「缺 μP / LR 双移位」。本计划若换模型尺寸或优化器，须复核 μP 坐标（width/base/depth/bs）与 LR 标定，避免重蹈覆辙。

4.3　数据配比 epochs<1 的采样语义

S1/S2 多个数据集 epochs<1（Math-L3=0.72、Code-L3=0.87、en_v1_4=0.81、Math-L1=0.85）。语义：在 2.8T 全程内，该集每个文档平均被采样 < 1 次 ⇒ 有 14%–28% 的数据从未被模型见过。

权衡：

  • 对海量主体数据（en_v1_4 0.81）epochs<1 是合理的——数据足够多，单遍即足。
  • 对稀缺高价值数据（Math-L3 仅 0.72、占比 0.02）epochs<1 = 部分难题从未训练到，可能浪费稀缺资源。建议对 Math-L3 / Code-L3 这类高难度集适当提升 epochs（如 ≥1.0），或在小 prop 下用「过采样 + 重复去重标识」确保全覆盖。
  • prop 与 epochs 是耦合的（epochs ≈ prop × 总token / 集大小）；若想提升某集 epochs，要么提 prop（挤占他集）要么接受更长总 token。建议在 §2.2 表基础上做一次「目标 epochs → 反推 prop」的配平。

4.4　Decay 阶段 SFT/Agent 占比 0.72 的合理性

Decay 段 80B token 中 SFT(0.60)+Agent(0.12)=0.72，预训练态数据仅 0.28。这是「以指令数据退火（instruction annealing）」策略，与 Phi 系列「末段注入教科书/SFT 数据」思路一致，能显著提升下游指令跟随与 Agent 能力。

风险与建议：

  • 退火窗口短：Decay 仅 2.78% 总 token，72% 的 SFT 影响被压缩在末段——若 SFT 数据质量不均或分布偏移大，可能在 LR 衰减中引入能力骤降（参考本项目 v2 decay 训坏先例）。
  • 建议分段：把 Decay 20k 步再切为「前半 0.4 SFT 比例 + 后半 0.85 SFT 比例」，让 base 能力先稳后退火，降低一次性倾斜风险。
  • 保留 base 评测基线：Decay 前（S2 末）存 ckpt 并跑 CS8/CX6 eval，与 Decay 后对比，量化「退火收益 vs base 损失」。
  • SFT-2605 / Agent-2609 去重与质量：0.60+0.12 的体量需确认两集已去重、无 prompt 泄漏、无安全/风控问题（本项目禁令：不绕过验证/风控）。

4.5　总计耗时与 GPU 预算

核心约束：纯训练 54.3 天、含预留 ~65 天，16×H100 连续占用 ~2 个月、~2.5 万 GPU·h。

  • 连续性风险：2 个月级单集群连续占用，故障/重启几乎不可避免 ⇒ 必须有可靠的断点续训（ckpt 频率建议 S1/S2 每 5000 步一存 ≈ 8.6 GB/次、Decay 每 1000 步），并验证 resume loss 无跳变（本项目 P-8 resume 闭环已验证可用）。
  • 分阶段决策点：S1（26 天 / 1.4T）跑完是一个天然评估闸门——建议 S1 末存 ckpt + 全量 eval（CS8/CX6/scaling-law 外推），评估达标再启 S2，避免一次性 commit 2 个月预算。
  • 资源争用：本集群与 vision/data/harness 共用 NFS 与部分节点；长任务期间需与各线协调 GPU/IO 时段（吞吐实测已要求无争用干净测量，长训练同理需避免 IO 抖动）。
  • 预算对照：本项目 2B 超参搜索阶段单次 ~44B token（P-8）；本计划 2.88T 是其 ~65 倍，是真正的「正式预训练」量级，资源量级需运维/用户拍板。
