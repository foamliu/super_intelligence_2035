1. 实验概述

ArmA 是 BaiZe 视觉编码器系列中的一个对照实验，使用 open_clip 标准 ViT-B/16（224px）从零开始进行纯对比学习（CLIP InfoNCE），以回答核心问题：

在同等数据预算下，纯对比目标（InfoNCE）训练出的视觉表征，与 BaiZe 主线采用的 AIMv2-style 稠密目标（InfoNCE + masked-patch-MSE）相比，在线性探针（lp）和 k-NN 检索两个维度上有何差异？

ArmA 的评测结果（lp 58.03±0.02% / 5-NN 53.98%）与主线 ④-4ep 基线（lp 67.05±0.02% / k-NN 42.35%）形成了鲜明的"检索强、线性可分性弱"的对照模式，与团队此前"C1/lp 背离"的假设一致（详见 §6）。

6. 关键解读

6.1 核心发现：lp ↓ / k-NN ↑ —— "检索强、线性可分性弱"

ArmA（纯 InfoNCE 对比训练）相对于 ④-4ep（AIMv2-style 稠密目标）呈现 两个方向的背离：

  • 线性探针（lp）低 9.02 pp：58.03% vs 67.05% —— 纯对比表征的线性可分性显著更弱。
  • k-NN 检索高 11.63 pp（+14.21 pp 若同取 k=5）：53.98% vs 42.35% —— 纯对比表征的近邻检索能力显著更强。

这一模式与团队此前的 "C1/lp 背离" 假设一致：CLIP 式对比学习倾向于将表征在特征空间中按语义聚类（提升 k-NN 检索），但不保证类间线性可分性（降低 lp）；而 AIMv2-style 的 masked-patch 重建项引入了空间稠密监督，迫使表征编码更丰富的局部信息，从而提升了线性可分性，但可能"稀释"了对比目标对全局语义聚类的专注度。

6.2 ⚠️ 严禁过度解读：这不是单变量对照

ArmA 与 ④-4ep 之间有多个变量同时不同，因此 不得 将 lp 差 9 pp 归因于"目标函数差异"：

变量ArmA④-4ep是否单变量？

目标函数InfoNCE (ClipLoss)AIMv2-style (InfoNCE + patch-MSE)❌ 不同

正确表述：ArmA 是一个"open_clip 标准配方"的独立实验点，其 lp 低于 ④-4ep、k-NN 高于 ④-4ep，提示对比目标与稠密目标在表征特性上可能存在 lp/k-NN 取舍，但 不能 在控制其他变量的前提下量化"目标函数贡献了多少 pp"。要得到单变量结论，需固定塔/步数/数据/批次，仅切换目标函数（这正是 ArmB 实验的设计意图之一）。

7. 诚实条款

  • 内部 ProtB 口径：本报告所有 lp/k-NN 数字使用 BaiZe 内部 Protocol B，非官方排行榜协议。Protocol B 设计目标是与公开主流值对齐，但仍是内部实现。
  • 单 backbone / 单预算点：ArmA 仅训练了一个 checkpoint（单 seed 训练），ProtB 评测用 3 seeds 但特征来自同一 backbone。不代表 open_clip ViT-B/16 在所有配置下的上界。
  • 5-NN 与 lp 口径不同：k-NN 使用 cosine similarity + k 近邻投票，lp 使用线性分类器 + softmax；两者衡量表征的不同性质。且 ArmA 的 k=5 与 ④-4ep 的 k=20 口径不同（见 §5.1）。
  • 仅评测 3 seeds：训练单 seed（1234），ProtB 评测 3 seeds（0/1/2），σ=0.02 pp 极小但仅反映评测端随机性，不含训练端随机性。
  • 效率数字：3.37 it/s 为效率修复后的稳态值（+40% vs 修前 2.40 it/s），修复为一揽子应用非单变量 A/B。
  • 数据量标注：ArmA 数据 ≈118M 对（10,787 shards），与 ④-4ep 使用的数据源相同但 epoch 数不同（2.7 vs 4）。

附录 A：open_clip × AIMv2-style 兼容性工程评估

A.1 结论（两层）

层面兼容？说明
模型 / 推理接口✅ 完全兼容open_clip 模型可直接用于 AIMv2-style 训练的视觉塔；推理侧只需 encode_image 的 pooled/patch 输出
训练损失 / 训练循环❌ 不兼容（需自定义）open_clip 自带的 loss 家族无 patch 级重建目标，训练循环不提供 mask 采样 / patch 目标 → 需自研训练环（可行，非不可能）

A.2 兼容证据

  1. ArmA 本身就是 open_clip 模型：训练使用 open_clip.create_model_and_transforms('ViT-B-16', pretrained=None)（armA_openclip_train.py:169-170），前向 model(imgs, texts) → (img_feat, txt_feat, logit_scale) + ClipLoss（armA_openclip_train.py:286-287），完整走 open_clip 接口。
  2. 导出/推理侧只需 encode_image：BaiZe 的 open_clip bridge 通过 model.encode_image(x) / model.visual(x) 获取 pooled 或 patch 特征（mllm_bridge/open_clip_baize.py:8-16, 26-34），不涉及训练损失。
  3. predictor 是训练期辅助头，不进入推理图：AIMv2-style 的 PatchPredictor（≈0.66M 参数）仅在训练时用于 masked-patch 重建，推理时完全不加载，因此不影响 open_clip 模型的加载与下游评测。

A.3 不兼容点

  1. open_clip loss 家族无 patch 级重建：open_clip 提供的损失有 ClipLoss / SigLipLoss / CoCaLoss / GenLIP 等，全部是对比型或 caption 型，没有 masked-patch 重建（MSE）目标。
  2. open_clip 训练循环不提供 mask 采样：标准训练循环只消费 (image, text) 对，不涉及 patch 级 mask 采样、patch target 构造等。
  3. 本仓 AIMv2-style 是自研训练环，核心逻辑（r9_train.py:788-807）：
pooled, patches = vision(imgs, return_patch=True)          # 单次前向，取 pooled + patch
target = mae_norm_pix_target(imgs, args.patch)              # MAE norm_pix 目标
mrand  = torch.rand(B, N, device=device) < args.mask_ratio # 随机掩码 (mask_ratio=0.6)
pred   = predictor(patches[mrand])                          # 预测被掩码的 patch
tgt    = target[mrand]                                      # 掩码位置的真实目标
patch_loss = torch.mean((pred.float() - tgt.float()) ** 2) # MSE
if args.contrast_weight > 0:
    If = normalize(pooled, dim=-1); Tf = normalize(text(txts), dim=-1)
    contrastive = loss_fn(If, Tf, logit_scale.exp(), None)  # InfoNCE
    cur_loss = contrast_weight * contrastive + patch_loss_weight * patch_loss
else:
    cur_loss = patch_loss_weight * patch_loss               # 纯 AR 路径

A.4 做"open_clip 模型 + AIMv2-style"需要 4 件事（≈1–2 人日，纯 CPU）

  1. 挂 PatchPredictor：在 open_clip ViT 上挂 PatchPredictor（Linear→LN→GELU→Linear，≈0.66M 参数），作为独立 DDP 模块。
  2. 取 patch tokens（复用同一次前向）：按 open_clip 版本用 visual.forward_features / visual.trunk.patch_embed / forward_intermediates 之一，或用 forward hook 复用同一次 vision 前向。禁止二次 forward（否则 ETA +35–45%）。
    ⚠️ 实现前先 python -c 打印 type(model.visual) 与可用方法并存证
  3. 自定义 loss + 训练步：照 ArmA 循环改 ≈50 行：在 model(imgs, texts) 后取 patch tokens → mask 采样 → predictor 前向 → MSE → 与 InfoNCE 加权求和。
  4. checkpoint 存取：剥离 predictor：保存 open_clip_state_dict.pt（剥离 predictor）+ predictor.pt + config.json；验收 open_clip.create_model_and_transforms('ViT-B-16', pretrained=<ckpt>) strict load 通过；若 contrast_weight=0 → find_unused_parameters=True 或冻结文本塔。

工程量评估：上述 4 步均为纯 CPU 开发，预计 1–2 人日。ArmB 实验已按此方案实现（armB_aimv2_openclip.py），6/6 CPU 单测通过。
