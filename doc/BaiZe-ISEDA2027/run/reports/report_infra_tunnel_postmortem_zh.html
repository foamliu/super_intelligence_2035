§0 架构与已知事实

dual-nix-tunnel 架构：Windows 桌面机 172.19.195.133 运行 tunnel.ps1 作为中继跳板，使 .17 的 127.0.0.1:3333 经中继转发到 36.15:22。.17 侧再以 ssh -p 3333 ... localhost 建立两条隧道：

  • 正向（沙盒端口转发） PID 618469（起于 2026-11-12 16:05）：ssh -p 3333 -N -L 8664..8668:10.129.32.75:... app.e0031982@localhost —— 把 36.15 沙盒后端 8653/8664-8669 暴露到 .17 本地。
  • 反向（模型服务转发） PID 1008898（起于 2026-11-13 03:14）：ssh -p 3333 -fN -R 18096:localhost:8096 ... —— 把 .17 GPU6:8096 的模型 serve 反向暴露到 36.15 的 localhost:18096。
  • 反向（备用 serve） PID 1278889（起于 2026-11-13 11:39）：ssh -p 3333 -fN -R 18098:localhost:8098 ...。

关键约束：10.251.36.15:22 对 .17 始终被防火墙拦截（仅 ICMP 互通）——中继隧道是 .17↔36.15 的唯一通路。中继一断，.17 对 36.15 的所有 SSH/转发即时失效。本报告 23:49 实测：nc -vz -w8 10.251.36.15 22 → timed out；ping 36.15 → 0% loss, rtt 0.28ms（主机在线，仅端口被墙）。

④ 故障域判断（五选一，逐项给依据）

候选判定依据
① 中继 Windows 机 172.19.195.133 不在线可能（主因之一）wake505「.17 不可触达，ping/ssh 均无响应」；中继机为 Windows 桌面机，可能休眠/掉网。无法从 .17 侧直接探测，内部确切状态无记录。
② 中继 tunnel.ps1 进程死可能（主因之一）wake506 恢复描述为「Windows 中继 tunnel.ps1 重新在线」，即 ps1 进程曾不在线。①/② 二选一或叠加，从 .17 侧无法区分。
③ 中继→36.15 SSH 认证失败排除恢复后无任何 known_hosts/key 报错，ssh -p3333 ... 'hostname' 干净落地 hfeg0tedaap02；若是认证失败应持续报 Permission denied，与「自愈」模式不符。
④ 36.15 sshd 拒连排除36.15 主机在线（ping 0% loss）；中继一恢复，36.15:22 经隧道立即可达并正常 shell ⇒ sshd 未拒连/未重启。10.251.36.15:22 对 .17 直连超时是基线防火墙策略（一直如此），非本次故障。
⑤ .17 本侧端口被占/被清排除.17 在窗口内未重启（uptime 123 天）；端口 3333 在中继恢复后自行复听，无 .17 侧人工重建隧道的动作记录 ⇒ 3333 监听随中继 remote-forward 会话起灭，非本侧被抢/被清。

结论：故障域 = ① + ②（中继侧）。确切内部触发（机器休眠 / ps1 崩溃 / 网络抖动）无记录，因 .17 无法触达 Windows 桌面机做进程/事件取证。

进程状态诚实说明：本报告 23:46 实测，.17 侧三条 ssh -p3333 客户端进程（PID 618469 / 1008898 / 1278889）lstart 分别显示 2026-11-12 / 11-13，etime 1.5–2.4 天，当前存活。这与 wake505「无 ssh -p3333 进程」记录存在张力，可能解释为：中继的 .17:3333 remote-forward 监听随中继掉线消失、随恢复复现，而 .17 侧客户端进程对短暂断连的容忍/重连行为从 .17 侧无法完全还原。功能性事实（22:4x 不可用、23:26 起可用）由 wake505/wake506/本报告三次独立实测一致确认，为可信结论；进程级微观不在 .17 可取证范围内，标注「无记录」。

⑤ 是不是我们这边造成的

否 非本线造成，也非本线修复。

  • 20:41–23:30 期间 posttrain 未对中继或隧道做任何动作：wake505（22:4x）全程为纯 CPU 工作（T6 归因表 / 计划填妥 / HTML 报告生成），仅读取已落盘的 run1 数据，未碰网络/进程。
  • wake506（23:30，恢复之后）的 kill 仅作用于 36.15 上的本线评测进程（baseline 5-run chainer PID 1229657 + run2 进程树），释放 GPU6:8096 serve 给归因链；未碰中继、未碰 .17 隧道进程、未碰别线（ZhuLong subagent A2 走云网关未动）。
  • 中继机 172.19.195.133 是运维 / 用户侧 Windows 桌面机，.17 无任何可达路径（wake505 实测 ping/ssh 无响应），物理上 .17 不可能造成其掉线。
  • 恢复发生在 wake506 介入之前（23:26 chain.log 已能经隧道取模型）⇒ 恢复由中继侧自行完成，与 posttrain 动作时序无因果。
