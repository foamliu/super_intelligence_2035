1. OOM 崩溃定性（18:09 S2 崩溃）

崩溃时间：2026-11-28 18:09:11

崩溃现象：.29 rank13 DataLoader worker（pid 3983423）被 SIGKILL，报 is killed by signal: Killed

证据采集：

  • dmesg -T | grep -iE 'killed process|Out of memory|oom-kill' → 无输出（权限受限或日志已轮转）
  • journalctl -k --since '2026-11-28 17:50' --until '2026-11-28 18:15' → 无输出（权限受限或日志已轮转）
  • MEMORY #3582 既有定论（2026-10-27 #801/#802 同签名事故）：根因 = fork-COW RSS 累积 → swap 耗尽 → 内核 OOM-kill

根因：DataLoader worker fork 时 COW（Copy-On-Write）页大量累积，nw=8 × mmap enabled 配置下 RSS 持续增长 → swap 8GB 耗尽 → 内核 OOM killer 选中 rank13 worker 发送 SIGKILL

修复：nw=2 + no_mmap=1（commit c423bcb9cc，19:59），减少 fork-COW 内存压力 4×

当前状态：S2 以 nw=2 稳定运行 2h55m，iter=351310，step~7.0s，loss~1.498，0 NaN，0 skip ✅

7. 残余风险

风险 1：.29 Swap 使用率 97.6%（中风险）

现状：.29 swap 7.8/8 GB 已用，仅剩 ~200 MB。但 vmstat 显示 si/so=0（无活跃换入换出），swapped 页是 COW 残留（nw=2 配置下 fork 产生的 COW 页被换出后未被访问）。

风险：若训练遇内存尖峰，极低 swap 余量可能导致再次 OOM-kill。

缓解：① nw=2+no_mmap 已大幅降低 COW 内存（相比 nw=8 减少 ~4×）；② RAM available 1,081 GB 充足；③ 持续监控 si/so，若 >0 立即告警。

风险 2：.12 /dev/shm psm_* 残留 178MB（低风险）

42 个 root 所有的 Intel PSM 共享内存文件（Jul 9-10），无权限清理，体量小不影响训练。

风险 3：.12 /tmp 别线大目录 ~40GB+（低风险）

vision/data 线在 .12 /tmp 有大量旧目录（~40GB+），非本线不可清理，不影响 pretrain 训练。
