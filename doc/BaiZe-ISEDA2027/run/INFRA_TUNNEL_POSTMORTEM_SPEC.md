## 1. 要回答的六个问题（每条都要**证据**，不许猜）

1. **最后一次确认通**：时间点 + 命令 + 原样输出（例：`curl -s http://127.0.0.1:18096/v1/models` 返回了什么、`ss -ltnp | grep 3333` 当时在不在）。
2. **第一次发现不通**：时间点 + **原样报错**（`Connection refused` / `timeout` / `No route to host` / `Permission denied`，不要改写）。
3. **中间发生了什么（时间线 20:00 → 23:30）**：本机/关联侧的重启、断网、进程被杀、会话超时。
   取证命令示例：`last reboot | head` · `journalctl -S "today 20:00" --no-pager | tail -50` · `dmesg -T | tail -30` · `ps -eo pid,lstart,cmd | grep -E "ssh|tunnel"`。
4. **故障域判断（五选一或组合，逐项给判别依据）**：
   - ① 中继 Windows 机 `172.19.195.133` **不在线**；
   - ② 中继上 `tunnel.ps1` **进程死了**；
   - ③ 中继 → 36.15 的 **SSH 认证失败**（key/密码/known_hosts）；
   - ④ **36.15 sshd 拒连**（MaxStartups 满 / 重启中 / 防火墙改规则）；
   - ⑤ `.17` 本侧**转发端口被占或被清**（3333 被别的进程抢、ssh 会话回收）。
   - 判别技巧：`nc -vz <ip> <port>` 看卡在 TCP 还是 SSH banner；`ssh -vvv -p 3333 ...` 看第一处报错。
5. **是不是我们这边造成的**：明确区分「基础设施侧（中继 Windows 机）/ 本线可控制部分」。**不许甩锅给无法验证的一方，也不许无证据自认。**
6. **修复路径**：谁能修、要什么权限、修好后**三条可复制的验证命令**（含预期输出）。
