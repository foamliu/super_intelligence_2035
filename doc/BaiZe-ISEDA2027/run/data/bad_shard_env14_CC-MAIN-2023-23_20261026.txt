## 3. .idx 头与偏移（用 Megatron _IndexReader 格式手解，py310 env）

命令（节选）：
```python
import numpy as np, struct, os
with open(idx,'rb') as f:
    magic=f.read(9); version=struct.unpack('<Q',f.read(8))[0]
    dtype_code=struct.unpack('<B',f.read(1))[0]
    seq_count=struct.unpack('<Q',f.read(8))[0]      # num_docs
    doc_count=struct.unpack('<Q',f.read(8))[0]
    seq_lens=np.frombuffer(f.read(seq_count*4),dtype=np.int32)
    seq_ptrs=np.frombuffer(f.read(seq_count*8),dtype=np.int64)
```

## 4. 定性结论

**.bin 被截断（truncated），.idx 正确。** .idx/.json 描述完整 30.62B token / 122.50GB .bin；
实际 .bin 仅 49.03GB（缺 ~73.47GB ≈ 18.36B token ≈ 60%）。.bin mtime 晚于 .idx 16h，
推断 10-22 02:20 有一次对该 .bin 的重写/截断未完成（parallel-finish 或 fullsource 重跑该 shard 时
以写模式打开 .bin 但未跑完，或外部进程截断）。manifest 第 92 行误标 `DONE 30624024695 49025167172`
（tokens=完整值但 bin_bytes=截断值）正是该不一致的留痕。
