§1 MiniCPM5 训练数据全貌（总 token + 逐源 + 出处）

1.1 MiniCPM5 训练管线（三阶段）

MiniCPM5-2B 训练 = 三阶段全栈实践 UltraData 分层数据管理（arXiv 2602.09003）：
① 基座训练（Base Training）= stable + decay → 建立核心语言能力与训练稳定性
② 中间训练（Mid-Training）= 200B Agent → 适配目标数据分布，灌入 Agent 能力
③ 后训练（Post-Training）= 400B SFT → RL → OPD → 深度推理 + 16 专家蒸馏
出处：ModelScope 官方模型卡；open-llm-radar.com/models/minicpm5-2b；HuggingFace openbmb/MiniCPM5-2B 模型卡（2026-10-13 实读）

2.2 并行策略分析

策略配置吞吐预期显存复杂度Mamba2 适配判定
DP16（首选）TP1 · PP1 · DP16（8+8 跨节点）~498K tok/s（2× 249K，近线性）~55GB/卡（同 P-8）最低✅ SSM 层无 TP 需求✅ 推荐
TP2 + DP8TP2（节点内 4 组）· DP8~465K（TP 通信税 −6~7%）~45GB/卡（权重减半）中⚠️ SSM 层 TP 收益有限备选
PP2 + DP8PP2（跨节点 2 stage）· DP8~470K（pipeline bubble ~5%）~30GB/卡（半层）高（Mamba2 序列依赖）❌ SSM 递归状态难切不推荐
推荐：DP16。理由：
① Mamba2 SSM 层 TP 收益有限：SSM 层权重矩阵远小于 Attention/FFN。P-9.7 实测 TP1·MBS2 = 60.6% MFU vs TP4·MBS8 = 52.8% MFU（−7.8pp），证明 TP 对本架构有净负收益。
② PP 对 Mamba2 不友好：SSM 是递归状态依赖的（h_t = f(h_{t-1}, x_t)），pipeline 切 stage 引入状态同步复杂度 + bubble 开销。
③ DP16 最省心：每卡独立前向/反向，跨节点仅需梯度 allreduce（2.22B×4B = ~8.9GB/step，50 GB/s RoCE 下 ~0.18s，占 ~16.85s/step 的 1%）。
④ 显存无压力：P-8 实测 55GB/卡（80GB），16 卡同配置 → 剩余 25GB 余量充足。

2.3 GBS / LR 联动决策

方案GBS每卡 samples/stepLR步时吞吐判定
A（推荐）1024（维持）64（vs 8卡 128）1e-3（不变）~8.5s~498K tok/s✅ 不改 LR，最安全
B（备选）2048（翻倍）128（同 8 卡）2e-3?（线性 scale）或 √2×?（√scale）~16.85s~498K tok/s⚠️ LR scale 有争议
结论：GBS=1024, LR=1e-3（方案 A）。16 卡 DP16 下 GBS 维持 1024 → 每卡处理量减半 → 步时减半 → 同样的 token 预算在 ~一半墙钟内完成。LR 保持 1e-3（P-5a 全局极小值 + P-8 AdamW 实证），不做 LR scale。理由：① GBS 不变 → effective batch dynamics 不变 → LR 无需调整；② 用户 2026-10-12 明确「LR 1e-3 不准改」；③ 方案 B 虽吞吐相同但引入 LR scale 争议，对首个正式训练不值得冒风险。

4.2 训练纪律

  • 从零开始，不加载任何预训练权重。
  • WSD 完整走完，decay 尾段必须吃到 SFT 退火混合（SFT 64% + L3 24% + code 8% + math 4%）。
  • 每 500 步记 train loss / val loss / grad norm / tok/s / GPU 独占核验。
  • NaN / 发散 / OOM 一律记录并保留 ckpt 与日志，不静默重启掩盖。
  • AdamW 已收敛基线：P-8 AdamW step~5849 loss=2.588 平滑下降无 spike。若正式训练仍发散 → 上报。
