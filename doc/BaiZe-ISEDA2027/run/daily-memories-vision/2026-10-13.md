## [18:18] Wake #52 — 🔴 Critical bug found & fixed + CLIP/OV2 ProtB results obtained

**What happened**: CLIP and OV2 both finished feature extraction and cached features to disk, then crashed during the linear probe with `RuntimeError: Expected all tensors to be on the same device, but got mat1 is on cpu, different from other tensors on cuda:0`.

**Root cause**: In `lp_protocol_bridge.py`, function `linear_probe_mainstream()` (line 189): `Xtr`, `ytr`, `yva` were all moved to `device`, but **`Xva` (validation features) was never moved**. When `clf(Xva)` is called at line 213, the classifier is on CUDA but Xva is on CPU → crash. This bug was latent — it didn't affect BaiZe's own Protocol B evaluations because those features happened to already be on GPU.

**Fix**: Added `Xva = Xva.to(device)` at line 189 (after `yva = yva.to(device)`). Idempotent — no effect if Xva is already on device.

**Recovery**: Since features were cached to disk *before* the probe crash, re-ran both models with `--skip-extract` flag on the now-free GPUs 0 and 3. Each seed took ~90s (3 seeds × 90ep SGD on 1.28M samples).
