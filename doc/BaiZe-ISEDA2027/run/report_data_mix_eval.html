🔴 核心发现：代理 val-loss 不能预测 lm_eval 评测均分（Spearman ρ = −0.43, p = 0.40, n = 6）。BO 选出的 loss 最优配比（#182）在 lm_eval 上反而排名最末（rank 6/6）。这证实了运维 2026-10-06 的判断：loss 排序 ≠ 能力排序，用 loss 当 BO 目标是方法学错误。
一句话结论：200-trial BO 在代理 val-loss 上收敛到 best=#182（web=82.7%, code=6.2%, math=11.1%），但 top-K 的 lm_eval 8 集均分仅 0.332–0.337（接近随机基线），且 loss 与均分呈负相关。根因：18.36M 模型 + 500 步（0.016B token）训练量太小。结论：第二轮 BO 必须用 MBS=16 + D=0.5–1B token/trial + lm_eval 均分作 objective。

9. 方法学反思

失败原因：① 模型太小(18.36M) ② 训练量太小(D=0.016B) ③ objective错误(val-loss负相关) ④ spread太小(0.005)
第二轮改进：D↑(0.5-1B,30-60×) + MBS=16(8.6×) + lm_eval objective + 8卡
