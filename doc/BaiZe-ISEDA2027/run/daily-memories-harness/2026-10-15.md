### R401 (2026-10-15 10:03) — DATA-LOSS BUG FOUND + FIXED

**Incident**: glm53_pilot_results.json shrunk from 1178 entries (R400 commit) to 343 entries.

**Root cause**: `run_serial_kimi.py:save_results()` line 341-342:
```python
except Exception:
    current = []
```
On JSON parse error (likely NFS partial write), `current` is set to `[]`, then ONLY the current harness entries are written, destroying all other harnesses data. This cascaded: each subsequent process read the truncated file, wrote only its own entries.

**Data lost**: 843 entries — codex(300), deepseek-harness(300), opencode(126), cline-patched(117).

**Fix applied** (3 changes to save_results + load_results):
1. On JSON parse error: SKIP write entirely (not `current=[]`), backup corrupt file
2. Atomic write: write to tempfile, then `os.rename()` (atomic on same filesystem)
3. Lock file opened with `'a'` not `'w'` (avoid truncating before lock acquired)
