### 根因分析

**根因①：429 限流无重试（codex/claude-code/hermes）**
- gw_proxy.py (9092) 收到 gateway 返回 HTTP 429 ("当前请求额度已用完，请等待N秒后重试") 时，直接把 429 转发给 harness
- harness SDK（codex/claude-code/hermes）不处理 429 → 直接 fail → "quota-blocked" 或 "no-patch"
- 7路并发同时请求 → gateway per-key 限流 → 429 频繁

**根因②：Content-Type 重复 header（deepseek-harness）**
- gw_proxy_dsh.py (9093) 的 `_headers()` 方法用 case-sensitive dict：
  - `h[k]=v` 保留原始 `Content-Type` header（来自客户端）
  - `h["Content-Type"]="application/json"` 又加一个（大写，不同 key）
  - → http.client 发送两个 Content-Type header → gateway 返回 400 "Missing Content-Type: application/json header"
- 日志证据：`/tmp/dsh_proxy_requests.log` 多次出现 `--- RESPONSE 400 --- {"error":{"message":"Missing Content-Type: application/json header"}}`

### 修复

**gw_proxy.py（3处 proxy path 加 429 retry-with-backoff）**：
1. `_proxy()` — chat completions streaming path (codex/opencode/hermes/pi)
2. `_proxy_messages()` — Anthropic /v1/messages path (claude-code)
3. `_proxy_responses()` — OpenAI /v1/responses path (opencode)

retry 逻辑：
- 收到 429 → 解析 body 中的 "请等待N秒" → sleep N 秒 → 重试
- 最多 5 次重试，wait 上限 30 秒
- 新增 `_parse_429_wait()` 函数 + `_MAX_429_RETRIES=5` + `_429_WAIT_RE` 正则

**gw_proxy_dsh.py（同 429 retry + Content-Type dedup）**：
- `_headers()` 改用 lowercase key：`h[kl]=v` → `h["content-type"]="application/json"` 覆盖而非追加
- `_proxy()` 加同款 429 retry 逻辑
