## 唤醒588（02:10）🔴修复fullsource脚本严重bug轮

### 发现的问题

`run_tokenize_env14_fullsource.sh` 的 `is_running()` 函数存在 **SIGPIPE + pipefail bug**：

```bash
# 原代码（有bug）
is_running() {
  local shard="$1"
  pgrep -af 'preprocess_data_cm[.]py' 2>/dev/null | grep -qF "$shard"
}
```

**根因链条**：
1. `grep -qF "$shard"` 找到匹配后立即退出（`-q` 模式）
2. `pgrep` 还在写输出 → 收到 SIGPIPE → exit code = 141
3. 脚本开头 `set -o pipefail` → pipeline 返回最右侧非零退出码 = 141
4. `is_running` 返回 141（非零 = "not running"）
5. 脚本认为该 shard 没有在运行 → 重复 launch 新进程
6. 多个进程同时写同一个 `.bin` 文件 → corruption + `.idx` 永远无法生成

**手动测试确认**：`bash -c 'set -uo pipefail; pgrep -af "preprocess_data_cm[.]py" | grep -qF "CC-MAIN-2024-10"; echo exit=$?'` → exit=0（正常），但这是因为没有 `pipefail`。加上 `pipefail` 后，当 `pgrep` 被 SIGPIPE 杀死时返回 141。

### 受影响的 10 个 shard

所有 .bin 文件 timestamp = 02:19（当前时间），说明正被多进程同时写入。done 类 shard 的 .idx/.json 是旧时间戳，与正在重写的 .bin 不匹配 → 数据已 corruption。

2. **Kill 全部 32 个 preprocess_data_cm.py 进程**（`pkill -f 'miniforge3/envs/py310/bin/python3.10.*preprocess_data_cm'`，pkill 自身也被匹配但已完成任务）

4. **修复 `is_running()` 函数**：
   ```bash

     local shard="$1"
     { pgrep -af 'preprocess_data_cm[.]py' 2>/dev/null || true; } | grep -qF "$shard"
   }
   ```
   `{ pgrep ... || true; }` 确保 pipefall 只看到 `grep` 的退出码
5. **修复 `count_running()` 函数**：
   ```bash

     local n

   ```
