## #1359 2026-11-05 06:0x — ★ ROOT CAUSE FOUND: Q/K weights corrupted by undo_permute

**发现**：3.6 nats logit 偏差的根因已定位——**attention 层的 Q/K 投影权重在 GGUF 转换时被 permute 损坏**。

**方法**：
- Checkpoint A-D 全查 Mamba2 层(mamba-base.cpp/ops.cpp)均为 PASS，故转向「全权重逐张量对照」
- 脚本 /tmp/baize_e_all_weights.py：用 GGUFReader 读 f32 GGUF，用 NemotronHForCausalLM 读 HF float32，逐张量对比
- 结果：
  - attn_q.weight:  max_diff=0.150390  **DIFF!** (4.1M/4.2M 元素不同，相关系数仅 0.016)
  - attn_k.weight:  max_diff=0.151367  **DIFF!**
  - attn_v.weight:  max_diff=0.0       OK
  - attn_output:    max_diff=0.0       OK
  - 所有 Mamba2 (ssm_in/conv1d/A/D/norm/out): max_diff=0.0  OK
  - MLP/embeddings/output_norm/lm_head: max_diff=0.0  OK
- 只有 Q 和 K 被损坏（undo_permute 只碰 q_proj/k_proj）

**根因链**：
1. NemotronHModel(conversion/nemotron.py:425) 继承 GraniteHybridModel(granite.py:436)
2. GraniteHybridModel.undo_permute = True (granite.py:440)
3. llama.py:261-265: `if self.undo_permute: permute(q_proj/k_proj)`
4. permute() (llama.py:177-182): `reshape(n_head, 2, hd//2, n_embd).swapaxes(1,2).reshape()`
   = 将 HF interleaved RoPE 布局行重排为 GGML half-rotation 布局
5. 但 Nemotron-H 的 RoPE 实现不需要此 permute → 权重行被打乱
6. permute 非 self-inverse（数学证明：映射 a*64+b→b*2+a，再 permute 无法恢复）→ 不可逆损坏

**验证**：
- 手动逆映射 GGUF row h*128+b*2+a → HF row h*128+a*64+b
- Q (n_head=16, hd=128): max_diff=0.000000  完美恢复
- K (n_kv=4, hd=128): max_diff=0.000000  完美恢复

**影响**：56 层中 4 层 attention 的 Q/K 被打乱 → attention 算出错误 head scores → 级联放大 → 1-token 即偏 3.6 nats。Mamba2 层计算正确（A-D PASS 印证）。

**修复方案**：
- 方案 A（推荐）：NemotronHModel 类覆写 `undo_permute = False`（conversion/nemotron.py 加一行）
- 方案 B：改 GraniteHybridModel.undo_permute=False（影响 Granite，需验证）
- 改完重转 GGUF → 重跑 1-token logits 对齐（目标 |Δ|→0）→ sciq/piqa 复判

**落盘**：llamacpp.txt §六-B（根因定位 + 检查点 E 完成）+ §八（最终结论更新）已更新，commit f9890a208。
