### 关键发现

#### Bug 1: Label shift bug
- **数据预移位**：`input_ids = full[:, :-1]`, `labels = full[:, 1:]` (已在训练循环中完成)
- **HF model 内部再移位**：`modeling_xmodel2.py` L1209-1210 做 `shift_logits = logits[:,:-1]`, `shift_labels = labels[:,1:]`
- **结果**：HF path 实际预测 `full[t+2]` from `full[t]` (double shift)
- **Chunked CE 原始代码**：直接 `CE(lm_head(hidden[t]), labels[t])` = 预测 `full[t+1]` from `full[t]` (single shift) — **与 HF path 不一致**
- **修复**：`chunked_cross_entropy(hidden[:, :-1], lm_head, labels[:, 1:], ...)` — 复制 HF 的 double shift

#### Bug 2: μP logit scale bug
- **HF model** `modeling_xmodel2.py` L1203-1204: `logits = self.lm_head(hidden_states); if use_mup: logits *= mup_output_scale / mup_width_multiplier`
- **Config**: `mup_output_scale=1.0, mup_width_multiplier=6.0, use_mup=true` → scale = 1/6
- **Chunked CE** 直接调 `raw_model.lm_head(hidden)` → **绕过 μP 缩放** → logits 6x 过大
- **影响**：loss 爆炸 (66.7 vs 正确 11.6)
- **修复**：`chunked_cross_entropy` 新增 `logit_scale` 参数，调用方传 `mup_scale = config.mup_output_scale / config.mup_width_multiplier = 1/6`

#### `no_ddp_no_sync` flag 语义反转
- `--no_ddp_no_sync` **禁用** no_sync（flag 名意为 "no no_sync"）
- 默认 (不传 flag) = no_sync **启用**
- A2 测试证实 no_sync 提供约 6% 吞吐 (280K vs 298K)

#### `reduce-overhead` compile mode 不兼容
- CUDA graphs 要求静态计算图，但 Xmodel-2 MLP 有 in-place tensor 覆盖
- `mode="default"` 是唯一可用模式

### 修复验证
- 10 步 smoke test (MBS=4, chunked CE, compile default, no_sync default)
- Step 0 loss=**11.8094** (匹配 HF path ~11.7) ✅
- 稳态 timing: t_fwd_bwd=**391.5ms/micro** (与修复前 390ms 相同 → 零性能开销) ✅
- 吞吐: **299K tok/s** (与 MBS=2 baseline 298K 等价)

### 结论
- MBS=4 + chunked CE (修复后) 与 MBS=2 HF path **吞吐等价** (~299K tok/s)
- 此前报告的 "304K = 2% 提升" 是 bug 导致的假象（错误 loss 更容易 → 更少 backward 计算量？不，更可能是测量噪声）
- chunked CE 的真正价值：**VRAM 效率** — 避免 materializing [B, S, V] logits (4×3712×151936×2B = 4.5GB)，允许更大 MBS
- no_sync 提供约 6% 吞吐提升
