⚠️ Non-Comparability Declaration

All linear-probe (lp) accuracies in this report are measured under the BaiZe internal evaluation protocol (Protocol A or Protocol B) and MUST NOT be directly compared with published external numbers (e.g., CLIP zero-shot, OpenCLIP, MAE, DINOv2, iBOT linear-probe). The absolute lp values are only meaningful relative to other BaiZe-internal arms using the same objective, same data scale, same epoch count, and same evaluation protocol.

What IS directly comparable

  • Internal arm-vs-arm comparisons: E1fair vs E2fair (same objective, same data snapshot, same schedule, same evaluation protocol) → Δlp is valid.
  • Old vs fair schedule comparison: same arm, same data, different lr schedule → schedule artifact quantification is valid.
  • Protocol A vs Protocol B within the same arm: measures evaluation-protocol sensitivity (≈10pp), not model quality.

What is NOT valid

  • Comparing BaiZe ProtB lp (62.34%) with DINOv2 lp (~78%) or MAE lp (~68%) as if they measure the same thing — they do not. The gap reflects differences in objective, data, and protocol, not just model quality.
  • Inferring "our model is worse than DINOv2" from raw lp numbers without controlling for data scale (95.8M vs 142M) and objective (contrastive+dense vs pure self-supervised).

6. Conclusion & Limitations

6.1 Conclusion

  • The old "bigger is WORSE" conclusion (Δlp = −5.59pp) was a schedule artifact. Under a fair cosine schedule (lr=5e-4, warmup=2000, min_lr=5e-5), the −5.59pp effect vanishes entirely (+0.17pp).
  • At this budget, the two widths are indistinguishable. Δlp (Protocol B) = +0.17pp, well within the pre-registered ±1.5pp threshold. The sign flips across protocols (+0.17pp Prot B, −0.17pp Prot A), confirming no systematic width effect.
  • Consistent with data-limited regime: R9/R10 already established that in the data-limited regime (~96M pairs vs AIMv2's ~12B), tower widening yields no lp benefit. This fair rerun is consistent with that finding.
  • Training loss ≠ lp: E2fair has lower training loss (0.1579 vs 0.2545), meaning the wider model fits training data better, but this does not translate to higher linear-probe accuracy.

6.2 Limitations

  • Single budget point: This experiment tests only one training budget (~187k steps, ~96M pairs, 1 epoch). A single point does not constitute a scaling law. The "indistinguishable" conclusion is specific to this budget.
  • Data-limited regime: Our ~96M image-text pairs are 102× smaller than AIMv2's ~12B. The conclusion may not hold at larger data scales.
  • Two widths only: Only two model widths (w512=126.78M, w768=284.54M) were tested. A fuller scaling study would need ≥3 points to fit a power law.
  • Single training seed: Training uses seed=1234 (single run). Only evaluation uses 3 seeds. Training-seed variance for Δlp is not measured.
  • Old results not re-evaluated: The old E1/E2 checkpoints are preserved but were not re-evaluated under Protocol B with 3 seeds — only original single-seed numbers exist for them.
  • Non-comparability with external benchmarks: All lp values use the BaiZe internal protocol (ProtA/ProtB). They are NOT comparable with published CLIP/MAE/DINOv2/iBOT numbers due to differences in objective function (AIMv2-style InfoNCE+MSE ≠ pure contrastive / pure self-supervised), data scale (95.8M pairs vs 142M–2B), frozen text tower, and evaluation protocol details. See §1.5 for the full disclosure.

8. Same-Model Zero-Shot Evaluation (① — "Did features benefit from text alignment?")

8.1 Protocol

To answer whether the visual features actually benefited from the frozen CLIP text-tower supervision, we evaluate the model's own zero-shot classification on the official IN-1k validation set (50,000 images). This is not an external benchmark — it uses the same model, same contrastive head, and same frozen text tower that were trained together.

Pathway: ViT → ReadoutHead(768-d) → cosine similarity vs frozen CLIP text tower × 80 OpenAI templates × 1,000 IN-1k class names → argmax.

The learned logit_scale (temperature) does not affect argmax — raw% = top1%.

9.2.1 Interpretation

  • LP − k-NN = 24.66pp: The linear probe learns a significant transformation beyond raw feature similarity. This gap is typical for self-supervised features at this data scale (cf. MAE: 33pp gap; DINOv2 with 142M data: 6pp gap).
  • Conclusion: The features are not weak (37.68% k-NN ≫ 0.1% random), but the probe is not underfitting either — the 62.34% LP is a fair readout of feature quality at this training budget. The bottleneck is data scale, not probe capacity.
