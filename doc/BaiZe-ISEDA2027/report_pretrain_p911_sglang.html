3. 假说验证（H1–H4）

H1: prefill 吞吐优势随 ctx 增长（SSM O(n) vs attn O(n²)）

ctxbs=1 prefill h/dbs=8 prefill h/d
40960.14x0.95x
163840.21x0.97x
655362.18x1.04x

H1 ✅ CONFIRMED

bs=1: 0.14x(4K)→0.21x(16K)→2.18x(64K)，交叉点在 16K-64K。这正是 SSM O(n) vs attention O(n²) 的理论预测。bs=8 时交叉较弱（1.04x at 64K），因 batching 摊销了 attention 的 O(n²) 成本。

H2: decode 吐吐优势随 ctx 增长

ctxbs=1 decode h/dbs=8 decode h/d (excl warmup)
40960.91x— (warmup)
163840.91x0.36x
655361.18x0.78x

H2 ⚠ PARTIALLY CONFIRMED

bs=1: 0.91x(4K/16K)→1.18x(64K)，交叉点在 ~50K。hybrid decode 优势在长 ctx 下开始显现但幅度不大。bs=8: 0.36x(16K)→0.78x(64K)，呈上升但 hybrid 仍慢于 dense。原因：sglang 对 dense GPT 的 KV cache 做了高度优化（PagedAttention），nemotron_h 的 Mamba2 SSM 在 sglang 中 decode 路径优化不及 dense。与 P-9.10③ mcore eager 的恒定 1.6× 不同——mcore eager 的 launch 开销掩盖了 ctx 效应，sglang 生产栀下交叉点在 ~50K 更真实。

VRAM 比值几乎恒定 0.97-0.98x，不随 ctx 增长。原因：--mem-fraction-static 0.85 预分配 ~68GB，实际 KV cache/SSM state 差异被掩盖。P-9.10③（自定义 benchmark）在非预分配模式下量到 hybrid VRAM 0.22×-0.44× at 128K，那才是 H3 的正确验证。

关键差异：
  • P-9.10③ mcore eager 的恒定 1.6× decode 优势不可信——mcore eager 每步都有 Python→CUDA launch 开销，掩盖了 ctx 对 decode 的影响。
  • P-9.11 sglang 使用 CUDA graph + PagedAttention，消除了 launch 开销，decode 交叉点出现在 ~50K（1.18× at 64K），更真实。
  • VRAM：sglang 静态预分配掩盖了差异；P-9.10③ 的直接测量（0.22-0.44× at 128K）更可信。
  • 128K：P-9.10④ 量到了（hybrid 13GB vs dense 61GB），sglang 因 max_pos=4096 未能跑通。

5. 128K 失败分析

128K context 对两个模型均失败（total_completion_tokens=0, TTFT=null, e2e≈0.5s）。两模型 max_position_embeddings=4096，sglang 以 --context-length 131072+SGLANG_ALLOW_OVERWRITE_LONGER_CONTEXT_LEN=1 启动，4K/16K/64K 均成功（RoPE 外推），但 128K（32×训练长度）被服务器拒绝。失败模式：e2e≈0.5s（立即返回），非超时/非 OOM。这是预期行为：模型从未在 >4K ctx 上训练，128K RoPE 外推已超出有效范围。如需 128K 推理能力，需在 P-8 阶段增加长序列训练。

6. 结论

假说P-9.10③ mcoreP-9.10④ customP-9.11 sglang综合裁定
H1 prefill↑ctx✅ 3.7-23×✅ 3.7-23×✅ 0.14→2.18×✅ CONFIRMED
H2 decode↑ctx⚠ 1.6× constant(masked)❌ d faster⚠ 0.91→1.18×⚠ PARTIAL
H3 VRAM↑ctx—✅ 0.22-0.44×❌ masked✅ via P-9.10④
H4 state const—✅ 0.20-0.48×—✅ via P-9.10④

综合裁定：

  • H1 ✅ CONFIRMED：hybrid prefill 优势随 ctx 增长，交叉点 ~16K-64K（sglang: 2.18× at 64K×1）
  • H2 ⚠ PARTIAL：hybrid decode 优势在 sglang 生产栀下于 ~50K 交叉（1.18× at 64K×1），但幅度不大；mcore eager 的恒定 1.6× 是 launch 开销伪影，不可信
  • H3 ✅ (via P-9.10④)：hybrid VRAM 0.22-0.44× at 128K（非预分配模式）；sglang 静态预分配掩盖了差异
  • H4 ✅ (via P-9.10④)：hybrid SSM state 恒定，仅 4 层 attention KV 线性增长

论文回填建议（§5 推理效率）：

  • prefill 加速：sglang 64K×1 的 2.18×（最可信的生产栀数据）
  • decode 加速：sglang 64K×1 的 1.18×（生产栀，交叉在 ~50K），不要用 mcore eager 的恒定 1.6×
  • VRAM 优势：P-9.10④ 的 0.22-0.44× at 128K（非预分配直接测量）
  • 128K 限制：如实说明 max_pos=4096，生产栀 128K 不可用
  • 三栀交叉验证：mcore eager(下界)→sglang(生产栀)→custom(无限制)一致确认 H1/H3/H4，H2 在生产栀下为弱确认
