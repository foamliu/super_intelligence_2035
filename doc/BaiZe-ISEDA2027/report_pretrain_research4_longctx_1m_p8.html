1. TL;DR

Five key conclusions:

  1. ABF (rope_theta=1e6) enables training-free extension to 1M with zero quality degradation — PPL stays 52.99–55.42 from 128K to 1M, compared to baseline 4K PPL=75.36 (B1 measured). [Measured] Only 4/56 layers use RoPE; 24 Mamba2 SSM layers have no positional encoding, so position-OOD risk is confined to 7.1% of layers. [Measured]
  2. Passkey retrieval = 0% at all context lengths — this is a model capability problem (2.2B + 20B tokens), not a context extension problem. Generating reasonable needle-in-haystack scores requires either (a) 100B+ training tokens or (b) targeted long-context fine-tuning. [Measured]
  3. The real bottleneck at ≥512K is the 4 attention layers' O(n²) cost, not RoPE quality or VRAM — at 1M, attention occupies ~77% of prefill time (B1 fitted). VRAM is only 34.68GB at 1M bs=1 (vs dense OOM at 1M). [Measured]
  4. maxpos_only (raise max_position_embeddings without rope_theta) = catastrophic NaN — all context lengths produce NaN. Extension must use ABF or YaRN, not bare max_pos increase. [Measured]
  5. Target context = 32K–128K (SWE-bench + EDA agentic sessions), not 1M. 1M is redundant capability that proves the SSM architecture has no hard ctx ceiling. P-8 should train at seq=4096 (fastest, 249K tok/s) and apply ABF at inference. [Measured] + [Inferred]

2. Our Current State (Measured Data)

2.1 Architecture: Why Hybrid Is Built for Long Context

56-layer Nemotron-H hybrid pattern (from P-6 ckpt conversion, EXPERIMENTS_PRETRAIN_2B_ROUND2.md P-6 section):

  • 4 full-attention layers (7.1%) — use RoPE position embeddings
  • 24 Mamba2/linear-attention layers (42.9%) — no positional encoding (SSM recurrent state is position-agnostic)
  • 28 MLP/FFN layers (50.0%) — no position dependence

Key implication: Only 4/56 = 7.1% of layers face position extrapolation risk when ctx > training length. A pure dense Transformer (our baseline: 42 attn layers) has 100% of layers at risk. [Measured·This project]

Three critical findings [Measured]:

  • ABF tax at 4K: PPL 83.24 vs baseline 75.36 = +10.5% — raising rope_theta from 1e4 to 1e6 slightly degrades the training-length performance, but PPL decreases with longer context (normal causal LM behavior).
  • 1M PPL = 55.42, no degradation — stable across 128K–1M (52.99–55.81). RoPE extrapolation quality is not the bottleneck.
  • maxpos_only = all NaN: raising max_position_embeddings from 4096 to 131072 without changing rope_theta causes high-frequency components to overflow → cos/sin table explosion → global NaN (even at 4K). Extension must use ABF/YaRN, not bare max_pos increase.

2.3 B Experiment: Passkey = 0% + ABF Zero-Shot Downstream

Source: EXPERIMENTS_PRETRAIN_2B_ROUND2.md §B, §B1. [Measured]

  • Passkey retrieval = 0% at ALL context lengths (4K, 8K, all configs) — the 2.2B model trained on 20B tokens cannot perform passkey retrieval regardless of context. This is model capability, not context extension. Needle-in-haystack = 0 currently.
  • ABF does NOT hurt short-context downstream tasks (B experiment, ABF rope_theta=1e6, max_pos=8192):
    • HellaSwag: baseline 0.371 → ABF 0.398 = +2.71pp (improved!)
    • ARC-Easy: 0.557 → 0.564 = +0.72pp (improved!)
    • MMLU: no significant change
    ⇒ ABF is safe for short-context quality. The +10.5% PPL tax at 4K does not translate to downstream task degradation.

3. External Evidence

3.1 YaRN: Training-Free Context Extension

YaRN (Peng et al., 2023, arXiv:2309.00071) — “YaRN: Efficient Context Window Extension of Large Language Models”. [Primary literature]

  • URL: https://arxiv.org/abs/2309.00071 (2023)
  • Mechanism: NTK-aware frequency scaling + piecewise interpolation + attention temperature correction. Scales rope_theta by factor s with wavelength-dependent blending: high-frequency dims keep original rotation, low-frequency dims stretch.
  • Result: LLaMA-7B/13B extended 4K→128K with ~400 tokens of continued pretraining; needle-in-haystack near-perfect at 128K. Requires ~100M–1B tokens of continued pretraining for best quality (vs pure ABF which is zero-shot).
  • Relevance to us: Our ABF (rope_theta=1e6) is a simplified version of YaRN. YaRN would likely give better 1M PPL, but requires continued pretraining. [Inferred]

3.2 ABF / NTK-aware Scaling: Zero-Shot Alternatives

NTK-aware scaling (community, 2023) and ABF (Adjusted Base Frequency). [Primary literature]

  • NTK-aware: scale base frequency by s^(d/(d-2)) — high-freq dims barely change, low-freq dims stretch. Works zero-shot for 4–8× extension.
  • ABF (our approach): simply set rope_theta = 1e6 (100× the default 1e4). Crudest form — uniform scaling without wavelength-aware blending.
  • Key comparison (yobitel.com survey, 2025): YaRN requires ~100M–1B tokens continued pretraining but achieves better long-context perplexity and NIAH. Qwen 2/3 use YaRN. [Secondary]

3.3 Long-Context Training Curriculum

Short-to-long curriculum (industry practice, 2024–2026). [Primary literature]

  • Consensus recipe (cyk1337.github.io survey, 2026): 85–95% compute at 8K, final 5–15% at 128K mid-train, RoPE base 5e5–1e6. Same compute, 20–40% wallclock reduction, no long-context quality degradation. [Secondary]
  • Mechanism: Progressive doubling (8K→16K→32K→128K) avoids weird positional priors. [Secondary]
  • Packing: FlashAttention varlen per-doc causal mask (packing ratio >98%, <3% throughput loss). [Secondary]

3.4 Needle-in-Haystack / Passkey Evaluation

NIAH (Kamradt, 2023) and RULER (Hsieh et al., 2024, arXiv:2404.06654). [Primary literature]

  • NIAH tests single-needle retrieval. RULER extends to multi-key, aggregation, variable tracing.
  • Passkey (Mohtashami, 2023, arXiv:2305.20050): simplest NIAH variant. Our 0% = model cannot do even this.
  • Key insight: NIAH/passkey depends on both context extension method and model capability. A 2B model at 20B tokens may lack the retrieval circuit; 100B+ tokens or targeted fine-tuning needed. [Inferred]

3.5 Nemotron-H: Architecture Context

Nemotron-H (NVIDIA, 2025). [Primary literature]

  • Nemotron-H-8B: 52 layers, 4 self-attention layers (~8%), 24 Mamba-2, 24 FFN — identical attn ratio to our 2.22B (4/56=7.1%). Trained on 4T tokens.
  • Nemotron-H-56B: 118 layers, 10 attention (~8.5%), 54 Mamba-2, 54 FFN.
  • Relevance: Our 7.1% attn ratio matches NVIDIA's design. NVIDIA trains 4T tokens; we plan 100B — the gap explains our passkey=0%. [Primary]

3.6 Sliding Window / NoPE for Attention Bottleneck

NoPE (Kazemnejad et al., 2023, arXiv:2305.16810) and Sliding Window Attention (Mistral 7B, arXiv:2310.06825). [Primary literature]

  • NoPE: Removing RoPE allows training-free extrapolation to 4× training length.
  • Sliding window: Limit attention to local window w → O(n·w)=O(n). Mistral 7B uses 4K window.
  • Relevance: Our bottleneck (c) could be addressed by either. Only 4/56 layers affected → small migration. [Inferred]

4. Candidate List

C1: Keep seq=4096 for P-8, apply ABF (rope_theta=1e6) at inference P0 Recommended

① Motivation: B1 proved ABF extends 4K→1M with no PPL degradation; training at 4K is fastest (249K tok/s vs 210K at 8K, P-9.7 -16%). ② Expected: Zero training cost; full 1M capability at inference. ③ Cost/risk: ABF tax +10.5% PPL at 4K, but B proved no downstream degradation. ④ Verifiable: PPL 4K–1M <60; passkey improves with more tokens. ⑤ Priority: HIGH.

C2: Decay segment raise seq to 8192 (optional free insurance) P1 Optional

① Motivation: Decay segment is ~10% of training. Raising to 8K gives real training data at 8K. ② Expected: Better 8K–32K quality. ③ Cost: ~0% wallclock. ④ Verifiable: PPL@8K with decay-8K < ABF-only. ⑤ Priority: MEDIUM.

C3: YaRN with ~400M–1B tokens continued pretraining (post P-8) P1 Post-P-8

① Motivation: YaRN's piecewise schedule + attention temperature gives better 1M PPL. ② Expected: Better NIAH/passkey at 128K–1M. ③ Cost: ~1–3 GPU·h; needs YaRN implementation. ④ Verifiable: NIAH >50% at 128K; PPL@1M < 55.42. ⑤ Priority: MEDIUM.

C4: Long-context data mixture in P-8 decay segment P1 During P-8

① Motivation: NIAH requires seeing long-range retrieval patterns. Include long docs (32K–128K) in decay phase. ② Expected: NIAH >0% without separate fine-tuning. ③ Cost: packing efficiency if seq stays 4K. ④ Verifiable: Passkey >0% after 100B tokens. ⑤ Priority: MEDIUM.

C5: Sliding window attention for 4 attn layers (post P-8, if ≥512K needed) P2 Future

① Motivation: O(n²) bottleneck is 4 attention layers. Sliding window makes attention O(n). ② Expected: 1M prefill ~40s (from 172s). ③ Cost: retrain; only 4/56 layers. ④ Verifiable: 1M prefill <60s; PPL@1M <60. ⑤ Priority: LOW.

C6: NoPE for 4 attention layers (experimental, post P-8) P2 Experimental

① Motivation: NoPE allows training-free extrapolation to 4× training length. ② Expected: No rope_theta tuning. ③ Cost: retrain; NoPE in hybrid unstudied. ④ Verifiable: PPL@16K < ABF's 60.08. ⑤ Priority: LOW.

C7: RULER benchmark suite (evaluation, no training cost) P0 Evaluation

① Motivation: RULER tests multi-key, aggregation, variable tracing — more comprehensive than passkey. ② Expected: Better understanding; track improvement. ③ Cost: ~1 GPU·h per checkpoint. ④ Verifiable: RULER at 4K/16K/64K/128K. ⑤ Priority: HIGH.

5. Recommended Route + Time Box

Phase 1 (P-8 training, immediate):

  1. Adopt C1 (seq=4096 + ABF at inference): P-8 trains at 4K (fastest, 249K tok/s, ~12.5 days for 100B). Apply ABF (rope_theta=1e6) in HF config for serving. Zero additional cost. Already validated by B1.
  2. Adopt C4 (long-context data in decay): Work with data agent to include long docs (32K–128K) in decay/annealing mixture. Most likely lever to get passkey >0%. Cost: ~0.
  3. Optionally adopt C2 (decay seq=8192): Near-free insurance for 8K quality.

Phase 2 (Post P-8, if 1M NIAH >0% needed):

  1. Adopt C7 (RULER evaluation): Evaluate each checkpoint with RULER at 4K/16K/64K/128K.
  2. Adopt C3 (YaRN continued pretraining): If P-8 @100B still gives passkey=0%, apply YaRN with ~400M–1B tokens. Cost: ~1–3 GPU·h.

Phase 3 (Only if ≥512K latency required):

  1. Consider C5 (sliding window) or C6 (NoPE) — both need retraining, only 4/56 layers. Not needed for target 32K–128K.

Time box summary:

  • P-8 training (C1+C4): 12.5 days @100B tokens (no additional long-context cost)
  • RULER eval (C7): ~1 GPU·h per checkpoint, ~10 GPU·h total
  • YaRN continued pretraining (C3, if needed): ~1–3 GPU·h post P-8
  • Sliding window/NoPE (C5/C6, if needed): full retrain ~12.5 days (only if ≥512K required)
