为什么两轮都呈负相关？

  • R1：objective = 验证集 loss。更低 loss 的配比 → 更"拟合验证集"→ 但验证集与下游任务分布不同 → 过拟合 loss 反而降低下游能力。ρ = −0.43。
  • R2：objective = lm_eval --limit 500。500 样本子集上的高分区比 → 可能利用了子集偏差（小样本噪声）→ 在全量评测（>10K 样本）上无法泛化。ρ = −0.80（更强负相关）。
  • 共同根因：代理模型仅 18.36M 参数 + D ≤ 0.5B tok → 模型欠训，不同配比间的"能力差异"被噪声淹没。代理指标的排名信号 不可靠。

R2 全量 lm_eval 比 R1 提升明显：avg 从 ~0.335 → ~0.388（+15.8%），主要归因于 D 从 0.016B → 0.5B（31×）。

但 top-5 内部 spread 仅 0.3835–0.3899（Δ=0.006, 1.6%），接近噪声水平 —— 配比差异在当前代理规模下不可靠区分。

推荐值取 BO 最优与全量最优的折中。math=0.01 是搜索空间下界，BO 未找到 math > 0.01 的优势区域（在 18.36M 代理上）。

关键提醒：该配比基于 18.36M 代理模型，直接迁移到 2.2B 的可靠性 未经验证。

根据 ye2024datamixinglaws 数据混合定律，最优配比随模型规模变化 —— 小模型偏好高 web 占比是因为 web 数据的"每 token 信息密度"对小模型最有效；大模型可能从 code/math 中获益更多。

建议：将 web=0.93, code=0.10, math=0.01 作为 先验锚点，在 2.2B 正式训练中保留 ±5% 的调整空间，特别是 math 占比可能需要在 2.2B 上重新搜索。

6. 限制与迁移性说明

已知限制

  1. 代理规模 ≠ 2.2B：代理仅 18.36M（d=128, L=14），与目标 2.2B（d=512, L=14）差 120×。配比结论的迁移性受 ye2024datamixinglaws 约束，需在 2.2B 上验证。
  2. D = 0.5B tok/trial：正式训练 D ≈ 100B+（200×差距）。配比在极欠训条件下的排序，可能与充分训练后不同。
  3. 代理指标不可靠：两轮 BO 的 Spearman ρ 分别为 −0.43 和 −0.80，均为 负相关 —— 代理指标（loss 或 lm_eval --limit 500）不能可靠预测全量下游任务表现。
  4. top-5 内部 spread 小：全量 lm_eval avg spread = 0.006（1.6%），接近统计噪声 —— 在当前代理规模下，不同配比的 区分度不足。
  5. math 搜索不充分：搜索空间 math ∈ [0.01, 0.17]，但 BO 收敛到 math≈0.01 下界 —— 可能是代理模型太小无法利用 math，而非 math 本身无价值。
  6. 仅 Stable 段：Decay 段（SFT 配比）未在本轮搜索，需后续补充。
  7. 34 个 failed trials：t1–t34 均失败（初始批次 GPU 分配问题），从 t35 起恢复正常。不影响 BO 搜索质量（Optuna 从失败 trial 中不学习参数关系）。

结论：BO R2 在 18.36M 代理上搜索 Stable 段配比，最优区域为 web ≈ 0.93, code ≈ 0.10, math ≈ 0.01。但代理指标与真实能力呈强负相关（ρ=−0.80），且 top-5 区分度接近噪声水平 —— 配比推荐应作为先验锚点而非最终答案，在 2.2B 正式训练中需保留调整空间。
