📋 TL;DR — TOP 5 推荐

现有训练用图文对 ≈ 59M（GPIC + CC12M + Amshaker）。本次在 HuggingFace 上系统检索了 13 个候选数据集，以 image 列是否为 Image feature（内嵌字节）为硬筛条件，得出以下推荐：

1
MVRL/WebMix-38M — ✅ Image bytes 38.8M 对 2 TB
HF Image 列格式存储编码字节（parquet + ZSTD 压缩）。来源 = CC12M + DataComp12M + YFCC15M + MSCOCO。与现有 CC12M 有重叠，但补充了 DataComp12M + YFCC15M 两个新源。推荐度：★★★★☆
2
VedaLabs/wit_base（= wikimedia/wit_base）— ✅ Image bytes 6.48M 对 CC BY-SA 4.0
API 确认 features['image'] == {'_type':'Image'}。300px 维基百科图像，108 种语言（含中文），多字段 caption。与现有数据零重叠。推荐度：★★★★★
3
BLIP3o/BLIP3o-Pretrain-Long-Caption — ✅ Image bytes ~27.2M 对 Apache-2.0
WebDataset tar（内嵌 jpg），SA-1B 图像 + VLM 长 caption。已在本地盘（2891 tar / 1.3T）。推荐度：★★★☆☆
4
hanlincs/InternVL-SA1B-Caption-WebDataset — ✅ Image bytes ~22.4M 对 Apache-2.0
WebDataset tar（内嵌 jpg），SA-1B + InternVL caption。与 BLIP3o 共享源图但 caption 不同。未在本地。推荐度：★★★☆☆
5
HuggingFaceM4/the_cauldron — ✅ Image bytes ~1.9M 对 50 子集
images 列 = Image list（字节嵌入 parquet）。VQA 指令格式，更适合 SFT 非预训练。推荐度：★★☆☆☆
关键结论：在 HF 上，大规模（>1M 对）且 image 列直接存字节的图文对数据集不多。大量知名数据集（COYO-700M、DataComp-1B、PixelProse、RedCaps、LAION 系）在 HF 上仅存 URL，需额外用 img2dataset 抓图。WebMix-38M 和 WIT 是本次最值得关注的两个。

§2 筛选口径与 bytes/url 判定法

2.1 判定方法

判定层方法✅ bytes 证据❌ URL 证据
最硬HF datasets-server /info APIfeatures['image'] == {'_type':'Image'}features['url'] == {'dtype':'string'}，无 image 列
次硬HF dataset card YAML headerdtype: image（在 features 中）无 image 列，仅 url 列
辅助HF dataset page Dataset Viewer显示 PIL Image 缩略图 / imagewidth(px) 列显示 URL 字符串列
辅助HF dataset page 文字描述"Images stored in Image column format as encoded bytes""parquet containing image URLs" / "Download Images (second step)"

2.2 逐条筛选口径

#维度口径
1image 载体✅ Image feature(bytes) / {bytes,path} vs ❌ string(url) / {url}
2规模图片对数 + 总字节
3许可cc-by(-sa) / mit / apache / 未标注
4caption短/长 caption、alt-text；语言 en / zh / multi
5是否已用GPIC / CC12M / Amshaker / LAION 系须标注
6可达性HF 直连/镜像、是否 gated
技术说明：HF 的 Image feature 在 parquet 中以 struct 类型存储，含 bytes（二进制，JPEG/PNG 编码）和 path（文件名）两个子字段。加载时 datasets 库自动解码为 PIL Image。URL-only 数据集仅存 string 类型的 URL 列，需 img2dataset 或 ThreadPoolExecutor+urllib 抓图。

§6 与现有数据（GPIC / CC12M / Amshaker）的互补性分析

Amshaker/Mobile-O-Pre-Train2250 tar / 3.7T (~6M 对)移动端交互场景短描述

互补性矩阵

候选数据集与 GPIC 重叠与 CC12M 重叠与 Amshaker 重叠互补价值
WebMix-38M低⚠️ 高（含 CC12M 子集）低✅ 补充 DataComp12M + YFCC15M 两个新源（~20M+ 新对），但 CC12M 部分重复
WIT (wit_base)无无无✅ 完全互补。Wikipedia 来源,与 web-crawl 数据零重叠。多语言（含中文）独特维度
BLIP3o低低低⚠️ SA-1B 图像来源独特（高质量分割图），但长 caption 风格与现有短 caption 不一致
InternVL-SA1B低低低⚠️ 同 SA-1B 源图（与 BLIP3o 重叠），但 caption 生成模型不同
the_cauldron低低低✅ VQA 格式,领域多样（图表/文档/科学/视觉推理），但非 caption 对
互补性结论：
  • WIT 是最佳互补——来源独特（Wikipedia vs web-crawl）、多语言（108 种含中文）、与现有数据零重叠,且 CC BY-SA 4.0 许可清晰。
  • WebMix-38M 量大但有重叠——CC12M 子集与现有重复,但 DataComp12M + YFCC15M 部分是新的。若需补量且不在意部分重复,可考虑。
  • BLIP3o / InternVL-SA1B——SA-1B 图像质量高,但 caption 偏长,适合 VLM 对齐阶段而非纯视觉编码器对比预训练。
  • the_cauldron——更适合 SFT / 指令微调,不适合预训练阶段。

§7 风险声明与诚实条款

1. API 验证不完全：本次通过 HF datasets-server /info API 仅成功验证了 VedaLabs/wit_base 一个数据集的 Image feature（返回 {"_type":"Image"}）。其余数据集因 API 超时 / 数据集过大 / 限流等原因未能通过 API 直接验证,其 bytes 判定基于：
  • HF dataset card 页面原文描述（如 WebMix-38M 的 "Images are stored in the Hugging Face Image column format as encoded bytes"）
  • HF Dataset Viewer 显示的列类型（Image 列 vs string URL 列）
  • YAML header 中的 dtype: image 声明
  • WebDataset 格式的 tar 文件天然内嵌图像字节
这些证据可信但非 API 级硬证，建议实际下载前用 load_dataset(..., streaming=True) 取首行二次确认。
2. 规模估计不确定：WIT 的总磁盘大小（~200-400 GB）和 InternVL-SA1B（~1-1.5 TB）为基于图像分辨率和数量的估算,非 HF 官方标注。WebMix-38M 的 2 TB 为 HF 页面标注值。
3. 重叠风险：
  • WebMix-38M 包含 CC12M 子集——与现有本地 CC12M（1100 tar / ~11M 对）有直接重叠。如需去重,须做跨集图像哈希比对。
  • BLIP3o 和 InternVL-SA1B 均使用 SA-1B 源图——两者之间有图像重叠,caption 不同。
  • PixelProse 包含 CC12M + RedCaps + CommonPool 子集——若用 PixelProse 的 caption + 自抓图,与现有 CC12M 也有重叠。
4. 许可风险：
  • WebMix-38M 在 HF 页面未标注总许可——其子源（CC12M=未标注、DataComp12M=CC BY 4.0、YFCC15M=各异、MSCOCO=CC BY 4.0）许可不同,使用前须逐子源确认。
  • WIT 的 CC BY-SA 4.0 要求衍生作品同样以 CC BY-SA 4.0 发布（传染性许可）,训练模型发布时需注意。
5. 本次调研边界：
  • 本次仅调研 + 出报告,不下数据（运维指令明令）。真下载须运维二次确认。
  • 调研不占 GPU，web 请求不占 NFS 带宽，未打断 85M / en_v1_4 下载。
  • 调研覆盖了任务书指定关键词（image-text pairs / caption / interleaved / alt-text / DataComp / pixelprose / redcaps / mmc4 / OBELICS / MINT / wit / datacomp），但不保证穷尽 HF 上所有符合条件的数据集。
  • 未覆盖 ModelScope / 其他平台上的数据集（DanQing100M 在 ModelScope 有全量 12TB 含图数据,本次仅在 HF 范围内标注其 URL-only 状态）。
6. 磁盘约束：当前 /nas_train ~85%（剩 ~32T），85M 剩余 ~17TB + en_v1_4 剩余 ~4.3TB → 85M 下满将达 ~93.6%（超 90% 红线）。在 85M/en_v1_4 下完前不建议启动新的大规模下载。
