权衡：Mamba2 的 SSM 前向/反向计算更密集，训练吞吐落后 ~24%；若以「训练吞吐」为第一优先级选 MiniCPM5，否则选 Mamba2。

1⚠️ 关键修正：Mamba2 真实参数量 = 2.220B（非 3.00B）

执行 S3 推理基准时，用 sum(p.numel()) 实测 Mamba2-hybrid 参数 = 2,220,268,032（2.220B），与此前记录（3.00B）不符。

  • 根因：3.00B 来自 mcore 的 Number of parameters in transformer layers in billions: 2.47 + embedding 0.53 打印——该打印对 Mamba/hybrid 误把全部 56 层按 full attention+MLP 计，而实际绝大多数层的 SSM 权重远小于 attention，故虚高 ~0.78B。
  • 两处独立实测一致：训练日志 rank(0,0)=2220268032 + 推理脚本 sum(numel())=2220268032。
  • 结论修正：两架构基本等参（MiniCPM5 仅多 ~13%），不再是「非等参 +19.5%」。这使 Mamba2 的「更低 loss + 更少参数」结论更强。

5综合结论

  • 质量/效率：Mamba2-hybrid 以更少参数达到更低 loss，loss-per-parameter 明显占优（2 项：loss + 推理速度）。
  • 吞吐：MiniCPM5-2B 训练吞吐快 ~24%（SSM 前向/反向计算密集是 Mamba2 的软肋）。
  • 部署：Mamba2-hybrid 推理（尤其 decode）占优，适合推理场景。
  • 最终推荐：Mamba2-hybrid 为本次搜索胜出架构（2/3 维度占优 + 更少参数）。
  • 局限：仅 1000 步早期收敛（loss ~4.7，远未收敛），且 MiniCPM5 decode 需复核；建议择胜出架构跑更长步数 + 用 SGLang 复核 decode 后定稿。
