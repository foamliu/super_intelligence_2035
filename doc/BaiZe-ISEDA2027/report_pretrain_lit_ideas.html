1Conditional Transfer from Controlled Pretraining Mixtures to Code 数据配比 仅灵感

出处
Conditional Transfer from Controlled Pretraining Mixtures to Code
arXiv:2610.11548 ｜ 2026-10-08 ｜ research日报10-10#2
一句话
区分三信号—diagnostic(loss是否跟踪全局进展)、teachable(loss是否响应自身token预算)、transfer(纳入后是否改善下游)—受控预训练固定70%Python、30%做单纯形配比扫描，发现「可教≠有用」且「loss自适应调度器背离下游」(Ado把OpenCodeInstruct压到~1%后比固定配比差2.4–11.0pp)。
与本线关系
直击BaiZe数据配比核心(R3 BO刚完成、P-8 decay配比已定、100B档待规划)。
(a) R3搜索：套用「固定主干+30%单纯形扫描」受控消融协议，升级为三信号分离评估；
(b) P-8 decay SFT64%：来源分层「先过transfer关而非loss关」；
(c) 100B档：反直觉「loss自适应背离下游」=直接警告—若用loss反馈调配比须以下游lm_eval而非残余loss做控制信号。
借鉴成本
GPU·h:0(纯读)；落地~8 GPU·h(小规模单纯形~500M token)。墙钟:读~2h+复现~1天。依赖:无。
风险
①单作者，审稿未知；②仅代码域，web/math迁移未验；③27任务中14可教，比例受任务选择影响；④pass@20 15.9→22.6小规模，统计显著性未报。
价签
可行9×潜力8=72(本批最高)
我们判断：最立即可执行—价值不在某数字，而在「不要被loss下降骗了」的方法论判据。BaiZe R3用BO优化下游lm_eval(已对齐transfer)，但「可教性」「诊断性」尚未分离。建议P-8完成后100B档数据规划阶段做三信号分离评估。

2On the Recall Scaling Laws in Mamba 架构/规模律 有代码

出处
On the Recall Scaling Laws in Mamba: A Theoretical and Mechanistic Study via Hashing
arXiv:2609.07681 ｜ 2026-09 ｜ TOP_K#15
代码:github.com/yuvalko1/mamba-recall-scaling-laws ｜ 53p,20fig
一句话
从理论+机制(hashing视角)刻画Mamba的recall(精确回忆)规模律，解释SSM在精确回忆上的能力边界与随规模走向。
与本线关系
直接支撑Mamba2-hybrid架构选型(52SSM+4Attn)。
(a) P-3选型复核:52:4比例基于经验，此论文给「哪些能力(recall/检索)归attention、哪些(长程聚合)归SSM」理论依据→验证或修正比例；
(b) 规模外推:2.22B→更大规模时SSM recall预期走向可预测；
(c) P-6 scaling law交叉验证:BaiZe已有48/48 runs R²=0.986，可与recall专项规模律交叉验证。
借鉴成本
GPU·h:~4(小规模recall测试,对照现有ckpt)；墙钟:读~3h+实验~0.5天；依赖:可用BaiZe现有ckpt(iter_1049~4196)+论文代码。
风险
①理论基于特定Mamba构造，Mamba2直接适用性待验(SSD结构不同)；②hashing是近似模型；③53页需精读。
价签
可行8×潜力8=64
我们判断：混合架构是论文核心卖点，但52:4缺理论支撑。此论文给「recall归attention、长程聚合归SSM」的机制解释—在BaiZe ckpt上复现recall测试→给§3架构补理论依据。建议P-8完成后用其代码对final ckpt做recall评估。

3PHBA: Prefix-State Hybrid Block Attention 混合架构 仅灵感

出处
PHBA: Prefix-State Hybrid Block Attention
arXiv:2610.08527 ｜ 2026-10-06 ｜ research日报10-08#1
一句话
在「线性序列模型+softmax注意力」混合架构里，把固定滑窗注意力换成top-k块稀疏检索，每个被检索块附带紧凑「前缀状态」(块边界门控线性递推生成)，同层内同时拿精确远程证据+压缩历史；给硬件友好Triton实现，流式处理不落地大中间张量。
与本线关系
与BaiZe Mamba2×attention同技术线。
(a) 注意力层升级候选:4个attention层用标准全局/滑窗；PHBA的top-k块稀疏+前缀状态可作滑窗替换候选(与NHA对照)；
(b) 存储/带宽:硬件感知Triton、流式路由、不落地大张量→呼应长上下文KV/中间张量瓶颈(P-9.11已证hybrid 1M ctx VRAM近恒定~26GB)；
(c) 与Mamba2兼容:前缀状态由门控线性递推生成，与SSM状态机制概念同源。
借鉴成本
GPU·h:~16(小规模对比~500M token)；墙钟:读+Triton复现~2天+实验~1天；依赖:须从头训小模型(架构不同,不能用P-8 ckpt)。
风险
①「优于强线性/混合基线」自报未复现；②无代码开源，Triton须自复现；③与~2B兼容性未知；④top-k块检索额外计算可能抵消KV节省。
价签
可行5×潜力8=40
我们判断：概念最对口(混合架构+注意力升级+KV压缩)，但落地门槛最高(无代码+从头训)。建议先读原文确认前缀状态与Mamba2 SSM接口兼容性，再决定是否投~16 GPU·h。归入「下一轮架构迭代」候选。

4YANchor-4B: O(N) Time, O(1) Memory 架构/推理 有代码+权重

出处
YANchor-4B: Effective Long-Horizon Reasoning in O(N) Time with O(1) Memory
arXiv:2610.10118 ｜ 2026-10-07 ｜ research日报10-09#2
代码:github.com/RocoreMatrix/YANchor ｜ 权重:HF HuishanJi/YANchor-4B ｜ 24p,8fig
一句话
通用循环模型：关键记忆保留为「锚点(Anchors)」供后续检索，O(N)生成时间+O(1)记忆，配多维记忆机制。AIME2024-26 pass@1 82.93%、HMMT 63.64%，称优于含更大模型的线性/常数状态同类；H100批量长生成吞吐称数倍提升。
与本线关系
混合架构/高效推理/训练成本主线，落在存储-带宽视角。
(a) 架构对照候选:Mamba2×attention之外的循环-记忆候选—「锚点检索」可启发在SSM状态外增加可检索锚点；
(b) 推理部署:O(1)记忆=长程推理KV/中间状态不随长度膨胀—P-9.11已证hybrid 1M VRAM近恒定，锚点机制可作替代/补充；
(c) ✅有代码+权重便于零训练复现。
借鉴成本
GPU·h:~8(读开源实现+小规模推理对照)；墙钟:读代码~1天+实验~0.5天；依赖:用官方4B权重直接推理(无需训练)。
风险
①「优于更大模型/数倍吞吐」自报未复现；②4B≠2.22B档，吞吐不可直接对比；③纯循环模型(非SSM-Attn混合)，迁移是「借鉴机制」非「直接替换」；④数学推理优势不一定迁移到通用语言建模。
价签
可行7×潜力6=42
我们判断：核心价值=「锚点记忆」机制—SSM状态压缩之外的另一种「不丢精确信息」思路。BaiZe的SSM做长程聚合(可能丢recall)，attention做精确检索(但KV贵)，锚点检索是介于二者的第三条路。建议先下载4B权重做推理吞吐/显存对照(零训练成本)。

价签
可行8×潜力6=48
