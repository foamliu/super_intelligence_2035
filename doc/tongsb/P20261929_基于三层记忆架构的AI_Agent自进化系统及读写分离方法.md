## 1. 技术领域 (Field)

本发明涉及人工智能领域的大语言模型 Agent 自进化技术，具体涉及一种基于三层记忆架构（L0 原始轨迹层 / L1 聚合模式层 / L2 版本归档层）的 AI Agent 自进化系统，以及在该系统上实现的记忆读写分离方法。

所述系统面向电子设计自动化（EDA）场景下的代码生成 Agent：Agent 接收自然语言任务需求，调用 EDA 软件暴露的 API 编写 Python 代码并在远程沙箱执行，由隐藏测试用例判定通过/失败。所述自进化系统从 Agent 完成批量任务后留下的对话轨迹（trace）中沉淀、聚合、蒸馏可复用经验知识，并在后续任务中通过语义检索将该知识注入 Agent 提示词，从而提升任务通过率（pass@1）。

本发明适用于一切"轨迹可采集、成败有客观评估器"的 LLM Agent 自进化场景，包括但不限于 EDA 代码生成、通用代码补全、工具调用 Agent 等。

## 2. 先前技术 (Related prior art)

**2.1 单层记忆的 Agent 反思方法**

Reflexion（Shinn et al.）提出"言语强化学习"，让 Agent 在任务失败后用自然语言反思并写入记忆，下一轮任务读取记忆。但其记忆是扁平单层的"自我反思文本"，存在三个缺陷：
- (a) 原始轨迹与聚合知识混在同一存储，要么提示词被原始日志撑爆，要么丢失回溯细节；
- (b) 反思锚定的成败信号来自 Agent 自评，而 Agent 自评严重高估（实测轨迹推断成功 150/158，而真实通过仅 114/158，假阳性约 40 例），在脏奖励信号上做反思会产生"有害编辑"；
- (c) 成功经验与失败教训未显式区分，检索时无法按可信度分级。

**2.2 端到端语义记忆方法**

MemOrb 用向量检索跨会话记忆，将完整轨迹嵌入并召回。但其将"事件经历"与"抽象知识"混在同一向量空间，缺乏分层，且读写共用一个开关——验证零知识基线时若关闭写入则连读取也一并关闭，无法测真实效果；若开启写入则污染基线。

**2.3 规程记忆自更新方法**

Voyager（Minecraft Agent）自动生成并验证技能库（procedural memory），但技能一旦写入即无条件覆盖旧版，缺乏可编辑边界保护，机器生成的规程会覆盖人工精心设计的核心资产。CoALA（Sumers et al.）理论指出"写 procedural memory 属高风险，易引入 bug 或颠覆设计者意图"，但未给出工程化的边界保护机制。

**2.4 现有技术的共同不足**

| 不足 | 现有技术表现 | 本发明解决方式 |
|---|---|---|
| 记忆不分层 | 轨迹与知识混存，prompt 膨胀或回溯丢失 | L0/L1/L2 三层分离 |
| 成败信号不可靠 | 用 Agent 自评做反思锚点 | ground-truth 富集覆盖 |
| 读写耦合 | 共用一个开关，基线无法独立验证 | 读写分离两个独立开关 |
| 规程无边界保护 | 机器覆盖人工技能 | `origin: auto_distilled` 来源标记 + 手写永不覆盖 |
| 知识无可信度分级 | 成败经验混检索 | 已验证/待验证/坑点三态 |

## 3. 发明目的与技术问题 (Motivation & challenge)

**3.1 发明目的**

提供一种让 LLM Agent 能从自身任务轨迹中自动沉淀可复用经验、并在后续任务中检索复用的自进化系统，使 Agent 的任务通过率随轮次迭代提升，且满足以下工程要求：
- 不污染人工设计的核心规程资产；
- 在零知识冷启动与有知识热运行两种状态下均可独立、可信地评估；
- 沉淀的知识有可信度分级，避免"似是而非"的知识系统性误导下游 Agent。

**3.2 技术挑战**

**挑战 1：记忆存储的分层与膨胀控制。**
一轮 benchmark 产生 158 个任务的完整轨迹（每个含数十条搜索记录、API 调用、错误日志），若全部塞入 prompt 会迅速超出上下文窗口；若只保留聚合摘要则丢失回溯细节，无法调试。需要一种分层结构，让"原始轨迹"与"聚合知识"各居其位。

**挑战 2：成败信号的可靠性。**
轨迹中 Agent 的自评（"成功了"）与沙箱隐藏测试的真实结果经常不一致——代码能跑完不代表结果对。实测轨迹把约 36 个失败任务误判为成功。若用误判信号做反思沉淀，假阳性会被标为"已验证"经验，系统性误导下游。

**挑战 3：读写控制的独立性。**
自进化系统有"沉淀（写）"和"检索复用（读）"两个动作。若共用一个开关：
- 关开关验证零知识基线时，读侧也被关，看不到已有知识，无法测真实复用效果；
- 开开关沉淀时，写侧也开，污染基线。
需要让两个动作由独立开关控制。

**挑战 4：规程记忆的安全写入。**
将聚合知识蒸馏成 Skill（技能）和 Rule（规则）写回 Agent 的操作规程是高风险写入——机器生成的规程可能含 bug 或颠覆设计意图。需要一种机器可读的可编辑边界，让自进化只能修改自己生成的规程，绝不覆盖人工手写的核心资产。

**挑战 5：知识的可信度分级与防误导。**
向量检索出的 API"看起来总是相关的"（词重叠近乎必然命中），规则无法判"似是而非"。一条来自失败任务的"方向对但参数错"的知识，若与来自成功任务的"已验证"知识混在一起，会让下游 Agent 误信。需要显式区分"成功经验 / 方向对但未通过 / 失败教训"三态。

## 4. 技术方案 (Technical solution)

本发明提供一种基于三层记忆架构的 AI Agent 自进化系统，包括 **三层记忆存储模块**、**写侧沉淀流水线**、**读侧检索注入模块**、**读写分离控制模块** 四部分。

### 4.1 三层记忆存储模块

系统采用文件系统作为记忆载体，按认知架构 CoALA 的记忆三分（情景 episodic / 语义 semantic / 规程 procedural）实现 L0/L1/L2 三层：

| 层 | 路径 | 内容 | 对应记忆类型 | 读写风险 |
|---|---|---|---|---|
| **L0_raw（原始轨迹层）** | `L0_raw/task_artifacts/{任务ID}.md` | 每任务的轨迹结构化记录：搜索记录、真实调用 API（used_apis）、错误、成败、失败根因 | 情景记忆（事件经历，可回溯） | 低（只追加） |
| **L1_patterns（聚合模式层）** | `L1_patterns/{edaPatterns,apiDecisionLog}.md` | 聚合后的条目，每条形如 `(标识符, [状态] 描述) [×佐证次数]` | 语义记忆（世界知识，可写） | 低（可写） |
| **L2_evolution（版本归档层）** | `L2_evolution/` | Skill 版本历史归档 | 规程记忆的历史 | — |
| **Skills / Rules（技能与规则层）** | `~/.cline/skills`、`~/Cline/Rules` | L1 蒸馏产物：详细决策树（Skill）/ 常驻极简硬约束（Rule） | 规程记忆（操作技能/规程） | **高**（改操作规程） |

**分层的技术效果**：L0 忠实记录每次尝试（可回溯），L1 只保留去重后的可复用模式（可注入），两者分离避免 prompt 被原始日志撑爆同时保留回溯能力。

### 4.2 写侧沉淀流水线

写侧主管模块（`update.py`）在每轮 benchmark 完成后，由写侧开关 `-e`（环境变量 `EDA_EVOLVE_ENABLED`）控制是否执行，按以下步骤流水线处理：

**步骤 1 · L0 抽取**：逐个解析任务轨迹（支持 zhulong 扁平格式与 cline 3.0 信封格式自动探测），提取结构化字段写入 L0。关键字段包括从生成代码静态提取的 **真实调用 API（used_apis）**——通过正则 `grep (pyScript|pa|ae)\.xxx(` 提取代码实际调用的 API，跳过 import/注释，作为 `[已验证]` 状态的来源依据。

**步骤 2 · ground-truth 富集**：从独立于进化循环的评估器（EDA-Eval-Framework）取沙箱隐藏测试的真实通过/失败结果，**直接覆盖**轨迹推断的成败字段。三级 fallback 定位：精确匹配 → 直接路径 → 递归搜索兜底。**关键守卫**：无 ground-truth 时（未设评估目录/空结果/读取失败）三条跳过路径都把未富集的 `execution_success` **强制设为 False**——防止轨迹推断的假阳性让失败任务被标为"已验证"，代价是宁缺毋滥地漏沉淀真成功任务。

**步骤 3 · 失败根因分类**：对失败任务判定 6 类根因（详见 P20261932），环境故障和生成故障不含 API 使用信号，跳过沉淀；其余 4 类进入反思。

**步骤 4 · 四类反思产出 L1 条目**：
- 场景反思（成功产"已验证"；失败由 LLM 判 API 方向，产"待验证"）；
- 坑点反思（仅失败，产负向警示）；
- 错→修反思（仅失败，产"错 X → 修 Y"映射）；
- 决策反思（有重复搜索等退化行为时）。
**关键设计**：四类反思都锚定成功信号——通过任务的错误不是失败信号，坑点/错→修反思在成功时直接短路返回 None。

**步骤 5 · L1 条目合并**：状态感知的合并策略——同标识符条目做佐证次数累加与状态演化（待验证→已验证升级，已验证不被降级守卫）；跨标识符的同类条目由 P2-7 语义合并（embedding 聚类 + LLM 判合）处理。

**步骤 6 · 蒸馏为 Skill/Rule**：L1 模式蒸馏为 Skill（按需加载的详细决策树）和 Rule（常驻极简约束），带来源标记保护（见 4.4）。

**步骤 7 · 质量门 + 向量同步**：四维 LLM 评审（抽象度/可复用/可操作/忠实度）+ 重写循环；L1 条目向量化灌入检索服务。

### 4.3 读侧检索注入模块

读侧由 **"L1 有无内容"** 控制（非写侧开关），包括两条路径：

**(a) 主动检索**：Agent 运行时通过 `query_memory_bank` 工具检索 L1 经验。三步流水线：查询重写（规则重写总开，双向缩写展开；LLM 重写默认关）→ 向量语义检索（top_k×2 后过滤 + 按佐证次数对数加权重排）→ 词重叠兜底（向量不可用时按标识符/描述/分区权重匹配）。

**(b) 被动注入**：L1 在每个任务的系统提示词中被动注入。两种模式：向量模式（逐任务语义召回 top-3，上限 1200 字符）为主；截断模式（向量禁用时读 L1 文件头部，上限 2000/1000 字符）为兜底。注入按 status 分层（已验证 > 待验证 > 无标签），已验证高相似度优先填满字符预算。注入段头注明"⚠️ 非答案，必须验证"免责声明，且 footer 强化为"参考知识推荐的 API 验证失败立即搜索替代 API"。

### 4.4 读写分离控制模块（核心创新）

本发明的核心创新在于**写入端与读取端由两个独立开关控制**：

| | 写侧开关 | 读侧开关 |
|---|---|---|
| **变量** | `-e` / `EDA_EVOLVE_ENABLED` | `l1_has_content`（L1 条目数 > 0） |
| **默认** | 关（需显式开启） | 由 L1 内容自动决定 |
| **控制什么** | 本轮轨迹是否喂给自进化（沉淀流水线） | 是否注册检索工具 + 是否注入 L1 到 prompt |
| **判定位置** | 编排脚本 | MCP Server 启动时 + 任务格式化时 |

**关键技术效果**：一个写侧关闭的运行，**仍然会读到**上一轮写侧开启时沉淀的 L1——因为读侧只看"L1 有没有内容"，不看"本轮是否写入"。冷启动时 L1 文件有条目数 0（带文件头但零条目的骨架，非空文件）→ 读侧判定无内容 → 不注册工具、不注入。

这使以下三种评估状态可独立控制：
- **零知识基线**：写侧关 + L1 已重置（条目数 0）→ 真·零知识；
- **自进化运行**：写侧开 → 沉淀；
- **复用已有知识**：写侧关 + L1 有内容 → 读侧自动生效。

### 4.5 可编辑边界保护机制

每个蒸馏 Skill/Rule 文件头带 `origin: auto_distilled` 来源标记。系统据此判定——**手写 Skill（无此标记）永不被覆盖**：

```
if 不是新条目 and 不是自动蒸馏的(目标目录):
    print("  跳过：手写 Skill 已存在")
    continue   # 手写 Skill 存在则跳过，绝不覆盖
```

这是**机器可读的可编辑边界**：自进化只能改自动蒸馏的规程，绝不碰人工手写的核心资产。

### 4.6 冷启动骨架与服务状态感知重置

重置后 L1 文件恢复成**带文件头 + 分区标题但零条目的骨架**（条目数为 0 ≠ 空文件），语义是"还没有条目"而非"文件缺失"，让读侧判定可靠返回"无内容"，且文件结构跨重置稳定。

向量库（ChromaDB）是有状态持久化服务，运行时打开 sqlite 并常驻内存，**运行中删文件会破坏内存中的客户端**。故重置按服务状态分流：服务在跑走 API 清空（集合级删除+重建），服务没跑才动磁盘清理；API 清空与磁盘清理永不同时。

## 5. 有益效果 (Advantageous effects)

**5.1 三层分离消除 prompt 膨胀与回溯丢失的矛盾**
L0 忠实记录每次尝试（可回溯调试），L1 只保留去重聚合模式（可注入 prompt），两者各居其位。实测一轮 158 任务的 L1 注入仅占 prompt 1200 字符上限，而 L0 完整轨迹保留在磁盘供事后分析。

**5.2 ground-truth 富集使反思锚定可靠奖励**
富集前轨迹推断成功 150/158（假阳性约 40），富集后用沙箱真实结果覆盖，假阳性被消除。对照 Reflexion 论文 Table 3（无测试+反思=52% 比基线 60% 还差），本发明通过可靠奖励锚定避免"在脏信号上做有害编辑"。

**5.3 读写分离使基线评估可信**
历史曾因读写共用开关得出"L1 注入有益 +1~2pp"的错误结论，串行重评推翻为净负（093 铁证：含 agent 推断错误参数名的"已验证"条目系统性误导）。读写分离后，治本（不沉淀 agent 推断 + [已验证] 严格化）的 L1 注入实现**净 +17 题**（74.7% → 85.4%），真代码问题降 54%，AssertionError 降 36%。

**5.4 三态分级防系统性误导**
"已验证/待验证/坑点"三态让检索时按可信度分级渲染与排序。治本前 093 案例中一条标"已验证"的错误参数名条目导致 agent 把对的位置参数改成 kwarg → fail；治本后"已验证"只基于 ground-truth，不再含 agent 推断，系统性误导消除。

**5.5 可编辑边界保护人工资产**
`origin: auto_distilled` 标记确保 4 个手写 Skill + 1 手写 Rule（人类专家精心设计的核心资产）永不被自进化覆盖，避免"颠覆设计者意图"。

**5.6 自进化复现人类手工进化**
在 challenge split（train 98 / val 20 / test 40，instance-disjoint）上，自进化从裸状态（0 经验）出发，经 1-2 轮沉淀即在 test 上追平人类手工进化的 V5.4 baseline（80.8% = 80.8%），R2 进一步把方差收敛到与人类一致（±3.82%）。裸 baseline 仅 65.0%，自进化知识净贡献 +12~14pp。多模型验证（5 个模型 71.5%~92.4%）证明 rule/skill/validator 是跨模型可迁移经验，非过拟合。

## 6. 具体实施方式 (Detailed embodiments)

**实施例 1：三层记忆的文件系统实现**

```
~/Cline/Memory/
├── L0_raw/task_artifacts/       # 情景记忆：每任务一个 .md
│   ├── 001.md
│   └── ...
├── L1_patterns/                  # 语义记忆：聚合模式
│   ├── edaPatterns.md           # 5 分区：API 场景映射/API 坑点/错→修/诊断模式/有效查询
│   └── apiDecisionLog.md        # 决策记录
└── L2_evolution/                 # 规程记忆历史：Skill 版本归档

~/.cline/skills/eda-*/            # 规程记忆：详细决策树
~/Cline/Rules/eda-*.md            # 规程记忆：常驻硬约束
```

L1 文件结构：含 frontmatter（entry_count、provenance 等）+ 5 个分区标题 + 条目。每条形如：
```
- (create-bit-array-and-set-bits, [已验证] 在创建位数组场景用 dbCrtArrayInst + emyInitDb) [×3]
```
N>1 才显示佐证次数。冷启动骨架：frontmatter `entry_count: 0` + 分区标题存在但零条目。

**实施例 2：读写分离的判定逻辑**

MCP Server 启动时（`main.py`）：
```python
_l1_has_content = _l1_has_entries(L1_patterns) or _l1_has_entries(L1_decisions)
_TOOL_DEFAULTS = {
    "query_memory_bank": _l1_has_content,  # 有 L1 知识才开
    ...
}
# L1↔Vector 一致性检查：L1 空但向量库有旧数据 → 警告 reset 未清干净
```

任务格式化时（`format_eval_task.py`）：
```python
# 读端：l1_has_content，与 evolve_enabled(写端) 独立
l1_has_content = _l1_has_entries(patterns) or _l1_has_entries(decisions)
if l1_has_content and vector_enabled:
    # 向量模式：逐任务语义召回
elif l1_has_content:
    # 截断模式：读 L1 文件头部
else:

def _enrich_from_execution_results(artifacts, eval_dir):
    if not eval_dir or not os.path.isdir(eval_dir):
        for a in artifacts: a["execution_success"] = False  # 跳过路径1：强制False
        return 0
    results = load_results(eval_dir)
    if not results:
        for a in artifacts: a["execution_success"] = False  # 跳过路径2：强制False
        return 0
    # 正常富集：覆盖
    for a in artifacts:
        passed = results.get(a["task_id"], False)
        a["execution_success"] = passed
```
