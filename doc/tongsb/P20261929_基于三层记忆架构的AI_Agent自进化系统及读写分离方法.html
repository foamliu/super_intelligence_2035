1技术领域 (Field)

本发明涉及人工智能领域的大语言模型 Agent 自进化技术，具体涉及一种面向电子设计自动化（EDA）脚本生成与工作流编排的 AI Agent 自进化系统，以及在该系统上实现的记忆读写分离方法。

所述系统面向 EDA 场景下的代码生成 Agent：Agent 接收自然语言任务需求，调用 EDA 软件暴露的 API 编写 Python 代码并在远程沙箱执行，由隐藏测试用例判定通过/失败。系统从 Agent 完成批量任务后留下的对话轨迹（trace）中沉淀、聚合、蒸馏可复用经验知识，并在后续任务中通过语义检索将该知识注入 Agent 提示词，从而提升任务通过率（pass@1）。

2先前技术 (Related prior art)

2.1 Reflexion：反思锚定脏奖励信号

Reflexion（Shinn et al.）让 Agent 在任务失败后用自然语言反思并写入记忆。但其反思锚定的成败信号来自 Agent 自评，而 Agent 自评严重高估——实测 EDA 轨迹推断成功 150/158，沙箱真实通过仅 114/158，假阳性约 40 例。在脏奖励上做反思会产生"有害编辑"（Reflexion 论文 Table 3：无测试 + 反思 = 52%，比基线 60% 还差）。问题：如何用客观真值富集奖励信号。

2.2 Hermes Agent：自动沉淀技能无边界保护

Hermes Agent（Nous Research，GitHub 101K+ stars）具备三层记忆与会话间自动沉淀能力：当一个工作流被判定"验证通过"（调用工具 5 次以上），自动将整个解决过程做成 Skill 文件；后续使用中若发现"更好路径"，直接更新/覆盖该 Skill 文档。这种"用一次记一辈子、自动迭代"的机制与本发明目标相近，但其 Skill 写入无来源标记、无手写/自动蒸馏的边界区分——机器生成的规程会覆盖人工精心设计的核心资产。问题：如何让自进化只改自己生成的规程，绝不覆盖手写核心资产。

2.3 OpenClaw：单文件记忆读写耦合

OpenClaw（GitHub 245K stars，历史第一）以文件为记忆载体，"开机仪式"在每次新会话启动时按固定流程加载 AGENTS.md / SOUL.md / USER.md / MEMORY.md，其中 MEMORY.md 标注为"完全开放"——AI 在会话中既读又写同一文件。读写由同一文件、同一权限控制，无独立开关。在 benchmark 评估场景下，若关闭记忆以验证零知识基线，则读取也一并被关，无法测真实复用效果；若开启记忆则写入污染基线。问题：如何让沉淀（写）与检索复用（读）由独立开关控制，使基线评估可信。

3发明目的与技术问题 (Motivation & challenge)

3.1 发明目的

提供一种将分层记忆架构适配到"有客观沙箱评估器的 EDA 脚本生成 + 工作流编排"领域的 LLM Agent 自进化系统，使 Agent 能从自身任务轨迹中自动沉淀可复用经验、并在后续任务中检索复用，让任务通过率随轮次迭代提升，且满足以下工程要求：

  • 利用 EDA 沙箱真值信号修正 Agent 自评假阳性，避免在脏奖励上做有害编辑；
  • 不污染人工设计的 EDA 核心规程资产；
  • 在零知识冷启动与有知识热运行两种状态下均可独立、可信地评估；
  • 沉淀的知识按 EDA 评测语义分级，避免"似是而非"的知识系统性误导下游 Agent。

3.2 技术挑战

挑战 1：脏奖励信号

EDA 沙箱有隐藏测试提供独立真值，但 Agent 自评与真值经常不一致——实测轨迹把约 36 个失败任务误判为成功。若不利用真值富集，假阳性会被标为"已验证"经验，系统性误导下游。如何把沙箱真值引入沉淀流水线并安全覆盖推断，且从跑通的代码静态抽取真实调用 API 作为"已验证"锚点，是首要挑战。

挑战 2：读写耦合

自进化有"沉淀（写）"和"检索复用（读）"两个动作。若共用一个开关：关开关验证零知识基线时读侧也被关，看不到已有知识无法测真实复用效果；开开关沉淀时写侧也开，污染基线。需要让两个动作由独立开关控制，使三种评估状态（零知识 / 自进化 / 复用已有知识）可独立控制。

挑战 3：规程记忆的安全写入

EDA 有专家手写多年的核心 Skill（如 eda-init、snap-origin、emydesign-attributes），是高价值人工资产。自动蒸馏的规程可能含 bug 或颠覆设计意图。需要机器可读的可编辑边界，让自进化只能改自己生成的规程，绝不覆盖手写核心资产。

挑战 4：知识的可信度分级与防误导

向量检索出的 API"看起来总是相关的"，规则无法判"似是而非"。一条来自失败任务的"方向对但参数错"的知识，若与来自成功任务的"已验证"知识混在一起，会让下游 Agent 误信。需要显式区分"已验证 / 待验证 / 坑点"三态，按可信度分级渲染与排序。

4技术方案 (Technical solution)

本发明提供一种基于三层记忆架构的 AI Agent 自进化系统，包括 三层记忆存储模块、写侧沉淀流水线、读侧检索注入模块、读写分离控制模块 四部分。

4.1 三层记忆存储模块

系统采用文件系统作为记忆载体，按情景 / 语义 / 规程三类记忆实现 L0/L1/L2 三层：

层路径内容记忆类型读写风险
L0_raw（原始轨迹层）L0_raw/task_artifacts/{任务ID}.md每任务的轨迹结构化记录：搜索记录、真实调用 API（used_apis）、错误、成败、失败根因情景记忆（事件经历，可回溯）低（只追加）
L1_patterns（聚合模式层）L1_patterns/{edaPatterns,apiDecisionLog}.md聚合后的条目，每条形如 (标识符, [状态] 描述) [×佐证次数]语义记忆（世界知识，可写）低（可写）
L2_evolution（版本归档层）L2_evolution/Skill 版本历史归档规程记忆的历史—
Skills / Rules（技能与规则层）~/.cline/skills · ~/Cline/RulesL1 蒸馏产物：详细决策树（Skill）/ 常驻极简硬约束（Rule）规程记忆（操作技能/规程）高（改操作规程）
三层流转：L0（每任务的情景记录，"发生了什么"）经写侧流水线（§4.2 步骤 1-5）抽取、富集、反思、合并后，蒸馏为 L1 的聚合模式条目（"提炼出什么可复用"，语义记忆）；L1 再经步骤 6 蒸馏为 Skills/Rules（规程记忆，"怎么操作"），其版本历史归档于 L2。"聚合模式"描述它怎么来的（从 L0 聚合提炼），"语义记忆"描述它认知上是什么（世界知识）——二者是同一层在两个维度上的两个名字，不矛盾。
举例：一条"创建位数组"经验从 L0 到 Skill 的流转

L0（情景记录，每任务一个文件） —— 任务 task_093.md 跑通了，记录里含：搜索记录 3 条、used_apis（正则从生成代码抽出）= [dbCrtArrayInst, emyInitDb]、execution_success=true（经 ground-truth 富集）、失败根因=无。

L1（聚合模式条目，跨任务去重后） —— 同一场景被 3 个不同任务跑通，合并去重后写入 L1_patterns/edaPatterns.md：

- (create-bit-array-and-set-bits, [已验证] 在创建位数组场景用 dbCrtArrayInst + emyInitDb) [×3]

其中 create-bit-array-and-set-bits 是标识符（API 场景名），[已验证] 是三态之一（因 3 次均沙箱通过），×3 是佐证次数（跨任务累加）。下一任务遇到同场景时，读侧检索到此条并注入 prompt。

Skill（规程记忆，L1 蒸馏产物） —— 该 L1 条目被进一步蒸馏为 ~/.cline/skills/eda-bit-array/SKILL.md（详细决策树，按需加载）+ ~/Cline/Rules/eda-bit-array.md（常驻极简硬约束），文件头标 origin: auto_distilled。Skill 旧版本归档至 L2。

4.3 读侧检索注入模块

读侧由 "L1 有无内容" 控制（非写侧开关），包括两条路径：

(a) 主动检索

Agent 运行时通过 query_memory_bank 工具检索 L1 经验。三步流水线：查询重写（规则重写总开，双向缩写展开；LLM 重写默认关）→ 向量语义检索（top_k×2 后过滤 + 按佐证次数对数加权重排）→ 词重叠兜底（向量不可用时按标识符/描述/分区权重匹配）。

(b) 被动注入

L1 在每个任务的系统提示词中被动注入。两种模式：向量模式（逐任务语义召回 top-3，上限 1200 字符）为主；截断模式（向量禁用时读 L1 文件头部，上限 2000/1000 字符）为兜底。注入按 status 分层（已验证 > 待验证 > 无标签），已验证高相似度优先填满字符预算。

注入段头注明 "⚠️ 非答案，必须验证" 免责声明，且 footer 强化为"参考知识推荐的 API 验证失败立即搜索替代 API"。

4.4 读写分离控制模块（核心创新之一）

本发明的核心创新在于写入端与读取端由两个独立开关控制：

写侧开关读侧开关
变量-e / EDA_EVOLVE_ENABLEDl1_has_content（L1 条目数 > 0）
默认关（需显式开启）由 L1 内容自动决定
控制什么本轮轨迹是否喂给自进化（沉淀流水线）是否注册检索工具 + 是否注入 L1 到 prompt
判定位置编排脚本MCP Server 启动时 + 任务格式化时
关键技术效果：一个写侧关闭的运行，仍然会读到上一轮写侧开启时沉淀的 L1——因为读侧只看"L1 有没有内容"，不看"本轮是否写入"。冷启动时 L1 文件有条目数 0（带文件头但零条目的骨架，非空文件）→ 读侧判定无内容 → 不注册工具、不注入。
图 3 · 读写分离双独立开关与三种评估状态

4.5 可编辑边界保护机制（核心创新之二）

每个蒸馏 Skill/Rule 文件头带 origin: auto_distilled 来源标记。系统据此判定——手写 Skill（无此标记）永不被覆盖：

if 不是新条目 and 不是自动蒸馏的(目标目录):
    print("  跳过：手写 Skill 已存在")
    continue   # 手写 Skill 存在则跳过，绝不覆盖
这是机器可读的可编辑边界：自进化只能改自动蒸馏的规程，绝不碰人工手写的核心资产。

5有益效果 (Advantageous effects)

5.1 ground-truth 富集使反思锚定可靠奖励
富集前轨迹推断成功 150/158（假阳性约 40），富集后用沙箱真实结果覆盖，假阳性被消除。对照 Reflexion 论文 Table 3（无测试+反思=52% 比基线 60% 还差），本发明通过可靠奖励锚定避免"在脏信号上做有害编辑"。
5.2 读写分离 + 三态分级使基线评估可信
历史曾因读写共用开关得出"L1 注入有益 +1~2pp"的错误结论，串行重评推翻为净负（093 铁证：一条标"已验证"的错误参数名条目导致 agent 把对的位置参数改成 kwarg → fail）。读写分离并配合"已验证/待验证/坑点"三态分级后，治本的 L1 注入实现净 +17 题（74.7% → 85.4%），真代码问题降 54%，AssertionError 降 36%。
5.3 自进化复现人类手工进化
在 challenge split（train 98 / val 20 / test 40，instance-disjoint）上，自进化从裸状态（0 经验）出发，经 1-2 轮沉淀即在 test 上追平人类手工进化的 V5.4 baseline（80.0% vs 77.5%），R2 进一步把方差收敛到与人类一致（SD=3.1%）。裸 baseline 仅 66.0%，自进化知识净贡献 +12~14pp。多模型验证（5 个模型 71.5%~92.4%）证明 rule/skill/validator 是跨模型可迁移经验，非过拟合。

实施例 2：可编辑边界保护

_SKILL_AUTO_MARKER = "origin: auto_distilled"
def _is_auto_distilled_skill(skill_dir):
    head = open(f"{skill_dir}/SKILL.md").read(500)
    return _SKILL_AUTO_MARKER in head

# 蒸馏时
if os.path.exists(target) and not _is_auto_distilled_skill(target):
    print("跳过：手写 Skill 已存在")
    continue  # 手写永不覆盖
