## **仍存在的问题**

1. **V5\.1\+evo timeout 率回升到 10\.6%（原因待查）**：L1\+evo 的 run\_code 调用数\(767\)和中位耗时\(7\.2s\)都比 baseline\(875/9\.1s\)低，但 timeout 翻倍\(41→81\)。非'复杂代码'所致——可能是 L1 让 agent 调 run\_code 更集中撞排队高峰，或这批 task 恰好是 timeout 重灾区。净效果正向\(pass 仍最高\)。

4. **Semaphore timeout 死结未根治**：客户端 60s 硬墙 \+ Semaphore 排队，四条客户端路全堵死（cline\_mcp\_settings/env/progress reset 无效，仅改 SDK 默认值有效但本轮未触发）。若未来 timeout 率回升，改 SDK DEFAULT\_REQUEST\_TIMEOUT\_MSEC 60000→180000（确定有效）。
